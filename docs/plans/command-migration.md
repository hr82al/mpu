# План переезда — команды по частоте использования

Приоритетный список для фазы 2 мастер-плана
(`2026-08-04-full-migration.md`); там же — фазы, критерии выхода и цикл
переезда одной команды. Единица переезда — команда; спеки живут в канале `ts/docs/specs/`
(правила — `ts/docs/CLAUDE.md`), статусы («—» / черновик / к реализации /
реализовано) — в самих спеках, здесь — зеркало для планирования.
Источник частот: журнал вызовов mpu, окно 28.07–05.08.2026, 2451 вызов
— пересобрано 2026-08-05 перед стартом переезда команд, как и
предписывал план; прежнее окно (21–27.07.2026, 3197 вызовов) даётся в
скобках для сравнения. Состав «Не едут» (решён 2026-07-27) пересмотру
не подлежит, кроме отмеченного там `process`. Порядок списка —
приоритет ценности; реализация идёт сверху вниз.

История: план заведён для отменённой Go-редакции (брокер + CLI);
2026-08-04 адаптирован под текущую архитектуру — один Deno/TS-бинарь,
CLI + MCP-сервер, не переехавшие команды исполняются маршрутом `legacy`
(подпроцесс Python-реализации). Спеки перенесены из `go/docs` в
`ts/docs/specs/` и раз-брокерены.

## Обвязка — реализована (MVP 2026-08-03)

- **mcp-server** — агентная точка входа: Streamable HTTP, профили
  `ro`/`rw`, закрытый список публикации, аннотации необратимых тулов.
  Заменил протокол брокера (`protocol/core`/`protocol/legacy` умерли).
  Спека: `ts/docs/specs/platform/mcp-server.md` — реализовано.
- **registry** — реестр команд: маршрутизация `native`/`legacy`,
  справка, completion, мост в Python. Поглотил брокерную
  legacy-делегацию. Спека: `ts/docs/specs/platform/registry.md` —
  реализовано.
- **command-contract** — контракт объявления команды (`path`, `policy`,
  схемы, `render` + необязательный мост частично переехавшей команды).
  Спека: `ts/docs/specs/platform/command-contract.md` — реализовано
  (статусы всех трёх спек обвязки выровнены с планом 2026-08-05: код
  ездит с MVP, а спеки числились «к реализации»).
- **config** — локальные предпочтения + `mpu config`. Спека:
  `ts/docs/specs/platform/config.md` — черновик.
- **env-file** — слой секретов/подключений native-команд (бывший конфиг
  брокера). Спека: реализовано (2026-08-04; доработка «конфигурация
  только из env-файла, окружение не читается» — 2026-08-05, порцией Б
  init).
- **store** — атом кэш-БД: открытие, идемпотентный bootstrap,
  транзакции, WAL, права 0600. Спека: `ts/docs/specs/platform/store.md`
  — реализовано (2026-08-05, порцией А init; в коде — `CacheDb`).
- **selector** — резолв `sl-N`/имени; исполняется самим CLI. Спека:
  реализовано (2026-08-05, порцией `~/tmp/prompt-4.txt`; вердикты по
  вопросам реализации внесены в спеку, три правки — сервер кандидата,
  пустой селектор, порядок ветки заголовка — приняты доработкой).
- **invoke-log** — локальный журнал вызовов, формат оригинала. Спека:
  **реализовано** (2026-08-05, порцией `~/tmp/prompt-5.txt`; вердикты по
  двенадцати вопросам реализации внесены в спеку, правок кода не
  потребовалось — все решения порции приняты, три из них зафиксированы
  как fix-отклонения от оригинала: lock только под ротацию, JSON-тело
  без пересборки при отсутствии совпадений, единый русский текст note).
  Мост переработан: запись legacy-вызова остаётся за
  Python-подпроцессом (его журнал не отключается), обвязка журналирует
  только native; перехват — слой вывода команд, без pty (в Deno его
  нет); файл и lock общие.
- **readonly-default** — чтение по умолчанию: read-only PG-сессия +
  разделение MCP-профилей. Спека: реализовано (2026-08-06, вместе с
  первой порцией sql-ro; обёртка транзакцией с меткой, тексты отказов
  приняты).
- **exec-transport** — база второй половины ядра: доставка команды в
  контейнер фермы (`mp-sl-N-cli` либо точное имя), стрим stdout/stderr,
  код выхода 1:1. Два взаимоисключающих бэкенда, выбор per-server:
  Portainer (HTTP + WebSocket) и ssh + `docker exec`; поверх — detach и
  кэш контейнеров. Потребители: `ssh`, `run-js`, `ps`, `health`,
  sw-маршрут `sql-ro`, семейство Portainer-обёрток. Portainer здесь —
  не отдельная команда к переезду, а один из бэкендов: его REST-часть
  уже переехала с `init` (`listEndpoints`/`listContainers`,
  `fetchPortainerJson`, политика TLS — `ts/src/init/portainer.ts`);
  недостаёт exec-части — создание exec, WebSocket-стрим, stdin
  tar-загрузкой, чтение кода выхода, kill по pidfile. Спека:
  `ts/docs/specs/platform/exec-transport.md` — **к реализации**
  (заморожена 2026-08-17; голдены `fixtures/exec-transport/`: четыре файла
  CLI-границы живьём, ответы Portainer синтетические по формам Docker
  Engine API, тело логов — base64). Встроенные дефолты dev-ноды внесены
  в текст, обязательными переменные не сделаны — оригинал работает без
  них. Едет одной порцией с командой `ssh` (спека тоже заморожена
  2026-08-17, голдены `fixtures/ssh/` сняты живьём): платформенный слой
  без потребителя нечем проверить. Detach уходит с `run-js`, разбор
  логов — с `health`/`logs`.

  **Реализовано 2026-08-17** одной порцией целиком, резать по границе
  бэкендов не понадобилось: оба бэкенда, свой клиент WebSocket с кадровым
  кодеком, свой tar на один файл, порт вывода удалённой команды и сама
  команда `ssh` (маршрут native, 916 тестов зелёные). Живьём не гонялось
  ничего — любая команда этого транспорта исполняется в живом
  прод-контейнере; WebSocket проверен фейковым сервером на петле,
  ssh-путь — подставным исполнителем подпроцесса. Приёмка оставила
  четыре хвоста, все с вердиктом `fix` в спеке `specs/ssh.md`: тексты
  отказа `--via` про запрошенный транспорт, ambiguous внутри fan-out,
  общий `--json` у команды с хвостовым входом и байтовое чтение stdin
  (правка порта io в `platform/command-contract.md`). Чтение номеров
  инстанс-серверов отложено намеренно — его единственный потребитель
  `run-js --all`, не `ps`/`health`.

  **`run-js` — следующая порция (спека заморожена 2026-08-17, голдены
  `fixtures/run-js/` сняты живьём безобидным `console.log`).** Вместе с ней
  приезжает detach и появляется потребитель у чтения номеров серверов. Буфер
  обмена `--dry-run` вынесен отдельной платформенной спекой
  `platform/clipboard.md` (OSC 52, затем `wl-copy`/`xclip`/`xsel`, все отказы
  молчаливые) — она же обслужит `--print`-обёртки, когда те поедут.

  **`run-js` принят 2026-08-17**, `run-js.md` и `platform/clipboard.md` —
  «реализовано». Хвостом порции приняты экранирование фильтра подстроки
  (`fix`: `_` и `%` работали как метасимволы `LIKE` и на fan-out ловили чужой
  контейнер) и перевод числовых входов на объявленный тип (`logs --tail`,
  `run-js --jobs`). **Следующая порция — `ps` и `health`** (спеки заморожены
  2026-08-17, голдены `ps` сняты на синтетическом кэше, у `health` голденов
  вывода нет и быть не может — состояние прод-фермы и куски боевых логов).

  **`ps` и `health` приняты 2026-08-17** вместе с разбором логов контейнера —
  `platform/exec-transport.md` реализован целиком, `health.md` — «реализовано».
  Живьём не гонялись намеренно: обе команды ходят в прод-ферму, `health` ещё и
  вытягивает боевые логи; сверка парой с рабочей версией — за мной. Приёмка
  оставила один хвост: регистр фильтра (`fix` — кэш сравнивал без учёта
  регистра, живой режим с учётом), до правки `ps.md` держится
  «к реализации». Дальше по плану — sw-маршрут `sql-ro` и Portainer-обёртки.

  Отдельными строками, не в порцию: `telegram ls --limit` и `telegram search
  --limit` объявлены строками при числовом смысле — перевод стоит делать
  вместе с пересверкой голденов их отказов (замечание реализации 2026-08-17);
  `logs --client` совпадает подстрокой по десятичной записи, поэтому фильтр
  `12` ловит и порт `:1234` — поведение по спеке, но выглядит ловушкой; тело
  ответа Portainer не проверяется на форму, поэтому не-массив даёт ошибку среды
  мимо ошибки клиента (свойство унаследованное, замечание 2026-08-17).

  Отдельной строкой, не в порцию: `xlsx get` с двумя `--from -` в одном вызове
  прочитает stdin дважды и на боевом порту упадёт на вычерпанном потоке
  (замечание реализации 2026-08-17, дефект пред-существующий).

## Порядок ядра — решено 2026-08-05

`selector` → `invoke-log` → `sql-ro` (обычный + dev маршрут) → команды
по частоте, чей атом уже готов (`kiten` поверх kaiten-http, `logs`
поверх loki-http) → **`exec-transport`** → `ssh`, `run-js`, sw-маршрут
`sql-ro` → `ps`, `health`, Portainer-обёртки.

Транспорт — самая тяжёлая платформенная часть (два бэкенда,
WebSocket-стрим, tty, kill, stdin tar'ом), и вперёд `sql-ro` он не
двигается: за свежее окно журнала sw-селектор не встретился ни разу
(0 из 740 вызовов `sql-ro`), dev-префикс — тоже, то есть первая порция
`sql-ro` закрывает 100 % фактических вызовов команды-лидера. Зато сразу
за транспортом дёшево едут `ssh` (175) и `run-js` (19) — они целиком
поверх него, — и снимается открытый вопрос sw-маршрута.

Цена дробления команды-лидера — временный мост: реестр держит маршрут
(`native`/`legacy`) на команде, а не на аргументе, поэтому пока
`sql-sw` не переехал, вызов с sw-алиасом внутри native-команды
делегируется прежней реализации подпроцессом. Мост снимается порцией
`sql-sw` и до тех пор сохраняет поведение sw-вызова прежним — иначе
пришлось бы либо ждать транспорта всей команде-лидеру, либо временно
урезать её контракт.

## Команды к переезду (по частоте)

1. **sql-ro** (740; было 1225) — SQL в enforced read-only сессии на PG
   по селектору. Едет двумя порциями: **обычный + dev маршрут** —
   прямое TCP-подключение, атомы selector, env-file, readonly-default,
   все готовы; **маршрут sw** — после `exec-transport`: prod sw-PG
   закрыт `pg_hba.conf`, SQL исполняется изнутри контейнера sw-back
   (`node --input-type=module -` со скриптом на stdin). Дробление
   ничего не стоит — sw-вызовов за окно нет. Первая порция:
   **реализовано** (2026-08-06 приняты и порция, и правки текстов
   отказов — постановки 6/8/9/11), goldens сняты
   с живой версии (`fixtures/sql-ro/`); `;`-склейка закрыта — печатается
   result set первого оператора, проверено живьём на обоих маршрутах.
   Маршрут sw выделен в отдельную спеку `specs/sql-sw.md` (черновик,
   общая для `sql` и `sql-ro`); до его переезда sw-селектор
   делегируется прежней реализации подпроцессом — реестр маршрутизирует
   по команде, не по аргументу, поэтому иначе порция не включилась бы.

   Локальное состояние из контракта убрано целиком: подсказки таймера,
   история значений полей и кэш справочников больше не наблюдаемы;
   резолв имён — живым запросом. Критерий расширяемости: новая
   командная спека не порождает новой платформенной.
   Первая волна — time (266), field (108), card (77), comment (32) =
   78 % трафика. Дальше: close (56); checklist (36); status (7) — вся
   моя работа матрицей; desc (7); roles (5); справочники; ls; move.
   Порядок порций — в дизайне (транспорт → три каталога → четыре

   её дневной отчёт `telegram status` (переехал 2026-08-17).
   **Состояние волны на 2026-08-14**: порция 1 (транспорт + каталог
   времени, 9 вызовов) и порция 2 (каталог карточек, 14 вызовов, с ними
