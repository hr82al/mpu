# План переезда — команды по частоте использования

Приоритетный список для фазы 2 мастер-плана
(`2026-08-04-full-migration.md`); там же — фазы, критерии выхода и цикл
переезда одной команды. Единица переезда — команда; спеки живут в канале `ts/docs/specs/`
(правила — `ts/docs/CLAUDE.md`), статусы («—» / черновик / к реализации /
реализовано) — в самих спеках, здесь — зеркало для планирования.
Источник частот: журнал вызовов mpu, окно 28.07–05.08.2026, 2451 вызов
— пересобрано 2026-08-05 перед стартом переезда команд, как и
предписывал план; прежнее окно (21–27.07.2026, 3197 вызовов) даётся в
скобках для сравнения. Состав «Не едут» (решён 2026-07-27) пересмотру
не подлежит, кроме отмеченного там `process`. Порядок списка —
приоритет ценности; реализация идёт сверху вниз.

История: план заведён для отменённой Go-редакции (брокер + CLI);
2026-08-04 адаптирован под текущую архитектуру — один Deno/TS-бинарь,
CLI + MCP-сервер, не переехавшие команды исполняются маршрутом `legacy`
(подпроцесс Python-реализации). Спеки перенесены из `go/docs` в
`ts/docs/specs/` и раз-брокерены.

## Обвязка — реализована (MVP 2026-08-03)

- **mcp-server** — агентная точка входа: Streamable HTTP, профили
  `ro`/`rw`, закрытый список публикации, аннотации необратимых тулов.
  Заменил протокол брокера (`protocol/core`/`protocol/legacy` умерли).
  Спека: `ts/docs/specs/platform/mcp-server.md` — реализовано.
- **registry** — реестр команд: маршрутизация `native`/`legacy`,
  справка, completion, мост в Python. Поглотил брокерную
  legacy-делегацию. Спека: `ts/docs/specs/platform/registry.md` —
  реализовано.
- **command-contract** — контракт объявления команды (`path`, `policy`,
  схемы, `render` + необязательный мост частично переехавшей команды).
  Спека: `ts/docs/specs/platform/command-contract.md` — реализовано
  (статусы всех трёх спек обвязки выровнены с планом 2026-08-05: код
  ездит с MVP, а спеки числились «к реализации»).
- **config** — локальные предпочтения + `mpu config`. Спека:
  `ts/docs/specs/platform/config.md` — черновик.
- **env-file** — слой секретов/подключений native-команд (бывший конфиг
  брокера). Спека: реализовано (2026-08-04; доработка «конфигурация
  только из env-файла, окружение не читается» — 2026-08-05, порцией Б
  init).
- **store** — атом кэш-БД: открытие, идемпотентный bootstrap,
  транзакции, WAL, права 0600. Спека: `ts/docs/specs/platform/store.md`
  — реализовано (2026-08-05, порцией А init; в коде — `CacheDb`).
- **selector** — резолв `sl-N`/имени; исполняется самим CLI. Спека:
  реализовано (2026-08-05, порцией `~/tmp/prompt-4.txt`; вердикты по
  вопросам реализации внесены в спеку, три правки — сервер кандидата,
  пустой селектор, порядок ветки заголовка — приняты доработкой).
- **invoke-log** — локальный журнал вызовов, формат оригинала. Спека:
  **реализовано** (2026-08-05, порцией `~/tmp/prompt-5.txt`; вердикты по
  двенадцати вопросам реализации внесены в спеку, правок кода не
  потребовалось — все решения порции приняты, три из них зафиксированы
  как fix-отклонения от оригинала: lock только под ротацию, JSON-тело
  без пересборки при отсутствии совпадений, единый русский текст note).
  Мост переработан: запись legacy-вызова остаётся за
  Python-подпроцессом (его журнал не отключается), обвязка журналирует
  только native; перехват — слой вывода команд, без pty (в Deno его
  нет); файл и lock общие.
- **readonly-default** — чтение по умолчанию: read-only PG-сессия +
  разделение MCP-профилей. Спека: реализовано (2026-08-06, вместе с
  первой порцией sql-ro; обёртка транзакцией с меткой, тексты отказов
  приняты).
- **exec-transport** — база второй половины ядра: доставка команды в
  контейнер фермы (`mp-sl-N-cli` либо точное имя), стрим stdout/stderr,
  код выхода 1:1. Два взаимоисключающих бэкенда, выбор per-server:
  Portainer (HTTP + WebSocket) и ssh + `docker exec`; поверх — detach и
  кэш контейнеров. Потребители: `ssh`, `run-js`, `ps`, `health`,
  sw-маршрут `sql-ro`, семейство Portainer-обёрток. Portainer здесь —
  не отдельная команда к переезду, а один из бэкендов: его REST-часть
  уже переехала с `init` (`listEndpoints`/`listContainers`,
  `fetchPortainerJson`, политика TLS — `ts/src/init/portainer.ts`);
  недостаёт exec-части — создание exec, WebSocket-стрим, stdin
  tar-загрузкой, чтение кода выхода, kill по pidfile. Спека:
  `ts/docs/specs/platform/exec-transport.md` — черновик (goldens не
  сняты).

## Порядок ядра — решено 2026-08-05

`selector` → `invoke-log` → `sql-ro` (обычный + dev маршрут) → команды
по частоте, чей атом уже готов (`kiten` поверх kaiten-http, `logs`
поверх loki-http) → **`exec-transport`** → `ssh`, `run-js`, sw-маршрут
`sql-ro` → `ps`, `health`, Portainer-обёртки.

Транспорт — самая тяжёлая платформенная часть (два бэкенда,
WebSocket-стрим, tty, kill, stdin tar'ом), и вперёд `sql-ro` он не
двигается: за свежее окно журнала sw-селектор не встретился ни разу
(0 из 740 вызовов `sql-ro`), dev-префикс — тоже, то есть первая порция
`sql-ro` закрывает 100 % фактических вызовов команды-лидера. Зато сразу
за транспортом дёшево едут `ssh` (175) и `run-js` (19) — они целиком
поверх него, — и снимается открытый вопрос sw-маршрута.

Цена дробления команды-лидера — временный мост: реестр держит маршрут
(`native`/`legacy`) на команде, а не на аргументе, поэтому пока
`sql-sw` не переехал, вызов с sw-алиасом внутри native-команды
делегируется прежней реализации подпроцессом. Мост снимается порцией
`sql-sw` и до тех пор сохраняет поведение sw-вызова прежним — иначе
пришлось бы либо ждать транспорта всей команде-лидеру, либо временно
урезать её контракт.
