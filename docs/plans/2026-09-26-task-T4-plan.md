## Черновик полномочий (человек правит и вписывает)

- Хост: «спецификатор mpu: пишет спеки и постановки, принимает порции
  (гейты, мутация, установка, живая проба безопасными строками); код `ts/`
  не пишет; субагенты и Workflow — нет (до отмены владельцем); прод — только
  чтение; push — только по просьбе владельца».
- Исполнитель: «код `ts/` строго по спеке; спеки не правит — вопрос в канал;
  субагенты и Workflow — нет; полный прогон тестов с пределом `timeout 900`;
  прод — никогда; push — нет; мерж — никогда».

## Черновик правил проекта (`rule`)

1. Синтаксис языка решает слепой замер `sonnet`, не вкус.
2. Громкий отказ с готовой строкой; обратная совместимость не нужна.
3. Прод не меняем; пишущие проверки — локальный стек.
4. Вопрос исполнителя: хост решает по коду/живому прогону, правит спеку, потом
   отвечает; не решается правилами — `owner`.
5. Перед каждой постановкой — чистый контекст исполнителя (оркестратор делает
   это сам).
