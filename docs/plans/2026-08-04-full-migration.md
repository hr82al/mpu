# План полного переезда py → ts (CLI + MCP)

Мастер-план от текущего состояния до вывода Python-реализации из
эксплуатации. Роли: **[С]** спецификатор, **[D]** изолированная
Deno-сессия, **[O]** оператор. Процедура одной порции — плейбук
(`../migration-playbook.md`); порядок и приоритеты команд —
`command-migration.md`; журнал решений — `../migration-log.md`.
Здесь — фазы, их критерии выхода и точки решения.

## Фаза 0 — точка отсчёта (готово, MVP 2026-08-03)

Один бинарь (`deno compile`), две точки входа: CLI и MCP-сервер
(Streamable HTTP, профили `ro`/`rw`, 24/26 тулов, аннотации
необратимых). Реестр: 57 команд верхнего уровня / 272 записи слепка;
native — семейство `xlsx`, `mcp token`, `version`, справка/completion;
всё остальное — маршрут `legacy` (подпроцесс Python). Переключатель
реализаций `scripts/mpu-impl` с откатом. Спеки отменённой Go-редакции
перенесены в `ts/docs/specs/` и адаптированы (2026-08-04).

## Цикл переезда одной команды (повторяется всю дорогу)

1. [С] Спека → «к реализации»: golden с живой Python-версии, фикстуры
   внешних границ, термины в глоссарий.
2. [D] Реализация строго по спеке; гейты `fmt/lint/check/test` зелёные.
3. [O] Чтение кода целиком, приёмка по плейбуку §4.
4. [С] Differential: обе реализации на одних входах, диф пуст
   (ожидаемые расхождения — только «Известные отклонения»).
5. [С] Маршрут в реестре `legacy` → `native` и удаление py-кода команды
   одним коммитом; тул MCP переходит на native-декларацию
   (`argsSchema`/`resultSchema`/`render`) — проверить `tools/list`.
6. [С] Переснять слепок дерева с Python (`manifest`), обновить фикстуры;
   completion-голдены этой команды теряют байт-силу (registry.md).
7. [С] Статусы: спека → «реализовано», галочка здесь и в
   `command-migration.md`; отклонения/улучшения → `../migration-log.md`.

## Фаза 1 — обвязка данных (без неё ни одна сетевая команда)

Порядок жёсткий — каждая ступень нужна следующей:

- [x] **env-file** — слой секретов/подключений: чтение, приоритет
  env → файл → дефолт, атомарная запись.
  Критерий: native-код читает те же ключи, что Python; расхождений нет.
  (2026-08-04: обе golden-пары байт-в-байт; отклонение fix — отказ записи
  при дубликате ключа вместо молчаливой потери оригинала.)
- [ ] **init / update** — bootstrap кэш-БД (SQLite `mpu.db`): схема,
  discovery Portainer, снапшот/точечный синк.
  Критерий: чистая машина → `init` → селектор жизнеспособен.
  Решение по ходу: формат кэш-БД остаётся общим с Python до конца
  переезда (одна БД, две реализации) — миграция схемы запрещена.
- [ ] **selector** — резолв селектора для native-команд.
  Критерий: вердикты и тексты ошибок дословно как у оригинала
  (golden из спеки).
- [ ] **invoke-log** — журнал в обвязке бинаря: обе точки входа, оба
  маршрута; журнал Python-подпроцесса отключается окружением.
  Критерий: одна запись на вызов, TTY-природа перехвата сохранена,
  no-capture список действует.
- [ ] **readonly-default** — read-only PG-сессия (едет вместе с первой
  SQL-командой, отдельной порцией не является).

Критерий выхода фазы: `sql-ro sl-1 "select 1"` native, differential
пуст, запись в журнале одна.

## Фаза 2 — волны команд (порядок и частоты — command-migration.md)

Внутри волны: сначала платформенный атом, затем команды. После каждой
волны — неделя обычной эксплуатации до следующей: журнал вызовов —
детектор регрессий.

- [ ] **SQL**: sql-ro → sql. (Самая ценная: 1225 + 4 вызова/нед.)
- [ ] **logs** (Loki).
- [ ] **Kaiten**: атом kaiten-http → kiten time, card, field, status,
  close, comment, ls, refs, move.
- [ ] **Exec**: атом exec-transport → ssh, run-js, ps, health.
- [ ] **api**: атом slback-http → api, api-wb-loader.
- [ ] **Sheets**: атом webapp-http → sheet, sheet-batch. Здесь же
  решить судьбу ключей `sheet.cache.*` (открытый вопрос config.md).
- [ ] **MR**: атом gitlab-api → mr-read, mr-write, glab-status.
- [ ] **Portainer-обёртки**: атом portainer → portainer-wrappers
  (ss-update и семейство).
- [ ] **Хвост**: search, log (чтение журнала), d2-miro, copy-shared,
  локальный стенд (copy-client, copy-dev, make-schema, mp-init,
  move-client, move-client-back, clean-local-clients).
- [ ] **telegram** — ⚖ точка решения (см. ниже).

### ⚖ Решение: telegram (MTProto)

Варианты, решать при её очереди, не раньше:
(а) native MTProto на TS — полный выезд возможен;
(б) остаётся на Python навсегда — тогда фаза 3 выполняется в редакции
«мост остаётся ровно для telegram», а фаза 4 — не полностью (uv-установка
Python живёт ради одной команды). Записать решение в журнал переезда.

Критерий выхода фазы: в реестре нет команд маршрута `legacy`, кроме
«не едут» и (если вариант б) telegram.

## Фаза 3 — распад моста

Только после того, как фаза 2 закрыта и месяц эксплуатации не выявил
расхождений (журнал + жалобы).

- [ ] [С] Реестр переводится на native-декларации как единственный
  источник: слепок дерева (`tree.json`), `legacy_tree.ts` и манифест
  Python умирают; «не едут»-команды исчезают из дерева (становятся
  обычным unknown command).
- [ ] [D] Удалить маршрут `legacy`, мост-подпроцесс, ключ конфига
  `mcp.legacy_bin`; смоук моста заменить смоуком native-справки.
- [ ] [С] Голдены, снятые с Python (help-list, completion, справки
  legacy-команд), заменить native-эталонами; спека registry.md —
  новый цикл (статус в «черновик» → «к реализации» без legacy).
- [ ] [С] Спеки: убрать оговорки «пока жив Python» (invoke-log про
  confirm, env-file про общую границу, init про общий файл БД).
- [ ] [O] Смоук: полный прогон типовых сценариев недели по журналу.

Критерий выхода: бинарь не запускает Python ни на одном пути;
`grep legacy ts/src` — пусто (кроме истории в docs).

## Сквозные правила

- Одна команда — один цикл — одна сессия; замороженная спека не
  движется (плейбук §7).
- Поведенческая нейтральность до фазы 3: скоуп команды при переезде не
  расширяется; идеи — в журнал.
- Откат всегда жив до фазы 4: `mpu-impl disable` возвращает Python
  целиком; после переключения маршрута одной команды откат — revert
  коммита маршрута.
- Не начинать следующую волну при признаках деградации из плейбука §7.
