# Замер синтаксиса блоков (sonnet), 2026-09-22
Генерация (ru/en): совпало `@x` (в т.ч. в значении ключа), `:=`, ifTrue:ifFalse:, do:/collect:/timesRepeat:; разошлись: блок (`block :c do…end` / `do with: c…end`), разделитель (`then` / `.`), метод. `>` у ru — недопустим в bash.
Слепой замер 10 задач: К1 `do :c … end` — 7/9 в счёт (ошибки: имя метода с `:`; end внутри блока); К2 `block :c … end` — 2/9 (забытый end перед сообщениями результату, @ у переменных, позиционные вызовы).
Выбор: К1. Правила по замеру: слово после end блока-аргумента — результату всего сообщения; внутри блока неявной группы нет; `define:` берёт имя следующим словом как есть; `ask` открывает выражение и внутри блока.
Все токены проверены в bash/fish/nu без кавычек.

## Строки и комментарии (2026-09-22)
Генерация (ru/en): комментарий `rem … end` / `note: … .`; строка `^…^` (приклеенный), `str … end`, «до точки».
Слепой замер 8 задач: В1 `^…^` — строки 7/7 верно, `end` внутри текста без экранирования; В2 `str … end` — строки верно, но `ask` потерян в 6 из 6 записей, неуверенность в счёте вложенных end.
Выбор: текст `^…^`, комментарий `rem … end`, литерал служебного слова `--`. Всё проходит bash/fish/nu без кавычек.
Попутно: `@c.id` через точку (отказ с подсказкой `@c id`); `do: :c` без `do` у обоих → предложение переименовать обход в `each:`.

## each: против do: (2026-09-22)
Полное описание, 6 задач: оба 6/6 по блокам. `each:`-агент поставил `ask` на все 6 строк (5 лишних); `do:`-агент потерял `ask` на записи. Оба склеили `where: … is: … each:` в одно сообщение и оба усомнились. Выбор: `each:` (читаемость). Лишний `ask` на составной строке — не отказ (владелец).
