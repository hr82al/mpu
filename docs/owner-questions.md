6. **Приёмка языка и справка (172+).** Серия 166–171 реализована и

7. **Дыра в правилах (найдено исполнителем в T1, важно).** У команд с
   режимами на входе `selector` режим можно передать ключом `target:`
   (`move-client-back target: rm`, `logs target: ls`) — тогда строка решается
   правилом пути без режима и обходит правило режима (например `ask` у
   записи). В `task` закрыто именем входа. Нужна платформенная порция:
   правило пути режима не должно обходиться ключом. Предлагаю поставить её
   первой после вашего «go» — это граница подтверждения записи.
8. **Живой цикл оркестратора (приёмка T3).** Код принят и установлен,
   `mpu-task` работает вхолостую. Для живого цикла нужны вы — профили ролей
   пишет только человек. Шаги (через MCP вам придут окна Accept, или в
   терминале ответ `y`):
   `mpu ask task setup project: toy note: ^проба оркестратора^`;
   `mpu task role project: toy role: exec dir: /home/user/mr/mp/tmp/toy/ts model: sonnet powers: ^только проба: echo, никаких правок^`;
   `mpu task role project: toy role: host dir: /home/user/mr/mp/tmp/toy model: sonnet powers: ^только проба^`.
   Дальше хост сам: `task post` игрушечной постановки, смотрит, как
   оркестратор открывает окна `toy-exec`/`toy-host`, будит, чистит; роняет
   окно; перезапускает службу; затем `task stop` и `role forget`.
   Скажите «готов к живому циклу» — проведу вместе с вами.
