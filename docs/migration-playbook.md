# Плейбук оператора: переезд через изолированные сессии

Пошаговый план для человека, ведущего переезд `mpu` с Python на Deno/TS.
Не для ИИ: правила для сессий лежат в `ts/CLAUDE.md` и `ts/docs/CLAUDE.md`,
архитектура — в `docs/ts-mcp-architecture.md`, фазы и их порядок — в
`docs/plans/2026-08-04-full-migration.md`. Здесь — что делаешь ТЫ, в каком
порядке и что контролируешь, чтобы код вышел максимально читаемым и
качественным.

## 0. Конвейер одним абзацем

Каждая порция работы проходит один и тот же цикл: **(1)** спецификатор
(обычная монорепо-сессия в `mpu/`) снимает спеку и golden с живой
Python-версии и морозит её («к реализации») → **(2)** изолированная
Deno-сессия реализует строго по спеке, не видя ни Python, ни план →
**(3)** ты читаешь код глазами и гоняешь гейты → **(4)** спецификатор
прогоняет differential со старой версией → **(5)** маршрут команды в
реестре переключается с `legacy` на `native`, py-код удаляется. Качество
держится на трёх вещах: замороженная спека, изоляция от легаси и твоё
чтение каждого модуля целиком.

## 1. Одноразовая подготовка (проверь, что готово)

- [x] Изоляция настроена: `mpu/.claude/settings.json` — песочница на
  **корень `mpu`**, с `denyRead` на `docs/` (и на `py/`, пока он был). Именно на
  корень, а не на `ts/`: `git` внутри `ts/` не работает — `.git` лежит
  уровнем выше, и при песочнице на `ts/` любая запись в индекс падает.
- [x] Хук на `git add`/`commit` без pathspec: закрытые каталоги выглядят
  для git удалёнными, и массовая операция закоммитила бы их удаление.
  Сессии обязаны писать `git commit … -- ts/`.
- [x] Сеть песочницы ограничена `deno.land`, `jsr.io`, `registry.npmjs.org`
  — ровно то, что нужно резолверу зависимостей.
- `ts/.claude/lock.sh` остался от прежней схемы изоляции и ни на что не
  влияет. Настройки — только в `mpu/.claude/settings.json`.

## 2. Порядок работ

Ведётся планом `docs/plans/2026-08-04-full-migration.md`: там фазы с
ролями (**[С]** спецификатор, **[D]** изолированная сессия, **[O]** ты),
критериями выхода и точками решения; порядок команд внутри фаз —
`docs/plans/command-migration.md`. План — единственный источник «что
дальше»; дублировать его список сюда бессмысленно, он движется.

Что важно понимать про форму MVP: команды переезжают **не по одной с
нуля**. Сначала поднимается каркас (контракт команды, реестр, MCP-ядро,
транспорт), затем все ещё не переехавшие команды разом становятся
доступны через маршрут `legacy` — вызовом установленной Python-версии
подпроцессом. С этого момента система живёт целиком, и перевод каждой
следующей команды на `native` — независимая, ничего не ломающая работа.

## 3. Как запускать изолированную сессию

- Запуск **из корня `mpu`**, не из `ts/`:

  ```bash
  cd /home/user/mr/mp/mpu && claude "$(cat ~/tmp/taskN-prompt.txt)"
  ```

- Первой репликой — smoke-проверка изоляции: попроси прочитать
  `docs/plans/command-migration.md`; должен быть отказ. Читается — стоп,
  чинить окружение, а не работать. (Прежде проверка шла на
  `py/pyproject.toml`; каталога больше нет с 2026-08-31.)
- Постановку задачи готовит спецификатор в файл `~/tmp/taskN-prompt.txt`.
  Своими словами поведение не пересказывай: всё поведение — в спеке,
  пересказ протаскивает легаси мимо канала.
- Одна задача — одна сессия. Задача не влезает в сессию — это дефект
  постановки: верни спецификатору дробить, не растягивай реализацию на
  две сессии (главный источник деградации качества).
- Вопросы сессии о поведении — не отвечай из головы. Ответ всегда один:
  спецификатор правит спеку (статус вернётся в «черновик»), сессия
  перечитывает. Раньше сюда добавлялось «и не подглядывай ей в `py/`» —
  подглядывать больше некуда, а правило осталось тем же. Устные ответы мимо спеки
  превращают контракт в фольклор.

## 4. Что контролируешь ты (и никому не делегируешь)

- **Читать каждый модуль целиком, глазами, от первой до последней
  строки.** Не прочитал — не мержится. «Потом отрефакторю» не работает:
  по плохому модулю через неделю написаны пять таких же.
- **Первые три модуля — эталоны**: итерируй сколько угодно раз, пока код
  не начнёт нравиться безоговорочно; потом пометь эталоном в
  `ts/CLAUDE.md`. Все следующие задачи ставятся «в стиле эталона» —
  качество эталонов определяет качество всего дерева.
- **Не принимай отчёт без фактических выводов гейтов** (не «всё
  зелёное», а вывод команд). Раз в сессию выборочно перепроверь одно
  утверждение руками — сессии быстро учатся тому, что проверяешь.
- **Замечания возвращай в ту же сессию** («в файле X строка Y — так не
  пойдёт, потому что Z; перепиши») вместо правки своими руками: твоя
  ручная правка не проходит гейты сессии и размывает единый стиль.
- **Скоуп-контроль**: «раз уж переписываю, заодно…» — нет. Идеи
  улучшений — в отчёт и в журнал переезда, в код — отдельной задачей.
- **Код не нравится в целом — выброси и переиграй** сессию с уточнённой
  спекой/постановкой. Переигровка стоит дешевле, чем спасение среднего
  кода правками: спасённый код становится эталоном для следующих.

## 5. Между сессиями (шляпа спецификатора)

- Differential: живая Python-версия и новая на одних входах, диф пуст.
  Ожидаемые расхождения — только из раздела «Известные отклонения»
  спеки; принятое улучшение — запись в журнал переезда
  (`docs/migration-log.md`, заводится при первой записи).
- Статусы: спека и галочки задачи в плане — сразу после приёмки, иначе
  план и дерево разъедутся молча.
- Переключение маршрута в реестре и удаление Python-версии команды —
  одним коммитом.
- Термины из отчёта сессии — в `ts/docs/glossary.md`.

## 6. Шпаргалка гейтов

```bash
cd mpu/ts && deno fmt --check && deno lint && deno check . && deno test --coverage=cov
```

Санитайзеры тестов не отключаются; `any` запрещён; покрытие затронутых
модулей не падает. Полные правила — `ts/CLAUDE.md`.

Гейты злее, чем комфортно, — это осознанно: ослабить успеешь всегда,
ужесточить по факту 20 нарушений — уже нет.

## 7. Ритм и стоп-краны

- Одна задача за раз, до приёмки. Параллелить сессии можно только после
  того, как эталоны зафиксированы.
- Одна хорошо сделанная команда лучше десяти транслитерированных —
  скорость не цель.
- Замороженная спека не движется. Захотелось поменять по ходу
  реализации — это новый цикл: статус в «черновик», сессию — заново.
- Признаки деградации, при которых остановиться и разобраться: файлы
  подпирают лимит строк, в отчётах «покрою позже», сессия предлагает
  «временно упростить» гейт или пишет тест, про который сама знает, что
  он проверяет не то.
