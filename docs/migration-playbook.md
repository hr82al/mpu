# Плейбук оператора: переезд через изолированные сессии

Пошаговый план для человека, ведущего переезд. Не для ИИ: правила для
сессий лежат в `go/CLAUDE.md` / `ts/CLAUDE.md` / `*/docs/CLAUDE.md`,
процедура и гейты — в `docs/go-migration.md` и `go/docs/implementation.md`.
Здесь — что делаешь ТЫ, в каком порядке и что контролируешь, чтобы код
вышел максимально читаемым и качественным.

## 0. Конвейер одним абзацем

Каждая команда проходит один и тот же цикл: **(1)** спецификатор
(обычная монорепо-сессия в `mpu/`) снимает спеку и golden с живой
Python-версии и морозит её («к реализации») → **(2)** изолированная
сессия (`go/` для операций брокера, `ts/` для CLI) реализует строго по
спеке, не видя ни Python, ни соседний канал → **(3)** ты читаешь код
глазами и гоняешь гейты → **(4)** спецификатор прогоняет differential
со старой версией → **(5)** маршрут в реестре переключается, py-код
удаляется. Качество держится на трёх вещах: замороженная спека,
изоляция от легаси и твоё чтение каждого пакета целиком.

## 2. Порядок фаз

1. **`xlsx` в ts-сессии** — первый вертикальный срез CLI. Без сети и
   брокера, спека и golden готовы. Смысл — проверить весь харнесс
   качества (гейты, TDD, твоё ревью) на самой простой команде, до того
   как появится что-то сложное.
2. **Скелет брокера в go-сессии** — HTTPS + JSON-RPC + `auth.login` +
   `core.version` по `specs/protocol/core.md` (заморожена, 9 контрактных
   пар). Перед стартом реши открытые вопросы: формат учёток в `.env`
   (открытый текст или хэш) и TTL токена — сессия иначе остановится
   спросить.
3. **Делегация**: спецификатором написать `specs/protocol/legacy.md`
   (форма операции `legacy.run`: поля, кадрирование потоков, стриминг —
   главный нерешённый кусок протокола) → реализовать
   `legacy-delegation` в go-сессии → **реестр CLI** в ts-сессии (спека
   `registry` заморожена) → сквозной тест: любая не переехавшая команда
   работает через `mpu` end-to-end. С этого момента система живёт, и
   каждая следующая команда — просто перевод маршрута.
4. **Остальная обвязка** по мере надобности команд: selector, config
   (обе стороны), invoke-log — черновики согласованы, каждому нужны
   доморозка и golden.
5. **Команды по частоте** (`go/docs/plan.md`): `sql-ro` первым, дальше
   сверху вниз. На каждую — полный цикл из §0.

## 3. Как запускать изолированную сессию

- `cd mpu/ts && claude` (или `mpu/go`). Первой репликой — smoke-проверка
  изоляции: попроси прочитать `../py/pyproject.toml`; должен быть отказ.
  Если читается — стоп, чинить окружение, а не работать.
- Постановка задачи — одной фразой, без пересказа поведения (всё
  поведение — в спеке; перескажешь своими словами — протащишь легаси
  мимо канала):

  > Реализуй спеку `docs/specs/xlsx.md` по TDD. Гейты из CLAUDE.md
  > должны быть зелёными фактически. Отчёт — по формату из CLAUDE.md.

- Одна спека — одна сессия. Спека не влезает в сессию — это дефект
  спеки: верни спецификатору дробить, не растягивай реализацию на две
  сессии (главный источник деградации качества).
- Вопросы сессии о поведении — не отвечай из головы и не подглядывай ей
  в `py/`. Ответ всегда один: спецификатор правит спеку (статус
  вернётся в «черновик»), сессия перечитывает. Устные ответы мимо спеки
  превращают контракт в фольклор.

## 4. Что контролируешь ты (и никому не делегируешь)

- **Читать каждый пакет целиком, глазами, от первой до последней
  строки** (§3.6 правил переезда). Не прочитал — не мержится. «Потом
  отрефакторю» не работает: по плохому пакету через неделю написаны
  пять таких же.
- **Первые три пакета каждой стороны — эталоны** (§5): итерируй сколько
  угодно раз, пока код не начнёт нравиться безоговорочно; потом пометь
  эталоном в `CLAUDE.md` модуля. Все следующие задачи ставятся «в стиле
  эталона» — качество эталонов определяет качество всего дерева.
- **Не принимай отчёт без фактических выводов гейтов** (не «всё
  зелёное», а вывод команд). Раз в сессию выборочно перепроверь одно
  утверждение руками — сессии быстро учатся тому, что проверяешь.
- **Замечания возвращай в ту же сессию** («в файле X строка Y — так не
  пойдёт, потому что Z; перепиши») вместо правки своими руками: твоя
  ручная правка не проходит гейты сессии и размывает единый стиль.
- **Скоуп-контроль**: «раз уж переписываю, заодно…» — нет. Идеи
  улучшений — в отчёт и в `go/docs/MIGRATION.md`, в код — отдельной
  задачей после переезда команды.
- **Код не нравится в целом — выброси и переиграй** сессию с уточнённой
  спекой/постановкой. Переигровка стоит дешевле, чем спасение среднего
  кода правками: спасённый код становится эталоном для следующих.

## 5. Между сессиями (шляпа спецификатора)

- Differential: старая и новая версия на одних входах, диф пуст.
  Ожидаемые расхождения — только из «Известных отклонений» спеки;
  принятое улучшение — запись в `go/docs/MIGRATION.md`.
- Статусы: спека и строка в `go/docs/plan.md` → «реализовано» — сразу,
  иначе план и дерево разъедутся молча.
- Переключение маршрута в реестре CLI и удаление Python-версии команды —
  одним коммитом.
- Терины из отчёта сессии — в `glossary.md` канала.

## 6. Шпаргалка гейтов

- **go**: `gofmt -l . && go vet ./... && staticcheck ./... && go test
  -race -count=1 ./...`; покрытие ≥ 80 % и только вверх; файл ≤ 300
  строк, функция ≤ 60, цикломатика ≤ 10; `//nolint` только с причиной
  в той же строке. Полные пороги — `go/docs/implementation.md`.
- **ts**: `deno fmt --check && deno lint && deno check . && deno test
  --coverage=cov`; санитайзеры тестов не отключаются; `any` запрещён.
  Полные правила — `ts/CLAUDE.md`.
- Гейты злее, чем комфортно, — это осознанно: ослабить успеешь всегда,
  ужесточить по факту 20 нарушений — уже нет.

## 7. Ритм и стоп-краны

- Одна команда за раз, до «реализовано». Параллелить сессии можно
  только после того, как эталоны обеих сторон зафиксированы.
- Одна хорошо сделанная команда в неделю лучше десяти
  транслитерированных — скорость не цель (§9 правил переезда).
- Замороженная спека не движется. Захотелось поменять по ходу
  реализации — это новый цикл: статус в «черновик», сессию — заново.
- Признаки деградации, при которых остановиться и разобраться: растут
  `//nolint`, файлы подпирают лимит строк, в отчётах «покрою позже»,
  сессия предлагает «временно упростить» гейт.

## 8. Ближайшие шаги (на сегодня)

1. Внешним терминалом — контрольный прогон ts-изоляции (§1).
2. `cd mpu/ts && claude` → smoke изоляции → отдать `xlsx` (§3).
   Итерировать до эталона; пометить эталоном.
3. Спецификатором: решить учётки/TTL (два вопроса в
   `specs/protocol/core.md`), написать `specs/protocol/legacy.md`.
4. `cd mpu/go && claude` → скелет брокера по `protocol/core`.
   Итерировать до эталона.
5. Дальше — §2, фаза 3.
