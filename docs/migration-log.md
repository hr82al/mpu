# Журнал переезда

Учёт решений переезда Python → Deno/TS: что умирает вместе с Python,
принятые расхождения differential-сверки, идеи улучшений из отчётов
изолированных сессий. План команд — `plans/command-migration.md`.

## Умрёт вместе с Python (решение 2026-07-27)

- **ozon-fix-fo-tax** — data-fix одного инцидента (источник 1 ₽ в
  ОПиУ/Фин отчёте SKU); сценарий исчерпан.
- **backup-wb-unit-proto**, **backup-ozon-unit-proto**,
  **backup-wb-unit-manual-data** — CTAS-бэкапы под конкретные
  ремедиации; при нужде бэкап делается штатным SQL (`CREATE TABLE … AS
  SELECT`), отдельные команды не оправданы.
- **wb-unit-proto-new** — разовая миграция старой
  `wb_unit_proto`-таблицы; выполнена.
- **sun** — восход/закат/зенит; вне домена mpu.
- **process, ss-load, ss-datasets, wb-unit-calc, wb-jobs, iu-wb,
  ozon-loader, ozon-jobs, data-loader-jobs, users, clients-migrations,
  datasets-migrations, app-migrations** — Portainer-обёртки над
  `node cli service:*` без вызовов за доступное окно журнала; при
  реальной нужде тот же вызов доступен как `node cli …` через `ssh`,
  отдельная команда на каждую не оправдана.
- **confirm** — вспомогательный pipe-фильтр подтверждения; без вызовов,
  шаблон использования не прижился.
- **kiten field ls / update / rm** (решение 2026-08-06, дизайн
  `plans/2026-08-06-kiten-core-redesign.md`) — три подкоманды поверх
  локального журнала значений полей. Журнал существовал ради них, а сам
  порождал дефект: правка или удаление несвежей записи отправляли на
  карточку значение той записи, а не то, которое трогали. Значение поля
  живёт на карточке, история правок — в самой Kaiten; локальная копия
  наружу не наблюдаема и переезду не подлежит. Остаётся `field set` —
  пишет переданное значение напрямую. Это и есть вердикт **fix** в
  «Известных отклонениях» спеки `specs/kiten-field.md`: у команды больше
  нет иного пути изменить поле.

## Заметки к будущим решениям

- PG-драйвер (решено 2026-08-05, живая проверка трёх кандидатов на
  PostgreSQL 16): взят `npm:pg` (node-postgres). Родной для Deno
  `jsr:@db/postgres` отвергнут не по вкусу, а по дефекту: на
  многооператорном тексте он не падает и не отдаёт наборы раздельно, а
  склеивает строки под именами колонок ПЕРВОГО оператора —
  «SELECT 1 AS a; SELECT 2 AS b» даёт `[{a:1},{a:2}]` при `rowCount:1`,
  то есть правдоподобную, но неверную таблицу. `npm:postgres`
  требованиям удовлетворяет (наборы раздельно, старт на ~40 мс быстрее),
  но многооператорный путь у него — отдельный метод `unsafe`, тогда как
  у `pg` это обычный `query()`. Общее для обоих npm-кандидатов: право на
  переменные окружения сужается до `--allow-env=PG*` (проверено), полный
  список PG-переменных стабильным контрактом не является.
- sql-ro (2026-08-05): при заморозке первой порции снят и закреплён
  контракт `;`-склейки — печатается result set **первого** оператора,
  причём печать начинается только после успешного выполнения всего
  текста (ошибка второго оператора гасит вывод первого). Маршрут sw
  оригинала печатает последний — расхождение помечено `fix` в
  `specs/sql-sw.md` и станет расхождением сверки, когда тот маршрут
  поедет. Там же — второй `fix`: префикс sw-ошибок в оригинале всегда
  `mpu sql sw:`, независимо от вызванной команды.
- telegram (обсуждено 2026-08-05, решение — при очереди команды): если
  Python выводится из эксплуатации целиком, замена Telethon —
  **`gramjs`** (npm-пакет `telegram`), прямой порт Telethon на TS с
  почти тем же API (`TelegramClient`, `StringSession`,
  `Api.contacts.Search`, `FloodWaitError`), поэтому 1204 строки нашего
  кода маппятся почти механически. Идея «взять нативные библиотеки
  Telethon» отпадает фактически: у Telethon их нет — зависимости
  `pyaes` и `rsa` чистый Python, MTProto реализован в самом пакете,
  нативный `cryptg` опционален и у нас не установлен. FFI к
  `libtdjson.so` (TDLib) снят с рассмотрения: `deno compile` не вшивает
  `.so` — бинарь перестаёт быть самодостаточным, `--allow-ffi` обходит
  всю модель прав, а переписывать пришлось бы с нуля (у TDLib своя
  модель авторизации и своя база на диске). Главный риск живучести — не
  библиотека, а TL-layer Telegram (меняется несколько раз в год),
  поэтому обязательна изоляция: команда ходит в Telegram только через
  атом `platform/telegram-mtproto`, смена библиотеки тогда стоит
  переписывания атома, а не команды. Отдельная разовая цена порта:
  StringSession Telethon и gramjs — разные форматы, потребуется
  повторная авторизация с телефоном и 2FA (человеком, не постановкой).
  Альтернатива решения — оставить команду на маршруте `legacy`
  навсегда; тогда она вычёркивается из плана переезда.
- env-file (2026-08-04): в собранном бинаре `--allow-env` перечисляет
  имена списком — чтение значений ключей слоя (`sl_<N>`, `pg_<N>`,
  `PG_*`, `DEV_*`, `MPU_LOG_*`) упрётся в право; запись при нестандартном
  `XDG_CONFIG_HOME` выйдет за `--allow-write=$HOME/.config/mpu`. Решение
  о форме прав — вместе с первой командой-потребителем слоя (sql-ro);
  напоминание — комментарием в `ts/deno.jsonc`.

## Идеи улучшений (из отчётов изолированных сессий, отдельными задачами после)

- `ts/CLAUDE.md`, раздел логирования: добавить правило «ошибку либо
  логируют, либо возвращают» — выпало при адаптации правил отменённой
  редакции; файл ведёт Deno-сессия, вносить через её задачу
  (замечено верификацией переноса 2026-08-04).
- `ts/CLAUDE.md`, блок «Команды»: строки `deno test` и
  `deno test path/to/x_test.ts --filter "имя"` страдают тем же дефектом,
  что исправленная строка гейта, — без прав задачи `test` падают 343
  теста из 576. Файл ведёт Deno-сессия: хвост следующей порции, одна
  строка на каждую (замечено приёмкой порции каталога справочников
  2026-08-14).
- Снапшоты публикуемых тулов (`ts/src/mcp/testdata/tools-{ro,rw}.json`)
  пересобираются разовым скриптом, повторяющим сборку из
  `invariants_test.ts`. Просится задача `deno task tools:snapshot` —
  завести в ближайшей порции, которая меняет состав тулов.
- Описание тула `kiten_card` — 1962 байта при пределе клиента 2048;
  второй по длине (`sheet_batch_get`) — 2036. Запас исчерпан: следующая
  правка справки обрежется молча. Нужна проверка длины описания в
  инвариантах MCP, а не глазами (замечено приёмкой порции 19).
- `Card.state` и `Card.condition` при отсутствии значения становятся
  `0` (`numberOrNull(raw.state) ?? 0`). Живой ответ их всегда несёт, но
  подмена нулём скрывает пустоту: `condition: 0` сервер не присылает.
  Решать вместе с ревизией формы «Карточка (список)».
- Дополнение внутри частично переехавшей группы (`mpu kiten <TAB>`)
  предлагает только нативные листья: соседи в реестре не заведены —
  машинный слепок отдаёт группу одной записью, без листьев. Полный
  список появится, когда слепок начнёт отдавать листья группы; до тех
  пор неполнота — ожидаемое состояние переезда (зафиксировано в
  `specs/platform/registry.md`, замечено приёмкой порции 19).
- `ts/src/kaiten/kaiten_test.ts` — локальный `fakeServer` дублирует
  общий тестовый стенд `ts/src/kaiten/testing.ts`, появившийся позже.
  Слияние — отдельной задачей: существующие тесты переписывать «под
  новый стиль» правилами модуля запрещено (там же).

## Платформенные факты (атомам не переоткрывать)

- **Живые MCP-клиенты не говорят ревизию `2026-07-28`** — Claude Code
  2.1.223 шлёт классический `initialize` без `MCP-Protocol-Version` и
  `Mcp-*`-заголовков и получал 400 (`-32020`) на каждом подключении,
  сервер был для агента недостижим. 2026-08-06 в сервер дописано
  классическое рукопожатие (`initialize`/`ping` + общие
  `tools/list`/`tools/call`; спека `platform/mcp-server.md`, раздел
  «Классическое рукопожатие»). Правка сделана из основной сессии, вне
  цикла постановок, — hotfix доступности; спека выровнена тем же днём.
  Снять совместимость — когда клиенты заговорят `2026-07-28`.
- **Клиент PostgreSQL (`npm:postgres` 3.4.x) безусловно читает
  `PGAPPNAME`** — до слияния своих умолчаний с переданными опциями, и
  без права на эту переменную не создаётся вовсе (`NotCapable`).
  Отсюда единственное имя вне служебного списка `--allow-env`; наш
  явный `application_name` перекрывает прочитанное, поэтому экспорт
  переменной в shell на поведение не влияет (проверено сверкой с
  исходником драйвера и smoke-сценарием, 2026-08-05). Прочие его
  переменные (`PGMAX`, `PGCONNECT_TIMEOUT`, …) подавлены передачей
  всех опций явно.
- **Пределы PG-обращений update (5000 ms соединение / 20000 ms
  запрос) выбраны без замера** — по аналогии с HTTP-пределами init и с
  запасом на тяжёлые выборки `public.clients`/`public.spreadsheets`.
  Уточнить замером на стенде при переезде `sql-ro`, где те же пределы
  окажутся на горячем пути (1225 вызовов/нед.).
- **Отключение проверки TLS-сертификата в Deno недостижимо через
  `fetch`**: у `Deno.createHttpClient` нет опции, гасящей проверку;
  `NODE_TLS_REJECT_UNAUTHORIZED` на `fetch` не влияет (проверено
  порцией А init, 2026-08-05). Рабочий путь — `node:https` с
  `rejectUnauthorized: false`, только для схемы `https:` и только при
  явно отключённой проверке (`PORTAINER_VERIFY_TLS`). Следующим
  HTTP-атомам (Loki, Kaiten) этот вопрос не переоткрывать.
- **Порт исполнения команды сужается срезами (решение 2026-08-15).**
  `CommandIo` собрал десять разнородных возможностей, и ни один из 51
  потребителя не объявляет нужный ему минимум (`Pick<CommandIo, …>` — 0
  совпадений). Решено сузить **везде** отдельной порцией-переукладкой, после
  резки длинных функций; правки спеки это не требует —
  `platform/command-contract.md` про форму типов молчит намеренно, а само
  правило стоит в `ts/CLAUDE.md` («Типы и API»). Разбор — `ts/docs/readability.md`,
  §6; очередь — там же, §8, порция J.
- **`kiten field` публикуется тулами (решение 2026-08-15).** Постановка порции 20
  ошибочно считала, что состав профиля `rw` меняют обе команды; фактически
  закрытый список не называл ни одного листа `field`, и правило fail-closed
  оставило команду без тула. Три листа (`field set`, `field artefact set`,
  `field artefact rm`) внесены в `rw` и `destructive` закрытого списка;
  снапшоты пересобираются задачей `tools:snapshot`, не руками.
- **`--to ''` у `kiten comment` — адресатов нет.** Спека молчала, реализация
  считает адресатов токенами значения, а не фактом наличия флага; закреплено
  в `kiten-comment.md`, «Граничные случаи». Без текста это exit 2 до сети —
  тот же отказ, что и без флага вовсе.
- **Локальная подсказка таймера не воскрешается (решение 2026-08-16).** Рабочая
  версия держала в кэш-БД строку «где идёт таймер» и потому называла карточку
  при конфликте `start`. Проба показала, что из API этого не узнать никак: поле
  `timer` отдаёт только своя карточка (при таймере на A чтение B даёт `null`),
  списка таймеров нет. Решено не заводить локальное состояние ради одной ветви:
  она честно сообщает «таймер идёт на другой карточке, найди в интерфейсе» и
  остаётся единственным местом вывода без готовой команды. Цена названа в
  `kiten-time.md`, «Известные отклонения»; паритет вернётся только вместе с
  хранилищем, отдельной порцией и по отдельному решению.
- **Объявленный вид адресата — исключение из второй попытки; телефон в нём
  (решение 2026-08-17).** Резолв строки идёт двумя попытками (штатный резолв →
  поиск чата по названию), и вопрос порции 29 был про телефон: спека выносила в
  исключение только `@` и ссылку `t.me`, поэтому `+79990000000` при неудаче
  уходил текстом в поиск по названию, а ответ Telegram про номер подменялся на
  «не удалось найти чат '+7999…': совпадений нет». Признак исключения — не вид
  строки, а **объявление вида пользователем**: `+` объявляет телефон так же, как
  `@` объявляет имя. Строка из одних цифр сюда не относится — она уходит
  числовым id ещё нормализацией. `platform/telegram-mtproto.md` правлена и
  возвращена в «к реализации» до посадки хвоста.
- **Поиск сообщений: фильтр по отправителю есть только у внутричатового поиска
  (проверено 2026-08-17).** У глобального поиска параметра отправителя нет
  вовсе, поэтому `--from` без `--chat` — фильтр на стороне команды поверх
  глобальной выдачи, с потолком просмотра. Это ограничение внешней системы, а не
  выбор реализации; в `telegram-search.md` оно записано как `preserve`, а молчание
  прежней версии при исчерпании потолка — как `fix` (предупреждение в stderr).
- **Клиентский фильтр `--from` доходит глубже прежней реализации при том же
  потолке (замер 2026-08-17).** На одном и том же глобальном запросе новая
  реализация вернула 195 сообщений против 42 у рабочей версии — надмножество,
  все от одного отправителя, глубина по времени апрель против июля при
  одинаковом потолке в 1000 просмотренных. Прежняя выдача обрывалась молча;
  расхождение принято как улучшение, а не как дрейф контракта, и именно оно
  стоит за вердиктом fix «предупреждение при недоборе».
- **Предел сообщения Telegram меряется кодовыми единицами UTF-16 (решение
  2026-08-17).** Спека `telegram-status.md` говорила «4096 символов», и
  реализация честно считала кодовые точки. Внешняя система считает длину и
  смещения разметки в кодовых единицах UTF-16, то есть эмодзи вне основной
  плоскости стоит два: счёт точками выпускает сообщение длиннее предела, и
  отказ приходит уже от Telegram — после того, как отчёт собран. Контракт
  уточнён, правка едет хвостом.
- **Намерение `--dry-run` печатает разрешённое название колонки, а не подстроку
  ввода (замер 2026-08-17).** Голдены `kiten-move` снимались без `--column`, где
  подстрока и название совпадают, поэтому разница вскрылась только на сверке:
  `ready <id> --column выполненные --dry-run` у рабочей версии даёт
  `→ «выполненные»`, у новой — полное название колонки. Приведено вердиктом
  `fix`: dry-run существует затем, чтобы увидеть результат резолва, а подстрока
  видна в самой команде. Голден на этот случай кладётся вместе с постановкой,
  которая заказывает тест.
- **Мутирующая ветка `kiten move` живьём не прогнана (2026-08-17).** Релог на
  своей карточке был подготовлен, но запуск мутации в этой сессии не разрешён
  средой; чужие рабочие карточки трогать нельзя по постановке. Ветка закрыта
  тестами на фейковом Kaiten и мутационными проверками порции; живой прогон
  (релог, `--board`, строка журнала и дневная сводка после них) остаётся за
  оператором. Заодно с ним закрывается непроверенный с порции 32 непустой отчёт
  `telegram status`.
- **`PGOPTIONS` доезжает до пишущей сессии — свойство оригинала, не дефект
  переезда (разобрано 2026-08-17).** Драйвер подставляет переменную окружения
  в стартовый пакет, когда своих опций ему не дали, а у `mpu sql` их нет по
  контракту; у `sql-ro` фолбэк закрыт побочно — непустой строкой
  `-c default_transaction_read_only=on`. Оригинал устроен так же (опции
  передаются только на read-only-пути), поэтому симметрию не наводим:
  закрыть можно лишь добавив пишущей сессии параметр стартового пакета,
  которого у неё нет, вместе с ценой «отказ пулера». Записано `preserve`.
- **Инвариант «частичной записи не бывает» имеет одно исключение — текст,
  управляющий транзакцией сам (2026-08-17).** Собственный `COMMIT` внутри
  SQL закрывает транзакцию вызова, и написанное до него остаётся в БД, даже
  если следующий оператор упадёт. У read-only-сессии такой обход упирается в
  метку сервера, у пишущей ловить нечем по построению; оригинал ведёт себя
  так же (неявная транзакция драйвера с фиксацией на выходе). Формулировка
  инварианта уточнена, вердикт `preserve`.
- **`mpu ssh`: отказа «нет селектора» не существует (замер 2026-08-17).**
  Первый позиционный токен всегда становится селектором, поэтому состояние
  «команда есть, селектора нет» недостижимо: `mpu ssh -- echo x` уходит
  резолвить клиента по слову `echo`. Голый `mpu ssh` отказывает про пустую
  команду — эта проверка раньше всех прочих, а взаимоисключение источников
  stdin проверяется уже после селектора и команды. Текст «укажите <selector>
  или --all-containers» из спеки убран, чтобы реализация не писала мёртвую
  ветку.
- **Общая форма вывода `--json` не применяется к команде, забирающей чужую
  командную строку (решено 2026-08-17).** У `mpu ssh` хвостовой вход берёт
  неопознанные токены, поэтому перехват `--json` точкой входа съедал бы флаг
  удалённой команды (`mpu ssh sl-1 mycli --json`), а печать JSON поверх уже
  вылившихся в stdout байтов давала бы непарсимый поток. Структурной формы у
  такой команды нет и быть не может; код выхода остаётся её собственным.
  Оригинал `--json` у `ssh` не имел вовсе. Правило внесено в
  `platform/registry.md` и `platform/command-contract.md` как второе исключение
  рядом с «команда объявила собственный вход с этим именем».
- **Вывод удалённой команды идёт в stdout — исключение из инварианта 1
  контракта команд (2026-08-17).** Инвариант отправляет в stderr всё, что не
  проекция результата, потому что имел в виду диагностику хода исполнения. Байты
  чужой команды — данные вызова: `mpu ssh … | wc -l` обязан видеть их так же,
  как прямой вызов. Порт вывода отдельный, исполнение по-прежнему не печатает.
- **stdin из пайпа читается байтами (2026-08-17).** Оригинал отдаёт сырые байты;
  реализация переезда декодировала пайп в UTF-8, из-за чего двоичный вход
  (`cat archive.gz | mpu ssh … -- gunzip`) портился молча. Требование байтового
  чтения внесено в `platform/command-contract.md`; правка порта io заказана
  следующей порцией. `--stdin-file` дефекту не подвержен — он всегда читал байты.
- **Явный `--via` без соответствующего доступа отказывает про запрошенный
  транспорт (2026-08-17, вердикт `fix`).** Оригинал доверял явному значению без
  проверки и обрывался необработанным исключением в глубине вызова; общий текст
  «не задано ни sl_N ни sl_N_portainer» вводит в заблуждение ровно тогда, когда
  второй транспорт задан. Тем же вердиктом закрыт ambiguous внутри
  `--all-containers`: обход прерывается тем же отказом, что и путь точного
  имени, — молча взять первого кандидата у мутирующей команды дороже.
- **Спеки разошлись о строке `mpu: detached, log=…` (разрешено 2026-08-17).**
  Транспортная спека с 2026-08-04 держит вердикт `fix`: launch фонового
  запуска идёт без `echo`, статус печатает CLI. Дописывая `run-js.md`, я внёс
  туда описание оригинала — «Portainer-путь печатает эту строку», — то есть
  противоречие собственному вердикту. Реализация пошла по транспортной спеке и
  была права; строка из `run-js.md` убрана. Урок общий: дословный замер
  оригинала не переписывается в спеку прежде, чем сверен с уже вынесенными
  вердиктами соседних спек.
- **«Игнорируется» — про смысл параметра, не про проверку значения
  (2026-08-17).** `--jobs` без `--parallel` ни на что не влияет, но негодное
  значение (`-j abc`) остаётся ошибкой ввода: молча принимать заведомо мусорный
  вход команда не должна. Формулировка спеки уточнена.
- **Тип входа объявляется доменным, а не транспортным (решено 2026-08-17).**
  Логические входы уже публикуются в схеме тула как `boolean`, а числовые
  (`logs --tail`, `run-js --jobs`) — строкой, поэтому агент обязан слать `"2"`
  вместо `2`, и опечатка типа ловится текстом отказа команды вместо схемы.
  Правило внесено в контракт команд; перевод существующих числовых входов —
  отдельной порцией. Диапазон и целочисленность остаются за командой.
- **Фильтр подстроки экранируется (2026-08-17, вердикт `fix`, порция принята).**
  Значение `--filter` уходило в `LIKE` без экранирования, поэтому `_` работал как
  «любой символ», а `%` — как «что угодно»: `sl_1` ловил `sl-1`, и совпадение
  выглядело удачей. Для fan-out живых команд (`ssh`, `run-js` с обходом
  контейнеров) это чужой контейнер в обходе прод-фермы. Экранируется и сама
  обратная косая — иначе фильтр `back\` менял бы выборку следующим символом.
- **Приведение числового входа — только десятичная запись (2026-08-17).**
  Числовые входы объявлены числами, приведение текста argv делает слой схемы.
  Правило доопределено после приёмки: язык реализации считает числом и `0x10`, и
  `1e3`, и значение в пробелах, а командная строка — не выражение языка; в
  оригинале `--tail 0x10` был ошибкой ввода, а не шестнадцатью строками. Прочие
  записи остаются текстом и отвергаются схемой.
- **«Предела нет» выражается отсутствием предела (2026-08-17).** У запроса логов
  контейнера предела чтения нет — реализация выразила это огромным числом, а
  таймер среды обрезает срок до собственного потолка, так что каждый tail отвечал
  бы мгновенным отказом «нет ответа за 9007199254740991 мс». Подставной клиент
  логов этого не показывал. Отсутствие предела с тех пор — отдельное значение, а
  непредставимый срок отвергается; правило внесено в `specs/health.md`.
- **Регистр фильтра подстроки: одинаково в обоих режимах (2026-08-17, `fix`).**
  У `ps` кэш-режим сравнивал без учёта регистра (свойство `LIKE`), живой — с
  учётом, поэтому `--filter WB-LOADER` находил контейнер в кэше и не находил его
  же на ферме. Один флаг одной команды не может значить разное; приводится живой
  режим — сужать кэш означало бы ничего не найти по набранному заглавными.
- **Пустые строки `health` доопределены (2026-08-17).** Голденов вывода у команды
  нет и быть не может (состояние прод-фермы и боевые логи), поэтому разделение
  блоков спека раньше не задавала: каждый блок начинается с пустой строки, внутри
  блока строки идут подряд.
