# Правила переезда `mpu` на Go

Статус: **принят к исполнению** (2026-07-27; архитектурный поворот 2026-07-29 —
`docs/broker-architecture.md`). Инфраструктура (изоляция `go/`, канал спецификаций
`go/docs/` — см. `go/docs/CLAUDE.md`) развёрнута; развилки §11 решены, гейты — в
`go/docs/implementation.md`. Языки: Go — брокер, Deno/TS — CLI (§10 — историческое
обоснование, пересмотрено). Вся обвязка согласована с брокер-архитектурой
(2026-07-29): `protocol/core` — к реализации, канал `ts/docs/` создан, спеки
registry/legacy-delegation/config/invoke-log/selector/readonly-default
пересмотрены; следующий шаг — первые вертикальные срезы (§4.4): `xlsx` в
Deno-сессии, login+version брокера в Go-сессии.

## 0. Принцип

Переезд ценен не языком, а тем, что новое дерево стартует без легаси. Любое правило
ниже существует ради одного: **в новом дереве не должно появиться кода, который стыдно
показать, — потому что следующий модуль будет написан по его образцу.**

Единица миграции — **команда**. Не файл, не библиотека, не «слой». После поворота
2026-07-29 команда при переезде распадается на CLI-часть (Deno/TS) и операции
брокера (Go), но планируется и считается готовой по-прежнему командой целиком.

## 1. Скоуп: что вообще едет

1.1. Команда попадает в план миграции, только если выполнены оба условия:

- есть вызовы в логе `~/.config/mpu/mpu.log` за последние 6 месяцев (лог на момент
  фиксации списка короче — брать всю доступную историю);
- она не одноразовая (не data-fix конкретного инцидента, не разовая миграция данных).

1.2. Всё остальное **не переносится и не сохраняется** — Python-версия остаётся в
git-истории, этого достаточно. Явно вести журнал переезда `go/docs/MIGRATION.md`
(список «умрёт вместе с Python» с причиной по каждой команде, принятые расхождения
§3.4, идеи улучшений §7.3); ведёт его сессия-спецификатор.

1.3. Мёртвые зависимости не едут по определению (пример: `sqlglot` в `pyproject.toml`
есть, в `src` не импортируется ни разу).

1.4. Список к миграции фиксируется **до** первой строки Go и не расширяется по ходу.
Возникла новая нужная команда — пишется сразу в Go, но это отдельная работа, не часть
переезда.

## 2. Строение

2.1. Для пользователя — один бинарь `mpu`: Deno-CLI, собираемый `deno compile`.
Не 72 бинаря, не группы бинарей: обнаружимость (`mpu help` как единственная точка
входа), сквозная обвязка, префиксные правила permissions, атомарность установки —
аргументы схлопывания `mpu-X` / `mpup-X` / `mpuapi-X` в силе. Второй исполняемый
файл системы — Go-брокер: сервис на сервере, пользователь его не вызывает и не
устанавливает.

2.2–2.5. Структура Go-дерева, запрет импорта между командами, правило трёх и
требования к `main.go` — канонический текст перенесён в `go/docs/implementation.md`
(«Структура дерева»): он обязан быть виден изолированной Go-сессии, здесь не
дублируется. Писался под Go-CLI — пересматривается под брокер при первой спеке
операций. Канал CLI-спек — `ts/docs/` (правила — `ts/docs/CLAUDE.md`); правила
реализации ts-дерева появятся там до первого кода.

## 3. Процедура миграции одной команды

Шаги строго по порядку, каждый — с проверяемым критерием.

**3.1. Снять контракт.** Записать: полный `--help`, реальные примеры вызовов из лога,
формат вывода, побочные эффекты (запись/мутация/сеть), read-only-вариант если есть.
Контракт оформляется сессией-спецификатором (с доступом к `py/`) двумя спеками:
CLI-поверхность — `ts/docs/specs/<command>.md` (канал Deno-сессий), операции
брокера — `go/docs/specs/` (канал Go-сессий); общий словарь операций — спеки
протокола `go/docs/specs/protocol/` (ts-сессиям открыт read-only). Скелет и
правила — `go/docs/CLAUDE.md` (для ts-канала — его аналог в `ts/docs/`). Это
единственный канал, которым знание о поведении попадает в изолированные сессии.
Спеки, снятые до поворота, лежат в `go/docs/specs/<command>.md` и служат
исходником для выделения обеих сторон при пересмотре.

**3.2. Написать golden-тест на Python-версии.** Прогнать старую команду на фиксированных
read-only входах, сохранить вывод как эталон (CLI-поверхность —
`ts/docs/specs/fixtures/<command>/`, ответы внешних систем —
`go/docs/specs/fixtures/`; снятые до поворота остаются в `go/docs/specs/fixtures/`
и переезжают при пересмотре спеки; по одному на класс поведения, входы
обезличены — правила в `go/docs/CLAUDE.md`).
До написания Go-кода. Для команд, читающих живые системы (БД, ssh, API), вместе с
эталоном фиксируются ответы внешней системы как фикстуры — differential гоняется
против них, иначе диф покажет дрейф данных, а не поведения; без фикстур старую и
новую версию гонять строго back-to-back, без разрыва во времени.

**3.3. Написать новую версию от контракта** (операции — Go-сессия, CLI — Deno-сессия).

- Исходный `.py` разрешено **прочитать**, чтобы понять поведение, — только
  сессии-спецификатору при снятии контракта, не реализующим сессиям.
- Исходный `.py` **запрещено держать открытым рядом при написании** и запрещено
  переносить построчно. Питоновская декомпозиция, имена и идиомы транслитерируются
  автоматически — это главный канал заражения.
- Ориентир стиля — эталонные пакеты (§5), а не Python-оригинал.

Практически изоляция реализована технически, не соглашением (`permissions.deny` +
`claudeMdExcludes`, см. `go/CLAUDE.md` §«Изоляция окружения»): Go-сессия физически
не может прочитать `mpu/py/`, `mpu/docs/` (включая этот файл) и родительский
`mpu/CLAUDE.md`. Чтение `.py` происходит только в сессии-спецификаторе при снятии
контракта (§3.1); в реализующую сессию оригинал не попадает ни в каком виде —
только спека её канала. Для Deno-сессий (`mpu/ts/`) — та же схема изоляции при
создании каталога.

**3.4. Differential run.** Старая и новая версия на одних входах, диф выводов пустой.
Прогоняет монорепо-сессия — у Go-сессии нет доступа к Python-версии; раздел
«Известные отклонения» спеки — эталон ожидаемых расхождений. Расхождение — либо баг
новой версии, либо осознанно принятое улучшение, записанное в `go/docs/MIGRATION.md`.

**3.5. Контрактные тесты.** Пишутся на чистую логику новой версии, а не портируются из
Python. **Существующие 115 тестовых файлов / 43k строк не переносятся.** Mock-heavy
сюита учит писать код под моки — именно то, от чего уезжаем. Ценные **случаи** из
старых тестов (вход → ожидаемый выход, границы парсеров/форматтеров) спецификатор
вправе выгребать как данные в golden-фикстуры спек (`go/docs/specs/fixtures/`) —
переносятся данные, не код (решение §11).

**3.6. Прочитать целиком глазами.** Команда не считается смигрированной, пока весь её
пакет не прочитан человеком от первой строки до последней.

**3.7. Переключить маршрутизацию** (§4): команда включается в реестр Deno-CLI
(уходит из legacy-делегации), Python-версия удаляется в том же коммите.
После этого сессия-спецификатор переводит статус спеки и строку в `go/docs/plan.md`
в «реализовано» — иначе план и дерево молча разъедутся.

## 4. Strangler: сосуществование

4.1. Пользователь и LLM всегда зовут `mpu <cmd>`. Ни `mpu-go`, ни `mpu2`, ни
переменных окружения-переключателей. `mpu` — Deno-CLI (`deno compile`).

4.2. Маршрутизация — реестр Deno-CLI: команда из реестра исполняется новой
реализацией (локально или операциями брокера); неизвестная реестру команда уходит
операцией делегации брокеру, который запускает установленный рядом с ним
Python-mpu с прозрачным пробросом argv, вывода и exit-кода. Откат команды —
правка одной строки реестра. Контракт делегации —
`go/docs/specs/platform/legacy-delegation.md`; интерактив legacy-команд поверх
JSON-RPC — открытый вопрос протокола (`docs/broker-architecture.md`).

4.3. Обвязка переезжает **первой**, до любой команды, двумя скелетами: брокер —
HTTPS + JSON-RPC + login/JWT, журнал вызовов, selector, read-only-enforcement,
делегация Python; CLI — точка входа, реестр, справка, вызов операций. Спеки
обвязки — `go/docs/specs/platform/<name>.md` (сторона каждого атома —
`go/docs/plan.md`); шаги §3.2/§3.4 к обвязке применяются через первые пробные
срезы (§4.4), а не буквально.

4.4. Харнесс проверяется двумя вертикальными срезами, самыми простыми из
возможных: CLI без брокера — `xlsx` (чистый парсер, спека и golden готовы);
брокер — login + тривиальная операция (version/ping). Их задача — проверить
харнесс целиком (реестр, протокол, гейты, differential, установка), а не
принести пользу.

4.5. Python живёт до последней команды. Дедлайна на «выпилить Python» нет — есть список
команд.

## 5. Эталонные пакеты

5.1. Первые **три** команды доводятся вручную до состояния, которое устраивает полностью,
сколько бы итераций это ни заняло. Они помечаются в CLAUDE.md как эталоны.
Харнесс-проверочная команда §4.4 в число эталонов не входит: её выбрали за простоту,
она образец обвязки, а не бизнес-логики; отсчёт трёх — со следующих команд.

5.2. Дальше формулировка задачи всегда содержит: «в стиле `internal/command/<эталон>`».

5.3. Один плохой пакет, просочившийся в дерево, заражает всё написанное после. Поэтому:
пакет, не прошедший §3.6, не мержится — «потом отрефакторю» не работает, к моменту
«потом» по нему уже написано пять других.

## 6. Гейты (правила, которые нельзя обойти уговорами)

Канонический текст гейтов — `go/docs/implementation.md` («Гейты»): пороги, механизмы
enforcement и принципы (злее, чем комфортно; `//nolint` только с причиной в той же
строке) перенесены туда, чтобы быть видными изолированной Go-сессии; здесь не
дублируются.

## 7. Ограничения для LLM

7.1. Не транслировать Python построчно (§3.3).

7.1a. Единственный scope агента, пишущего Go-код, — `mpu/go/` целиком (код,
`go/CLAUDE.md`, `go/docs/` со спеками и эталонными пакетами §5). `mpu/py/`,
`mpu/docs/` (включая этот файл) и родительский `mpu/CLAUDE.md` заблокированы
технически (§3.3) — не расширяются и явным запросом. Всё, что нужно реализации,
обязано быть в спеке; чего в спеке нет — вопрос спецификатору, а не поход в `.py`.
Для агента, пишущего Deno-CLI, — зеркально: scope `mpu/ts/` + read-only
`go/docs/specs/protocol/`; настраивается при создании каталога.

7.2. Не мигрировать команду, которой нет в списке §1.

7.3–7.4. Поведенческая нейтральность переезда и дисциплина зависимостей — канонический
текст в `go/docs/implementation.md` («Ограничения реализации»), виден Go-сессии; идеи
улучшений из отчётов Go-сессии спецификатор заносит в `go/docs/MIGRATION.md`.

7.5. Не переносить питоновские обходные пути и костыли, не поняв, зачем они. Каждый
неочевидный кусок Python-логики либо объясняется в комментарии Go-версии, либо не
переносится.

7.6. Не отчитываться «смигрировано», пока §3.4 и §3.6 не выполнены фактически.

## 8. Определение готовности команды

Всё сразу:

- [ ] контракт зафиксирован по каналам §3.1 (CLI-поверхность и операции
      брокера) по скелету `go/docs/CLAUDE.md`;
- [ ] golden-эталон снят на Python-версии;
- [ ] differential-диф пуст (или расхождения записаны и приняты);
- [ ] контрактные тесты зелёные;
- [ ] все гейты §6 зелёные;
- [ ] пакет прочитан целиком человеком;
- [ ] маршрутизация переключена (реестр CLI), Python-версия удалена в том же
      коммите;
- [ ] новые доменные термины внесены в `go/docs/glossary.md`;
- [ ] статус спеки и `go/docs/plan.md` — «реализовано».

## 9. Non-goals

- Паритет по коду. Паритет только по поведению.
- Скорость переезда. Одна хорошо сделанная команда в неделю лучше десяти
  транслитерированных.
- Полное избавление от Python по календарю. Telegram (`telethon`) может остаться на
  Python неограниченно долго — делегация брокера это позволяет.
- Переписывание тестов 1:1.

## 10. Почему Go, а не TS

> Историческое обоснование (2026-07-27) выбора Go для CLI. Поворотом 2026-07-29
> CLI переведён на Deno/TS, Go остался языком брокера; таблица сохранена как
> контекст решения.

| | Go | TS |
| --- | --- | --- |
| Старт процесса | ~10 мс | ~40–150 мс (при том, что за 150 мс импорта pydantic уже боролись) |
| Дистрибуция | один статический бинарь | node/bun + бандл |
| «Верёвка» для LLM | мало: нет наследования, ошибки явные | много: любой уровень абстракции достижим |
| MTProto (telethon) | `gotd/td` — низкоуровневый, авторизация руками | `gramjs` — прямой порт, API почти 1:1 |
| Postgres / HTTP / ssh | `pgx`, stdlib, `crypto/ssh` | сопоставимо |
| Общее с монорепо | нет | конвенции `sl-back` / `sw-back` / `sw-front` |

Решающее: `mpu` вызывается десятками раз за сессию (старт процесса — доказанная
ценность), и Go даёт меньше способов написать умно и плохо. Единственная реальная боль —
Telegram — изолируется в одну команду и остаётся на Python (§9).

## 11. Решённые вопросы

Обе развилки закрыты при принятии документа (2026-07-27):

- **§1.2** — одноразовые команды **удаляются**, а не складываются в `legacy/`:
  git-история — достаточный архив, причина смерти каждой команды фиксируется в
  `go/docs/MIGRATION.md`.
- **§3.5** — код тестов **не переносится** ни в каком объёме; ценные случаи из старых
  тестов переносятся как **данные** в golden-фикстуры спек.

Поворот 2026-07-29 (детали — `docs/broker-architecture.md`):

- **Архитектура** — брокер на Go (удалённый сервис, HTTPS + JSON-RPC 2.0,
  временный JWT по логину/паролю из `.env` брокера), CLI — на Deno/TS;
  песочница CLI — опциями Deno (на этом этапе не планируется).
- **§4** — делегация Python переезжает из CLI-диспетчера в брокер; §2/§4
  пересмотрены в этой редакции. Точка входа `mpu` — прямой Deno-CLI
  (`deno compile`, без Go-лончера); решено 2026-07-29.
- Спеки пересмотрены 2026-07-29: `platform/registry` — CLI-спека реестра
  (маршрутизация + справка), делегация Python — `platform/legacy-delegation`
  (брокер, бывш. dispatcher); снятые golden остаются эталоном
  CLI-поверхности.
