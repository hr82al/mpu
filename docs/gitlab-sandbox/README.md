# Песочница GitLab для пары по `mpu mr`

Локальный GitLab CE в docker: на нём снимаются формы **пишущих** вызовов
(`comment`, `note`, `reply`, `resolve`, `edit`, `delete`, `describe`), которые
нельзя гонять на боевом инстансе — они оставляют настоящие комментарии в чужих
MR.

    bash setup.sh        # поднять, посеять проект с MR, выдать токен
    bash teardown.sh     # снести всё: контейнер, тома, образ, конфиг-каталог

`setup.sh` идемпотентен; полный цикл «нет ничего → есть MR» занимает около
десяти минут, из них большая часть — первичная инициализация GitLab.

## Как ходить в песочницу

Токен и адрес лежат в **отдельном** конфиг-каталоге, боевые ключи не трогаются:

    XDG_CONFIG_HOME=<каталог>/config mpu mr view --mr root/mpu-sandbox!1

Уйти этим вызовом в боевой GitLab нельзя: там другой адрес и другой токен.

## Грабли, на которые уже наступили

- Опция `grafana['enable']` в свежих версиях не поддерживается — контейнер
  падает на старте с `Mixlib::Config::UnknownConfigOptionError`.
- Стартовый пароль администратора проверяется словарём: `sandbox-root-password`
  отвергается, и контейнер умирает **после** того, как выставил себе статус
  `healthy`.
- Ждать поэтому надо ответа по HTTP, а не health-статуса.

## Чего песочница не доказывает

Версия образа (снималось на 19.3.1 CE) не сверялась с боевым инстансом.
Расхождение пары на форме ответа или коде — повод сперва проверить версию, а не
искать дефект в нашем коде.
