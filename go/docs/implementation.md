# Реализация: структура дерева и гейты

Правила для изолированной Go-сессии, реализующей спеки `specs/`. Стиль
кода, TDD и проверка изменений — корневой `CLAUDE.md` модуля; содержание
спек — `CLAUDE.md` этого каталога. Этот файл — канонический текст правил
структуры и гейтов: документы на стороне монорепо на него ссылаются, не
дублируют.

## Структура дерева

```
cmd/mpu/main.go              # argv + реестр команд, ничего больше
internal/command/<name>/     # одна команда — один пакет
internal/platform/<x>/       # pg, ssh, config, log, selector, http
```

- `main.go` не содержит логики. Реестр команд — плоская таблица,
  читается за 30 секунд.
- **Пакет команды не импортирует другой пакет команды.** Только
  `internal/platform/*` и stdlib. Загейчено `depguard`, не соглашением.
- Общий код появляется в `platform/` только по правилу трёх: два
  вызывающих — копипаста допустима, три — выносим. Абстракции «на
  будущее» запрещены.

## Гейты

Проза — рекомендация, падающая проверка — закон. Всё ниже — в pre-commit
и CI:

| Гейт | Порог | Механизм |
| --- | --- | --- |
| `golangci-lint` | злая конфигурация | `errcheck`, `exhaustive`, `wrapcheck`, `gocyclo`, `depguard` |
| Длина файла | ≤ 300 строк | `revive` (`file-length-limit`) |
| Длина функции | ≤ 60 строк | `funlen` |
| Цикломатика | ≤ 10 | `gocyclo` |
| `interface{}` / `any` | запрещены вне границ сериализации | кастомное правило (`forbidigo`/`ruleguard`) |
| Импорт между командами | запрещён | `depguard` |
| Покрытие | ≥ 80 % на новом дереве, двигается только вверх | `go test -cover` в CI |
| `go vet`, `gofumpt` | без исключений | — |

- Пороги ставятся злее, чем комфортно: ослабить всегда успеется,
  ужесточить по факту 20 нарушений — уже нет.
- `//nolint` — только с причиной в той же строке и упоминанием в ревью.
  Массовое появление `//nolint` — сигнал, что правило неверное: чинить
  правило, а не код.
- `wrapcheck` без настройки шумит на обёртках stdlib в `platform/*` —
  `ignoreSigs` фиксируется в `.golangci.yml` сразу.
- `exhaustive` срабатывает только на enum-switch — точечный гейт, не
  универсальный.

## Ограничения реализации

- Переезд поведенчески нейтрален: скоуп команды не расширяется — «раз уж
  переписываю, заодно добавлю флаг» запрещено, иначе сверка со старой
  версией теряет смысл. Идеи улучшений — в отчёт; в код они попадают
  отдельной задачей после переезда.
- Зависимость, которой нет в `go.mod`, — только с явным вопросом.
- Не отчитываться «готово», пока контрактные тесты и все гейты не
  зелёные фактически.
- Эталонные пакеты — первые принятые команды, помечены в корневом
  `CLAUDE.md` модуля; новая команда пишется «в стиле
  `internal/command/<эталон>`».

## Готовность со стороны Go-сессии

- [ ] контрактные тесты по спеке зелёные;
- [ ] все гейты зелёные;
- [ ] пакет пригоден к чтению целиком, от первой строки до последней.

Остальные пункты готовности команды (differential-сверка, переключение
диспетчера, статусы спеки и плана) закрывает монорепо-сторона — Go-сессия
о них только сообщает в отчёте.
