# CLAUDE.md — изолированные спецификации переезда

`docs/` — единственный канал передачи знания в изолированные Go-сессии.
Go-сессия не видит `py/`, родительские `CLAUDE.md` и остальной монорепо:
всё, что нужно для реализации команды, обязано лежать здесь. Чего нет в
спеке — для Go-сессии не существует.

Файл обслуживает две роли:

- **сессия-спецификатор** — монорепо-сессия с доступом к Python-реализации;
  пишет и обновляет спеки по правилам ниже. Внутри `go/` ей можно трогать
  **только `docs/`**: Go-код, `go.mod`, корневой `CLAUDE.md` модуля пишутся
  исключительно из изолированной Go-сессии. Процедура переезда на стороне
  монорепо (скоуп, golden-эталоны на Python, differential-сверка,
  маршрутизация реестра CLI) — `mpu/docs/go-migration.md`; Go-сессии его не
  видят, поэтому всё, что нужно реализации, дублируется в спеку.
- **изолированная Go-сессия** — реализует команду строго по спеке;
  правила — в последнем разделе.

## Структура

- `specs/<command>.md` — спецификация одной команды. Единица переезда —
  команда, поэтому и единица спецификации — команда. Команда с
  подкомандами дробится на отдельные спеки (`specs/<command>-<sub>.md`),
  каждая самодостаточна.
- `specs/platform/<name>.md` — спецификация платформенного кусочка
  (обвязка брокера: резолв селектора, конфиг, журнал вызовов,
  read-only-дефолт, legacy-делегация, HTTP-клиенты внешних систем).
  Контракт возможности — вход → результат → инварианты → ошибки, **не**
  Go-API: сигнатуры и типы проектирует Go-сессия. Скелет тот же,
  CLI-разделы — «нет».
- `specs/protocol/<домен>.md` — спецификация протокола брокера
  (JSON-RPC-операции, auth, коды ошибок; единица — домен операций).
  **Общий канал двух сторон**: Deno-сессии CLI читают его read-only —
  поэтому протокольные спеки не ссылаются ни на `platform/`, ни на
  командные спеки этого канала, кроме как информативно. Скелет тот же,
  CLI-разделы — «нет».
- Спеки, снятые до архитектурного поворота 2026-07-29 (командные и часть
  platform), описывают старую одностороннюю реализацию: упоминания
  «локальной кэш-БД», «env-файла», «журнала» в них читаются как
  соответствующие ресурсы **брокера** (`platform/config.md`,
  `platform/invoke-log.md`); формулировки приводятся к точным при
  переводе каждой спеки в «к реализации», вместе с выделением
  CLI-части в канал `ts/docs/`.
- `specs/fixtures/<command>/` — фикстуры: длинные golden-выводы и примеры
  ответов внешних систем; спека на них ссылается.
- `glossary.md` — доменный термин → каноничное имя в Go-коде.
  Изолированные сессии не видят кода друг друга; без глоссария каждая
  переведёт термины по-своему. Каждая спека пользуется именами отсюда;
  новый термин — новая строка. Появляется вместе с первой спекой.
- `plan.md` — список команд к переезду, порядок и статус (черновик скоупа
  уже заведён по журналу вызовов; фиксация — по §1.4 правил переезда).
- `MIGRATION.md` — журнал переезда: принятые расхождения
  differential-сверки, список «умрёт вместе с Python», идеи улучшений.
  Ведёт сессия-спецификатор.
- `implementation.md` — правила реализации для Go-сессии: структура
  дерева, гейты с порогами и механизмами, ограничения (поведенческая
  нейтральность, зависимости). Канонический текст — здесь; правила
  переезда на стороне монорепо на него ссылаются.

## Спека — контракт, инварианты, граничные случаи. Ничего больше

Спека описывает, **что** обещает команда, и молчит о том, **как** устроен
Python-оригинал. Фильтр на каждое утверждение — два теста сразу:

- **наблюдаемость** — видно снаружи команды: пользователю, в файле, в БД,
  в сети. Устройство реализации не наблюдаемо и в спеку не входит;
- **проверяемость** — по утверждению можно написать падающий тест. Не
  формулируется тестом — переформулировать или выбросить.

Состав — четыре содержательных блока; сверх них в скелете только
служебные разделы («Известные отклонения», «Открытые вопросы» — учёт
решений и пробелов, не содержание). Прочее в спеку не допускается:

1. **Контракт** — назначение; CLI (синопсис, флаги, аргументы, полный
   `--help`; реальные примеры вызовов из практики — обезличенные, они
   показывают, какие флаги и сценарии живые); формат ввода/вывода; коды
   выхода; побочные эффекты (что читает, что пишет, куда ходит по сети;
   read-only-вариант, если есть); конфигурация (env, файлы, дефолты).
2. **Инварианты** — свойства, верные для каждого вызова: идемпотентность,
   стабильный порядок вывода, «read-only-вариант не пишет», «секреты не
   попадают в вывод». Один инвариант покрывает класс случаев и ценнее
   десятка примеров.
3. **Граничные случаи и ошибки** — каждый строго парой «вход → ожидаемое
   поведение»: пустой ввод, нет данных, невалидный аргумент, недоступна
   сеть/БД. Граничный случай без ожидаемого поведения — не спецификация,
   а вопрос; ему место в «Открытых вопросах».
4. **Golden-примеры** — по одному на класс поведения: happy path, типовая
   ошибка, граничный случай. Снимаются с живой Python-версии
   (фиксированный вход → дословный вывод), не сочиняются по памяти; их
   должно хватать на контрактные тесты без доступа к оригиналу. Два
   примера одного класса — шум.

Ужесточения — ради качества Go-дерева:

- **Случайное поведение — не контракт.** Фиксируется только то, на что
  полагаются вызывающие. Деталь формы без функционального значения,
  существующая потому, что «так вышло у Python» (порядок ключей словаря,
  формат трейсбека, представление float), в спеку не входит вовсе — этим
  она отличается от «Известных отклонений», которые влияют на вызывающих
  и требуют вердикта. Go-версия вольна сделать лучше; расхождение
  всплывёт на differential-сверке и учитывается там же, где отклонения
  (принятое улучшение → `MIGRATION.md`, §3.4 go-migration.md).
- **Внешняя граница — дословно.** Для каждой внешней системы (PostgreSQL,
  HTTP API, ssh, файлы) спека фиксирует точную форму обмена: SQL-запросы
  (либо их точная семантика: таблицы, фильтры, агрегаты) и форма
  результата; эндпоинты и схемы ответов; вызываемые команды. Примеры
  ответов — в фикстурах. Изолированная сессия не может это подсмотреть:
  граница наблюдаема и обязана быть в спеке, устройство — нет.
- **Секретам и живым данным в спеке не место.** Спеки и фикстуры
  коммитятся; токены, пароли, email'ы, персональные и живые клиентские
  данные не попадают ни в примеры вызовов, ни в golden-выводы — входы
  синтетические или обезличенные.
- **Нормативный язык.** «Обычно», «как правило», «может», «примерно»
  запрещены: формулировка, допускающая две трактовки, породит два
  поведения.
- **Размер — сигнал.** Спека читается за один присест; длиннее ~200
  строк — в неё почти наверняка попал пересказ реализации. Сначала резать
  пересказ; если спека всё ещё велика — команда действительно большая,
  дробить её по подкомандам (см. «Структура»).
- **Порция — одна сессия.** Спека должна быть реализуема за одну
  Go-сессию: реализация, не влезающая в одну сессию, — главный источник
  деградации качества у LLM. Дробить спеку, а не растягивать реализацию.
- **Никакого устройства оригинала**: имена python-функций и классов,
  декомпозиция на модули, внутренние структуры данных, цитаты кода,
  псевдокод алгоритма. Перенос устройства — главный канал заражения
  нового дерева старым: Go-версия проектируется заново, и спека не должна
  подсказывать ей чужую форму.
- **Самодостаточность**: ни одной ссылки на `py/`, пути вне `go/`,
  приватные инструменты и внутренние документы монорепо — изолированная
  сессия не сможет их разрешить. Тест спеки: реализуема ли команда тем,
  кто видел только этот файл.

## Известные ошибки оригинала — не тащить молча

Поведение оригинала ≠ правильное поведение. Смысл переезда — новое дерево
без старых ошибок, поэтому каждая из них проходит через явное решение.

- Каждый баг, квирк и обходной путь, найденный при снятии спеки и
  влияющий на вызывающих, фиксируется в разделе «Известные отклонения» с
  вердиктом:
  - **fix** — в Go не воспроизводить. Спека описывает правильное
    поведение; отклонение записано, чтобы расхождение при сверке со старой
    версией не приняли за регрессию.
  - **preserve** — воспроизводить осознанно: от поведения кто-то зависит.
    Обязательна названная причина.
- Умолчание — **fix**. `preserve` без причины не бывает.
- Непонятный обходной путь не переносится, пока не понят: либо в спеке
  записано, зачем он, либо он не едет.
- Для differential-сверки на стороне монорепо этот раздел — эталон
  ожидаемых расхождений; их учёт (принятые улучшения → `MIGRATION.md`) —
  по `mpu/docs/go-migration.md` §3.4.

## Скелет спеки

Заголовки `specs/<command>.md` — в этом порядке. Неприменимый раздел
остаётся с пометкой «нет», а не удаляется: пустой раздел читается как «не
проверяли», явное «нет» — как «проверили, отсутствует».

```markdown
# mpu <command>

Статус: черновик | к реализации | реализовано

## Назначение
## CLI-контракт
## Ввод/вывод
## Побочные эффекты
## Конфигурация
## Инварианты
## Граничные случаи и ошибки
## Golden-примеры
## Известные отклонения
## Открытые вопросы
```

Статус «к реализации» замораживает спеку: содержательная правка после
этого возвращает статус в «черновик» и означает новый цикл реализации —
движущаяся мишень обесценивает и контрактные тесты, и differential-сверку.

Первая принятая спека помечается в `plan.md` как эталон структуры;
последующие пишутся «в стиле `specs/<эталон>.md`». Отступление от эталона
без названной причины — возврат на доработку. Эталонные Go-пакеты (образец
кода, помечены в корневом `CLAUDE.md` модуля) — отдельное понятие.

## Чек-лист спецификатора — перед статусом «к реализации»

- [ ] каждое утверждение наблюдаемо и проверяемо тестом;
- [ ] внешние границы дословны: SQL/эндпоинты/команды + фикстуры ответов;
- [ ] секретов и живых данных нет ни в тексте, ни в фикстурах;
- [ ] самодостаточность: ни одной ссылки за пределы `go/`;
- [ ] объём — одна сессия реализации, иначе дробить;
- [ ] термины сверены с `glossary.md`, новые — внесены;
- [ ] golden-примеры: happy path, ошибка, граница; по одному на класс.

## Правила для изолированной Go-сессии

- Спека — единственный источник истины о поведении и **read-only**:
  реализацию подгоняют под спеку, не наоборот. Любые правки спеки —
  включая статус и «Открытые вопросы» — вносит сессия-спецификатор по
  отчёту Go-сессии.
- Спека противоречива или молчит о наблюдаемом поведении с
  **функциональным значением** (реакция на вход, код выхода, смысл и
  состав данных в выводе) — остановиться и спросить. Не додумывать
  поведение оригинала: проверить его негде. Полученный ответ действует в
  текущей сессии; чтобы он попал в спеку — упомянуть вопрос и ответ в
  отчёте.
- Молчание спеки об **устройстве** или о форме без функционального
  значения (порядок, оформление, представление чисел вне
  golden-примеров) — не пробел, а свобода: проектируется заново по
  правилам корневого `CLAUDE.md` модуля, у оригинала не спрашивают.
- «Известные отклонения» с вердиктом `fix` — реализуется правильное
  поведение из спеки; воспроизведение старой ошибки — дефект реализации.
- Отклонение с вердиктом `preserve` сопровождается в Go-коде комментарием
  с причиной из спеки: читатель кода не должен ходить в спеку, чтобы
  понять, почему поведение выглядит странным.
- Доменные имена в коде — из `glossary.md`. Термина нет — выбрать имя по
  правилам модуля и явно пометить его в отчёте для внесения в глоссарий.
- Нужные фикстуры копируются в `testdata/` пакета: тесты самодостаточны,
  источник истины — спека.
- Стиль и TDD — корневой `CLAUDE.md` этого модуля; структура дерева,
  гейты и ограничения реализации — `implementation.md` рядом; здесь —
  только содержание спек.
