# mpu run-js

Статус: черновик

## Назначение

Выполнить ESM-код внутри контейнера sl-back: код подаётся на stdin
команды `node --input-type=module -`, поэтому ему доступны node_modules,
import-алиасы и env приложения; рабочий каталог — корень приложения.
Таргетинг и транспорт — как у `mpu ssh`; дополнительно fan-out по всем
инстансам, параллельный и фоновый режимы.

## CLI-контракт

`mpu run-js [SELECTOR] [CODE] [-f/--file PATH] [--all]
[--all-containers SUBSTR] [--dry-run] [--via ssh|portainer]
[--parallel] [-j/--jobs N] [-d/--detach]`

- Ровно один из SELECTOR / `--all` / `--all-containers`, иначе exit 2:
  «mpu run-js: укажите ровно один из <selector> / --all /
  --all-containers». При `--all`/`--all-containers` первый позиционный
  трактуется как CODE; если при этом заданы два позиционных → exit 2:
  «mpu run-js: с --all / --all-containers допустим максимум один
  позиционный (<code>); <selector> избыточен».
- Селектор — как у `mpu ssh` (`platform/selector.md`): `dev:N` / `sl-N`
  / точное имя контейнера / клиент-селектор.
- Источник кода, приоритет: CODE → `--file` → stdin (пайп; на
  интерактивном терминале — stderr-подсказка «mpu run-js: введите
  ESM-код, завершите Ctrl+D», чтение до EOF). CODE и `--file` вместе →
  exit 2: «mpu run-js: позиционный JS и --file взаимоисключающи». Код
  пуст или только пробельные символы → exit 2: «mpu run-js: пустой JS».
- `--all` — fan-out по всем инстанс-серверам (N>0) из кэша контейнеров,
  по возрастанию N; кэш пуст → exit 2: «mpu run-js: в SQLite-кэше нет
  sl-N (N>0); запусти `mpu init`».
- `--all-containers SUBSTR` — fan-out по контейнерам кэша с подстрокой
  в имени; пусто → exit 2: «mpu run-js: контейнеры с подстрокой
  '<SUBSTR>' не найдены в кэше; запусти `mpu init`».
- `--via` — override транспорта для серверных таргетов
  (`platform/exec-transport.md`); контейнеры по имени — всегда Portainer.
- `--dry-run` — без выполнения и без сети: на каждый таргет печатается
  блок `mpu ssh <ref> -- node --input-type=module -
  <<'__MPU_RUN_JS_EOF__'`, затем код (завершающие переводы строки
  обрезаны), затем `__MPU_RUN_JS_EOF__`; при >1 таргета перед каждым
  блоком `# target=<ref>`. `<ref>` = `sl-N` / `dev:N` / имя контейнера.
  Весь вывод дополнительно копируется в буфер обмена. Exit 0.
- Режимы выполнения: последовательный (дефолт); `--parallel` — все
  таргеты одновременно, `--jobs` ограничивает число одновременных (0 =
  все; без `--parallel` игнорируется); `--detach` — фоновый запуск с
  немедленным возвратом.
- Примеры (обезличенные): `mpu run-js sl-1 'console.log(1)'`;
  `cat script.mjs | mpu run-js sl-11`; `mpu run-js --all --parallel -f
  script.mjs`; `mpu run-js --all -d -f script.mjs`; `mpu run-js
  --all-containers wb-loader 'console.log(1)'`.

## Ввод/вывод

Кроме `--dry-run`, перед выполнением stderr: `# mpu run-js: targets =
[<метки через запятую+пробел>]`; метка таргета = `sl-N` / `dev:N` / имя
контейнера.

Последовательный режим: перед каждым таргетом stderr `# target=<метка>`;
вывод стримится; первый ненулевой код → stderr `mpu run-js: <метка>
exit=<код> — abort`, выход с этим кодом.

`--parallel` (действует при >1 таргета; с одним — последовательный
режим): stderr `# mpu run-js: parallel — <K> targets, <M> workers;
вывод по каждому таргету печатается по его завершении`; вывод каждого
таргета буферизуется и печатается по его завершении: stderr `# =====
<метка> (exit=<код>) =====`, затем stdout таргета в stdout и stderr — в
stderr. Прогоняются все таргеты; сбой одного изолируется. Были
ненулевые → в конце stderr `mpu run-js: failures on [<метки>]`, exit 1;
иначе 0. Порядок завершения таргетов — не контракт.

`--detach`: генерируется detach id — 8 шестнадцатеричных символов;
stderr `# mpu run-js: detached run_id=<id> — лог на каждом сервере:
/tmp/mpu-run-<id>.log`. На каждом таргете скрипт заливается в
`/tmp/mpu-run-<id>.mjs` и node стартует фоном с выводом в лог
(`platform/exec-transport.md`); завершения не ждём. Успех запуска →
stderr `# <метка>: started → <лог>`; ненулевой код запуска → `# <метка>:
launch exit=<код>`; исключение → `# <метка>: detach FAILED — <причина>`;
остальные таргеты продолжаются. Если среди таргетов есть серверные —
подсказки: `# собрать логи: mpu run-js <scope> '<js-читалка лога>'`
(`<scope>` = `--all` при нескольких серверных, иначе метка) и `# или
вживую: mpu ssh <первая серверная метка> -- tail -f <лог>`. Любой сбой
запуска → в конце stderr `mpu run-js: detach failures on [<метки>]`,
exit 1; иначе 0.

Коды выхода: 0 — успех всех таргетов; последовательный — код первого
сбоя; `--parallel`/`--detach` — 1 при любом сбое; 2 — ошибки
ввода/резолва/конфигурации.

## Побочные эффекты

Выполнение произвольного JS в живом контейнере со всем окружением
приложения (PG/Redis/NATS-доступ). `--detach` оставляет скрипт и лог в
`/tmp` контейнера намеренно (живут до рестарта). `--dry-run` не ходит в
сеть, но пишет в буфер обмена.

## Конфигурация

Через `platform/exec-transport.md` и `platform/config.md`; собственных
ключей у команды нет.

## Инварианты

- Селектор трактуется идентично `mpu ssh`.
- Последовательный режим — abort-on-first-failure; `--parallel` и
  `--detach` всегда обходят все таргеты и агрегируют сбои в exit 1.
- `--dry-run` не выполняет ни кода, ни сетевых обращений.
- Код доставляется node через stdin — не через аргументы; временный файл
  появляется только при `--detach`.
- Один detach id на все таргеты вызова: пути скрипта и лога совпадают на
  всех серверах.

## Граничные случаи и ошибки

- Пустой stdin-пайп (EOF сразу) → exit 2 «пустой JS».
- `--detach` вместе с `--parallel` → выполняется detach (запуск и так
  неблокирующий).
- Detach на таргеты-контейнеры без серверных — строки-подсказки «собрать
  логи» не печатаются.
- Ошибки резолва селектора, неоднозначное имя контейнера, ошибки
  транспорта — тексты и коды как у `mpu ssh`.
- Ctrl+C в последовательном/parallel-режиме → удалённый процесс
  убивается (`platform/exec-transport.md`); detach-процессы Ctrl+C не
  затрагивает.

## Golden-примеры

Снять при переводе в «к реализации»: `mpu run-js sl-0
'console.log("mpu-golden")'` (happy path); `mpu run-js sl-0 --dry-run
'console.log(1)'` (детерминированный блок, без сети); CODE + `--file`
(mutex, exit 2); пустой stdin-пайп (exit 2 «пустой JS»);
`mpu run-js --help`.

## Известные отклонения

- **preserve** — `--all` перечисляет только инстансы (N>0): main-сервер
  `sl-0` в fan-out не включается, хотя валиден как прямой селектор.
  Причина: fan-out целится в однотипные инстанс-приложения; код «для
  всех инстансов» на main-сервере не имеет смысла и опасен — исключение
  намеренное.
- **fix** — `--via ssh` при таргете-контейнере в оригинале молча
  игнорируется (выполнение идёт через Portainer), тогда как `mpu ssh` в
  той же ситуации даёт ошибку. Правильно — та же ошибка exit 2, что в
  `mpu ssh`.

## Открытые вопросы

- Контракт «буфер обмена» для `--dry-run` (механизм копирования,
  поведение без графической сессии) в черновике не зафиксирован —
  уточнить при фиксации спеки; кандидат — отдельная платформенная
  возможность, общая с другими print-режимами.
