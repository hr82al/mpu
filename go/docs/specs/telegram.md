# mpu telegram

Статус: черновик

## Назначение

Telegram от имени пользователя (личный аккаунт, протокол MTProto, не бот):
`send` — отправить текст или файлы, `ls` — найти адресата, `search` — поиск по
содержимому сообщений, `status` — отправить отчёт о карточках Kaiten,
перемещённых мной сегодня. Авторизация — заранее, `mpu init` (`init.md`).

## CLI-контракт

Подкоманды: `send`, `ls`, `search`, `status`; `mpu telegram` без подкоманды
печатает справку, exit 2.

Адресат (`--chat` у `send`/`status`/`search`, `--from` у `search`): `@username`
| числовой id (в т.ч. отрицательный) | `t.me/<имя>` (`https://`/`http://`/без
схемы) | телефон | `me` (Избранное) | название чата. Нормализация: t.me-префикс
срезается (остаток без крайних `/`; пустой → строка целиком), ведущий `@`
срезается, строка из цифр с необязательным минусом → id, прочее — строка как
есть. `send`/`status` без `--chat` берут `TELEGRAM_DEFAULT_CHAT`; `search`
env-дефолт не использует. Резолв: штатно клиентом; строковая цель при неудаче
ищется по названию чата (RPC `contacts.Search`, контакты + глобальный каталог,
первые 50 кандидатов, без учёта регистра, точные совпадения приоритетнее
подстрочных); ровно одно → адресат найден, иначе ошибка («Граничные случаи»).

`mpu telegram send MESSAGE [--chat X] [--md] [-f/--file PATH ...]` — `MESSAGE`
обязателен; `-` — весь stdin. `-f` повторяем; файлы уходят документами (без
превью), несколько — одним альбомом; непустой текст — подпись (к последнему
файлу), пустой — без подписи; отдельного текстового сообщения нет. `--md` —
Markdown в тексте и подписи (`[текст](url)` → ссылка); иначе текст как есть.

`mpu telegram ls [QUERY] [--limit N] [--table]` — без `QUERY` (или с пустой
строкой) последние диалоги; с `QUERY` — серверный поиск (`contacts.Search`),
дедуп по id (первое вхождение побеждает), порядок ответа сервера. `--limit` —
целое 1..500, дефолт 50 (и у `search`).

`mpu telegram search [QUERY] [--chat X] [--from Y] [--limit N] [--table]` — с
`--chat` поиск внутри чата (RPC `messages.search`), пустой `QUERY` допустим
(история чата); без `--chat` — по всем диалогам (RPC `messages.searchGlobal`),
непустой `QUERY` обязателен. `--from` с `--chat` — серверный фильтр по
отправителю; без `--chat` — клиентский поверх глобального поиска: нужен
непустой `QUERY`, скан ≤ 1000 сообщений выдачи, совпадения — до `--limit`.

`mpu telegram status [--chat X] [--live/--no-live] [--dry-run]` — отправить
адресату отчёт за сегодня (календарный день МСК, UTC+3); `--live` (дефолт) —
дополнить журнал данными Kaiten; `--dry-run` — текст в stdout, без Telegram.

Примеры из практики: `mpu telegram ls 'DEV'`; `mpu telegram send - --chat me
--md`; `mpu telegram status --dry-run --no-live`; `search 'выгрузка' --chat me`.

## Ввод/вывод

stdout — данные; stderr — ошибки одной строкой `telegram: <причина>[;
попробуй: <подсказка>]`, без трейсбеков. Exit: 0 — успех; 2 — ошибки ввода
(до сети); 1 — конфиг и Telegram. `send` и `status` после отправки печатают
JSON-строку `{"id": <int>, "chat_id": <int>, "date": "<ISO-8601 UTC>"|null}`.

Дефолтный вывод `ls`/`search` — JSON-массив, отступ 2, юникод как есть. `ls`:
`{"id","title","kind","username"}`; `kind` ∈ `user|bot|group|channel|unknown`;
нет username → `null`; `id` маркированный: канал/супергруппа — `-(10^12 +
raw)`, базовая группа — `-raw`, пользователь/бот — `raw`; пригоден как
адресат. `search`:
`{"id","chat_id","chat_title","sender","date","text","link"}`; `sender`/`date`
→ `null`, если Telegram их не отдал; `link`: чат с username →
`https://t.me/<username>/<id>`, супергруппа/канал без username (chat_id ≤
-10^12) → `https://t.me/c/<raw>/<id>`, иначе `null`. `--table`: у `ls` —
колонки ID/KIND/USERNAME/TITLE и итог `(N dialogs)`, пусто → `(нет диалогов)`
без счётчика; у `search` — DATE/CHAT/SENDER/TEXT и `(N messages)`, пусто →
`(ничего не найдено)`.

`status` — сбор: (1) журнал перемещений — таблица `kaiten_card_moves` кэш-БД
(пишется командами `mpu kiten`): строки с `moved_at` (epoch-секунды) в
инклюзивном окне [00:00:00; 23:59:59] текущего МСК-дня; поля `card_id`,
`title`, `url`, `to_column`, `moved_at`; пустой `url` → web-URL карточки
`{base}/{card_id}`. (2) `--live` — Kaiten REST (обвязка и web-URL —
`platform/kaiten-http.md`): `GET /users/current` → мой id; `GET /cards?
member_ids=<id>&updated_after=<начало дня, ISO UTC>&updated_before=<конец
дня>`; на карточку — `GET /cards/{id}/location-history`; в отчёт — карточки с
моей сменой колонки (author_id = мой id) за текущий МСК-день, берётся
последняя; название колонки — `GET /boards/{id}/columns` по доскам выборки,
названия нет → id числом, id колонки нет → `—`.

`status` — текст: шапка `Отчёт за сегодня (YYYY-MM-DD МСК):`; записей нет →
`<шапка>\n\nСегодня перемещений не было.`; иначе после пустой строки — строки
`N. [Заголовок](url) — Колонка эмодзи` (с 1): дедуп по card_id (побеждает
наибольший `moved_at`), порядок по (`moved_at`, card_id) по убыванию; `[`/`]`
заголовка → полноширинные `［`/`］`; заголовка нет → `#<card_id>`. Имя колонки
заменяется по `KITEN_COLUMN_MAP`; эмодзи — по заменённому имени (без учёта
регистра): override из `KITEN_STATUS_EMOJI` → точное «Готово»/«Выполнено» →
✅ → первая подстрока (`ревью` 👀, `тест` 🧪, `разработ` 🛠️,
`выгру`/`dev`/`prod` 🚀, `очеред` 📋, `оцен` 📊, `баг` 🐞) → 🔹. Текст
длиннее 4096 символов (лимит Telegram) перед отправкой усекается по границе
целых строк так, чтобы с маркером `\n…(обрезано)` в конце уложиться в лимит;
`--dry-run` печатает без усечения; отправка в Markdown; вывод — как у `send`.

## Побочные эффекты

`send` и `status` без `--dry-run` отправляют реальное сообщение от имени
личного аккаунта — необратимо и видно получателям (`me` — Избранное —
безопасно). Каждый вызов открывает и закрывает соединение с Telegram. `status`
читает кэш-БД (при первом обращении инициализирует её схему), при `--live` —
GET-запросы к Kaiten. PostgreSQL не используется.

## Конфигурация

env-файл (слой — `platform/config.md`); все ошибки конфига ниже — exit 1:

- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` — обязательны; отсутствие любой →
  stderr начинается с `telegram: environment variable <ИМЯ> is not set.`
  (в тексте — путь env-файла); нечисловой `TELEGRAM_API_ID` → `telegram:
  TELEGRAM_API_ID должен быть числом, получено '<строка>'`.
- `TELEGRAM_SESSION` — строка сессии, пишет `mpu init` (`init.md`); пустая или
  невалидная → до операции `` telegram: не авторизован; запусти `mpu init` ``.
- `TELEGRAM_DEFAULT_CHAT` — дефолтный адресат `send`/`status`.
- `TELEGRAM_PROXY` — прокси только для Telegram; URL со схемой http/https
  (CONNECT) | socks5/socks5h | socks4/socks4a, обязателен host:port, креды
  `user:pass@` percent-декодируются, DNS резолвится на прокси; иная схема →
  `telegram: неподдерживаемая схема прокси '<схема>'; попробуй:
  http/https/socks5/socks4`; без host:port → `telegram: в прокси-URL нужен
  host:port — '<url>'`. Не задан → fallback `HTTPS_PROXY`, затем
  `https_proxy` (ловушка: `HTTPS_PROXY` в env-файле проксирует весь mpu).
- `KITEN_API_KEY`, `KITEN_BASE_URL` — live-обогащение `status`
  (`platform/kaiten-http.md`); `KITEN_STATUS_EMOJI`, `KITEN_COLUMN_MAP` —
  JSON-объекты «имя колонки → эмодзи/метка», ключи без учёта регистра; пусто /
  невалидный JSON / не-объект → молча без переопределений.

## Инварианты

- Один вызов — один сеанс: соединение открывается заново и гарантированно
  закрывается даже при ошибке; авторизация проверяется до операции, ошибки
  ввода (exit 2) — до открытия соединения.
- `--chat` всегда приоритетнее `TELEGRAM_DEFAULT_CHAT`; числовой адресат —
  всегда id, не название; `send` с файлами не шлёт отдельного текстового
  сообщения; `status --dry-run` не обращается к Telegram (Kaiten при
  `--live` — обращается); глобальный `search` с пустым запросом запрещён.
- JSON — единственный дефолтный формат `ls`/`search`, `--table` — единственная
  альтернатива; ключи JSON присутствуют всегда, пустота — `null`; секреты
  (`TELEGRAM_API_HASH`, строка сессии, пароль прокси) не попадают в вывод.

## Граничные случаи и ошибки

- Адресат не задан → exit 2 до сети: `telegram: адресат не задан; укажи --chat
  или TELEGRAM_DEFAULT_CHAT в .env`.
- Название чата: несколько совпадений → exit 1: `telegram: под название
  '<название>' подходит несколько чатов: '<title>' → id <id>; …; попробуй:
  указать адресата по id или @username`; не найдено → exit 1: `telegram: не
  удалось найти <что> '<цель>': <причина>; попробуй: mpu telegram ls
  '<название>' и укажи id или @username` («чат»; для `--from` — «отправителя»).
- `send`: пустой текст (в т.ч. `-` с пустым stdin) без `-f` → exit 2 до сети:
  `telegram: пустой текст сообщения`; `-f` на несуществующий путь / не файл →
  exit 2 до сети: `файл-вложение не найден: <путь>`; `send '' -f <файл>` —
  документ без подписи, не ошибка.
- rate-limit Telegram → exit 1: `telegram: rate-limit, подожди <N>s`; прочая
  ошибка RPC → exit 1: `telegram: RPC error: <текст>`.
- `search` без `QUERY` и `--chat` → exit 2: `telegram: нужен текст запроса или
  --chat (пустой глобальный поиск запрещён)`; `--from` без `--chat` и `QUERY`
  → exit 2: `telegram: --from без --chat требует текст запроса (глобальный
  поиск по отправителю — только с текстом)`.
- `search --from` без `--chat`: просмотрено 1000 сообщений, совпадений меньше
  `--limit` → stderr `telegram: скан остановлен на 1000 сообщениях; более
  старые совпадения не показаны`, exit 0.
- `--limit` вне 1..500 → ошибка валидации CLI, exit 2; пустая выдача
  `ls`/`search` в JSON → `[]`, exit 0.
- `status`: журнал и live пусты → текст «Сегодня перемещений не было.», не
  ошибка; ошибка Kaiten при `--live` → stderr `mpu telegram status:
  live-обогащение пропущено (Kaiten: <текст>)`, работа продолжается на журнале.

## Golden-примеры

Снять при переводе в «к реализации» на собственном аккаунте (без чужих личных
данных в фикстурах; отправка — только в `me`, Избранное): `status --dry-run
--no-live` (happy path без сети Telegram); `send 'тест' --chat me` (JSON-ответ
отправки); `ls --limit 3` и `ls --limit 3 --table`; `search` без аргументов
(пустой глобальный поиск, exit 2); `send 'x' -f /no/such/file` (exit 2).

## Известные отклонения

- **fix** — ошибки ввода оригинал завершает exit 1, а запреты пустого
  глобального поиска проверяет уже после подключения к Telegram. Правильно —
  exit 2 и проверка до сети; тексты ошибок неизменны.
- **fix** — клиентский from-фильтр (`--from` без `--chat`) оригинал молча
  обрывает на потолке скана: выдача короче `--limit` неотличима от «совпадений
  больше нет». Правильно — stderr-предупреждение («Граничные случаи»).
- **fix** — усечение `status` оригинал делает по сырым символам: маркер
  `…(обрезано)` может встать посреди разорванной markdown-ссылки. Правильно —
  усечение по границе целых строк (см. «Ввод/вывод»).
- **preserve** — `--dry-run` печатает неусечённый текст: усечение — свойство
  отправки, dry-run показывает человеку полный отчёт.
- **preserve** — резолв по названию ищет только среди первых 50 результатов
  серверного поиска; название вне их → «не удалось найти». Причина:
  канонические адресаты — id и @username; лимит — тот же, что у `ls`.

## Открытые вопросы

- По плану переезда команда может остаться на Python неограниченно (MTProto);
  решение отложено до её очереди — спека фиксирует контракт на этот случай.
- Rate-limit неотличим кодом выхода от прочих ошибок Telegram; нужен ли
  отдельный код/поле для авторетрая — решить при переводе в «к реализации».
