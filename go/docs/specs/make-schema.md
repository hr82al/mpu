# mpu make-schema

Статус: черновик

## Назначение

Создать схему клиента в локальном стенде: запустить
`clientsMigrations init` внутри локального контейнера `mp-sl-N-cli`.
Идемпотентно — `init` создаёт `schema_<client_id>`, только если её ещё
нет. Локальный `docker exec`, не удалённый транспорт.

## CLI-контракт

`mpu make-schema SELECTOR [--server sl-N] [--print|-p]
[--client-id INT]`

- `SELECTOR` — селектор клиента (`platform/selector.md`); без аргумента
  — справка, exit 2.
- `--server sl-N` — контейнер-цель. Без флага контейнер всегда
  `mp-sl-1-cli` независимо от сервера, в который резолвится селектор; с
  флагом — `mp-sl-<N>-cli`. Флаг работает как override резолва
  (`platform/selector.md`): замещает селектор, кандидаты пусты —
  поэтому вместе с `--server` обязателен `--client-id`.
- `--client-id` — явный client_id, побеждает резолв селектора.
- `--print` / `-p` — напечатать собранную docker-команду в stdout одной
  строкой (аргументы через пробел) и скопировать её в буфер обмена
  (best-effort: OSC 52, затем wl-copy/xclip/xsel; сбой молчалив), без
  выполнения, exit 0.

Выполняемая команда:
`docker exec mp-sl-<N>-cli node cli service:clientsMigrations init
--client-id <id> --server sl-<N>`.

Коды выхода: 0 — успех и `--print`; 2 — ошибки резолва; иначе — rc
`docker exec` как есть (без дополнительного сообщения).

## Ввод/вывод

`--print`: команда в stdout. Иначе stdout/stderr `docker exec`
наследуются терминалом напрямую (без буферизации и префиксов).

## Побочные эффекты

Запуск `docker exec` в локальном контейнере (создание схемы в локальном
PG выполняет `node cli` внутри контейнера). `--print` — только буфер
обмена. Сети и записи в кэш-БД нет.

## Конфигурация

нет (контейнер локальный, PG-креды не нужны; селектор — кэш-БД,
`platform/selector.md`).

## Инварианты

- Идемпотентность: повторный запуск на существующей схеме ничего не
  меняет (свойство `init`).
- `--print` не выполняет команду и не имеет побочных эффектов, кроме
  буфера обмена; сбой копирования не влияет на вывод и код выхода.
- Номер в имени контейнера и значение `--server sl-<N>` внутри команды
  всегда совпадают.

## Граничные случаи и ошибки

- client_id не извлекается из резолва (нет кандидатов с client_id или
  их больше одного) и `--client-id` не задан → stderr
  `mpu make-schema: cannot resolve --client-id from selector; pass
  --client-id` + список кандидатов (если есть), exit 2.
- `--server` не вида `sl-N` → ошибка override резолва
  (`platform/selector.md`), exit 2.
- Контейнер `mp-sl-<N>-cli` не существует/не запущен → `docker exec`
  падает, его rc пробрасывается как код выхода (подсказка — поднять
  стенд: `specs/mp-init.md`).

## Golden-примеры

Снять при переводе в «к реализации»: `mpu make-schema --help`;
`mpu make-schema <client_id> --print` (печать команды без выполнения);
`mpu make-schema <client_id> --server sl-0 --client-id <client_id>
--print` (подстановка N в контейнер и `--server`);
`mpu make-schema <client_id> --server sl-0 --print` (ошибка: с
`--server` нужен `--client-id`, exit 2).

## Известные отклонения

- **preserve** — `--server` внутри выполняемой команды передаётся
  `node cli` всегда, хотя `init` создаёт схему только по `--client-id`
  и переданный `--server` игнорирует (поведение стороннего `node cli`,
  вне контроля команды). Причина: паритет с вызываемым контрактом
  `node cli`; команда обязана воспроизводить передачу аргумента как
  есть, не проверяя его смысловой эффект.
