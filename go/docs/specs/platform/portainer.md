# platform/portainer — шаблон node-CLI обёртки

Статус: черновик

## Назначение

Общая машинерия семейства команд-обёрток над sl-back CLI: собрать
inner-команду `node cli service:<сервис> <метод> [флаги]`, выбрать режим
(выполнение / печать ssh-формы / печать локальной формы) и доставить.
Потребители — `specs/portainer-wrappers.md`.

Exec-граница Portainer у этого атома **совпадает** с
`platform/exec-transport.md` — это одна и та же спека, здесь она не
дублируется: обёртка передаёт inner-команду транспорту как argv-список,
таргет — сервер N (контейнер `mp-sl-N-cli`), stdin пуст.

## Ввод/вывод

Вход: имя сервиса; имя метода; упорядоченный набор флагов; результат
резолва селектора (`platform/selector.md`: номер сервера + кандидаты);
режим; имя команды для сообщений об ошибках (`<команда>` ниже).

**Режим** — из пары пользовательских флагов `--print`/`-p` и `--local`:

- без `--print` → **exec**: выполнение через Portainer-транспорт;
- `--print` без `--local` → **ssh-печать**: требует env `sl_<N>` (IP) и
  `PG_MY_USER_NAME`;
- `--print --local` → **локальная печать**: env-lookup не выполняется.

**Сборка inner-команды**: токены `node`, `cli`, `service:<сервис>`,
`<метод>`, затем флаги строго в порядке объявления:

- имя флага нормализуется к kebab-виду: ведущие `--` опциональны,
  `_` → `-`, итог всегда с `--` (`client_id` / `--client_id` /
  `--client-id` → `--client-id`);
- пустое значение (нет значения) и false → флаг опускается целиком (ни
  флага, ни значения);
- true → флаг без токена-значения;
- строка / целое → `--флаг <значение>` (один токен значения);
- список строк/целых → `--флаг v1 v2 …` (по токену на элемент; sl-back
  CLI читает подряд идущие не-флаговые токены массивом); пустой
  список → флаг опускается.

**Валидация значений (SafeToken)**: каждый строковый/числовой токен
значения обязан целиком состоять из символов
`A-Z a-z 0-9 _ . / : - , @ [ ]` (минимум один символ). Нарушение →
stderr `<команда>: value contains shell-unsafe chars for <флаг>:
'<значение>'`, exit 2 — до любой печати и любого сетевого вызова,
одинаково во всех трёх режимах.

**Доставка по режиму**:

- exec: argv inner-команды → транспорт `platform/exec-transport.md`
  (сервер N, пустой stdin); stdout/stderr стримятся по мере
  поступления; код выхода inner-команды становится кодом выхода mpu 1:1
  (0 → 0).
- ssh-печать: в stdout — единственная строка
  `ssh -i <HOME>/.ssh/id_rsa -t <user>@<ip> 'docker exec -it
  mp-sl-<N>-cli sh -c "<inner>"`', где `<inner>` — токены через
  одиночные пробелы без дополнительного квотирования (SafeToken
  гарантирует безопасность подстановки), `<HOME>` — абсолютный путь
  домашнего каталога; строка копируется в системный буфер обмена
  (недоступность буфера игнорируется молча); выполнения нет; exit 0.
- локальная печать: в stdout — `sl-<N>-cli sh -c "<inner>"` (alias
  локального стенда) + тот же буфер обмена; выполнения нет; exit 0.

**Auto-pick из кандидатов** (для `--client-id`, `--spreadsheet-id`):
явно заданный флаг побеждает; иначе — если все кандидаты резолва с этим
полем несут одно и то же значение, берётся оно; иначе stderr
`<команда>: cannot resolve <флаг> from selector; pass <флаг>` +
форматированный список кандидатов (форма — `platform/selector.md`),
exit 2.

## Побочные эффекты

exec-режим — реальное выполнение inner-команды в живом контейнере
прод-сервера (эффект определяется методом — спека семейства);
print-режимы — только stdout и буфер обмена, сети нет. Резолв
селектора — чтение кэш-БД, без записи.

## Конфигурация

Env-файл (контракт — `platform/config.md`): `sl_<N>` и
`PG_MY_USER_NAME` — только для ssh-печати; Portainer-ключи exec-режима —
`platform/exec-transport.md`. Путь ssh-ключа в печатаемой строке —
`<HOME>/.ssh/id_rsa`, не настраивается (совпадает с exec-transport).

## Инварианты

- За вызов применяется ровно один режим — exec, ssh-печать или
  локальная печать; смешения не бывает.
- Все три режима строят один и тот же `<inner>` из одинаковых входов.
- Порядок флагов повторяет порядок объявления, никогда не сортируется.
- Валидация SafeToken выполняется до сети и до печати во всех режимах.
- Резолв селектора выполняется до печати: ошибки резолва идентичны во
  всех режимах.
- Код выхода exec-режима равен коду inner-команды 1:1, никогда не
  схлопывается в 0.
- Секреты (ключи, содержимое env-файла) не попадают ни в печатаемые
  строки, ни в тексты ошибок.

## Граничные случаи и ошибки

- ssh-печать, нет `sl_<N>` → stderr `<команда>: no sl_<N> in
  ~/.config/mpu/.env`, exit 2.
- ssh-печать, нет `PG_MY_USER_NAME` → stderr `<команда>:
  PG_MY_USER_NAME not set in ~/.config/mpu/.env`, exit 2.
- Значение флага с пробелом, `$`, кавычкой, `;`, `|`, скобкой →
  exit 2 (SafeToken), без сетевых вызовов и частичного состояния.
- true-значение никогда не порождает токена-значения; пустое/false —
  ни флага, ни значения (хвостовых пустых токенов не бывает).
- exec-режим при недоступном Portainer/конфиге — тексты и коды
  `platform/exec-transport.md`.

## Golden-примеры

Снять при переводе в «к реализации» — через команды семейства
(`portainer-wrappers.md`), все в print-режимах, без выполнения:
ssh-форма и локальная форма одного вызова на фиксированном конфиге;
ошибка SafeToken; ошибка отсутствия `PG_MY_USER_NAME`.
