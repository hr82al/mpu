# platform/config — рантайм-конфиг

Статус: черновик (на пересмотре под брокер-архитектуру 2026-07-29:
конфиг расщепляется — секреты и серверные настройки уходят в `.env`
брокера, у CLI остаются локальные предпочтения, см. plan.md; текст ниже
описывает единый локальный конфиг оригинала и служит исходником
пересмотра)

## Назначение

Два слоя конфигурации: env-файл (секреты и подключения) и таблица
`config` в локальной служебной БД (пользовательские дефолты) с CLI
`mpu config`. Все команды берут настройки только через этот механизм.

## CLI-контракт

`mpu config [key] [value] [--unset] [--json]`

- Без аргументов — все ключи реестра по порядку объявления, с действующим
  значением и источником: `key<пробелы>значение|-(unset)  (source)`;
  суффикс источника опускается для `config`, печатается для `(env)` и
  `(default)`. `--json` — массив `{key, value, source, default,
  description}`.
- `config <key>` — значение; str-ключ без значения → пустой stdout,
  exit 0 (pipe-friendly); int-ключ без значения → печатается дефолт.
  Неизвестный ключ → exit 2:
  `unknown config key: "<имя>"; попробуй: допустимые ключи: <CSV>`.
- `config <key> <value>` — upsert. Int-ключ с нечисловым значением →
  exit 2 `<key> ожидает целое число, получено "<value>"`, БД не
  трогается. При активной env-переменной поверх ключа запись проходит,
  но stderr предупреждает:
  `внимание: <ENV>=<значение> в окружении перекрывает это значение`.
- `config --unset <key>` — идемпотентное удаление, exit 0 даже если
  записи не было; stdout `<key> сброшен к дефолту: <default|(unset)>`.
  `--unset` без ключа → exit 2 `--unset требует имя ключа`.
- Реестр ключей закрыт: `sheet.default` (str), `xlsx.default` (str),
  `sheet.cache.tab_ttl` (int, 7200), `sheet.cache.max_tab_bytes`
  (int, 10485760), `sheet.cache.max_total_mb` (int, 500). Дефолты
  int-ключей не дублируются в CLI — берутся из модуля-потребителя.
- `mpu config` НЕ читает и НЕ пишет env-файл — только таблицу `config`.

## Ввод/вывод

Приоритет действующего значения любого ключа реестра, строго:
env `MPU_<KEY>` (имя выводится детерминированно: точки → `_`, верхний
регистр) → таблица `config` → дефолт потребителя. Значения хранятся как
TEXT буквально (`"007"` сохраняется как `007`, не нормализуется).

Env-слой: файл `$XDG_CONFIG_HOME/mpu/.env` (или `~/.config/mpu/.env`),
формат dotenv. Загружается один раз за процесс; отсутствие файла — не
ошибка. Уже экспортированная в shell переменная побеждает файл.
Программная запись переменной: атомарная замена файла (tmp + rename),
права 0600, update-in-place существующей строки; значение с переводом
строки или одинарной кавычкой — ошибка; со пробелами/`#` — одинарные
кавычки.

## Побочные эффекты

Только локальные: чтение/запись env-файла и служебной БД
(`~/.config/mpu/mpu.db`, WAL). Сети нет. Директория конфига создаётся
при первом обращении; схема БД — только явной инициализацией
(`mpu init`): без неё операции с таблицей `config` → exit 1 с
подсказкой `mpu init`.

## Конфигурация

Ключи env-слоя, принадлежащие обвязке (остальные ~150 принадлежат
конкретным командам и фиксируются в их спеках):

- `sl_<N>`, `pg_<N>` — IP серверов (N = 0…), `sl_<N>_portainer` —
  legacy-fallback оркестратора;
- `PG_PORT` (5432), `PG_DB_NAME` (`wb`), `PG_MY_USER_NAME` /
  `PG_MAIN_USER_NAME`, `PG_MY_USER_PASSWORD` / `PG_MAIN_USER_PASSWORD`
  (личные креды приоритетнее общих);
- `DEV_PG_HOST/PORT/DB` (dev-стенд, одна БД на всех клиентов),
  `DEV_PG_USER/PASSWORD`;
- `MPU_LOG_*` — журнал вызовов (контракт — `platform/invoke-log.md`);
- `MPU_SS`, `MPU_XLSX` — env-дефолты целей `sheet`/`xlsx`.

## Инварианты

- Чтение (`config`, `config <key>`) идемпотентно, без побочных эффектов.
- Порядок приоритета env → config → default одинаков для всех ключей и
  никогда не инвертируется.
- Невалидное значение int-ключа не долетает до БД (валидация до записи).
- Обращение к ключу вне реестра никогда не создаёт запись «на лету».
- Секреты не печатаются: вывод `mpu config` содержит только ключи
  реестра (не env-слой).

## Граничные случаи и ошибки

- env-переменная активна И значение записано в БД → действует env,
  источник `env`, значение в БД сохраняется, но не действует.
- `--unset` при активной env-переменной удаляет только запись БД —
  действующим остаётся env (см. «Известные отклонения»).
- Нет схемы БД (не было `mpu init`) → exit 1 + `mpu init` для любых
  операций с таблицей.
- Формат ошибок единый: stderr
  `mpu config: <причина>[; попробуй: <подсказка>]`, без трейсбеков;
  exit 2 — ошибки ввода, exit 1 — инфраструктура.

## Golden-примеры

Снять при переводе в «к реализации»: `mpu config --json` на чистой БД
(baseline пяти ключей), `mpu config sheet.cache.tab_ttl --json`
(значение из дефолта), `mpu config --help`.

## Известные отклонения

- **fix** — сообщение `--unset` показывает дефолт, даже когда активна
  env-переменная и действующим значением останется она; правильное
  поведение — предупреждать про env, как это делает set. Расхождение
  всплывает только при активной env-переменной.
- **preserve** — env-файл учитывает `XDG_CONFIG_HOME`, а служебная БД
  всегда лежит в `~/.config/mpu/` (асимметрия слоёв). Причина:
  расположение файлов — внешний контракт для существующей машины
  пользователя; идея унификации — в журнал переезда.

## Открытые вопросы

- Полный реестр env-переменных (`.env.example` в корне mpu) Go-сессии
  не виден: переменные конкретной команды обязаны дублироваться в её
  спеке. При старте реализации решить, копировать ли реестр целиком в
  `go/docs/`.
