# platform/config — конфигурация брокера

Статус: черновик (пересобрана 2026-07-29 под брокер-архитектуру:
здесь — серверная часть расщеплённого конфига; локальные предпочтения
CLI — `ts/docs/specs/platform/config.md`)

## Назначение

Единственный источник конфигурации брокера — env-файл (dotenv). В нём
живут все секреты и серверные настройки; операции берут настройки
только через этот механизм. CLI этот файл не читает и не видит —
граница доверия.

## CLI-контракт

нет (конфигурация сервиса; правится администратором на сервере руками,
операций редактирования конфига в протоколе нет).

## Ввод/вывод

- Файл: `$XDG_CONFIG_HOME/mpu/.env` (или `~/.config/mpu/.env`
  пользователя, под которым работает брокер), формат dotenv, права
  0600. Загружается при старте процесса; изменение файла требует
  перезапуска брокера. Отсутствие файла — не ошибка (все ключи по
  дефолтам), отсутствие обязательного ключа — ошибка старта с именем
  ключа.
- Уже экспортированная в окружение процесса переменная побеждает файл.
- Программная запись переменной (операции, кэширующие токены внешних
  систем): атомарная замена файла (tmp + rename), права 0600,
  update-in-place существующей строки; значение с переводом строки или
  одинарной кавычкой — ошибка; со пробелами/`#` — одинарные кавычки.

## Побочные эффекты

Чтение при старте; запись — только атомарная замена файла (см. выше).
Схема кэш-БД брокера — только явной инициализацией (bootstrap-механизм
кэша, спека `init`/`update`); без неё зависящие от кэша операции →
ошибка с подсказкой инициализации.

## Конфигурация

Ключи обвязки (ключи конкретных операций — ~150 — фиксируются в спеках
их доменов по мере переезда):

- `sl_<N>`, `pg_<N>` — IP серверов стенда (N = 0…), `sl_<N>_portainer` —
  legacy-fallback оркестратора;
- `PG_PORT` (5432), `PG_DB_NAME` (`wb`), `PG_MY_USER_NAME` /
  `PG_MAIN_USER_NAME`, `PG_MY_USER_PASSWORD` / `PG_MAIN_USER_PASSWORD`
  (личные креды приоритетнее общих);
- `DEV_PG_HOST/PORT/DB` (dev-стенд, одна БД на всех клиентов),
  `DEV_PG_USER/PASSWORD`;
- учётные пары CLI-пользователей (login + хэш пароля, bcrypt/argon2id),
  секрет подписи JWT и TTL токена (дефолт 7 дней); контракт auth —
  `specs/protocol/core.md`;
- лимит размера тела запроса и таймауты соединения
  (`specs/protocol/core.md`);
- `MPU_LOG_*` — журнал вызовов (контракт — `platform/invoke-log.md`);
- путь и окружение Python-установки для legacy-делегации
  (`platform/legacy-delegation.md`; имена ключей — при реализации);
- политика кэша листов Google Sheets (бывшие пользовательские
  `sheet.cache.*` — см. отклонения; дефолты оригинала, наследуемые
  серверной политикой: TTL вкладки 7200 с, лимит вкладки
  10485760 байт, общий лимит 500 МБ; имена ключей — при пересмотре
  атома webapp-http).

## Инварианты

- Секреты не покидают брокер: значения env-ключей не появляются ни в
  ответах операций, ни в журнале вызовов, ни в логах (маскирование —
  `platform/invoke-log.md`).
- Порядок приоритета: переменная окружения процесса → env-файл →
  дефолт; одинаков для всех ключей и никогда не инвертируется.
- Атомарная запись не теряет и не дублирует прочие строки файла;
  повторная запись того же значения идемпотентна.
- Конфигурация читается один раз за жизнь процесса: поведение брокера
  не меняется между запросами без перезапуска.

## Граничные случаи и ошибки

- Переменная и в окружении процесса, и в файле → действует окружение.
- Значение для записи содержит перевод строки или одинарную кавычку →
  ошибка операции записи, файл не тронут.
- Нет обязательного ключа (учётки, JWT-секрет) → отказ старта брокера с
  именем недостающего ключа, а не падение на первом запросе.

## Известные отклонения

- **fix** — в оригинале политика кэша листов (`sheet.cache.tab_ttl`,
  `sheet.cache.max_tab_bytes`, `sheet.cache.max_total_mb`) была
  пользовательскими ключами `mpu config`; у общего брокера кэш один на
  всех, политика становится серверной (env-ключи брокера) и из
  пользовательского реестра CLI исчезает.
- **preserve** — env-файл учитывает `XDG_CONFIG_HOME` (расположение —
  внешний контракт для существующей машины; идея унификации — в журнал
  переезда).

## Открытые вопросы

- Полный реестр env-переменных (`.env.example` в корне mpu) Go-сессии
  не виден: переменные конкретного домена обязаны дублироваться в его
  спеке. При старте реализации решить, копировать ли реестр целиком в
  `go/docs/`.
- Перечитывание конфига без рестарта (SIGHUP) — не заводить до реальной
  нужды (YAGNI); сейчас контракт — рестарт.
