# platform/dispatcher — точка входа и strangler-маршрутизация

Статус: черновик

## Назначение

Единственная бинарь-точка входа `mpu`: разбор argv, маршрутизация на
подкоманду (Go или, на время переезда, Python-ветка), журнал каждого
вызова. Пользователь всегда зовёт `mpu <cmd> …` и не видит, какая
реализация ответила.

## CLI-контракт

- `mpu <cmd> [args…]` — единственная форма вызова. Установка —
  `~/.local/bin/mpu`.
- `mpu` без аргументов, `mpu -h`, `mpu --help` — печатают общую справку
  (Usage, опции, список всех команд с одностроками; порядок — порядок
  реестра, не алфавит), **exit 2** (не 0 — исторический контракт, см.
  «Известные отклонения»).
- `mpu <неизвестное>` → stderr `No such command '<имя>'.` + подсказка
  `Try 'mpu -h' for help.`, exit 2.
- `mpu --version` — опции не существует → ошибка `No such option`,
  exit 2. Версия — только подкомандой: `mpu version` → строка версии,
  exit 0.
- `mpu help` — отдельная подкоманда: свой формат списка; `mpu help
  <cmd>` рендерит справку команды; `mpu help <неизвестная>` → stderr
  `mpu help: unknown command '<cmd>'` + список известных, exit 2.
- Shell-completion: служебная env-переменная completion-режима полностью
  отключает журнал и побочную работу обвязки.

## Ввод/вывод

Маршрутизация: статичная таблица «команда → Go | Python» в коде
диспетчера; перевод команды и откат — правка одной строки. Неизвестное
имя не ищется нигде, кроме таблицы (+ реестर Go-команд).

Python-ветка (пока жива): вызов установленного Python-mpu дочерним
процессом с прозрачным пробросом argv, stdin/stdout/stderr, TTY-статуса
и exit-кода. Наблюдаемое поведение делегированной команды не отличается
от прямого вызова Python-версии.

## Побочные эффекты

Один вызов = ровно одна запись в журнале вызовов (контракт —
`platform/invoke-log.md`), независимо от исхода и ветки; при
делегировании в Python журнал Python-ветки отключается окружением,
чтобы записей не было две. Другие эффекты — только внутри команд.

## Конфигурация

`platform/config.md` (env-файл читается лениво при старте — уже ради
конфигурации журнала). Версия — константа сборки, не из окружения.

## Инварианты

- Интерфейс не зависит от способа установки/запуска; в журнале команда
  всегда начинается литеральным `mpu`, независимо от argv[0].
- Диспетчер детерминирован: одно имя — одна команда; состояние между
  вызовами не живёт (кроме файлов обвязки: журнал, кэш-БД, env-файл).
- Журнал не может изменить наблюдаемый пользователем вывод и exit-код
  команды (fail-open, работа на копии перехваченных байт).
- Ошибка на любом этапе, включая инициализацию самого диспетчера,
  попадает в журнал (exit 1, детали в err-секции) — мимо журнала не
  проваливается ничего.
- Реестр команд — один источник истины; `mpu --help`, `mpu help` и
  маршрутизация читают его же (в оригинале это не так — см. отклонения).

## Граничные случаи и ошибки

- Строковый аварийный выход команды → exit 1, текст в stderr.
- Необработанное падение → exit 1, трейс в журнал, пользователю —
  стандартное сообщение об ошибке.
- Python-ветка недоступна (удалена/не установлена) при команде,
  замаршрутизированной на Python → явная ошибка диспетчера с именем
  команды, exit 1 (не молчаливый провал).

## Golden-примеры

Снять при переводе в «к реализации»: `mpu --help`, `mpu -h`, `mpu`
(совпадение текстов, exit 2); `mpu version` (exit 0); `mpu help`,
`mpu help version`, `mpu help нет-такой` (exit 2);
`mpu totally-bogus-command` (текст + exit 2); `mpu --version` (ошибка,
exit 2); по одной односоставной и многосоставной команде `--help`.

## Известные отклонения

- **preserve** — справка (bare/`-h`/`--help`) завершается exit 2, а не
  0. Нетипично, но это действующий контракт для скриптов; менять — только
  осознанным решением после переезда. Идея нормализации — в журнал
  переезда.
- **fix** — в оригинале «`mpu help`» ведёт собственный рукописный список
  команд отдельно от реестра (два источника истины, известная ловушка
  дрейфа). В Go список один — реестр диспетчера; расхождение возможно
  лишь как разница состава списков, если в оригинале успел случиться
  дрейф.
- **fix** — байтовый паритет текста общей справки не требуется:
  оформление (рамки/цвета оригинала) не воспроизводится; фиксируется
  структурный контракт — Usage, состав и порядок команд, тексты
  однострок, exit-код. Differential по help сравнивать структурно.
- **fix** — в оригинале `mpu --help` платит цену загрузки всех модулей
  (~секунда); в Go справка мгновенна. Наблюдаемая разница — только
  время.

## Открытые вопросы

- Точный механизм вызова Python-ветки (путь к установленной
  Python-бинари, передача окружения) — зафиксировать при реализации
  обвязки; требование спеки — прозрачность проброса и одна запись в
  журнале.
