# platform/invoke-log — журнал вызовов

Статус: черновик

## Назначение

Каждый запуск `mpu` оставляет одну запись в локальном журнале: командная
строка, вывод, ошибки, код возврата, длительность. Журнал — память
оператора («что я уже прогонял и почему упало») и источник частот для
плана переезда. Плюс команда чтения `mpu log`.

## CLI-контракт

`mpu log [--tail/-n INT] [--failed] [--cmd TEXT] [--since TEXT]
[--run ID] [--file PATH]` — только чтение.

- `--run` обрабатывается первым и один: запись целиком, exit 0; не
  найдена → exit 1 `запись run=<id> не найдена`; остальные фильтры
  игнорируются.
- Иначе фильтры по И: `--failed` (exit != 0) → `--cmd` (префикс
  `mpu <cmd>`) → `--since` (относительное `\d+[smhd]` или unix-ts;
  невалидное → exit 2 `--since: <причина>`), затем `--tail` последних
  (дефолт 20; ноль и отрицательные = все записи).
- Читается весь ротированный набор от старшего архива к текущему
  (хронологически); `--file` ограничивает одним файлом. Отсутствующий
  файл молча пропускается; пусто → stderr `записей не найдено`, exit 0.

## Ввод/вывод

Формат записи (verbatim; секция с пустым содержимым не печатается):

```
### <YYYY-MM-DD HH:MM:SS.mmm> <+HH:MM> run=<id> pid=<pid> cwd=<каталог>
$ mpu <argv после маскирования>
--- note run=<id> ---      # диагностика обвязки, если была
--- out run=<id> ---       # stdout verbatim
--- truncated run=<id> stream=out dropped=<байт> ---
--- err run=<id> ---       # stderr (+traceback при падении)
--- end run=<id> exit=<код> dur=<сек, 3 знака>s ---
<пустая строка>
```

`run_id` = `YYYYMMDD-HHMMSS.mmm-<pid>`. Границы записи при чтении
определяются только шапкой и `--- end` с тем же run_id — похожие маркеры
внутри чужого вывода запись не рвут.

Код возврата в записи: нормальный выход/int — как есть; строковый
выход → 1 (текст в err); необработанное исключение → 1, traceback в
err, запись пишется, падение затем передаётся дальше (не гасится).

## Побочные эффекты

Пишет файл журнала (дефолт `~/.config/mpu/mpu.log`) + соседний
lock-файл; оба 0600, права выравниваются при каждой записи; каталог
создаётся. Перехват вывода — на уровне файловых дескрипторов 1/2
(дочерние процессы тоже попадают); терминал остаётся терминалом для
команды (isatty сохраняется). Сети и БД нет.

## Конфигурация

`MPU_LOG_ENABLED` (выкл: 0/off/false/no, любой регистр),
`MPU_LOG_FILE`, `MPU_LOG_MAX_OUTPUT_BYTES` (дефолт 8 МиБ на поток,
0 = без обрезки), `MPU_LOG_MAX_BYTES` (порог ротации, дефолт 50 МБ,
0 = не ротировать), `MPU_LOG_KEEP` (архивов, дефолт 5, 0 = ротация без
архивов). Битое числовое значение → дефолт + note в текущую запись.
Режим shell-completion отключает журнал целиком.

## Инварианты

- Ровно одна запись на процесс, append атомарен на локальной ФС;
  параллельные писатели не смешиваются.
- Журналирование fail-open: любая ошибка журнала (права, диск, лок)
  молча глотается — команда никогда не падает и не меняет свой exit
  из-за журнала.
- Секреты маскируются до записи, необратимо: значения опций, чьё имя
  содержит password/token/secret/api-key/session (без учёта регистра,
  и раздельная, и `=`-форма), и такие же ключи рекурсивно внутри
  JSON-тела `-b/--body` (`@file` не разворачивается; невалидный JSON не
  трогается).
- Команды `log`, `confirm`, `search` и `api get-token` пишутся в журнал
  БЕЗ секций out/err (перехват для них не включается вовсе).
- Ротация ждёт лок не дольше 0,5 с: не успела — запись пишется без
  ротации; сама запись при неудачной ротации никогда не теряется.
- `mpu log` идемпотентен и не мутирует.

## Граничные случаи и ошибки

- Перехват вывода не удался → команда работает без перехвата, запись
  без out/err.
- Вывод сверх лимита → маркер `truncated` с числом байт; неполный
  хвостовой UTF-8-символ дорезается.
- Пустой (0 байт) файл журнала не ротируется никогда — первая запись
  любой величины ложится целиком.
- Лог-файла нет → чтение даёт «записей не найдено», exit 0.
- Ошибка чтения (кроме отсутствия файла) → exit 1 с путём и причиной.

## Golden-примеры

Снять при переводе в «к реализации»: `mpu log --help`; `--tail 5`;
`--failed --tail 20`; `--cmd sql-ro --tail 10`; `--since 1h`;
`--run <живой id>`. Снимать на журнале без чувствительного содержимого
или маскировать при укладке в фикстуры.
