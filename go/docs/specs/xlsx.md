# mpu xlsx

Статус: к реализации

## Назначение

Чтение локальных `.xlsx` (OOXML) без сети и без кэша: список листов,
значения диапазонов, алиасы путей. Первая (харнесс-)команда порта —
проверяет диспетчер, гейты и differential целиком.

## CLI-контракт

Подкоманды: `ls`, `get`, `open`, `resolve`, `alias add|ls|rm`.
`mpu xlsx` без подкоманды печатает справку, exit 2.

Резолв пути к файлу (общий для `ls`/`get`/`open`/`resolve`), первый
непустой источник побеждает: `-f/--file` → env `MPU_XLSX` → конфиг-ключ
`xlsx.default`. Значение источника сначала пробуется как алиас, если
похоже на имя алиаса (нет `/`, `\`, не начинается с `~`, не кончается
на `.xlsx`, матчит `[A-Za-z0-9_.-]+`): алиас найден → берётся его путь;
не найден → значение трактуется как путь (относительный — от cwd).
Ни один источник не дал пути → exit 2, stderr:
`mpu xlsx: путь к .xlsx не задан. Проверены (по порядку): --file/-f,
env MPU_XLSX, config xlsx.default; попробуй: --file <путь>,
export MPU_XLSX=<путь> или задай config xlsx.default`.

`mpu xlsx ls [-f PATH] [-l/--long] [--json]`
- default: `{title}\n` на лист, порядок как в книге;
- `-l`: `{title:<w}  {rows}×{cols:>w}  #{index}`, ширины по code points;
- `--json`: массив `{"title","index" (0-based),"rows","cols"}`,
  indent=2, ensure_ascii=false, **без финального `\n`**;
- `-l` + `--json` → exit 2: `only one of --long / --json can be set`;
- rows/cols — фактический максимум встреченных ячеек (с учётом merge),
  0×0 для пустого листа.

`mpu xlsx get [RANGES...] [-f PATH] [-n/--sheet NAME] [--from FILE|-]
[--render both|values|formulas] [--json] [--raw] [--tsv]`
- Источники диапазонов складываются: аргументы + `--from` (построчно,
  `-` = stdin, строки с `#` после trim — комментарий, пустые
  пропускаются); если диапазонов нет, но задан `--sheet` — весь лист.
- `--sheet` префиксует только диапазоны без `!` (имя кавычится, если
  содержит пробел/`'`/`!`); с `!` — не трогаются.
- Дедупликация по строковому виду после префиксации, порядок первого
  вхождения сохраняется.
- Голое имя листа = весь лист. Диапазон без `!` и без `--sheet` →
  exit 2 с подсказкой про `--sheet`. Совсем нет диапазонов → exit 2:
  `no ranges provided; попробуй: mpu xlsx get [RANGES...] [--from FILE]
  [--sheet SHEET]`.
- `--render` вне both|values|formulas → exit 2. Более одного из
  `--json`/`--raw`/`--tsv` → exit 2:
  `only one of --json / --raw / --tsv can be set`.
- Вывод default (JSON): `{"file": <абсолютный путь>, "cells": [...]}`,
  ячейка `{"range":"Лист!A1","value":...,["formula":"=..."]}`; indent=2,
  ensure_ascii=false, без финального `\n`. Ключ `formula` есть только у
  реальных формул (никогда `formula: null`). `--render values` — только
  `value`; `--render formulas` — только `formula` (у не-формул ключа нет).
- `--tsv`: шапка `range\tvalue[\tformula]`, по строке на ячейку, финальный
  `\n`; экранирование: `\` → `\\`, `\n` → `\n`-литерал, `\r`, `\t` так же.
- `--raw`: ровно одна ячейка → голое значение без `\n`; больше — по
  строке на ячейку, значения через `\t`, без шапки и колонки range.
- Рендер значений в tsv/raw — строковый: null → пусто, bool →
  `True`/`False`, int → `42`, float → `3.5` (см. «Известные отклонения»).
- Открытые диапазоны (`A:A`, `1:5`, `A1:A`, голое имя листа) клэмпятся к
  фактическим границам листа; заданная граница не уменьшается (`A5:A` на
  листе из 3 строк → строка 5..5). Реверсный `B2:A1` нормализуется в
  `A1:B2`.

Типизация значений `get`: shared string / inline string → строка (rich
text склеивается без форматирования, XML-entities раскрываются, пробелы
сохраняются); bool → true/false; ячейка-ошибка → её текст строкой
(`#DIV/0!`); число → int, если целое, иначе float; нечисловой raw в
числовой ячейке → сырая строка; пустое значение → null. Формула наружу
всегда с ведущим `=`; у зависимых ячеек shared/array-формул формулы нет,
значение есть. Merged-область: значение якорной (верхней-левой) ячейки
копируется на всю область без формулы; уже существующая явная ячейка
внутри области не перезаписывается.

`mpu xlsx open [-f PATH] [--print/-p]` — `--print` печатает резолвленный
путь; иначе запускает `xdg-open`/`open` отвязанным процессом, не ожидая
и не проверяя результат; открывателя нет → exit 1 с подсказкой `--print`.

`mpu xlsx resolve [-f PATH] [--json]` — диагностика трёх источников
пути; `--json`: `{"resolved": {"path","source",["alias"]} | null,
"checked": [{"source","label","value","used"} ×3]}`; не резолвится и не
json → exit 2.

`mpu xlsx alias add NAME PATH` — имя по `[A-Za-z0-9_.-]+`, иначе exit 2;
пустой путь → exit 2; upsert, путь хранится как введён (не проверяется);
`alias ls [--json]`; `alias rm NAME` — идемпотентно, exit 0 всегда.

## Ввод/вывод

stdout — данные; stderr — ошибки в формате
`mpu xlsx: <причина>[; попробуй: <подсказка>]`, без трейсбеков.
Exit: 0 — успех; 2 — ошибки ввода (флаги, диапазоны, путь не задан,
имя алиаса); 1 — ошибки файла (не найден, не zip, битый XML, нет листа)
и `open` без открывателя.

## Побочные эффекты

Чтение файла: книга разбирается в память целиком при открытии (все
листы сразу, без потоковой обработки и лимита размера). Запись — только
служебная БД конфига при `alias add/rm`. Сети нет. `open` порождает
отвязанный дочерний процесс.

## Конфигурация

Env `MPU_XLSX`; конфиг-ключ `xlsx.default` и хранилище алиасов — в
служебной БД mpu (контракт — `platform/config.md`).

## Инварианты

- Повторный вызов с теми же входами даёт побитово тот же вывод (чистое
  чтение, без кэша и состояния).
- Сетевых обращений нет ни в одной подкоманде.
- `formula` в JSON присутствует ⇔ у ячейки есть формула.
- `get` возвращает плотный прямоугольник: пустые ячейки включены
  (`value: null`), только-непустых режимов нет.
- Конфликты флагов и разбор диапазонов валидируются до открытия файла.
- `alias rm` несуществующего имени — успех, не ошибка.

## Граничные случаи и ошибки

- Файл не существует → exit 1: `file not found: "<путь>"`.
- Не zip → exit 1: `not a valid xlsx file: "<путь>" (not a zip archive)`.
- Zip без книги → exit 1: `… (missing xl/workbook.xml)`.
- Битый XML → exit 1: `… (malformed XML: <детали>)`.
- Несуществующий лист → exit 1:
  `sheet "X" not found. Available: <имена через запятую+пробел>`.
- Пустой лист целиком → `"cells": []`, exit 0 (не ошибка).
- Открытый диапазон целиком вне данных → пустой результат, exit 0.
- Строки/ячейки без явных координат в XML нумеруются последовательно от
  предыдущей позиции.
- Merge с отсутствующей якорной ячейкой игнорируется молча.

## Golden-примеры

Фикстуры в `fixtures/xlsx/` (входы `sample.xlsx` — 2 листа: «Данные»
6×3 со строками, числами, bool, формулой, ошибкой, merge; «Пустой» —
без ячеек; `broken.xlsx` — не zip). Сняты с живой версии 2026-07-27:

| Вызов | Эталон | exit |
| --- | --- | --- |
| `ls -f sample.xlsx` | `ls.txt` | 0 |
| `ls -f sample.xlsx -l` | `ls-long.txt` | 0 |
| `ls -f sample.xlsx --json` | `ls-json.txt` | 0 |
| `get -f sample.xlsx 'Данные!A1:C3'` | `get-range.json` | 0 |
| `get -f sample.xlsx 'Данные!A4:A6'` | `get-formula-error-merge.json` | 0 |
| `get -f sample.xlsx 'Данные!A1:C2' --tsv` | `get-tsv.txt` | 0 |
| `get -f sample.xlsx 'Данные!B2' --raw` | `get-raw.txt` | 0 |
| `get -f sample.xlsx 'Пустой'` | `get-empty-sheet.json` | 0 |
| `get -f sample.xlsx` (без диапазонов) | `err-no-ranges.txt` | 2 |
| `get -f broken.xlsx 'S!A1'` | `err-not-zip.txt` | 1 |
| `get -f sample.xlsx 'Нет!A1'` | `err-unknown-sheet.txt` | 1 |

Поле `"file"` в JSON — абсолютный путь: машинозависимо, при сверке
сравнивать с подстановкой.

## Известные отклонения

- **preserve** — tsv/raw печатают bool как `True`/`False` (строковый
  рендер оригинала), тогда как JSON — `true`/`false`. Причина:
  поведенческая нейтральность харнесс-команды, differential обязан быть
  пустым. Идея унификации — в журнал переезда.
- **preserve** — значение, похожее на алиас, но отсутствующее в алиасах,
  молча трактуется как относительный путь (нет ошибки «alias not
  found»); итог — обычно `file not found` с непривычным путём. Причина:
  нейтральность; идея явной ошибки — в журнал переезда.
- **preserve** — явная ячейка внутри merged-области побеждает якорную
  (данные файла не затираются).
