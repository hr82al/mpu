# CLAUDE.md — `@mpu/http`

Транспорт HTTP внешних систем mpu: один вызов через `node:http`/`node:https`
под двумя пределами времени, прокси (явный → окружение → напрямую; `http`,
`https`, `socks5`, `socks5h`), редиректы как у `fetch`, причина отказа одной
строкой, маска учётных данных прокси, сборка `multipart/form-data`.
Потребитель — `ts/` монорепозитория mpu (Kaiten, GitLab, Loki, Portainer,
Sheets, sl-back, Telegram), ставит пакет архивом из `release/`.

Спеки — в `ts/docs/specs/` mpu (сессии библиотеки не видны): договор пакета
`platform/tslibs-package.md`, сама библиотека `platform/tslibs-http.md`,
поведение транспорта `platform/loki-http.md`, прокси
`platform/node-runtime.md` [S.9]. Ссылки на спеки в комментариях кода — от
`ts/docs/specs/`.

## Команды

```bash
bun install
VITEST_MAX_FORKS=2 bun run gate   # biome → tsc → тесты Bun, Node, Deno → сборка → check:release
bun run build                     # dist/index.js и dist/*.d.ts
bun run release                   # release/mpu-http-<версия>.tgz
bun run check:release             # архив в release/ = упаковка текущего dist/
```

Рантаймы гейт гонит по одному. Поменялись исходники или `package.json` —
`bun run release` и архив в тот же коммит, иначе `check:release` красный.
Новая версия — `version` в `package.json` и новый архив в `release/` одним
коммитом, прежний архив удаляется; потребитель переходит своей правкой
`package.json`.

## Раскладка

- `index.ts` — поверхность: всё, что видит потребитель. Мимо неё ничего не
  экспортируется; расширение поверхности — решение, а не попутная правка.
- `src/` — устройство и тесты `*.test.ts` рядом с кодом. Помощники тестов
  (подставной сервер, пойманная ошибка) — из `@mpu/testing`.
- `release/` — архивы версий, коммитятся; `dist/` — нет.

## Правила кода

Действуют правила `ts/CLAUDE.md` mpu; главное из них:

- Ничего специфичного для рантайма: ни `Deno.*`, ни `Bun.*`, ни `fetch` с
  параметрами рантайма — только `node:*` и npm. Тесты — Vitest, зелёные под
  Bun, Node и Deno.
- Функция ≤ 40 строк, вложенность ≤ 3; ранние выходы. JSDoc на каждом
  экспорте; комментарий объясняет «почему».
- Строгий TypeScript, без `any`; `as` и `!` — с обоснованием рядом.
- Бросаются только `Error` и подклассы с говорящим `name`, обёртка — через
  `cause`; текст ошибки с маленькой буквы, одной строкой.
- Внешнее (окружение процесса) передаётся параметром, а не читается по месту.
- Никакой работы при импорте; тяжёлое — лениво, на своей ветке.
- Синхронизация сном (`setTimeout`) в тестах запрещена.

## Порядок изменения

Гейт зелёный → разбор итогового диффа субагентом со свежим контекстом (не
автор) по чек-листам `../../ts/docs/checklists/review.md` + `review-mpu.md`
(сессию библиотеки запускают с `--add-dir` на этот каталог; копий нет) →
исправление найденного → гейт зелёный повторно → коммит. Ядро чек-листов:
объект держит свою память (запись + свободные функции над ней — не объект);
особый случай — отдельная реализация, а не ветка по виду; позднее связывание
и один null-объект на модуль вместо проверок `typeof`/`instanceof`/`null`;
голые данные (строка-код, булев флаг, кортеж) — протоколом.

## Зависимости

Версии точные, без `^`; `bun.lock` коммитится.

- `https-proxy-agent` — туннель CONNECT для `https:` через прокси, одинаково
  под Bun, Deno и Node (проба этапа 2; `undici` под Bun подменяется и
  ломается).
- `socks-proxy-agent` — прокси `socks5`/`socks5h`: Bot API обещает эти схемы,
  прежний клиент Deno их понимал (решение владельца 2026-10-07). Версия 8.x —
  на той же `agent-base` 7, что у `https-proxy-agent`.
- `@mpu/testing` (dev, архивом `../testing/release/`) — подставной сервер и
  пойманная ошибка для тестов.
- `vitest` 3.2.4 — тесты под тремя рантаймами; `@biomejs/biome` — формат и
  линт; `typescript`, `@types/node` — проверка типов и `.d.ts` сборки.
