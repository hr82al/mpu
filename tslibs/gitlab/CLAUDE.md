# CLAUDE.md — `@mpu/gitlab`

Клиент GitLab MR API без привязки к рантайму и к слою команд: доступ, резолв
адреса MR (селектор, `git remote`), вызовы REST API v4 (чтение и запись
дискуссий, описания, создание MR, ветки коммита), формы ответов, position
инлайн-комментария, матчинг дискуссии. Потребитель — `ts/` монорепозитория
mpu (подкоманды `mpu mr …`, `mpu glab-status`), ставит пакет архивом из
`release/`.

Спеки — в `ts/docs/specs/` mpu (сессии библиотеки не видны): договор пакета
`platform/tslibs-package.md`, порция `platform/tslibs-n1.md`, поведение —
`platform/gitlab-api.md` и спеки команд-потребителей (`mr-read.md`,
`mr-write.md`, `glab-status.md`). Ссылки на спеки в комментариях кода — от
`ts/docs/specs/`.

## Команды

```bash
bun install                       # пакеты
VITEST_MAX_FORKS=2 bun run gate   # biome → tsc → тесты Bun, Node, Deno → check:release
bun run build                     # dist/index.js, dist/testing.js и *.d.ts
bun run release                   # release/mpu-gitlab-<версия>.tgz
bun run check:release             # сборка и упаковка = архив в release/
```

Рантаймы гейт гонит по одному. Поменялись исходники или `package.json` —
`bun run release` и архив в тот же коммит, иначе `check:release` красный.
Любое изменение `dist/` — новая версия: `version` в `package.json` и новый
архив в `release/` одним коммитом, прежний архив удаляется; потребитель
переходит своей правкой `package.json`.

## Раскладка

- `index.ts` — поверхность: доступ и `GitlabError`, формы ответов, резолв и
  `MrRefError`, вызовы API, position, матчинг и `DiscussionRefError`,
  `spawnGit`.
- `testing.ts` — вход `@mpu/gitlab/testing`: фейковый GitLab на петле
  (`startFakeGitlab`) для тестов библиотеки и потребителя.
- `src/` — устройство и тесты `*.test.ts` рядом с кодом. Помощники тестов —
  из `@mpu/testing`.
- `release/` — архивы версий, коммитятся; `dist/` — нет.

## Правила кода

Действуют правила `ts/CLAUDE.md` mpu; главное из них:

- Ничего специфичного для рантайма: ни `Deno.*`, ни `Bun.*` — только `node:*`
  и npm. Тесты — Vitest, зелёные под Bun, Node и Deno.
- Слой команд `mpu` библиотеке не известен: ни импорта из `ts/`, ни env-файла,
  ни текстов справки. Ошибки — `GitlabError` (отказ GitLab, поле `status`;
  сетевой сбой — 0), `MrRefError` (селектор MR; `input` — ошибка ввода, до
  сети), `DiscussionRefError` (дискуссия не найдена); коды выхода и подсказки
  назначает потребитель.
- Внешнее — параметрами: адрес и токен — `GitlabAccess`, запуск git — портом
  `RunGit` (`spawnGit` — настоящий). Токен не попадает ни в один текст ошибки.
- Функция ≤ 40 строк, вложенность ≤ 3; ранние выходы. JSDoc на каждом
  экспорте; комментарий объясняет «почему».
- Строгий TypeScript, без `any`; `as` и `!` — с обоснованием рядом.
- Никакой работы при импорте.
- Синхронизация сном (`setTimeout`) в тестах запрещена. Сети наружу в тестах
  нет — только стенд на петле; настоящий git тесты не запускают.

## Порядок изменения

Гейт зелёный → разбор итогового диффа субагентом со свежим контекстом (не
автор) по чек-листам `../../ts/docs/checklists/review.md` + `review-mpu.md`
(сессию библиотеки запускают с `--add-dir` на этот каталог; копий нет) →
исправление найденного → гейт зелёный повторно → коммит. Ядро чек-листов:
объект держит свою память (запись + свободные функции над ней — не объект);
особый случай — отдельная реализация, а не ветка по виду; позднее связывание
и один null-объект на модуль вместо проверок `typeof`/`instanceof`/`null`;
голые данные (строка-код, булев флаг, кортеж) — протоколом.

## Зависимости

Версии точные, без `^`; `bun.lock` коммитится. Своих рантайм-зависимостей
нет. Пакеты mpu — `devDependencies` архивом `../<имя>/release/` для своей
установки и необязательные `peerDependencies` для потребителя: вложенный путь
`file:` архива `bun` разрешает от корня потребителя, и прямая зависимость там
не ставилась бы (проба T1). Потребитель ставит их сам — копия на граф одна.

- `@mpu/http` — транспорт HTTP: пределы времени, причина сетевого отказа
  одной строкой.
- `@mpu/subprocess` — запуск `git` для резолва адреса (`spawnGit`).
- `@mpu/base` — `@mpu/base/oserror`: отсутствие `git` в `PATH` по коду ОС.
- `@mpu/testing` — подставной сервер для `@mpu/gitlab/testing` и пойманная
  ошибка тестов; потребителю нужна, только если он берёт
  `@mpu/gitlab/testing`.
- `vitest` 3.2.4 — тесты под тремя рантаймами; `@biomejs/biome` — формат и
  линт; `typescript`, `@types/node` — проверка типов и `.d.ts` сборки.
