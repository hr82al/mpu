# CLAUDE.md — `@mpu/invokelog`

Журнал вызовов `mpu`: одна запись на исполнение команды (CLI-вызов или
вызов тула MCP-сервером) — что запускали, вывод, ошибки, код, длительность;
маскирование секретов в строке вызова, формат записи, настройки `MPU_LOG_*`,
дозапись и ротация файла под межпроцессным локом. Потребитель — `ts/`
монорепозитория mpu (точка входа, MCP-сервер, сервер строк, исполнитель,
`mpu log`), ставит пакет архивом из `release/`.

Спеки — в `ts/docs/specs/` mpu (сессии библиотеки не видны): договор пакета
`platform/tslibs-package.md`, порция `platform/tslibs-n4.md`, поведение —
`platform/invoke-log.md` (ротация и лок — `platform/node-runtime.md` [S.7],
ключи — `platform/env-file.md`). Ссылки на спеки в комментариях кода — от
`ts/docs/specs/`.

## Команды

```bash
bun install                       # пакеты
VITEST_MAX_FORKS=2 bun run gate   # biome → tsc → тесты Bun, Node, Deno → check:release
bun run build                     # dist/index.js и *.d.ts
bun run release                   # release/mpu-invokelog-<версия>.tgz
bun run check:release             # сборка и упаковка = архив в release/
```

Рантаймы гейт гонит по одному. Поменялись исходники или `package.json` —
`bun run release` и архив в тот же коммит, иначе `check:release` красный.
Любое изменение `dist/` — новая версия: `version` в `package.json` и новый
архив в `release/` одним коммитом, прежний архив удаляется; потребитель
переходит своей правкой `package.json`.

## Раскладка

- `index.ts` — поверхность: `makeInvokeLog`, `NO_INVOKE_LOG`, `DEFAULT_KEEP`
  и типы записи. Входа `./testing` нет: журнал, который ничего не пишет, —
  часть поверхности, а не тестовый помощник.
- `src/` — устройство (`mod` — запись, `mask` — строка вызова с маской,
  `record` — формат записи, `settings` — ключи `MPU_LOG_*`, `file` — дозапись
  и ротация) и тесты `*.test.ts` рядом с кодом; `testrotate.ts` — процесс-
  ротатор межпроцессного теста, его запускает только `file.test.ts`.
- `src/testdata/` — копии эталонов записи из канала
  `ts/docs/specs/fixtures/platform/invoke-log/` байт-в-байт. Сверить их с
  каналом не может ни пакет (канал вне его папки), ни `ts/` (папку пакета он
  не читает), поэтому правило: копия меняется только переносом файла из
  канала тем же коммитом, что и эталон, никогда правкой по месту; Biome их не
  форматирует (`biome.json`, `!**/testdata`).
- `untyped-modules.d.ts` — `proper-lockfile` без своих типов; нужную часть
  поверхности объявляет `src/file.ts` (`LockFiles`).
- `release/` — архивы версий, коммитятся; `dist/` — нет.

## Правила кода

Действуют правила `ts/CLAUDE.md` mpu; главное из них:

- Ничего специфичного для рантайма: ни `Deno.*`, ни `Bun.*` — только `node:*`
  и npm. Тесты — Vitest, зелёные под Bun, Node и Deno. Второй процесс в
  тесте — `runTs` из `@mpu/command/testing`, а не имя рантайма из `PATH`.
- Журнал не меняет исход команды: ни один метод записи не бросает, ошибка
  журнала (права, диск, лок) глотается в `finish` (fail-open, спека).
- Секреты не попадают в запись ни в каком виде: маска строки вызова и
  секции `err` у ошибки ввода; файл журнала — права 0600.
- Функция ≤ 40 строк, вложенность ≤ 3; ранние выходы. JSDoc на каждом
  экспорте; комментарий объясняет «почему». Правило — для нового кода:
  перенос N4 был дословным, и `recording` (`src/mod.ts`), `maskArgv`
  (`src/mask.ts`) длиннее предела — дробятся следующей правкой этих мест.
- Строгий TypeScript, без `any`; `as` и `!` — с обоснованием рядом.
- Никакой работы при импорте: `proper-lockfile` грузится лениво, в ротации
  (его `graceful-fs` при загрузке подменяет `fs.close` процесса).
- Синхронизация сном (`setTimeout`) в тестах запрещена.

## Порядок изменения

Гейт зелёный → разбор итогового диффа субагентом со свежим контекстом (не
автор) по чек-листам `../../ts/docs/checklists/review.md` + `review-mpu.md`
(сессию библиотеки запускают с `--add-dir` на этот каталог; копий нет) →
исправление найденного → гейт зелёный повторно → коммит. Ядро чек-листов:
объект держит свою память (запись + свободные функции над ней — не объект);
особый случай — отдельная реализация, а не ветка по виду; позднее связывание
и один null-объект на модуль вместо проверок `typeof`/`instanceof`/`null`;
голые данные (строка-код, булев флаг, кортеж) — протоколом.

## Зависимости

Версии точные, без `^`; `bun.lock` коммитится. Пакеты mpu —
`devDependencies` архивом `../<имя>/release/` для своей установки и
необязательные `peerDependencies` для потребителя: вложенный путь `file:`
архива `bun` разрешает от корня потребителя, и прямая зависимость там не
ставилась бы (проба T1). Потребитель ставит их сам — копия на граф одна.

- `proper-lockfile` 4.1.2 — лок ротации каталогом `mpu.lock` рядом с
  журналом: `mkdir` атомарен между процессами, flock у `node:fs` нет
  (`platform/node-runtime.md` [S.7], решение владельца 2026-10-07).
  Единственная рантайм-зависимость из npm.
- `@mpu/base` — `@mpu/base/oserror`: отсутствие файла или лока по коду ОС.
  Peer необязательный, но `dist/index.js` импортирует его при загрузке —
  потребителю он нужен.
- `@mpu/command` — только тип `InputSpec` (входы команды, по которым маска
  отличает объявленную опцию): в `dist/index.js` импорта нет, в `.d.ts` —
  есть. В тестах — `runTs` из `@mpu/command/testing`.
- `@mpu/language`, `zod` (dev) — peer `@mpu/command`: его `.d.ts` на них
  ссылаются, `tsc` пакета без них не проходит. Код пакета их не импортирует.
- `vitest` 3.2.4 — тесты под тремя рантаймами; `@biomejs/biome` — формат и
  линт; `typescript`, `@types/node` — проверка типов и `.d.ts` сборки.
