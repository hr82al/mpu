# CLAUDE.md — `@mpu/slback`

Разговор с sl-back без привязки к рантайму и к слою команд: сборка URL и
заголовков, один вызов под пределом времени, разбор ответа и отказа, токен
через кэш или логин. Потребитель — `ts/` монорепозитория mpu (команды
`mpu api …`, `get-token`, `ss-access`, `wb-cards-reset`, `wb-loader`), ставит
пакет архивом из `release/`; env-файл и место кэша токена — у потребителя.

Спеки — в `ts/docs/specs/` mpu (сессии библиотеки не видны): договор пакета
`platform/tslibs-package.md`, сама библиотека `platform/tslibs-slback.md`,
поведение — `platform/slback-http.md`, `api.md`, `api-write.md`. Ссылки на
спеки в комментариях кода — от `ts/docs/specs/`.

## Команды

```bash
bun install                       # пакеты
VITEST_MAX_FORKS=2 bun run gate   # biome → tsc → тесты Bun, Node, Deno → check:release
bun run build                     # dist/index.js, dist/testing.js и *.d.ts
bun run release                   # release/mpu-slback-<версия>.tgz
bun run check:release             # сборка и упаковка = архив в release/
```

Рантаймы гейт гонит по одному. Поменялись исходники или `package.json` —
`bun run release` и архив в тот же коммит, иначе `check:release` красный.
Любое изменение `dist/` — новая версия: `version` в `package.json` и новый
архив в `release/` одним коммитом, прежний архив удаляется; потребитель
переходит своей правкой `package.json`.

## Раскладка

- `index.ts` — поверхность: вызов и `SlbackError`, обрезка и дословный
  разбор JSON, сеанс (`openSlback`, `SlbackPort`) и `NoAccessTokenError`,
  запись кэша токена.
- `testing.ts` — вход `@mpu/slback/testing`: подставной sl-back на петле
  (`startFakeSlback`, `loginReply`) для тестов библиотеки и потребителя.
- `src/` — устройство и тесты `*.test.ts` рядом с кодом. Помощники тестов —
  из `@mpu/testing`.
- `release/` — архивы версий, коммитятся; `dist/` — нет.

## Правила кода

Действуют правила `ts/CLAUDE.md` mpu; главное из них:

- Ничего специфичного для рантайма: ни `Deno.*`, ни `Bun.*` — только `node:*`
  и npm. Тесты — Vitest, зелёные под Bun, Node и Deno.
- Слой команд `mpu` библиотеке не известен: ни импорта из `ts/`, ни
  env-файла, ни кэш-БД, ни текстов справки. Ошибки — `SlbackError` (сеть,
  предел времени, HTTP ≥ 400 с телом, ответ не JSON) и `NoAccessTokenError`
  (логин без токена); отказ порта (нет адреса, нет кред) проходит тем
  классом, которым его бросил потребитель. Коды выхода назначает
  потребитель.
- Внешнее — портом `SlbackPort`: адрес и креды — функциями (сеанс зовёт их
  только перед сетью), чтение и запись кэша токена. Пароль и токен не
  попадают в текст ошибки.
- Функция ≤ 40 строк, вложенность ≤ 3; ранние выходы. JSDoc на каждом
  экспорте; комментарий объясняет «почему».
- Строгий TypeScript, без `any`; `as` и `!` — с обоснованием рядом.
- Никакой работы при импорте.
- Синхронизация сном (`setTimeout`) в тестах запрещена; срок записи кэша —
  часами-параметром `Clock`. Сети наружу в тестах нет — только стенд на
  петле.

## Порядок изменения

Гейт зелёный → разбор итогового диффа субагентом со свежим контекстом (не
автор) по чек-листам `../../ts/docs/checklists/review.md` + `review-mpu.md`
(сессию библиотеки запускают с `--add-dir` на этот каталог; копий нет) →
исправление найденного → гейт зелёный повторно → коммит. Ядро чек-листов:
объект держит свою память (запись + свободные функции над ней — не объект);
особый случай — отдельная реализация, а не ветка по виду; позднее связывание
и один null-объект на модуль вместо проверок `typeof`/`instanceof`/`null`;
голые данные (строка-код, булев флаг, кортеж) — протоколом.

## Зависимости

Версии точные, без `^`; `bun.lock` коммитится. Своих рантайм-зависимостей
нет.

- `@mpu/http` — транспорт HTTP: пределы времени, причина сетевого отказа
  одной строкой. Для своей установки — `devDependencies` архивом
  `../http/release/`; потребителю —
  `peerDependencies` (необязательная, чтобы `bun` не искал её в реестре):
  вложенный путь `file:` архива `bun` разрешает от корня потребителя, и
  прямая зависимость там не ставилась бы (проба T1). Потребитель ставит
  `@mpu/http` сам — копия на граф одна.
- `@mpu/testing` — подставной сервер для `@mpu/slback/testing` и пойманная
  ошибка тестов; тем же способом: `devDependencies` архивом
  `../testing/release/`, `peerDependencies` необязательная — нужна только
  потребителю, который берёт `@mpu/slback/testing`.
- `vitest` 3.2.4 — тесты под тремя рантаймами; `@biomejs/biome` — формат и
  линт; `typescript`, `@types/node` — проверка типов и `.d.ts` сборки.
