# CLAUDE.md — `@mpu/loki`

Разговор с Loki без привязки к рантайму и к слою команд: series-запрос за
окно discovery в уникальные хосты и пары (host, service), чтение записей
`query_range`. Потребитель — `ts/` монорепозитория mpu (команды `init`,
`update`, `logs`), ставит пакет архивом из `release/`; запись итога discovery
в кэш-БД — у потребителя.

Спеки — в `ts/docs/specs/` mpu (сессии библиотеки не видны): договор пакета
`platform/tslibs-package.md`, сама библиотека `platform/tslibs-ops.md`,
поведение — `platform/loki-http.md`, `init.md` (шаг 3), `logs.md`. Ссылки на
спеки в комментариях кода — от `ts/docs/specs/`.

## Команды

```bash
bun install                       # пакеты
VITEST_MAX_FORKS=2 bun run gate   # biome → tsc → тесты Bun, Node, Deno → check:release
bun run build                     # dist/index.js и *.d.ts
bun run release                   # release/mpu-loki-<версия>.tgz
bun run check:release             # сборка и упаковка = архив в release/
```

Рантаймы гейт гонит по одному. Поменялись исходники или `package.json` —
`bun run release` и архив в тот же коммит, иначе `check:release` красный.
Любое изменение `dist/` — новая версия: `version` в `package.json` и новый
архив в `release/` одним коммитом, прежний архив удаляется; потребитель
переходит своей правкой `package.json`.

## Раскладка

- `index.ts` — поверхность: доступ и `requireLokiAccess`, `LokiError` и
  `LokiHttpError`, discovery (`collectLokiSeries`), чтение записей
  (`queryRange`).
- `src/` — устройство и тесты `*.test.ts` рядом с кодом. Помощники тестов —
  из `@mpu/testing`.
- `src/testdata/` — копия golden-ответа канала спецификаций
  `ts/docs/specs/fixtures/platform/loki-http/series-ok.json`. Сверить её с
  каналом библиотека не может — он вне её папки; меняется эталон в канале —
  копия обновляется здесь тем же коммитом, что и копия в `ts/`. Biome её не
  трогает (`biome.json`, `files.includes`): отформатированная копия молча
  разошлась бы с источником.
- `release/` — архивы версий, коммитятся; `dist/` — нет.

## Правила кода

Действуют правила `ts/CLAUDE.md` mpu; главное из них:

- Ничего специфичного для рантайма: ни `Deno.*`, ни `Bun.*` — только `node:*`
  и npm. Тесты — Vitest, зелёные под Bun, Node и Deno.
- Слой команд `mpu` библиотеке не известен: ни импорта из `ts/`, ни кэш-БД,
  ни текстов справки. Ошибки — `LokiError` (сеть, предел времени, нет
  адреса, код вне 2xx у discovery) и его подкласс `LokiHttpError` (код вне 2xx
  у `queryRange`, с телом); коды выхода и тексты назначает потребитель.
- Внешнее — параметрами: адрес — `LokiAccess`, env-файл — узким портом
  `{ get }`.
- Функция ≤ 40 строк, вложенность ≤ 3; ранние выходы. JSDoc на каждом
  экспорте; комментарий объясняет «почему».
- Строгий TypeScript, без `any`; `as` и `!` — с обоснованием рядом.
- Никакой работы при импорте.
- Синхронизация сном (`setTimeout`) в тестах запрещена: пределы времени —
  маленькими числами параметра `timeouts`. Сети наружу в тестах нет — только
  стенд на петле.

## Порядок изменения

Гейт зелёный → разбор итогового диффа субагентом со свежим контекстом (не
автор) по чек-листам `../../ts/docs/checklists/review.md` + `review-mpu.md`
(сессию библиотеки запускают с `--add-dir` на этот каталог; копий нет) →
исправление найденного → гейт зелёный повторно → коммит. Ядро чек-листов:
объект держит свою память (запись + свободные функции над ней — не объект);
особый случай — отдельная реализация, а не ветка по виду; позднее связывание
и один null-объект на модуль вместо проверок `typeof`/`instanceof`/`null`;
голые данные (строка-код, булев флаг, кортеж) — протоколом.

## Зависимости

Версии точные, без `^`; `bun.lock` коммитится. Своих рантайм-зависимостей
нет.

- `@mpu/http` — транспорт HTTP: пределы времени, причина сетевого отказа
  одной строкой. Для своей установки — `devDependencies` архивом
  `../http/release/`; потребителю — `peerDependencies` (необязательная,
  чтобы `bun` не искал её в реестре): вложенный путь `file:` архива `bun`
  разрешает от корня потребителя, и прямая зависимость там не ставилась бы
  (проба T1). Потребитель ставит `@mpu/http` сам — копия на граф одна.
- `@mpu/testing` (dev) — подставной HTTP-сервер на петле и пойманная ошибка
  для своих тестов; `devDependencies` архивом `../testing/release/`. Входа
  `./testing` у пакета нет — потребителю помощники пакета не нужны.
- `vitest` 3.2.4 — тесты под тремя рантаймами; `@biomejs/biome` — формат и
  линт; `typescript`, `@types/node` — проверка типов и `.d.ts` сборки.
