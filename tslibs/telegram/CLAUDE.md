# CLAUDE.md — `@mpu/telegram`

Разговор с Telegram без привязки к рантайму: сеанс MTProto от личного
аккаунта (открыть по настройкам, узнать себя, найти адресата, отправить текст
и файл, диалоги, поиск, скачать вложение, вход) и вызов Bot API. Потребитель —
`ts/` монорепозитория mpu (команды `mpu telegram …`, хук уведомлений, вопросы
бота), ставит пакет архивом из `release/`.

Спеки — в `ts/docs/specs/` mpu (сессии библиотеки не видны): договор пакета
`platform/tslibs-package.md`, сама библиотека `platform/tslibs-telegram.md`,
поведение слоя `platform/telegram-mtproto.md` и `telegram-*`. Ссылки на спеки в
комментариях кода — от `ts/docs/specs/`.

## Команды

```bash
bun install                       # пакеты и src/wasm_modules.ts (prepare)
VITEST_MAX_FORKS=2 bun run gate   # biome → tsc → тесты Bun, Node, Deno → check:release → check:lazy → check:binary
bun run build                     # dist/index.js, dist/session.js, общий кусок и *.d.ts
bun run release                   # release/mpu-telegram-<версия>.tgz
bun run check:release             # сборка и упаковка = архив в release/
bun run check:lazy                # в графе лёгкого входа нет @mtcute (после сборки)
bun run check:binary              # бинарь bun build --compile поднимает wasm без файла рядом
```

Рантаймы гейт гонит по одному. Поменялись исходники или `package.json` —
`bun run release` и архив в тот же коммит, иначе `check:release` красный.
Новая версия — `version` в `package.json` и новый архив в `release/` одним
коммитом, прежний архив удаляется; потребитель переходит своей правкой
`package.json`.

## Раскладка

- `index.ts` — лёгкая поверхность: конфигурация, адресат, отправка и поиск
  поверх порта клиента, вложения, Bot API, ошибки. Рантайм-импорта `@mtcute/*`
  в её графе нет — сторожит `check:lazy`.
- `session.ts` — вход `@mpu/telegram/session`: живой клиент MTProto
  (`openSession`, `openLoginClient`) и wasm криптографии. Потребитель грузит
  его лениво — старт каждой команды за клиент не платит. Общий код двух входов
  сборка кладёт в общий кусок (`--splitting`): класс ошибки один на оба.
- `src/` — устройство и тесты `*.test.ts` рядом с кодом. Помощники тестов —
  из `@mpu/testing`.
- `src/wasm_modules.ts` — байты `@mtcute/wasm` модулем; порождает
  `scripts/gen-wasm-modules.ts` при установке и сборке, не коммитится.
- `scripts/crypto-probe.ts` — вход пробы `check:binary`.
- `release/` — архивы версий, коммитятся; `dist/` — нет.

## Правила кода

Действуют правила `ts/CLAUDE.md` mpu; главное из них:

- Ничего специфичного для рантайма: ни `Deno.*`, ни `Bun.*` — только `node:*`
  и npm. Тесты — Vitest, зелёные под Bun, Node и Deno.
- Слой команд `mpu` библиотеке не известен: ни импорта из `ts/`, ни текстов
  справки и флагов. Ошибки — `TelegramError` (отказ конфигурации или
  Telegram) и `TelegramInputError` (ввод), текст — строка слоя
  `telegram: <причина>`; коды выхода назначает потребитель.
- Внешнее — параметрами: env-файл — портом `EnvKeys`, каталог вложений —
  `Inbox`. Отказ `EnvKeys.require` («ключа нет») слой не переоформляет: его
  класс знает только потребитель, он и отдаёт его строкой слоя.
- Функция ≤ 40 строк, вложенность ≤ 3; ранние выходы. JSDoc на каждом
  экспорте; комментарий объясняет «почему».
- Строгий TypeScript, без `any`; `as` и `!` — с обоснованием рядом.
- Никакой работы при импорте; тяжёлое — лениво, на своей ветке.
- Синхронизация сном (`setTimeout`) в тестах запрещена; время — поддельные
  часы Vitest. Сети в тестах нет.

## Порядок изменения

Гейт зелёный → разбор итогового диффа субагентом со свежим контекстом (не
автор) по чек-листам `../../ts/docs/checklists/review.md` + `review-mpu.md`
(сессию библиотеки запускают с `--add-dir` на этот каталог; копий нет) →
исправление найденного → гейт зелёный повторно → коммит. Ядро чек-листов:
объект держит свою память (запись + свободные функции над ней — не объект);
особый случай — отдельная реализация, а не ветка по виду; позднее связывание
и один null-объект на модуль вместо проверок `typeof`/`instanceof`/`null`;
голые данные (строка-код, булев флаг, кортеж) — протоколом.

## Зависимости

Версии точные, без `^`; `bun.lock` коммитится.

- `@mtcute/node` — клиент MTProto: шифрование, схема TL, транспорт с прокси
  (socks4/socks5/http/https). Тянет `better-sqlite3` (нативный) — с
  `MemoryStorage` он не загружается.
- `@mtcute/convert` — строка сессии в формате прежней реализации: клиент её
  как есть не принимает; без конвертера переезд потребовал бы повторного входа.
- `@mtcute/markdown-parser` — разметка Markdown отправки (`--md` команды).
- `@mtcute/wasm` — транзитивный, назван поимённо ради `initSync`: штатная
  инициализация берёт wasm рядом с пакетом, а у собранной программы его там
  нет; байты приходят модулем `src/wasm_modules.ts`.

  Четыре `@mtcute/*` — строго одной версии и бампятся отдельной порцией:
  библиотека держит строку сессии и api-hash и несёт бинарный wasm. При бампе
  `src/wasm_modules.ts` пересобирается сам (сверяет `src/crypto.test.ts`).
- `@mpu/http` — транспорт Bot API: пределы времени, прокси, причина отказа
  одной строкой. Для своей установки — `devDependencies` архивом
  `../http/release/`; потребителю — `peerDependencies` (необязательная, чтобы
  `bun` не искал её в реестре): вложенный путь `file:` архива `bun`
  разрешает от корня потребителя, и прямая зависимость там не ставилась бы
  (проба T1). Потребитель ставит `@mpu/http` сам — копия на граф одна.
- `@mpu/testing` (dev, архивом `../testing/release/`) — подставной сервер и
  пойманная ошибка для тестов.
- `vitest` 3.2.4 — тесты под тремя рантаймами; `@biomejs/biome` — формат и
  линт; `typescript`, `@types/node` — проверка типов и `.d.ts` сборки.
