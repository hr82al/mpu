# `@mpu/receiver` — протокол получателя

Автор домена описывает получателя данными рядом с методами (`about`) и
получает даром проверку ключей, политику `allow`/`ask`/`deny`, журнал, отказ на
непонятое, справку, файл интерфейса и тесты соответствия. Спека —
`ts/docs/specs/platform/tslibs-receiver.md`, договор пакета —
`ts/docs/specs/platform/tslibs-package.md` (в сессии библиотеки их может не
быть видно: тогда источник — этот файл и тесты).

## Команды

```bash
bun install                 # зависимости (bun.lock коммитится)
bun run gate                # biome check, tsc, тесты Bun/Node/Deno, сборка
bun run test:node           # один рантайм; файл — путём, случай — -t "имя"
bun run interface           # голдены INTERFACE.md/interface.json тестового домена
bun run build               # dist/ (не коммитится)
bun run release             # release/mpu-receiver-<версия>.tgz (коммитится)
```

Vitest ограничен `maxWorkers: 2` (`vitest.config.ts`): машину делят несколько
сессий. Новая версия — `version` в `package.json` и новый архив в одном
коммите, прежний архив удалён.

## Устройство

- `index.ts` — поверхность (JSDoc на каждом экспорте); `testing.ts` —
  `conformance()` и фейки портов.
- `src/about.ts` — типы описания: `About<T>`, `described<T>()` (точная сверка
  схемы `args` с параметром метода).
- `src/envelope.ts` → `src/protocol.ts` → `src/method.ts`: порядок проверок
  конверта — отмена → понимание → ключи (`src/keys.ts`) → решение книги
  (`src/rules.ts`; ответ человека — `Reply` `agreed`/`refused`) → исполнение и
  журнал → ответ (`src/answer.ts`, `src/refusal.ts`). `src/effect.ts` —
  эффект метода объектом (правило по умолчанию, полка отражения, аудит (д)).
- `src/graph.ts` — граф домена от корня по `returns` (ключ — сам класс; класс
  без `about` — `BareNode`); его читают `src/interface.ts` (файл интерфейса) и
  `src/conformance.ts` (проверки (а)–(ж)); `src/compat.ts`, `src/write.ts` —
  совместимость и запись файлов.
- `test/kaiten/` — тестовый домен и его голдены; `test/broken.ts` — по одной
  поломке на проверку; `test/about.types.ts` — что ловит `tsc`
  (`@ts-expect-error`).

`zod` импортируется только `import * as z from "zod"`: под `bun --bun`
именованный `{ z }` приходит `undefined` (замер 2026-10-07, Bun 1.4.2).

Метод домена, который не должен быть снаружи, — `#private`: TS-`private`
во время работы публичен, и проверка (а) его найдёт.

## Зависимости — зачем

Версии точные, без `^`.

- `zod` — схема ключей метода (`args`): из неё проверка входа, тип параметра
  (`z.infer`), JSON-схема для справки и `interface.json`.
- `fastest-levenshtein` — расстояние для ближайших селекторов и ключей
  непонятого сообщения.
- `vitest` (dev и `peerDependencies`) — раннер тестов под тремя рантаймами;
  `dist/testing.js` импортирует его для `conformance()`.
- `@vitest/coverage-istanbul` — покрытие с одинаковыми цифрами под тремя.
- `typescript` — `tsc --noEmit` гейта и `.d.ts` сборки (версия как у `ts/`).
- `@types/node` — типы `node:*` для `tsc`.
- `@biomejs/biome` — формат и линт; `interface.json` из него исключён: файл
  пишет генератор, форматтер переписал бы его, и сверка (е) краснела бы.

## Правила кода (выжимка `ts/CLAUDE.md`)

- Ничего специфичного для рантайма: только `node:*` и разрешённые npm-пакеты
  (`zod`, `fastest-levenshtein`); тесты — Vitest, зелёные под Bun, Node, Deno.
  `rg -n 'Deno\.|Bun\.' src index.ts testing.ts` — пусто.
- Объект держит свою память; особый случай — отдельная реализация протокола,
  а не ветка по виду; отсутствие — один null-объект на модуль; `switch` по
  union — только для данных на границе контракта. Композиция вместо
  наследования (`extends` — только подклассы `Error`). Никаких Proxy, глобалов,
  работы при импорте.
- Функция ≤ 40 строк, вложенность ≤ 3; ранний `return`. Строгий TS, без `any`;
  `as` — с комментарием-обоснованием. Внешнее (часы, журнал, правила, ФС) —
  параметром.
- Ошибки — подклассы `Error` с `name`, обёртка через `cause`; текст с
  маленькой буквы. Секреты не попадают ни в журнал, ни в отказ, ни в файл
  интерфейса.
- TDD: тест первым и красным; `toStrictEqual`, сообщение вторым аргументом
  `expect`. Тест инварианта или политики — с мутационной проверкой: сломать
  проверяемое там, где его читает проверка, увидеть красное, вернуть.
- Перед каждым коммитом: `bun run gate` зелёный → разбор диффа свежим
  контекстом по чек-листам `review.md` + `review-mpu.md` → исправления → гейт
  снова. Коммиты — Conventional Commits, тема по-русски в императиве, только
  явными путями (`git add tslibs/receiver/…`, `git commit -- tslibs/receiver`).
