# CLAUDE.md — `@mpu/cmd-sql`

Команды `mpu sql-ro` и `mpu sql`: ad-hoc SQL по селектору в PostgreSQL сервера
`sl-N`, клиента или dev-стенда, и общий для них ход вызова — цель, сессия
драйвера, печать ответа. Потребители — реестр `ts/` монорепозитория mpu и
соседние команды того же сервера (резервные копии, вызовы кабинетов,
копирования): правила подключения у них одни. Пакет ставится архивом из
`release/`.

Спеки — в `ts/docs/specs/` mpu (сессии пакета не видны): порция
`platform/tslibs-commands.md` (D2), договор пакета `platform/tslibs-package.md`;
поведение — `sql-ro.md`, `sql.md`, `platform/readonly-default.md`. Ссылки на
спеки в комментариях кода — от `ts/docs/specs/`.

## Команды

```bash
bun install
VITEST_MAX_FORKS=2 bun run gate   # biome → tsc → тесты Bun, Node, Deno → check:release
bun run build                     # dist/*.js, index.d.ts
bun run release                   # release/mpu-cmd-sql-<версия>.tgz
bun run check:release             # сборка и упаковка = архив в release/
```

Рантаймы гейт гонит по одному. Поменялись исходники или `package.json` —
`bun run release` и архив в тот же коммит, иначе `check:release` красный.
Любое изменение `dist/` — новая версия: `version` в `package.json` и новый
архив одним коммитом, прежний удаляется; потребитель переходит своей правкой
`package.json`.

Под Vitest+Bun `zod` идёт через преобразование Vite
(`vitest.config.ts`, `server.deps.inline`): родной импорт внешнего модуля
теряет реэкспорт `z`.

## Раскладка

- `index.ts` — поверхность `.`: обе команды, ход вызова (`runSql`,
  `denoSession`), цель (`serverTarget`, `devTarget`, `routeOf`), сессия и её
  ошибки, форма ответа (`SqlOutcome`).
- `pg.ts` — вход `./pg`: драйвер (`openPgSession`, `clientOptions`). Отдельно
  потому, что `.` грузит драйвер лениво (`src/run.ts`, `await import`): npm-пакет
  `pg` не попадает в путь запуска остальных команд потребителя.
- `untyped-modules.d.ts` — `declare module "pg"`: своих типов у пакета нет,
  поверхность объявляет `src/pg.ts` (`PgClient`); файл входит и в
  `tsconfig.build.json`, иначе `.d.ts` не собираются.
- `src/` — устройство и тесты `*.test.ts` рядом с кодом.
- `src/testdata/` — копии канала `ts/docs/specs/fixtures/` байт-в-байт: в
  корне — из `sql-ro/`, `platform/readonly-default/` и `platform/selector/`
  (эталоны соседних атомов, которые сверяет `sql-ro`), в `testdata/sql/` — из
  `sql/` (имена у команд совпадают, содержимое разное). Сверить их с каналом не может
  ни пакет (канал вне его папки), ни `ts/` (папку пакета он не читает), поэтому
  правило: копия меняется только переносом файла из канала тем же коммитом, что
  и эталон, никогда правкой по месту; Biome их не форматирует (`biome.json`,
  `!**/testdata`).
- `release/` — архивы версий, коммитятся; `dist/` — нет.

## Порядок изменения

Гейт зелёный → разбор итогового диффа субагентом со свежим контекстом (не
автор) по чек-листам `../../ts/docs/checklists/review.md` + `review-mpu.md`
(сессию библиотеки запускают с `--add-dir` на этот каталог; копий нет) →
исправление найденного → гейт зелёный повторно → коммит. Ядро чек-листов:
объект держит свою память (запись + свободные функции над ней — не объект);
особый случай — отдельная реализация, а не ветка по виду; позднее связывание
и один null-объект на модуль вместо проверок `typeof`/`instanceof`/`null`;
голые данные (строка-код, булев флаг, кортеж) — протоколом.

## Правила кода

Действуют правила `ts/CLAUDE.md` mpu; главное из них:

- Ничего специфичного для рантайма: ни `Deno.*`, ни `Bun.*` — только `node:*`
  и npm. Тесты — Vitest, зелёные под Bun, Node и Deno.
- Пакет не знает о приложении: ни импорта из `ts/` (`registry`, `line`,
  `backend`), ни текстов, которые назначает приложение. Команда объявлена
  контрактом `@mpu/command`; регистрирует её реестр `ts/`.
- Функция ≤ 40 строк, вложенность ≤ 3; ранние выходы. JSDoc на каждом
  экспорте; комментарий объясняет «почему».
- Строгий TypeScript, без `any`; `as` и `!` — с обоснованием рядом.
- Бросаются только `Error` и подклассы; обёртка — через `cause`.
- Никакой работы при импорте. Синхронизация сном в тестах запрещена.

## Зависимости

Версии точные, без `^`; `bun.lock` коммитится. Библиотеки `tslibs/*` —
необязательные `peerDependencies` плюс `devDependencies` архивом
(договор [S.9]): потребитель ставит их сам, копия на граф одна.

- `pg` 8.22.0 (`dependencies`) — драйвер PostgreSQL: расширенный протокол и
  отказ сервера на многооператорный текст держат границу чтения `sql-ro`
  (`ts/CLAUDE.md`, «Граница чтения и записи»). Меняешь транспорт — гарантия
  уходит вместе с ним.
- `zod` 4.4.3 — схемы аргументов и результата команд. **Обязательный**
  peer: схема пересекает границу пакета (её читает реестр потребителя), тип
  и рантайм — одного `zod`.
- `@mpu/command` (архивом) — контракт команды, порт io, селектор и кэш-БД.
- `@mpu/language` (архивом) — грамматика строки в тексте справки
  (`/messages`).
- `@mpu/base` (только dev, архивом) — его в рантайме грузит `@mpu/command`;
  пакет сам его не импортирует.
- `@mpu/testing` (dev, архивом) — пойманная ошибка тестов
  (`@mpu/testing/thrown`).
- `vitest` 3.2.4 — тесты под тремя рантаймами; `@biomejs/biome` — формат и
  линт; `typescript`, `@types/node` — проверка типов и `.d.ts` сборки.
