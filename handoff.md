## Процедура приёмки порции

1. Отчёт: `deno task handoff read > ~/mr/mp/tmp/mpu-smalltalk/report-<N>.md`.
2. Гейты сам: `deno fmt --check`, `deno lint`, `deno check .`,
   `flock /home/user/tmp/gate.lock timeout 1200 deno task test`, `deno task smoke`.
3. Одна мутация сам (у проверки, `cp` в бэкап → правка → тест → вернуть,
   `git status -- ts/` чистый).
4. Заморозка голденов: `diff`, затем `cp` из `back/src/**/testdata/…` в
   `ts/docs/specs/fixtures/…`.
5. `bash install.sh </dev/null`; живая проба — только безопасные строки
   (`ask telegram status dry no-live`, `ask image sync dry`); `telegram status`
   без `dry` ОТПРАВЛЯЕТ.
6. Статус спеки «реализовано … принято …» с живыми числами; отметка в
   `docs/work-queue.md`; коммит `git -C ~/mr/mp/mpu` путями поимённо.
7. Следующая порция: `/clear` исполнителю вводом tmux (`/clear`, Enter
   отдельно, `go`, Enter), затем `deno task handoff post <prompt>`, фоном
   `wait report 36000` и `stall-watch.sh`.
8. Вопрос исполнителя: решить по коду/живому прогону → правка спеки + коммит →
   ответ SendMessage; не решается — `docs/owner-questions.md`, идти дальше.

## Долг (кандидаты в порции-досылы)

- ⚠️ Безопасность: режим команды на входе `selector` передаётся ключом `target:` и обходит
  правило пути режима (`move-client-back target: rm`) — вопрос 7 владельцу.

- Платформа: у команд «только человек» (`ownerOnly`) ошибка разбора до вопроса решается как
  строка без правила (отказ двери вместо текста спеки) — поэтому проверки ввода `task role`
  идут после вопроса (T2); T1 `rule`/`owner-answer` без `project:` — так же.
- ⚠️ Платформа, ПРИОРИТЕТ (всплыло дважды: T1, 173a): собственный отказ команды (ошибка ввода,
  код 2) не даёт объекта `refusal` с `hint` — нарушает инвариант «громкий отказ с готовой строкой».
  Нужно: ошибка ввода команды несёт слова исправленной строки → поле в кадре исполнителя → ядро
  выпускает `refusal` перед `err` (и в MCP `structuredContent`); снимок `back-rpc`, если кадр там.
- Подсказка «ближайшие» предлагает соседа для имени, скрытого от агента (`web` → `wb`, 173c);
  безвредно, но вводит в заблуждение — платформа: не подсказывать для скрытых путей.
- Журнал вызовов хранит вывод как есть (ключи клиента в записи `sql-ro
  … ozon_api_keys`) — предложено владельцу.
- 171: у новых элементов web нет стилей (`.label/.method/.said/.report`);
  `Rules.tsx` `Row`/`Rules` длиннее предела; один раз полный прогон встал
  >10 мин на `line/chain_test.ts` (не воспроизвёлся).
- 170b: `backend/limit_test.ts:102` плавает под нагрузкой; отказ набранной
  строки до исполнения и отказ источника `run:` журнала не дают.
- 169b: совет массового удаления дописывает `deletes: allow` после `end`;
  `ruled` сеет `ask`, export держится на раннем посеве `allow`.
- 167c: сырой ответ клиента MCP для голдена `elicitation.json` не снят
  (пробный сервер `~/mr/mp/tmp/mpu-smalltalk/probe-167c/`).
- Мелочи прежних приёмок: `grep-regex: ^ERROR` — «сырой» вид ключа;
  `define:` разбирает `purpose:` по старому правилу `^`; отказ разбора теряет
  `ask` в `hint`; `telegram search` не объявляет `items`; группа команд
  значением (`x := kiten`) — решать замером.
