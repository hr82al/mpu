# Чек-лист постановки (универсальный, TypeScript)

Модели: постановка и рецензия — сильная модель; проектирование — сильная, или слабая при
обязательной рецензии сильной; доводка и код по spec — любая.

Постановка описывает, ЧТО наблюдается снаружи, и никогда — КАК устроено.
Порядок шагов; каждый шаг — обязательный раздел постановки.

1. **Кто и зачем.** Одна фраза: кто снаружи, чего хочет.
2. **Сценарии.** 10–20 сценариев «дано → ожидается» с конкретными данными, от простых к сложным,
   включая ошибки и отказы. Каждое поведение — минимум один сценарий; нет сценария — поведение
   не задано. Данные — литералами (`{ id: 7, kind: 'batch' }`), результаты — значениями или
   текстом ошибки, которую видит вызывающий.
3. **Инварианты.** Что всегда верно / никогда не случается — как факты, без механизма («после
   неудачной отправки ни одно сообщение не доставлено дважды»).
4. **Правила — таблицами.** Каждое правило — таблица случаев (≥ 10 строк, все ветви); формулу и
   алгоритм не писать.
5. **Вывод — примерами.** Формат ответа, сообщений об ошибках, кодов — только полный набор
   примеров, без описания.
6. **Границы.** Что система НЕ делает.
7. **Свойства решения.** Дёшево / неизменяемо / атомарно / детерминировано / без блокировок /
   переживает повторную доставку — если важно, записать как требование; иначе решение этого не
   сделает.
8. **Проверка на утечку.** Перечитать и убрать: слова «класс / интерфейс / модуль / сервис /
   поле / метод / таблица / колонка / DTO / эндпоинт / очередь / Map / массив / флаг»; «X
   вызывает Y», «X передаёт Y», «сначала создаётся…»; «хранится как…»; «если … то … иначе» в
   правилах; имена сущностей решения. Ссылки на разделы доменного описания утечкой не считаются:
   домен — не устройство.
9. **Проверка на полноту.** Можно ли написать тесты, не задав ни одного вопроса? Нет — добавить
   сценарий.
10. **Контрольный исполнитель.** Проверка текста на утечку недостаточна (замерено: судья утечки
    пропустил постановку, по которой пилот воспроизвёл оригинал). Дать постановку исполнителю без
    чек-листов и посмотреть на его spec: если есть эталон — воспроизвёл решения эталона →
    постановка их выдаёт; если эталона нет — у исполнителя не осталось ни одного открытого
    проектного выбора (структура «очевидна» из условия) → постановка предписывает, переписать.
    Применять, когда постановка заводит новый узел (модуль, сервис, протокол), а не колонку или
    поле в существующем.

После него — `statement-<проект>.md`, если есть.
