# mpu clean-local-clients

Статус: черновик

## Назначение

Снести из локального стенда per-client данные всех локальных клиентов,
кроме keep-листа: схемы и public-строки на локальном sl-1, токен-строки
на локальном sl-0, собственную проводку входа в локальной БД
воркспейсов. Только локальные контейнеры, никогда не прод. По умолчанию
— dry-run (печать плана), удаляет только с `--yes`.

## CLI-контракт

`mpu clean-local-clients [--keep IDS] [--yes]`

- `--keep` — client_id через запятую, которых ОСТАВИТЬ (инверсный
  список); дефолт `54,776`. Пробелы вокруг токенов допустимы, пустые
  токены пропускаются; нечисловой токен → usage-ошибка
  (`keep: '<токен>' не число (ожидается список client_id)`), exit 2.
- `--yes` — выполнить удаление; без него любой вызов — дословный
  dry-run (то же вычисление целей, только печать).
- Примеры из практики: `mpu clean-local-clients`;
  `mpu clean-local-clients --keep 54,776,1234 --yes`.

Коды выхода: 0 — успех (и dry-run, и удаление, и «нечего удалять»);
2 — ошибка конфигурации подключений или невалидный `--keep`.

## Ввод/вывод

stdout — отчёт: список локальных client_id sl-1 (по возрастанию; пусто
→ прочерк), keep-лист + пометка про схему `shared`, список целей под
удаление. Затем: dry-run → строка «сухой прогон — ничего не удалено.
Для удаления повтори с --yes»; после удаления → итог с числом удалённых
клиентов и числом снятых workspace-проводок; все цели в keep-листе →
`✓ нечего удалять — все локальные клиенты в keep-листе`.

## Побочные эффекты

Множество локальных клиентов = схемы локального sl-1:
`SELECT nspname FROM pg_namespace WHERE nspname ~ '^schema_[0-9]+$'` →
номера. Цели = это множество минус keep-лист. При `--yes`, по целям:

1. **Локальный sl-1** (одна транзакция, `SET session_replication_role
   = replica`): DELETE детей `spreadsheets` (`spreadsheets_sheets`,
   `spreadsheets_sheets_values`, `spreadsheets_datasets`,
   `spreadsheets_datasets_values`, `spreadsheets_loader_data`) по
   `spreadsheet_id IN (SELECT spreadsheet_id FROM public.spreadsheets
   WHERE client_id IN (<цели>))`; DELETE строк клиента из `clients`
   (по `id`) и по `client_id` из таблиц набора `specs/copy-client.md`
   шаг 3; затем `DROP SCHEMA IF EXISTS schema_<id> CASCADE` на каждую
   цель.
2. **Локальный sl-0** (транзакция, replica-режим): DELETE из `clients`
   (по `id`), `wb_tokens`, `clients_wb_cabinets` (по `client_id`).
3. **Локальная БД воркспейсов** (без replica-режима — порядок явный,
   FK-безопасный): на каждую цель ищется user по email-сигнатуре
   `client_<id>@local.host`; нет user'а → цель пропускается. Если
   существует workspace `id = <id>` с `owner_id` этого user'а —
   DELETE `subscriptions` (по sid'ам из `workspaces_wb_cabinets`
   workspace'а) → `workspaces_wb_cabinets` → `wb_cabinets` (по
   `workspace_id`) → `workspaces`; счётчик снятых workspace'ов
   инкрементируется. User удаляется в любом случае (даже без
   workspace).

## Конфигурация

Локальные подключения sl-1 / sl-0 / воркспейсы — как в
`specs/copy-client.md` («Конфигурация»), host всегда `127.0.0.1`.

## Инварианты

- Read-only без `--yes`: dry-run выполняет только чтение списка схем.
- keep-лист инверсный: перечисляется, что оставить; схема `shared`
  не имеет номера клиента и не попадает в цели никогда.
- Назначение — только локальные адреса (host зашит), прод недостижим.
- Удаляемая проводка воркспейсов — только собственная (email-сигнатура
  `client_<id>@local.host` + владение workspace'ом): чужие и заведённые
  вручную workspace не трогаются, даже если client_id в целях.
- Клиент без схемы на sl-1 в цели не попадает (множество целей строится
  только из схем).
- Пустой список целей → ранний выход без подключения к sl-0/воркспейсам
  и без удаления, даже с `--yes`.

## Граничные случаи и ошибки

- Конфигурация подключений неполна → stderr
  `mpu clean-local-clients: <текст>`, exit 2 — до какого-либо чтения.
- `--keep ""` (все токены пустые) → keep-лист пуст, под удаление — все
  локальные клиенты (валидно).
- Нет ни одной схемы `schema_<N>` → список «—», «нечего удалять»,
  exit 0.
- Цель есть в схемах, но её строк нет в public — DELETE'ы затрагивают
  0 строк, DROP SCHEMA выполняется, не ошибка.

## Golden-примеры

Снять при переводе в «к реализации» (на локальном стенде):
`mpu clean-local-clients --help`; `mpu clean-local-clients` (dry-run,
дефолтный keep); `mpu clean-local-clients --yes` (реальное удаление,
итоговый отчёт); `--keep x` (usage-ошибка).
