# `mpu-next`: тонкий клиент сервера строк

Статус: реализовано — порция 142 (`2e7f8ca`, `9b8c2ce`, `a908cf9`; подпроект `ts/cli/`, задача `cli`); принято 2026-09-18: гейты зелёные (тестов 2119, smoke 21/1), живой прогон хостом в терминале — вопрос, `y` → записано, `n` → не подтверждено (1), Ctrl+C → «прервано» (130), правило после прерывания не изменилось.

## Назначение

Команда в терминале, которая сама ничего не исполняет: отдаёт слова строки
серверу `mpu-back` (`platform/back-rpc.md`), печатает его вывод по мере
появления, задаёт вопросы подтверждения человеку и выходит с кодом строки.
Живёт в новом подпроекте `ts/cli/`. Прежние `mpu`, `mpu mcp` и точка входа
`back/next.ts` не меняются.

Автоподъём службы, когда сервер не отвечает, — не в этой порции: службу
`mpu.service` запускает супервизор (порция 8), до него поднимать нечего.

## CLI-контракт

```
deno task cli <слова строки…>
```

Слова уходят серверу как есть. Всё, что делает строка, — дело сервера.

| Итог | stdout | stderr | код |
|---|---|---|---|
| кадры сервера | каждый `out` — как есть, по мере прихода | каждый `err` — как есть, по мере прихода | из кадра `exit` |
| сервер не отвечает (соединение отклонено) | — | `mpu-next: сервер строк не отвечает на <адрес> (запуск: deno task back)` | 1 |
| токена нет ни одного | — | `mpu-next: нет токена доступа (<путь основного>)` | 1 |
| сервер ответил 401 или 403 | — | `mpu-next: сервер отказал в доступе (<код>)` | 1 |
| сокет закрылся без кадра `exit` | — | `mpu-next: сервер оборвал строку` | 1 |

Адрес — `http://127.0.0.1:7338`; переменная `MPU_BACK_URL` его заменяет
(для тестов и запуска на другом порту).

## Канал и токен

Выбор двери и токена — по тому, что клиенту доступно:

| Основной токен читается | управляющий терминал открывается | Дверь | `human` | Токен |
|---|---|---|---|---|
| да | да | `/line` | `true` | основной |
| да | нет | `/line` | `false` | основной |
| нет | — | `/agent/line` | `false` | агентский |

«Есть кого спросить» — это **управляющий терминал** (`/dev/tty` открывается), а
не терминальность stdin. Причина: у клиента в середине конвейера stdin занят
данными (`mpu-next … | mpu-next confirm`), и по stdin такой клиент объявил бы
`human: false` — вопрос не был бы задан именно там, ради чего вопросы и
существуют (`confirm.md`). Запущенный из задания по расписанию или из-под
службы клиент управляющего терминала не имеет, и `human` остаётся `false`.

Вопрос клиент показывает и ответ читает **на управляющем терминале**: там же,
где его видит человек. Когда stderr — тот же терминал, разницы не видно.

«Основной токен читается» — файл есть, читается и не пуст; нет файла, нет права
на чтение или файл пуст — одинаково «не читается». Агентского токена тоже нет — строка «токена
нет ни одного», путь в тексте — основного.

Кадр `ask` (придёт только при `human: true`): текст показывается на
управляющем терминале без перевода строки, ответ — одна строка оттуда же
уходит кадром `answer`. Терминал закрылся до ответа — уходит пустой ответ
(для сервера «нет»).
Терминальность stdout на выбор двери не влияет; сама строка у сервера в любом
случае видит потоки не-терминалами (`back-rpc.md`).

**Ctrl+C (SIGINT) во время строки:** клиент закрывает сокет, печатает в stderr
`mpu-next: прервано` и выходит с кодом 130. Сервер на закрытый сокет: вопрос
без ответа — «нет»; уже начатое исполнение доходит до конца (строки не
прерываются), его вывод отбрасывается.

**Агентский токен — новое на стороне `mpu-back`** (дополнение
`platform/back-rpc.md`, «Доступ»):

- файл `agent-token` рядом с основным (`$HOME/.config/mpu/agent-token`),
  права 0600; оба токена создаёт **сервер при старте**, если их нет; клиент
  файлы не пишет;
- на `/agent/line` поле `human: true` сервер принимает **только с основным
  токеном** (так ходит MCP-сервер, порция 7, — вопрос уходит человеку в
  интерфейс клиента агента); с агентским токеном сервер считает `human: false`,
  что бы ни пришло в кадре;
- принимается на `/agent/line`, `POST /rpc` (все методы — они только читают);
  на `/line` — 401;
- основной токен принимается везде, как раньше.

Зачем: агенту Claude Code запрещено читать основной токен (правила
разрешений клиента, 2026-09-18), а агентский ему читать можно. Через
агентский токен агент получает только канал агента: правила не меняет, решение
`ask` без человека отказывает.

## Ввод/вывод

- Первый кадр: `{"words": [...], "cwd": "<текущий каталог клиента>", "human": …}`.
- Stdin клиента серверу не передаётся (отклонение `back-rpc.md`).
- Код выхода клиента — число из `exit`.

## Инварианты

- Клиент не исполняет команд и не читает файлов, кроме двух токенов.
- Для любой строки, **дошедшей до сервера и получившей кадр `exit`**, итог
  клиента (stdout, stderr, код) равен итогу `mpu-next` из `back/next.ts` на тех
  же словах, правилах и ответе, с оговорками `back-rpc.md` (stdin пуст, потоки
  строки не терминалы). Строки таблицы «CLI-контракт» про недоступный сервер,
  токен, 401/403, обрыв и Ctrl+C — свои исходы клиента, у `back/next.ts` их
  нет.
- Токен не печатается никогда.
- Без основного токена клиент ни при каких условиях не подключается к `/line`.

## Граничные случаи и ошибки

| Дано | Ожидается |
|---|---|
| `version`, сервер жив | `0.1.0` в stdout, код 0 |
| `kitn` | stderr `mpu: не понимает kitn; ближайшие: kiten`, код 2 |
| `allow: "kiten ls"`, терминал, ответ `y` | вопрос в stderr, данные в stdout, код 0, правило записано |
| то же, ответ `n` | `mpu allow: kiten ls: не подтверждено`, код 1 |
| `allow: "kiten ls"`, основной токен недоступен | дверь `/agent/line`; `изменить правила может только человек`, код 1 |
| сервер не поднят | текст «не отвечает» с адресом, код 1 |
| агентский токен на `/line` (проверка сервера) | 401 |
| агентский токен на `/agent/line` с `"human": true`, решение `ask` (проверка сервера) | кадра `ask` нет; `… нужно подтверждение, а спросить некого`, код 1 |
| основной токен на `/agent/line` с `"human": true`, решение `ask` | кадр `ask` приходит |
| Ctrl+C во время строки | `mpu-next: прервано`, код 130 |
| вывод строки большой (≥ 1 МБ) | приходит целиком, по кускам, порядок внутри потока сохранён |
