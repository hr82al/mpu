# mpu code refs

Статус: к реализации (2026-09-08; голдены — `fixtures/code/`, факты
сняты оракулом полноты на дереве-фикстуре)

## Назначение

Кто ещё ссылается на этот символ и кто читает этот модуль. Ответ полон
либо назван неполным — общий слой `platform/code-analyzer.md`.

Команда не объясняет, что символ делает: на вопрос «что такое X»
отвечает сам код и его сигнатура.

## CLI-контракт

`mpu code refs АДРЕС [--limit N]`

Политика — `ro`; мутирующего варианта нет и не заводится. Объявление,
разбор входа и форма вывода — `platform/command-contract.md`; справка на
обоих уровнях — `platform/registry.md`.

**АДРЕС** — `[РЕПОЗИТОРИЙ:]ПУТЬ[:СТРОКА]`, путь относителен корню
репозитория. Репозиторий опущен — берётся тот, внутри которого лежит
текущий рабочий каталог; каталог вне репозиториев рабочей области →
отказ, exit 2.

Две формы адреса — две цели:

- `ПУТЬ:СТРОКА` — **символ**, объявленный в этой строке; ответ —
  файлы-потребители;
- `ПУТЬ` — **модуль**; ответ — файлы, которые его читают.

**`--limit N`** — предел записей в каждом разделе, по умолчанию 200
(запись и счётчик усечения — `platform/code-analyzer.md`).
Раздел усечён — сказано в нём самом; усечение не ошибка, exit 0.

Справка листовой команды живёт в коде — там же, где сама команда
(`platform/registry.md`). Спека её не цитирует: два источника одного текста
расходятся молча, а проверить расхождение нечем. Спека задаёт **состав**:
справка обязана называть форму адреса и обе его цели, единицу перечня (файл,
а не обращение), то, что печатается область видимости и раздел «не
разрешено», значение и умолчание `--limit` (в записях, не в строках), коды выхода и хотя бы один
пример вызова — полный, а не фрагмент, и с адресом, который разбирается;
существования этого адреса на диске не требуется: пример, ссылающийся на
живой исходник, устаревает от первой же правки.

## Ввод/вывод

Шапка, разделы и хвост — `platform/code-analyzer.md`. Свои разделы:

**Символ.** Строка с именем и сигнатурой, под ней — **одна** строка
области видимости: три её значения и правило поиска входа проекта — в
`platform/code-analyzer.md`. Строка печатается всегда, в том числе
отрицанием.

**потребители: N файлов** — по строке на файл: `путь:строка`. Строка —
та, которой файл символ получает (импорт либо реэкспорт).

Единица ответа — **файл**, а не обращение. Это не оформление: на живом
коде один файл-потребитель даёт десятки обращений, и число «мест»
без такого уговора не сходится ни с чем. Обращения внутри файла в счёт
не идут и не печатаются.

**Модуль.** Вместо строки символа — `модуль ПУТЬ`; раздел называется
`читатели: N файлов`, строка читателя — строка его импорта.

Нулевой раздел печатается как `потребители: 0` без последующих строк.

## Побочные эффекты

Только чтение (`platform/code-analyzer.md`). Запись в журнал вызовов —
обычная, со всеми секциями: секретов в выводе нет.

## Конфигурация

Своей нет; корень рабочей области и разбор — `platform/code-analyzer.md`.

## Инварианты

- Перечень потребителей символа равен ответу оракула полноты
  (`platform/code-analyzer.md`): переименование символа ломает ровно эти
  файлы и никакие другие.
- Единица перечня — файл; один файл в перечне встречается один раз.
- Область видимости названа всегда, одной строкой.
- Раздел «не разрешено» печатается всегда, в том числе нулевой, и
  ответа не отменяет.
- Порядок строк — `(репозиторий, путь, строка)`; вывод детерминирован.
- Команда только читает.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu code refs: `, без трейсбеков.

| Вход | Ожидаемое поведение |
| --- | --- |
| Строка адреса не содержит объявления | exit 2, `в строке <N> нет объявления`, следом перечень объявлений файла со строками |
| Файла по адресу нет | exit 2, `файла <путь> нет в <репозиторий> на <отметка>` |
| Репозиторий неизвестен | exit 2, `неизвестный репозиторий '<имя>'`, следом перечень известных |
| Символ не экспортируется, потребителей нет | exit 0, `потребители: 0` + строка `приватное в модуле` |
| Адрес `ПУТЬ:СТРОКА` в репозитории без единого проекта | exit 1, отказ `объявления не разбираются текстовым анализатором: в репозитории <имя> нет ни одного проекта`; разделов нет |
| Адрес `ПУТЬ` в репозитории без единого проекта | ответ текстового анализатора: читатели — файлы, где путь модуля встречается текстом; гарантия в шапке `текстовый разбор — ответ неполон` |
| Потребитель получает символ через алиас проекта | попадает в перечень наравне с относительным импортом |
| Потребитель — тестовый файл, исключённый конфигурацией проекта | попадает в перечень: исключения снимаются |
| Импорт в репозитории не разрешился | строка в «не разрешено»; перечень потребителей не меняется |
| Записей в разделе больше `--limit` | exit 0, строка `усечено: показано N из M` в конце раздела |

## Golden-примеры

`fixtures/code/`. Дерево-фикстура и его материализация —
`platform/code-analyzer.md`. Каждый файл оканчивается одним переводом
строки.

- `refs-symbol.stdout.txt` — `refs fixture:src/days.ts:2`: семь
  файлов-потребителей `addDays`, и каждый попал туда своей формой:
  `src/report.spec.ts` отсекается штатным `exclude`, `src/aliased.ts`
  получает символ через алиас `#/`, `src/dynamic.ts` — динамическим
  `import()`, `src/index.ts` — реэкспортом, `src/seed_test.ts` — тестовая
  обвязка, шаблоном `*.spec.ts` не описанная. Снятие любого из условий
  разбора убирает из ответа ровно по файлу, и тест обязан краснеть на
  каждом.
- `refs-module.stdout.txt` — `refs fixture:src/window.ts`: один читатель.
  Показывает, что перечень читателей модуля и перечень потребителей
  символа — разные ответы, а не одно с другим.
- `refs-orphan.stdout.txt` — `refs fixture:src/orphan.ts:2`: пустой
  перечень при экспортируемом символе. Пустой ответ — ответ, не отказ;
  область видимости названа одной строкой.

Во всех трёх раздел «не разрешено» несёт одну и ту же строку —
неразрешимый импорт `src/broken.ts:3`. Он не подмешивается в перечень
потребителей и ответа не отменяет.
