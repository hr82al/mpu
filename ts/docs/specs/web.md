# Фронт `mpu`: дерево объектов и правила подтверждения

Статус: 10a реализовано — порция 147 (`8b00190`), установлено 2026-09-18; 10b реализовано — порция 148 (`ffafe1e`), 2026-09-18 хостом: гейты зелёные (тестов 2200, vitest 13, smoke 21/1), `install.sh` на машину оператора — `install: готово`, фронт в `~/.local/share/mpu/web/current`; живая проверка браузером 2026-09-21 пройдена: обмен ключа, дерево, вопрос с «Да»/«Нет»/`Esc`, «сбросить». ⚠️ Граница «человек / агент» в окружении владельца не держится (`back-rpc.md`, «Проверено 2026-09-18»).

## Назначение

Методы образа и синхронизация — `web-image.md` (171).

Страница в браузере по `http://mpu.localhost:7338`: дерево объектов `mpu`
(команды и группы) с действующим решением правил на каждом узле; на узле можно
поставить `allow` / `ask` / `deny` или сбросить к наследуемому. Изменение
применяется сразу и видно следующей строке любого клиента. Дальше на странице
появятся другие экраны — эта спека задаёт первый.

Две порции: **10a** — сторона `mpu-back` (статика, вход, действующие решения),
**10b** — само приложение (`ts/web/`).

## Вход в браузере (10a)

Правила меняет только человек (`platform/policy.md`), поэтому браузер входит
через того, у кого есть основной токен:

1. `mpu-next web` (в терминале человека) — строка `web` уходит серверу по
   `/line` с основным токеном. Метод корня `web` (только на двери `/line`; на
   `/agent/line` — `doesNotUnderstand`) выдаёт одноразовый ключ: 32
   шестнадцатеричных знака, живёт 60 секунд. Вывод — одна строка
   `http://mpu.localhost:7338/?key=<ключ>` и перевод строки.
2. Страница, открытая по ссылке, делает `POST /web/session` с телом
   `{"key": "<ключ>"}` и заголовком `Origin: http://mpu.localhost:7338`. Ключ
   действителен — ответ 204 и cookie
   `mpu_session=<32 hex>; HttpOnly; SameSite=Strict; Path=/; Max-Age=43200`
   (12 часов); ключ погашен. Недействителен — 404.
3. Cookie `mpu_session` даёт **права** основного токена (это не сам токен —
   свой случайный секрет) на `/rpc`, `/line` (WebSocket и `POST`) и
   `/line/answer`, но принимается **только** при `Origin`, **в точности**
   равном `http://mpu.localhost:<порт back>` — схема, хост и порт целиком
   (без `Origin`, с другим хостом или **другим портом** того же хоста — 401).
   Правило для токенов прежнее (`back-rpc.md`, «Доступ»); строгое — только
   для cookie: браузер прикладывает её к любому запросу на `mpu.localhost`, с
   какой бы локальной страницы (`localhost:<порт>`) он ни шёл. На
   `/agent/line` cookie не принимается.
4. Сессии хранятся в файле `$HOME/.config/mpu/web-sessions` (0600) **только
   хэшами** (sha256): из прочитанного файла войти нельзя. Переживают
   перезапуск `back`; метод корня `web-logout` (тоже только на двери
   `/line`) гасит все сессии и ключи, вывод — число погашенных сессий.

Агент получить ключ не может: у него нет основного токена, а метод `web` на его
двери не существует.

**Граница доверия браузера.** Агент, управляющий настоящим браузером человека
(расширение Claude в Chrome), пользуется его cookie и может сам нажать «Да» в
окне подтверждения. Сервер этого не отличит. Окно ограничено сроком сессии
(12 часов) и `web-logout`; закрывается запретом сайта `mpu.localhost` для
расширения браузерной автоматизации (настройка владельца). Playwright со своим
профилем cookie человека не видит.

## Статика (10a)

`GET /` и `GET /assets/*` отдают собранное приложение из каталога
`$HOME/.local/share/mpu/web/current` (путь — параметр `back`; `current` —
символьная ссылка на каталог сборки `web/<sha256>/`, прежние сборки остаются
для отката ссылкой); неизвестный путь без
расширения — `index.html` (маршруты приложения). Статика отдаётся без токена;
`Content-Security-Policy: default-src 'self'`. Каталога нет — `GET /` отвечает
200 с текстом `mpu-back: фронт не установлен` и переводом строки.

## Действующие решения (10a)

Новый метод `/rpc` `policy.tree` → узлы снимка дерева (`tree.snapshot`), у
каждого:

```json
{"path": ["kiten", "card"], "verdict": "allow", "rule": "kiten card", "own": true}
```

- `verdict` — решение, которое получила бы строка, дошедшая до этого узла
  (для узла с хвостом — строка с `<args>`);
- `rule` — путь правила-победителя, `null` — ни одно не совпало (`ask`);
- `own` — у самого узла есть своё правило.

Считает `back` тем же набором правил, что решает строки: фронт правил не
вычисляет.

Экран «Правила»:

| Что | Как |
|---|---|
| дерево | из `policy.tree` + `tree.snapshot` (назначения); свёрнуто до первого уровня; поиск по пути |
| узел | путь, назначение, действующее решение цветом, откуда (`rule`), своё ли |
| родитель | если у потомков разные действующие решения — метка «смешанно» (только показ, из ответа сервера) |
| действия узла | `allow` · `ask` · `deny` · «сбросить» (есть своё правило) |
| изменение | строка `["allow:", "<путь>"]` (и т. п.) через `POST /line`, `human: true`, `Accept: application/json`; ответ `ask` с номером → модальное окно с текстом вопроса «Да / Нет» → `POST /line/answer`; после ответа — перечитать `policy.tree` |
| нет сессии (401) | экран «Откройте ссылку из `mpu-next web`» |
| `back` недоступен | сообщение с адресом, повтор по кнопке; пустого дерева нет |

Доступность: кнопки — `<button>` с подписью; модальное окно — фокус внутри,
`Esc` — «Нет».

## Инварианты

- Изменить правило из браузера можно только с cookie сессии и только через
  вопрос-подтверждение (тот же номер, что у HTTP-строки).
- Cookie сессии без `Origin: http://mpu.localhost:7338` не действует.
- Фронт не вычисляет решения: только показывает ответ `policy.tree`.
- Токены в страницу не попадают (cookie `HttpOnly`, в JS недоступна).

## Граничные случаи и ошибки

| Дано | Ожидается |
|---|---|
| `mpu-next web` без основного токена (агент) | `mpu: не понимает web`, код 2 |
| ключ второй раз | 404 |
| ключ через 61 секунду | 404 |
| `POST /web/session` с `Origin: http://evil.localhost` | 403 |
| `/rpc` с cookie, без `Origin` | 401 |
| `/rpc` с cookie, `Origin: http://localhost:5173` | 401 |
| `/rpc` с cookie, `Origin: http://mpu.localhost:9999` | 401 |
| файл `web-sessions` прочитан, его строка подставлена в cookie | 401 |
| `/agent/line` с cookie | 401 |
| `policy.tree` после `deny: "kiten"` | у `kiten` и потомков без своего правила — `deny`, `rule: "kiten"` |
| статики нет | `GET /` → `mpu-back: фронт не установлен` |
| фронт: ответ «Нет» в окне | правило не изменилось, дерево прежнее |
