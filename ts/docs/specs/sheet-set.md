# mpu sheet set — запись значений в таблицу

**Статус:** к реализации (2026-08-28).

## Назначение

Единственная пишущая команда семейства вне пакетного мини-языка: пишет
значения через `values/batchUpdate`. Три режима ввода, различаемые формой
вызова, а не флагом.

Отличать от `batch-update` (`sheet-batch.md`): та правит **устройство** листа
инструкциями мини-языка и идёт одним атомарным запросом; эта пишет
**значения** в диапазоны.

## CLI-контракт

```
mpu sheet set ДИАПАЗОН ЗНАЧЕНИЕ [-s ЦЕЛЬ] [-l|--literal]
mpu sheet set --from ФАЙЛ|-   [-s ЦЕЛЬ] [-l|--literal]
… | mpu sheet set [ЦЕЛЬ]      [-l|--literal]
```

Режим выбирается так:

1. `--from` задан → пакет из файла: строки `диапазон<TAB>значение`, пустые и
   начинающиеся с `#` пропускаются, строка без табуляции — код 2;
2. иначе значение не задано и на входе не терминал → JSON из потока ввода:
   `[{"range": …, "value"|"formula": …}, …]`;
3. иначе заданы оба позиционных → одна ячейка;
4. иначе — код 2 с образцом употребления.

**Позиционный аргумент меняет смысл между режимами:** в режимах 1 и 3 первый
позиционный — диапазон, в режиме 2 — цель (таблица). Это неочевидно и должно
быть сказано в справке прямым текстом, а не выводиться читателем из примеров.

## Ввод/вывод

Тип ввода в JSON-режиме задаёт **имя свойства**, а не флаг: `formula` →
разбор как ввод пользователя, `value` → запись как есть. Флаг `--literal`
задаёт умолчание для режимов 1 и 3 и на JSON-режим не влияет.

Элемент без `range`, без `formula`/`value`, не-объект, пустой массив,
неразбираемый JSON — код 2 с номером элемента.

## Побочные эффекты

Запись в таблицу. Затронутые вкладки инвалидируются в локальном кэше — та же
операция, что у `batch-update` (`sheet-cache.md`, инвариант 3).

В JSON-режиме открытый одностолбцовый диапазон (`Кол<N>:Кол`) раскрывается в
заливку до последней занятой строки столбца — для этого делается
**дополнительный запрос чтения** этого столбца. Значит режим 2 пишет не только
то, что ему дали, и стоит дороже прочих; в справке это должно быть названо.

## Инварианты

1. **Разные типы ввода — разные запросы, и это наблюдаемо.** Записи с
   `formula` и с `value` уходят двумя запросами (по одному на тип). Отсюда
   следствие, которое нельзя скрывать: **операция не атомарна** — первый
   запрос может пройти, второй упасть, и часть значений окажется записанной.
   При отказе второго сообщение обязано называть, что записано, а что нет;
   молчаливый код 1 после частичной записи недопустим.

2. **Форма вывода не зависит от числа запросов.** Оригинал печатает объект
   при одном запросе и массив при двух — то есть форма ответа зависит от
   того, смешал ли оператор типы ввода. Потребитель вывода не должен это
   разбирать: форма одна всегда.

3. **Величина берётся из результата.** Печатаемое число записанных ячеек
   берётся из ответа сервера, а не из числа поданных элементов: сервер может
   записать иначе, чем мы просили (раскрытие заливки, пустые строки). Правило
   — `CLAUDE.md`, «Величина берётся там, где совершается работа».

4. **Неразбираемый диапазон не пропускается молча.** Оригинал при
   инвалидации кэша молча пропускает диапазоны, которые не смог разобрать
   (`continue`). Тогда запись прошла, а кэш вкладки остался старым — и
   следующее чтение отдаст устаревшее. Неразбираемый диапазон — отказ до
   записи, а не тихий пропуск после.

## Граничные случаи и ошибки

- цель не резолвится → код 2 (общий путь семейства);
- `--from` на несуществующий файл → код 2;
- строка пакета без табуляции → код 2 с номером и содержимым строки;
- сервер недоступен или ответил ошибкой → код 1, кэш не инвалидируется;
- пустой пакет (файл из одних комментариев) → код 2: писать нечего.

## Приёмка

Живая пара на черновой таблице, по содержимому ячеек, а не по коду возврата:

- одна ячейка формулой и одна как есть: в таблице лежит вычисленное и
  дословное соответственно;
- пакет из файла: все строки записаны, комментарии пропущены;
- JSON со смешанными типами: записаны обе группы, форма вывода одна и та же;
- открытый столбец в JSON: заливка дошла до последней занятой строки, а не
  до конца листа;
- после записи вкладка в кэше инвалидирована — следующее чтение идёт к
  серверу (проверяется по наличию строки `sheet_tabs`).
