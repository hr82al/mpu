# mpu move-client-back

Статус: черновик

## Назначение

Реверс переноса, выполненного `mpu move-client`, и управление журналом
переносов. Общий механизм — журнал переносов (кэш-БД, таблица
`client_moves`) и постановка job'а `clientsTransfer createJob` в
контейнере `mp-dt-cli` — описан в `specs/move-client.md`; здесь — только
собственный контракт реверса и подкоманд `ls`/`rm`. Реверс читает запись
хода «source → target», ставит обратный job (target → source) и после
успешной постановки удаляет запись.

## CLI-контракт

`mpu move-client-back [SELECTOR|ls|rm] [SELECTOR]`

- первый аргумент — диспетчер: `ls` (и синоним `list`, и вызов вовсе без
  аргументов) — список записанных ходов; `rm <selector>` — удалить
  запись хода без переноса; иначе аргумент — селектор клиента для
  реверса.
- Селектор: чистое целое число трактуется как client_id напрямую, минуя
  кэш (робастно к непрогретому кэшу); прочее — обычный резолв
  (`platform/selector.md`) с сужением до одного client_id.

Коды выхода: 0 — успех (для реверса — успешная постановка job'а, не
завершение переноса); 2 — ошибки резолва, валидации аргументов,
отсутствие/порча записи хода, нерезолвящийся контейнер `mp-dt-cli`;
иначе — rc `createJob` как есть.

## Ввод/вывод

stderr — прогресс (у реверса): строка с направлением возврата, затем
печать запускаемой команды `createJob` (дословная форма —
`specs/move-client.md`, «Ввод/вывод»); вывод `createJob` стримится
транспортом (`platform/exec-transport.md`). stdout:

- `ls` — таблица ходов, новые сверху: колонки client_id, «перенос
  (откуда → куда)», «когда» (локальное время `YYYY-MM-DD HH:MM:SS`);
  пусто → `нет записанных ходов`;
- `rm` — строка об удалённой записи с её маршрутом.

## Побочные эффекты

- Реверс: постановка job'а `createJob` в контейнере `mp-dt-cli` —
  команда и транспорт как у `mpu move-client`
  (`specs/move-client.md`, «Побочные эффекты»), source и target
  поменяны местами относительно записи хода.
- Кэш-БД, таблица `client_moves` (форма — там же): реверс — DELETE
  строки после rc=0; `rm` — DELETE без переноса; `ls` — только чтение.

## Конфигурация

Транспорт до `mp-dt-cli` — `platform/exec-transport.md`; кэш-БД —
`platform/env-file.md`. Собственных настроек нет.

## Инварианты

- rc `createJob` ≠ 0 → запись хода не удаляется, rc пробрасывается
  наверх.
- `ls` и `rm` не запускают перенос.
- Успех реверса = job поставлен; фактическое завершение переноса
  команда не отслеживает.

## Граничные случаи и ошибки

- Реверс без записи хода → `mpu move-client-back: нет записанного хода
  для client <id> (сначала `mpu move-client`, либо запусти `mpu
  init`)`, exit 2.
- Запись хода, где source или target не парсится как `sl-N` →
  `повреждённая запись хода: <source> → <target>`, exit 2.
- Запись, где source == target → `source и target записи оба sl-<N> —
  нечего возвращать`, exit 2.
- `rm` без селектора → ``rm` требует селектор (rm <selector>)`, exit 2.
- `rm` без записи хода → строка `нет записи хода для client <id>` в
  stderr, exit 0 (идемпотентно).
- Отсутствующая таблица `client_moves` (кэш-БД без `mpu init`) — во
  всех формах как отсутствие записей: `ls` → `нет записанных ходов`,
  `rm` и реверс → как «нет записи хода».
- Клиент с client_id/заголовком буквально `ls`/`rm`/`list` адресуем
  только числовым client_id (слова заняты диспетчером).
- Селектор, резолвящийся без client_id → `selector '<значение>' не
  указывает на конкретного клиента` (+ кандидаты), exit 2; несколько
  client_id → `selector matches N clients — narrow it down`, exit 2.

## Golden-примеры

Снять при переводе в «к реализации»: `mpu move-client-back --help`;
`mpu move-client-back ls` (чтение кэш-БД, без мутаций);
`mpu move-client-back rm` без селектора (usage-ошибка).
