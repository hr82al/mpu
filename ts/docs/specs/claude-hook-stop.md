# mpu claude-hook stop

Статус: черновик (серия R, порция R2; постановка —
`telegram-relay-r2-statement.md`, сценарии `[S.n]`; канал —
`claude-channel.md`; вопросы в чате — `platform/telegram-questions.md`)

## Назначение

Claude Code в конце каждого хода зовёт хук `Stop`. Команда ставит в чат
владельца сообщение «ждёт ввода» с последним сообщением сессии и сразу
выходит: сессия не задерживается [§7 постановки]. Ответ владельца текстом
уходит в сессию через её канал (`claude-channel.md`); сессия без канала
получает уведомление без ответа [S7].

## CLI-контракт

```
mpu claude-hook stop
```

- Аргументов нет; вход — stdin, payload `Stop`. Исполняет ядро (как прочие
  `claude-hook`); посев — `allow` строкой таблицы `platform/policy.md`;
  тулом MCP не публикуется; код всегда 0 (клиент — как для
  `claude-hook pre-tool-use`: строка входит в общий список строк-хуков).
- stdout всегда пуст: хук ничего не решает за Claude Code — ни `block`, ни
  `additionalContext`.
- Ключ сессии — `CLAUDE_CODE_MESSAGING_SOCKET` клиента (`claude-channel.md`,
  «Ключ сессии»).

## Ввод

Живой payload — `fixtures/telegram-relay/r2/live-stop.json` (обезличен):
`session_id`, `transcript_path`, `cwd`, `permission_mode`,
`hook_event_name: "Stop"`, `stop_hook_active`, `last_assistant_message`,
`background_tasks`, `session_crons`.

| Поле | Требование | Нарушено → без вопроса, причина |
|---|---|---|
| весь stdin | JSON-объект | `вход не разобран: stdin — не JSON-объект` |
| `stop_hook_active` | не `true` | `продолжение хода` [S8] |
| `last_assistant_message` | строка (пустая — допустима) | `вход не разобран: нет last_assistant_message` |

`transcript_path`, `cwd` — необязательны (как у `permission-request`).

## Вопрос «ждёт ввода»

- Заголовок — как у `claude-hook-permission-request.md` («Payload → форма
  вопроса»: сессия, проект, окно), значок `💬`, имени нет; «откуда» пусто —
  `💬 сессия` (таблица постановки §4).
- Текст шага — `last_assistant_message`; длиннее места в сообщении — берётся
  **конец**, первой строкой `…` [S6]. Пусто — `(без текста)`.
- Кнопки: `Позже`, `Пропустить`; свой текст — да, если у сессии есть
  зарегистрированный канал; иначе — нет, последняя строка тела
  `ответ — в терминале (сессия без канала)`, кнопка одна — `Пропустить` [S7].
- Вид вопроса — «ждёт ввода» (ниже, ряд): срочные его обгоняют.

## Исходы

| Исход | Что происходит | Строка сообщения |
|---|---|---|
| текст владельца | текст уходит в канал сессии (`claude-channel.md`); доставлено — исход | `✅ <текст> — из чата` [S2] |
| канал отказал в доставке | вопрос остаётся активным, владельцу — `не доставлено: сессия без канала` | — |
| `Пропустить` | вопрос снят | `⏭ пропущено` [S4] |
| `Позже` | вопрос уходит в конец ряда «ждёт ввода»; других нет — подсказка `больше ничего не ждёт` | — [S5, S12] |
| в транскрипте после постановки появилась запись `user` с текстом (строка `content` или блок `text`; не `tool_result`) | вопрос снят | `✅ решено в терминале` (≤ 2 с) [S3] |
| регистрация канала сессии оборвалась | вопрос снят | `⌛ сессия закрыта` [S9] |
| новый `Stop` той же сессии | прежний вопрос снят как «решено в терминале», новый ставится [S13] | — |
| ядро перезапущено | как у R1 | `⌛ истёк — ответьте в терминале` |

Сессия без канала: «сессия закрыта» не определяется (регистрации нет) — вопрос
снимается транскриптом, `Пропустить` или новым `Stop`.

Запись `assistant` признаком нового хода **не** служит: последний ответ хода
Claude Code дописывает в транскрипт уже после вызова `Stop` (снято 2026-10-06:
хук вызван при размере транскрипта 276630 байт, запись `assistant` «Привет» —
за этим смещением). [D.2]
Набранный в терминале текст — запись `{"type":"user","message":{"role":"user",
"content":"<текст>"}}` (строка); голден порядка —
`fixtures/telegram-relay/r2/transcript-around-stop.jsonl` (ввод, затем ответ
`assistant`, записанный после вызова хука).

## Вывод

stdout пуст всегда. stderr — при отказе поставить вопрос, одна строка
`mpu claude-hook stop: без вопроса — <причина>`; причины — таблица «Ввод»,
`бот не настроен`, `бот недоступен: …`, `сервер mpu не отвечает: …`.

## Установка

`install.sh` вписывает в `~/.claude/settings.json` запись
`{"matcher":"","hooks":[{"type":"command","command":"mpu claude-hook stop","timeout":30}]}`
в `hooks.Stop` — по тем же правилам, что запись `PermissionRequest`
(`claude-hook-permission-request.md`, «Фрагмент настроек и установка»);
вывод `install: claude хук stop: вписано` / `без изменений`. Голден —
`fixtures/telegram-relay/r2/settings-fragment-stop.json`. [S16]

## Инварианты

- Хук выходит, поставив вопрос: время работы не зависит от ответа владельца.
- Текст владельца доставляется только в канал с ключом этой сессии.
- `CLAUDE_CODE_MESSAGING_TOKEN` и токен бота не появляются нигде.

## Пункты чек-листа

Порция R2 целиком (`claude-channel.md`, этот хук, `platform/telegram-questions.md`,
раздел «R2»):

`design.md`:

1. Примитивы — изменил: у ряда два вида вопроса (срочный / «ждёт ввода») и
   операции «отложить» (`Позже`) и «снять» (`Пропустить`) выводятся из
   примитивов R1a «снять» и порядка ряда; доставка текста — примитив канала.
2. Особые случаи → получатели — изменил: «сессия с каналом / без канала» —
   две реализации ответа на текст (доставить / «ответьте в терминале»), а не
   ветка; вид вопроса сам знает своё место в ряду.
3. Проверки `null` — изменил: отсутствие канала — объект «без канала»,
   отсутствие названия/окна — как в R1b.
4. Кто решает — изменил: порядок ряда решает ряд по виду вопроса; доставку —
   канал; «сессия закрыта» — регистрация канала; снятие по транскрипту —
   наблюдатель R1c.
5. Память приватна — изменил: реестр каналов (ключ → канал) — объект ядра с
   намерениями «доставить», «есть ли канал» не отдаётся наружу для `if`.
6. Голые данные → протокол — изменил: ключ сессии — тип, а не строка пути.
7. Основание проверкой — изменил: «хук и канал одной сессии получают один
   `CLAUDE_CODE_MESSAGING_SOCKET`» → живой замер R2-2 и тест на голдене
   окружения; «`last_assistant_message` в payload» → голден `live-stop.json`.

`design-mpu.md`:

1. Команда — сообщение: `claude-hook stop`, `claude-channel` — объявления со
   справкой.
2. Вид метода — изменил: `claude-channel` исполняет клиент (stdio Claude
   Code), `claude-hook stop` — ядро.
3. Решение политики — изменил: посев `allow` строкой таблицы для
   `claude-hook stop`.
4. Один источник — изменил: список строк-хуков клиента — один; заголовок
   вопроса — одна сборка с R1b.
5. Величина из результата — ничего.
6. Права Deno — изменил: `CLAUDE_CODE_MESSAGING_SOCKET` в `--allow-env`
   клиента, ядра, исполнителя (как `TMUX_PANE`); smoke краснеет без права.
7. Границы модулей — изменил: канал — модуль клиента (`cli/`), импортирует из
   `back/` только контракт кадров.
8. Внешнее ссылкой — изменил: stdio, окружение, часы повтора — параметры.
9. Голден снятый — изменил: `live-stop.json`, `live-channel-exchange.jsonl`
   сняты 2026-10-06; ответ Claude Code на `notifications/claude/channel` и
   вид в ленте — снят пробным каналом.
10. Пропускаемая проверка — ничего.
