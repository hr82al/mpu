# mpu sheet: реестр таблиц — alias, sync, open

**Статус:** к реализации (2026-08-28).

## Назначение

Три вещи вокруг одного вопроса «какую таблицу открывают»: `alias` заводит
короткие имена, `sync` наполняет локальный реестр таблиц с сервера, `open`
пользуется резолвом, чтобы открыть таблицу или её лист в браузере.

Резолв цели общий для всего семейства (`sheet.md`, «Резолв цели»): алиас →
идентификатор → подстрока заголовка → `client_id`. Кандидатов для двух
последних видов даёт таблица `sl_spreadsheets`, которую наполняет `sync`.

## CLI-контракт

```
mpu sheet alias add ИМЯ ТАБЛИЦА
mpu sheet alias ls
mpu sheet alias rm ИМЯ
mpu sheet sync
mpu sheet open [ЛИСТ] [-s|--spreadsheet ЦЕЛЬ]
```

`ИМЯ` — буквы, цифры, `_`, `.`, `-`; прочее отвергается кодом 2.
`ТАБЛИЦА` — идентификатор или ссылка; из ссылки берётся идентификатор, и он
обязан пройти проверку формы, иначе код 2.

## Хранилище

- `sheet_aliases (name PRIMARY KEY, ss_id, created_at)` — заведение поверх
  существующего имени обновляет `ss_id`, не заводя второй строки;
- `sl_spreadsheets (ss_id PRIMARY KEY, client_id, title, template_name,
  is_active, server, synced_at)` — наполняется `sync` целиком.

## Побочные эффекты

`alias ls` и `open` без имени листа состояние не меняют. `open` **с** именем
листа наполняет кэш метаданных: она спрашивает перечень вкладок, а тот при
промахе пишет ключ `sheet:info:<ss_id>` (`sheet-cache.md`). Это делает её
потребителем кэша, не хозяином.

`sync` заменяет содержимое `sl_spreadsheets` целиком — удаление и вставка в
одной транзакции.

## Форма ссылки `open`

Сверяется дословно — запуск открывателя из изолированной сессии недостижим,
и ссылка остаётся единственным проверяемым результатом команды:

```
без листа:  https://docs.google.com/spreadsheets/d/<ss_id>/edit
с листом:   https://docs.google.com/spreadsheets/d/<ss_id>/edit#gid=<sheet_id>
```

`<sheet_id>` — числовой идентификатор вкладки из метаданных, не её имя.
Ссылка и печатается, и передаётся открывателю: печать не зависит от того,
удался ли запуск.

## Инварианты

1. **Замена реестра атомарна.** Оборванный `sync` не оставляет реестр
   опустошённым: удаление и вставка — одна транзакция.

2. **Сообщение называет ту величину, которая в него подставлена.** Оригинал
   `sync` печатает `synced N spreadsheets`, где `N` — число строк, **которые
   вернул сервер**, а не число вставленных: записи не-объекты и записи без
   идентификатора или клиента пропускаются молча. При ответе с мусором вывод
   завышает результат, и оператор не узнает, что часть таблиц в реестр не
   попала. Печатать надо вставленное; отброшенное, если оно есть, называется
   отдельно.

3. **След `sync` двойной, и второй важнее первого.** Строки в
   `sl_spreadsheets` — прямой след; настоящая цель — то, что после `sync`
   резолв **находит то, чего не находил**. Приёмка меряет оба, и второй не
   выводится из первого.

4. **Пустой ответ не стирает непустой реестр.** Пустой список — и
   правдоподобный ответ сбойного сервера, и правда для свежей установки или
   клиента без таблиц; различить их по самому ответу нельзя. Поэтому граница
   проходит не по ответу, а по тому, что мы вот-вот потеряем: пустой ответ
   при **непустом** реестре — отказ кодом 1 с сохранением прежнего
   содержимого; пустой ответ при пустом реестре — штатный исход, код 0.
   Иначе реестр невозможно завести с нуля.

5. **Снятие алиаса различает исходы.** Снятие существующего — успех со
   строкой; снятие отсутствующего — код 1 и сообщение, что имени нет.

6. **Строка называет то, что изменилось.** Заведение поверх существующего
   имени печатает обе стороны замены (прежний идентификатор → новый), снятие
   — что именно снято. Иначе оператор не отличит замену от заведения, а
   снятие от промаха по имени. `created_at` при замене не трогается: поле
   означает, когда заведено имя, а не когда назначен нынешний идентификатор.

## Граничные случаи и ошибки

- недопустимое имя алиаса → код 2, показать допустимый набор символов;
- `ТАБЛИЦА` не похожа на идентификатор или ссылку → код 2;
- `alias ls` при отсутствующей таблице алиасов → пустой вывод, код 0;
- `open ЛИСТ`, листа нет → код 2 и перечень доступных листов;
- `open`, сервер метаданных недоступен → код 1;
- `open`, открывателя в системе нет → **код 1 при напечатанной ссылке**:
  молчаливый ноль означал бы «таблица открыта», а её никто не открывал;
  печать остаётся — она и есть то, что спасает вызов (проверено 2026-08-28:
  с пустым `PATH` ссылка печатается, код 1);
- `sync`, сервер недоступен или ответ не список → код 1, реестр не тронут.

## Приёмка

Живая пара, по следу:

- `alias add` поверх существующего имени: строк в `sheet_aliases` не
  прибавилось, `ss_id` сменился;
- `alias rm` дважды подряд: первый — успех, второй — код 1;
- `sync` до и после: число строк `sl_spreadsheets` **и** отдельный замер
  резолва — цель, не резолвившаяся до, резолвится после (инвариант 3);
- `sync` на ответе с записью без идентификатора: напечатанное число равно
  вставленному, отброшенное названо;
- `open` без листа: кэш метаданных не изменился; `open ЛИСТ`: ключ
  `sheet:info:<ss_id>` появился (или обновился) — граница потребителя.
