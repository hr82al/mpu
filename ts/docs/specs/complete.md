# `mpu-complete`: дополнение в bash, fish, nu

Статус: к реализации

## Назначение

Дополнение строки `mpu-next` в оболочке — на полуслове, быстро и без побочных
эффектов. Подпроект `ts/complete/`, программа `mpu-complete`, задача
`deno task complete`. Источник — только снимок дерева, который пишет
`mpu-back` (`platform/back-rpc.md`, «Снимок дерева»): ни сети, ни токенов,
работает и при погашенной службе. Нынешнее дополнение старого `mpu` (bash,
zsh) не меняется.

«Умные» значения (номера карточек, клиенты) — не в этой порции: ни один объект
ещё не отвечает на `complete:`.

## Снимок: дополнение `mpu-back`

Узел снимка получает поле `flags` — у узла с хвостом `args` (команда реестра,
группа с `bare` или с селектором впереди): флаги нынешнего разбора аргументов
этой команды или группы.

```json
{"path": ["sql-ro"], "summary": "…", "selectors": [], "tail": "args",
 "flags": [{"name": "--json", "summary": "…"}, {"name": "--dry", "summary": "…"}]}
```

- `name` — длинная форма с `--`; у флага с короткой формой — ещё запись
  короткой (`-p`) с тем же `summary`;
- у узла без хвоста `flags` — пустой массив;
- `--help` в `flags` не входит — его добавляет само дополнение;
- у команды — её входы-флаги и общий `--json`; у группы с хвостом (`mcp`,
  `ozon-jobs`) — `[]`: флаги объявлены у детей или разбираются самим
  исполнением группы, а источник — только объявление команды.

Узел снимка получает ещё `summaries` — назначение каждого собственного
селектора, у которого нет своего узла (`allow:`, `ask:`, `deny:`, `forget:`,
`policy` у корня): `{"allow:": "…", …}`. У селекторов с узлом назначение — в
узле. Поле добавочное: прежние поля снимка не меняются.

У `mpu-complete` есть `--version`, как у прочих установленных программ.

## CLI-контракт

```
mpu-complete [--snapshot <путь>] -- <слово>…
mpu-complete init bash|fish|nu [--command <имя>]
```

**Дополнение.** Слова после `--` — строка без имени команды; последнее слово —
дописываемое (может быть пустым `""`). Снимок — `$HOME/.cache/mpu/tree.json`,
`--snapshot` его заменяет.

Вывод — варианты по одному на строку: `<вариант>\t<описание>`, отсортированы по
варианту; перевод строки после каждого. Код всегда 0 — дополнение не падает.

| Дано (слова) | Варианты |
|---|---|
| `""` | селекторы корня (дети и собственные `allow:`, `ask:`, `deny:`, `forget:`, `policy`) с назначениями |
| `"ki"` | селекторы корня, начинающиеся с `ki` |
| `"kiten" ""` | селекторы узла `kiten` |
| `"kiten" "card" "-"` | флаги узла `kiten card`, начинающиеся с `-`, плюс `--help` |
| `"kiten" "card" "123" ""` | ничего (узел с хвостом, слово не флаг — значения не дополняются) |
| `"kitn" ""` | ничего (пути нет) |
| `"kiten" "--"` | только `--help` (у группы без хвоста флагов нет) |
| `"help" "ki"` | как `"ki"` (слово `help` и `--help` при обходе пропускаются) |
| снимка нет или он не JSON | ничего |

Описание — `summary` узла или флага; у `--help` — `справка`. Табуляция и
перевод строки в описании заменяются пробелом.

**`init`.** Печатает скрипт подключения для оболочки; `--command` — имя
дополняемой программы (по умолчанию `mpu-next`). Эталоны —
`fixtures/complete/init-bash.sh`, `init-fish.fish`, `init-nu.nu` (составляет
исполнитель, хост замораживает после живой проверки):

- **bash:** функция через `complete -F`, которая зовёт
  `mpu-complete -- <слова>` и кладёт в `COMPREPLY` только варианты (до `\t`).
  Слово с `:` (`seller-id:`) — одно слово: скрипт склеивает части, которые bash
  разрезал по `COMP_WORDBREAKS`, и отдаёт `COMPREPLY` без уже набранного
  префикса.
- **fish:** `complete -c <имя> -f -a '(mpu-complete -- (commandline -opc)[2..] (commandline -ct))'`
  — fish сам показывает описание после `\t`.
- **nu:** замыкание-дополнитель для `$env.config.completions.external`,
  которое для `<имя>` зовёт `mpu-complete -- ...$spans.1..` и отдаёт записи
  `{value, description}`; для остальных команд — прежний дополнитель
  (скрипт печатает, как его подключить, не затирая чужой).

## Инварианты

- Дополнение не ходит в сеть, не читает токенов, не пишет файлов, не поднимает
  службу и не пишет в журнал вызовов.
- Время ответа на снимке нынешнего дерева — меньше 100 мс от запуска до выхода
  (замер в отчёте).
- Варианты берутся только из снимка: новая команда появляется в дополнении
  после перезапуска `mpu-back` без правки `mpu-complete`.

## Граничные случаи и ошибки

Все — в таблице «CLI-контракт»; плюс:

| Дано | Ожидается |
|---|---|
| `mpu-complete` без `--` | stderr `mpu-complete: нужен -- и слова`, код 2 |
| `init zsh` | stderr `mpu-complete: оболочка zsh не поддерживается (bash, fish, nu)`, код 2 |
| в снимке узла нет | ничего, код 0 |
