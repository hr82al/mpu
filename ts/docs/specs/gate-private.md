# mpu gate private

Статус: черновик (2026-09-10 — постановка по живым случаям; к реализации — после ответа на
«Открытые вопросы»)

## Назначение

Ворота утечки приватного тулинга в то, что увидит человек: дифф ветки, тела её коммитов и описание
MR. Приватное — имя CLI `mpu`, имена навыков, служебные пути и эвфемизмы, которые выдают само
существование инструмента. Один словарь на все проверки вместо разового `grep` с разным набором
слов у каждой сессии.

**Живые случаи (2026-09-10).**

- Перед выгрузкой веток поставки «Чек-лист» хост и исполнитель каждый своим `grep` искали по
  `git diff origin/main...HEAD` и `git log --format=%B` слова `mpu`, `proc-`, `skill`, `ak-ts`,
  `probe`, `design.md`, `review.md`, `~/tmp`, `mp/.claude`, «чек-лист качества». Наборы слов у двух
  сессий различались.
- Ложное срабатывание: `mpu` внутри слов `computed_at`, `NOT_COMPUTED`, `formatComputedAt` — нужен
  поиск по границе слова.
- Настоящая утечка другого вида: в опубликованной ветке `!559` лежали 29 файлов `.playwright-mcp/`
  (снимки и выгрузки страниц служебного браузера) из пяти коммитов; ветку пришлось чистить
  переписыванием истории. Имена путей в `--stat` диффа — такой же объект проверки, как текст.

## CLI-контракт

`mpu gate private [--repo REPO] [--base REF] [--mr REF] [--json]`

- `--repo`, `--base` — как в `gate-style.md` (дефолт базы: `ozon` → `origin/main`, `sw-front` →
  `origin/dev`, `sw-back` → `origin/trunk`, `sl-back` → `origin/main`).
- `--mr` — дополнительно проверить описание MR (адресация — `platform/gitlab-api.md`); без флага
  описание не читается.
- `--json` — вместо отчёта JSON-объект.

Политика — `ro`.

## Ввод/вывод

### Что проверяется

1. Добавленные строки `git diff <base>...HEAD` (текст).
2. Пути файлов диффа (`--name-only`): добавленные файлы под служебными каталогами.
3. Тела и заголовки коммитов `git log <base>..HEAD --format=%B`.
4. Описание MR (`--mr`).

### Словарь (одна точка правды для всех четырёх проверок)

| Класс | Правило | Пример |
| --- | --- | --- |
| имя CLI | слово `mpu` или `new-mpu` по границе слова (`\bmpu\b`) | «прогнать `mpu ss-update`» |
| имена навыков | точные имена каталогов `mp/.claude/skills/*` (снимаются с диска на вызов) и слово по префиксам `inv-`/`tool-`/`conv-`/`proc-`/`ref-`, за которым идёт слово | «см. `proc-ozon-cl`» |
| служебные пути | `~/tmp`, `/home/user/`, `mp/.claude`, `.superpowers/`, `.playwright-mcp` | «лежит в `~/tmp/checklist-k4`» |
| служебные файлы | пути диффа, начинающиеся с `.playwright-mcp/` или `.superpowers/` | 29 файлов в `!559` |
| эвфемизмы | «внутренний инструмент», «наша утилита», «внутренний CLI», «служебный скрипт», «инструмент сверки», «чек-лист качества» (без учёта регистра, словоформы — открытый вопрос) | «донастроили внутренний инструмент» |

Правило словаря — из корневых правил монорепо, раздел о приватном тулинге: прячется и имя, и сам
факт существования инструмента.

### Результат

`{ repo, base, findings: [{ where: diff|path|commit|mr, class, file?, line?, commit?, text }],
counts }` — `text` — строка с находкой, найденное слово выделено `«…»`. Отчёт: группы по `where`,
последняя строка `находок: N`. Exit 0 — находок нет, 1 — есть.

## Побочные эффекты

Нет.

## Конфигурация

Нет своей; имена навыков — с диска рабочей области (`mp/.claude/skills`).

## Инварианты

- Словарь один: те же классы на всех четырёх объектах проверки.
- Слово ищется по границе: `computed` не находка.
- Команда ничего не правит — ни коммиты, ни описание MR.

## Граничные случаи и ошибки

- Сам репозиторий `mp` (где навыки и живут) — отказ, exit 2: там упоминания законны.
- `--mr` без доступа к API → отчёт по остальным трём, в stderr — ошибка атома, exit по находкам.
- База не найдена → exit 2.
