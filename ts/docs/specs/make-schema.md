# mpu make-schema

Статус: реализовано

## Назначение

Создать схему клиента в локальном стенде: запустить `clientsMigrations
init` внутри локального контейнера `mp-sl-N-cli`. Метод идемпотентен —
`schema_<client_id>` создаётся, только если её ещё нет.

Единственная команда с **локальным** транспортом: вызов идёт `docker
exec` на этой же машине, без Portainer и без ssh. Поэтому она и не
входит в семейство обёрток (`platform/portainer.md`): у того весь ход
построен вокруг удалённого контейнера, и соседство в общей таблице
врало бы.

## CLI-контракт

```
mpu make-schema SELECTOR [--server sl-N] [--client-id N] [-p|--print]
```

- `SELECTOR` — клиент (`platform/selector.md`): client_id,
  spreadsheet_id либо заголовок таблицы. Голый вызов печатает справку,
  exit 2.
- `--client-id N` — явный client_id; побеждает резолв селектора и
  делает кэш-БД ненужной.
- `--server sl-N` — номер контейнера стенда. Без флага это `mp-sl-1-cli`
  **независимо** от того, в какой сервер резолвится селектор: стенд
  один, и его номер к прод-серверу клиента отношения не имеет.
- `-p/--print` — напечатать docker-команду одной строкой и скопировать
  её в буфер обмена (`platform/clipboard.md`), ничего не выполняя.
- `--local` у команды нет: она и так локальная.
- Политика — `rw`: метод создаёт схему. Тулом публикуется в профиле
  `rw` вместе с прочими мутирующими.

Выполняемая команда:

```
docker exec mp-sl-<N>-cli node cli service:clientsMigrations init \
  --client-id <C> --server sl-<N>
```

## Ввод/вывод

stdin не читается. При `--print` в stdout уходит одна строка —
собранная docker-команда; она же копируется в буфер обмена. Иначе
stdout и stderr `docker exec` проходят насквозь, а код выхода
наследуется 1:1 без дополнительных сообщений.

## Побочные эффекты

Без `--print` — один локальный `docker exec`, внутри которого метод
создаёт схему `schema_<client_id>` в PostgreSQL стенда. Ни сети наружу,
ни записи в кэш-БД: кэш только читается ради резолва селектора, и с
явным `--client-id` не читается вовсе. При `--print` побочный эффект
один — буфер обмена.

## Конфигурация

Своих ключей env-файла у команды нет: контейнер локальный, PG-креды
нужны не ей, а `node cli` внутри контейнера.

## Инварианты

- Транспорт локальный при любом вводе: ни Portainer, ни ssh команда не
  задействует. Отсюда и отсутствие `--local`.
- Номер в имени контейнера и значение `--server sl-<N>` внутри вызова
  всегда совпадают.
- `--print` не выполняет ничего, кроме копирования в буфер; сбой
  копирования на вывод и код выхода не влияет.
- Идемпотентность: повторный вызов на существующей схеме её не меняет —
  свойство метода `init`.

## Граничные случаи и ошибки

- `client_id` не выводится (кандидатов нет либо у них разные значения)
  и `--client-id` не задан → `mpu make-schema: cannot resolve
  --client-id from selector; pass --client-id` + список кандидатов,
  exit 2.
- `--server` не вида `sl-N` → `mpu make-schema: bad --server: '<V>'
  (expected sl-N)`, exit 2.
- `--client-id` не целое положительное → отказ разбора ввода, exit 2.
- Контейнера `mp-sl-<N>-cli` нет или он не запущен → `docker exec`
  падает, и его код выхода проходит насквозь. Поднять стенд —
  `specs/mp-init.md`.

## Известные отклонения

- **preserve** — `--server` уходит внутрь вызова всегда, хотя `init`
  создаёт схему только по `--client-id` и переданный `--server`
  игнорирует. Причина: паритет с исходной командой; обёртка
  воспроизводит передачу аргумента, а не судит о его смысле.
- **fix** — `--server` больше не работает как override резолва. В
  черновике спеки он замещал селектор, из-за чего вместе с ним
  становился обязателен `--client-id`. Здесь `--server` выбирает только
  контейнер стенда, а client_id по-прежнему берётся из селектора: стенд
  и сервер клиента — разные вещи, и связывать их значило бы требовать
  флаг там, где ответ уже известен.
