# mpu d2-miro

Статус: черновик — к реализации не готова, пока владелец не назвал доску для живой проверки (см. «Открытые вопросы»)

## Назначение

Рендер D2-диаграммы (`<файл>.d2` + его SVG-рендер) на доску Miro
редактируемым фреймом: шейпы/тексты по layout'у SVG, connectors по
рёбрам. Повторный рендер идемпотентен: фрейм с тем же title удаляется
со всем содержимым и пересоздаётся на прежнем месте.

## CLI-контракт

`mpu d2-miro D2_FILE [--title T] [--board ID] [--position x,y]
[--skip-render] [--dry-run]`

- `D2_FILE` — существующий читаемый файл; отсутствует/каталог → ошибка
  CLI-парсера, exit 2.
- `--title` — title фрейма; default — имя файла без расширения.
- `--board` — разовый override `MIRO_BOARD_ID`.
- `--position` — координаты центра фрейма `x,y` (два float через
  запятую); не парсится → ошибка CLI-парсера, exit 2.
- `--skip-render` — использовать существующий `.svg` даже если он
  старше `.d2` (при отсутствующем `.svg` рендер всё равно выполняется).
- `--dry-run` — разбор и печать плана, ни одного вызова Miro API.

**Выбор SVG** (`<файл>.svg` рядом с `.d2`), первое сработавшее правило:

1. `--skip-render` и SVG существует → взять как есть.
2. SVG существует и его mtime ≥ mtime `.d2` → взять как есть.
3. `d2` есть в PATH → stderr `[info] rendering <имя.d2> -> <имя.svg>`,
   запуск `d2 <путь.d2> <путь.svg>`; ненулевой выход → ошибка, exit 1.
4. `d2` нет в PATH, SVG существует → stderr `[warn] d2 CLI not found,
   using stale <путь.svg> (file mtime older than .d2)`, взять как есть.
5. `d2` нет в PATH, SVG нет → ошибка `d2 CLI is not in PATH and no SVG
   file exists next to the .d2 source. Install d2 (https://d2lang.com)
   or pass --skip-render with a pre-rendered .svg.`, exit 1.

**Разбор входа**: из `.d2` — вид шейпа (`shape:`), метка, цвета
(`style.fill` / `style.stroke`), `class: card` (карточка),
markdown-блоки, рёбра; из SVG — координаты/размеры каждого шейпа и
viewBox. Имена с точками задают вложенность (контейнеры). Расхождение
множеств имён → stderr `[warn] in SVG but not in d2 source: [<имена>]`
/ `[warn] in d2 source but not in SVG: [<имена>]`, рендер продолжается.

Info-строка (stderr): `[info] <имя.d2>: <K> shapes, <E> edges,
<M> markdown blocks; viewBox <W>x<H> -> frame <FW>x<FH> (scale=1.000)`.
Масштаб всегда 1:1: размер фрейма = размер viewBox, высота увеличена на
область markdown-блоков (аннотаций) внизу.

**`--dry-run`** — план в stdout, после info-строки:

```
[dry-run] would create:
  <target:20> <имя>  kind=<kind>
  edge   <src> -> <dst>  label='<метка до 30 симв.>'[ [skipped: card→card]]
```

`<target>` = `card` для kind=card, иначе `shape(<miro-вид>)`,
выравнивание по левому краю до 20 символов; шейпы — по имени
(сортировка), рёбра — в порядке источника.

## Ввод/вывод

stdout — только план `--dry-run`; всё служебное (`[info]`, `[warn]`,
`[skip]`, `[done]`) — stderr. Финальная строка успеха: stderr
`[done] frame='<title>' shapes=<N> texts=<T> connectors=<M> skipped=<S>
retries=<R>` — `texts`, `skipped` и `retries` печатаются, когда тексты,
пропуски и повторы были.

`texts` внесён 2026-08-31 по наблюдению реализующей стороны: это число
**участвует в решении об отказе** (код 1 даётся, когда ноль и шейпов, и
markdown-блоков), а в итоговой строке его не было. Величина, решающая исход,
обязана быть названа — иначе по выводу нельзя понять, почему код именно
такой. Хвосты не украшение: они служат
инварианту «частичный успех называет числами». Без `skipped` строка успеха
одинакова у полной отрисовки и у той, где не создалось ничего; без
`retries` неотличимы прогон по здоровой службе и прогон, вытянутый
повторами, — а именно `retries` показывает, что служба сегодня отдаёт
`5xx`, и объясняет десять секунд там, где обычно две.

Exit: 0 — успех, в том числе с `[skip]`-пропусками; **1 — на доске не
создано ни одного объекта**, хотя план был непуст (см. ниже); 2 — ошибки
ввода/конфигурации
(CLI-параметры, отсутствие `MIRO_TOKEN`/`MIRO_BOARD_ID`); 1 — ошибки
внешних систем (Miro API, сбой d2-рендера, нет `d2` и нет SVG).

**Miro API — граница дословно.** База
`https://api.miro.com/v2/boards/<board_id>` (board_id
URL-экранируется); заголовки `Authorization: Bearer <MIRO_TOKEN>`,
`Accept: application/json`; тела — JSON. Ответ 429 → stderr
`[miro] 429 rate-limit, sleep <N>s`, пауза `Retry-After` секунд (нет
заголовка — экспоненциальный backoff от 1 с, потолок 30 с), повтор;
максимум 6 попыток. Прочие не-2xx → ошибка
`miro <METHOD> <path> -> <status>: <тело до 300 симв.>`.

- Фреймы доски: `GET /items?limit=50[&cursor=<c>]&type=frame`,
  пагинация по полю `cursor` ответа.
- Дети фрейма: `GET /items?parent_item_id=<id>&limit=50[&cursor=<c>]`.
- Разлочивание: `PATCH /items/<id>` тело `{"locked": false}`; ответы
  400 и 404 терпимы (не ошибка).
- Удаление: `DELETE /items/<id>` для каждого ребёнка, затем
  `DELETE /frames/<id>`; 404 = уже удалён (успех); 400 со словом
  `locked` в теле → разлочить PATCH'ем и повторить DELETE один раз
  (404 на повторе — успех).
- Создание фрейма: `POST /frames`, тело `{"data": {"title": <T>,
  "format": "custom", "type": "freeform"}, "style": {"fillColor":
  "#ffffff"}, "position": {"x", "y"}, "geometry": {"width",
  "height"}}`.
- Шейп: `POST /shapes` — `data.shape`, `data.content` (HTML-метка),
  `style` (fillColor/fillOpacity/borderColor/borderWidth/borderStyle/
  color/fontSize/textAlign/textAlignVertical), `position`, `geometry`
  (width ≥ 60, height ≥ 40), `parent.id` = id фрейма.
- Текст: `POST /texts` — `data.content` (HTML), `position`,
  `geometry.width` (≥ 200), `parent.id`.
- Connector: `POST /connectors` — `startItem.id`, `endItem.id`
  (+ `snapTo` при разводке), `shape: "curved"`, `style.strokeColor:
  "#1a1a1a"`, `style.strokeWidth: "1"`, при метке —
  `captions: [{"content": <HTML>}]`.

**Позиция фрейма**, первое сработавшее правило: явный `--position`;
существующий фрейм с тем же title → его (x, y); иначе — правее самого
правого фрейма доски: x = его правый край + 200 + W/2, y = средний y
всех фреймов; фреймов нет → (200 + W/2, 0). Существующий одноимённый
фрейм после определения позиции удаляется (stderr `[info] removing
existing frame '<title>' (<id>)`), затем `[info] created frame <id>
at (<x>, <y>)`.

**Рендер**: контейнеры создаются раньше своих детей (z-order);
контейнер рисуется по bbox прямых детей с паддингом, метка — сверху
слева; элементы `class: card` — прямоугольник со скруглением и рамкой;
markdown-блоки без SVG-layout — под диаграммой (текст — text-элементом,
markdown-таблица — сеткой прямоугольных шейпов, ячейка = отдельный
шейп). Метки — HTML с экранированием `& < >` и `\n` → `<br/>`. Ошибка
создания отдельного элемента не прерывает рендер: stderr
`[skip] <вид> <имя>: <ошибка>` / `[skip] connector <src> -> <dst>:
<ошибка>`, остальное создаётся. Ребро, у вершины которого нет
созданного шейпа → `[skip] edge <src> -> <dst> (no shape: [<имена>])`.
Двунаправленная пара рёбер (A→B и B→A) разводится: у ребра с
алфавитно меньшим src обе привязки `snapTo: top`, у обратного —
`bottom`.

## Побочные эффекты

Мутация доски Miro: существующий одноимённый фрейм удаляется со всем
содержимым (включая добавленное руками и залоченное — lock снимается
автоматически), создаются новые элементы; отмена — только средствами
Miro. Локально: правила выбора SVG выполняются и при `--dry-run` —
вызов `d2` может создать/перезаписать `<файл>.svg`. Сеть — только Miro
API (кроме dry-run).

## Конфигурация

Env-файл (контракт — `platform/env-file.md`): `MIRO_TOKEN` (обязателен),
`MIRO_BOARD_ID` (обязателен, если нет `--board`). Внешний бинарь `d2`
в PATH — опционален при актуальном SVG.

## Инварианты

- `--dry-run` не выполняет ни одного вызова Miro API.
- Повторный рендер того же title сохраняет позицию фрейма —
  единственный случай, когда позиция берётся не из `--position` и не из
  авто-правила.
- Дети фрейма удаляются до самого фрейма — сирот на доске не остаётся.
- Ошибка создания одного элемента не прерывает рендер остальных — **и итог
  это называет**: сколько элементов создано, сколько не создано и почему.
  Молчаливый успех при частично собранном фрейме недопустим: на доске
  останется картинка, которую оператор примет за целую. Числа берутся из
  ответов службы, а не из длины плана (`CLAUDE.md`, «Величина берётся там,
  где совершается работа»).
- Ответы Miro API — стык, и его фикстуры **снимаются с живой доски, а не
  сочиняются** (`CLAUDE.md`, «Фикстуру стыка снимают, а не сочиняют»).
  Сочинённый ответ проверяет догадку о форме той же догадкой: тест зелёный,
  потому что обе стороны написал один человек.
- Токен не попадает ни в вывод, ни в тексты ошибок.

## Граничные случаи и ошибки

- Пустая доска → фрейм в (200 + W/2, 0).
- Одноимённый фрейм или его дети залочены → авто-разлочивание и
  удаление без подтверждения (см. «Известные отклонения»).
- SVG новее `.d2` → используется без пере-рендера и без
  `--skip-render`; флаг влияет только на случай устаревшего SVG.
- Шейп есть в SVG, но не в `.d2` → рендерится с видом по умолчанию
  (прямоугольник) после `[warn]`-строки.
- Метка ребра пустая → connector без `captions`.
- Нет `MIRO_TOKEN` (или `MIRO_BOARD_ID` без `--board`) → ошибка
  конфигурации, exit 2, с указанием env-файла.

## Поддерживаемое подмножество D2 — снято 2026-08-31

Фикстуры: `fixtures/d2-miro/sample.d2` + `sample.svg` (рендер настоящим
`d2 v0.7.1` тем же вызовом, что делает команда: `d2 <вход> <выход>`) и
голден плана `sample-dry-run.txt`. Состав входа — по списку из
«Golden-примеры»: два шейпа, контейнер, card, markdown-блок,
двунаправленная пара рёбер.

**Имя шейпа читается как `[a-zA-Z_]\w*`, метка — только из кавычек.**
Это не украшение синтаксиса, а граница разбора: имена сопоставляются с
SVG по совпадению, и кириллический идентификатор пары не находит.

Контрпример снят рядом — `sample-cyrillic.d2` и его голден. Опасно тут
то, что **отказа не происходит**: шейпы всё равно попадают в план, но
уже из SVG, а не из исходника, и вместе с этим тихо теряются свойства.

```
[dry-run] would create:
  shape(rectangle)     витрина  kind=rectangle      <- в исходнике cylinder
  shape(rectangle)     загрузчик  kind=rectangle
[warn] in SVG but not in d2 source: ['витрина', 'загрузчик']
[info] … 2 shapes, 1 edges, 0 markdown blocks       <- md-блок исчез совсем
```

Против правильного входа:

```
[info] … 5 shapes, 5 edges, 1 markdown blocks
  shape(can)           mart  kind=cylinder
```

Отсюда требование к переносу: **расхождение имён — не предупреждение, а
отказ либо счёт в отчёте**. Молчаливая потеря `shape:` и markdown-блока
при коде 0 — худший из возможных исходов: план выглядит выполненным.

У правильного входа остаётся своё предупреждение — `in d2 source but not
in SVG: ['card']`: markdown-блок в SVG под своим именем не находится.
Это наблюдаемое поведение обеих сторон, и оно ожидаемое; переносу его
воспроизводить как есть.

## Известные отклонения

- **fix** — отсутствие `MIRO_TOKEN`/`MIRO_BOARD_ID`, сбой d2-рендера и
  не-retryable ошибки Miro API наружу уходят Python-трейсбеком
  (exit 1). Правильно: `mpu d2-miro: <причина>` в stderr без трейсбека,
  exit 2 для конфигурации, exit 1 для внешних систем.
- **fix** — `--dry-run` помечает рёбра card→card `[skipped:
  card→card]`, но реальный рендер такие connectors создаёт. План обязан
  совпадать с рендером: пометку не печатать.
- **preserve** — залоченные элементы разлочиваются и удаляются без
  подтверждения. Причина: заявленная идемпотентность повторного
  рендера; остановка на чужом lock сделала бы re-render
  неавтоматизируемым.

### Полный провал отрисовки — код 1

Планировалось объектов больше нуля, а создано ноль — команда отказывает
кодом 1 и называет числа:

```
[done] frame='plain' shapes=0 connectors=0 skipped=3
mpu d2-miro: на доске не создано ни одного объекта из 2 шейпов и 0 markdown-блоков
```

**Считаются шейпы и markdown-блоки вместе**, а не одни шейпы. Граница
предложена реализующей стороной и принята с доводом, который бьёт мою
прежнюю формулировку («ни одного шейпа при непустом плане») с обеих
сторон:

- она **не сработала бы**, где должна: вход из одних `|md`-блоков даёт
  `shapes` пустыми по построению — markdown-блок шейпом из SVG не выходит
  (видно на `fixtures/d2-miro/sample.d2`: `card: |md` есть во входе, в
  `sample.svg` его нет). Все тексты могли бы отбиться — и это пустой фрейм
  с кодом 0;
- она **сработала бы ложно**: шейпы отбиты «outside of parent boundaries»,
  а текст лёг по другим координатам — фрейм не пуст, а отказ утверждал бы
  обратное.

Замер 2026-08-31, живая пара «до/после» на подопытной доске, мутант со
сдвинутыми координатами ребёнка:

| вход | создано | код |
| --- | --- | --- |
| `sample.d2` (есть `|md`) | шейпов 0, текст 1 | 0 — фрейм не пуст |
| `plain.d2` (без `|md`) | 0 и 0 | **1** |
| `plain.d2`, здоровый бинарь | шейпов 2, связей 1 | 0 |

Частичный успех остаётся кодом 0: его числа в `[done]` честны, и скрипту
их достаточно.

Прежняя редакция раздела фиксировала обратное — код 0 при любом исходе,
как у оригинала (`d2_miro.py:576,621`). Расхождение с оригиналом теперь
осознанное: машиночитаемая половина обязана говорить то же, что
человекочитаемая, иначе обманут ровно тот потребитель, ради которого она
заведена.

### Пустой план не создаёт фрейм — отказ до обращения к службе

План пуст (ни шейпов, ни markdown-блоков) — команда отказывает **до
единственного вызова службы**, кодом 2: входной файл не тот. Доска при этом
не трогается вовсе.

Отдельный случай от «полного провала» выше, и коды разные не случайно: там
план был непуст и служба отбила работу — это отказ внешней системы, код 1;
здесь работать не над чем — это ошибка ввода, код 2.

Отказ одинаков в обоих режимах — **`--dry-run` тоже отказывает**. Довод не
«предпросмотр обещает показать план, а показывать нечего», а более сильный:
спека уже требует, чтобы план совпадал с рендером (отклонение-`fix` про
пометку `[skipped: card→card]`). Предпросмотр, печатающий пустой список и
возвращающий ноль там, где рендер отказывает, врёт — говорит «всё в порядке,
делать нечего» на входе, который не тот.

Текст отказа и подсказка:

```
mpu d2-miro: в плане нет ни одного объекта: ни шейпов в <имя.svg>,
ни markdown-блоков в <имя.d2>; попробуй: тот же вызов без --skip-render
```

Подсказка — действием, и без флага она другая: `d2 <путь.d2>`. **Названы оба
файла**, потому что источники разные: шейпы приходят из SVG, markdown-блоки
— из `.d2`. Первая редакция винила один SVG, и оператор чинил бы не тот
файл.

Случай не выдуманный: пустой план даёт устаревший или чужой SVG рядом с
`.d2` (`--skip-render` берёт готовый файл). Замер 2026-08-31 до правки:

```
[info] stale.d2: 0 shapes, 0 edges, 0 markdown blocks; viewBox 100x80 -> frame 100x160
[info] created frame 3458764682219432075 at (11599, 0)
[done] frame='stale' shapes=0 connectors=0
код 0
```

На доске оставался пустой фрейм, а вызывающий получал успех — при том что
`--dry-run` на том же входе печатал `[dry-run] would create:` с пустым
списком, то есть план сам себя называл пустым и всё равно исполнялся.

После правки, замер того же дня: оба режима отказывают кодом 2, состав доски
до и после совпадает (62 элемента, пустых фреймов нет).

## Открытые вопросы

- Точная геометрия рендера (паддинги контейнеров, отступ подзадач

## Снято с живой службы 2026-08-31

Фикстуры — `fixtures/d2-miro/live/`, сняты на доске выше; отпечатки,

- **Координаты ребёнка — относительно фрейма, не холста.** Абсолютные

### `POST /frames` отвечает 500 примерно в половине попыток

Замер 2026-08-31, утро, 15 запросов подряд: девять `500` с телом
`{"type":"error","code":"3.0000","message":"Internal error occurred"}`,
объект при этом не создаётся. Не троттлинг: `x-ratelimit-remaining`
показывал 97 600 из 100 000. Не зависит ни от заголовка фрейма, ни от
позиции, ни от размера: та же форма проходит и падает в соседние минуты.
Проверялась и версия «дело в сетевом пути» — на одном замере прокси дал
`201` против `500` напрямую, но на трёх прогонах картина перевернулась
(прокси `500` трижды, напрямую `201`, `201`, `500`), то есть путь ни при
чём, а единичный замер здесь ничего не значит.

**Повтор лечит.** Из шести фреймов с четырьмя попытками и паузой
1-2-3 секунды создались пять; одному не хватило четырёх попыток.

**Это эпизод, а не постоянное свойство службы.** Тем же днём, несколькими
часами позже: восемь созданий подряд — восемь `201`, ноль `500`; пять живых
прогонов команды прошли без единого повтора. Значит требование повторять
`5xx` живой мутацией **не проверяется надёжно**: в здоровый час мутант
«повторять только 429» зелен, и зелен честно. Проверять её детерминированным
двойником — фейковая служба, отдающая `500×k → 201`, — а живой прогон
засчитывать как подтверждение работоспособности, не как проверку повтора.

Отсюда требование к переносу: повторять не только `429`, но и `5xx` — с
потолком попыток и **счётчиком в отчёте**. Оригинал повторяет
исключительно `429` (`py/src/mpu/lib/http_retry.py:36`), поэтому на такой
службе он падает посреди отрисовки — а частичный успех, по инварианту
этой же спеки, обязан называть числами. Это расхождение с оригиналом
осознанное, и оно улучшение, а не вкус.
