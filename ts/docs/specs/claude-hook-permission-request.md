# mpu claude-hook permission-request

Статус: черновик (серия R, порция R1; постановка —
`telegram-relay-statement.md`, сценарии `[S.n]`; вопросы в чате —
`platform/telegram-questions.md`)

## Назначение

Claude Code перед каждым вопросом человеку о праве — и перед каждым
AskUserQuestion — зовёт хук `PermissionRequest`, показывая при этом свой
терминальный диалог (снято 2026-10-06: диалог открыт, пока хук ждёт). Команда
задаёт тот же вопрос владельцу в Telegram и, если он ответил там первым,
отдаёт решение Claude Code. Ответили в терминале — команда снимает вопрос из
чата и выходит без решения.

## CLI-контракт

```
mpu claude-hook permission-request
```

- Аргументов и ключей нет; весь вход — stdin, payload хука.
- Исполняет строку ядро, а не исполнитель (как `claude-hook pre-tool-use`
  [D.1] той спеки): ожидание ответа держит вопрос ядра и не занимает
  исполнителя. Объявление отвергает `run` текстом «строку claude-hook
  permission-request исполняет ядро, не исполнитель». [D.1]
- Политика объявления — `rw` (сообщение уходит наружу); посев — `allow`
  отдельной строкой таблицы посева `platform/policy.md` (рядом с `task post`):
  хук запускается без человека, и `ask` означал бы «спросить некого» на каждом
  вызове [S25]. [D.2]
- Тулом MCP не публикуется: в `fixtures/mcp-server/tool-policies.json` её нет;
  тул `mpu` со словами `["claude-hook","permission-request"]` — stdin у MCP нет
  → `вход не разобран: stdin — не JSON-объект`, код 0 [S24].
- Код выхода всегда 0 — у всей команды вместе с клиентом: для строки ровно из
  слов `claude-hook permission-request` клиент ведёт себя как для
  `claude-hook pre-tool-use` (та спека, «Клиент»): отказ до сокета, обрыв,
  ненулевой код ядра → stdout пуст, stderr
  `mpu claude-hook permission-request: без решения — сервер mpu не отвечает:
  <причина>`, код 0. Список слов «строк-хуков» — один, в контракте кадров. [D.3]

### Справка [S23]

Однострока: `Как ответить на вопрос Claude Code о праве из Telegram?`. Первый
абзац: зовёт Claude Code хуком `PermissionRequest` (права и AskUserQuestion),
руками не зовут; терминальный диалог при этом открыт, решает первый ответ. Дальше
состав: вход, исходы (JSON решения в stdout / строка «без решения» в stderr),
код всегда 0, фрагмент настроек, пример `mpu claude-hook permission-request <
payload.json`. Голден справки снимает исполнитель, хост сверяет со списком.

## Ввод

Живые payload'ы — `fixtures/telegram-relay/hook/` (обезличены):
`live-permission-bash.json`, `live-permission-bash-dev-suggestion.json`
(подсказка `Read` `//dev/**`, `destination: session`),
`live-permission-ask-user-question-multi.json`. Голден
`live-permission-ask-user-question-single.json` снят хуком `PreToolUse` того
же вызова: поля те же, `hook_event_name` заменён — до досъёма пометка
«производный».

Разбор терпимый (незнакомое — игнорируется). Требования сверху вниз, первое
нарушенное — причина «без решения»:

| Поле | Требование | Нарушено → причина |
|---|---|---|
| весь stdin | JSON-объект | `вход не разобран: stdin — не JSON-объект` |
| `tool_name` | непустая строка | `вход не разобран: нет tool_name` |
| `tool_input` | объект | `вход не разобран: tool_input — не объект` |
| `tool_input.questions` (AskUserQuestion) | список 1–4 вопросов, у каждого `question` строка, `options` 2–4 с `label` | `вход не разобран: questions` |
| `transcript_path` | строка | `вход не разобран: нет transcript_path` |

`cwd`, `permission_suggestions`, `permission_mode`, `session_id` —
необязательны; не того типа — как отсутствие. Содержимое stdin не попадает в
журнал вызовов (как у прочих хуков).

## Payload → форма вопроса

Заголовок — `<значок> <имя>` + ` · <проект>` + ` · <окно>`, части без значения
опускаются вместе с разделителем (таблица постановки §4 «Заголовок»):

- право: значок `🔐`, имя — `tool_name`; MCP-тул `mcp__<сервер>__<тул>` —
  `<тул> (MCP)`; AskUserQuestion: значок `❓`, имя — `header`, нет — `Вопрос`;
- проект — базовое имя `cwd` без завершающих слэшей;
- окно — `<сессия>:<номер> <имя окна>` tmux, если клиент хука запущен под tmux
  (`TMUX_PANE` клиента; ядро спрашивает `tmux display-message -p -t <pane>
  '#S:#I #W'`). Нет переменной или tmux не ответил за 1 с — части нет. [D.4]

Право (`tool_name` ≠ `AskUserQuestion`) — один шаг:

- текст: `tool_input.description` (если строка), затем `tool_input.command`
  (Bash), иначе `tool_input` одной строкой JSON;
- варианты: `Yes`; по одному на каждую подсказку `permission_suggestions`
  (подписи — таблица постановки §4 «Подписи кнопок права»: правило —
  `Bash(<ruleContent>)`, без `ruleContent` — `<toolName>`, `addDirectories` —
  `dir <путь>`, неизвестный `type` — `<type>`; несколько правил — через `, `,
  префикс `Yes, always: `); `No` последним;
- вид — один вариант; свой текст — да (значит отказ с пояснением), строка
  исхода `❌ No: <текст> — из чата`; у варианта `No` значок исхода `❌`.

AskUserQuestion — шаг на каждый вопрос `questions[i]`: текст — `question`,
варианты — `options[].label` (описания — строками `• label — description`),
вид — `multiSelect`, свой текст — да.

## Ответ → решение

Ровно одна поверхность на исход, перевод строки в конце, JSON без пробелов,
порядок ключей как ниже (голдены — постановка §5):

| Исход вопроса | stdout |
|---|---|
| `Yes` | `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}` |
| подсказка k | то же + `"updatedPermissions":[<подсказка k как пришла>]` — Claude Code сам пишет правило (снято: `addRules` `localSettings` → `.claude/settings.local.json` корня git-репо `cwd`) [S3] |
| `No` | `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"deny"}}}` |
| текст на право | `deny` + `"message":"<текст>"` (снято: Claude получает текст дословно) [S5] |
| AskUserQuestion | `allow` + `"updatedInput":{"questions":<как пришли>,"answers":{"<question>":"<ответ>"}}`; несколько — подписи через `, ` (снято: `S, M`), свой текст — как есть [S9–S12] |

Без решения — stdout пуст, stderr одна строка
`mpu claude-hook permission-request: без решения — <причина>`:

| Причина | Когда |
|---|---|
| `решено в терминале` | вопрос снят (ниже) |
| `истёк срок ожидания` | срок ядра вышел |
| `бот не настроен` / `бот недоступен: …` | отказ показа (`telegram-questions.md`, «Ошибки») [S16, S27] |
| `сервер mpu не отвечает: …` | клиент (CLI-контракт) |
| `вход не разобран: …` | таблица «Ввод» [S26] |

## Решено в другом месте [S6, S14]

Claude Code не сообщает хуку, что на вопрос ответили в терминале (снято: хук
живёт до своего срока). Признак — транскрипт сессии `transcript_path`:

- до вопроса в нём уже есть запись `assistant` с `tool_use`, чьи `name` и
  `input` равны `tool_name` и `tool_input` payload'а (снято: `tool_use`
  пишется до вопроса); берётся последняя такая;
- появление записи `user` с `tool_result`, у которого `tool_use_id` равен `id`
  этого `tool_use` (разрешено — `is_error: false`, отказ — `true`) → вопрос
  снят текстом `решено в терминале` не позже чем через 2 с.
- Рост файла сам по себе не признак: соседний вызов того же хода, разрешённый
  правилом, дописывает свой `tool_result` во время ожидания (проба 7). [D.5]
- `tool_use` не найден или файл не читается — снятие по транскрипту не
  действует; вопрос решается чатом, сроком или обрывом.

## Срок

Срок ядра — 3540 с с прихода вопроса; срок хука во фрагменте — 3600 с: ядро
выходит раньше, чем Claude Code снимет хук, и правит сообщение в «истёк» само.
Оба числа выводятся из одной константы (срок хука − 60 с). Снятие хука Claude
Code раньше срока (обрыв строки) — исход «истёк» [S18]. [D.6]

## Фрагмент настроек и установка [S20–S22]

Голден — `fixtures/telegram-relay/settings-fragment.json`:

```json
{"hooks":{"PermissionRequest":[{"matcher":"",
  "hooks":[{"type":"command","command":"mpu claude-hook permission-request","timeout":3600}]}]}}
```

Ставит `install.sh` шагом после правил Claude Code (`platform/cutover.md`,
«Claude Code»), той же формой вывода:

| Состояние `~/.claude/settings.json` | Действие | Вывод |
|---|---|---|
| записи с этой командой нет | дописать запись фрагмента в конец `hooks.PermissionRequest` | `install: claude хук permission-request: вписано` |
| ровно одна запись, равная фрагменту | ничего; файл не переписан | `… : без изменений` |
| запись с этой командой отличается (`timeout`, `matcher`) или их несколько | заменить на одну запись фрагмента на месте первой | `… : вписано` |
| чужие записи `PermissionRequest`, прочие хуки, ключи | не трогаются, порядок сохранён | — |
| файл не JSON | файл не тронут | `install: claude хук permission-request: ошибка: <путь> не JSON`, код 1 |
| `claude` нет | шаг не выполняется | (строка `install: claude: не установлен` уже есть) |

Файл — ссылка: пишется то, на что она смотрит; запись атомарна (как у правил).

## Конфигурация

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_ID`, прокси — `telegram-questions.md`.
`TMUX_PANE` добавляется в закрытый список переменных клиента
(`platform/call-context.md`, «Какие переменные принимаются»): переменная
только подписывает вопрос и не меняет, куда идёт строка. [D.4]

## Права Deno

Ядру — `--allow-run=/usr/bin/tmux` (подпись окна). Тест, краснеющий без
права: smoke — `tmux -V` от имени собранного `mpu-back`. [D.7]

## Инварианты

- Код выхода 0 при любом исходе.
- На вопрос — не больше одного решения в stdout; после снятия решения нет.
- Сбой бота или ядра не задерживает и не решает терминальный диалог.
- Токен и содержимое stdin не появляются в выводе и журнале.

## Граничные случаи

- `permission_mode` `auto`/`plan`/`bypassPermissions` — Claude Code хук не
  зовёт; если позвал — обычная работа.
- Два вопроса одной сессии приходят по очереди (так задаёт Claude Code) —
  отдельными вопросами ряда [S15].
- `tool_input` больше предела сообщения — текст шага усечён
  (`telegram-questions.md`).

## Пункты чек-листа

Универсальный `design.md` (вместе с `platform/telegram-questions.md`):

1. Примитивы — изменил: у вопросов три примитива — задать форму (→ исход),
   снять, истечь; счётчик `ещё ждут`, выбор следующего, правка сообщения
   выводятся из ряда в одном месте. У хука два перевода: payload → форма,
   исход → решение.
2. Особые случаи → получатели — изменил: вид подсказки (`addRules`,
   `addDirectories`, неизвестный) подписывает себя сам; исход (ответ / снят /
   истёк) сам даёт строку сообщения и вывод хука; «бот без ключей» — объект,
   отвечающий отказом «бот не настроен» на любой вопрос, без опроса.
3. Проверки `null` — изменил: нет окна tmux, нет `tool_use` в транскрипте —
   объекты «без окна» и «без признака снятия», а не ветки по отсутствию.
4. Кто решает — изменил: ряд решает активный вопрос и N; вопрос — свой
   единственный исход; потребитель — тексты исхода и значок; ядро вопросов —
   правку сообщения; транскрипт-наблюдатель — снятие.
5. Память приватна — изменил: ряд не отдаёт список ожидающих наружу для
   решений; номер сообщения Telegram держит сам вопрос.
6. Голые данные → протокол — изменил: данные кнопки (метка запуска, номер,
   вариант) — объект с разбором и сборкой; payload хука — DTO границы.
7. Основание проверкой — изменил: «`tool_use` пишется до вопроса» → тест на
   голдене транскрипта; «соседний `tool_result` во время ожидания» → тест
   [D.5]; «у бота один читатель» → сценарий 409.

`design-mpu.md`:

1. Команда — сообщение: объявление `claude-hook permission-request` со
   справкой; исполнение ядром [D.1].
2. Вид метода — изменил: `rw` + посев `allow` строкой таблицы [D.2]; «исполняет
   ядро» — отказ `run`, не флаг.
3. Решение политики — ничего (посев у владельца книги правил).
4. Один источник — изменил: срок хука и срок ядра из одной константы [D.6];
   список строк-хуков клиента — один, в контракте кадров [D.3]; подписи — из
   формы.
5. Величина из результата — изменил: N в `ещё ждут` берётся из ряда в момент
   правки, не считается при показе.
6. Права Deno — изменил: `--allow-run=/usr/bin/tmux` ядру, smoke [D.7].
7. Границы модулей — изменил: вопросы в Telegram — модуль предметной области
   рядом с `telegram`, хук — рядом с `claude-hook`; поверхность — `mod.ts`.
8. Внешнее ссылкой — изменил: часы (срок), Bot API, tmux, файл транскрипта —

9. Голден снятый — изменил: payload'ы и Bot API сняты 2026-10-06; успех
   `answerCallbackQuery` и одиночный AskUserQuestion — помечены

10. Пропускаемая проверка — изменил: smoke `tmux -V` пропускается без tmux —
