# web: методы образа и синхронизация

Статус: черновик (переработка 2026-09-25, не принята хостом) — к реализации — порция 171 (после 170). Дополняет `web.md`.

## Назначение

Человек видит и правит методы образа (`platform/image.md`) в web так же, как
правила: дерево — вывод отражения от корня, метод — узел под получателем.
Экран «Образ» показывает, что изменит `image sync` (`image-sync.md`), сводит
базу с файлами и решает конфликты.

## Экран «Правила» — дополнение

| Что | Как |
|---|---|
| метод образа | узел под получателем с меткой «образ»; поля — из узла `tree.snapshot`: `summary`, `image: {author, time, source, definition}` |
| `image.definition` (новое поле снимка) | строка определения метода — та же, что строка файла метода (`image-sync.md`, «Файл метода») без перевода строки: `kiten define: cardsIn: purpose: ^мои в колонке^ keys: ^id колонки^ do :col kiten ls where: column is: @col done`; `keys:` — только при непустом описании |
| узел метода | путь, назначение (`summary`), автор, время, исходник (`source`, моноширинно), действующее решение и действия правила — как у команды |
| протокол корня | `tree.snapshot` отдаёт на верхнем уровне `protocol` — список методов протокола из модуля объектов (сценарий 12); блок «понимает любой объект» — один, у корня |
| правка определения | поле ввода заполнено ровно `image.definition`; «Сохранить» — строка `["ask", …слова поля]`; слова — деление по правилу «Текст → слова» (`image-sync.md`) |
| удаление | «Удалить метод» — строка `["ask", …слова получателя, "forget:", <последнее звено пути узла как есть>]` |
| ответ строки | как у правил (`web.md`): вопрос с номером → окно «Да / Нет»; итог без номера — сразу; вопрос задаёт или не задаёт `back` по правилу пути |
| отказ строки | текст `refusal.text` под полем; текст поля не сбрасывается |
| после итога строки (не вопроса) | перечитать `tree.snapshot` и `policy.tree` — при любом коде: `image sync` с кодом 1 тоже меняет базу (`image-sync.md`, «Инварианты») |

## Экран «Образ»

| Что | Как |
|---|---|
| адрес | `/image`, пункт навигации «Образ» рядом с «Правила» (`/`) |
| нет сессии / `back` недоступен | как на «Правилах» (`web.md`) |
| до первого действия | текст «Отчёта ещё нет» и кнопки «Проверить», «Синхронизировать» |
| «Проверить» | строка `["ask", "image", "sync", "dry"]` |
| «Синхронизировать» | строка `["ask", "image", "sync"]` |
| отчёт | `stdout` итога — строками как напечатаны: действие, метод (через табуляцию), последняя — итог `совпало N, изменено M, конфликтов K`; код 1 при строке `конфликт`/`сбой`/`файл не разобран` — отчёт, а не ошибка |
| строка `конфликт` | метод; исходник базы — `image.source` узла метода, если он в снимке; кнопки «взять базу» / «взять файлы» — строка `["ask", "image", "sync", "base:"\|"files:", <адрес>]` |
| адрес конфликта | из метода строки по таблице `image-sync.md`, «Адрес метода»: звенья получателя через `.`, имя без последнего `:` (`kiten cardsIn:` → `kiten.cardsIn`, `sheet sum:with:` → `sheet.sum:with`, `kiten ls column:` → `kiten.ls.column`, `kiten mine` → `kiten.mine`) |
| отказ | текст `refusal.text` под кнопкой; `refusal.hint` не `null` — кнопка «Выполнить: mpu <слова hint через пробел>», строка — `hint` как есть |

## Инварианты

- Фронт пишет в образ только строками `define:`, `forget:`, `image sync`; вопрос
  задаёт или не задаёт `back` по правилу пути; фронт своего вопроса не
  добавляет и не пропускает.
- Фронт не разбирает определение: текст для правки — один, `image.definition`;
  слова — деление по правилу «Текст → слова», как у файла метода и программы.
- Числа итога на экране — те, что напечатал прогон; фронт их не считает.
- После прогона `image sync`, изменившего базу, следующий `tree.snapshot`
  отражает базу (`image-sync.md`, «Запись стороны базы»: снимок дерева
  переписан; `удалён метод` — как `forget:`).

## Границы

- Экран «Образ» не показывает исходник файла у конфликта и строки `ждёт
  человека` суточного `image export`: прогоны не хранятся (`image-sync.md`,
  «Границы»), «Открытые вопросы».
- Фронт не читает файлы каталога образа и не выбирает `dir:` — только каталог
  по умолчанию (`image.dir`).

## Golden-примеры

- `fixtures/back-rpc/schema.json`: `treeNode` приводится к ответу
  `tree.snapshot` — `path`, `summary`, `tail`, `messages`, `keys`, `formats`,
  `variants`, необязательное `image: {author, time, source, definition}`;
  у `rpc.tree.snapshot` — поле `protocol` (элемент — как у `messages`). Тест
  сверяет ответ `tree.snapshot` живого `back` со схемой, а не только схему с
  копией в `testdata`.
- `fixtures/web/snapshot-image.json` — ответ `tree.snapshot` `back` на стенде
  сценария 1 (один метод `kiten cardsIn:`); из него пересобирается
  `ts/web/src/testdata/snapshot.json`.

Снимает исполнитель прогоном `back`, замораживает хост. Ответы строк в
сценариях — формы из кода; при реализации исполнитель сверяет их прогоном
`back` (`POST /line`, `/line/answer`) и прикладывает к отчёту.

## Известные отклонения

- Правило адреса метода (`image-sync.md`, «Адрес метода») исполняют двое:
  `back` при разборе `base:`/`files:` и фронт при сборке кнопки конфликта.
  Второй исполнитель держится тестом на таблице адресов («Пункты
  чек-листа», `design.md` 7г); один источник — «Открытые вопросы», 2.
- Адрес `kiten.mine` выбирает и `kiten mine`, и `kiten mine:` (`image-sync.md`,
  «Адрес метода»): кнопка у одного конфликта решает оба.
- Имя в `forget:` уходит как в пути узла (`cardsIn:`), поэтому отказ правила
  читается `cardsIn:: запрещено…` (сценарий 11) — форма кода.

## Открытые вопросы

К владельцу; порцию не блокируют — экран реализуется по сценариям:

1. Последний прогон не хранится (`image-sync.md`, «Границы»), `dry` идёт через
   `ask` (сц. 20–21 там же). Следствия для экрана: отчёт — только после
   «Проверить» с вопросом двери; исходник файла у конфликта не виден (в
   stdout его нет); строки `ждёт человека` суточного `image export` на экран
   не попадают. Варианты: хранить последний прогон с исходником файла у
   конфликта (169), `dry` без вопроса (169), или экран как есть.
2. Строка отчёта даёт метод (`kiten cardsIn:`), а ключ `base:`/`files:` ждёт
   адрес (`kiten.cardsIn`). Адрес в строке отчёта (или структурный вид
   отчёта) у `image sync` оставил бы правило одному исполнителю — правка 169.
3. У отказа массового удаления `image-sync.md` не называет объект `refusal`
   (`reason`, `hint`). Кнопке «Выполнить» нужен `hint` =
   `["ask","image","sync","deletes:","allow"]` (у `dry` — с `dry`) — правка
   169, «Предохранители». Без неё сценарий 20 — только текст отказа.
