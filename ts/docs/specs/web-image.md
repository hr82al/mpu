# web: методы образа и синхронизация

Статус: к реализации — порция 171 (после 170). Дополняет `web.md`.

## Назначение

Методы образа (`platform/image.md`) видны и правятся в web так же, как
правила: дерево — вывод отражения от корня, метод — узел под получателем.
Страница синхронизации показывает последний прогон `image sync`
(`image-sync.md`) и решает конфликты.

## Экран «Правила» — дополнение

| Что | Как |
|---|---|
| метод образа | узел под получателем с меткой «образ»; поля узла — из снимка `tree.json` (`image: {author, time, source}`) |
| узел метода | путь, назначение, автор, время, исходник (моноширинно), действующее решение и действия правила — как у команды |
| протокол корня | (`messages`, `understands:`, `keys`, `formats`, `variants`, `help`) показан один раз, на корне, не на каждом узле |
| правка исходника | поле ввода с текстом определения; «Сохранить» — строка `["ask", "<получатель>", "define:", …]` словами исходника через `POST /line` → окно подтверждения → перечитать дерево |
| удаление | «Удалить метод» — строка `["ask", "<получатель>", "forget:", "<имя>"]` → окно подтверждения |
| отказ строки | текст `refusal.text` под полем, исходник не сбрасывается |

## Экран «Образ»

| Что | Как |
|---|---|
| последний прогон | время, итог (`согласно N, изменено M, конфликтов K`), строки отчёта |
| конфликт | получатель, имя, исходник базы и файла рядом; «взять базу» / «взять файлы» — строка `["ask", "image", "sync", "prefer:", "db"|"files", "method:", …]` → окно подтверждения |
| «Синхронизировать» | строка `["ask", "image", "sync"]` → окно подтверждения; отказ массового удаления — текст и кнопка «Удалить всё равно» (`deletes: allow`) |
| прогона не было | «Синхронизации ещё не было» и кнопка |

Последний прогон хранит `back` (таблица в `image.db`) и отдаёт методом
`/rpc` `image.lastSync` (схема — `fixtures/back-rpc/schema.json`).

## Инварианты

- Фронт не пишет в образ ничем, кроме строк `define:`/`forget:`/`image sync`
  через окно подтверждения.
- Фронт не разбирает исходник: слова — деление по пробелам, как у программы
  (`platform/program-input.md`).

## Граничные случаи

| Дано | Ожидается |
|---|---|
| метод `kiten cardsIn:` в образе | узел под `kiten` с меткой «образ», исходник, автор |
| правка исходника, «Да» | дерево перечитано, новый исходник и время |
| правка исходника, «Нет» | образ не изменён |
| исходник без `purpose:` | под полем «метод без назначения: purpose: ^…^» |
| «Удалить метод», «Да» | узла нет |
| конфликт, «взять файлы», «Да» | конфликт исчез из отчёта, исходник базы — из файла |
| «Синхронизировать» при пустом каталоге и архиве | отказ массового удаления, кнопка «Удалить всё равно» |
