# mpu telegram send

Статус: реализовано

## Назначение

Отправить сообщение от имени личного аккаунта: текст, файлы или файлы с
подписью. Сеанс, конфигурация, прокси и приведение адресата — общие,
`platform/telegram-mtproto.md`.

## CLI-контракт

```
mpu telegram send MESSAGE [--chat X] [--md] [-f/--file PATH ...]
```

- `MESSAGE` — позиционный, обязателен. Значение `-` означает «весь stdin».
  Пустая строка допустима только вместе с `-f`.
- `--chat X` — адресат. Не задан → берётся `TELEGRAM_DEFAULT_CHAT`.
- `--md` — текст и подпись размечены Markdown: `[текст](url)` становится
  ссылкой, `**жирный**` — жирным. Без флага текст уходит как есть, и разметка
  остаётся видимыми символами.
- `-f/--file PATH` — вложение; флаг повторяем, порядок вложений равен порядку
  флагов.

`mpu telegram` без подкоманды печатает справку и завершается кодом 2 (общее
правило групп, `platform/registry.md`).

## Ввод/вывод

Файлы уходят **документами**, без превью, под своими именами. Несколько файлов
уходят одним альбомом. Непустой текст становится **подписью** к последнему
вложению — тому самому, чей номер печатается в stdout; пустой текст означает
отправку без подписи. Отдельного текстового
сообщения рядом с файлами не отправляется — ни до, ни после.

Без вложений отправляется обычное текстовое сообщение.

После отправки stdout получает **одну строку** — объект JSON без отступов,
юникод не экранируется, порядок ключей `id`, `chat_id`, `date`, за строкой один
перевод строки:

```
{"id": 5000001, "chat_id": 100000001, "date": "2026-08-16T08:04:09+00:00"}
```

Источники значений: `id` — номер отправленного сообщения (при альбоме —
последнего из них, того самого, что несёт подпись); `chat_id` — маркированный
идентификатор чата, в который сообщение легло, тот же вид, что печатает `ls`;
`date` — время отправки по данным Telegram, ISO-8601, либо `null`, если Telegram
времени не сообщил. Ключи присутствуют всегда.

stderr — только ошибки, по формату слоя.

## Побочные эффекты

Отправка необратима и видна получателю: сообщение уходит от имени личного
аккаунта пользователя. Единственный безопасный адресат для проверок — `me`,
«Избранное». Иных эффектов нет: PostgreSQL и кэш-БД не участвуют.

## Конфигурация

Своей нет; всё — из `platform/telegram-mtproto.md` (`TELEGRAM_API_ID`,
`TELEGRAM_API_HASH`, `TELEGRAM_SESSION`, `TELEGRAM_DEFAULT_CHAT`,
`TELEGRAM_PROXY`).

## Инварианты

- Ровно одна операция отправки на вызов: одно сообщение либо один альбом.
- Пустой текст без вложений — ошибка, а не отправка пустого сообщения.
- Порядок вложений в альбоме равен порядку флагов `-f`.
- `--md` действует одинаково на текст и на подпись; без флага разметка не
  интерпретируется нигде.
- Существование файлов проверяется до сети: при недоступном вложении соединение
  не открывается и ничего не отправляется.
- `chat_id` в выводе — целое число; подстановки вместо неизвестного значения
  не бывает (см. «Известные отклонения»).

## Граничные случаи и ошибки

- Адресат не задан ни флагом, ни env → exit 2 до сети: `telegram: адресат не
  задан; укажи --chat или TELEGRAM_DEFAULT_CHAT в .env`.
- Пустой текст без `-f` (в том числе `-` при пустом stdin) → exit 2 до сети:
  `telegram: пустой текст сообщения`. Пустым считается и текст из одних
  пробелов: подписью он быть не может, и понятие пустоты одно и то же в отказе
  и в подписи. Соответственно `send '   ' -f <файл>` — документ без подписи.
- `send '' -f <файл>` → документ без подписи, exit 0. Не ошибка.
- `-f` на несуществующий путь или на не-файл → отказ разбора аргументов, exit 2
  до сети, в выводе — текст `файл-вложение не найден: <путь>`.
- Адресат — строка, не сводимая к `me`, числовому id, имени пользователя,
  ссылке `t.me` или телефону → exit 1: `telegram: не удалось найти чат
  '<цель>': <причина>; попробуй: mpu telegram ls '<цель>' и укажи id или
  @username`.
- rate-limit → exit 1 `telegram: rate-limit, подожди <N>s`; прочий отказ
  протокола → exit 1 `telegram: RPC error: <текст>`.

## Golden-примеры

`fixtures/telegram-send/`, сняты с рабочей версии на собственном аккаунте,
отправка — только в «Избранное». Числа обезличены: номера сообщений →
`5000001`…`5000004`, идентификатор чата → `100000001`; время оставлено как
снято. Обезличивание — единственная правка голденов.

- `send-text-stdout.txt` — текст в «Избранное», строка JSON.
- `send-file-stdout.txt` — один документ с подписью.
- `send-album-stdout.txt` — два документа альбомом, подпись у последнего.
- `err-empty-text-stderr.txt` — пустой текст без вложений, exit 2.
- `err-file-missing-stderr.txt` — `-f` на несуществующий путь, exit 2. Голден
  **нормализован**: рабочая версия печатает многострочную рамку разбора флагов,
  воспроизводить которую спека запрещает (см. «Известные отклонения»), поэтому в
  голдене лежит одна строка требуемого вида. Хранить здесь рамку было бы
  ловушкой: реализация либо встала бы на противоречии, либо подогнала код под
  запрещённое поведение.

Каждый файл вывода оканчивается одним переводом строки.

## Известные отклонения

- **fix** — если Telegram не сообщил идентификатор чата, прежняя реализация
  молча печатает `"chat_id": 0`, то есть выдаёт за ответ значение, которого не
  получала. Правильно — не подставлять: значение либо настоящее, либо это отказ
  операции.
- **fix** — ошибки ввода (пустой текст, незаданный адресат) прежняя реализация
  завершает кодом 1; правильно — 2, тексты неизменны (слой).
- **fix** — подпись альбома прежняя реализация вешает на **первое** вложение, а
  в stdout печатает номер **последнего** (замер живым прогоном 2026-08-16:
  в альбоме подпись несёт первое сообщение, напечатан номер второго). То есть
  напечатанный номер указывает на сообщение без подписи. Правильно — подпись у
  последнего вложения, и печатается его же номер.
- **preserve** — отказ разбора аргументов (`-f` на несуществующий путь) выводится
  общим многострочным форматом ошибок парсинга флагов, без префикса `telegram:`.
  Причина — единый класс ошибок разбора у всего CLI. Контракт — факт отказа,
  код 2 и наличие ключевого текста; рамка побайтово не воспроизводится.
