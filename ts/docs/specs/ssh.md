# mpu ssh

Статус: к реализации (основная часть реализована 2026-08-17; открыты четыре
хвоста — тексты отказа `--via`, ambiguous в fan-out, `--json` у хвостового
входа, байтовый stdin)

## Назначение

Выполнить произвольную shell-команду внутри контейнера по селектору — на
sl-сервере (`mp-sl-N-cli`), на dev-ноде или в произвольном контейнере по
точному имени; либо fan-out по контейнерам кэша. Вывод стримится, код
выхода удалённой команды наследуется 1:1.

## CLI-контракт

`mpu ssh [SELECTOR] [--via ssh|portainer] [--all-containers SUBSTR]
[--stdin-text TEXT | --stdin-file PATH | --stdin-tty] [--] CMD...`

- Первый позиционный токен — селектор; все последующие позиционные и
  неопознанные токены образуют удалённую команду; `--` принудительно
  завершает разбор флагов. При `--all-containers` выделенного селектора
  нет — все позиционные токены составляют команду.
- Селектор (базовый резолв — `platform/selector.md`; расширения
  exec-команд оттуда же): `dev:<хвост>` (хвост `N` или `sl-N`, пробелы
  по краям хвоста игнорируются) — `mp-sl-N-cli` на dev-ноде; `sl-N`;
  точное имя контейнера из кэша; client_id / spreadsheet_id / title →
  единственный сервер.
- `--via` — override транспорта серверных таргетов
  (`platform/exec-transport.md`). С контейнером по имени `--via ssh` →
  exit 2, stderr: «mpu ssh: --via ssh не поддерживается для контейнера
  по имени; только для sl-N»; `--via portainer` там — no-op. Запрошенный
  транспорт не настроен → exit 2 текстом про **него**, а не общим отказом
  конфигурации: `mpu ssh: --via ssh: для sl-<N> не задан ssh-доступ (sl_<N> +
  PG_MY_USER_NAME)` и `mpu ssh: --via portainer: для sl-<N> не задан Portainer
  (sl_<N>_portainer + PORTAINER_API_KEY)`. Общий текст «не задано ни … ни …»
  остаётся за случаем без `--via`, когда выбирать действительно не из чего.
- Общий параметр формы вывода (`--json`) к команде не применяется: хвостовой
  вход забирает неопознанные токены, поэтому `--json` до `--` уходит удалённой
  командой (`platform/command-contract.md`). Следствие — код выхода команды
  формой вывода не подменяется никогда. До имени команды параметр снимается,
  как у всех: `mpu --json ssh sl-1 ls` → exit 2, stderr
  `mpu: --json не применяется к команде 'ssh'`. Селектором `--json` не
  становится — отказ про несуществующего клиента вместо внятного тут хуже
  всего (замер 2026-08-17: реализация отвечала `mpu ssh: nothing matched:
  '--json'`, оригинал — `No such option: --json`).
- `--all-containers SUBSTR` — fan-out: команда последовательно во всех
  контейнерах кэша, имя которых содержит SUBSTR; взаимоисключимо с
  селектором. stderr до запуска: `# mpu ssh: containers = [<имена через
  запятую+пробел>]`, перед каждым таргетом — `# container=<имя>`.
  Первый ненулевой код прерывает остальные и становится кодом выхода.
- stdin команды — взаимоисключимые явные источники; задано больше
  одного → exit 2, stderr: «mpu ssh: --stdin-text / --stdin-file /
  --stdin-tty взаимоисключающи». `--stdin-text` — строка (UTF-8);
  `--stdin-file` — байты файла (несуществующий/нечитаемый → ошибка
  ввода, exit 2); `--stdin-tty` — интерактивное чтение до EOF со
  stderr-подсказкой «mpu ssh: введите stdin для команды, завершите
  Ctrl+D». Без явного источника: stdin-пайп читается целиком;
  интерактивный терминал — пустой stdin (не блокироваться).
- Примеры (обезличенные): `mpu ssh sl-1 -- ls -la /app`; `mpu ssh sl-5
  "VAR=x node cli service:example run"`; `mpu ssh dev:1 -- ls /app`;
  `mpu ssh mp-dt-cli -- env`; `cat s.mjs | mpu ssh sl-11 -- node
  --input-type=module -`; `mpu ssh --all-containers wb-loader -- node -v`.

## Ввод/вывод

stdout/stderr удалённой команды — в stdout/stderr процесса по мере
поступления (Portainer-путь — одним потоком в stdout, см.
`platform/exec-transport.md`). Служебные строки (`# …`) и ошибки — в
stderr, формат ошибок `mpu ssh: <причина>[; подсказка]`. Коды выхода:
код удалённой команды как есть; 2 — ошибки ввода/резолва/конфигурации;
1 — ошибки транспорта.

## Побочные эффекты

Выполнение произвольной команды в живом (прод/dev) контейнере со всем
его окружением; временные файлы в `/tmp` контейнера — контракт
`platform/exec-transport.md`. Резолв селектора — чтение кэш-БД, записи
нет.

## Конфигурация

Всё — через `platform/exec-transport.md` (транспорт, ssh-ключ) и
`platform/env-file.md`; собственных ключей у команды нет.

## Инварианты

- Успех вызова = нулевой код удалённой команды; код никогда не
  подменяется.
- Селектор трактуется идентично `mpu run-js` (общий контракт резолва).
- За вызов применяется ровно один источник stdin.
- Fan-out последовательный; порядок — по имени контейнера (как в
  выборке из кэша); прерывание на первом сбое.
- Содержимое stdin не печатается в вывод mpu.

## Граничные случаи и ошибки

- Нет токенов команды → exit 2: «mpu ssh: пустая команда». Эта проверка
  **раньше** всех прочих: голый `mpu ssh` отказывает про команду, а не
  про селектор (замер 2026-08-17).
- Отдельного отказа «нет селектора» не существует, и заводить его не
  нужно: первый позиционный токен всегда становится селектором, поэтому
  состояние «команда есть, селектора нет» недостижимо — `mpu ssh -- echo
  x` уходит резолвить клиента по слову `echo` и отказывает его текстами
  (`platform/selector.md`, замер 2026-08-17).
- `--all-containers` без совпадений в кэше → exit 2: «mpu ssh:
  контейнеры с подстрокой '<SUBSTR>' не найдены; запусти `mpu init`».
- `dev:` с невалидным хвостом → exit 2: «mpu ssh: dev-селектор ожидает
  номер sl-сервера: `dev:N` (например dev:1), получено: '<значение>'».
- Неоднозначное имя контейнера **внутри fan-out** → тот же отказ ambiguous, что
  и для точного имени, exit 2; обход прерывается на этом контейнере (строка
  `# container=<имя>` для него уже напечатана). Молча брать первого кандидата
  нельзя: команда мутирующая, и «не тот сервер» здесь дороже прерванного обхода.
- Неоднозначное имя контейнера → exit 2: «mpu ssh: container '<имя>'
  ambiguous — <K> Portainer endpoints:» + строки-кандидаты
  `  endpoint=<имя>  id=<id>  url=<url>`; в клиент-поиск не проваливаемся
  (опечатка не должна маскироваться).
- Ошибка резолва клиент-селектора → exit 2, тексты и кандидаты —
  `platform/selector.md`.
- Удалённая команда вернула 2 → выход 2 (не отличим от ошибки ввода —
  следствие наследования кода, контракт).
- Ctrl+C → удалённый процесс убивается явно
  (`platform/exec-transport.md`).

## Golden-примеры

`fixtures/ssh/`. Все пять сняты живым прогоном рабочей версии
2026-08-17 на прод-ферме (безобидные команды и отказы ввода).

- `ok-echo-stdout.txt` — `ssh sl-0 -- echo mpu-golden-probe`, exit 0.
- `err-empty-cmd-stderr.txt` — вызов без команды, exit 2.
- `err-stdin-mutex-stderr.txt` — два источника stdin сразу, exit 2.
  Замер: mutex проверяется **после** селектора и команды, поэтому голден
  снят вызовом с селектором; без него первым отвечает «пустая команда».
- `err-all-containers-empty-stderr.txt` — `--all-containers` без
  совпадений в кэше, exit 2.
- `err-dev-selector-stderr.txt` — `dev:` с невалидным хвостом, exit 2.

Каждый файл оканчивается одним переводом строки. `sh -c 'exit 7'`
голдена не имеет: stdout пуст, наблюдаемое — код выхода (тот же случай,
что в `platform/exec-transport.md`).

## Известные отклонения

Транспортные — в `platform/exec-transport.md`; ниже собственные.

- **fix** — запрошенный `--via` без соответствующего доступа отказывает
  контролируемо и текстом про запрошенный транспорт. Оригинал доверял явному
  `--via` без проверки и обрывался необработанным исключением уже в глубине
  вызова, а общий текст «не задано ни sl_N ни sl_N_portainer» вводит в
  заблуждение ровно в том случае, когда второй транспорт как раз задан.
- **fix** — неоднозначное имя контейнера в fan-out отказывает так же, как для
  точного имени. Оригинал перехватывал ambiguous только на пути точного имени, а
  в обходе ронял необработанное исключение.
- **fix** — общий `--json` командой не распознаётся и уходит удалённой стороне.
  У оригинала этого параметра не было вовсе; после переезда общая форма вывода
  иначе съедала бы чужой флаг и обнуляла код выхода.
Отдельно — **расхождение реализации со спекой, не оригинала**: stdin из пайпа
читается текстом и перекодируется в UTF-8, поэтому двоичный вход портится
(`cat archive.gz | mpu ssh … -- gunzip`). Оригинал отдаёт байты, спека требует
байтов; устраняется байтовым чтением stdin в порту io
(`platform/command-contract.md`, «Ввод/вывод») — работа заказана следующей
порцией. Явный `--stdin-file` дефекту не подвержен: он читает файл байтами.
