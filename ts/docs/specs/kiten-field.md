Статус: к реализации (2026-08-14: CLI-поверхность, вывод и коды выхода сверены с

доменного имени и не открывается. Локальная история значений убрана переработкой
2026-08-06 — `set` пишет переданное значение напрямую, подкоманды `ls`/`update`/

## Назначение

Кастомные поля карточки Kaiten: скалярные (MR / гипотеза / что сделано /
результат) — подкоманда `set`; файловое поле «9. AI-артефакт» (md-вложение) —
подгруппа `artefact`. Тем же механизмом записи полей пользуется `mpu kiten close`
(`kiten-close.md`).

Внешняя граница — `platform/kaiten-api-cards.md`; транспорт, токен и формат
ошибок — `platform/kaiten-http.md`.

## CLI-контракт

`KIND` — закрытый список: `mr`, `hypothesis`, `done`, `result`; иное значение —
ошибка ввода CLI-слоя, exit 2, без сети. Соответствие kind → кастомное поле
инстанса Kaiten фиксировано:

| KIND | id поля | название |
| --- | --- | --- |
| mr | 398965 | «Ссылка на Merge Request» (тип url) |
| hypothesis | 291984 | «6. Причина/гипотеза» |
| done | 291985 | «7. Что сделано» |
| result | 291990 | «8. Результат» |
| (artefact) | 610303 | «9. AI-артефакт» (тип attachment) |

Ключ поля в теле запроса — `id_<id>`.

- `mpu kiten field set SELECTOR KIND VALUE` — установить поле карточки в `VALUE`.
  Значение записывается ровно то, что передано; прежнее заменяется без чтения и
  без слияния.
- `mpu kiten field artefact set SELECTOR PATH` — загрузить md-файл в поле
  «9. AI-артефакт» и привязать к нему. `PATH` обязан существовать и быть обычным
  читаемым файлом (иначе ошибка ввода CLI-слоя, exit 2); имя файла обязано
  оканчиваться на `.md` без учёта регистра, иначе exit 2: `артефакт должен быть
  .md-файлом, получен '<имя>'` — проверка по имени, не по содержимому.
- `mpu kiten field artefact rm SELECTOR` — удалить все файлы карточки,
  привязанные к полю (идемпотентно); файлы комментариев и файлы карточки вне поля
  не трогаются.
- `mpu kiten field` (и `mpu kiten field artefact`) без подкоманды — справка,
  exit 2.

Живые сценарии: `mpu kiten field set 12345678 mr
https://gitlab.example.com/team/repo/-/merge_requests/999`;
`mpu kiten field artefact set 12345678 razbor.md`.

## Ввод/вывод

Внешняя граница — `platform/kaiten-api-cards.md`: установка кастомного поля;
загрузка файла в attachment-поле; чтение карточки и удаление её файлов для
`artefact rm`. Удаление привязанного файла очищает значение поля на сервере,
отдельный запрос на очистку не отправляется.

stdout:

- `set`: `ok: {kind} → {значение} · {url карточки}`;
- `artefact set`: `ok: артефакт {имя} → {url карточки} (файл {url файла})` — имя и
  url файла из ответа сервера. Этот `url` **не открывается**: ответ загрузки
  отдаёт его без доменного имени файлового хоста — `https://files/<uuid>.<ext>`
  (замер 2026-08-14). Печатается как пришёл; достраивать его командой нечем,
  абсолютную ссылку несёт только карточка
  (`platform/kaiten-api-cards.md`, форма «Файл»);
- `artefact rm`: `ok: удалено из «AI-артефакт»: {имя1, имя2} · {url}`; поле уже
  пусто → `ok: поле «AI-артефакт» уже пусто · {url}`.

Источники значений в строках вывода: `{kind}` — как передан в аргументе;
`{значение}` — как передано, без нормализации; `{url карточки}` — строится как
`{базовый URL}/{id}`, не приходит из ответа; `{имя}` и `{url файла}` —
из ответа загрузки (вызов 13); список имён в `artefact rm` — имена удалённых
файлов из карточки, в порядке их следования в `files[]`, через `, `.

Каждая строка вывода оканчивается одним `\n`; пустых строк в выводе нет.

Exit: 0 — успех; 2 — ошибки ввода (KIND, селектор, PATH, не-md имя,
ненастроенный `KITEN_API_KEY`); 1 — ошибки внешней системы. Префикс всех
сообщений — полный путь команды: `mpu kiten field set: …`,
`mpu kiten field artefact set: …`, `mpu kiten field artefact rm: …`; у ошибок
внешней системы после префикса идёт `kaiten error: <текст>`.

## Побочные эффекты

Только вызовы внешнего API. Локального состояния нет: на диск команда не пишет
ничего, читает только файл, переданный в `artefact set`.

## Конфигурация

`KITEN_API_KEY`, `KITEN_BASE_URL` — `platform/kaiten-http.md`.

## Инварианты

- После успешного `set` поле карточки равно переданному `VALUE` — без чтения
  прежнего значения и без слияния с ним.
- Скалярные поля и артефактное поле независимы: `set` не трогает файлы,
  `artefact` не трогает скалярные поля.
- `artefact rm` идемпотентен и не трогает файлы вне поля 610303.
- Проверка расширения `.md` выполняется до сетевого вызова.

## Граничные случаи и ошибки

- `field set <id> badkind x` → exit 2, без сети.
- `artefact set x.MD` → проходит (регистр расширения не значим); markdown-файл с
  именем `x.txt` → exit 2.
- `artefact set` с путём, которого нет либо который не обычный файл → exit 2, без
  сети.
- `artefact rm` на карточке без файлов поля → `ok: поле «AI-артефакт» уже пусто`,
  exit 0.
- `artefact rm`: сбой удаления в середине списка → уже удалённые файлы не
  восстанавливаются, exit 1.
- Селектор без числового сегмента → exit 2 (`platform/kaiten-http.md`, «Селектор
  карточки»).

## Golden-примеры

Сняты живым прогоном на тестовой карточке Kaiten 2026-08-14 и обезличены;
лежат в `fixtures/kiten-field/`.

Успех: `ok-set-mr-stdout.txt` и `ok-set-hypothesis-stdout.txt` (`set` — url и
текст с двоеточием внутри значения), `ok-artefact-set-stdout.txt`,
`ok-artefact-set-upper-md-stdout.txt` (расширение `.MD` — проходит,
регистр не значим), `ok-artefact-rm-stdout.txt` (одно вложение),
`ok-artefact-rm-two-files-stdout.txt` (два — виден разделитель `, `),
`ok-artefact-rm-empty-stdout.txt` (идемпотентный успех на пустом поле).

Ошибки: `err-badkind-message.txt` и `err-not-md-message.txt` — тексты
сообщений ветвей exit 2; сети они не касаются (проверка расширения идёт до
загрузки), проверяются exit-код, пустой stdout и текст на stderr, а обрамление
рабочей версии — оформление её CLI-фреймворка, не контракт. Отдельного файла на
недоступную карточку нет: ответ общий для всех команд — 403 с пустым телом
(`platform/kaiten-api-cards.md`, «Граничные случаи»), голден лежит у `card`.

## Известные отклонения

- **fix** — `set` с пустым значением уходит на сервер как пустая строка и
  отказывает сырым 400 (`should NOT be shorter than 1 characters …
  should be null`; замер живым прогоном 2026-08-16). Правильное поведение:
  пустое значение — это очистка поля, и в теле уходит `null`
  (`platform/kaiten-api-cards.md`, вызов 8 — `value` строка либо `null`);
  успех печатается как `ok: {kind} → — · {url карточки}`.
- **fix** — прежняя реализация выводила значение поля косвенно, через последнюю
  запись локальной истории, из-за чего правка или удаление несвежей записи
  применяли к карточке не то значение, которое трогали. Правильное поведение:
  `set` устанавливает переданное значение, иных путей изменить поле у команды нет.
