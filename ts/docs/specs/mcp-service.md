# mpu mcp status | start | stop | restart | enable | disable

Статус: постановка (2026-09-09, порция 105). Спека пишется до кода
(`proc-ak-ts`, `checklists/design.md`); пометки `[D.n]` — принятые решения.

## Назначение

Держать MCP-сервер поднятым без занятого терминала. Сервер уже есть
(`platform/mcp-server.md`), но живёт ровно столько, сколько открыто окно, в
котором его запустили; клиент, обращающийся к нему в другое время, получает
отказ соединения и не отличает «сервер не поднят» от «сервер сломан».

Служба — служба менеджера пользователя (`systemd --user`), не общесистемная:
сервер слушает петлевой интерфейс и работает с реквизитами своего
пользователя.

## CLI-контракт

```
mpu mcp status     что со службой сейчас
mpu mcp enable     описать службу, запустить, включить в автозапуск
mpu mcp disable    остановить, снять с автозапуска, удалить описание
mpu mcp start      запустить уже описанную службу
mpu mcp stop       остановить
mpu mcp restart    остановить и запустить снова
```

Политика — `rw` у пяти меняющих, `ro` у `status` `[D.10]`. Это и есть
read-вариант семейства (`conv-mpu-readonly-split`, категория 1): в правах
Claude Code `mpu mcp status` идёт в `allow`, остальные пять — в `ask`.
Разделение держится именем подкоманды, а не флагом: слой прав видит только
строку вызова.

**`mpu mcp` без подкоманды не меняется ничем** `[D.8]`. Механизм для этого уже
работает: `mpu mcp token` — лист той же группы, у которой есть голое
исполнение (`bare` в `registry/mod.ts`), и новые подкоманды становятся такими
же листьями. Слово, не совпавшее с подкомандой, уходит в прежний разбор флагов
и даёт прежнюю ошибку ввода. Мутация, обязанная краснеть: подкоманда
перехватывает `mpu mcp --port 7400`.

## Ввод/вывод

**Описание службы** — файл `mpu-mcp.service` в каталоге служб пользователя
(`$XDG_CONFIG_HOME/systemd/user`, умолчание `$HOME/.config/systemd/user`)
`[D.1]`. Имя фиксировано: служба одна на пользователя, как и порт.

**Чем запускается** `[D.2]`: путь установки — `$HOME/.local/bin/mpu`, тот же,
который заменяет `build.md`. Не путь работающей программы: `Deno.execPath()` на
Linux уже разрешён ядром, и служба приколотилась бы к сегодняшнему файлу вместо
того, чтобы следовать за установкой. Путь установки — одна константа на две
спеки. Аргумент один — `mcp`: профили и порт
берутся из конфигурации (`platform/mcp-server.md`), и служба подхватывает их
перезапуском, а не переписыванием описания `[D.3]`.

**Состояние читается двумя источниками** `[D.4]`: существование службы — это
существование файла описания; запущена ли она и включён ли автозапуск —
`is-active` и `is-enabled` у менеджера. Одним источником не обойтись: файл
лежит и при остановленной службе, а `is-enabled` на несуществующем описании
отвечает неотличимо от «выключена».

**`enable`** — единственная, кто заводит и чинит `[D.5]`. Описание пишется
всегда и целиком: нет его вовсе, отстало (путь установки или аргумент
изменились), испорчено или написано не нами — итог один, описание нашего
сегодняшнего вида. Затем оно перечитывается менеджером, включается автозапуск
и служба поднимается; работающая — перезапускается.

`start`, `stop` и `restart` только переключают уже поставленное и на
отсутствие описания отказывают. `restart` — не пара «`stop`, затем `start`»,
а одно обращение к менеджеру: пара оставила бы службу лежащей, если второе
обращение не удалось. Иначе `disable` перестал бы что-либо значить: он описание
удаляет, и заводящий `start` воскрешал бы выключенную службу первым же
вызовом — «выключено насовсем» выразить стало бы нечем. Печатает адрес и профили. Заголовок авторизации
он **не** печатает `[D.9]`: `platform/mcp-server.md` держит правило «ни в каких
других поверхностях токен не печатается», и место для него уже есть —
`mpu mcp token`. Вместо секрета печатается имя этой команды.

**`disable`** останавливает, снимает автозапуск и удаляет описание `[D.6]`:
оставленный файл заставил бы `start` работать после `disable`.

**`status`** печатает всё, что знает о службе, и ничего не меняет `[D.10]`:
есть ли описание, работает ли служба, включён ли автозапуск, адрес и профили
из конфигурации, версию программы, которой служба запущена, и задержку
сеанса. Отсутствие службы — такой же ответ, как её наличие: `status` на
машине без службы печатает «не установлена» и завершается нулём. Версию
показывает та программа, что указана в описании, а не работающая копия: они
расходятся ровно между `mpu build` и перезапуском службы, и увидеть это
расхождение — половина смысла команды.

**Голое `mpu mcp` уступает порт службе и возвращает её** `[D.11]`. Служба
работает — команда останавливает её, поднимает сервер в переднем плане на том
же порту и по завершении запускает службу снова; обе строки печатаются, чтобы
владелец видел, что делается с его машиной. Службы нет или она остановлена —
не трогается ничего, и после выхода не запускается: заводить то, чего не
было, команда не должна.

Возврат службы обязан пережить обычный способ закончить работу — прерывание с
клавиатуры и сигнал завершения, — поэтому он не привязан к нормальному концу
процесса. Чего он пережить не может, названо прямо: снятие процесса без
права на обработку и обрыв самого сеанса. После такого служба остаётся
остановленной, `status` это показывает, `start` возвращает. Тем самым голое
`mpu mcp` перестаёт быть безобидным чтением и трогает состояние машины —
в правах Claude Code ему место рядом с меняющими, не в `allow`.

**Задержка сеанса** `[D.7]`: если сеанс пользователя не задержан (свойство
`Linger` у пользователя; `loginctl` без имени пользователя отвечает про
менеджера, а не про него, и имя приходится брать числовым идентификатором —
переменная `USER` у бинаря запрещена правом `--deny-env`), служба останавливается при выходе из системы.
`enable` печатает об этом строкой и не включает задержку сам — она требует
прав, которых у пользователя может не быть, а команда, тихо расширяющая свои
права, хуже команды, которая назвала нехватку.

## Побочные эффекты

Создаёт, изменяет и удаляет одно описание службы; запускает и останавливает
её. Ничего другого не трогает: конфигурация, токен (кроме первого создания),
порт и профили остаются как есть.

## Конфигурация

Своей нет; порт и профили — `platform/mcp-server.md`.

## Инварианты

- `mpu mcp` без подкоманды принимает те же флаги и печатает то же, что
  прежде; добавилось одно — оно уступает порт работающей службе и возвращает
  её после себя.
- Служба, которой не было до голого `mpu mcp`, не появляется после него.
- `status` не меняет ни описания, ни состояния службы, ни конфигурации.
- Повторный вызов любой подкоманды оставляет ту же наблюдаемую картину.
- Токен службы и токен переднего плана — один и тот же, и ни одна из шести
  подкоманд его не печатает, включая `status`.
- Служба слушает только петлевой интерфейс.
- После `disable` описания службы не существует.
- Ни одна подкоманда не включает задержку сеанса и не меняет конфигурацию.

## Публикация тулом

Ни одна из шести не публикуется: их нет в закрытом списке
(`src/mcp/tools.ts`, fail-closed), и вносить нельзя — агент, пришедший через
сервер, останавливал бы сервер, которым говорит.

## Права бинаря

`--allow-write` расширяется каталогом служб пользователя. `systemctl` и
`loginctl` порождает `--allow-run`, уже имеющийся.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu mcp <подкоманда>: `.

| Случай | Ответ | Код |
|---|---|---|
| `status`, описания нет | «служба не установлена» — это ответ | 0 |
| `status`, описание есть | состояние, адрес, версия, автозапуск | 0 |
| `start`, описания нет | «службы нет — поставь `mpu mcp enable`» | 1 |
| `restart`, описания нет | та же строка | 1 |
| `restart`, служба остановлена | запущена | 0 |
| голое `mpu mcp`, служба работает | остановлена, поднят передний план, по выходе возвращена | как раньше |
| голое `mpu mcp`, службы нет | не трогается ни до, ни после | как раньше |
| `stop`, описания нет | та же строка | 1 |
| `start`, служба работает | ничего не меняется | 0 |
| `stop`, служба остановлена | ничего не меняется | 0 |
| `disable`, описания нет | ничего не меняется | 0 |
| `enable` повторно | описание приведено, служба перезапущена | 0 |
| служба не поднялась (порт занят) | вывод менеджера и как смотреть журнал | 1 |
| менеджера служб пользователя нет | названа причина, ничего не создано | 1 |
| каталог служб недоступен на запись | назван путь | 1 |
| неизвестный флаг подкоманды | ошибка ввода | 2 |

## Пункты чек-листа

1. **Примитивы.** Шесть обращений к менеджеру: спросить состояние,
   перечитать, включить, запустить, остановить, перезапустить — плюс запись и удаление
   описания. `enable`, `disable` и `status` выводятся из них в одном месте, по
   разу; `status` — тот же снимок состояния, которым остальные решают, что
   делать, только напечатанный.
2. **Особые случаи → получатели.** Ветки «описания нет / есть, стоит /
   работает» — три состояния службы с одним протоколом (`описать`,
   `запустить`, `остановить`, `снять`), каждое отвечает по-своему: «нет»
   отказывает на `start`/`stop` и молчит на `disable`. `switch` по строке
   ответа менеджера допустим ровно на границе: там он данные транспорта.
3. **Проверка типа и `null`.** «Службы нет» — не `undefined`, а состояние,
   отвечающее на весь протокол, включая «расскажи о себе» для `status`; один
   экземпляр на модуль, своей памяти у него нет.
4. **Кто решает.** «Перезапускать или запускать» решает состояние службы, не
   `enable`. «Печатать ли предупреждение о сеансе» решает сеанс. Модульного
   состояния команды не заводят.
5. **Память приватна.** Путь описания и имя службы наружу не отдаются;
   `mpu build` спрашивает у службы «перезапустись, если работаешь», а не
   читает её состояние, чтобы решить самому.
6. **Голые данные → протокол.** Ответы `is-active`/`is-enabled` — строки
   транспорта; за границей живёт состояние службы, а не строка.
