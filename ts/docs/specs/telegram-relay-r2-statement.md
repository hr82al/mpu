# Ретранслятор Claude Code в Telegram — постановка порции R2

Статус: согласовано владельцем 2026-10-06; спеки — `claude-channel.md`, `claude-hook-stop.md`, `platform/telegram-questions.md` («R2»)

Серия R (общая постановка — `telegram-relay-statement.md`). R2 — «сессия
закончила ход и ждёт вас»: сообщение в чат и ответ текстом прямо в эту сессию.
Живые образцы — проба R2-1 2026-10-06 (`fixtures/telegram-relay/r2/`).

## 1. Кто и зачем

Владелец, у которого несколько сессий Claude Code, хочет узнавать в Telegram,
что сессия закончила ход и ждёт его, видеть её последнее сообщение и отвечать
ей текстом из чата, не переходя в окно.

## 2. Сценарии

Общие данные. Чат владельца — `111`. Сессия A — название `mpu-bot`,
`cwd=/home/user/mr/mp/ozon`, tmux `w:2 claude`, запущена командой `claude`
после установки (с каналом mpu). Сессия C — запущена без канала
(`command claude`, мимо алиаса).

Конец хода:

1. **Сессия закончила ход.** A отвечает «Какой цвет вы любите?» и
   останавливается. → В чат приходит:
   ```
   💬 mpu-bot — ozon · w:2 claude
   Какой цвет вы любите?
   ```
   с кнопками `Позже` · `Пропустить`. В терминале A ничего не меняется,
   сессия ждёт ввода как обычно.
2. **Ответ текстом.** Владелец пишет боту `Синий`. → В сессию A приходит
   сообщение канала с текстом `Синий`; A продолжает работу так же, как если бы
   текст набрали в терминале («Запомнил: ваш любимый цвет — синий»).
   Сообщение в чате — `… ✅ Синий — из чата`, кнопок нет.
3. **Ответ в терминале.** Вместо ответа в чате владелец набирает текст в
   терминале A. → Сообщение в чате — `… ✅ решено в терминале` не позже чем
   через 2 с после того, как ввод набран в терминале.
4. **Пропустить.** Жмёт `Пропустить`. → Сообщение — `… ⏭ пропущено`, кнопок
   нет; A по-прежнему ждёт ввода в терминале; повторно этот конец хода в чат не
   приходит.
5. **Позже.** Жмёт `Позже`, а других ожидающих нет. → Подсказка
   `больше ничего не ждёт`, сообщение остаётся активным.
6. **Длинное последнее сообщение.** Последнее сообщение A — 9000 символов. →
   В чате **конец** сообщения, обрезанный до предела Telegram, первой строкой
   тела — `…`; вопрос в конце ответа виден.
7. **Сессия без канала.** C закончила ход. → Приходит сообщение того же
   вида с последней строкой `ответ — в терминале (сессия без канала)` и
   кнопкой `Пропустить`; текст владельцу на него — `ответьте в терминале`.
8. **Продолжение хода.** Хук остановки сработал на продолжении, которое сам
   хук и вызвал (`stop_hook_active: true`). → В чат ничего не приходит.
9. **Сессия закрыта.** Владелец закрыл окно A, не ответив. → Сообщение —
   `… ⌛ сессия закрыта`, кнопок нет; ряд идёт дальше.

Очередь (решение владельца: срочные первыми):

10. **Срочный вопрос обгоняет.** Активно «ждёт ввода» A; сессия B спрашивает
    право. → Сообщение A правится: кнопки сняты, строка `ещё ждут`
    обновлена; вопрос B приходит **новым** сообщением и становится активным.
    После ответа на B сообщение A приходит снова новым сообщением с кнопками.
11. **Ждущий ввода — после срочных.** Ждут: право B (активно), затем
    закончили ход A и D. → После ответа на B активным становится A, затем D
    (по времени конца хода).
12. **Позже при других ожидающих.** Активно A, ждёт D. → `Позже`: A уходит в
    конец ряда «ждёт ввода», активным становится D (новым сообщением).
13. **Повторный конец хода.** A закончила ход, сообщение ещё ждёт; владелец
    ответил в терминале, A снова закончила ход. → Прежнее сообщение —
    `✅ решено в терминале`, новое — с новым последним сообщением.

Установка:

14. **Алиас.** `install.sh` в bash. → Вывод
    `install: claude канал: подключено`; в конфиге оболочки блок mpu
    задаёт `claude` с флагом канала mpu; `claude --version` из новой оболочки
    работает. Повторно — `… : без изменений`, байты файла те же. fish и nu —
    так же, если настроены; не настроены — `… : не настроена`.
15. **Сервер канала.** Первый запуск `claude` после установки показывает
    предупреждение о development-канале mpu — одно на запуск, сессия
    работает.
16. **Хук остановки.** `install.sh` вписывает хук `Stop` рядом с
    `PermissionRequest` теми же правилами идемпотентности (R1, сценарии 20–22).

AskUserQuestion (уточнение R1):

17. **Заголовок шага.** AskUserQuestion из двух вопросов с `header` `Цвет` и
    `Размер`. → На втором шаге заголовок `❓ Размер 2/2 — …`, а не `Цвет`.

## 3. Инварианты

- Текст владельца уходит ровно в ту сессию, чьё сообщение активно, и ровно
  один раз.
- Срочный вопрос (право, AskUserQuestion) никогда не ждёт за «ждёт ввода».
- Хук остановки не задерживает сессию: сообщение ставится, хук выходит сразу.
- Сессия без канала текста из чата не получает никогда.
- Токен бота не появляется ни в чате, ни в выводе, ни в журнале.

## 4. Правила

Заголовок «ждёт ввода» — как у R1 (`💬` вместо `🔐`/`❓`, имени нет):

| Сессия | Заголовок |
|---|---|
| `mpu-bot`, ozon, `w:2 claude` | `💬 mpu-bot — ozon · w:2 claude` |
| без названия, ozon, вне tmux | `💬 ozon` |
| ничего | `💬 сессия` |

Исход сообщения «ждёт ввода»:

| Что случилось | Последняя строка |
|---|---|
| текст из чата | `✅ <текст> — из чата` |
| в терминале набран ввод | `✅ решено в терминале` |
| `Пропустить` | `⏭ пропущено` |
| процесс сессии завершился | `⌛ сессия закрыта` |
| сервер mpu перезапущен | `⌛ истёк — ответьте в терминале` |

Порядок ряда:

| Ждут | Активно |
|---|---|
| право B | B |
| «ждёт» A, затем право B | B (A — с правкой, без кнопок) |
| «ждёт» A, «ждёт» D | A |
| «ждёт» A, «ждёт» D, `Позже` у A | D, затем A |
| право B, AskUserQuestion E | B, затем E (по времени) |

## 5. Вывод — примеры

Хук остановки: stdout всегда пуст, код 0; без постановки — stderr одна строка:

```
mpu claude-hook stop: без вопроса — продолжение хода
mpu claude-hook stop: без вопроса — бот не настроен
mpu claude-hook stop: без вопроса — сервер mpu не отвечает: <причина>
```

Сообщение канала в сессии (как его показывает Claude Code):

```
← mpu-channel · telegram: Синий
```

## 6. Границы

- Не пересылает в чат промежуточные сообщения хода — только конец хода.
- Не принимает из чата файлы и картинки — только текст.
- Субагенты (`SubagentStop`) в чат не идут.
- Сессии, запущенные мимо алиаса, получают уведомление без ответа (сценарий 7).
- Флаг канала в `launch.sh` изолированных сессий — вне mpu, правит хост.

## 7. Свойства решения

- Текст доставляется в сессию не позже 2 с после сообщения владельцу.
- Сообщение «ждёт ввода» не держит процессов: хук остановки выходит сразу.
- Установка идемпотентна.
