# mpu wt doctor

«Открытые вопросы»)

## Назначение

Диагноз worktree репозиториев рабочей области: `node_modules`, который симлинком (или ссылками
внутри) уводит из worktree в основной чекаут, и несколько копий React в одном дереве. Команда
только читает и **предлагает** починку текстом команд — сама ничего не удаляет и не ставит.

**Живые случаи.**

- 2026-09-01: в worktree `ozon` пакетные каталоги `node_modules` были симлинками в основной
  чекаут. Внутри них `@ozon/*` — относительные ссылки (`apps/datacore/node_modules/@ozon/contracts
  -> ../../../../packages/contracts`), путь считается от разыменованного каталога и уезжает в
  `packages/` основного чекаута: замер «до / после» собрал `apps/*` одной ветки против `packages/*`
  другой, молча. Проверка, которой это ловится: `readlink -f
  <worktree>/apps/datacore/node_modules/@ozon/contracts` обязан начинаться с каталога worktree.
- 2026-09-09: пересобранный ссылками каталог потерял `.bin` (глоб не берёт имена с точки) — пакетный
  скрипт не нашёл свой бинарь.
- 2026-09-10: в worktree `wt/ozon/checklist-k3`, `checklist-k4` и worktree `!558` корневой и часть
  пакетных `node_modules` оказались симлинками в основной чекаут; `pnpm install` в таком worktree
  переписал бы общее дерево. После частичной починки старые копии ссылались на React основного
  чекаута — две копии React, «Invalid hook call» в 20 спеках фронта. Лечилось переустановкой
  пакетных `node_modules` начисто.

Рабочая область и её репозитории — `platform/code-analyzer.md`, раздел «Ввод/вывод».

## CLI-контракт

`mpu wt doctor [REPO]... [--json]`

- `REPO` — имена репозиториев рабочей области; без аргументов — все, у которых есть worktree
  (`git worktree list` даёт больше одной записи).
- `--json` — вместо отчёта JSON-массив находок.

Политика — `ro`: только `readlink`/`realpath`, `git worktree list`, чтение `package.json`.

## Ввод/вывод

### Что проверяется в каждом worktree (кроме основного чекаута)

Каталоги-кандидаты: `node_modules` в корне worktree и в каждом каталоге первого-второго уровня,
где лежит `package.json` (`apps/*`, `packages/*`).

1. **`symlink-out`** — сам каталог `node_modules` — симлинк, и его цель (`realpath`) лежит вне
   worktree. Для корневого каталога это находка уровня `warn` (корень общий по рецепту и занимает
   сотни МБ — осознанный выбор), для пакетного — `error`.
2. **`workspace-link-out`** — внутри пакетного `node_modules` ссылка на пакет рабочего
   пространства (`@<scope>/*`, где scope — из `name` корневого `package.json` или любого
   `packages/*/package.json`) разрешается (`realpath`) вне worktree. `error`: сборка и тесты берут
   чужую ветку.
3. **`bin-missing`** — пакетный `node_modules` существует, но в нём нет `.bin`, а в одноимённом
   каталоге основного чекаута `.bin` есть. `warn`.
4. **`react-copies`** — `realpath` каталога `react` (`<dir>/node_modules/react`, с подъёмом к
   корню, как ищет Node) из каждого каталога с `package.json`, где `react` — зависимость; различных
   путей больше одного → `error`, с перечнем «каталог → путь React».

### Находка

`{ repo, worktree, check, severity, path, target, fix }` — `path` — проверенный путь, `target` —
его `realpath` (для `react-copies` — список), `fix` — текст предлагаемой починки (см. ниже).

### Предлагаемая починка (текст, не действие)

- `symlink-out`/`workspace-link-out` пакетного каталога → `rm <path>` и установка в самом worktree
  командой, которую репозиторий называет своей (для `ozon` — установка в dev-контейнере с
  `--config.@sw-back:registry=…`; текст берётся из открытого вопроса ниже, не выдумывается);
- `bin-missing` → пересобрать каталог вместе с `.bin`;
- `react-copies` → переустановить пакетные `node_modules` начисто в этом worktree.

### Отчёт (без `--json`)

По worktree: заголовок `<repo> · <путь worktree>`, под ним строки `✗ <check> <path> → <target>`
(error) или `! …` (warn) и строка `  починка: <fix>`. Чистый worktree — одна строка `✓ <путь>`.
Отчёт оканчивается итоговой строкой `worktree: N, ошибок: E, предупреждений: W` и переводом строки.

## Инварианты

- Команда не удаляет, не создаёт и не переписывает ни одного файла.
- Корневой `node_modules`-симлинк сам по себе — не ошибка (рецепт репозитория), ошибка — утечка
  пакетов рабочего пространства и копии React.

## Граничные случаи и ошибки

- Нет ни одного worktree → `(worktree нет)`, exit 0.
- Висячий симлинк (цель не существует) → находка `symlink-out` с `target: null`, `error`.
- Exit-код: 0 — ошибок нет (предупреждения допустимы), 1 — есть хоть одна `error`; так команду
  можно ставить воротами перед прогоном тестов.

  `react` («Invalid hook call»).
