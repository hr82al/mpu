# mpu kiten comment

Статус: черновик

## Назначение

Комментарий к карточке Kaiten от имени владельца токена: текст
(markdown), файлы-вложения, адресаты первой строкой; `@all`
разворачивается во владельца карточки. Обвязка —
`platform/kaiten-http.md`.

## CLI-контракт

`mpu kiten comment SELECTOR [-m/--message TEXT | -F/--body-file PATH]
[-f/--file PATH]... [--to HANDLES]...`

- Текст — из ровно одного источника: `-m TEXT` либо `-F PATH` (`-` —
  stdin). Оба сразу → exit 2: `нельзя одновременно -m/--message и
  -F/--body-file`. Ни одного и нет вложений/адресатов → exit 2:
  `нужно ровно одно из -m/--message и -F/--body-file`. С вложениями
  или адресатами текст необязателен (оба источника опущены → пустой
  текст). Обязательный текст из одних пробелов → exit 2:
  `пустой текст комментария`.
- `-f PATH` (повторяемый) — вложение: прикрепляется сам файл, не его
  содержимое. Путь обязан быть существующим обычным файлом, иначе
  exit 2: `файл-вложение не найден: {путь}`; ошибка чтения → exit 2:
  `не удалось прочитать вложение {путь}: <причина>`. Имя вложения в
  Kaiten — базовое имя файла, без каталога.
- `--to HANDLES` (повторяемый; значение делится по пробелам на
  токены) — адресаты. Токен без ведущего `@` получает его; дубликаты
  убираются без учёта регистра, порядок и регистр первого вхождения
  сохраняются. Строка адресатов (через пробел) ставится самой первой
  строкой комментария, затем пустая строка, затем текст; текст пуст →
  комментарий состоит из одной строки адресатов.
- `@all` (в `--to` или самостоятельным токеном в тексте:
  регистронезависимо, не часть слова или email) → `@{username
  владельца карточки}`. Владельца/username нет → предупреждение в
  stderr, литеральный `@all` остаётся (и в тексте, и среди адресатов),
  команда продолжается.

Живые сценарии: `mpu kiten comment 12345678 -m 'Готово, проверьте'`;
`mpu kiten comment 12345678 --to '@all' -F -`;
`mpu kiten comment 12345678 -f отчёт.xlsx -m 'файл во вложении'`.

## Ввод/вывод

HTTP-граница (формы — `platform/kaiten-http.md`):

- `GET /cards/{id}` — только когда нужен владелец: заданы адресаты
  либо в тексте есть токен `@all`; иначе карточка не читается;
- без вложений: `POST /cards/{id}/comments` body `{"text": <текст>}`;
- с вложениями: один `POST /cards/{id}/comments` multipart — поле
  `text` плюс по одной файловой части `files[]` на вложение; Kaiten
  создаёт один комментарий и привязывает файлы к нему.

stdout успеха:

    ok: комментарий {id} → {url карточки}
       вложения: {имя1, имя2}          ← если были вложения
       адресаты: {@a @b}               ← если кто-то реально упомянут

`адресаты` — реально упомянутые логины (литеральный `@all` не входит),
без дублей.

Exit: 0 — успех (в том числе с предупреждением про владельца); 2 —
ошибки ввода; 1 — ошибки API
(`mpu kiten comment: kaiten error: <текст>`).

## Побочные эффекты

Один POST в Kaiten (комментарий, при вложениях — вместе с файлами);
GET карточки — только при необходимости владельца. Локальных записей
нет.

## Конфигурация

`KITEN_API_KEY`, `KITEN_BASE_URL` — `platform/kaiten-http.md`. Других
нет.

## Инварианты

- Текст и вложения уходят одним запросом — один комментарий, частичной
  публикации не бывает.
- `@all` — клиентская текстовая подстановка; сервер получает обычный
  текст, токена `@all` как механизма в запросе нет.
- Без адресатов и без `@all` в тексте карточка не читается — ровно
  один HTTP-запрос.
- Валидация текста и вложений — до первого сетевого запроса.
- Отсутствие владельца не превращается в ошибку.

## Граничные случаи и ошибки

- `-f <каталог>` → exit 2: `файл-вложение не найден: {путь}`.
- `-F <нечитаемый путь>` → exit 2:
  `не удалось прочитать {путь}: <причина>`.
- Только `-f`/`--to`, без `-m`/`-F` → комментарий без текста, exit 0.
- `--to '@all'`, владельца нет → stderr `mpu kiten comment: у карточки
  нет владельца с username — оставляю '@all' как есть`; `@all`
  остаётся первой строкой; строки `адресаты:` в выводе нет; exit 0.
- `--to 'ivan @Ivan'` → один адресат `@ivan` (дедуп без учёта
  регистра, первое вхождение побеждает).
- Невалидный селектор → exit 2 (`platform/kaiten-http.md`,
  «Селектор карточки»).
- Ошибка API → exit 1, локальных следов нет.

## Golden-примеры

Снять при переводе в «к реализации» (тестовая карточка):
`comment <id> -m 'текст'` (happy path), `comment <id> -f a.txt`
(только вложение), `comment <id> --to '@all @ivan' -m 'текст @all'`
(адресаты + раскрытие), `comment <id>` (exit 2, нет источника текста),
`comment <id> -m x -F y` (exit 2).
