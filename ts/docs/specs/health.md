# mpu health

Статус: черновик

## Назначение

Быстрый health-check сервера: живой список `mp-*` контейнеров с
состояниями + tail stderr-логов контейнеров-«виновников»
(лоадер-подобных демонов). Штатно завершившиеся one-shot контейнеры
проблемой не считаются. Exit 1 при любом неожиданно не-running
контейнере.

## CLI-контракт

`mpu health SELECTOR [-n/--tail N] [--since S] [--all]`

- SELECTOR обязателен: `sl-N` либо клиент-селектор (как у `mpu ps`);
  без аргумента — справка, exit 2.
- `--tail/-n` — строк лога на контейнер, дефолт 30.
- `--since` — окно логов: `<число><s|m|h|d>` (отсчёт назад от текущего
  момента) либо строка из одних цифр = буквальный unix-ts; иной формат →
  exit 2. Без флага — весь доступный лог (`--tail` всё равно
  ограничивает объём).
- `--all` — tail для всех демонов `mp-*`, не только лоадер-подобных.

## Ввод/вывод

Источник — живой список контейнеров endpoint'а сервера
(`platform/exec-transport.md`, тот же запрос, что у `mpu ps`).
Обработка и вывод (stdout, в этом порядке):

1. Строки без имени отбрасываются; сортировка по имени; `mp`-строки =
   имя начинается с `mp-sl-` или `mp-wb-`.
2. Заголовок `=== sl-<N>: <K> mp-* containers ===`, пустая строка,
   таблица `NAME  STATE  STATUS` (колонки по ширине содержимого, два
   пробела) по `mp`-строкам; при нуле `mp`-строк — по всем контейнерам
   (см. «Известные отклонения»).
3. One-shot completed: имя содержит (без учёта регистра) `migrations`
   или `init-`, И `state` = `exited`, И `status` начинается с
   `Exited (0)` → блок `✓ One-shot containers (completed normally):` со
   строками `  <имя>: <status>`. На код выхода не влияют.
4. Остальные не-running `mp`-строки → блок `⚠️  Containers not in
   'running' state:` со строками `  <имя>: state=<state>
   status=<status>`.
5. Tail-блок: демоны = `mp`-строки, чьё имя не содержит one-shot
   ключевых слов (независимо от состояния); таргеты = демоны с одной из
   подстрок имени (без учёта регистра) `loader`, `data-processor`,
   `ss-updater`, `ss-loader`, `ss-jobs`, `nats-listeners`, `workers`,
   `instance-app`, `main-app`; с `--all` — все демоны. Если таргеты
   есть: заголовок `=== tail --<N> (stderr) for <K> container(s) ===`,
   затем на каждый контейнер `--- <имя> (stderr, tail=<N>) ---` и
   stderr-байты его лога как есть. Запрос лога —
   `platform/exec-transport.md`: `stdout=false`, `stderr=true`,
   `timestamps=true`, `follow=false`, `tail=<N>`, `since=<ts>` (если
   задан). Пустой stderr в окне → `  (no stderr in window)`. Ошибка
   HTTP по одному контейнеру → `  (logs error: <детали>)`, переход к
   следующему; на код выхода не влияет.

Коды выхода: 1 ⇔ блок п. 4 непуст (есть неожиданно не-running) либо не
получен сам список контейнеров; иначе 0 (сбои получения логов код не
меняют); 2 — ошибки ввода/резолва/конфигурации.

## Побочные эффекты

Только чтение: список контейнеров и логи по HTTP. Записи и мутаций
контейнеров нет.

## Конфигурация

Portainer-доступ — `platform/exec-transport.md`; собственных ключей у
команды нет.

## Инварианты

- Read-only при каждом вызове.
- One-shot контейнер со статусом `Exited (0)` никогда не даёт exit 1;
  любой другой не-running `mp`-контейнер — всегда даёт.
- В tail печатается только stderr-поток логов; stdout не выводится.
- `--tail`/`--since`/`--all` влияют только на лог-блоки — не на таблицу
  состояний и не на код выхода.
- `--since` валидируется до сетевых обращений (см. «Известные
  отклонения»).

## Граничные случаи и ошибки

- HTTP-ошибка получения списка → stderr «mpu health: portainer error:
  <детали>», exit 1.
- Невалидный `--since` → stderr «mpu health: --since: ожидается
  <число>{s|m|h|d} или unix-ts, получено '<значение>'», exit 2.
- `--since 90` — буквальный unix-ts 90, не «90 секунд назад».
- One-shot контейнер со статусом `Exited (1)` → блок ⚠️, exit 1.
- Контейнер в `restarting` / `created` → блок ⚠️, exit 1.
- TTY-контейнер (логи без Docker-фрейминга,
  `platform/exec-transport.md`) → весь лог считается stdout → в
  tail-блоке `  (no stderr in window)`.
- Нет лоадер-подобных демонов и нет `--all` → tail-блок отсутствует
  целиком, включая заголовок.
- Ошибки резолва/конфигурации Portainer → exit 2, тексты — как у
  `mpu ps`.

## Golden-примеры

Снять при переводе в «к реализации»: `mpu health sl-0` (форма блоков,
код выхода); `mpu health sl-0 --since xx` (ошибка формата, exit 2);
`mpu health --help`. Фикстура ответа containers/json с running-,
one-shot- (`Exited (0)` и `Exited (1)`) и не-running-строками — для
контрактного теста классификации и кода выхода.

## Известные отклонения

- **preserve** — при нуле `mp`-строк таблица состояний печатает все
  контейнеры endpoint'а, хотя заголовок сообщает `0 mp-* containers`.
  Причина: диагностическая команда — показать содержимое endpoint'а
  полезнее пустой таблицы.
- **fix** — в оригинале `--since` валидируется только при непустом
  списке tail-таргетов и уже после сетевых обращений: без таргетов
  невалидное значение молча проходит. Правильно — валидация при каждом
  вызове до похода в сеть.
- **preserve** — tail только stderr: демон, пишущий ошибки в stdout, в
  tail-блоке не виден. Причина: сервисы стека пишут ошибки в stderr;
  включение stdout утопило бы диагностику в рабочем шуме.
