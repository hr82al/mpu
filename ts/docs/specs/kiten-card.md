# mpu kiten card

Статус: к реализации (2026-08-14: вывод всех трёх видов сверен с рабочей
версией, голдены `--json` и `--md` сняты на синтетической карточке;
уточнено, что `properties` — всегда объект)

## Назначение

Прочитать одну карточку Kaiten целиком — шапка, свойства, описание,
файлы, комментарии — в одном из трёх видов: наглядный терминальный,
чистый GFM-markdown для LLM, сырой JSON. Только чтение.

## CLI-контракт

`mpu kiten card SELECTOR [--md] [--json] [--images/--no-images]
[--comments/--no-comments]`

- `SELECTOR` — ID карточки или её URL (короткий/глубокий); разбор — по
  `platform/kaiten-http.md` («Селектор карточки»).
- `--md` — чистый GFM markdown (без ANSI-оформления и картинок).
- `--json` — сырой JSON (карточка + комментарии).
- `--images/--no-images` (дефолт `--images`) — инлайн-картинки в
  наглядном режиме; на `--md`/`--json` не влияет.
- `--comments/--no-comments` (дефолт `--comments`) — включать
  комментарии; `--no-comments` отключает и сам запрос комментариев.

Выбор вида, по убыванию приоритета: `--json` → `--md` ЛИБО stdout не
терминал → наглядный терминальный рендер. Пайп без флагов отдаёт
markdown: `mpu kiten card 123 | <потребитель>` — чистый GFM.

Примеры из практики (обезличены):

    mpu kiten card 65634936 --json
    mpu kiten card https://btlz.kaiten.ru/65634936 --md
    mpu kiten card 65634936 --no-comments

## Ввод/вывод

Внешняя граница — `platform/kaiten-api-cards.md` (карточка, комментарии)
и `platform/kaiten-api-refs.md` (кастомные поля компании). Комментарии
запрашиваются только при включённом `--comments`. Имена кастомных полей
для markdown/наглядного вида — один живой запрос справочника полей
компании, best-effort: сбой → в выводе сырые ключи, команда не падает.
На `--json` имена не нужны — этот запрос не выполняется (см. «Известные
отклонения»).

Метка этапа (`state`) во всех видах: 1 → `queued`, 2 → `in progress`,
3 → `done`; иное число → само число строкой; значения нет → пустая
строка.

`--json` — объект (отступ 2, юникод как есть):
`id` (число), `key`, `title`, `state` (метка), `condition` (число:
1 активная, 2 архив), `due_date`, `board`, `column`, `lane` (названия),
`size_text`, `created`, `updated`, `type`, `tags` (массив строк),
`url`, `owner` (объект `{id, full_name, email, username}` либо null),
`members` (массив таких же объектов), `properties` (объект
`ключ "id_NNN" → значение` — ключи сырые, без резолва имён; всегда
объект, полей нет → `{}`, никогда не null; поле с null-значением из
ответа API в объект не попадает),
`description`, `files` (массив
`{id, name, url, mime_type, comment_id, card_cover}`), `comments`
(массив `{id, author, created, text}`). Отсутствующее строковое
значение — null.

Markdown (`--md` / пайп):

- `# {title}`;
- строки `- **Key**: …`, `- **URL**: …`, `- **Этап**: {метка}`,
  `- **Доска**: {доска · колонка · дорожка}` (непустые через ` · `),
  `- **Владелец**: …`, `- **Участники**: …` (через запятую),
  `- **Дедлайн**: {YYYY-MM-DD}`, `- **Теги**: …` — каждая строка
  печатается только при непустом значении; `URL` и `Этап` — всегда;
- `## Свойства` (если есть): `- {имя поля}: {значение}`; имя — по
  справочнику кастомных полей (`id_NNN` → имя), не резолвится → сырой
  ключ;
- `## Описание` — всегда; пустое описание → `_нет описания_`;
- `## Файлы` (если есть): `- [{имя, иначе url}]({url})`;
- `## Комментарии` (если есть): на каждый —
  `### {автор} · {YYYY-MM-DD HH:MM}` (автора нет → `—`; даты нет —
  только автор), пустая строка, текст комментария дословно (GFM,
  включая `![](url)`);
- вывод завершается ровно одним `\n`.

Наглядный режим (stdout — терминал): та же информация — шапка,
свойства, описание, комментарии, вложения-картинки; терминальное
оформление и способ отрисовки картинок — свобода реализации.
`--images` управляет только загрузкой и отрисовкой картинок.

Exit: 0 — успех; 2 — ошибки ввода (селектор); 1 — ошибки API.

## Побочные эффекты

Только чтение внешней системы. Локального состояния нет: на диск
команда не пишет ничего. В наглядном режиме с `--images` —
дополнительные HTTP-запросы за байтами картинок по их `url`; это
загрузка файлов с файлового хоста Kaiten, а не вызовы API, и в каталоге
внешней границы она не значится.

## Конфигурация

`KITEN_API_KEY`, `KITEN_BASE_URL` — по `platform/kaiten-http.md`.

## Инварианты

- Kaiten не мутируется ни при каких флагах.
- `--json`-вывод не зависит от справочника кастомных полей (ключи
  `properties` сырые) и от `--images`.
- `--no-comments` → запрос комментариев не выполняется, в JSON
  `comments: []`, раздела `## Комментарии` нет.
- Ключ JSON присутствует всегда; отсутствие значения — null (не
  пропуск ключа).

## Граничные случаи и ошибки

- Невалидный селектор (нет числового сегмента) → exit 2,
  `не удалось извлечь id карточки из '<строка>'`.
- Несуществующая/недоступная карточка → exit 1, stderr
  `mpu kiten card: kaiten error: kaiten GET /cards/{id} -> 404: <тело>`.
- Карточка без описания → JSON `description: null`, markdown
  `_нет описания_`.
- Комментариев нет → JSON `comments: []`, раздела `## Комментарии` нет.
- Справочник кастомных полей не отвечает → markdown печатает сырые
  ключи `id_NNN`, команда не падает.

## Golden-примеры

Вход — синтетическая карточка: `fixtures/kiten-card/card-detail.json`
(ответ полной карточки) и `fixtures/kiten-card/comments.json` (ответ
комментариев). Карточка нарочно несёт все ветви вывода: непустые теги,
участники, дедлайн, три файла (уровня карточки, комментария и поля),
свойство с именем из справочника и свойство `id_999999`, которого в
справочнике нет.

Выводы сняты с рабочей версии на этом входе:

- `card-json.json` — `--json`; справочник имён при этом не запрашивается;
- `card-md.md` — `--md` при справочнике
  `{398965: «Ссылка на Merge Request», 291984: «6. Причина/гипотеза»}`;
  нерезолвленное свойство печатается сырым ключом;
- `card-md-no-comments.md` — то же с `--no-comments`: раздела
  `## Комментарии` нет.

Ошибочные ветви голден-файлами не покрываются: `card abc` (селектор,
exit 2) и 404 (exit 1) закреплены точными текстами в разделе «Граничные
случаи и ошибки», а рамка, в которую рабочая версия их заворачивает, —
оформление её CLI-фреймворка, не контракт. Проверяемое здесь: exit-код,
пустой stdout и текст на stderr.
