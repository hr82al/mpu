# mpu kiten close

Статус: черновик

## Назначение

Оркестратор закрытия карточки Kaiten одним вызовом: остановить таймер
(по флагу), заполнить пустые обязательные поля, запостить ответ
клиенту, перенести карточку в «Готово». Детерминированный: тексты
готовит вызывающий и передаёт аргументами; порядок шагов фиксирован —
таймер → поля → ответ → перенос.

Составные части — по соседним спекам: остановка таймера —
`kiten-time.md` («stop»), запись полей — `kiten-field.md`, перенос с
релогом и журналом — `kiten-move.md`; обвязка —
`platform/kaiten-http.md`.

## CLI-контракт

`mpu kiten close SELECTOR [--hypothesis TEXT] [--done TEXT]
[--result TEXT] [--mr URL] [--reply TEXT | --reply-file PATH]
[--column REF] [--force-fields] [--no-move] [--stop-timer] [--dry-run]`

- `--hypothesis`/`--done`/`--result`/`--mr` — значения четырёх
  скалярных полей (`kiten-field.md`). Пишутся только переданные и
  только если поле на карточке пусто (значения нет или одни пробелы);
  непустые пропускаются; `--force-fields` перезаписывает. Порядок
  обработки и вывода фиксирован: hypothesis, done, result, mr.
- Ответ — из ровно одного источника: `--reply TEXT` либо
  `--reply-file PATH` (`-` — stdin). Оба сразу → exit 2:
  `--reply и --reply-file взаимоисключающи`. Пустой/пробельный текст →
  exit 2: `пустой текст ответа`. Самостоятельный токен `@all` в тексте
  (регистронезависимо, не часть слова или email) разворачивается в
  `@{username владельца карточки}`; владельца/username нет —
  предупреждение в stderr, литеральный `@all` остаётся, команда
  продолжается.
- `--column REF` — колонка переноса (ID или имя); по умолчанию env
  `KITEN_READY_COLUMN`, иначе «Готово». `--no-move` — не переносить.
- `--stop-timer` — остановить запущенный таймер и записать время по
  контракту `kiten-time.md` («stop» без `--time` и `-m`). Без флага
  таймер не трогается никогда: запись учёта времени не создаётся
  побочным эффектом закрытия; о запущенном таймере — громкое
  предупреждение.
- `--dry-run` — печать плана; выполняются только GET-чтения.

Живой сценарий: `mpu kiten close 12345678 --hypothesis '…' --done '…'
--result '…' --reply-file - --stop-timer`.

## Ввод/вывод

Валидация ответа (взаимоисключение, пустота, чтение файла) — до
первого сетевого запроса. Затем `GET /cards/{id}` — карточка «до»: из
неё берутся текущие значения полей, владелец и таймер.

`--dry-run` (stdout, в этом порядке):

    dry-run close · {url карточки}
      таймер: {строка таймера}
      поля: записать [{kinds | —}]{; пропущены (заполнены) [{kinds}]}
      ответ: {запостить[ (@all → @{username})] | без ответа}
      перенос: пропущен (--no-move)        ← только при --no-move

и, без `--no-move`, — dry-run-строка переноса из `kiten-move.md`
(выполняет свой GET карточки и резолв цели). Строка таймера: таймера
нет → `не запущен`; `--stop-timer` → `остановить (запущен с
{ДД.ММ ЧЧ:ММ МСК}, {длительность})`; таймер идёт без флага — тело
предупреждения (ниже). Мутаций нет ни одной.

Применение (без `--dry-run`), stdout по шагам:

    ok close: поля [{kinds | —}]{; пропущены (заполнены) [{kinds}]}
       таймер: {длительность} · {роль} · запись {id}   ← если остановлен
       ответ: комментарий {id}{ (@all → @{username})}  ← если постился
    ok: {до} → {после}{ (релог)} · {url}               ← строка переноса

Строка таймера — по перечитанной с сервера записи (`kiten-time.md`),
непустые части через ` · `.

stderr-предупреждения (команда продолжается, exit 0):

- `mpu kiten close: у карточки нет владельца — '@all' оставлен как
  есть` — в тексте ответа был `@all`, раскрыть некому;
- при применении, если таймер идёт и `--stop-timer` не задан:
  `внимание: на карточке запущен таймер (с {ДД.ММ ЧЧ:ММ МСК},
  {длительность}); он НЕ остановлен — `mpu kiten time stop {id}` (или
  --stop-timer)`; момента старта у таймера нет → `с ?` без
  длительности.

Ошибки API — exit 1, stderr с маркером упавшего шага:
`mpu kiten close: kaiten error (таймер): <текст>` / `(поля)` /
`(ответ)`; ошибка стартового GET — без маркера; ошибки шага
переноса — по `kiten-move.md`.

Exit: 0 — успех; 2 — ошибки ввода (селектор, ответ, нерезолвящийся
`--column`); 1 — ошибки API.

## Побочные эффекты

По шагам: остановка таймера — PATCH таймера + локальная подсказка
(`kiten-time.md`); каждая записываемая пара поле+значение — запись в
журнал полей и PATCH поля, как `field set` (`kiten-field.md`); ответ —
`POST /cards/{id}/comments` body `{"text": <текст>}` (без вложений);
перенос — PATCH и строка журнала перемещений с пустой заметкой
(`kiten-move.md`). Сквозного отката нет: сбой шага оставляет
предыдущие шаги применёнными (см. «Известные отклонения»).

## Конфигурация

`KITEN_READY_COLUMN` — колонка переноса по умолчанию;
`KITEN_TIME_ROLE` — роль остановки таймера (`kiten-time.md`);
токен и base URL — `platform/kaiten-http.md`.

## Инварианты

- Порядок шагов фиксирован: таймер → поля → ответ → перенос. Таймер
  первый: учтённое время не должно теряться из-за сбоя позднего шага.
- Повторный запуск после частичного сбоя безопасно доводит остальное:
  записанные поля пропускаются как заполненные, перенос повторяется
  релогом, остановленного таймера второй раз нет.
- Без `--stop-timer` таймер не останавливается и запись времени не
  создаётся ни при каких условиях.
- Заполненное поле без `--force-fields` не перезаписывается.
- `@all` — клиентская подстановка до отправки; отсутствие владельца не
  блокирует закрытие.
- `--dry-run` не выполняет мутирующих запросов и не пишет локально.

## Граничные случаи и ошибки

- Все переданные поля на карточке заполнены → `поля: записать [—];
  пропущены (заполнены) [{kinds}]`, остальные шаги выполняются.
- Ни одно поле не передано → `поля [—]`, шаг полей пропущен.
- `--stop-timer` при незапущенном таймере → шаг молча пропущен, строки
  `таймер:` в выводе применения нет.
- `--reply-file <нечитаемый путь>` → exit 2:
  `не удалось прочитать {путь}: <причина>`.
- `--column` не резолвится на доске карточки → exit 2 (в том числе при
  `--dry-run`).
- Сбой шага «поля» → таймер (если был) уже остановлен и записан; сбой
  шага «ответ» → поля уже записаны; exit 1.
- Перенос при карточке уже в целевой колонке → релог
  (`kiten-move.md`).

## Golden-примеры

Снять при переводе в «к реализации» (тестовая карточка):
`close <id> --dry-run --hypothesis h --done d --result r --reply
'Готово @all'` (полный план), `close <id> --dry-run --no-move` (план
без переноса), `close <id> --reply a --reply-file b` (exit 2),
`close <id> --hypothesis h --no-move` (применение: поля + пропуски),
`close <id>` при запущенном таймере без `--stop-timer`
(предупреждение).

## Известные отклонения

- **preserve** — сквозного отката между шагами нет; сбой позднего шага
  оставляет ранние применёнными, команда завершается ошибкой. Причина:
  у Kaiten API нет транзакций; порядок выбран так, что самое ценное —
  учтённое время — фиксируется первым, а повторный запуск идемпотентно
  доводит остальные шаги.
- **fix** — роль записи при `--stop-timer` оригинал берёт сразу из env
  `KITEN_TIME_ROLE`/дефолта, минуя роль, запомненную при `time start`.
  Правильно — порядок ролей из `kiten-time.md` («stop»): подсказка →
  env → дефолт.
