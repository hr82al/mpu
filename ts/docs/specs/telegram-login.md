# mpu telegram login — вход от имени пользователя

**Статус:** к реализации (2026-08-28). Последняя непереехавшая команда
семейства: `send`, `ls`, `search`, `status`, `log` уже native.

## Назначение

Интерактивный вход в Telegram: сохранить пользовательскую сессию в env-файл,
чтобы остальные команды семейства работали без повторного входа. Та же
реализация — шаг входа в `mpu init`.

```
mpu telegram login
```

Опций нет.

## Сценарий

1. **Сессия уже есть** → печатает «уже авторизован», код 0, вход не
   запускается. Идемпотентность здесь не удобство, а защита: повторный вход
   отзывает прежнюю сессию.
2. **Нет TTY** → пропуск с подсказкой заполнить ключи вручную, **код 0**.
   Не отказ: команда общая с шагом `mpu init`, а тот не должен падать в
   неинтерактивном запуске.
3. **Нет ключей приложения** → спрашивает согласие завести их, с указанием,
   где взять; отказ пользователя — выход без записи.
4. Телефон берётся из env-файла либо спрашивается и **сохраняется**.
5. Код из Telegram — обычный ввод; пароль второго фактора — **скрытый**.
6. Успех: сессия и телефон записаны в env-файл, сообщение об этом.

## Инварианты

1. **Секреты не печатаются.** Строка сессии — полноценный доступ к аккаунту:
   она не идёт ни в stdout, ни в stderr, ни в журнал вызовов, ни в текст
   ошибки. Пароль второго фактора вводится скрыто и не сохраняется вовсе.

2. **Единственное место записи — env-файл.** Ни временных файлов, ни копий
   рядом; при отказе на любом шаге частично записанного состояния не
   остаётся, кроме телефона и ключей приложения — они не секреты доступа и
   переживают неудачный вход намеренно.

3. **Отсутствие TTY — не ошибка** (код 0), отсутствие ключей после
   согласия — ошибка ввода (код 2).

4. **Повторный вход не запускается молча.** Если сессия есть, но неверна,
   команда говорит об этом прямо, а не делает вид, что всё в порядке.

## Проверка — и её честная граница

**Полный вход живьём непроверяем и проверяться не должен:** он требует
настоящего телефона, кода из Telegram и отзывает действующую сессию
владельца. Прогон «до конца» сломал бы рабочий доступ.

Проверяемо без входа:

- ветка «уже авторизован» — сессия в env-файле есть;
- ветка «нет TTY» — запуск с перенаправленным вводом, код 0 и подсказка;
- ветка «нет ключей приложения» — на подменном env-файле без них;
- что строка сессии не появляется ни в одном выводе и ни в журнале.

Что непроверяемо — говорить прямо, а не выдавать за проверенное. Живой вход
выполняет владелец вручную, если сессия когда-нибудь истечёт.

## Приёмка

- на основном конфиге: «уже авторизован», код 0, сессия не переписана
  (сверить env-файл до и после — по отметке времени, не по содержимому);
- ввод не с терминала → код 0 и подсказка;
- подменный env-файл без ключей → сценарий согласия, отказ не пишет ничего;
- `mpu log` после всех прогонов не содержит строки сессии.
