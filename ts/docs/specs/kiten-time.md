# mpu kiten time

Статус: черновик (переписана 2026-08-06: команда стала тонкой поверх каталога
внешнего API. Локальные подсказки таймера, сводка без селектора и `--dry-run`
убраны; роль резолвится живым запросом; комментарий таймера читается с сервера)

## Назначение

Учёт времени карточки Kaiten: записи (`ls`/`add`/`edit`/`rm`) и личный таймер
(`start`/`status`/`stop`/`discard`). Остановка таймера с этой же семантикой
переиспользуется `mpu kiten close` — контракт остановки здесь. Внешняя граница —
`platform/kaiten-api-time.md` (записи, таймеры, роли) и
`platform/kaiten-api-cards.md` (чтение карточки); транспорт, токен и формат
ошибок — `platform/kaiten-http.md`.

## CLI-контракт

Общее: `SELECTOR` — ID карточки или её URL (`platform/kaiten-http.md`); обязателен
у всех подкоманд. `DURATION` → целые минуты: `3h` | `1h15m` | `1:15` | `90` (голое
число = минуты) | `2.5h`; единицы `h`/`m`/`ч`/`м` (каждая не чаще раза), регистр и
внутренние пробелы не значимы, дробь с `.`/`,` округляется ВВЕРХ до минуты; итог —
1..1440. Даты — строго `YYYY-MM-DD`; дата по умолчанию — сегодня по МСК (UTC+3), не
по локальной зоне машины.

`--role REF` — ID или название роли. Числовой `REF` берётся как ID без сетевого
запроса; нечисловой резолвится по живому справочнику ролей: точное совпадение
названия без учёта регистра, иначе подстрока. Действующая роль: явный `--role` →
env `KITEN_TIME_ROLE` (нерезолвимое значение — ошибка с префиксом
`KITEN_TIME_ROLE:`, без отката) → роль 12058 («Техподдержка»); дефолт числовой и
запроса не требует.

Длительность в выводе — `1 ч 15 мин` / `2 ч` / `45 мин`; счётчик записей:
«1 запись» / «2 записи» / «5 записей».

`ls SELECTOR [--all] [--date-from D] [--date-to D] [--role REF] [--json]` — записи
карточки; по умолчанию только записи владельца токена (внешний API отдаёт записи
всей компании — фильтр клиентский), `--all` — всех; фильтры дат по дате записи,
границы инклюзивные. Вывод: таблица `ID ДАТА ВРЕМЯ РОЛЬ [ПОЛЬЗОВАТЕЛЬ при --all]
КОММЕНТАРИЙ` + `итого: <длительность> (N записей)`; нет записей → `(пусто)`.
`--json`: `{"total_minutes": int, "logs": [...]}`; запись — плоский объект
`{id, card_id, for_date, minutes, role_id, role, user_id, user, comment}`.

`add SELECTOR DURATION [--date D] [--role REF] [--comment/-m TEXT]` — создать
запись; пустой `--comment` (дефолт) = без комментария. Дата в будущем не
блокируется: stderr `внимание: дата <D> в будущем`. Успех: `ok: +<длительность> ·
<дата> · <роль> · запись <id> · <URL>` — из ответа сервера.

`edit SELECTOR LOG_ID [--time DURATION] [--date D] [--role REF] [--comment/-m TEXT]
[--force]` — частичное обновление: тело только из явно заданных осей;
`--comment ''` очищает комментарий — иное, чем отсутствие флага. Успех: `ok: запись
<id> · <только изменённые оси> · <URL>` (очистка — `комментарий очищен`).

`rm SELECTOR LOG_ID [--force]` — удалить запись; печатает удалённую целиком
(`ok: удалена запись <id> · <дата> · <длительность> · <роль>[ · «комментарий»] ·
<URL>`) — страховка от опечатки в ID.

`start SELECTOR [--comment/-m TEXT]` — запустить таймер. Роль внешний API у
таймера не хранит, поэтому `start` её не принимает: роль выбирается при остановке.
Комментарий передаётся серверу и хранится на таймере. Перед стартом — свежее
чтение карточки. Успех: `ok: таймер запущен <ЧЧ:ММ МСК> · <URL>`.

`status SELECTOR [--json]` — чтение без мутаций. `таймер: идёт <длительность>
(с <ЧЧ:ММ МСК>)[ · «комментарий»]` либо `таймер: не запущен`, затем `всего по
карточке: <длительность>`. `--json`: `{"card_id", "timer": null | {id, started_at,
elapsed_minutes, comment}, "total_minutes"}`.

`stop SELECTOR [--time DURATION] [--role REF] [--comment/-m TEXT]` — остановить
таймер, создав запись. Роль записи: явный `--role` → env → дефолт. Комментарий:
явный `-m` → комментарий таймера, прочитанный с сервера (передаётся в запрос
обязательно — сам сервер его из таймера не переносит). Без `--time` начало не
передаётся, финиш = «сейчас». С `--time N`: начало = старт таймера, усечённый до
целой минуты, финиш = начало + N; финиш попал бы в будущее (N больше натёкшего) →
финиш = «сейчас», усечённое до минуты, начало = финиш − N, плюс предупреждение.
Созданная запись перечитывается из списка записей карточки: `ok: таймер остановлен
· записано <длительность>[ (по факту <длительность>) при --time ≠ факту] · <дата> ·
<роль> · запись <id> · <URL>`; сервер не вернул id записи → `ok: таймер остановлен ·
запись <id> · <URL>`.

`discard SELECTOR` — сбросить таймер без создания записи. Таймер идёт → `ok: таймер
сброшен без записи (шёл <длительность>) · <URL>`; нет → `ok: таймера нет — нечего
сбрасывать · <URL>`, exit 0 (идемпотентно — в отличие от `stop`, где тихий успех
означал бы потерянную работу).

Живые сценарии: `time status 1234567`; `time ls 1234567`; `time stop 1234567 --role
Диагностика -m 'разбор жалобы'`; `time add <URL карточки> 1h30m -m 'фикс'`.

## Ввод/вывод

stdout — данные и `ok:`-строки; stderr — предупреждения `внимание: …` и ошибки `mpu
kiten time <sub>: <причина>[; попробуй: <подсказка>]`, без трейсбеков. Exit: 0 —
успех; 2 — ошибки ввода (длительность, дата, роль, пустое обновление,
нераспарсенный селектор); 1 — доменные и сетевые. Не-2xx ответ внешней системы →
exit 1 в формате `platform/kaiten-http.md`; обрамление ошибок ввода (usage-блок)
задаёт общий CLI-слой.

## Побочные эффекты

Только вызовы внешнего API по `platform/kaiten-api-time.md` и
`platform/kaiten-api-cards.md`:

- `ls`: записи карточки; без `--all` — плюс текущий пользователь.
- `add`: создание записи.
- `edit`/`rm`: записи карточки (+ текущий пользователь для проверки владельца) →
  обновление либо удаление записи. Пустое тело обновления не отправляется никогда.
- `start`: чтение карточки → запуск таймера.
- `status`: чтение карточки (поле таймера — единственный источник истины о нём).
- `stop`: чтение карточки → остановка таймера → записи карточки (перечитать
  созданную). Отправляемые метки времени — ISO 8601 в зоне старта таймера,
  миллисекунды всегда `.000`.
- `discard`: чтение карточки → сброс таймера.
- Резолв нечислового `--role` либо `KITEN_TIME_ROLE` — справочник ролей.

Локального состояния нет: на диск команда не пишет ничего.

## Конфигурация

Env `KITEN_TIME_ROLE` — роль по умолчанию (ID или название). Базовый URL и токен —
`platform/kaiten-http.md`.

## Инварианты

- Единица длительности — целые минуты, округление вверх; секунд нет нигде.
- «Сегодня» и часы-минуты в выводе — по МСК.
- Фильтр «только мои записи» — всегда клиентский, по id владельца токена.
- Решения о таймере принимаются только по свежему чтению карточки.
- `stop` печатает перечитанную с сервера запись, а не свои вычисления.
- `ls` и `status` не делают мутирующих вызовов.
- Чужая запись не меняется и не удаляется без `--force`; запись без владельца
  (`user_id` = null) — без ограничений.
- Справочник ролей запрашивается только когда значение роли нечисловое.

## Граничные случаи и ошибки

- `DURATION` (причина с префиксом `'<вход>': `, всё exit 2): ноль/отрицательное →
  `нулевая длительность бессмысленна`; > 1440 → `больше 24 ч в одной записи;
  заведите записи по дням через --date`; `1h15` → `после числа нужна единица
  измерения — вероятно, вы имели в виду '1h15m'`; `1:60` → `минуты в форме Ч:ММ
  должны быть 00–59`; мусор → `неразобранная длительность; ожидается <перечень
  форм>`.
- Невалидная дата → exit 2 `<флаг>='<значение>': ожидается YYYY-MM-DD`.
- `--role` без совпадений → exit 2 ``role '<ref>' не найден — см. `mpu kiten
  roles` ``; несколько → exit 2 `role '<ref>' неоднозначен (<N> совпадений):` + до
  10 кандидатов `id (название)`.
- `edit` без единой оси → exit 2 `нужно хотя бы одно из --time / --date / --role /
  --comment`.
- `edit`/`rm`: `LOG_ID` не с карточки → exit 1 `записи <id> нет на карточке
  <card_id>` + подсказка `time ls <card_id>`; чужая запись без `--force` → exit 1
  `запись <id> принадлежит другому пользователю (user_id=<их>, я <мой>); повтори с
  --force`.
- `start`: таймер на этой карточке уже идёт → exit 1 `таймер на карточке <id> уже
  запущен (с <ЧЧ:ММ МСК>)` + подсказки `time stop`/`time discard`. Ответ сервера о
  существующем таймере без идентификатора → exit 1 `Kaiten сообщает, что таймер уже
  создан` + подсказка `time stop`.
- `stop` без запущенного таймера → exit 1 `таймер на карточке <id> не запущен` +
  подсказка `time start <id>`.
- `stop --time` больше натёкшего → stderr `внимание: --time <X> больше фактических
  <Y> — начало сдвинуто назад`, запись создаётся.
- Дата созданной `stop` записи ≠ московскому дню финиша (сервер берёт её от финиша
  в UTC; расходятся в 00:00–03:00 МСК) → stderr-предупреждение с готовой командой
  `time edit <карточка> <id> --date <мск-день>`.

## Golden-примеры

Часть снята живым прогоном на тестовой карточке 2026-08-14 и обезличена —
`fixtures/kiten-time/`: `status-idle-stdout.txt` и `status-running-stdout.txt`
(оба состояния таймера), `start-stdout.txt`, `discard-stdout.txt` (сброс без
записи), и три ветви конфликта: `err-start-other-card-local-stderr.txt`
(таймер идёт на другой карточке — прежняя реализация отбивает локально, до сети),
`err-start-same-card-local-stderr.txt` (то же для той же карточки) и
`err-start-force-conflict-stderr.txt` (тот же запуск в обход локальной проверки —
видно ответ внешней системы, 400 с телом-конфликтом).

Осталось снять при переводе в «к реализации»: `time ls <card>` и с `--json`;
`status --json`; `time add <card> 0` (exit 2); `time edit <card> <log_id>` без
осей (exit 2); `time rm <card> <чужой log_id>` без `--force` (exit 1).

## Известные отклонения

- **fix** — в `add` текст ошибки разбора длительности начинается с `--time`, хотя
  `DURATION` у `add` — позиционный аргумент и флага `--time` там нет. Правильное
  поведение: причина называет аргумент `DURATION` (у `edit`/`stop` — флаг
  `--time`).

Что показала проба и что из неё следует для команды: таймер у пользователя один
на всю компанию, и `start` при уже идущем таймере получает один и тот же ответ —

ответа карточку не узнать, поэтому текст ошибки для человека строится так:
поймав конфликт, команда читает таймер пользователя отдельным вызовом и называет
карточку и время начала; не удалось прочитать — сообщение без карточки, но с
причиной. Отдельного текста «на другой карточке» как самостоятельной ветви нет:
ветвь одна — «таймер уже идёт», а карточка в ней переменная.
