# mpu kiten time

Статус: к реализации (2026-08-06 переписана: команда стала тонкой поверх каталога
внешнего API. Локальные подсказки таймера, сводка без селектора и `--dry-run`
убраны; роль резолвится живым запросом; комментарий таймера читается с сервера.
2026-08-15 сверена с рабочей версией построчно по всем восьми подкомандам —
CLI-поверхность, вывод, коды выхода, внешние вызовы; сверка нашла два дефекта в
самой спеке и один голден-ловушку, все исправлены здесь, см. «Известные
отклонения»)

## Назначение

Учёт времени карточки Kaiten: записи (`ls`/`add`/`edit`/`rm`) и личный таймер
(`start`/`status`/`stop`/`discard`). Остановка таймера с этой же семантикой
переиспользуется `mpu kiten close` — контракт остановки здесь. Внешняя граница —
`platform/kaiten-api-time.md` (записи, таймеры, роли) и
`platform/kaiten-api-cards.md` (чтение карточки); транспорт, токен и формат
ошибок — `platform/kaiten-http.md`.

## CLI-контракт

Общее: `SELECTOR` — ID карточки или её URL (`platform/kaiten-http.md`); обязателен
у всех подкоманд. `DURATION` → целые минуты: `3h` | `1h15m` | `1:15` | `90` (голое
число = минуты) | `2.5h`; единицы `h`/`m`/`ч`/`м` (каждая не чаще раза), регистр и
внутренние пробелы не значимы, дробь с `.`/`,` округляется ВВЕРХ до минуты; итог —
1..1440. В форме `Ч:ММ` минутная часть — одна или две цифры, и одна цифра значит
именно её: `1:5` = 65 минут, не 110. Даты — строго `YYYY-MM-DD`, несуществующий
день (`2026-02-30`) отвергается локально тем же текстом, что и непохожая на дату
строка; дата по умолчанию — сегодня по МСК (UTC+3), не по локальной зоне машины.

`--role REF` — ID или название роли. Числовой `REF` берётся как ID без сетевого
запроса; нечисловой резолвится по живому справочнику ролей: точное совпадение
названия без учёта регистра, иначе подстрока. Действующая роль: явный `--role` →
env `KITEN_TIME_ROLE` (нерезолвимое значение — ошибка с префиксом
`KITEN_TIME_ROLE:`, без отката) → роль 12058 («Техподдержка»); дефолт числовой и
запроса не требует. Пустое значение ключа `KITEN_TIME_ROLE` равносильно его
отсутствию — уходит на дефолт, а не резолвится.

**Роль в выводе — всегда название, а не id.** Ответ мутирующего вызова названия
роли не несёт (проверено живым прогоном 2026-08-15), поэтому `add`, ось роли у
`edit` и `stop` дорезолвируют его справочником ролей; ответ списка (`ls`, `rm`)
название уже содержит, там запроса не нужно. Названия нет и в справочнике —
печатается числовой id.

Длительность в выводе — `1 ч 15 мин` / `2 ч` / `45 мин`; счётчик записей:
«1 запись» / «2 записи» / «5 записей».

`ls SELECTOR [--all] [--date-from D] [--date-to D] [--role REF] [--json]` — записи
карточки; по умолчанию только записи владельца токена (внешний API отдаёт записи
всей компании — фильтр клиентский), `--all` — всех; фильтры дат по дате записи,
границы инклюзивные. Порядок строк — порядок ответа внешней системы, своей
сортировки нет. Вывод: таблица `ID ДАТА ВРЕМЯ РОЛЬ [ПОЛЬЗОВАТЕЛЬ при --all]
КОММЕНТАРИЙ` + `итого: <длительность> (N записей)`; нет записей → `(пусто)`.
`--json`: `{"total_minutes": int, "logs": [...]}`; запись — плоский объект
`{id, card_id, for_date, minutes, role_id, role, user_id, user, comment}`. `role` —
название роли из ответа внешней системы; названия нет → `null` (в таблице в этом
случае печатается числовой `role_id`: колонка всегда заполнена, JSON-поле — нет).

`add SELECTOR DURATION [--date D] [--role REF] [--comment/-m TEXT]` — создать
запись; пустой `--comment` (дефолт) = без комментария. Дата в будущем не
блокируется: stderr `внимание: дата <D> в будущем`. Успех: `ok: +<длительность> ·
<дата> · <роль> · запись <id> · <URL>` — из ответа сервера.

`edit SELECTOR LOG_ID [--time DURATION] [--date D] [--role REF] [--comment/-m TEXT]
[--force]` — частичное обновление: тело только из явно заданных осей;
`--comment ''` очищает комментарий — иное, чем отсутствие флага. Успех: `ok: запись
<id> · <только изменённые оси> · <URL>` (очистка — `комментарий очищен`). Оси в
порядке `время → дата → роль → комментарий` независимо от порядка флагов;
значения — из ответа сервера, а не из введённых аргументов.

`rm SELECTOR LOG_ID [--force]` — удалить запись; печатает удалённую целиком
(`ok: удалена запись <id> · <дата> · <длительность> · <роль>[ · «комментарий»] ·
<URL>`) — страховка от опечатки в ID.

`start SELECTOR [--comment/-m TEXT]` — запустить таймер. Роль внешний API у
таймера не хранит, поэтому `start` её не принимает: роль выбирается при остановке.
Комментарий передаётся серверу и хранится на таймере. Перед стартом — свежее
чтение карточки. Успех: `ok: таймер запущен <ЧЧ:ММ МСК> · <URL>`.

`status SELECTOR [--json]` — чтение без мутаций. `таймер: идёт <длительность>
(с <ЧЧ:ММ МСК>)[ · «комментарий»]` либо `таймер: не запущен`, затем `всего по
карточке: <длительность>`. `--json` (голден `status-json-stdout.txt`): `{"card_id", "timer": null | {id, started_at,
elapsed_minutes, comment}, "total_minutes"}`.

`stop SELECTOR [--time DURATION] [--role REF] [--comment/-m TEXT]` — остановить
таймер, создав запись. Роль записи: явный `--role` → env → дефолт. Комментарий:
явный `-m` → комментарий таймера, прочитанный с сервера (передаётся в запрос
обязательно — сам сервер его из таймера не переносит). Без `--time` начало не
передаётся, финиш = «сейчас». С `--time N`: начало = старт таймера, усечённый до
целой минуты, финиш = начало + N; финиш попал бы в будущее (N больше натёкшего) →
финиш = «сейчас», усечённое до минуты, начало = финиш − N, плюс предупреждение.
Созданная запись перечитывается из списка записей карточки: `ok: таймер остановлен
· записано <длительность>[ (по факту <длительность>) при --time ≠ факту] · <дата> ·
<роль> · запись <id> · <URL>`; сервер не вернул id записи → `ok: таймер остановлен ·
запись <id> · <URL>`.

`discard SELECTOR` — сбросить таймер без создания записи. Таймер идёт → `ok: таймер
сброшен без записи (шёл <длительность>) · <URL>`; нет → `ok: таймера нет — нечего
сбрасывать · <URL>`, exit 0 (идемпотентно — в отличие от `stop`, где тихий успех
означал бы потерянную работу).

Живые сценарии: `time status 1234567`; `time ls 1234567`; `time stop 1234567 --role
Диагностика -m 'разбор жалобы'`; `time add <URL карточки> 1h30m -m 'фикс'`.

## Ввод/вывод

stdout — данные и `ok:`-строки; stderr — предупреждения `внимание: …` и ошибки `mpu
kiten time <sub>: <причина>[; <подсказка>]`, без трейсбеков. Подсказка бывает двух
форм, и обе — контракт: `; попробуй: <готовая команда>` там, где действие одно
(`; попробуй: mpu kiten time ls 10000001`), и императив с командой в обратных
кавычках там, где действий несколько и надо выбрать (`; останови \`mpu kiten time
stop 10000001\` или сбрось \`mpu kiten time discard 10000001\``). Тексты обеих форм
перечислены в «Граничных случаях» поимённо. Готовая команда — всегда с
подставленными значениями; шаблон с угловыми скобками в выводе — дефект (см.
«Известные отклонения»). Exit: 0 —
успех; 2 — ошибки ввода (длительность, дата, роль, пустое обновление,
нераспарсенный селектор); 1 — доменные и сетевые. Не-2xx ответ внешней системы →
exit 1 в формате `platform/kaiten-http.md`; обрамление ошибок ввода (usage-блок)
задаёт общий CLI-слой.

## Побочные эффекты

Только вызовы внешнего API по `platform/kaiten-api-time.md` и
`platform/kaiten-api-cards.md`:

- `ls`: записи карточки; без `--all` — плюс текущий пользователь.
- `add`: создание записи.
- `edit`/`rm`: записи карточки (+ текущий пользователь для проверки владельца) →
  обновление либо удаление записи. Пустое тело обновления не отправляется никогда.
- `start`: чтение карточки → запуск таймера.
- `status`: чтение карточки (поле таймера — единственный источник истины о нём).
- `stop`: чтение карточки → остановка таймера → записи карточки (перечитать
  созданную). Отправляемые метки времени — ISO 8601 в зоне старта таймера,
  миллисекунды всегда `.000`.
- `discard`: чтение карточки → сброс таймера.
- Резолв нечислового `--role` либо `KITEN_TIME_ROLE` — справочник ролей; он же —
  за названием роли для вывода `add`/`edit`/`stop`.

Локального состояния нет: на диск команда не пишет ничего.

## Конфигурация

Env `KITEN_TIME_ROLE` — роль по умолчанию (ID или название). Базовый URL и токен —
`platform/kaiten-http.md`.

## Инварианты

- Единица длительности — целые минуты, округление вверх; секунд нет нигде.
- «Сегодня» и часы-минуты в выводе — по МСК.
- Фильтр «только мои записи» — всегда клиентский, по id владельца токена.
- Решения о таймере принимаются только по свежему чтению карточки.
- `stop` печатает перечитанную с сервера запись, а не свои вычисления.
- `ls` и `status` не делают мутирующих вызовов.
- Чужая запись не меняется и не удаляется без `--force`; запись без владельца
  (`user_id` = null) — без ограничений.
- Справочник ролей запрашивается в двух случаях и только в них: значение роли
  нечисловое (нужен резолв) либо название роли нужно человекочитаемому выводу
  мутирующей подкоманды (`add`, ось роли `edit`, `stop`).

## Граничные случаи и ошибки

- `DURATION` (причина с префиксом `'<вход>': `, всё exit 2): ноль/отрицательное →
  `нулевая длительность бессмысленна`; > 1440 → `больше 24 ч в одной записи;
  заведите записи по дням через --date`; `1h15` → `после числа нужна единица
  измерения — вероятно, вы имели в виду '1h15m'`; `1:60` → `минуты в форме Ч:ММ
  должны быть 00–59`; мусор → `неразобранная длительность; ожидается <перечень
  форм>`.
- Невалидная дата → exit 2 `<флаг>='<значение>': ожидается YYYY-MM-DD`.
- `--role` без совпадений → exit 2 ``role '<ref>' не найден — см. `mpu kiten
  roles` ``; несколько → exit 2 `role '<ref>' неоднозначен (<N> совпадений):` + до
  10 кандидатов `id (название)`.
- `edit` без единой оси → exit 2 `нужно хотя бы одно из --time / --date / --role /
  --comment`.
- `edit`/`rm`: `LOG_ID` не с карточки → exit 1 `записи <id> нет на карточке
  <card_id>` + подсказка `time ls <card_id>`; чужая запись без `--force` → exit 1
  `запись <id> принадлежит другому пользователю (user_id=<их>, я <мой>); повтори с
  --force`.
- `start`, таймер уже идёт: ветвь **одна**, карточка в ней переменная (см. «Открытые
  вопросы»). Внешняя система отвечает 400 одинаково для этой же и для чужой карточки,
  поэтому команда, поймав конфликт, читает таймер пользователя отдельным вызовом →
  exit 1 `таймер уже идёт на карточке <id> (с <ЧЧ:ММ МСК>)`; подсказка — `; останови
  `mpu kiten time stop <id>`` для чужой карточки, для той же — плюс `или сбрось
  `mpu kiten time discard <id>``. Прочитать таймер не удалось → exit 1 `Kaiten
  сообщает, что таймер уже создан` + подсказка `time stop`, без карточки.
- `DURATION` из пробелов либо пустой → exit 2 `'<вход>': пустая длительность;
  ожидается <перечень форм>` — отдельный текст, не «неразобранная длительность».
- `stop` без запущенного таймера → exit 1 `таймер на карточке <id> не запущен` +
  подсказка `time start <id>`.
- `stop --time` больше натёкшего → stderr `внимание: --time <X> больше фактических
  <Y> — начало сдвинуто назад`, запись создаётся.
- Дата созданной `stop` записи ≠ московскому дню финиша (сервер берёт её от финиша
  в UTC; расходятся в 00:00–03:00 МСК) → stderr-предупреждение с готовой командой
  `time edit <карточка> <id> --date <мск-день>`.

## Golden-примеры

Часть снята живым прогоном на тестовой карточке 2026-08-14 и обезличена —
`fixtures/kiten-time/`: `status-idle-stdout.txt` и `status-running-stdout.txt`
(оба состояния таймера), `start-stdout.txt`, `discard-stdout.txt` (сброс без
записи). Прогон 2026-08-15 добавил `status-running-comment-stdout.txt` — таймер с
комментарием и ненулевым итогом по карточке: видно и суффикс `· «комментарий»`, и
что «всего по карточке» считает записи, а не идущий таймер.

Тем же прогоном подтверждена идемпотентность `discard` (второй подряд даёт
`ok: таймера нет — нечего сбрасывать`, exit 0) и то, что рабочая версия печатает
роль в строке успеха `start`, — основание для нормализации ниже.

`start-stdout.txt` **нормализован** (2026-08-15): из снятой строки убрано ` ·
Техподдержка` — роль. Рабочая версия печатала её из локальной подсказки, а
локального состояния у команды больше нет и роль на старте не выбирается вовсе
(она выбирается при остановке). Голден со снятой строкой был ловушкой: он
показывал поведение, которое воспроизводить запрещено.

Три ветви конфликта `start` — `err-start-other-card-local-stderr.txt`,
`err-start-same-card-local-stderr.txt`, `err-start-force-conflict-stderr.txt` —
**свидетельства отклонений, а не образцы**. Первые два сняты с локальной отбивки
до сети (её больше нет: решение принимается по ответу внешней системы), третий
показывает сырой ответ 400, вместо которого команда обязана назвать карточку и
время. Воспроизводить ни один из трёх не нужно; целевые тексты — в «Граничных
случаях».

Голдены записей сняты живым прогоном 2026-08-15 на тестовой карточке (три
созданные записи, затем правка, очистка комментария и удаление) и обезличены:
`ls-stdout.txt` (три записи, у одной комментарий пуст — видно, что колонка
остаётся пустой, а не печатает прочерк), `ls-json-stdout.txt`, `ls-all-stdout.txt`
(колонка `ПОЛЬЗОВАТЕЛЬ`), `ls-empty-stdout.txt`, `add-stdout.txt`,
`edit-stdout.txt` (две оси разом), `edit-comment-cleared-stdout.txt`,
`rm-stdout.txt`, `rm-with-comment-stdout.txt` (суффикс `· «комментарий»`),
`err-log-not-on-card-stderr.txt` (exit 1, с подсказкой формы `; попробуй:`).
Тем же прогоном снят `status-json-stdout.txt` (таймера нет) — он относится к
`status`, то есть к таймерной части, а не к записям.

Тексты ветвей exit 2 сети не касаются: `err-duration-zero-message.txt`,
`err-duration-empty-message.txt`, `err-duration-tail-message.txt`,
`err-duration-minutes-message.txt`, `err-edit-no-axis-message.txt`,
`err-date-format-message.txt`. Обрамление рабочей версии (usage-блок и рамка) —
оформление её CLI-фреймворка, не контракт: проверяются exit-код, пустой stdout и
текст на stderr.

Четыре голдена длительности **нормализованы**: сняты они с `add`, где рабочая
версия печатает префикс `--time` при позиционном аргументе (известное отклонение
ниже), и в файлах он заменён на `DURATION`. Та же ветвь у `edit`, где `--time` —
настоящий флаг, лежит отдельно и снята как есть:
`err-edit-duration-zero-message.txt`. Пара нужна именно как пара — она и есть
проверка, что префикс называет аргумент, через который значение пришло.

Ширина колонок таблицы `ls` подгоняется под содержимое, а длинные значения
переносятся по словам (видно в `ls-all-stdout.txt` на имени пользователя). Это
поведение табличного рендера, а не контракт команды: сверять по этим голденам
состав колонок, порядок строк и итоговую строку, но не позиции пробелов.

Не снято: `time rm <card> <чужой log_id>` без `--force` (exit 1). Записи другого
пользователя на тестовых карточках нет, а завести её нельзя — токен один. Текст
ветви описан выше дословно; голден появится, если такая запись когда-нибудь
возникнет.

## Известные отклонения

- **fix** — в `add` текст ошибки разбора длительности начинается с `--time`, хотя
  `DURATION` у `add` — позиционный аргумент и флага `--time` там нет. Правильное
  поведение: причина называет аргумент `DURATION` (у `edit`/`stop` — флаг
  `--time`).
- **fix** — предупреждение о сдвинутой дате `stop` печатает шаблон буквально:
  `time edit <карточка> <id> --date 2026-08-15`, где `<карточка>` и `<id>` — не
  подставленные значения, а угловые скобки в тексте. Правильное поведение: команда
  в подсказке готова к копированию, с реальными id карточки и записи.
- **fix** — конфликт `start` разрешался локально, до сети: команда хранила
  подсказки о запущенных таймерах в локальной БД, обходила подсказанные карточки
  запросами и по ним решала, что таймер уже идёт; в обход этой проверки (`--force`)
  наружу уходил сырой ответ 400. Локального состояния у команды нет, поэтому
  решение принимается по ответу внешней системы, а карточка и время берутся
  отдельным чтением таймера пользователя. Следствия: флага `--force` у `start` нет
  (обходить нечего), и запрос на старт всегда ровно один.
- **fix** — локальное состояние в целом: рабочая версия писала и читала подсказки
  таймера (роль, комментарий, время старта) в локальной БД у `add`, `start`,
  `status`, `stop`, `discard`. Отсюда же брались роль при `stop` (перед env и
  дефолтом) и карточка при `status` без селектора. Ничего этого нет: роль при
  остановке — `--role` → env → дефолт, селектор обязателен всюду, на диск команда
  не пишет.
- **fix** — `--dry-run` у `add`, `edit`, `rm`, `stop` и сводка `ls`/`status` без
  селектора сняты вместе с локальным состоянием: сводка на нём и держалась.
- **fix** — подсказка «вероятно, вы имели в виду» строится рабочей версией от
  нормализованной строки и всегда с латинской `m`: `1H15` → `'1h15m'`, `1ч15` →
  `'1ч15m'`. Правильное поведение: подсказка повторяет введённое как есть, а
  буква берётся из алфавита уже встреченных единиц (`1ч15` → `'1ч15м'`), — иначе
  она чинит вход не тем алфавитом, которым он написан. Разбираются обе формы:
  смешение алфавитов допустимо (`1ч15m` = 75 минут) и здесь ни при чём.
- **fix** — оси в строке `ok:` у `edit` рабочая версия печатает из введённых
  аргументов (из ответа сервера берётся только id записи). Правильное поведение:
  значения из ответа — строка успеха описывает записанное, а не отправленное.
  Наблюдаемо расходится только там, где сервер значение нормализует.
