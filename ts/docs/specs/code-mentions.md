# mpu code mentions

Статус: к реализации (2026-09-08; голден — `fixtures/code/`)

## Назначение

Где путь упомянут в документации и существует ли он в коде. Отвечает на
случай «файл переехал, а адреса в документах остались»: каждое такое
упоминание по отдельности выглядит правильным, и находят их только
все разом.

## CLI-контракт

`mpu code mentions ПУТЬ [--in ОКНО] [--limit N]`

Политика — `ro`. Объявление и форма вывода —
`platform/command-contract.md`; общий слой — `platform/code-analyzer.md`.

**ПУТЬ** — путь к файлу относительно корня репозитория, как его пишут в
документах. Совпадение считается по подстроке: в тексте адрес обычно
обрамлён обратными кавычками, скобками ссылки или знаками препинания.

**`--in ОКНО`** — `РЕПОЗИТОРИЙ` целиком либо `РЕПОЗИТОРИЙ:КАТАЛОГ`. Не
задано — ответ по каждому репозиторию рабочей области отдельным
разделом.

**`--limit N`** — предел строк в разделе, по умолчанию 200.

Справка листовой команды:

    mpu code mentions ПУТЬ [--in ОКНО] [--limit N]

    Где путь упомянут в документации (файлы .md вне node_modules) и
    существует ли он в коде.

    Ответ этой команды всегда помечен неполным: документы разбираются
    текстом, и упоминание, записанное иначе (переносом строки, другим
    регистром, через переменную), она не находит.

      --in ОКНО   РЕПОЗИТОРИЙ или РЕПОЗИТОРИЙ:КАТАЛОГ
      --limit N   предел строк в разделе (по умолчанию 200)

## Ввод/вывод

Шапка и раздел «не разрешено» — `platform/code-analyzer.md`. Гарантия в
шапке всегда `текстовый разбор — ответ неполон`: команда работает по
тексту документов, а не по разбору.

**Строка существования** — `ПУТЬ — в коде нет` либо `ПУТЬ — есть в коде`.
Печатается первой и всегда: без неё перечень упоминаний не отвечает на
заданный вопрос — протух адрес или нет.

**упоминания: N** — по строке на вхождение: `путь-документа:строка`.
Несколько вхождений в одной строке документа считаются одним. Разные
строки одного документа — разные вхождения.

Область просмотра — файлы `.md` репозитория вне `node_modules`.

Нулевой раздел печатается как `упоминания: 0`.

## Инварианты

- Строка существования печатается всегда и первой.
- Гарантия в шапке — всегда «неполон»: команда не притворяется разбором.
- Вхождение — пара «документ, строка»; повтор в одной строке не
  удваивает счёт.
- Порядок строк — `(репозиторий, путь, строка)`.
- Команда только читает.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu code mentions: `.

| Вход | Ожидаемое поведение |
| --- | --- |
| Путь пустой | exit 2, `нужен путь` |
| Репозиторий окна неизвестен | exit 2, `неизвестный репозиторий '<имя>'`, следом перечень известных |
| Путь существует и упомянут | exit 0, `— есть в коде` + перечень |
| Путь существует и не упомянут | exit 0, `— есть в коде`, `упоминания: 0` |
| Путь не существует и не упомянут | exit 0, `— в коде нет`, `упоминания: 0` |
| Документов `.md` в окне нет | exit 0, `упоминания: 0` |
| Раздел длиннее `--limit` | exit 0, строка `усечено: показано N из M` |

## Golden-примеры

`fixtures/code/`. Дерево-фикстура — `platform/code-analyzer.md`. Файл
оканчивается одним переводом строки.

- `mentions-stale.stdout.txt` — `mentions fixture:src/gone.ts`: путь в
  коде отсутствует и упомянут в `docs/guide.md` дважды, в строках 3 и 5.
  Тест обязан краснеть, если строка существования пропадёт: перечень
  упоминаний без неё одинаково выглядит и для живого адреса, и для
  протухшего.
