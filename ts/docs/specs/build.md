# mpu build

Статус: реализовано — 2026-09-14 третий кандидат дерева исходников и его запоминание `[D.8]` — порция 114 (`bd2508a`, принято живьём: `mpu build --check` из `~` и `/tmp` находит дерево); уникальный временный файл запоминания, отказ пути с переводом строки, описание `не прочитано (<причина>)`, снятие BOM — порция 116 (`f07cc3a`, принято: гонка двух записей 0 аномалий из 90 против 50/50 до правки); прочее реализовано и сверено 2026-09-10 по `mpu build --help` (команда в справке; поверхность флагов построчно не сверялась). Ранее: постановка (2026-09-09, порция 105). Спека пишется до кода
(`proc-ak-ts`, `checklists/design.md`); пометки `[D.n]` — принятые решения.

## Назначение

Пересобрать и переустановить сам инструмент одной командой. Сегодня это
делается задачей `deno` и внешним скриптом-переключателем: путь вывода,
список прав и проверка собранного живут в трёх местах, и падение любого из
них оставляет установленную программу в неизвестном состоянии.

## CLI-контракт

`mpu build [--check]`

Политика — `rw`: команда заменяет установленную программу. `--check` —
enforced read-only вариант (`conv-mpu-readonly-split`, категория 1):
собирает и проверяет, установку не трогает; в правах Claude Code
`mpu build --check` идёт в `allow`, `mpu build` — в `ask`. `[D.6]`

Объявление и форма вывода — `platform/command-contract.md`.

## Ввод/вывод

**Дерево исходников** ищется тремя кандидатами в этом порядке `[D.1]`:

1. каталог, в котором лежит работающая программа (`Deno.execPath()` после
   разрешения символических ссылок), если он — `<дерево>/bin`, а рядом есть
   `<дерево>/deno.jsonc`;
2. ближайший предок текущего каталога с сентинелом `.mp-workspace-root`
   (`platform/code-analyzer.md`, «Рабочая область») → `<корень>/mpu/ts`;
3. **запомненное дерево** `[D.8]` — путь из файла
   `$XDG_CONFIG_HOME/mpu/build-source` (умолчание каталога —
   `$HOME/.config`; пустая или относительная `XDG_CONFIG_HOME` равнозначна
   незаданной — `platform/env-file.md`): первая
   строка файла без концевых пробелов и перевода строки, абсолютный путь.

Кандидат подходит, если по его пути лежат `deno.jsonc` и `main.ts`. Ни один не
подошёл — отказ, называющий все три проверенных места; у третьего — одно из
`запомненное дерево: <путь>` (путь есть, дерева там нет), `запомненное дерево:
не записано` (файла нет или первая строка пуста), `запомненное дерево:
<путь> — не абсолютный путь`, `запомненное дерево: не прочитано (<причина>)`
(файл есть, но не читается: на его месте каталог, нет прав; `<причина>` —
первая строка системной ошибки, путь в ней уже назван ОС, отдельно не
повторяется). Нечитаемый файл — описание, а не исключение: первые два
кандидата от него не зависят и при успехе выигрывают. Ведущий BOM (`U+FEFF`)
первой строки снимается до проверки абсолютности. Догадываться о дереве нельзя: собрать не тот
исходник хуже, чем не собрать.

**Запоминание** `[D.8]`: после успешной установки (шаг 5 порядка — установленное
ответило `version`) команда перезаписывает `build-source` путём дерева, из
которого собрала, — одной строкой с переводом строки на конце, атомарно
(временный файл рядом и переименование), права 0644. Имя временного файла
уникально на вызов: два одновременных `mpu build` с общим каталогом
конфигурации не пишут в один временный файл (замер разбора 114: при общем
`build-source.new` в 23 прогонах из 40 одна сторона печатала «не записано»,
хотя её путь лёг в файл). Путь дерева, содержащий перевод строки (`\n` или
`\r`), не записывается: исход — `запомненное дерево: не записано (путь дерева
содержит перевод строки)`, файл не тронут; иначе он читался бы обрезанным по
первой строке и мог указать на другое дерево. Запоминается фактическое
дерево, по какому бы кандидату оно ни нашлось. `--check`, отказ сборки или
проверки, возврат прежнего экземпляра файл не трогают. Не удалась только
запись файла — установка уже состоялась: печатается строка
`запомненное дерево: не записано (<причина>)`, exit 0 — отказ запоминания не
отменяет установку и не превращает её в ошибку. Вывод успешной установки
получает строку `запомненное дерево: <путь>`.

Почему файл, а не путь в самом бинаре: замер 2026-09-14 (deno 2.9.6) —
у скомпилированной программы `import.meta.url`, `import.meta.dirname` и
`Deno.mainModule` указывают на виртуальный `/tmp/deno-compile-<имя>/main.ts`,
исходный путь в бинарь не попадает. Почему не ключ env-файла: env-файл правит
пользователь руками (`platform/env-file.md`), а этот путь — след работы команды.

**Аргументы сборки берутся из задачи `build` в `deno.jsonc`** `[D.2]` — там же,
где их берёт `back/scripts/smoke.ts`, и тем же приёмом: строка задачи читается,
`$HOME` и `$XDG_CONFIG_HOME` раскрываются (умолчание второй — `$HOME/.config`;
`deno task` подставляет незаданную переменную пустой строкой, и правило записи
получает путь `/mpu` — замер 2026-09-09), значение `-o` подменяется на путь
кандидата. Список прав не переписывается: два источника одного списка
разъезжаются молча.

**Путь установки** — `$HOME/.local/bin/mpu`, и заменяется он как путь `[D.4]`:
если там лежала символическая ссылка (режим переключателя `back/scripts/mpu-impl`),
на её месте оказывается файл. Идти по ссылке нельзя — цель лежит в дереве
исходников, права на запись туда у бинаря нет, а брать их обходом через
порождённый процесс значило бы выдать право себе. Возврат к прежней
реализации переключателем от этого не страдает: он ставит ссылку заново.

**Порядок установки** `[D.4]`:

1. `deno task smoke` — сборка со списком прав задачи и проверка того, что видно
   только запуску бинаря; проверяется не устанавливаемый экземпляр, а сборка:
   у экземпляра smoke подменены `HOME` и каталог конфигурации, иначе проверка
   писала бы в настоящий домашний каталог. Красная — установка не тронута,
   дальше не идём.
2. Кандидат собирается в тот же каталог, что и цель, под соседним именем.
3. Кандидат отвечает `version` и `--help` — своим экземпляром, не установленным.
4. Прежний экземпляр сохраняется соседним именем; кандидат переименовывается
   поверх цели.
5. Установленное отвечает `version`. Не отвечает — прежний экземпляр
   возвращается на место, exit 1. Ответило — сохранённый экземпляр удаляется:
   каталог установки лежит в `PATH`, и оставленный `mpu.prev` стал бы
   работающей командой прежней версии.

Переименование в пределах каталога атомарно, и работающий процесс держит свой
inode: команда переживает замену самой себя.

**Служба MCP** `[D.7]`: после установки, если служба работает (`mcp-service.md`),
она перезапускается — иначе в памяти остаётся прежняя версия, и ответ службы
расходится с ответом терминала. Не установлена или остановлена — не трогается.

`--check` `[D.6]` обрывает порядок после первого шага: `deno task smoke`
собирает и проверяет свой экземпляр во временном каталоге, а кандидат по пути
установки не появляется вовсе.

Вывод — пять-шесть строк: собранная версия и прежняя, итог проверки, путь
установки, запомненное дерево `[D.8]`, судьба службы. У `--check` вывод свой, а не усечённый: кандидата
он не собирает вовсе, версии не существует, и первой строкой печатается
найденное дерево исходников, а последней — `установка не тронута (--check)`.
Строка «собрано: не собиралось» называла бы несделанное `[D.6]`.

**Служба не перезапустилась** — установка при этом уже состоялась, и молчать
об этом нельзя: печатаются обе строки, «установлено» и отказ перезапуска
(значение «перезапуск не удался» в судьбе службы), exit 1 `[D.7]`. Обратный
порядок — отдать наружу один отказ — оставил бы владельца в уверенности, что
программа не заменена, тогда как она заменена.

## Побочные эффекты

Заменяет установленную программу, перезапускает службу MCP и после успешной
установки перезаписывает `$XDG_CONFIG_HOME/mpu/build-source` `[D.8]`. Исходники,
прочую конфигурацию, кэш и репозитории не трогает. Гейты разработки (формат,
линтер, типы, тесты) не гоняет: это не проверка установки `[D.3]`.

## Конфигурация

Ключей нет. Файл `$XDG_CONFIG_HOME/mpu/build-source` — след команды, а не
настройка: пишет его только сама команда, но читать и поправить руками можно
(одна строка — абсолютный путь дерева). Права на запись в этот каталог у
бинаря уже есть (`--allow-write=…,$XDG_CONFIG_HOME/mpu`).

## Инварианты

- Установленная программа не меняется, пока не собран и не проверен кандидат.
- В любой момент по пути установки лежит целая программа — прежняя или новая.
- Установленное, не ответившее на `version`, заменяется прежним экземпляром.
- `--check` не пишет ничего в каталог установки.
- Проверка прав идёт по сборке с тем же списком `--allow-*`, каким ставится.
- Команда не выбирает ветку и не обновляет исходники.
- Результат поиска дерева не зависит от текущего каталога, если дерево
  запомнено: `mpu build` из любого каталога находит его третьим кандидатом.
- `build-source` меняется только успешной установкой и всегда содержит путь
  дерева, из которого собрана установленная программа; `--check` и неуспешная
  установка его не трогают.

## Публикация тулом

Не публикуется: команды нет в закрытом списке публикации, и вносить её туда
нельзя — иначе агент, работающий через сервер, заменяет программу, которой
сам же исполняется. Список fail-closed (`back/src/mcp/tools.ts`), так что
бездействие здесь и есть правильное действие; спека называет его, чтобы оно
не выглядело забытым.

## Права бинаря

`--allow-write` расширяется каталогом `$HOME/.local/bin` `[D.5]`: туда пишется
кандидат и туда возвращается прежний экземпляр. Сборку и `systemctl` порождает
`--allow-run`, уже имеющийся.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu build: `.

| Случай | Ответ | Код |
|---|---|---|
| дерево исходников не найдено | названы все три проверенных места | 1 |
| запуск из каталога вне монорепо, дерево запомнено | собирает запомненное дерево | 0 |
| в `build-source` относительный путь или путь без дерева | кандидат не подходит, описан в отказе | 1 |
| установка удалась, `build-source` не записался | `установлено` + `запомненное дерево: не записано (<причина>)` | 0 |
| `build-source` есть, но не читается (каталог на его месте, нет прав) | описание `запомненное дерево: не прочитано (<причина>)`; первые два кандидата при успехе выигрывают | 1, если дерево не найдено |
| первая строка начинается с BOM | BOM снимается, путь проверяется как обычно | — |
| путь дерева содержит перевод строки | файл не записывается, `запомненное дерево: не записано (путь дерева содержит перевод строки)` | 0 |
| два `mpu build` одновременно | у каждого свой временный файл; итог каждого правдив | — |
| `deno` не найден | названа причина | 1 |
| сборка упала | вывод сборщика целиком | 1 |
| `deno task smoke` красный | названа упавшая проверка | 1 |
| кандидат не отвечает `version` | установка не тронута | 1 |
| установленное не отвечает | прежний экземпляр возвращён | 1 |
| служба не перезапустилась | сказано и об установке, и об отказе | 1 |
| нет прав на запись по пути установки | назван путь | 1 |
| неизвестный флаг | ошибка ввода | 2 |

## Пункты чек-листа

1. **Примитивы.** Три: собрать по аргументам задачи, проверить экземпляр по
   пути, заменить файл по пути. Установка выводится из них в одном месте —
   в теле команды; `--check` обрывает ту же последовательность после второго.
2. **Особые случаи → получатели.** Ветка «где исходники» — три кандидата с
   одним протоколом «дай каталог дерева или скажи, где искал» (таблица
   `[D.1]`); запомненное дерево `[D.8]` — третий такой же кандидат, а не
   `if` в теле команды. Ветка «служба работает / нет» решается не здесь: спрашивается у
   службы (`mcp-service.md`), и ответ «нечего перезапускать» — её ответ, а не
   `if` в этой команде.
3. **Проверка типа и `null`.** Прежней версии может не быть (первая
   установка) — это не `undefined`, а экземпляр, отвечающий на весь протокол:
   версия «нет», возврат на место — пустое действие.
4. **Кто решает.** «Ставить или нет» решает проверка, а не команда: команда
   спрашивает у кандидата, отвечает ли он. «Перезапускать ли службу» решает
   служба.
5. **Память приватна.** Пути (дерево, цель, кандидат, прежний) наружу не
   отдаются как поля — команда печатает их сама.
6. **Голые данные → протокол.** Строка задачи `build` — не строка, а разбор:
   аргументы с подменяемым `-o`. Тот же разбор нужен `back/scripts/smoke.ts`, и
   двух копий у него быть не должно `[D.2]`.
