# mpu code shape

Статус: реализовано (2026-10-14, порция CS1). Голден — `fixtures/code/shape-file.stdout.txt`.

## Назначение

Какие функции файла длиннее предела, глубже предела по вложенности и где флаг поведения передан голым булевым
литералом. Повод звать — приёмка и рецензия диффа: правила «функция ≤ 40 строк, вложенность ≤ 3 уровней» и «булев
аргумент, выбирающий поведение, — протокол» (корневые правила монорепо и `review.md` п. 3) записаны числами, но
меряются глазами, то есть не меряются. Греп длину функции и глубину не видит, а булев литерал в ассерте теста от флага
поведения не отличает.

## CLI-контракт

`mpu code shape АДРЕС... [--base REF] [--limit N]`

Политика — `ro`, команда видна агенту. Адрес, `--base` и `--limit` — как у `code literals` (`code-literals.md`, включая «Решения по отчёту CL1»: новый файл
при `--base` изменён целиком, база в чужом репозитории — отказ, порядок проверок адреса):
адрес — `[РЕПОЗИТОРИЙ:]ПУТЬ` к `.ts`/`.tsx` без строки; `--base` оставляет записи, у которых хоть одна строка
функции (или строка вызова — для флагов) добавлена или изменена относительно `merge-base REF HEAD` в рабочем
дереве; `--limit` по умолчанию 200. Шапка — отметка дерева без поля гарантии: в абзаце-исключении
`platform/code-analyzer.md` «Исключение — `code literals`» порция CS1 меняет заголовок на «Исключение — `code
literals` и `code shape`» и первое предложение — на «поле гарантии в их шапке не печатается» (внесено спецификатором).

Справка — состав как у `literals`: вопрос в одностроке; первый абзац — момент (приёмка и рецензия) и чем лучше
грепа; три раздела с пределами; что исключено; ключи; коды выхода; полный пример.

## Что меряется

**Функция** — объявление функции, метод, стрелочная функция и функциональное выражение. Обратный вызов
`describe(…)` и его форм через точку функцией не считается: это контейнер тестов, а не логика.

1. **длинные** — функция, у которой от строки открывающей скобки тела до строки закрывающей включительно больше
   **40** строк; стрелка с телом-выражением меряется от `=>` до конца выражения. Вложенная функция меряется
   отдельно и в длину внешней входит — так её и читают.
2. **глубокие** — функция, в теле которой цепочка вложенных операторов управления длиннее **3**. Оператор
   управления — `if`, `for`, `for…of`, `for…in`, `while`, `do`, `switch`, `try`; `else` и `else if` — тот же
   уровень, что их `if`, `catch` и `finally` — тот же уровень, что их `try`. Тело вложенной функции начинает счёт с
   нуля и меряется своей записью.
3. **флаги** — вызов с двумя и более аргументами, где позиционный аргумент — литерал `true` или `false`. Вызов с
   одним аргументом (сеттер состояния, `useState(false)`, ассерт `toBe(true)`) — не флаг: аргумент там — значение,
   а не выбор поведения. Вызов матчера — метод в цепочке от `expect(…)` (`toHaveBeenCalledWith(54, true)`) — тоже не
   флаг: это утверждение о вызове.

Обратные вызовы `it`/`test` меряются как функции (решение спецификатора 14.10: в живом
`ChecklistClient.spec.tsx` из 37 `it` ни один не длиннее 40 строк — раздел не станет фоном).

## Ввод/вывод

Как у `literals`: шапка репозитория, по файлу — строка пути и три раздела, записи с отступом в два пробела, в конце
репозитория — `не разрешено: N`, вывод оканчивается одним переводом строки.

    длинные: N
      строка  ИМЯ  строк: K
    глубокие: N
      строка  ИМЯ  глубина: K
    флаги: N
      строка  ВЫЗОВ(…)  аргумент: M

`ИМЯ` — имя объявления; у безымянной стрелки — имя переменной или свойства, которому она присвоена, иначе
`(анонимная)`. `ВЫЗОВ` — текст вызываемого выражения (`render`, `api.fetch`). `строка` — первая строка функции или
вызова. Порядок — по строке.

## Побочные эффекты

Только чтение; с `--base` — `git merge-base` и `git diff` только для чтения.

## Конфигурация

Своей нет. Пределы 40 и 3 — правила монорепо, не ключи: ключ предела превратил бы правило в пожелание.

## Инварианты

- Предел включительный: 40 строк и глубина 3 — не нарушение, 41 и 4 — нарушение.
- Вложенная функция — своя запись в «глубоких» и своя в «длинных»; внешняя её глубину не наследует.
- Вызов с одним аргументом не бывает «флагом».
- Обратный вызов `describe` не попадает ни в один раздел.
- Команда только читает.

## Граничные случаи и ошибки

Отказы — те же, что у `literals` (нет адресов, адрес со строкой, нет файла, не `.ts`/`.tsx`, `--base` не разрешается),
с префиксом `mpu code shape: `. Файл с синтаксической ошибкой — строкой в «не разрешено», остальные адреса
разбираются. Нарушений нет — три раздела по `0`.

## Решения по отчёту CS1 (спецификатор, 2026-10-14)

Принято так, как реализовано:

- `new Foo(x, true)` — тоже вызов; печатается текстом вызываемого без `new`: `Foo(…)`.
- Вызываемое, записанное в несколько строк, печатается одной строкой: переводы строк с отступом снимаются
  (`foo\n  .bar(x, true)` → `foo.bar(…)`).
- Каждый булев литерал вызова — своя запись (`f(true, false)` — две записи).
- Флаги считаются везде, включая тело `describe` и верхний уровень файла; операторы управления тела `describe` и верхнего
  уровня глубину никому не дают.
- Имя записи: своё → `constructor` → переменная, свойство объекта или класса, `a.b = …` → `(анонимная)`. Конструктор и
  аксессоры меряются как методы; перегрузки и `declare` без тела не меряются.
- Строка записи и строки для `--base` — узел функции (у `export const g =\n  () => {…}` — строка стрелки).
- Исключается только `describe` в голове цепочки; `test.describe(…)` меряется.
- Порядок записей — прямой обход дерева: по началу узла, внешняя раньше вложенной.

## Пункты чек-листа

Универсальный `design.md`: 1 примитивы — «функция с её телом и строками» и «вызов с аргументами»; три раздела —
три измерения над ними. 2 особые случаи — `describe`-контейнер, вложенная функция, стрелка-выражение — свои
правила одного протокола «как мерить», не ветки в цикле. 3 — без `--base` фильтр «все строки изменены» (как у
`literals`). 4 — попадание в раздел решает измерение. 5 — ничего. 6 — вид функции — union на границе разбора.
7 — пределы включительные держатся голденом (`row` 40, `step` 3). 8 — ничего. 9 — пределы — правила монорепо, не
нагрузка. 10 — потребитель — приёмка: пустые разделы = правило соблюдено.

Проектный `design-mpu.md`: 1 — сообщение `shape` семейства `code`; 2 — видимость — `tool-policies.json`; 4 —
пределы — один источник (константы объявления команды), справка выводит их оттуда; 7 — `tslibs/cmd-code`, общие
с `literals` адрес, `--base` и шапка — одним модулем, не копией; остальное — ничего.
