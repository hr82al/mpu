# mpu code literals

Статус: к реализации (2026-10-14, порция CL1). Голден — `fixtures/code/literals-file.stdout.txt`.

## Назначение

Какие значения данных в этом файле повторены литералом и какая величина записана в двух формах. Повод
звать — приёмка и рецензия теста: правило чек-листа `review.md` п. 6 («данные теста, повторённые литералом
больше одного раза, — именованная константа; одна величина в двух форматах — одна константа»). Глазами по
диффу это не ловится: на живом файле теста `'2026-09-06'` стояло 31 раз, и четыре рецензии подряд этого не
назвали. Греп ловит повтор строки, но не отличает данные от адресов экрана (`data-testid`, подписи, роли,
названия тестов) и не видит одну величину в двух записях (`'101'` и `101`, `'2026-09-04'` и
`'04.09.2026'`).

## CLI-контракт

`mpu code literals АДРЕС... [--base REF] [--limit N]`

Политика — `ro`, команда видна агенту (вносится в `fixtures/mcp-server/tool-policies.json`). Объявление и
форма вывода — `platform/command-contract.md`; общий слой — `platform/code-analyzer.md` (рабочая область,
репозитории, отметка дерева, форма ответа).

**АДРЕС** — `[РЕПОЗИТОРИЙ:]ПУТЬ` к файлу `.ts` или `.tsx`; строки нет. Адресов может быть несколько, разделы
идут по одному на репозиторий, файлы внутри — в порядке путей.

**`--base REF`** — показывать только те записи, у которых хотя бы одно вхождение стоит на строке, добавленной
или изменённой относительно `merge-base REF HEAD` в рабочем дереве (как `git diff REF...` вместе с
незакоммиченным). Запись при этом печатается со всеми своими вхождениями: повтор складывается и из старых
строк. Без ключа — все записи файла.

**`--limit N`** — предел записей в каждом разделе, по умолчанию 200 (запись и счётчик усечения —
`platform/code-analyzer.md`).

Справка живёт в коде рядом с командой. Состав: вопрос в одностроке; первый абзац — момент (приёмка и рецензия
теста) и чем лучше грепа (отличает данные от адресов экрана, видит одну величину в двух формах); форма адреса;
что считается литералом данных и что исключено; оба раздела; `--base` и `--limit` с умолчанием; коды выхода;
полный пример вызова с разбираемым адресом.

## Что считается

**Литерал данных** — строковый литерал, строка атрибута JSX, шаблон без подстановок и числовой литерал (со знаком
минус перед ним — как одно значение) в выражении файла.

**Не считается** (адреса, имена и шум — закрытый список):

1. первый аргумент вызовов `describe`, `it`, `test` и их форм через точку (`it.each`, `describe.skip`,
   `test.only` …) — название теста; у `it.each(...)` / `test.each(...)` — первый аргумент второго вызова;
2. все аргументы, включая объект опций (`{ name: … }`), вызовов-поисков экрана:
   `(get|getAll|query|queryAll|find|findAll)By(TestId|Role|Text|LabelText|PlaceholderText|AltText|Title|DisplayValue)`
   — у объекта и у `screen`, `within(…)`. ⚠️ Исключение снимается только для **дат** (ниже): подпись дня в поиске
   экрана — вторая форма той же даты;
3. спецификатор модуля: `import`/`export … from`, `import(…)`, `require(…)`, первый аргумент `vi.mock`,
   `vi.importActual`, `jest.mock`;
4. имя свойства в объекте и в типе, литеральный тип в позиции типа;
5. значения `''`, `0`, `1`, `-1`.

**Равенство.** Строки равны по тексту, числа — по значению (`1e3` и `1000` равны).

**Даты — значения, где бы ни стояли.** Каждое вхождение даты `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ` внутри текста
строкового литерала (целиком или частью: `'from=2026-09-04'`) — вхождение этой даты; повтор даты считается по таким вхождениям одной записи
(`ГГГГ-ММ-ДД` отдельно от `ДД.ММ.ГГГГ`: разные записи одного дня — пара «двух форм», не повтор), а не по равенству
строк. Строка, целиком равная дате, повтором «строки» отдельно не считается.

**Две формы одной величины** — закрытый список пар:
- число и строка, чей текст — десятичная запись того же числа (`101` и `'101'`);
- дата `ГГГГ-ММ-ДД` и тот же день `ДД.ММ.ГГГГ` (`2026-09-04` и `04.09.2026`).

## Ввод/вывод

Шапка раздела репозитория — отметка дерева `platform/code-analyzer.md` **без поля гарантии**: команда разбирает
синтаксис отдельных файлов, полнота перечня от проекта не зависит. Дальше по каждому файлу, в порядке путей:
строка с путём от корня репозитория, под ней два раздела, записи — с отступом в два пробела:

**повторы: N** — по строке на значение, встречающееся в файле больше одного раза:

    ЗНАЧЕНИЕ ×K  строки A, B, …

`ЗНАЧЕНИЕ` — строка в одинарных кавычках, число цифрами, дата — `'ГГГГ-ММ-ДД'`. Порядок записей — по первой строке
вхождения; номера строк — по возрастанию, каждый один раз, а `K` считает вхождения.

**две формы: N** — по строке на пару из закрытого списка:

    ПЕРВАЯ ↔ ВТОРАЯ  строки A, B, …

Первая — число или дата `'ГГГГ-ММ-ДД'`, вторая — строка или `'ДД.ММ.ГГГГ'`; строки — вхождения обеих форм. Пара
печатается, даже если каждая форма встречается по одному разу. Порядок — как у «повторов».

После всех файлов репозитория — **не разрешено: N**: файлы, которые не разобрались (синтаксическая ошибка), по
строке `путь: причина`.

Вывод оканчивается одним переводом строки.

## Побочные эффекты

Только чтение (`platform/code-analyzer.md`); с `--base` — ещё `git merge-base` и `git diff` только для чтения.

## Конфигурация

Своей нет.

## Инварианты

- Исключённое (названия тестов, поиски экрана, модули, имена свойств, тривиальные значения) не попадает ни в
  один раздел ни при каком числе вхождений.
- Запись «повторов» — только при `K ≥ 2` в одном файле; между файлами повторы не складываются.
- С `--base` запись печатается целиком или не печатается; вхождения вне изменённых строк в ней остаются.
- Порядок — детерминированный; времени в выводе нет.
- Команда только читает.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu code literals: `, отказ — «ошибка и как исправить».

| Вход | Ожидаемое поведение |
| --- | --- |
| Адресов нет | exit 2, `нужен хотя бы один адрес файла: mpu code literals ПУТЬ.spec.tsx` |
| Адрес с номером строки (`путь:12`) | exit 2, `адрес — файл без строки: литералы считаются по всему файлу` |
| Файла нет | exit 2, `файла <путь> нет в репозитории <имя>` |
| Не `.ts`/`.tsx` | exit 2, `литералы считаются только в .ts и .tsx: <путь>` |
| `--base` не разрешается в коммит | exit 2, `базу <REF> не найти: git merge-base <REF> HEAD не ответил` |
| Файл с синтаксической ошибкой | exit 0, файл — строкой в «не разрешено», разделы по остальным адресам печатаются |
| Повторов и пар нет | exit 0, `повторы: 0`, `две формы: 0`, `не разрешено: 0` |
| Записей в разделе больше `--limit` | exit 0, строка `усечено: показано N из M` |

## Сценарии

Своё дерево-фикстура `literals-tree/` (рядом с `deno-tree/` и `broken-tree/`; общее дерево не трогается — его

1. Дано: `mpu code literals fixture:front/src/sample.spec.tsx`. Ожидается exit 0, stdout дословно (голден
   `fixtures/code/literals-file.stdout.txt`):

   ```

   front/src/sample.spec.tsx
   повторы: 2
     '2026-09-06' ×3  строки 5, 9, 10
     '2026-09-04' ×3  строки 18, 19

     '2026-09-04' ↔ '04.09.2026'  строки 17, 18, 19
   ```

   Не попадают: модули (1–3), названия тестов (7, 8, 15 — `'показывает день'` дважды), поиск экрана `'cell-day'`
   (10–12) и `'button'` (17), ключ `from` (19), значение `1` (12). `'04.09.2026'` в поиске экрана не повтор, но
   форма даты для пары.
2. Дано: тот же файл в git-репозитории, закоммичен с `sku='100'` на строке 16, в рабочем дереве — `sku='101'`;
   `mpu code literals <репо>:front/src/sample.spec.tsx --base HEAD`. Ожидается exit 0, после строки отметки дерева
   (её поля зависят от репозитория и в сравнение не идут):

   ```

   повторы: 0
   две формы: 1
     101 ↔ '101'  строки 9, 16
   не разрешено: 0
   ```
3. Дано: `mpu code literals` без адресов. Ожидается exit 2, stderr — отказ из таблицы, stdout пуст.
4. Дано: `mpu code literals fixture:front/src/sample.spec.tsx:12`. Ожидается exit 2, отказ «адрес — файл без
   строки», stdout пуст.
5. Дано: `mpu code literals help`. Ожидается exit 0, справка по составу из «CLI-контракта».
6. Дано: агент через MCP. Ожидается: тул `code literals` виден, политика `allow`.
7. Дано: два адреса — файл с синтаксической ошибкой и `fixture:front/src/sample.spec.tsx`. Ожидается exit 0, разделы
   второго — как в сценарии 1, первый — строкой в «не разрешено» с причиной разбора.
8. Дано: файл без повторов и пар. Ожидается exit 0, `повторы: 0`, `две формы: 0`, `не разрешено: 0`.

## Пункты чек-листа

Универсальный `design.md`:

| пункт | что изменил |
| --- | --- |
| 1 примитивы | два: «литерал данных файла с его значением и строкой» и «группа равных значений»; оба раздела выводятся из групп в одном месте |
| 2 особые случаи | каждая пара «двух форм» — своя реализация одного протокола «узнать пару», а не ветки по виду значения; исключения — закрытый список правил с одним протоколом «исключает ли узел» |
| 3 `null`/тип | отсутствие `--base` — объект «все строки изменены», не `undefined` в фильтре |
| 4 кто решает | попадание вхождения в вывод решает правило исключения и фильтр строк, не цикл печати |
| 5 память приватна | группа сама считает `K` и строки; снаружи не правится |
| 6 голые данные | вид литерала — закрытый union на границе разбора, дальше — протокол значения |
| 7 основание проверкой | «название теста и поиск экрана не попадают» — голден и мутация (сценарий 1) |
| 8 носители состояния | ничего — состояния нет |
| 9 лимит против нагрузки | `--limit 200` — живой файл теста Чек-листа (`ChecklistClient.spec.tsx`, 39 тестов) — порядка десяти записей; запас на порядок |
| 10 значение через потребителя | потребитель — приёмка и рецензия: пустые разделы = правило соблюдено |

Проектный `design-mpu.md`: 1 — сообщение `literals` получателя семейства `code`, рядом с `twins`; 2 — «видна
агенту» — решение политики (`tool-policies.json`), не поле; 3 — ничего; 4 — коды выхода и умолчание `--limit` —
один источник в объявлении команды; 5 — `K` берётся из подсчёта группы; 6 — новых прав нет (чтение файлов и `git`
уже есть у семейства); 7 — модуль `tslibs/cmd-code`; 8 — `git` и файловая система — ссылками анализатора; 9 — голден
снимает исполнитель прогоном и сверяет с правилами построчно (сценарий 1); 10 — пропускаемых проверок нет.
