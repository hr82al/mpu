# mpu code twins

Статус: к реализации (2026-09-08; голдены — `fixtures/code/`)

## Назначение

Есть ли у этого фрагмента близнец в другом файле. Два разных вопроса,
поэтому два раздела, которые не смешиваются: побайтовое совпадение тела
и совпадение после нормализации.

Копия находится не тогда, когда её ищут, а когда меняют соседний код, —
поэтому вход команды адрес, а не образец: тело извлекает она сама.

## CLI-контракт

`mpu code twins АДРЕС [--limit N]`

Политика — `ro`. Объявление и форма вывода —
`platform/command-contract.md`; общий слой — `platform/code-analyzer.md`.

**АДРЕС** — `[РЕПОЗИТОРИЙ:]ПУТЬ:СТРОКА`; строка обязательна. Тело берётся
у объявления-функции, охватывающего эту строку: объявления, стрелки,
метода. Окно поиска — репозиторий адреса.

**`--limit N`** — предел записей в каждом разделе, по умолчанию 200
(запись и счётчик усечения — `platform/code-analyzer.md`).

Справка листовой команды живёт в коде, рядом с самой командой
(`platform/registry.md`). Спека её не цитирует: два источника одного текста
расходятся молча. Спека задаёт **состав** — справка обязана называть форму
адреса и то, у какого объявления берётся тело; оба раздела и правило
нормализации «похожих»; значение и умолчание `--limit` (в записях, не в строках), коды выхода и хотя
бы один пример вызова — полный, а не фрагмент, и с адресом, который
разбирается; существования этого адреса на диске не требуется: пример,
ссылающийся на живой исходник, устаревает от первой же правки.

## Ввод/вывод

Шапка и раздел «не разрешено» — `platform/code-analyzer.md`. Свои
разделы:

**Строка запроса** — имя и сигнатура объявления, чьё тело взято.

**побайтово: N** — по строке на совпадение: `путь:строка  имя`.
Совпадением считается посимвольное равенство текста тела от открывающей
скобки до закрывающей включительно. Имя объявления в сравнении не
участвует: на живом коде три копии одного тела носили три разных имени.
Запрошенное тело стоит **первым**, вне общего порядка, и усечением не
режется; остальные идут в порядке `(репозиторий, путь, строка)`. Иначе
инвариант «раздел содержит запрошенное тело» держался бы только на
счётчике: при `--limit 2` на фикстуре запрошенное оказывается третьим по
порядку и выпадает из собственного ответа.

**похоже: N** — по строке на совпадение, под ней строка `разница: …`,
называющая, чем тела расходятся. Категорий четыре, и все они —
установленные расхождения: комментарии, литералы, имена, форматирование
(одни пробелы и переводы строк). Расхождение, не отнесённое ни к одной
из четырёх, печатается как `разница: не установлена`.

Разница между «форматированием» и «не установлена» существенна:
расхождение одними пробелами **установлено**, и называть его незнанием —
такая же подмена, как называть незнание форматированием.

Нормализация, по которой считается совпадение: комментарии сняты,
пробелы сжаты, параметры и локальные имена переименованы по порядку
появления, литералы заменены позиционными метками.

Литералы нормализуются намеренно: копия отличается от оригинала как раз
сообщением об ошибке и комментарием. Риск ложного сближения закрыт тем,
что раздел отдельный и разница печатается — решение остаётся за
читателем.

Тело, попавшее в «побайтово», в «похоже» не повторяется.

## Инварианты

- Сравнение идёт по телу; имя объявления на результат не влияет.
- Раздел «побайтово» содержит запрошенное тело первой строкой; усечение
  его не режет, и раздел не бывает пуст.
- Тело не попадает в оба раздела сразу.
- Нормализация для «похоже» снимает комментарии, сжимает пробелы,
  переименовывает параметры и локальные имена, заменяет литералы —
  и ничего сверх этого.
- У каждой строки раздела «похоже» есть строка разницы.
- Порядок строк — `(репозиторий, путь, строка)`, с единственным
  исключением: запрошенное тело стоит первой строкой раздела
  «побайтово». Исключение названо здесь, а не выведено из умолчания.
- Команда только читает.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu code twins: `.

| Вход | Ожидаемое поведение |
| --- | --- |
| Адрес без строки | exit 2, `нужна строка: тело берётся у объявления, охватывающего её` |
| Строка не покрыта объявлением-функцией | exit 2, `в строке <N> нет объявления-функции`, следом объявления файла |
| Объявление без тела (перегрузка, `declare`) | exit 2, `у объявления в строке <N> нет тела` |
| Репозиторий без единого проекта | отказ раздела с причиной `тела не разбираются текстовым анализатором: в репозитории <имя> нет ни одного проекта`; окно здесь — репозиторий адреса, поэтому раздел один и `exit 1` |
| Близнецов нет | exit 0, `побайтово: 1` (само запрошенное) и `похоже: 0` |
| Тело совпадает побайтово и после нормализации | попадает только в «побайтово» |
| Записей в разделе больше `--limit` | exit 0, строка `усечено: показано N из M` |

## Golden-примеры

`fixtures/code/`. Дерево-фикстура — `platform/code-analyzer.md`. Каждый
файл оканчивается одним переводом строки.

- `twins-exact.stdout.txt` — `twins fixture:src/window.ts:4`: три
  побайтово равных тела под тремя разными именами (`windowDays`,
  `dayGrid`, `daySeries`). Запрошенное стоит первым, остальные — в общем
  порядке; голден снят с этого правила, а не с прежнего. Тест обязан краснеть, если сравнение начнёт
  учитывать имя: тогда останется одно совпадение из трёх.
- `twins-similar.stdout.txt` — `twins fixture:src/loaderA.ts:2`: раздел
  «побайтово» пуст сверх самого запроса, а в «похоже» — одно тело,
  расходящееся снятым комментарием и текстом литерала. Тест обязан
  краснеть, если нормализация перестанет снимать комментарии или
  литералы: совпадение исчезнет.
