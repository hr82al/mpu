# mpu code twins

Статус: реализовано (2026-09-09, порции 100, 102; ответ сверен живым прогоном по рабочей области. Заморожена 2026-09-08; голдены — `fixtures/code/`)

## Назначение

Есть ли у этого фрагмента близнец в другом файле. Два разных вопроса,
поэтому два раздела, которые не смешиваются: побайтовое совпадение тела
и совпадение после нормализации.

Копия находится не тогда, когда её ищут, а когда меняют соседний код, —
поэтому вход команды адрес, а не образец: тело извлекает она сама.

## CLI-контракт

`mpu code twins АДРЕС [--limit N]` · `mpu code twins --base REF [--in РЕПОЗИТОРИЙ] [--limit N]` (раздел «Режим по диффу»)

Политика — `ro`. Объявление и форма вывода —
`platform/command-contract.md`; общий слой — `platform/code-analyzer.md`.

**АДРЕС** — `[РЕПОЗИТОРИЙ:]ПУТЬ:СТРОКА`; строка обязательна. Тело берётся
у объявления-функции, охватывающего эту строку: объявления, стрелки,
метода. Окно поиска — репозиторий адреса.

**`--limit N`** — предел записей в каждом разделе, по умолчанию 200
(запись и счётчик усечения — `platform/code-analyzer.md`).

Справка листовой команды живёт в коде, рядом с самой командой
(`platform/registry.md`). Спека её не цитирует: два источника одного текста
расходятся молча. Спека задаёт **состав** — справка обязана называть форму
адреса и то, у какого объявления берётся тело; оба раздела и правило
нормализации «похожих»; значение и умолчание `--limit` (в записях, не в строках), коды выхода и хотя
бы один пример вызова — полный, а не фрагмент, и с адресом, который
разбирается; существования этого адреса на диске не требуется: пример,
ссылающийся на живой исходник, устаревает от первой же правки.

## Ввод/вывод

Шапка и раздел «не разрешено» — `platform/code-analyzer.md`. Свои
разделы:

**Строка запроса** — имя и сигнатура объявления, чьё тело взято.

**побайтово: N** — по строке на совпадение: `путь:строка  имя`.
Совпадением считается посимвольное равенство текста тела от открывающей
скобки до закрывающей включительно. Имя объявления в сравнении не
участвует: на живом коде три копии одного тела носили три разных имени.
Запрошенное тело стоит **первым**, вне общего порядка, и усечением не
режется; остальные идут в порядке `(репозиторий, путь, строка)`. Иначе
инвариант «раздел содержит запрошенное тело» держался бы только на
счётчике: при `--limit 2` на фикстуре запрошенное оказывается третьим по
порядку и выпадает из собственного ответа.

**похоже: N** — по строке на совпадение, под ней строка `разница: …`,
называющая, чем тела расходятся. Категорий четыре, и все они —
установленные расхождения: комментарии, литералы, имена, форматирование
(одни пробелы и переводы строк). Расхождение, не отнесённое ни к одной
из четырёх, печатается как `разница: не установлена`.

Разница между «форматированием» и «не установлена» существенна:
расхождение одними пробелами **установлено**, и называть его незнанием —
такая же подмена, как называть незнание форматированием.

Нормализация, по которой считается совпадение: комментарии сняты,
пробелы сжаты, параметры и локальные имена переименованы по порядку
появления, литералы заменены позиционными метками.

Литералы нормализуются намеренно: копия отличается от оригинала как раз
сообщением об ошибке и комментарием. Риск ложного сближения закрыт тем,
что раздел отдельный и разница печатается — решение остаётся за
читателем.

Тело, попавшее в «побайтово», в «похоже» не повторяется.

## Инварианты

- Сравнение идёт по телу; имя объявления на результат не влияет.
- Раздел «побайтово» содержит запрошенное тело первой строкой; усечение
  его не режет, и раздел не бывает пуст.
- Тело не попадает в оба раздела сразу.
- Нормализация для «похоже» снимает комментарии, сжимает пробелы,
  переименовывает параметры и локальные имена, заменяет литералы —
  и ничего сверх этого.
- У каждой строки раздела «похоже» есть строка разницы.
- Порядок строк — `(репозиторий, путь, строка)`, с единственным
  исключением: запрошенное тело стоит первой строкой раздела
  «побайтово». Исключение названо здесь, а не выведено из умолчания.
- Команда только читает.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu code twins: `.

| Вход | Ожидаемое поведение |
| --- | --- |
| Адрес без строки | exit 2, `нужна строка: тело берётся у объявления, охватывающего её` |
| Строка не покрыта объявлением-функцией | exit 2, `в строке <N> нет объявления-функции`, следом объявления файла |
| Объявление без тела (перегрузка, `declare`) | exit 2, `у объявления в строке <N> нет тела` |
| Репозиторий без единого проекта | отказ раздела с причиной `тела не разбираются текстовым анализатором: в репозитории <имя> нет ни одного проекта`; окно здесь — репозиторий адреса, поэтому раздел один и `exit 1` |
| Близнецов нет | exit 0, `побайтово: 1` (само запрошенное) и `похоже: 0` |
| Тело совпадает побайтово и после нормализации | попадает только в «побайтово» |
| Записей в разделе больше `--limit` | exit 0, строка `усечено: показано N из M` |

## Режим по диффу (`--base`) — порция CT1 (2026-10-14)

Статус раздела: к реализации. Адресный режим выше не меняется.

### Зачем

Второй вход — дифф вместо адреса: какие из функций, тронутых изменением, уже есть в другом месте репозитория. Повод —
приёмка и рецензия: правило «одно знание в двух местах» (`review.md` п. 6) сегодня проверяется вопросом по одному
адресу, которого никто не задаёт, — копия находится, только когда её ищут. На поставке Чек-листа экран написал заново
календарь и разбор ответа, которые уже были рядом.

### CLI-контракт

`mpu code twins --base REF [--in РЕПОЗИТОРИЙ] [--limit N]`

- `--base REF` без адреса — режим по диффу; вместе с адресом — отказ (exit 2, `адрес и --base — разные вопросы:
  либо одно тело по адресу, либо тела, тронутые диффом`).
- **Тронутые тела** — объявления-функции (как у адресного режима) в файлах `.ts`/`.tsx` репозитория, чей диапазон
  строк в рабочем дереве пересекается с куском диффа по новой стороне (`git diff REF...` вместе с незакоммиченным,
  база — `merge-base REF HEAD`). Тело, из которого удалена строка, тронуто (кусок стоит на его диапазоне);
  переименование файла или функции с нетронутым телом — нет.
- `--in РЕПОЗИТОРИЙ` — репозиторий диффа; без него — репозиторий текущего каталога; текущий каталог вне репозитория
  рабочей области — отказ (`--base без --in: каталог вне репозитория рабочей области`).
- `--limit N` — как сейчас, на каждый раздел каждого тела.

### Ввод/вывод

Шапка — отметка дерева репозитория, как сейчас. Затем строка `тронуто тел: N, с близнецами: M`. Затем по блоку на
тело **с близнецами** — в порядке `(путь, строка)`: строка запроса (как у адресного режима — имя и сигнатура, впереди
`путь:строка`), под ней разделы «побайтово» и «похоже» той же формы, что у адресного режима, с одним отличием: само
тронутое тело в «побайтово» не печатается (оно названо строкой запроса), и раздел без совпадений не печатается. Тело
без близнецов блока не получает — его нет и в выводе, только в счёте `N`. В конце — `не разрешено: N`, как сейчас.
Вывод оканчивается одним переводом строки.

### Инварианты

- `N` — число тронутых тел, `M` — тех из них, у кого есть хотя бы одно совпадение вне себя; `M ≤ N`.
- Пара тел, тронутых обоими, печатается в блоке каждого: копия, внесённая одним диффом в два места, видна с обеих
  сторон.
- Тело, не тронутое диффом, строкой запроса не бывает, но близнецом — бывает.
- Адресный режим не меняется: его голдены прежние.

### Граничные случаи

| Вход | Ожидаемое поведение |
| --- | --- |
| `--base` вместе с адресом | exit 2, отказ выше |
| `--base` не разрешается в коммит | exit 2, `базу <REF> не найти: git merge-base <REF> HEAD не ответил` |
| Дифф не трогает ни одного тела | exit 0, `тронуто тел: 0, с близнецами: 0`, `не разрешено: 0` |
| Тронутое тело без близнецов | не печатается, учтено в `N` |

### Сценарии

Фикстура — временный git-репозиторий теста (`mkdtemp` + уборка) с копией дерева `fixture:back/src/` из голденов
`twins-*` (три побайтово равных тела `windowDays`, `dayGrid`, `daySeries` и пара `loaderA`/`loaderB`, похожих после
нормализации), закоммиченной как база. Строка отметки дерева в сравнение не идёт.

Ожидаемый вывод — после строки отметки дерева, побайтово; пути и разница — в форме адресного режима (голден
`twins-similar.stdout.txt`: `src/loaderA.ts:2 utcDayList (from: string, to: string): string[]`, похожее —
`src/loaderB.ts:2`, разница `комментарий снят; литерал 'accrual window is not a date' против 'buyout window is not
a date'`; `src/broken.ts` дерева даёт строку в «не разрешено»).

1. В `src/loaderA.ts` литерал `'accrual window is not a date'` заменён на `'accrual window is not a day'`; `--base HEAD`:

   ```
   тронуто тел: 1, с близнецами: 1

   src/loaderA.ts:2  utcDayList (from: string, to: string): string[]

   похоже: 1
     src/loaderB.ts:2  utcDayList
       разница: комментарий снят; литерал 'accrual window is not a day' против 'buyout window is not a date'

   не разрешено: 1
     src/broken.ts:3 → ./nowhere — модуль не найден
   ```
2. Добавлен файл `src/loaderC.ts` с функцией `utcDayList`, побайтово равной телу из `src/loaderA.ts`, в строке 2;
   `--base HEAD`:

   ```
   тронуто тел: 1, с близнецами: 1

   src/loaderC.ts:2  utcDayList (from: string, to: string): string[]

   побайтово: 1
     src/loaderA.ts:2  utcDayList

   похоже: 1
     src/loaderB.ts:2  utcDayList
       разница: комментарий снят; литерал 'accrual window is not a date' против 'buyout window is not a date'

   не разрешено: 1
     src/broken.ts:3 → ./nowhere — модуль не найден
   ```
3. Изменена строка вне всех тел (импорт) → `тронуто тел: 0, с близнецами: 0`.
4. Две новые функции с одинаковыми телами в двух новых файлах → `тронуто тел: 2, с близнецами: 2`, каждая — в блоке
   другой.
5. `--base HEAD` вместе с адресом → exit 2, отказ.
6. `mpu code twins help` → справка называет оба режима; однострока и первый абзац — по составу `code-twins.md`
   плюс повод режима по диффу.

### Решения по отчёту CT1 (спецификатор, 2026-10-14)

Принято, как реализовано: тронутость считается по отрезку текста тела от `{` до `}` (правка левее `{` — имя, параметры,
тип возврата — тело не трогает); неравная замена строк считает новые строки изменёнными целиком; переименование файла
видно, когда о нём знает git (коммит или индекс), простой `mv` без `git add` — новый файл целиком; дифф берётся только
по `*.ts`/`*.tsx`; `--in` без `--base` — отказ `--in — репозиторий диффа: только вместе с --base`; ни адреса, ни
`--base` — отказ `адрес обязателен: [РЕПОЗИТОРИЙ:]ПУТЬ:СТРОКА либо --base REF`; окно разбора — все проекты репозитория.

Доводка CT1b (меняет поведение):

- **Тело без операторов** (`{}` — пустой конструктор, `check(): void {}`, `async () => {}`) не бывает ни телом запроса,
  ни близнецом — в обоих режимах. Живой прогон: 7 блоков из 10 были пустыми телами с 429 «близнецами» каждое. В `N`
  такие тела не входят. В адресном режиме адрес на пустое тело — отказ exit 2: `у объявления в строке <N> пустое
  тело — близнецов не ищем`.
- **Тронутый `.ts`/`.tsx` вне всех проектов** — строкой в «не разрешено»: `путь: файл вне проектов — тела не
  разбираются`. В `N` не входит.

### Пункты чек-листа режима

Универсальный `design.md`: 1 примитив прежний — «тело и его близнецы»; режим по диффу — второй источник тел запроса,
не вторая команда. 2 — два режима — две реализации протокола «откуда тела запроса» (адрес / дифф), не флаг в цикле.
3 — без близнецов тело просто не печатается, без `null`-веток в печати. 4 — что печатать, решает блок тела.
7 — «пара, тронутая обоими, — в обоих блоках» держится сценарием 4. Остальные — ничего.

Проектный `design-mpu.md`: 1 — то же сообщение `twins`, новый ключ; 4 — коды выхода и умолчание `--limit` — прежний
источник; 7 — `--base` и разбор диффа — общий модуль с `literals` и `shape`, не третья копия; остальное — ничего.
