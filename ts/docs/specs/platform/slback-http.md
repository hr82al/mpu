# platform/slback-http — HTTP-обвязка sl-back

Статус: черновик

## Назначение

Общая обвязка неймспейса `mpu api` (спеки `api.md`, `api-*.md`): резолв
базового URL, креды и логин, файловый кэш JWT-токена, форма
HTTP-запросов к sl-back и формат ошибок. Контракт возможности — не
Go-API.

## Ввод/вывод

### Базовый URL

Резолв по env, применяется первое правило с выполненным условием:

1. `BASE_API_URL` непуст и начинается с `http` → он и есть база;
   хвостовые `/` срезаются.
2. Непусты `BASE_API_URL` (path) и `NEXT_PUBLIC_SERVER_URL` (host) →
   host без хвостовых `/` + `/` + path без ведущих `/`.
3. Непуст только `NEXT_PUBLIC_SERVER_URL` → он без хвостовых `/`.
4. Иначе — ошибка до любого сетевого вызова: `sl-back base URL не
   задан. Поставь BASE_API_URL (full URL) или NEXT_PUBLIC_SERVER_URL
   (host) + BASE_API_URL (path) в <путь env-файла>`.

### Креды и токен

- Креды — env `TOKEN_EMAIL` / `TOKEN_PASSWORD`; любой из них пуст →
  ошибка `sl-back credentials missing: <недостающие имена через
  запятую+пробел>. Add to <путь env-файла> or export in shell.`.
- Токен-кэш (`TokenCache`) — файл
  `$XDG_CONFIG_HOME/mpu/.api-token.json` (дефолт
  `~/.config/mpu/.api-token.json`), JSON
  `{"token": <строка>, "expires_at": <unix-секунды>}`. Запись жива,
  пока `now < expires_at`; TTL при записи — 600 s от момента
  получения (константа, env не читается).
- Чтение кэша: файл отсутствует / не читается / битый JSON / не
  объект / `token` не строка / `expires_at` не число / просрочен →
  кэша нет; это не ошибка.
- Получение токена: валидный кэш → его токен, без сети; иначе
  `POST /auth/login` без авторизации с телом `{"email", "password"}`
  → из ответа берётся `accessToken` (непустая строка, иначе ошибка
  `sl-back login: нет accessToken в ответе: <JSON ответа, обрезан до
  200>`) → токен пишется в кэш и используется.
- Запись кэша: атомарная (временный файл + переименование), права
  файла 0600; сбой записи не влияет на исход команды (см. «Известные
  отклонения»).

### Запрос

- URL = база + путь (ведущий `/` добавляется, если его нет).
  Query-параметры: пары со значением не-null URL-кодируются и
  добавляются через `?` (либо `&`, если `?` уже есть в URL).
- Заголовок `authorization: Bearer <токен>` — на каждом запросе,
  кроме `POST /auth/login`. JSON-тело сопровождается заголовком
  `Content-Type: application/json`; запрос без тела его не несёт.
- Таймаут — 30 s на запрос (константа). Одна попытка: ретраев и
  backoff нет ни для какого исхода.

### Ответ и ошибки

- Транспортная ошибка (DNS, соединение, таймаут) → ошибка
  `<METHOD> <путь> failed: transport error: <причина>`.
- HTTP ≥ 400 → ошибка `<METHOD> <путь> failed: HTTP <код>`; статус и
  тело ответа (обрезано до 500) сохраняются — вызывающая команда
  печатает тело отдельной строкой.
- 2xx с пустым телом → «нет данных», не ошибка.
- 2xx с телом не-JSON → ошибка
  `<METHOD> <путь>: non-JSON response: <тело, обрезано до 200>`.
- Иначе результат — разобранный JSON любого типа (объект / массив /
  строка / число / null).
- Маркер обрезки во всех текстах: после первых N символов —
  `…(+<число> bytes)`.
- `<путь>` в текстах ошибок — путь запроса без базового URL.

## Побочные эффекты

Сеть — только sl-back (база из env). Запись — только файл токен-кэша.
Реакция CLI на ошибки обвязки (префикс команды, exit-код) — `api.md`.

## Конфигурация

- `BASE_API_URL` — полный URL (начинается с `http`) либо path-префикс
  к host.
- `NEXT_PUBLIC_SERVER_URL` — host; обязателен, если `BASE_API_URL` не
  полный URL.
- `TOKEN_EMAIL`, `TOKEN_PASSWORD` — креды `/auth/login`.
- Все — из env-файла mpu либо окружения (контракт слоя —
  `platform/config.md`); `XDG_CONFIG_HOME` смещает и env-файл, и
  токен-кэш.

## Инварианты

- Одна попытка на запрос; никакой исход не ретраится.
- `POST /auth/login` — единственный запрос без авторизации; все
  прочие несут Bearer-токен.
- Токен и пароль не попадают в тексты ошибок обвязки.
- TTL кэша — фиксированные 600 s wall-clock; срок годности самого JWT
  не проверяется.
- Кэш общий для всех процессов; атомарная запись исключает чтение
  полузаписанного файла. Файловой блокировки нет: при параллельных
  процессах допустимы дублирующие login, последняя запись побеждает.
- Query-пара со значением null не попадает в URL.

## Граничные случаи и ошибки

- Оба env базового URL пусты → ошибка базового URL до сети (в том
  числе в `--print`-режимах команд, которым нужна база).
- Кэш-файл битый или просрочен на 1 s → тихий re-login, не ошибка.
- 2xx с HTML-телом → `non-JSON response`, несмотря на успешный
  статус.
- Логин вернул 2xx без `accessToken` → ошибка «нет accessToken».
- HTTP ≥ 400 с пустым телом → сохранённое тело пусто, вызывающая
  команда extra-строку не печатает.

  влияет на исход команды.
