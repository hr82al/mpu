# Супервизор и установка рядом со старым `mpu`

Статус: реализовано — порция 145 (`1161f2b`); принято 2026-09-18: гейты зелёные (тестов 2173, smoke 21/1); живая установка хостом на машину оператора — `install: готово`, служба `mpu-next` активна на 7338/7339, старая `mpu-mcp` на 7337 не тронута; повтор — «без изменений», перезапусков нет; `USR1` — новый `mpu-back`, `mpu-mcp` тот же; `kill -9` `mpu-back` — поднят через 1 с.

## Назначение

Новые части (`mpu-back`, `mpu-mcp`, `mpu-next`) становятся установленными
программами и службой пользователя, которая сама их поднимает и
перезапускает. Ставятся они **рядом** со старым `mpu`: другие имена программ,
другая служба, другие порты. Старый `mpu`, `mpu mcp`, служба `mpu-mcp.service`
и порт 7337 не трогаются — переключение отдельной порцией.

## Части

| Программа | Из чего собирается | Что делает |
|---|---|---|
| `mpu-supervisor` | новый подпроект `ts/supervisor/` | единственное, что запускает служба; держит `mpu-back` и `mpu-mcp` |
| `mpu-back` | `back/back.ts` | сервер строк, порт 7338 |
| `mpu-mcp` | `mcp/main.ts` | переводчик MCP, порт 7339 |
| `mpu-next` | `cli/main.ts` | тонкий клиент |

Каждая программа на `--version` печатает версию сборки одной строкой и
выходит с кодом 0, ничего не поднимая.

Сборка — задачами `compile:back`, `compile:mcp`, `compile:cli`,
`compile:supervisor` корневого `deno.jsonc`: права каждой — те же, что у
задачи запуска (`back`, `mcp`, `cli`; у супервизора — свои, ниже), путь
результата — переменной окружения `MPU_OUT` (`-o $MPU_OUT` в задаче: `deno
task` дописывает аргументы в конец, а у `deno compile` всё после скрипта —
аргументы самой программы). У `compile:back` — те же `--include`, что у задачи
`build` (воркер разбора кода и два `.wasm` Telegram): без них собранный
`mpu-back` падает на `code` и `telegram`. Права и состав сборки названы в одном
месте — в задачах.

## Супервизор

```
mpu-supervisor --back <путь> --mcp <путь>
```

| Событие | Поведение |
|---|---|
| старт | запускает оба дочерних: `<back> --port 7338`, `<mcp> --port 7339` |
| дочерний завершился сам (любой код) | перезапускает **только его**; паузы 1, 2, 4, 8, 16, 30, 30… секунд подряд идущих падений; проработал ≥ 60 секунд — счёт паузы сначала |
| `SIGUSR1` | перезапуск `mpu-back` (остановка сигналом `SIGTERM`, затем запуск); `mpu-mcp` не трогается |
| `SIGUSR2` | то же для `mpu-mcp` |
| `SIGTERM`, `SIGINT` | `SIGTERM` обоим, ждёт до 10 секунд, оставшимся — `SIGKILL`; код 0 |
| дочерний не запустился (нет файла, нет прав) | строка в stderr, дальше как при падении |

Вывод дочерних — в stdout/stderr супервизора построчно, с префиксом
`[back] ` или `[mcp] `. Строки супервизора — с префиксом `[supervisor] `.
Порты и адрес `back` для `mcp` (`MPU_BACK_URL`) — из флагов/окружения, по
умолчанию 7338/7339.

Права задачи `supervisor`: запуск двух программ из `$HOME/.local/bin`, сигналы
(`--allow-run` на эти пути), окружение `HOME`. Ни сети, ни файлов.

## Служба

`$XDG_CONFIG_HOME/systemd/user/mpu-next.service` (по умолчанию
`$HOME/.config/systemd/user/`), ровно такая (эталон —
`fixtures/supervisor-install/mpu-next.service`):

```ini
[Unit]
Description=mpu-next: сервер строк и переводчик MCP
After=default.target
StartLimitIntervalSec=60
StartLimitBurst=5

[Service]
Type=simple
ExecStart=%h/.local/bin/mpu-supervisor --back %h/.local/bin/mpu-back --mcp %h/.local/bin/mpu-mcp
Restart=on-failure
RestartSec=2

[Install]
WantedBy=default.target
```

## `ts/install.sh`

Чистый shell (bash), нужны только `deno`, `systemctl`, `sha256sum`, `curl`.
Запущенный `mpu` ему не нужен. Вызов из `ts/`:

```
./install.sh [--only back,mcp,cli,supervisor] [--check]
```

Порядок, каждый шаг печатает одну строку `install: <шаг>: <итог>`:

1. **Сборка** выбранных частей во временный каталог рядом с целью
   (`$MPU_BIN_DIR`, по умолчанию `$HOME/.local/bin`) задачами `compile:*`.
   Каждая собранная программа отвечает на `--version`, иначе — отказ шага.
2. **Сравнение** с установленной по sha256. Одинаковы — часть «без изменений»,
   не ставится и не перезапускается.
3. `--check` — на этом остановиться, ничего не ставить, код 0.
4. **Установка** изменившихся: `mv` поверх цели (атомарная подмена в том же
   каталоге).
5. **Служба**: файла нет или он отличается от эталона — записать,
   `systemctl --user daemon-reload`, `systemctl --user enable mpu-next`.
6. **Перезапуск**: служба не активна — `start`; изменился `mpu-supervisor` или
   файл службы — `restart`; иначе для каждого изменившегося дочернего —
   сигнал **только главному процессу службы** (супервизору):
   `systemctl --user kill --kill-whom=main -s USR1 mpu-next` для `mpu-back`,
   `-s USR2` для `mpu-mcp` (изменились оба — оба сигнала). Без
   `--kill-whom=main` systemd шлёт сигнал всем процессам службы, и дочерние,
   для которых `USR1`/`USR2` — завершение, падают. Ничего не изменилось —
   ничего.
7. **Проверка** (до 15 секунд на каждую): `GET …:7338/health` и
   `GET …:7339/health` → 200; у перезапущенной части — ожидание ответа с
   **другим** `pid`, чем снятый до перезапуска (служба была активна);
   `POST …:7339/mcp` без токена → 401; `mpu-next version` → код 0 и версия
   сборки.

Итог: всё прошло — последняя строка `install: готово`, код 0. Любой шаг упал —
строка `install: <шаг>: ошибка: <причина>`, код 1, следующие шаги не
делаются; уже подменённые программы остаются (откат — повторный запуск с
предыдущей ревизии дерева).

Переопределения окружением — для тестов: `MPU_BIN_DIR`, `MPU_UNIT_DIR`,
`MPU_SYSTEMCTL` (команда вместо `systemctl`), `MPU_DENO` (команда вместо
`deno`: в тестах поддельная сборка — маленькая программа с `--version` или
отказ), `MPU_BACK_URL`, `MPU_MCP_URL`. Настоящая сборка `compile:back`
проверяется отдельным тестом: бинарь отвечает на `--version` и несёт воркер и
`.wasm`. Версия сборки у всех четырёх программ — из одного места (`back`,
отдаётся соседям через контракт кадров). Задаче `test` для запуска
`install.sh` добавляется `--allow-run` на `/bin/bash` (решение хоста, порция
145).
Файл службы от них не зависит — он всегда эталонный и ссылается на
`%h/.local/bin`; с переопределённым `MPU_BIN_DIR` живой `systemctl` не
используется (только поддельный).

## Инварианты

- Ни `install.sh`, ни супервизор не трогают `~/.local/bin/mpu`,
  `mpu-mcp.service` и порт 7337.
- Повторный `install.sh` без изменений в дереве ничего не ставит и не
  перезапускает.
- Перезапуск одного дочернего не меняет PID другого.
- После остановки супервизора не остаётся ни одного дочернего процесса.

## Граничные случаи и ошибки

| Дано | Ожидается |
|---|---|
| `mpu-back` упал 3 раза подряд | паузы 1, 2, 4 с; `mpu-mcp` жив, PID прежний |
| `mpu-back` проработал 60 с и упал | пауза снова 1 с |
| `SIGUSR1` | `mpu-back` новый PID, `mpu-mcp` прежний |
| `SIGTERM`, дочерний не реагирует 10 с | `SIGKILL`, супервизор — код 0 |
| `install.sh` второй раз подряд | все части «без изменений», перезапусков нет, `install: готово` |
| `install.sh --only mcp` после правки `mcp/` | собран и поставлен только `mpu-mcp`, `kill -s USR2`, остальное не тронуто |
| сборка `back` упала | `install: сборка back: ошибка: …`, код 1, ничего не поставлено |
| проверка `health` не дождалась 200 | `install: проверка back: ошибка: …`, код 1 |
| `install.sh --check` | шаги 1–2, код 0, в `$MPU_BIN_DIR` и `$MPU_UNIT_DIR` ничего не изменилось |

## Пункты чек-листа

`design.md`:

1. Примитивы — изменил: у супервизора два примитива — запустить дочерний и
   дождаться его конца; перезапуск, пауза, остановка выводятся из них [D.1].
2. Особые случаи → получатели — изменил: каждый дочерний — объект со своей
   паузой и своим процессом, сигнал адресуется ему, а не ветка по имени [D.2].
3. Проверка `null` — изменил: «процесса сейчас нет» (пауза) — состояние
   дочернего, не `null` в поле [D.2].
4. Кто решает — изменил: когда перезапускать и с какой паузой — сам дочерний
   [D.2].
5. Память приватна — изменил: PID и счёт падений — внутри дочернего [D.2].
6. Голые данные → протокол — изменил: сигнал → действие над конкретным
   дочерним, одна таблица на границе [D.3].

`design-mpu.md`:

1–3 — ничего: команд нет.
4. Один факт — один источник — изменил: права сборки — только в задачах
   `deno.jsonc`; `install.sh` их не повторяет [D.4].
5. Величина из результата — изменил: «без изменений» — по sha256 собранного,
   а не по времени файлов [D.5].
6. Права Deno — изменил: у супервизора — запуск двух программ и окружение
   `HOME`, больше ничего [D.4].
7. Границы модулей — изменил: `ts/supervisor/` не импортирует соседей [D.1].
8. Внешнее ссылкой — изменил: каталоги, `systemctl`, адреса — переопределяемы
   окружением; часы супервизора — параметр [D.6].
9. Голден снятый — изменил: файл службы — эталон в канале [D.4].
10. Пропускаемая проверка — изменил: проверки `install.sh` не пропускаются —
    нет сервиса, значит ошибка [D.5].

[D.1] Два примитива. [D.2] Дочерний — объект. [D.3] Сигнал — на границе.
[D.4] Права и эталон — в одном месте. [D.5] По хэшу, без пропусков.
[D.6] Всё внешнее — переопределяемо.
