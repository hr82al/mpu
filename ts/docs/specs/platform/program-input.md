# Программа из stdin и из файла

Статус: черновик (переработка 2026-09-25, не принята хостом) — к реализации — порция 170 (после 169).

## Назначение

Длинную программу неудобно и не всегда возможно передать словами командной
строки (предел `ARG_MAX`, кавычки оболочки). Программа приходит из stdin или
из файла; разбор — тот же, что у слов строки (`evaluator.md`).

## Контракт

| Вызов | Итог |
|---|---|
| `mpu` без слов, stdin не терминал, ввод не пуст | программа — stdin целиком |
| `mpu` без слов, stdin не терминал, ввод пуст или только из разделителей и BOM | справка корня, код 0, как прежде (решение владельца) |
| `mpu` без слов, stdin терминал | справка корня, как прежде |
| `mpu ask` без слов, stdin не терминал | программа из stdin с начальным `ask`; ввод пуст — справка `ask`, как прежде |
| `mpu run: <путь.mpu> [<ключ>: <значение>]…` | программа из файла; ключи — параметры |
| `mpu ask run: <путь.mpu> …` | то же с начальным `ask` |
| MCP `["run:", "<путь.mpu>", …]` | то же; путь абсолютный или от cwd строки — у MCP это домашний каталог (`mcp-objects.md`); `~` не раскрывается |
| `mpu run: help` | справка `run:` (`help` значением `run:` — справка, не путь) |

- **Как stdin-программа доходит до сервера.** Кадры прежние
  (`stdin-on-request.md`): клиент шлёт `words: []` (или `["ask"]`) и
  `stdinOnRequest: true`; сервер сразу отвечает `stdinRequest`, текст кадра
  `stdin` — программа. Решает сервер: строка без слов (или только `ask`) с
  вводом — программа из ввода, без ввода или с пустым вводом — справка. Тем
  же правилом `POST /line` с `{"words": [], "stdin": "2 plus: 2"}` исполняет
  программу. Правило одно у обеих дверей WebSocket (`/line`, `/agent/line`):
  через `/agent/line` программа с `ask`-командой получает «спросить некого»,
  код 1. MCP ввода не передаёт (`words` — не пустой список): программа у
  агента — только `run:`.
- **Исключение из 165c.** Голый `mpu` (и `mpu ask`) при stdin-канале без
  писателя ждёт ввода: `sleep 999 | mpu` висит до Ctrl+C. Строки со словами —
  как прежде (`sleep 999 | mpu version` отвечает сразу).
- **Ввод у stdin-программы занят программой.** Команда, читающая ввод
  (значение `stdin`, `-` прежних подстановок), получает отказ при исполнении,
  код 2, в форме «stdin уже прочитан» (`value-expression.md`):
  `mpu <путь команды>: ввод занят программой — программу передай файлом:
  mpu run: <файл.mpu>`.
  Команды до неё исполнены; вопрос двери к ней задаётся до отказа (ввод
  запрашивается после ответа, `stdin-on-request.md`). У `run:` и набранной
  строки ввод свободен.
- **`run:`** — только первым словом строки (после необязательного `ask`).
  Строка, начатая `run:`, — вызов источника, а не программа, даже если в
  значении параметра есть `^` (`col: ^готово к ревью^` идёт тем же путём,
  что `col: review`). `run:` в другом месте — в набранной программе, в тексте
  файла, в теле блока или `define:` — отказ разбора до исполнения:
  `выражение N: run: — только первым словом строки`. Вложенных файлов нет,
  предела глубины не нужно. `stdin` значением `run:` — путь, а не ввод.
- **Файл программы.** Отказы — до чтения файла, в этом порядке:
  1. последний сегмент набранного пути не кончается на `.mpu` — «программа —
     файл .mpu»;
  2. набранный путь (после разрешения относительного и `..`) лежит в
     каталоге настроек — «каталог настроек mpu программой не читается».
     Каталогов два, оба — окружения сервера строк: `$HOME/.config/mpu`
     (токены) и `$XDG_CONFIG_HOME/mpu` (`.env`; не задан — совпадает с
     первым);
  3. пути нет (и висячая ссылка) — «нет файла <полный набранный путь>»;
  4. реальный путь (ссылки раскрыты) лежит в каталоге настроек — отказ 2;
  5. реальный путь не кончается на `.mpu` — «программа — файл .mpu, а <путь>
     ведёт в <реальный путь>»;
  6. не обычный файл (каталог, канал, устройство) — «не файл <полный путь>»;
  7. у файла больше одной жёсткой ссылки — «у файла несколько ссылок —
     программой не читается»: так закрыт хардлинк на токен или ключ, который
     по пути не отличить;
  8. нет права чтения — «нет права чтения <полный путь>».
- **Текст → слова:** разделители — ровно пробел U+0020, табуляция U+0009,
  U+000A, U+000D; неразрывный пробел U+00A0 и прочие — часть слова. Этот же
  набор — у правила «слово с пробельным символом — как есть»
  (`at-word-literal.md`, правило 1). Это правка: сейчас там любой пробельный
  символ JS (`/\s/`), и слово MCP с U+00A0 берётся как есть; после порции
  такое слово — обычное, `^` в его начале открывает текст (строка MCP ниже).
  BOM (`EF BB BF`) в начале снимается у файла и у stdin одинаково. Байты не в
  UTF-8 — отказ до исполнения: байт — первый байт неверной
  последовательности, смещение — от начала файла или ввода, BOM включён
  (у значения `stdin` строки — как прежде, без проверки). Своих кавычек нет:
  строка из терминала работает в файле и наоборот, `^…^` — текст из
  нескольких слов.
- **Параметры** (`run:`): внутри программы — только `@<имя>` (`@col`).
  Значение — текст, как у ключа-текста (`at-word-literal.md`): одно слово как
  есть, `^…^` — из нескольких слов, `-- x` — экранирование, `stdin` — ввод
  строки; число не распознаётся (`n: 5` → текст «5»). Ключ пишется `col: v` и
  `--col v`.
  - Голое имя параметра (`col`) параметром не становится: оно — команда или
    текст, как без параметра. `@<имя>` значением ключа-текста — текст (167b):
    `@kalabass` параметра не ждёт. В ключ-текст параметр — группой: `text: do
    @msg end`.
  - Использованный — `@<имя>` там, где переменная толкуется, и не связанный
    самой программой. Использованный, но не переданный — отказ до исполнения;
    переданный, но не использованный — не ошибка; переданный, когда программа
    связывает то же имя (`col :=` или параметр блока `:col`), — отказ до
    исполнения.
- **Программа из stdin** параметров не принимает: `@x` — отказ 166 «не
  связана».
- **`ask`** первым словом текста программы — то же, что `mpu ask run:`:
  начальный `ask` объявляет, вопрос человеку — на каждую запись
  (`ask-composite.md`); без человека — «спросить некого», код 1. `ask` и
  снаружи, и в тексте — лишний, не отказ. Дверь `ask` понимает `run:` —
  исключение из «дверь не понимает сообщений корня» (`ask-door.md`): `run:` —
  источник программы, а не сообщение корня; программа проходит обход 167.
  Справка двери (`mpu ask help`) показывает `run:` в «Сообщениях».
- **Правила:** `run:` — не узел правил (как `ask`, `ask-door.md` [D.4]): в
  `policy` его нет; строку решают правила команд программы (обход 167).
- **Отказ программы и источник.** Источник — набранная строка целиком, с
  `ask`, если он набран (`mpu ask run: x.mpu col: review`), или `stdin`.
  Префикс «<источник>: » получают: отказы источника (файл, параметры, пустая
  программа, UTF-8 файла), отказы разбора и вычисления программы
  («выражение N: …»), отказ обхода «строка может записать». Как у
  однокомандной строки, без префикса источника: отказы правил и двери на
  команду (`mpu sql: запрещено правилом «sql»`, `…: не подтверждено`,
  `…: нужно подтверждение, а спросить некого`), отказ «ввод занят
  программой», stderr самих команд. Отказы клиента о вводе (предел, UTF-8
  stdin) — `mpu: …`, как прежний отказ о пределе. Текст программы в отказ не
  попадает: готовой строки из слов программы нет, `refusal.hint` — `null`,
  `candidates` остаются (`kitn` → `["kiten"]`); это перекрывает
  `refusal-object.md` «одна ближайшая → hint» для программ из stdin и файла.
  Отказ «строка может записать» даёт `hint` из слов источника (`["ask",
  "run:", "x.mpu"]`, у stdin — `["ask"]`).
- **`refusal.reason` новых отказов** (код 2, объект — `refusal-object.md`):
  `программа пуста`, `нет файла`, `программа — файл .mpu`, `каталог
  настроек не читается`, `не файл`, `несколько ссылок`, `нет права чтения`,
  `файл не в UTF-8`, `ждёт параметр`, `совпадает с переменной` (и для `:=`,
  и для параметра блока), `ввод занят программой`, `run: не первым словом`.
  Отказы клиента (`mpu: ввод не в UTF-8 …`, `mpu: ввод больше 8 МиБ`) объекта
  не дают: до сервера строка не дошла.
- **Предел:** у файла — нет (решение владельца); у программы из stdin — 8
  МиБ, прежний предел ввода у клиента (`stdin-on-request.md`). Снять его —
  отдельная правка, не в 170. Память — сторож (`line-executor.md`).
- **Журнал вызовов:** запись строки — как набрана (`$ mpu run: x.mpu col:
  review`; из stdin — `$ mpu`), без текста программы. Маскирование этой
  записи решают команды программы тем же обходом 167: есть команда, которая
  свои аргументы не журналирует, — маскируется вся строка, как у набранной
  программы (путь пуст — каждое слово `REDACTED`). Записи на каждую дошедшую
  команду (`evaluator.md`, `ask-composite.md`) остаются.
- **Смежные спеки** правятся вместе с порцией (до постановки): `stdin-on-
  request.md` — исключение 165c и сервер, запрашивающий ввод сразу у строки
  без слов; `at-word-literal.md` правило 1 — набор разделителей;
  `ask-door.md` — `run:` в двери и её справке; `refusal-object.md` — у
  программ из stdin и файла `hint` нет и при одной ближайшей.

## Инварианты

- Содержимое файла, чей набранный или реальный путь не `.mpu`, файла в
  каталоге настроек и файла с несколькими ссылками не появляется ни в
  stdout, ни в stderr, ни в `refusal`/`hint`, ни в журнале: файл не
  открывается.
- Одна и та же программа даёт одни и те же слова из файла и из stdin, с BOM и
  `\r\n` или без.
- Ни одна `ask`-команда программы не исполняется без своего «да» человека.
- Отказ программы не повторяет её текст.
- Значение параметра команды, не журналирующей аргументы, не попадает в
  журнал.

## Граничные случаи

Стенд: Kaiten и Telegram подменённые, реестр — как в `ask-composite.md`:
`kiten ls` — `allow`, три карточки с `id` 11, 12, 13; `kiten comment` —
`ask`, stdout пуст, запоминает «<id> <текст>»; `telegram send` — `allow`,
stdout пуст, запоминает «<chat> <текст>»; `telegram log message: <текст>` —
`allow`, stdout пуст, аргументы не журналирует; `sql` — `deny`. Домашний
каталог — `/home/u`, каталог вызова — `/home/u/w`; `x.mpu` —
`/home/u/w/x.mpu`; сервер строк запущен с `XDG_CONFIG_HOME=/home/u/xdg`.
Пустая ячейка stderr — пусто. Тексты новых отказов — литералы спецификатора
по форме живых отказов.

`mpu run: help`:

```
Использование: mpu run: <файл.mpu> [<ключ>: <значение>]…

Звать, когда программа длиннее строки или ломается на кавычках оболочки:
файл делится по пробелам так же, как строка, а @ключ внутри берёт значение
из ключа вызова (mpu run: x.mpu col: review). Без слов программа берётся

```
