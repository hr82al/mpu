# Длинный вывод: логи без предела и большой результат в MCP

Статус: реализовано — порция 165d (`fba7355`, `7ae25ff`); принято 2026-09-23 хостом: гейты зелёные (тестов 2334, smoke 19/1), мутации M1–M7 красные. Живой прогон (Loki, MCP, `/tmp/mpu-out`) — хост после установки.

## Назначение

Живой замер 2026-09-23 (хост, `mpu logs target: sl-1 since: 6h`):

| Строк | CLI | MCP |
|---|---|---|
| 200 | 35 КиБ, код 0 | ответ 74 КиБ |
| 5000 | 0,9 МиБ, 1 с, код 0 | ответ 1,9 МиБ одним куском — агенту не прочесть |
| 50000 | код 1: `loki HTTP 400: max entries limit per query exceeded … (50000 > 5000)` | то же |

Кроме того: у `logs` ключ «сколько» — `tail:`, а не `limit:` из словаря
(`keys-translation.md`); слепой замер `sonnet` пишет `limit: 20000`
(`mpu/docs/probes/2026-09-23-long-output/`). Результат `logs` — не коллекция:
`… end size` отказывает «запись не понимает size».

Порция делает три вещи: логи любой длины, логи — коллекция строк, большой
результат MCP — файлом.

## 1. `limit:` вместо `tail:` и прочих «сколько»

- `logs`: ключ `limit:` (прежний смысл `--tail`, умолчание 200, > 0).
  `tail: 50` — отказ общим механизмом переименованного словарного ключа:
  «сколько — ключом: mpu logs … limit: 50», код 2, с `refusal.hint`
  (`refusal-object.md`); метка словаря `limit` — «сколько» (была «предел»);
  то же получают `-n 50` и прочие «сколько», переведённые в `limit:`.
- То же правило для каждого ключа любой команды, означающего «сколько
  записей вывести» (`tail`, `n`, `count`, `last`, `top` …): исполнитель
  перечисляет найденные в отчёте, спорные решает хост. Ключ с другим смыслом
  числа (`days`, `depth`) не трогается.
- Решено хостом: `logs tail:` и `log tail:` (семантика «≤ 0 — все» сохраняется)
  и `health tail:` (строк лога на контейнер — справка говорит «на контейнер»;
  поле результата `tail` не меняется) → `limit:`.

## 2. Логи любой длины

Разовый Loki-запрос с `limit` больше предела сервера (5000 — параметр
команды, не литерал) идёт страницами: `direction=backward`, первая страница —
окно `[since .. now]`; следующая — то же окно с `end` = наименьший `ts`
прошлой страницы + 1 нс; записи, уже полученные (тот же `ts`, те же
метки потока, тот же текст), отбрасываются. Остановка: набрано `limit`,
страница короче запрошенного или новых записей в ней нет. Печать — по
возрастанию `ts`, как прежде. Своего предела у `limit` нет (решение
владельца: без лимитов; память — сторож 166a).

Ошибка на любой странице — как ошибка разового запроса (код 1), ничего не
печатается.

## 3. Результат `logs` — коллекция строк

`logs` объявляет `items` (`collection-protocol.md`): запись — строка лога с
полями `time` (ISO UTC, миллисекунды), `host`, `service` (метка
`compose_service`, нет — пусто), `stream` (`stdout`/`stderr`), `text` (текст
записи без хвостового перевода строки). Печать без сообщений результату —
побайтово прежняя. Portainer-путь — записи stdout- и stderr-части (`stream`),
`host`/`service` пусты; с `timestamps` `time` — префикс Docker, приведённый к
ISO с миллисекундами, а `text` — строка целиком вместе с префиксом (печать
отобранного возвращает байты Docker). Печать отобранного: stdout-записи — в
stdout как прежде; stderr-записи в текст не попадают (их stderr ушёл при
исполнении), но входят в `size` и `json`.

`logs hosts` и `logs services target: …` — коллекции скаляров (имён):
`… end size` — число, `end first` — имя.

Следующая страница Loki — `end` = наименьший `ts` прошлой страницы + 1 нс
(граничный `ts` входит при любой трактовке границы), повторы снимает
отбрасывание по (`ts`, метки, текст). JSON Lines слежения — прежний.

## 4. Большой результат в MCP — файлом

Решает `back` при сборке ответа двери агента (`/agent/line`): итоговый
собранный ответ (с `exit`) со `stdout` больше **64 КиБ** (параметр `back`)
вывода целиком не несёт — вместо поля `stdout` в нём `file: {path, bytes,
lines, slice}` (`slice` — результат-коллекция); куски до вопроса `ask` — как
есть. Схема собранного ответа (`fixtures/back-rpc/schema.json`) меняется.
Переводчик MCP строит по `file` текст и `structuredContent.file`. Дверь
`/line` (и с `Accept: application/json`) не меняется.

- весь `stdout` пишется в файл `<каталог>/<run>.txt`: каталог — параметр,
  умолчание `/tmp/mpu-out` (его читают агенты), права файла `0600`, каталога
  `0700`; `<run>` — `run_id` журнала вызова (`invoke-log.md`);
- `N` — число `\n` плюс 1, если хвост без перевода строки; `M` — байты / 1024,
  целым с округлением вверх;
- текст ответа: `вывод N строк, M КиБ — файл <путь>; срез без повторного
  запроса: it end last: 100 · it end size` (строка среза — у любого
  результата-коллекции, `slice`; иначе — только путь);
- `structuredContent`: поле `file: {"path", "bytes", "lines"}`, поля `stdout`
  нет; `stderr` и `exit` — как прежде; `isError` — по коду, как прежде;
- `it` хранит результат целиком: срез идёт без нового запроса к Loki.
- Файлы каталога старше суток удаляются при следующей записи.

CLI не меняется: человек сам направляет вывод в файл или конвейер.

Права Deno: `/tmp` уже в `--allow-write` у `back`; отдельного права на
`/tmp/mpu-out` нет. Живой прогон записи файла — у хоста (в сессии `/tmp` только
для чтения).

## Инварианты

- CLI-вывод `logs` без новых ключей побайтово прежний (голдены `logs/`).
- MCP-ответ ≤ 64 КиБ — побайтово прежний.
- Содержимое файла побайтово равно `stdout`, который вернул бы CLI.
- Журнал вызовов не зависит от двери: секция вывода — как прежде (с обрезкой), путь файла не пишется.

## Граничные случаи

| Дано | Ожидается |
|---|---|
| `mpu logs target: sl-1 since: 6h limit: 12000` (поддельный Loki: 5000 на страницу, 11000 записей в окне) | 11000 строк по возрастанию, 3 запроса, код 0 |
| то же, записи на границе страниц с одним `ts` | без дублей и без потерь |
| `mpu logs target: sl-1 tail: 50` | отказ «сколько — ключом: mpu logs target: sl-1 limit: 50», код 2 |
| `mpu logs target: sl-1 end size` | число строк |
| `mpu logs target: sl-1 end where: text includes: ERROR` | только строки с `ERROR`, печать как у `logs` |
| `it end last: 50` после `logs` | последние 50 строк без запроса к Loki |
| MCP `logs … limit: 5000` (ответ 0,9 МиБ) | текст «вывод 5000 строк, … — файл /tmp/mpu-out/<run>.txt; срез …»; файл побайтово = CLI-вывод; `structuredContent.file` |
| MCP `kiten ls` (≤ 64 КиБ) | как прежде |
| MCP большой вывод не-коллекции (`kiten card` с длинным описанием) | файл, текст без строки среза |
| MCP большой `sql-ro` (коллекция) | файл, строка среза |
| вторая страница Loki отвечает 500 | код 1, текст ошибки разового запроса, stdout пуст |

## Известные отклонения

- `it …` над большой коллекцией: `slice` — нет (память строки `it` не пишет коллекцию), строки среза нет, путь файла есть. Вердикт — **preserve** до следующей правки `it`.
- Группа записей с одним `ts` не меньше страницы (5000 в одну наносекунду) страницами не проходится: остановка «новых нет». **preserve**.
- Сбой записи файла — ответ целиком и строка в диагностику сервера.

- Порог 64 КиБ — ниже предела ответа тула у клиентов (Claude Code — около
  25 000 токенов): ответ за порогом клиент обрезает или отвергает, агент
  узнаёт об этом после траты контекста. Вердикт — **fix** (файл).
