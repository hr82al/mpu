# Картинка в ответе строки

Статус: к реализации (порция TF2)

## Назначение

Агент, которому коллега прислал скриншот в Telegram, сейчас получает от
`mpu telegram file` путь к файлу и должен отдельным шагом открыть файл, чтобы
увидеть картинку. Владелец (2026-10-05): картинка из Telegram приходит агенту
прямо в ответе тула MCP блоком изображения, без чтения файла.

Слово «картинка» здесь — растровое изображение в ответе строки. «Образ» в mpu
занят (`platform/image.md`) и к этой спеке отношения не имеет.

Единственный источник картинок в этой порции — `telegram file`
(`telegram-file.md`, раздел «Порция TF2»). Картинка — записанный командой файл,
чьи байты разбираются как картинка (таблица «Вид картинки — по байтам»).

## Контракт

**Кадр сервера.** Строка, чья команда дала картинку, получает кадр

```json
{"picture": {"mime": "image/jpeg", "data": "/9j/4AAQSkZJRg=="}}
```

- `mime` — один из четырёх: `image/jpeg`, `image/png`, `image/gif`,
  `image/webp` (форматы, которые принимает Claude: документация Anthropic
  «Vision», раздел «Supported formats», снято 2026-10-05);
- `data` — base64 байтов файла, записанного командой, без переносов строк.

Кадры картинок идут после всего вывода строки, непосредственно перед кадром
`exit`, в порядке команд, которые их дали, — в WebSocket и NDJSON
(`platform/back-rpc.md`, `platform/back-http-line.md`). Строка, кончившаяся
отказом или кодом ≠ 0, не даёт ни одного кадра картинки — и тогда, когда
картинку дала её успешная команда (P19). Файл, который к концу строки не
прочитать (удалён, нет прав), картинки не даёт; итог строки от этого не
меняется.

**Собранный ответ** (`Accept: application/json`) получает поле `pictures` —
список объектов кадров в порядке появления; у строки без картинок поля нет.

```json
{"stdout": "…", "stderr": "", "exit": 0, "pictures": [{"mime": "image/jpeg", "data": "/9j/4AAQSkZJRg=="}]}
```

**Ответ тула MCP** (`platform/mcp-objects.md`): после текстовых блоков —
по блоку на картинку, в том же порядке:

```json
{"type": "image", "data": "/9j/4AAQSkZJRg==", "mimeType": "image/jpeg"}
```

Форма блока — `ImageContentSchema` закреплённого SDK
(`npm:@modelcontextprotocol/sdk@1.30.0`, `dist/esm/types.js`). В
`structuredContent` картинок нет: данные не дублируются.

**CLI и web** кадр принимают и ничего по нему не показывают: печать —
прежняя, побайтово.

## Предел

Сумма байтов картинок одного ответа строки — не больше **3 750 000** (base64
≤ 5 000 000 — самый строгий предел на изображение из документации Anthropic:
5 МБ base64 у Amazon Bedrock и Google Cloud). Картинка, с которой сумма
перешла бы предел, кадра не даёт и предел не расходует; следующие, которые ещё
помещаются, — дают (P13, P14). Сумма считается по байтам файлов, не по длине
base64.

Claude Code считает картинки в предел вывода тула `MAX_MCP_OUTPUT_TOKENS`
(25 000 по умолчанию; документация Claude Code «MCP», снято 2026-10-05), но
не говорит, как. Поэтому предел — догадка до живой проверки хостом при
приёмке: фото Telegram и документ-картинка около предела доходят до агента
блоком.

## Вид картинки — по байтам

Блок даётся по первым байтам записанного файла; `mime`, присланный
Telegram, не решает (P9, P10): блок, который Claude не разберёт, ломает
разговор агента, а не одну строку.

| Первые байты файла | `mime` от Telegram | Блок `mimeType` |
|---|---|---|
| `FF D8 FF` | `image/jpeg` | `image/jpeg` |
| `FF D8 FF` | `application/octet-stream` | `image/jpeg` |
| `89 50 4E 47 0D 0A 1A 0A` | `image/png` | `image/png` |
| `GIF87a` | `image/gif` | `image/gif` |
| `GIF89a` | `image/gif` | `image/gif` |
| `RIFF` + 4 байта + `WEBP` | `image/webp` | `image/webp` |
| `RIFF` + 4 байта + `WEBP` | `image/jpeg` | `image/webp` |
| `GIF89a` | `image/png` | `image/gif` |
| `RIFF` + 4 байта + `WAVE` | `audio/wav` | нет |
| `<svg` / `<?xml` | `image/svg+xml` | нет |
| 4 байта + `ftypheic` | `image/heic` | нет |
| `49 49 2A 00` (TIFF) | `image/tiff` | нет |
| `42 4D` (BMP) | `image/bmp` | нет |
| `# не картинка` | `image/png` | нет |
| `FF D8` (2 байта, файл короче подписи) | `image/jpeg` | нет |
| пустой файл | `image/jpeg` | нет |

## Инварианты

- Печать CLI, web и stdout строки — побайтово как без этой порции; голдены
  TF1 не меняются.
- Картинка не попадает ни в `structuredContent`, ни в `it`, ни в журнал
  вызовов.
- Сумма байтов картинок одного ответа ≤ предела.
- Кадр картинки бывает только у строки с кодом 0.
- `data` декодируется ровно в байты файла по `path` из stdout той же строки.
- Список тулов MCP не меняется (`fixtures/mcp-objects/tools.json`).

## Границы

- Картинку не уменьшают и не перекодируют: что не помещается — без блока.
- `telegram search` картинок не даёт: выдача поиска — описания, не файлы.
- Ответ тула больше 64 КиБ stdout (`platform/long-output.md`, §4) уходит
  файлом как прежде; картинки этого ответа остаются блоками.
- `it` картинку не повторяет: для неё — снова `telegram file`.
- Анимация GIF и WebP не разбирается: Claude берёт первый кадр сам.
- Картинка, оставшаяся без блока (не та подпись, за пределом), следа в
  ответе не оставляет: stdout той же строки несёт `mime` и `size`, справка
  `telegram file` называет правило (F22) — по ним агент видит, почему блока
  нет.

## Решения спецификатора

- [D.1] Картинка — новый вид кадра строки, а не поведение `mcp`: `mcp` о
  командах не знает (`platform/mcp-objects.md`, инварианты), а путь «кадр →
  поле собранного ответа → блок» уже пройден отказом
  (`platform/refusal-object.md`). Следующая команда с картинкой проходит тем
  же путём без правок `mcp`.
- [D.2] Вид картинки — по байтам, не по `mime` Telegram (таблица выше).
- [D.3] Предел — суммарно на ответ: Claude Code считает предел на весь ответ
  тула, а не на картинку. Значение — самое строгое из документированных;
  живая проверка — у хоста. Предел — параметр `back` (design-mpu 8), а не
  литерал по месту. Кадры — перед `exit`, а не после своей команды: только
  так строка с итогом ≠ 0 не выпускает картинок, уже отданных по ходу.
- [D.4] Кадр уходит всем дверям, CLI и web его пропускают: дверь «для
  агента» в строке не различается, а локальная пересылка нескольких мегабайт
  дешевле второго вида строки.
- [D.5] Картинку даёт результат команды, а не команда печатью: исполнение не
  печатает (`platform/command-contract.md`, инвариант 1). Результат, у
  которого картинки нет, отвечает одним общим «картинки нет» — у всех
  прежних команд поведение не меняется.
