# Строка как выражение: ключи, `do … end`, справка и результат — объекты

Статус: к реализации — порция 158.

## Назначение

Строка `mpu` читается как выражение Smalltalk: голое слово — всегда унарное
сообщение, значение — только аргумент ключевого сообщения, унарное выше
ключевого, группа — `do … end`. Результат команды и результат `help` —
объекты-данные, формат вывода — их унарное сообщение. Порция меняет
грамматику (`messages.md`), справку (`objects.md`, «режим справки»), вывод
результата и переводит на ключи три команды-образца: `kiten card`, `sql`,
`sql-ro`. Остальные команды сохраняют хвост `<args>` до следующей порции.
Синтаксис одинаков для CLI и MCP: оба отдают слова одному разбору в `back`.

## Слова грамматики — одна константа

Слово открытия группы (`do`), закрытия (`end`) и знак литерала (`--`) заданы
одной константой модуля разбора. Её читают: разбор, тест зарезервированных
имён, справка корня, описание тула `mpu`, тексты подсказок в отказах, голдены
справки (пересобираются задачей). Литералом в коде и тестах эти слова не
пишутся нигде, кроме самой константы. [D.1]

`do` и `end` — зарезервированные слова: команда, группа, ключ или формат с
таким именем — ошибка при сборке дерева (тест).

## Разбор (заменяет строки таблиц `messages.md`)

| Положение | Итог |
|---|---|
| ключи подряд (`id: 1 text: x`, `--x a --y b`) | **одно** ключевое сообщение `id:text:`; деления на сообщения разным приёмникам больше нет [D.2] |
| за значением ключа — слово, не ключ и не `end` | ошибка «значение `<значение>` не понимает `<слово>`» с подсказкой (таблица отказов), код 2 |
| `end`, до которого нет открытого `do` | закрывает группу от начала строки: всё до него — выражение, следующее слово — сообщение его результату [D.3] |
| `do` первым словом строки | явное открытие; `do … end` ≡ `… end` |
| `do` не первым словом | ошибка «`do` — только в начале строки», код 2 |
| `--` перед любым словом, включая `do`, `end`, `--` | слово — литерал: значение ключа, если ключ ждёт значения, иначе унарное сообщение |
| `.` | обычное слово (строка `.` из таблицы `messages.md` снята) |
| `--help` | то же, что слово `help` (единственная флаговая форма унарного сообщения) |
| хвост приёмника с хвостом | слова до первого `end` без `--` перед ним; `--` непосредственно перед `do`/`end` снимается, слово остаётся; прочие слова — как есть |
| `help` или `--help` в хвосте до `end` (`mpu kiten ls 5 help`) | справка команды, как сегодня; исключение — хвост с чужими словами (`ssh`): там слово как есть |
| строка пуста | `help` корню (как было) |
| `end` последним словом | закрывает группу; результат — в виде по умолчанию |
| `--json`, `--md`, `--tsv`, `--table`, `--raw`, `--out` в любом месте строки ключевой команды (в том числе перед путём) | отказ «формат — сообщение результату» с готовой строкой; у команд с хвостом — как сегодня до следующей порции |
| хвост с чужими словами (`ssh`: вход, который пропускает неизвестное) | берётся целиком, как сегодня: `end` и `--` в нём не толкуются — до перевода `ssh` на ключ `cmd:` |

Одно слово строки — одно значение: `sql: "select 1"` приходит одним словом,
кавычки делает оболочка; `"end"` — то же слово `end`. [D.3]

## Справка — сообщение `help`

- `help` понимает любой объект; ответ — **объект-справка** (данные). Режима
  справки нет: `mpu kiten card help` ничего не исполняет, потому что `help`
  уходит объекту команды, а не результату. [D.4]
- Поля объекта-справки и их источники — объявление объекта: `path` (текст
  пути, `objects.md`), `purpose` (однострока), `text` (текст справки),
  `examples` (строки вызова), `keys` — `{name, kind: value|flag, required,
  purpose}`, `formats` — имена форматов результата, `messages` —
  `{selector, purpose}`.
- Текстовый вид — форма `objects.md` («Текст справки»), у образцов — в
  порядке однострока → абзац «когда звать» → «Примеры:» (2–3 строки) →
  ключи, форматы, коды выхода. Формат `json` — объект-справка, отступ 2,
  перевод строки в конце.
- `mpu help` — справка корня. `mpu help kiten card` → отказ
  «`mpu help`: не понимает kiten; справка — последним словом: `mpu kiten card
  help`», код 2. Тул MCP `help` с `path` шлёт слова `[...path, "help"]`.

## Команда-образец: ключевое сообщение

| Команда | Было | Ключи | Флаги (как были) | Форматы результата |
|---|---|---|---|---|
| `kiten card` | `SELECTOR` | `id:` — id или URL карточки | `--no-comments`, `--no-images` | без формата — как сегодня (терминал — наглядный, пайп — markdown); `md`; `json` |
| `sql-ro`, `sql` | `SELECTOR SQL`, `--server`, `-v` | `target:` — как прежний селектор (номер клиента, имя или часть, `sl-N`, `dev:N`); `sql:` — нет → stdin, как сегодня | `--dry`, `--verbose` (бывший `-v`: одиночный дефис — не ключ) | без формата — таблица; `md`; `json` |

Ключи образцов: `target`, `id` — из словаря ключей; `sql` вне словаря — предмет команды (текст запроса). Словарь целиком и тест «ключ вне словаря — с записанной причиной» — следующая порция.

Команда исполняется своим ключевым сообщением; без обязательного ключа —
«не хватает ключа …» (`messages.md`). `--server` снят: `target: sl-N` делает
то же (search_path сервера).

## Результат — объект

- Результат любой команды (образцов и команд с хвостом) — объект с видом по
  умолчанию (сегодняшний текст) и форматами-сообщениями. `json` понимает
  любой результат, вывод побайтово равен сегодняшнему `--json`. Прочие
  форматы — те, что команда выбирала флагом: `kiten card` `md`; `sql`/`sql-ro`
  `md`; `ps` `tsv`; `sheet get` и `xlsx get` `raw`, `tsv`; `telegram ls` и
  `telegram search` `table`; `mr comments` `md`; `kiten status` `matrix`,
  `group`, `md`, `url`. [D.5]
- Какие форматы понимает результат, объявляет команда; неизвестный формат —
  отказ **до исполнения** (пишущая команда не исполняется ради отказа
  печати). [D.5]
- **Код выхода отдаёт результат** и не зависит от формата: строка с `end
  json` и без него — один код. Сегодня `--json` всегда давал 0. [D.6]
- **Поток.** Результат — одна из двух реализаций: значение или поток
  записей. Формат печатает запись: у потока `json` — одна строка JSON на
  запись (JSON Lines), каждая с переводом строки. Поток в этой порции —
  `logs --follow`; отмена и код — как сегодня (`line-cancel.md`). [D.7]

**Вопрос подтверждения** у строки с форматом — без формата: `mpu ask sql target: sl-1 sql: "…" end json` спрашивает `выполнить mpu sql target: sl-1 sql: …?`. Формат — подача результата, не исполнение; путь правила тот же.

## MCP

Описание тула `mpu` — текст `fixtures/mcp-objects/tool-desc-v3.txt`
(слова группы подставлены из константы), ≤ 2048 байт. Голден `tools.json`
пересобирает исполнитель, замораживает хост. Описание — целевое для всей
серии: строки о вариантах (`dry`, `all`, …) и словаре ключей верны после

не видят. Слепой замер на собранном описании — хост, после установки.

|---|---|---|

| `mpu sql-ro sl-1 "select 1"` | `mpu sql-ro: значение — ключом: mpu sql-ro target: sl-1 sql: "select 1"` | 2 |

| `mpu --json kiten card id: 123` | как `… --json` после ключей | 2 |

Склеенное ключевое сообщение, которое получатель понимает частично (есть
метод, чьи ключи — начало набранных), даёт подсказку со словом `end` после
понятой части: цепочка ключевых сообщений пишется только так (слепой замер
2026-09-22: делёж «по получателю» агент переносил на унарные и ошибался).

Слово-значение для подсказки «значение — ключом» — первые слова строки по
порядку обязательных ключей команды; слово с пробелом — в кавычках.

## Инварианты

- Голое слово — никогда не значение; значение — только ключом.
- Слова `do`, `end`, `--` читаются из одной константы; её замена на другую
  пару меняет разбор, справку, описание тула и подсказки без других правок
  кода (мутация приёмки).
- Строка с неизвестным форматом не исполняет команду.
- Код выхода один для всех форматов результата.
- `help` ничего не исполняет.
- Дверь `ask` (`ask-door.md`) работает с новой грамматикой без изменений:
  `mpu ask sql target: sl-1 sql: "…" end json`.
- Путь правила строки ключевой команды — **прежний**: путь команды и звено
  `<args>`, какие бы ключи ни были набраны (`sql-ro <args>` и со `sql:`, и со
  stdin). Узел ключевой команды — исполняющийся, как прежде узел с хвостом:
  `policy.tree` — один узел на команду, дверь `ask` видит его так же, голден
  `fixtures/web/policy-tree.json` не меняется.

## Граничные случаи

| Дано | Ожидается |
|---|---|
| `mpu kiten card id: 123 end md` | markdown карточки, как сегодня `--md` |
| `mpu do kiten card id: 123 end md` | то же |
| `mpu kiten card --id 123` | то же, что `id: 123` |
| `mpu sql-ro target: ромашка sql: "select 1" end json` | JSON как сегодня `--json` |
| `echo "select 1" \| mpu sql-ro target: 54` | SQL из stdin, как сегодня |
| `mpu kiten comment 55 -- end` (хвост) | хвост `["55", "end"]` |
| `mpu kiten ls end json` (хвост) | хвост пуст, результат — JSON |
| `mpu logs sl-1 --follow end json` | JSON Lines до Ctrl+C |
| `mpu kiten card help` | справка, код 0, запроса к Kaiten нет |
| `mpu kiten card help end json` | объект-справка JSON: `keys` содержит `{"name": "id", "kind": "value", "required": true, …}` |
| `mpu kiten ls end xml` | отказ до исполнения, код 2 |
| `mpu a b end json end md` | второй `end` закрывает от начала строки: `md` — результату `(… json)` |
| `mpu kiten card id: 1 do` | «`do` — только в начале строки», код 2 |
| `mpu d2-miro … end json` при пропусках | код как у той же строки без `end json` |

## Известные отклонения

- До следующей порции команды с хвостом принимают и флаг формата, и
  сообщение формата: два способа одного, снимается переводом на ключи.
- Команды с хвостом: формат-сообщение в этой порции переводится в прежний флаг команды (`ps end tsv` → `--tsv`, `kiten status end matrix` → `--out matrix`, `json` → прежний общий путь JSON); список форматов объявляет команда. Вид результата у них остаётся в команде до перевода на ключи — там же рендер переезжает в виды результата и флаги снимаются.
- Дополнение (`complete`) ключей образцов не предлагает: дополнение переходит на сообщения отражения (`messages`, `keys`, `formats`, `complete:`) отдельной порцией после перевода всех команд на ключи.
