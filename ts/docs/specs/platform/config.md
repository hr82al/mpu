# platform/config — локальные предпочтения CLI

Статус: черновик (создана 2026-07-29 при расщеплении конфига:
здесь — клиентская часть; секреты и серверные настройки — `.env`
брокера, CLI их не читает и не видит)

## Назначение

Локальные пользовательские предпочтения CLI и команда `mpu config` над
ними. Секретов в этом слое нет по построению; токен брокера — не ключ
конфига, а отдельный файл (0600, контракт — `specs/protocol/core.md`).

## CLI-контракт

`mpu config [key] [value] [--unset] [--json]`

- Без аргументов — все ключи реестра по порядку объявления, с
  действующим значением и источником:
  `key<пробелы>значение|-(unset)  (source)`; суффикс источника
  опускается для `config`, печатается для `(env)` и `(default)`.
  `--json` — массив `{key, value, source, default, description}`.
- `config <key>` — значение; str-ключ без значения → пустой stdout,
  exit 0 (pipe-friendly); int-ключ без значения → печатается дефолт.
  Неизвестный ключ → exit 2:
  `unknown config key: "<имя>"; попробуй: допустимые ключи: <CSV>`.
- `config <key> <value>` — upsert. Int-ключ с нечисловым значением →
  exit 2 `<key> ожидает целое число, получено "<value>"`, хранилище не
  трогается. При активной env-переменной поверх ключа запись проходит,
  но stderr предупреждает:
  `внимание: <ENV>=<значение> в окружении перекрывает это значение`.
- `config --unset <key>` — идемпотентное удаление, exit 0 даже если
  записи не было; stdout `<key> сброшен к дефолту: <default|(unset)>`.
  `--unset` без ключа → exit 2 `--unset требует имя ключа`.
- Реестр ключей закрыт: `broker.url` (str) — адрес брокера;
  `sheet.default` (str), `xlsx.default` (str) — дефолтные цели команд
  `sheet`/`xlsx`. (Ключи `sheet.cache.*` оригинала стали серверной
  политикой брокера — см. отклонения.)

Кроме ключей реестра, локальное хранилище держит именованные алиасы
файлов команды `xlsx` (`alias add/rm`; контракт самих подкоманд — спека
`xlsx.md`): алиасы переживают вызовы, в вывод `mpu config` не входят.

## Ввод/вывод

Приоритет действующего значения любого ключа реестра, строго:
env `MPU_<KEY>` (имя выводится детерминированно: точки → `_`, верхний
регистр) → локальное хранилище → дефолт потребителя. Значения хранятся
как строки буквально (`"007"` сохраняется как `007`, не нормализуется).

Env-слой — переменные окружения процесса (`MPU_BROKER_URL`, `MPU_SS`,
`MPU_XLSX`, …); отдельного env-файла у CLI нет — секреты живут только
у брокера, а несекретным настройкам хватает окружения shell и
хранилища.

## Побочные эффекты

Только локальные: чтение/запись файла хранилища в
`~/.config/mpu/` (имя и формат файла — дело реализации; каталог
создаётся при первой записи, файл — 0600). Сети нет; `mpu config`
никогда не ходит в брокер. Отдельная инициализация не требуется:
отсутствующее хранилище равнозначно пустому.

## Конфигурация

сам механизм конфигурации; собственных настроек не имеет.

## Инварианты

- Чтение (`config`, `config <key>`) идемпотентно, без побочных
  эффектов.
- Порядок приоритета env → config → default одинаков для всех ключей и
  никогда не инвертируется.
- Невалидное значение int-ключа не долетает до хранилища (валидация до
  записи).
- Обращение к ключу вне реестра никогда не создаёт запись «на лету».
- Секреты не печатаются: в реестре нет секретных ключей, токен брокера
  командой `mpu config` не выводится.

## Граничные случаи и ошибки

- env-переменная активна И значение записано в хранилище → действует
  env, источник `env`, записанное значение сохраняется, но не
  действует.
- `--unset` при активной env-переменной удаляет только запись
  хранилища — действующим остаётся env; stderr предупреждает про env,
  как это делает set (исправление квирка оригинала, см. отклонения).
- Хранилище отсутствует → чтение работает (всё по дефолтам), запись
  создаёт каталог и файл.
- Формат ошибок единый: stderr
  `mpu config: <причина>[; попробуй: <подсказка>]`, без трейсбеков;
  exit 2 — ошибки ввода, exit 1 — инфраструктура.

## Golden-примеры

Снять с живой Python-версии при переводе в «к реализации» (UX-паритет
команды): `mpu config --help`; `mpu config --json` на чистом хранилище
(baseline: в оригинале 5 ключей — сверять состав по реестру этой
спеки, см. отклонения); `mpu config sheet.cache.tab_ttl --json`
(значение из дефолта — для фикстуры формата source=default).

## Известные отклонения

- **fix** — реестр ключей изменён относительно оригинала: добавлен
  `broker.url`; `sheet.cache.tab_ttl`, `sheet.cache.max_tab_bytes`,
  `sheet.cache.max_total_mb` ушли в серверную конфигурацию брокера
  (кэш общий, политика админская). Differential вывода `mpu config`
  сравнивать по составу реестра этой спеки.
- **fix** — сообщение `--unset` в оригинале показывает дефолт, даже
  когда активна env-переменная и действующим значением останется она;
  правильное поведение — предупреждать про env, как это делает set.
- **fix** — оригинал требовал `mpu init` (схему служебной БД) для
  операций записи; у локального хранилища CLI инициализации нет —
  отсутствующий файл равнозначен пустому.
- **fix** — env-файл `~/.config/mpu/.env` у CLI упразднён: секреты —
  только у брокера, несекретные настройки — окружение shell и
  хранилище. Переменные `MPU_*` из shell работают как раньше.

## Открытые вопросы

- Судьба env-дефолтов целей (`MPU_SS`, `MPU_XLSX`) как отдельных имён
  против выводимых `MPU_SHEET_DEFAULT`/`MPU_XLSX_DEFAULT`: оригинал
  использует короткие имена — решить при спеке команд `sheet`/`xlsx`
  (кандидат: preserve коротких имён как алиасов).
- Нужен ли ключ конфига для пути токен-файла — сейчас путь фиксирован
  реализацией (`~/.config/mpu/`).
