Статус: реализовано — сверено 2026-09-10 по потребителю `mpu config --help` (возможность используется работающей командой; контракт построчно не сверялся). Ранее: к реализации (заморожена 2026-08-27: источник — таблица `config` в
`mpu.db`, env-слоя нет; создана 2026-07-29 при расщеплении конфига; пересобрана
2026-08-03: реестр ключей обслуживает и CLI, и MCP-сервер одного бинаря) Порция 169a (`174112b6`, `328734c9`, `281beb54`) принята 2026-09-25: тестов 2483, smoke 19/1, мутации M1–M7 красные (перепроверена хостом M5 — `cmd:` без снятия `ask`); установлено; живьём `mpu log cmd: telegram` находит `$ mpu ask telegram status dry no-live`, справка `mpu config` перечисляет `image.dir`. Не прогнана живьём строка `define:` (запись в образ владельца).

## Назначение

Локальные пользовательские предпочтения CLI и команда `mpu config` над ними.
Секретов в этом слое нет по построению; токен доступа MCP-сервера — не ключ
конфига, а отдельный файл (0600, контракт — `specs/platform/mcp-server.md`).

## CLI-контракт

`mpu config [key] [value] [--unset] [--json]`

- Без аргументов — все ключи реестра по порядку объявления, с действующим
  значением и источником: `key<пробелы>значение|-(unset)  (source)`; суффикс
  источника опускается для `config` и печатается для `(default)` — источника
  `env` больше не существует.
  `--json` — массив `{key, value, source, default, description}`.
- `config <key>` — значение; str-ключ без значения → пустой stdout, exit 0
  (pipe-friendly); int-ключ без значения → печатается дефолт. Неизвестный ключ →
  exit 2: `unknown config key: "<имя>"; попробуй: допустимые ключи: <CSV>`.
- `config <key> <value>` — upsert. Int-ключ с нечисловым значением → exit 2
  `<key> ожидает целое число, получено "<value>"`, хранилище не трогается.
  Предупреждения про перекрытие окружением нет: перекрывать нечем.
- `config --unset <key>` — идемпотентное удаление, exit 0 даже если записи не
  было; stdout `<key> сброшен к дефолту: <default|(unset)>`. `--unset` без ключа
  → exit 2 `--unset требует имя ключа`.
- Реестр ключей закрыт (`mcp.port` снят вместе с сервером 7337 —
  `platform/monolith-removal.md`): `sheet.default` (str), `xlsx.default`
  (str) — дефолтные цели команд `sheet`/`xlsx`; `sheet.cache.tab_ttl` (int,
  7200), `sheet.cache.max_tab_bytes` (int, 10485760),
  `sheet.cache.max_total_mb` (int, 500) — параметры кэша листов; `image.dir`
  (str) — каталог файлов методов образа (`image-sync.md`), внесён
  2026-09-25 порцией 169a, последним в порядке реестра. Умолчание —
  `$HOME/mr/mp/mpu/image`, раскрытое от `HOME` порта команды (не из
  окружения по месту); `HOME` нет — умолчания нет. Как у любого str-ключа,
  `config key: image.dir` без записи печатает пустую строку; умолчание
  видно в списке с пометкой `(default)`. Список ключей в справке `mpu
  config` берётся из реестра. Литералы списка, `end json` и `unset` для
  `image.dir` — раздел «Ключ `image.dir`», сценарии C1–C3. Три ключа `sheet.cache.*`
  внесены в реестр 2026-08-27: после того как env-слой убран, конфиг — их
  единственный источник (`platform/webapp-http.md`), и не показывать их в
  `mpu config` значило бы сделать их ненастраиваемыми.

Кроме ключей реестра, локальное хранилище держит именованные алиасы файлов
команды `xlsx` (`alias add/rm`; контракт самих подкоманд — спека `xlsx.md`):
алиасы переживают вызовы, в вывод `mpu config` не входят.

## Ввод/вывод

Приоритет действующего значения любого ключа реестра, строго: локальное
хранилище → дефолт потребителя. **Переменных окружения у механизма предпочтений
нет** — решение пользователя 2026-08-27: «только явно через параметры, доступ к
лишним переменным окружения не нужен». Прежние алиасы оригинала (`MPU_SS` для
`sheet.default`, `MPU_XLSX` для `xlsx.default`) и выводимые длинные имена
(`MPU_MCP_PORT` и подобные) не действуют ни в каком виде; права `--allow-env`
под них не расширяются. Значения хранятся как строки буквально (`"007"`
сохраняется как `007`, не нормализуется).

Слой секретов и подключений native-команд — отдельный контракт `env-file.md`,
к реестру предпочтений он отношения не имеет.

## Побочные эффекты

Только локальные: чтение и запись **таблицы `config` в кэш-БД**
`~/.config/mpu/mpu.db` (`platform/store.md`) — по строке на ключ, колонки
`key`/`value`, обе строковые. Это не «дело реализации»: базу делят обе
реализации, и разойтись им нельзя — снято живьём 2026-08-27, после
`mpu config sheet.default <id>` в таблице лежит
`('sheet.default', '<id>')`. Отдельного JSON-файла предпочтений не существует;
чтение по такому пути — дефект, а не альтернативная форма (так уже случилось
однажды: реализация читала несуществующий `config.json` и молча отдавала
умолчания). Сети нет; `mpu config` не открывает соединений. Отдельная
инициализация не требуется: отсутствующая таблица равнозначна пустой.

## Конфигурация

сам механизм конфигурации; собственных настроек не имеет.

## Инварианты

- Чтение (`config`, `config <key>`) идемпотентно, без побочных эффектов.
- Порядок приоритета config → default одинаков для всех ключей и никогда не
  инвертируется; третьего слоя нет.
- Значение, записанное `mpu config <key> <value>`, немедленно видно любому
  потребителю ключа — и рабочей реализации, и переехавшей: источник у них
  один и тот же (таблица `config` в `mpu.db`).
- Невалидное значение int-ключа не долетает до хранилища (валидация до записи).
- Обращение к ключу вне реестра никогда не создаёт запись «на лету».
- Секреты не печатаются: в реестре нет секретных ключей, токен доступа
  MCP-сервера командой `mpu config` не выводится.

## Граничные случаи и ошибки

- Переменная окружения с «подходящим» именем (`MPU_SS`, `MPU_MCP_PORT` и
  прочие) на выдачу не влияет никак: источника `env` нет, и значение ключа от
  окружения не зависит — это проверяемое утверждение, а не умолчание.
- Хранилище отсутствует (нет БД или нет таблицы `config`) → чтение работает
  (всё по дефолтам), запись создаёт каталог, БД и таблицу.
- Формат ошибок единый: stderr `mpu config: <причина>[; попробуй: <подсказка>]`,
  без трейсбеков; exit 2 — ошибки ввода, exit 1 — инфраструктура.

## Ключ `image.dir` (порция 169a)

Ключ — шестой, последним в порядке реестра; ширина
колонки ключей не меняется (по `sheet.cache.max_tab_bytes`). Умолчание в
выводе — раскрытый путь от `HOME` порта команды, не литерал `$HOME/…`;
`HOME` нет — умолчания нет, значение `(unset)`. Описание ключа — в стиле
соседних, с обратными кавычками: ``Каталог файлов методов образа для `mpu
image sync` и `mpu image export` ``. Список ключей
в справке `mpu config` берётся из реестра, а не вторым списком (сценарии
C1–C3).

Голдены `fixtures/config/` сняты с оригинала на пяти ключах и не меняются.
Исполнитель меняет тесты `config/cmd_config_test.ts`: «список» — первые пять
строк равны `list-default.stdout`, шестая — строка сценария C1; «список
--json» — первые пять записей равны `list-json.stdout`, шестая — запись
сценария C2; «подсказка перечисляет ключи» — список голдена и `, image.dir`;
«реестр: пять ключей» → «шесть ключей», `image.dir` последним; «умолчания
реестра совпадают с теми, что применяют потребители» — `image.dir` в нём
появится с первым потребителем (`image sync`, порция 169), в 169a
потребителя нет. Снапшоты `tools/list` (`deno task tools:snapshot`)
исполнитель пересобирает: в них справка `config`.

## Известные отклонения

- **fix** — реестр ключей изменён относительно оригинала: `mcp.port` был
  добавлен и снят вместе с сервером 7337 (`platform/monolith-removal.md`). Ключ `mcp.legacy_bin` (путь к Python-реализации) существовал, пока жил
  маршрут `legacy`, и снят вместе с ним порцией 97. Чужая строка с этим
  именем, оставшаяся в кэш-БД у того, кто его задавал, **игнорируется
  молча**: чистить чужие данные ради косметики хуже, чем оставить их лежать.
  Три ключа `sheet.cache.*` остаются в реестре, как в
  оригинале: решение 2026-08-27 — после снятия env-слоя конфиг стал их
  единственным источником, и не показывать их значило бы сделать кэш листов
  ненастраиваемым. Итого шесть ключей против пяти (`image.dir` — ниже);
  differential вывода `mpu config` сравнивать по составу реестра этой спеки.
- **fix** — добавлен `image.dir` (2026-09-25, порция 169a): каталог образа
  для `image sync`/`image export`; в оригинале его нет, differential по
  составу — по реестру этой спеки.
- **fix** — env-слоя у механизма предпочтений нет вовсе (решение пользователя
  2026-08-27): ни переменных процесса, ни env-файла. Оригинал читает окружение
  и отвечает `"source": "env"` — снято парой 2026-08-27 на `sheet.default`; у
  нас такого источника не существует, а тексты команд его не советуют.
- **fix** — оригинал требовал `mpu init` (схему служебной БД) для операций
  записи; у нас отсутствующая таблица `config` равнозначна пустой, и запись
  создаёт её сама.
- **fix** — env-файл `~/.config/mpu/.env` в механизм предпочтений не входит:
  он остаётся слоем секретов и подключений native-команд (`env-file.md`).
- **fix** — пустое значение не задаётся: `mpu config <key> ""` → exit 2
  `<key>: пустое значение не задаётся; сбросить ключ — --unset`, хранилище не
  трогается. Оригинал такую строку записывает, и она оседает невидимкой:
  пустое значение читается всеми потребителями как «записи нет», список её не
  показывает, а `--json` объявляет `source: default` при существующей записи.
  Обычный источник вызова — `mpu config <key> "$VAR"` с пустой переменной, и
  промолчать здесь значит потерять намерение (найдено 2026-08-28).
- **fix** — `--unset` вместе со значением → exit 2 `--unset не сочетается со
  значением`; ни удаления, ни записи. Оператор просил два разных действия
  сразу, и выбрать за него одно молча нельзя — тот же класс, что молча
  проглоченный флаг.
- **fix** — чтение работает и там, где пути к хранилищу нет вовсе (не задан
  HOME): список и `config <key>` отвечают умолчаниями, exit 0. Отказывает
  только запись, которой без файла не обойтись. Прямое следствие правила
  «отсутствующее хранилище равнозначно пустому»; иначе `mpu config` в cron или
  контейнере падал бы там, где `mpu mcp` работает.
- `mcp.port` и его проверка диапазона сняты вместе с сервером 7337
  (`platform/monolith-removal.md`).
- **preserve** — три ключа `sheet.cache.*` принимают несуразные значения (`0`,
  `999999999`) без возражений, как и оригинал: замер 2026-08-28. Потребитель
  кэша отбрасывает их сам и пишет заметку в журнал вызовов
  (`platform/webapp-http.md`), а расхождение с рабочей версией на ровном месте
  дороже пользы от строгости.
- **fix** — короткое env-имя `MPU_SS` не действует: вместе с env-слоем ушло и
  оно. `MPU_XLSX` — не исключение из решения, а другой слой: у `xlsx` это ключ
  **env-файла** (`xlsx.md`, «реализовано»), а не переменная окружения процесса,
  и права `--allow-env` он не требует. Механизма предпочтений это не касается.
