# Внутреннее имя: `next` уходит, остаётся строка

Статус: реализовано — порция 155 (`1389700`, один коммит: 32 файла, 77
строк). Принято 2026-09-22: гейты сняты хостом по одному, числа до и после
совпали (тестов 2142, `smoke` — проверок 19, пропущено 1; `fmt` 791, `lint`
776, `check` чисто); `grep` по пяти подпроектам и `web` не даёт `mpu-next`
нигде, кроме имени прежней службы, которое установщик ищет по делу;
переустановка на машине владельца прошла, и `strings` по **установленному**
клиенту даёт ноль вхождений.

## Назначение

Снаружи имя уже чистое: ни клиент, ни сервер не печатают `mpu-next` ни одной
строкой. Внутри дерева рабочее имя живо — замер 2026-09-22, после порции 154:
**35 вхождений в 22 файлах кода**, 80 в документах, два комментария внутри
собранного клиента (видны `strings`), плюс каталог ядра исполнения
`back/src/next/` и девять модулей, импортирующих по этому пути.

`next` означало «следующая версия», и версия эта наступила: следующей больше
нет, есть работающая. Имя, называющее момент времени, а не предмет, — то же
самое, что `data` или `result`: читатель узнаёт из него только то, что автор
не выбрал названия [D.1].

Порция механическая: переименование без единой правки поведения.

## Что чем становится

| Сегодня | После порции | Почему |
|---|---|---|
| каталог `back/src/next/` | `back/src/line/` | там живёт исполнение **строки** — доменное слово спек (`platform/back-rpc.md`) |
| «точка входа `mpu-next`», «строка `mpu-next`» в шапках и JSDoc | «строка» без имени программы | строку исполняет сервер, а зовут её три клиента; называть её именем одного — неверно по сути, а не только устарело |
| `mpu-next` в описании схемы `tree.snapshot` | «узлы дерева команд» | это **контракт**: описание уходит наружу через `/rpc schema` |
| `mpu-next` в именах тестов и голденов | то же без имени программы | имя теста читают как утверждение |

Имя файла `back/src/next/line.ts` после переезда каталога станет
`line/line.ts`; удвоение снимается тем же переименованием — внутреннее имя
модуля выбирает исполнитель по тому, что в нём лежит [D.2].

## Чего порция не делает

- **Не трогает `ts/cli/`**: подпроект назван по своей роли (клиент), а
  задача `cli` — по нему же. Переименование ради симметрии — правка без
  причины.
- **Не переписывает историю в статусах спек.** «Порция 142 (`mpu-next`)» —
  запись о том, что было, и она верна [D.3].
- **Не меняет поведения ни в одном случае.** Проверка этого — гейты до и
  после: состав тестов тот же, числа те же.

## Порядок

Один коммит: переименование целиком. Разбить его нельзя — половина дерева с
новым путём и половина со старым не компилируется, а «переименовать и
поправить импорты отдельно» даёт красный гейт посередине [D.4].

Исключение — голден схемы: он снимается прогоном после переименования и
замораживается хостом при приёмке.

## Инварианты

- `grep -rn "mpu-next"` по `ts/`, исключая `docs/` и статусы спек, не даёт ни
  одного вхождения, кроме имени прежней службы `mpu-next.service` в
  установщике и его прогоне: это реальное имя того, что он снимает, а не
  наше название (найдено при реализации; список подпроектов в проверке
  включает и `ts/web` — там жили те же видимые человеку строки).
- Собранный клиент не содержит строки `mpu-next` (проверяется `strings`).
- Числа гейтов до и после совпадают: тестов столько же, `smoke` даёт те же
  проверки.
- Ни один файл не меняет поведения: дифф состоит из имён и путей.

## Граничные случаи и ошибки

| Дано | Ожидается |
|---|---|
| `grep -rn "mpu-next" ts/back ts/cli ts/mcp ts/supervisor ts/complete` | пусто |
| `strings ~/.local/bin/mpu \| grep mpu-next` | пусто (после переустановки) |
| `deno task test` до и после | одно и то же число тестов, 0 упавших |
| `deno task smoke` до и после | одно и то же число проверок |
| `/rpc schema` | описание снимка без имени программы; голден переснят |
| импорт `../next/mod.ts` где-нибудь остался | `deno check` краснеет — пути меняются все разом |
| статус спеки «порция 142 (`mpu-next`)» | не трогается: это запись о прошлом |

## Golden-примеры

`fixtures/back-rpc/schema.json` — пересъёмка после переименования (меняется
одно описание). Снимает исполнитель, хост замораживает при приёмке.

## Известные отклонения

- Документы (`docs/`, 80 вхождений) переименовываются **не целиком**: в
  текстах спек `mpu-next` меняется на «строку» там, где речь о предмете, и
  остаётся там, где речь о программе с таким именем в прошлом. Правит их
  хост, не исполнитель: `docs/` — его канал.

## Пункты чек-листа

`design.md`:

1. Примитивы — изменил: предмет называется тем, что он есть (строка), а не
   тем, когда он появился [D.1].
2. Особые случаи → получатели — ничего: получателей порция не трогает.
3. Проверка `null` — ничего.
4. Кто решает — изменил: внутреннее имя модуля выбирает тот, кто видит его
   содержимое, а не история каталога [D.2].
5. Память приватна — ничего.
6. Голые данные → протокол — ничего.

`design-mpu.md`:

1. Команда — сообщение объекту — ничего.
2–3 — ничего.
4. Один факт — один источник — изменил: имя предмета названо один раз —
   доменным словом спек, и код перестаёт спорить с ними [D.1].
5. Величина из результата — ничего.
6. Права Deno — ничего.
7. Границы модулей — ничего: границы те же, меняются имена.
8. Внешнее ссылкой — ничего.
9. Голден снятый — изменил: описание схемы переснимается прогоном [D.5].
10. Пропускаемая проверка — изменил: «в бинаре нет старого имени» не
    пропускается — это единственная проверка, которую не видит `grep` по
    исходникам [D.5].

[D.1] Имя называет предмет. [D.2] Имя выбирает тот, кто видит содержимое.
[D.3] История не переписывается. [D.4] Переименование — один коммит.
[D.5] Голден и бинарь проверяются прогоном.
