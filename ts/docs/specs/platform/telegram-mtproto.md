# platform/telegram-mtproto

Статус: реализовано

## Назначение

Сеанс Telegram от имени личного аккаунта (протокол MTProto, не бот) — общая
часть всех подкоманд `telegram`: конфигурация, строка сессии, прокси, открытие
и закрытие соединения, приведение адресата к виду, понятному клиенту, и
раскладка ошибок по кодам выхода. Своей CLI-поверхности у слоя нет.

## Возможность

- **Открыть сеанс**: конфигурация → подключённый авторизованный клиент.
  Закрытие — обязанность вызывающего и происходит в любом исходе.
- **Резолв адресата**: строка пользователя → адресат, пригодный для операции.
- **Классификация ошибки**: отказ → текст одной строкой и код выхода.

## Конфигурация

Значения читаются из env-файла (слой — `platform/env-file.md`).

- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` — обязательны. Отсутствие любой:
  stderr начинается с `telegram: environment variable <ИМЯ> is not set.` (далее
  в тексте — путь env-файла), exit 1. Нечисловой `TELEGRAM_API_ID` →
  `telegram: TELEGRAM_API_ID должен быть числом, получено '<строка>'`, exit 1.
- `TELEGRAM_SESSION` — строка сессии (см. ниже). Пустая или не принятая
  клиентом → до любой операции `` telegram: не авторизован; запусти `mpu init` ``,
  exit 1. Тот же текст и тот же код даёт **отозванная** сессия: строка разбирается,
  но учётной записи за ней больше нет. Различать эти два случая пользователю
  незачем — действие одно и то же.
- `TELEGRAM_DEFAULT_CHAT` — адресат по умолчанию для подкоманд, которые кому-то
  пишут. Пустое значение равнозначно незаданному.
- `TELEGRAM_PROXY` — прокси, применяемый только к Telegram. Не задан → берётся
  `HTTPS_PROXY`, затем `https_proxy`.

## Строка сессии — внешняя граница

`TELEGRAM_SESSION` — не внутреннее представление, а разделяемое значение: её
пишет шаг входа `mpu init` (`init.md`), и пока переезд не закончен, одну и ту же
строку читают обе реализации команды. Отсюда два обязательных требования:

- строка принимается **как есть**, без повторного входа оператора;
- команда её **не переписывает**: после любой операции значение в env-файле
  побайтово прежнее.

Оба требования проверяемы: снять значение до вызова и после, сравнить; вызов на
строке, записанной входом, обязан дойти до операции.

## Прокси

Значение — URL. Схема задаёт вид туннеля: `http`, `https` — CONNECT; `socks5`,
`socks5h` — SOCKS5; `socks4`, `socks4a` — SOCKS4. Схемы с `h`/`a` — синонимы
основных: они означают резолв имён на стороне прокси, а адреса узлов Telegram
приходят числовыми, поэтому наблюдаемой разницы нет.

- `host:port` обязателен; порт отсутствует → `telegram: в прокси-URL нужен
  host:port — '<url>'`, exit 1.
- Учётные данные — в форме `user:pass@`; percent-последовательности
  декодируются (`%40` → `@`).
- Иная схема → `telegram: неподдерживаемая схема прокси '<схема>'; попробуй:
  http/https/socks5/socks4`, exit 1.

Ловушка, которую слой обязан оставить видимой: `HTTPS_PROXY`, заданный в
env-файле, проксирует не только Telegram, а весь инструмент; `TELEGRAM_PROXY`
такого действия не имеет.

## Резолв адресата

Вход — строка. Нормализация, по порядку: префикс `t.me` (со схемой `https://`,
`http://` или без неё) срезается, остаётся хвост без крайних `/` — пустой хвост
означает, что строку берут целиком; ведущий `@` срезается; строка из цифр с
необязательным ведущим минусом — это числовой id, не название; всё прочее идёт
как строка.

Строка из цифр длиннее безопасного целого числа (более 15 знаков) числовым
идентификатором **не** считается и идёт строкой: разбор такой строки в число
округлил бы её молча, и сообщение ушло бы в чужой чат. Отказ приходит от
резолва, а не от округления.

`me` — «Избранное», собственный чат пользователя. Ему предшествует определение
себя: адресат `me` резолвится только после того, как сеанс узнал собственную
учётную запись.

Явно указанный адресат всегда приоритетнее значения из env-файла.

Порядок резолва строки — **две попытки, а не одна**:

1. штатный резолв клиентом: `me`, числовой id, имя пользователя, ссылка `t.me`,
   телефон;
2. **если он не удался** — поиск чата по названию (`telegram-ls.md`, «Резолв по
   названию»).

Вторая попытка обязательна и для строки, которая выглядит именем пользователя:
`news` — валидное имя пользователя по форме, но если такого имени нет, это
скорее всего название чата, и отказ на первой попытке останавливать команду не
должен. Единственное исключение — строка, где пользователь объявил вид сам:
ведущий `@` и ссылка `t.me` означают именно имя пользователя, и на них вторая
попытка не делается.

Сам поиск по названию живёт в `telegram-ls.md` и до реализации той подкоманды
второй попытки нет — строка даёт отказ резолва.

## Инварианты

- Один вызов — один сеанс: соединение открывается заново и закрывается в любом
  исходе, включая отказ авторизации и ошибку операции.
- Авторизация проверяется до операции; ошибки ввода (код 2) обнаруживаются до
  открытия соединения, то есть без единого сетевого обращения.
- Секреты не попадают ни в stdout, ни в stderr: `TELEGRAM_API_HASH`, строка
  сессии, пароль прокси не появляются в выводе ни при каком отказе, включая
  сообщения об ошибках разбора URL прокси — в них остаётся URL без учётных
  данных.

## Ошибки и коды выхода

- **2** — ошибки ввода: отсутствующий или пустой адресат, невалидные значения
  флагов. Обнаруживаются до сети.
- **1** — конфигурация (см. выше) и Telegram: rate-limit → `telegram:
  rate-limit, подожди <N>s`; прочий отказ протокола → `telegram: RPC error:
  <текст>`.
- **0** — успех.

Формат строки ошибки — `telegram: <причина>[; попробуй: <подсказка>]`, одна
строка, без трейсбеков.

## Известные отклонения

- **fix** — ошибки ввода прежняя реализация завершает кодом 1, не отличая их от
  отказов Telegram. Правильно — код 2 и проверка до сети; тексты неизменны.
- **fix** — при отказе резолва прежняя реализация имеет два разных пути с
  похожим текстом: собственно неудачу резолва (с подсказкой) и исключение,
  выброшенное уже самой операцией отправки, которое оформляется как «не удалось
  найти чат» без подсказки. Второй путь маскирует ошибку операции под ошибку
  адресата. Правильно — резолв один: если адресат получен, отказ операции
  сообщается как отказ операции.
- **preserve** — прокси задаётся одним URL, а не набором полей: это формат,
  который уже лежит в env-файлах операторов, и менять его переезд не вправе.
