# Порция SB1 — клиент sl-back пакетом `tslibs/slback`

Статус: к реализации после OP1 (2026-10-07). Гибрид владельца 2026-10-07:
TS-домены — пакеты `tslibs/<домен>` в монолите. Договор пакета —
`platform/tslibs-package.md`; поведение — `platform/slback-http.md`,
`api.md` (не меняется). `back/src/slback` (~550 строк) уже на `@mpu/http`, со
слоем команд связан двумя местами; потребители — `api`, `get-token`,
`ss-access`, `wb-cards-reset`, `wb-loader`.

## Кто и зачем

Разработчик хочет, чтобы разговор с sl-back (сборка URL, заголовки, одна
попытка под пределом времени, разбор ответа и отказа, получение и
кэширование токена) был библиотекой без привязки к рантайму и к слою команд;
команды `mpu api …` и соседние берут её архивом.

## Граница (наблюдаемая, снято с `main` 2026-10-07)

- В пакет: `client.ts`, `token.ts` (разбор и текст кэша токена), их тесты,
  фейки `testing.ts` (`@mpu/slback/testing`).
- Связи со слоем команд (распутывает исполнитель, `.tmp/design-SB1.md` до
  кода):
  - `config.ts` читает `EnvFile` слоя команд и бросает `DomainError` —
    пакет получает адрес и учётные данные параметрами; чтение env-файла и
    перевод отказа — в `ts/` (как `config` в T1);
  - `session.ts` берёт `CommandIo` (env-файл, чтение и запись кэша токена) —
    пакет принимает порт кэша токена или остаётся сессия в `ts/`; выбор и
    причина — в design-SB1.

## Сценарии [S.n]

1. `tslibs/slback`: `bun install && bun run gate` → зелёно под Bun, Node,
   Deno, `check:release` зелёный; `release/mpu-slback-0.1.0.tgz` закоммичен;
   `@mpu/http` — необязательный `peerDependency` плюс `devDependency`
   архивом; тестовые помощники — `@mpu/testing`.
2. Список листовых случаев `back/src/slback` до = объединение после (пакет +
   `ts/`), строка в строку; сверх — только новые случаи перевода отказа на
   границе.
3. `rg -n 'Deno\.|Bun\.' tslibs/slback/src` → пусто; в пакете нет импорта из
   `ts/`.
4. `ts/package.json` — архив; `cd ts && rm -rf node_modules/@mpu && bun
   install --frozen-lockfile` проходит; гейты `ts/` и `bun run smoke`
   зелёные.
5. Голдены команд `api …`, `get-token`, `ss-access`, `wb-cards-reset`,
   `wb-loader` — без изменений и зелёные.
6. Пароль и токен sl-back не появляются ни в выводе, ни в тексте ошибки, ни
   в журнале — существующие тесты зелёные.
7. Решение после OP1: тест атомарности `writeLokiCache` в `ts/` — сбой
   вставки посреди записи (например, вторая таблица отвергает строку) →
   обе таблицы кэша Loki прежние; мутация «без транзакции» краснеет.
8. Живьём (хост после установки): `mpu api list-clients` (чтение), `mpu api
   get-client id: <любой>` — вывод той же формы, что до порции; кэш токена
   переиспользуется (второй вызов без входа).

## Инварианты

- Наблюдаемое поведение команд не меняется.
- Пакет не знает о слое команд: ни импорта из `ts/`, ни env-файла, ни
  текстов справки.

## Границы

- Самоописание `about`, конверт — этап 6.
- Чтение env-файла и место кэша токена — в `ts/`.

## Пункты чек-листа

`design.md`: 1 примитивы — один вызов sl-back; токен выведен из него; 2
особые случаи — токен в кэше / нет — реализации, не ветки у вызывающего; 7
основание проверкой — [S.2], [S.4]. `design-mpu.md`: 4 один источник —

внешнее — адрес, учётные данные и кэш параметрами/портом; прочее — ничего.
