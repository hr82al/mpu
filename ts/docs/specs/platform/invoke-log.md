# platform/invoke-log — журнал вызовов

Статус: реализовано (2026-08-05, маршрут `native`; goldens сняты с
живой версии — `fixtures/platform/invoke-log/`. Вердикты по двенадцати
вопросам реализации внесены в текст: `mcp token` без секций вывода,
секции и код MCP-записи, `mpu mcp` без записи, имена архивов, перевод
строки в конце секции, пересборка JSON только при совпадении, `dur`,
текст note, пустая секция после обрезки, `--` не распознаётся, lock
только под ротацию)

## Назначение

Каждое исполнение команды — включая завершившееся ошибкой — оставляет
ровно одну запись: что запускали, вывод, ошибки, код, длительность.
Журнал — память оператора («что я уже прогонял и почему упало») и
источник частот. Обе точки входа бинаря журналируются: CLI-вызов и
вызов тула MCP-сервером. Реестровые поверхности — справка, `version`,
completion, ошибки маршрутизации — записей не оставляют (совпадает с
оригиналом; проверено прогоном 2026-08-05: `version`, `--help` и
опечатка имени команды записей не создают). Запуск сервера (`mpu mcp`)
записи тоже не оставляет: это поверхность точки входа, а не вызов
команды, и одна запись на всю сессию сервера не несёт смысла —
журналируются вызовы тулов внутри неё.

## Ввод/вывод

Формат записи — текстовый, унаследован от оригинала дословно; секция с
пустым содержимым не печатается:

```
### <YYYY-MM-DD HH:MM:SS.mmm> <+HH:MM> run=<id> pid=<pid> cwd=<каталог>
$ mpu <argv после маскирования, shell-кавычение>
--- note run=<id> ---      # диагностика обвязки, если была
--- out run=<id> ---       # stdout verbatim
--- truncated run=<id> stream=out dropped=<байт> ---
--- err run=<id> ---       # stderr / текст ошибки
--- end run=<id> exit=<код> dur=<сек, 3 знака>s ---
<пустая строка>
```

`run_id` = `YYYYMMDD-HHMMSS.mmm-<pid>`. Границы записи при чтении
определяются только шапкой и `--- end` с тем же run_id — похожие маркеры
внутри чужого вывода запись не рвут. Строка `$ mpu …` всегда начинается
литеральным `mpu`, независимо от argv[0]. Код в записи: exit-код
команды/подпроцесса; внутренняя ошибка обвязки → 1, детали в err-секции.

**Запись вызова через MCP-сервер**: та же шапка; `pid` и `cwd` —
серверного процесса; строка команды —
`$ mpu <путь команды через пробел> '<JSON аргументов одной строкой>'`
(shell-кавычение; маскирование JSON — по правилам ниже); `run_id` — то
же правило формирования. Секции те же, что у CLI: в `out` — текстовое
содержимое ответа (то же, что при этом вызове увидел бы человек в
CLI), в `err` — текст ошибки; код записи — тот же класс, что CLI отдаёт
exit-кодом: 0 успех, 1 доменная ошибка и внутренний сбой, 2 ошибка
ввода. Структурное содержимое ответа в запись не дублируется: журнал
остаётся читаемым и единообразным с CLI-записями того же файла.

Секция заканчивается переводом строки: если вывод команды им не
заканчивался, он дописывается — маркер следующей секции всегда с новой
строки, сам вывод в записи дословный.

## Побочные эффекты

Пишет файл журнала (дефолт — `~/.config/mpu/mpu.log`) + соседний
lock-файл `mpu.lock` (имя без суффикса `.log` — осознанно, чтобы не
попадать под глоббинг ротации); каталог создаётся. Оба файла — 0600:
у журнала права выравниваются при каждой записи, lock-файл создаётся
с ними и переоткрывается только под ротацию, до первой ротации его нет
вовсе (см. «Известные отклонения»). Пока жив маршрут `legacy`, файл и
lock общие с Python-реализацией: обе стороны сериализуют ротацию одним
lock-файлом. Сети нет.

Ротация: при превышении порога архивы сдвигаются с хвоста —
`<файл>.<keep-1>` → `<файл>.<keep>`, … , `<файл>.1` → `<файл>.2`,
текущий файл → `<файл>.1`; лишний архив вытесняется. `keep=0` — вместо
ротации файл удаляется, архивы не заводятся.

**Разделение моста.** Запись legacy-вызова делает сам
Python-подпроцесс — его собственный журнал (тот же файл, тот же
формат); обвязка бинаря запись для маршрута `legacy` НЕ создаёт —
иначе записей было бы две. Native-вызовы журналирует обвязка: вывод
перехватывается на уровне слоя вывода команды (копия того, что команда
печатает, включая собранный ею вывод её подпроцессов), дескрипторы
1/2 не подменяются.

## Конфигурация

`MPU_LOG_ENABLED` (выкл: 0/off/false/no, любой регистр),
`MPU_LOG_FILE`, `MPU_LOG_MAX_OUTPUT_BYTES` (дефолт 8 МиБ на поток,
0 = без обрезки), `MPU_LOG_MAX_BYTES` (порог ротации, дефолт 50 МБ,
0 = не ротировать), `MPU_LOG_KEEP` (архивов, дефолт 5; 0 = вместо
ротации файл удаляется) — env-слой (`platform/env-file.md`): только
env-файл, окружение процесса не читается. Файл общий с
Python-подпроцессом — выключение ключом в нём гасит оба журнала;
экспорт `MPU_LOG_*` в shell на native-журнал не влияет (журнал
legacy-подпроцесса до вывода моста окружение учитывает — поведение
Python). Битым считается всё, кроме целого неотрицательного (в том
числе `-1` и `1.5`); такое значение → дефолт + строка note в текущую
запись, по строке на ключ, дословно:
`MPU_LOG_KEEP=abc: не целое неотрицательное число, взято умолчание 5`.
Годное значение note не порождает.

## Инварианты

- Ровно одна запись на вызов — native пишет обвязка, legacy пишет
  Python-подпроцесс; append атомарен на локальной ФС, параллельные
  записи не смешиваются.
- Fail-open: любая ошибка журнала (права, диск, лок) не меняет
  результат и код команды; журнал работает на копии байт вывода и не
  может исказить то, что видит пользователь.
- Мимо журнала не проваливается ничего из native-исполнения: ошибка на
  любом этапе обработки вызова, включая инициализацию обвязки, попадает
  в запись (детали в err-секции).
- Секреты маскируются до записи, необратимо, маской-литералом
  `REDACTED`: значения опций, чьё имя содержит
  password/token/secret/api-key/api_key/session (без учёта регистра;
  обе формы — `--opt value` и `--opt=value`); значения таких же ключей
  рекурсивно внутри JSON-аргументов (тел `-b`/`--body` и JSON-аргументов
  MCP-вызова; `@file`-индирекция не разворачивается; невалидный JSON не
  трогается). Разбор argv для маскирования — свой и нарочно грубый:
  схемы команды у записи нет, разделитель `--` не распознаётся, и
  подходящий по имени аргумент после него тоже маскируется.
  Перемаскировать безопаснее, чем недо-. Тело JSON, в котором ни один
  ключ не совпал, остаётся в записи дословно; при совпадении оно
  пересобирается компактно, и исходное форматирование теряется.
- Отдельные команды помечены как «аргументы не журналируются»: у такой
  команды все аргументы после пути команды заменяются той же маской
  `REDACTED` независимо от имён, а JSON-аргументы MCP-вызова заменяются
  маской целиком. Пометка — свойство команды в реестре, не эвристика по
  argv: маскирование по имени опции остаётся правилом по умолчанию для
  всех прочих. Такова `telegram log` (`specs/telegram-log.md`), чей
  единственный аргумент — персональный текст. Секции out/err пометка не
  затрагивает: в них у этой команды только номер сообщения и текст
  ошибки.
- Детекция команд «без записи вывода» — по разрешённому реестром пути
  команды, не по сырому argv; их записи не содержат секций out/err.
  Это `log` (иначе журнал удвоил бы себя собой), `search` и
  `mcp token`: последняя — единственная поверхность, печатающая токен
  доступа, а `platform/mcp-server.md` требует, чтобы он не попадал ни в
  какой вывод и лог. Legacy-команды со своим правилом (`confirm`,
  `api get-token`) обслуживает журнал Python-подпроцесса.
- TTY-природа вывода не искажается: перехват не подменяет дескрипторы,
  isatty у команды и её подпроцессов — как при прямом вызове; вывод
  подпроцесса, которому команда отдала терминал напрямую (наследование,
  как авторизация Telegram в `specs/init.md`), в запись не попадает —
  это цена сохранения интерактива, зафиксированная здесь.
- Ротация ждёт лок не дольше 0,5 с: не успела — запись пишется без
  ротации; запись при неудачной ротации никогда не теряется. Пустой
  (0 байт) файл журнала не ротируется никогда.

## Граничные случаи и ошибки

- Сбой инициализации перехвата → команда исполняется без перехвата,
  запись без out/err.
- Вывод сверх лимита → маркер `truncated` с числом байт сразу после
  секции своего потока; неполный хвостовой UTF-8-символ дорезается.
  Обрезка съела содержимое целиком → секции не остаётся вовсе (пустая
  не печатается), маркер `truncated` печатается.
- Журнал выключен (`MPU_LOG_ENABLED`) → команды работают, записей нет.
- Два вызова тула MCP в одну миллисекунду → run_id обязаны различаться
  (уникальность в пределах файла — инвариант). Способ — за реализацией
  при условии, что формат `run_id` не меняется: у оригинала уникальность
  держалась на одном лишь `pid`, чего хватало процессу с единственной
  записью, но не долгоживущему серверу.
- `dur` меряется от начала обработки вызова до её конца: у CLI это
  практически старт процесса (обвязка открывает запись до
  маршрутизации), у MCP — приход вызова тула.

## Golden-примеры

Сняты с живой версии 2026-08-05 (`fixtures/platform/invoke-log/`;
фикстуры — эталон формы: значения шапки (время, run, pid, dur)

- `record-out-ok.txt` — успешный вызов с out-секцией;
- `record-err-ok.txt` — успешный вызов, вывод только в err-секции

- `record-failed-masked.txt` — упавший вызов (exit=2): значение
  `--token=…` в строке `$ mpu` замаскировано `REDACTED`, err-секция с
  многострочным выводом (рамка не рвёт запись).

Остальные классы — контрактные тесты: обрезка сверх лимита (маркер
truncated + дорез UTF-8); note при битом env-значении; отсутствие
записи для реестровых поверхностей; отсутствие записи обвязки для
маршрута legacy; MCP-запись с JSON-маскированием; ротация (порог,
сдвиг архивов, keep=0 → удаление, пустой файл не ротируется).

## Известные отклонения

- **fix** — оригинал открывает (и потому создаёт) lock-файл при каждой
  записи, ещё до проверки, нужна ли ротация, а права выравнивает только
  у файла журнала; правильно — трогать lock только под ротацию: до
  первой ротации файла нет, сериализация ротаций между реализациями от
  этого не страдает (лок берётся именно тем, кто собрался ротировать).
- **fix** — оригинал пересобирает JSON-тело всегда, как только оно
  разобралось, даже если маскировать было нечего, и форматирование
  пользователя теряется на ровном месте; правильно — не трогать тело,
  в котором ни один ключ не совпал.
- **fix** — тексты note у оригинала английские, с префиксом `log:` и
  раздельные для «не число» и «отрицательное»; правильно — один русский
  текст на оба случая (форма — в «Конфигурации»).
- **fix** — перехват у оригинала — подмена файловых дескрипторов 1/2 с
  выделением pty при TTY; новая обвязка перехватывает на уровне слоя
  вывода команд. Причина: pty-механизма в рантайме новой реализации
  нет; наблюдаемые следствия совпадают для всего native-исполнения,
  кроме подпроцесса с прямым наследованием терминала (см. инварианты) —
  у оригинала его вывод в запись попадал.
