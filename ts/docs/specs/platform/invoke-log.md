# platform/invoke-log — журнал вызовов брокера

Статус: черновик (пересобрана 2026-07-29 под брокер-архитектуру:
журнал — центральный аудит операций на стороне брокера; локальный
журнал оригинала — исходник этой спеки, его формат записей сохранён)

## Назначение

Каждая принятая брокером операция — включая завершившуюся ошибкой и
неизвестный `method` — оставляет ровно одну запись: кто, что, вывод,
ошибки, код, длительность. Журнал — память операторов («что я уже
прогонял и почему упало») и источник частот. Локальные команды CLI,
не ходящие в брокер (`xlsx`), следов не оставляют — принятое
упрощение раскладки.

## CLI-контракт

нет (серверный механизм. Чтение пользователем — команда `mpu log`
через операции домена `log`; их словарь — спека протокола при переезде
команды `log`, фильтры исполняются на стороне брокера).

## Ввод/вывод

Формат записи — текстовый, унаследован от оригинала с добавлением
`user=` (см. отклонения); секция с пустым содержимым не печатается:

```
### <YYYY-MM-DD HH:MM:SS.mmm> <+HH:MM> run=<id> user=<login> op=<method>
$ mpu <argv после маскирования>          # у legacy.run и командных операций
--- note run=<id> ---      # диагностика обвязки, если была
--- out run=<id> ---       # stdout verbatim
--- truncated run=<id> stream=out dropped=<байт> ---
--- err run=<id> ---       # stderr / текст ошибки операции
--- end run=<id> exit=<код> dur=<сек, 3 знака>s ---
<пустая строка>
```

`run_id` = `YYYYMMDD-HHMMSS.mmm-<суффикс уникальности>`. Границы записи
при чтении определяются только шапкой и `--- end` с тем же run_id —
похожие маркеры внутри чужого вывода запись не рвут. Строка `$ mpu …`
всегда начинается литеральным `mpu`, независимо от argv[0] вызвавшего
CLI. Код в записи: результат операции/exit-код legacy-процесса;
внутренняя ошибка → 1, детали в err-секции.

## Побочные эффекты

Пишет файл журнала на сервере брокера (дефолт —
`~/.config/mpu/mpu.log` пользователя сервиса) + соседний lock-файл;
оба 0600, права выравниваются при каждой записи; каталог создаётся.
Перехват вывода исполняемых процессов (legacy-делегация) — на уровне
файловых дескрипторов 1/2: вывод дочерних процессов тоже попадает в
запись. Сети нет. Shell-completion исполняется целиком на CLI и
операций не порождает — правило оригинала «completion отключает
журнал» выполняется по построению.

## Конфигурация

`MPU_LOG_ENABLED` (выкл: 0/off/false/no, любой регистр),
`MPU_LOG_FILE`, `MPU_LOG_MAX_OUTPUT_BYTES` (дефолт 8 МиБ на поток,
0 = без обрезки), `MPU_LOG_MAX_BYTES` (порог ротации, дефолт 50 МБ,
0 = не ротировать), `MPU_LOG_KEEP` (архивов, дефолт 5, 0 = ротация без
архивов) — env брокера (`platform/config.md`). Битое числовое
значение → дефолт + note в текущую запись.

## Инварианты

- Ровно одна запись на операцию; append атомарен на локальной ФС,
  параллельные записи не смешиваются.
- Fail-open: любая ошибка журнала (права, диск, лок) не меняет
  результат и код операции; журнал работает на копии перехваченных
  байт и не может исказить проброшенный вывод.
- Мимо журнала не проваливается ничего: ошибка на любом этапе
  обработки операции, включая инициализацию обвязки, попадает в запись
  (детали в err-секции).
- Секреты маскируются до записи, необратимо: пароль из `auth.login` не
  пишется ни в каком виде; значения опций, чьё имя содержит
  password/token/secret/api-key/session (без учёта регистра, раздельная
  и `=`-форма), и такие же ключи рекурсивно внутри JSON-тел
  (`@file`-индирекция не разворачивается; невалидный JSON не
  трогается); выданный JWT не логируется.
- Операции, помеченные в своих спеках «без записи вывода» (наследники
  правил для `log`, `confirm`, `search`, `api get-token`), пишутся без
  секций out/err — перехват для них не включается вовсе.
- Ротация ждёт лок не дольше 0,5 с: не успела — запись пишется без
  ротации; запись при неудачной ротации никогда не теряется.

## Граничные случаи и ошибки

- Перехват вывода не удался → операция исполняется без перехвата,
  запись без out/err.
- Вывод сверх лимита → маркер `truncated` с числом байт; неполный
  хвостовой UTF-8-символ дорезается.
- Пустой (0 байт) файл журнала не ротируется никогда — первая запись
  любой величины ложится целиком.
- Журнал выключен (`MPU_LOG_ENABLED`) → операции работают, записей нет.

## Golden-примеры

нет — серверный механизм: формат записи закрепляется контрактными
тестами брокера по шаблону из «Ввод/вывод»; пользовательская
поверхность (`mpu log` и его фильтры `--tail/--failed/--cmd/--since/
--run`) снимет свои golden со старой версии при переезде команды `log`
(вывод чтения — те же записи verbatim).

## Известные отклонения

- **fix** — запись расширена полями `user=<login>` (журнал
  многопользовательский) и `op=<method>`; `pid=`/`cwd=` оригинала
  теряют смысл на сервере и заменены этими полями. Прочая структура
  записи сохранена намеренно: differential чтения `mpu log` сравнивать
  с поправкой на шапку.

## Открытые вопросы

- Видимость чужих записей: показывает ли `mpu log` операции всех
  пользователей или только свои — решить при спеке домена `log`
  (дефолт-кандидат: все видят всё, журнал — общая память команды).
- Суффикс уникальности `run_id` на многопоточном сервере (pid
  оригинала не подходит) — при реализации.
- Детекция «операций без перехвата» — по словарю операций, а не по
  argv (устраняет открытый вопрос оригинала про флаг перед именем
  команды); закрепить тестом при реализации.
