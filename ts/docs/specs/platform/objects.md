## Назначение

Строка вызова — цепочка сообщений (`platform/messages.md`). Эта спека задаёт,
как цепочка исполняется: сообщение уходит объекту-приёмнику, объект отвечает
результатом, результат становится приёмником следующего сообщения. Здесь же —
что понимает любой объект (справка, список селекторов, «понимаешь ли ты»),
что происходит с непонятым сообщением и как метод меняется в работающем
процессе.

Порция вводит модель на **тестовом дереве объектов** (ниже). Перевод
нынешних команд в объекты — следующая порция. Модуль в `ts/back/`, к точке
входа CLI и к MCP-серверу не подключается.

## Тестовое дерево

Объекты, которые тест строит сам (кодом, а не таблицей данных):

| Объект | Путь | Назначение | Сообщения |
|---|---|---|---|
| корень | `mpu` | `вспомогательные операции над данными монорепо` | `kiten` (`карточки Kaiten`) → объект Kaiten; `version` (`версия mpu`) → данные `"0.1.0"` |
| Kaiten | `mpu kiten` | `карточки Kaiten` | `card` (`карточки по номеру`) → объект карточек; `card:` (`одна карточка по номеру`; ключ `card`, значение, обязателен) → карточка с этим номером; `ls` (`мои карточки`) → данные `["a", "b"]` |
| карточки | `mpu kiten card` | `карточки по номеру` | любое слово из цифр → карточка с этим номером (вид звена `<card>`, назначение `карточка с номером`); прочее слово → отказ `нет карточки <слово>` |
| карточка | `mpu kiten card 123` / `mpu kiten card: 123` | назначение вернувшего сообщения | `show` (`карточка целиком`) → данные `{"id": "<номер>"}`; `comment` (`комментарий к карточке`) → объект комментария; `comment:` (`оставить комментарий`; ключ `comment`, значение, обязателен) → данные `{"commented": "<номер>", "text": "<текст>"}` |
| комментарий | `… comment` | `комментарий к карточке` | `clear` (`убрать текст`) → данные `{"commented": "<номер>", "text": ""}`; любое слово → данные `{"commented": "<номер>", "text": "<слово>"}` (вид звена `<text>`, назначение `текст комментария`) |

Назначение объекта — назначение сообщения, которое его вернуло (у корня —
своё; у объекта, вернувшегося на произвольное слово, — назначение вида
звена). У каждого сообщения кроме назначения есть текст справки; в тестовом
дереве он равен `Справка: <назначение>.`

## Ввод/вывод

**Вход:** слова строки и корневой объект.

**Выход** — один из трёх:

- итог-данные: `{ "path": [<звенья>], "value": <данные> }` — последний
  ответ цепочки данные, либо строка исполнялась в режиме справки (тогда
  данные — текст справки);
- итог-объект: `{ "path": [<звенья>], "object": "<текст>" }` — слова
  кончились, а последний ответ — объект; текст — справка метода, который его
  вернул (тот же, что дал бы режим справки), путь — без `help`;
- отказ: текст и код 2.

`path` — по звену на исполненное сообщение: унарное — его слово; ключевое —
ключи через двоеточие в порядке алфавита с двоеточием в конце (`card:`,
`a:b:`); слово, которое объект понял как произвольное, — вид звена
(`<card>`). Путь — то, по чему следующая порция проверяет правила
подтверждения.

Эталон — `fixtures/objects/cases.json` (слова → итог или отказ) и
`fixtures/objects/help-*.txt` (тексты справки).

## Правила

**Методы и виды результата.** Каждый метод объекта (унарный, ключевой, а
также ответ на произвольное слово — «метод вида звена») объявляет назначение,
текст справки и **вид результата**: данные или объект определённого вида.
Вид объекта знает собственные селекторы своих объектов без создания объекта;
вид данных — что сообщений дальше нет. Это протокол, а не булев признак.

**Исполнение.** Шаг разбора (`platform/messages.md`) получает описание
текущего приёмника — **от самого приёмника**: собственные селекторы объекта
плюс общие (`help`, `selectors`, `respondsTo:` — ключ `respondsTo`,
значение). Собственные селекторы — единственный источник для разбора,
`selectors` и справки; общие добавляет одно общее для всех объектов
поведение, и только в описание для разбора. Сообщение уходит
приёмнику; ответ — следующий приёмник. Слова кончились — итог: данные
последнего ответа. Ошибка разбора — отказ с её текстом.

**Что понимает любой объект** (в `selectors` и в разделе «Сообщения» справки не перечисляется, но в описании для разбора есть):

| Сообщение | Ответ |
|---|---|
| `help` | см. «Справка» ниже |
| `selectors` | собственные селекторы объекта, по алфавиту: унарные словом, ключевые — `a:b:` |
| `respondsTo:` (ключ `respondsTo`, значение; ключевой селектор пишется за `--`: `respondsTo: -- card:` — правило значения `platform/messages.md`) | `true`, если селектор есть среди собственных или среди общих; иначе `false`. Про произвольные слова не отвечает: у объекта карточек `respondsTo: 123` → `false` |

**Данные в конце цепочки.** Ответ-данные — тоже объект («значение»). Любое
сообщение к нему, включая общие `selectors` и `respondsTo:`, — отказ `<путь>: цепочка окончена, <селектор> отправить
некому`.

**Непонятое сообщение.** Объект, у которого нет такого селектора, отвечает
`doesNotUnderstand`. По умолчанию — отказ
`<путь>: не понимает <селектор>`; если среди собственных селекторов объекта
есть близкие (расстояние Левенштейна ≤ 2), добавляется
`; ближайшие: <через запятую>` — не больше трёх, по возрастанию расстояния,
при равенстве по алфавиту. Объект может переопределить ответ: так объект
карточек понимает номер. Проверка порядка: сначала собственный селектор,
затем общий, затем `doesNotUnderstand`.

**Справка.** Если в цепочке есть сообщение `help` (словом `help` или
`--help`, в любом месте), строка исполняется в режиме справки:

1. сообщение `help` из цепочки убирается — по слову, до поиска селектора; остальные идут в прежнем порядке
   (`mpu help kiten card` ≡ `mpu kiten help card` ≡ `mpu kiten card --help`);
2. все сообщения, кроме последнего, исполняются как обычно (отказы — те же);
3. **последнее сообщение не исполняется**: итог — справка его метода у
   текущего приёмника (для произвольного слова — справка метода вида звена);
   метода нет — тот же отказ `doesNotUnderstand`, что без справки;
4. сообщений не осталось — справка корня.

Так справка к команде никогда её не запускает. Путь итога — `help` и
звенья сообщений (`["help", "kiten", "card"]`). Слово `help` как
произвольное слово объекту не попадает: общий селектор проверяется раньше
`doesNotUnderstand`; передать текст `help` можно только значением ключа.

**Путь в тексте.** `<путь>` в отказах и справке — `mpu` и звенья до
приёмника через пробел, ключевые звенья с двоеточием, произвольное слово —
как написано в строке (`mpu kiten card 123`), ключевое — ключи со
значениями в порядке строки (`mpu kiten card: 123`).

**Текст справки** — оканчивается одним переводом строки. Справка метода с
видом результата «объект»:

```
Использование: <путь> <сообщение>

<назначение>

<текст справки>

Сообщения:
  <селектор>  <назначение>
  …
```

`<путь>` — путь до объекта, которого метод вернул бы (включая слова самого
метода); назначение и текст — метода; «Сообщения» — собственные селекторы
вида результата, по алфавиту, выровнены по самому длинному из всех строк
раздела плюс два пробела; если вид понимает произвольное слово — строка
`<вид звена>` с назначением метода вида идёт последней. Справка корня — та
же форма с назначением и текстом корня. Справка метода с видом результата
«данные» — без строки «Использование» и без раздела «Сообщения»: `<путь>`
строкой, пустая строка, назначение, пустая строка, текст справки.

**Замена метода на лету.** Метод объекта может жить в модуле, загружаемом по
URL. Новая версия модуля, загруженная в тот же процесс, заменяет метод: у
следующего сообщения — новый ответ, без перезапуска и без пересоздания
остальных объектов.

## Инварианты

- Объект сам сообщает свои селекторы; справка, рефлексия и разбор берут их из
  одного места.
- `selectors` и справка не расходятся: каждый селектор из `selectors` есть в
  разделе «Сообщения», и наоборот (кроме строки вида звена).
- В режиме справки последнее сообщение не исполняется.
- Исполнение не читает окружение, файлы и сеть, кроме загрузки модуля при
  замене метода.
- Один и тот же вход на тех же объектах — тот же итог.
