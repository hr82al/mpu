# Перевод всех команд на словарь ключей

Статус: к реализации — порция 159.

## Назначение

Порция 158 перевела на ключи три образца (`kiten card`, `sql`, `sql-ro`); эта
переводит остальные: позиционных значений и хвостов больше нет ни у одной
команды, кроме названных исключений; флаги формата становятся форматами
результата. **Ни одна возможность команды не теряется**: каждый нынешний вход
получает новый адрес; исчезает только написание (короткий флаг, snake_case),
и на него — отказ с готовой строкой.

Значение ключа в этой порции — **одно слово** строки (как в 158): многословное
значение в терминале берётся в кавычки оболочки, в MCP — один элемент массива.
Запись многословного текста без кавычек (`^…^`) — порция языка, не эта.

## Словарь ключей

| Ключ | Смысл |
|---|---|
| `target` | где исполнить — прежний селектор (номер клиента, имя или часть, `sl-N`, `dev:N`), та же логика разбора (`selector.md`) |
| `id` | номер или идентификатор главной сущности команды |
| `text` | свободный текст (комментарий, сообщение) |
| `query` | что искать |
| `since`, `until` | границы времени |
| `limit` | сколько |

Прочий ключ — описательное имя вне словаря с причиной: записью в таблице
«Вне словаря» справочника команды и в объявлении команды. Тест: у каждой
команды каждый ключ либо из словаря, либо с причиной.

## Правила перевода

| Сейчас | Становится |
|---|---|
| позиционный селектор | `target:` |
| сужающие флаги `--client-id`, `--sid`, `logs --client` | ключи `client-id:`, `sid:`, `client:` (как были) |
| `--server` у `sql`/`sql-ro` | снят в 158 |
| `--server` у прочих | ключ `server:` (как был): равносильность `target: sl-N` не доказана прогоном |
| позиционный идентификатор главной сущности | `id:` |
| второй идентификатор в той же команде | ключ по имени сущности: `mr:`, `log:`, `client:`, `spreadsheet:`, `dataset:`, `module:`, `discussion:` |
| параметры пути команд `api` (`:userId`, `:clientId`, …) | единственный — `id:`; несколько — внутренний `id:`, внешние по имени сущности (`client:`, `spreadsheet:`, `dataset:`) |
| позиционный свободный текст | `text:` |
| позиционный текст поиска | `query:` |
| флаги формата (`--json`, `--md`, `--tsv`, `--table`, `--raw`, `--out <вид>`) | форматы результата (`… end json`, как в 158); флаг — отказ с готовой строкой |
| флаги поведения (`--dry-run`, `--print`, `--local`, `--all`, `--via`, `--follow`, `--no-comments`, `--force` …) | без изменений (варианты — отдельная порция) |
| подстановка stdin (значение не дано, `-`, `--from -`, `--body-file -`) | без изменений |
| короткий флаг (`-v`, `-p`, `-m`, `-F`, `-f`, `-s`, `-n`, `-l`, `-R`, `-e`, `-i`, `-t`, `-y`, `-j`, `-d`, `-b`) | только полное имя; короткий — отказ «флаг — полным именем: …» с готовой строкой (как `-v` в 158) |
| двойное написание (`spreadsheet_id` и `spreadsheet-id`, `ref_date`, `nm_ids`, `update_type`, `date_from`, `grep_regex` …) | только через дефис; с подчёркиванием — отказ с готовой строкой |
| вход-список (позиционный `rest`: `xlsx get`/`sheet get` диапазоны, `glab-status` MR; повторяемые флаги: `logs --grep`, `--grep-regex` …) | ключ в единственном числе, **повторяется**; значения копятся по порядку: `xlsx get range: A1 range: B2`, `logs grep: a grep: b`; повтор прочих ключей — прежняя ошибка «ключ указан дважды» |
| группа с селектором впереди (`ozon-jobs`, `wb-jobs`, `data-loader-jobs`, `*-migrations`, `users`) | `target:` у подкоманды: `mpu ozon-jobs show target: sl-2`; прежнее `mpu ozon-jobs sl-2 show` — отказ «значение — ключом» с готовой строкой; путь правила — путь подкоманды (`ozon-jobs show <args>`), у узла группы хвоста больше нет |
| чужой хвост `ssh` | значение `cmd:` одним словом: в терминале — кавычками оболочки (`cmd: "ls -la"`), в MCP — одним элементом массива |

## Исключения — поимённо

| Команда | Сейчас | Становится | Почему |
|---|---|---|---|
| `mr comment` | поле `target` (FILE:LINE) | `at:` | `target` занят словарём |
| `mr create` | поле `target` (ветка назначения) | `into:` | то же |
| `move-client` | флаг `target` (сервер назначения) | `to:` | то же |
| `move-client-back` | `ls` / `rm <селектор>` значением | унарные `ls`, `rm` + `target:` | слово-режим в позиции значения |
| `logs` | `ls` значением селектора / сервиса | унарные `hosts` (`mpu logs hosts`), `services` (`mpu logs services target: sl-1`) | то же |
| `kiten status` | `--since` и `--time-since` | `since:` и `horizon:` | два независимых окна |
| `kiten time edit/rm` | карточка и запись учёта | `id:` (карточка), `log:` (запись) | два идентификатора |
| `mr delete/edit` | заметка и MR | `id:` (заметка), `mr:` | то же |
| `mr reply/resolve/unresolve/show` | тред и MR | `id:` (тред), `mr:` | то же |
| `run-js` | код значением / `--file` / stdin | `text:` / `file:` / stdin | три режима называются, не угадываются |
| `kiten field set` | пустое значение — очистить поле | `text: ""` (пустое слово) | пустой текст отличим от «ключа нет» |
| `api ss-access`, `api wb-cards-reset`, `api wb-loader *` | селектор | `target:`, если команда резолвит его общим модулем селектора; иначе `spreadsheet:` / `cabinet:` | не тот же вид значения |

Умолчания без ключа остаются: `kiten card` — наглядно в терминале, markdown в
пайпе; `mr *` без `mr:` — MR текущей ветки; `copy-dev` без `target:` —
режим рабочих пространств; `xlsx *` без `file:` — `MPU_XLSX`, затем
`xlsx.default`.

## Проверка полноты и пара

- **Снимок старой схемы.** Первым коммитом порции — снимок входов всех команд
  до перевода (имя, вид, обязательность, умолчание, stdin), снятый из кода;
  лежит в `testdata` (голден «снятый»).
- **Тест полноты:** каждый вход снимка есть в новой схеме по правилам или
  таблице исключений, либо назван в списке снятых написаний (короткие флаги,
  snake_case, флаги формата — только эти три вида). Вход без адреса — красный
  тест.
- **Пара разбора:** на каждую команду — пример прежней строки и новой; обе
  разбираются в **один и тот же** вход команды (объект аргументов), включая
  умолчания и stdin. Без сети и стенда.
- **Справки** всех команд — ключи из объявления, примеры новой формы
  (однострока → «когда звать» → примеры → состав); голдены пересобираются
  прогоном.

## Граничные случаи

| Строка | Ожидается |
|---|---|
| `mpu kiten comment 55 ok` | `mpu kiten comment: значение — ключом: mpu kiten comment id: 55 text: ok`, код 2 |
| `mpu kiten comment id: 55 text: ok -m x` | `…: флаг — полным именем: … --message x`, код 2 |
| `mpu process 54 --spreadsheet_id X` | `…: ключ через дефис: … --spreadsheet-id X`, код 2 |
| `mpu ps --tsv` | `…: формат — сообщение результату: mpu ps end tsv`, код 2 |
| `mpu logs ls` | `…: хосты — сообщением: mpu logs hosts`, код 2 |
| `mpu mr comment id: 5 at: src/a.ts:10 text: "см. тут"` | комментарий к строке, как прежде `mr comment 5 src/a.ts:10 -m …` (пара разбора) |
| `mpu ssh target: sl-1 cmd: "ls -la"` | как прежде `mpu ssh sl-1 ls -la` |
| `mpu api get-client-module client: 54 id: wb` | как прежде `mpu api get-client-module 54 wb` |

## Известные отклонения

- Короткие флаги и snake_case-написания исчезают как написание; возможность —
  у полного имени.
- Порция крупная: исполнитель останавливается после целого раздела на зелёном
  дереве, если не помещается (разделы — в постановке).

## Открытые вопросы

Нет. Спорные строки таблицы исключений — в отчёт, владелец вычитает список
«снятых написаний» после порции (он без потерь возможностей по построению).
