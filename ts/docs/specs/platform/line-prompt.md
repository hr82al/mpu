# Вопрос посреди строки: ответ, пароль, буфер обмена

Статус: к реализации (порция 14 переключения).

## Назначение

Осталось три места, где команда обращается к терминалу человека напрямую, а
значит — к терминалу сервера, которого у неё нет:

- **вопрос посреди работы.** `mpu confirm` показывает буфер конвейера и
  спрашивает «Применить?» у терминала, а не у stdin: stdin занят данными
  (`confirm.md`). На сервере такого терминала нет;
- **скрытый ввод.** Пароль читается посимвольно с терминала, без эха;
- **буфер обмена.** Команда кладёт текст в буфер человека — escape-строкой в
  свой stderr или запуском локальной программы.

Порция переносит все три на клиента: спрашивает и копирует тот, у кого есть
терминал, а сервер только просит об этом.

## Вопрос строки — один вид кадра на все случаи

Кадр `ask` уже есть — им спрашивают подтверждение правила
(`platform/back-rpc.md`). Он получает вид запроса:

```json
{"ask": "Применить? [y/N] ", "kind": "line"}
{"ask": "Пароль GitLab: ", "kind": "secret"}
```

- `kind: "line"` — клиент показывает текст и читает строку ответа; поля нет —
  то же самое (совместимость с прежними клиентами);
- `kind: "secret"` — клиент читает **без эха**; строка ответа не попадает ни в
  журнал вызовов, ни в вывод, ни в сообщения об ошибках.

Ответ — прежний кадр `answer` (у HTTP — `…/answer` с номером). Одна строка
может спросить несколько раз подряд; каждый вопрос ждёт своего ответа.

Вопрос задаётся только каналу с человеком (`human: true`). Канал без
человека получает отказ строки «спросить некого» — как сегодня с решением
`ask` (`platform/policy.md`).

**Вид `secret` на двери агента не задаётся никогда**, даже когда агент пришёл
с `human: true` (так ходит `mpu-mcp`): строка отказывает «спросить некого».
Скрытому вводу у агента негде быть скрытым — ответ прошёл бы через переписку
клиента и осел в его истории. Отказ здесь дешевле утёкшего пароля.

## Буфер обмена — просьба, а не запись в чужой терминал

Сервер в терминал не пишет. Команда, которой нужно положить текст в буфер,
шлёт кадр:

```json
{"clip": "текст для буфера"}
```

Что делает клиент:

| Клиент | Поведение |
|---|---|
| `mpu-next` в терминале | кладёт текст в буфер обмена своего терминала |
| `mpu-next` не в терминале (пайп) | печатает текст в stderr — как сегодня |
| агент (MCP, `/agent/line`) | кадр не приходит: на его двери копирование не предлагается |

Механика копирования (escape-последовательность терминала, обёртка для
мультиплексора, запуск программы копирования) переезжает к клиенту не сразу:
до порции 15 она нужна и монолитному `mpu`, который живёт внутри `mpu-back`.
На это время `ts/cli/` получает **второй разрешённый импорт** из `back/` —
модуль копирования, рядом с контрактом кадров. Исключение записывается в
`ts/CLAUDE.md` со сроком: уходит вместе с монолитом. Заводить ради ста строк
третий подпроект или писать копирование заново (два источника одного знания)
— дороже.

Клиент, не знающий кадра `clip`, его игнорирует: строка от этого не падает.

## Что меняется у команд

| Место | Сегодня | После порции |
|---|---|---|
| `mpu confirm` | открывает терминал процесса, пишет вопрос в stderr, читает ответ | шлёт кадр `ask` вида `line` |
| скрытый ввод | посимвольное чтение терминала процесса | кадр `ask` вида `secret` |
| копирование | escape-строка в stderr либо запуск локальной программы | кадр `clip` |

Порт ввода-вывода команды получает эти три возможности как просьбы к
вызывающему; терминал сервера не открывается ни разу.

## Инварианты

- Ни один секрет не попадает в журнал вызовов, вывод строки и тексты ошибок:
  ответ на `secret` живёт только в памяти строки и в терминале человека.
- Команда, спросившая при `human: false`, получает отказ, а не пустой ответ:
  молчание нельзя принять за «нет» там, где вопрос был не про подтверждение.
- Строка, ждущая ответа, не занимает места в пределе одновременности
  (`platform/line-concurrency.md`).
- Обрыв канала во время вопроса = отмена строки
  (`platform/line-cancel.md`, проверено живьём 2026-09-21): ответа нет,
  команда прекращается, записи журнала не остаётся.
- Клиент старой версии, не знающий `kind` и `clip`, работает как прежде.

## Граничные случаи и ошибки

| Дано | Ожидается |
|---|---|
| `mpu-next … \| mpu-next confirm` в терминале | вопрос виден в терминале, ответ уходит строке, буфер конвейера проходит дальше |
| то же, но stdin и stdout — пайпы, терминала нет | строка отказывает «спросить некого», код 1, и печатает прежнюю диагностику терминальности — теперь про клиента (`confirm.md`) |
| `secret` на двери агента (даже с `human: true`) | отказ «спросить некого», вопрос не задаётся |
| `secret`: человек ввёл пароль | в журнале вызовов строки пароля нет ни в каком виде |
| `secret` через `POST /line/answer` | принимается; тело ответа в журнал не пишется |
| два вопроса подряд в одной строке | каждый ждёт своего ответа; порядок сохранён |
| ответа нет 120 секунд | как у подтверждения: «нет», строка кончается (`platform/back-rpc.md`) |
| `clip` у клиента в пайпе | текст в stderr, буфер не трогается |
| `clip` у клиента, где буфер недоступен | текст в stderr, строка не падает |
| отмена во время вопроса | строка остановлена, ответа не ждут |

## Известные отклонения

- Копирование у старого `mpu` шло escape-строкой в stderr и потому работало
  только под некоторыми терминалами; здесь это решает клиент, и способ
  выбирает он. Вердикт — **fix**.

## Открытые вопросы

  появится первая команда, которой он нужен; сейчас не вводится.

## Пункты чек-листа

`design.md`:

1. Примитивы — изменил: примитив — «спросить у того, кто позвал»; ответ,
   пароль и копирование — три его вида, а не три механизма [D.1].
2. Особые случаи → получатели — изменил: обычный ответ и скрытый — две
   реализации чтения у клиента, выбранные видом вопроса, а не ветка `if
   (secret)` у каждого чтения [D.2].
3. Проверка `null` — изменил: клиент без буфера обмена — получатель, который
   печатает текст в stderr, а не проверка «есть ли буфер» перед каждым
   копированием [D.3].
4. Кто решает — изменил: как показать вопрос и куда положить текст, решает
   клиент; сервер только просит [D.1].
5. Память приватна — изменил: ответ на скрытый вопрос живёт в строке, которая
   спросила, и наружу не выходит ни одним путём [D.4].
6. Голые данные → протокол — изменил: `kind` — не флаг поведения у сервера, а
   имя вида вопроса, по которому клиент выбирает свою реализацию [D.2].

`design-mpu.md`:

1. Команда — сообщение объекту — ничего: новых команд нет.
2–3 — ничего.
4. Один факт — один источник — изменил: «спросить некого» называется один раз
   — отказом строки, как у решения `ask` [D.5].
5. Величина из результата — ничего.
6. Права Deno — изменил: право на запуск программы копирования нужно клиенту,
   а не серверу; у сервера оно не появляется [D.3].
7. Границы модулей — изменил: вопрос и копирование доходят до команд тем же
   портом ввода-вывода, терминал сервера не открывается [D.1].
8. Внешнее ссылкой — изменил: срок ожидания ответа — тот же параметр, что у
   подтверждения [D.5].
9. Голден снятый — изменил: кадры вопроса, пароля и копирования снимаются
   прогоном [D.6].
10. Пропускаемая проверка — изменил: «пароль не попал в журнал» не
    пропускается: нечего проверить — значит ошибка [D.4].

[D.1] Спросить — просьба к вызывающему. [D.2] Вид вопроса выбирает
реализацию у клиента. [D.3] Копирование — дело клиента. [D.4] Секрет живёт в
строке. [D.5] Отказ один. [D.6] Голдены сняты прогоном.
