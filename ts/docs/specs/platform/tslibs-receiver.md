# Порция K1 — библиотека протокола получателя `tslibs/receiver`

Статус: к реализации (2026-10-07). Дизайн — `docs/2026-10-06-tslibs-receiver-protocol-design.md`
(согласован владельцем), решения D3 и «аргументы — схемой `zod`» (план,
«Решения владельца»); договор пакета — `platform/tslibs-package.md`; объект
отказа — `platform/refusal-object.md`. Этап 6 плана; первая библиотека в
`tslibs/` — автономная, потребитель (`ts/`) подключит её после этапа 3.

## Кто и зачем

Автор домена хочет описывать получателя данными рядом с методами и получать
даром: проверку аргументов, политику `allow`/`ask`/`deny`, журнал, ответ на
непонятое сообщение, справку, файл интерфейса и тесты соответствия. Хост
хочет узнавать интерфейс домена, не читая его код.

## Поверхность (наблюдаемая автором домена)

- Получатель — класс; статическое поле `about` проверяется типом `About<T>`:
  ключи описаний — ровно публичные методы `T` (лишний или пропущенный —
  ошибка `tsc`).
- Метод с аргументами принимает один объект ключей; его схема в описании —
  `z.object({...})`; тип сверяет `z.infer` схемы с параметром метода.
- Описание метода: `comment` (обязательно), `args` (схема или её отсутствие),
  `returns` (`"data"` или класс-получатель), `effect` (`read` по умолчанию,
  `write`, `send`), `raises`, `examples` (вызов и ответ), `deprecated`
  (`{ use, since }`), `secret` — ключи, которые журнал маскирует.
- `envelope(receiver, ctx)` → `Enveloped<T>`; `ctx` — путь, книга правил
  (порт: путь → `allow`|`ask`|`deny`), журнал (порт записи), спрашивающий
  (порт: вопрос → да/нет), `signal`.
- Команда `bun run interface` в библиотеке-домене пишет `INTERFACE.md` и
  `interface.json` обходом графа от корня; набор тестов соответствия
  подключается доменом одной строкой со своим корнем и фейками.

## Сценарии [S.n] (тестовый домен в тестах библиотеки: `Kaiten` → `Card` → `Checklist`)

1. `card.comment({ text: "ок" })` через конверт, правило `allow` → ответ
   метода; журнал получил запись `{ path: "kaiten card comment", args: { text:
   "ок" }, outcome: "ok", ms: <число> }`.
2. `card.comment({})` → объект отказа, метод не вызван:
   `{ reason: "не хватает ключа", hint: null, candidates: [], text: "kaiten card comment: не хватает ключа text — пиши: kaiten card comment text: <строка>" }`.
3. `card.comment({ text: 5 })` → отказ `reason: "неверный ключ"`, `text`:
   `kaiten card comment: ключ text — ожидается строка, пришло 5`.
4. Правило `deny` → отказ `reason: "запрещено правилом"`, `text`:
   `kaiten card comment: запрещено правилом — изменить правила может только человек (mpu policy)`; метод не вызван; запись журнала `outcome: "denied"`.
5. Правило `ask`, спрашивающий ответил «да» → метод вызван; «нет» → отказ
   `reason: "не подтверждено"`, `text`: `kaiten card comment: человек ответил «нет» — строка не исполнена`.
6. Нет правила для пути → правило из `effect`: `read` → `allow`, `write` и
   `send` → `ask`; навигация (`returns` — получатель, `effect` не задан) →
   `allow`.
7. `card.coment` (селектора нет) → не исключение, а отказ `reason:
   "непонятно"`, `candidates: ["comment"]`, `hint: ["kaiten","card","comment"]`,
   `text`: `kaiten card не понимает coment — ближе всего: comment; понимаю: show, comment, checklist`.
8. Публичный, но неописанный метод → тот же отказ «непонятно»: снаружи
   достижимо только описанное.
9. `card.checklist()` → результат завёрнут тем же конвертом, путь продолжен:
   `kaiten card checklist`; его методы проходят правила по своему пути.
10. Отражение: `describe()` → `about` + путь; `selectors()` → `{ reading:
    ["show"], writing: ["comment"], navigation: ["checklist"] }`;
    `respondsTo("comment")` → `true`, `respondsTo("x")` → `false`;
    `help("comment")` → однострока, когда звать, ключи, пример;
    `printString()` → `Card 123`.
11. Ключ из `secret` в журнале — `"***"`; в тексте отказа значения секрета нет.
12. `signal` прерван → вызов не начинается, отказ `reason: "отменено"`.
13. `bun run interface` на тестовом домене → `INTERFACE.md` и
    `interface.json` (голдены в тестах библиотеки); повторный запуск — тот же
    вывод байт в байт.
14. Тесты соответствия на тестовом домене зелёные; каждая проверка краснеет
    на своей поломке: (а) метод без описания; (б) описание без метода
    (ловит `tsc` и проверка во время работы); (в) пример с неверным ответом;
    (г) `returns` — класс без `about`; (д) метод `read`, который пишет в фейк;
    (е) `interface.json` не равен сгенерированному; (ж) удалён метод или
    добавлен обязательный ключ без `deprecated` с заменой.
15. Договор пакета: `bun install && bun run gate` → зелёно под Bun, Node,
    Deno; `release/mpu-receiver-0.1.0.tgz` закоммичен, в нём только
    `package.json` и `dist/`.

## Инварианты

- Снаружи достижимо только описанное; отсутствие — объект отказа, не
  исключение.
- У факта один источник: арность, ключи, эффект, примеры — в `about`;
  справка, файл интерфейса, посев правил, проверка аргументов — из него.
- Пример в описании всегда исполним и верен.
- Библиотека не знает о `ts/`: книга правил, журнал, спрашивающий — порты.

## Границы

- Подключение к `ts/` и перевод доменов — после этапов 3–4.
- Внешняя форма строки (D1) — у хоста; библиотека получает селектор и
  объект ключей.
- XState — не здесь.
