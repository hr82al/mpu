# `ask` в составной строке

Статус: реализовано — порция 167 (`047f8de`, `bd8056b`); принято 2026-09-23 хостом: гейты зелёные (тестов 2426, smoke 19/1), мутации M1–M13 красные, голдены `ask-door/composite-*.json` (9) заморожены. Живьём (без записей в прод): строка с `kiten comment` в блоке без `ask` — отказ «строка может записать (kiten comment) — начни с ask: mpu ask …», код 2, в журнал не попала (CLI и MCP); `mpu ask kiten ls … end size` — без вопросов, 44. Вопросы на каждую запись живьём не снимались (запись в прод запрещена) — стенд с подменённым Kaiten.

## Назначение

Правила разрешений клиента видят только начало строки (`Bash(mpu ask *)`),
поэтому строка, которая **может** дойти до записи — в том числе внутри блока
или цикла, — начинается словом `ask` один раз. Вопрос человеку — на
**каждую** запись в момент, когда вычисление до неё дошло. Начальный `ask` не
разрешает, а объявляет. Дверь однокомандной строки — `ask-door.md`; здесь —
строка из нескольких выражений, групп и блоков (`evaluator.md`).

## Обход до исполнения

До исполнения исполнитель обходит всю строку — выражения, группы, тела
блоков — и собирает **достижимые команды**: каждое место, где сообщение
отправляется команде реестра, известной по разбору (`kiten comment`, `sql`).
Для каждой — решение правил по её пути (`policy.md`).

| Обход нашёл | Начало строки | Итог |
|---|---|---|
| хоть одну `deny` | любое | `mpu <путь>: запрещено правилом «<путь> <args>»` (путь команды — значения до исполнения неизвестны), код 1, ничего не исполнено |
| хоть одну `ask` | нет `ask` | адресный отказ `mpu <строка>: строка может записать (<путь первой ask-команды>) — начни с ask: mpu ask <строка>`, код 2, `refusal.reason` «строка может записать», `refusal.hint` — `["ask", …слова]`; ничего не исполнено |
| хоть одну `ask` | `ask` | исполнение; вопрос — на каждую `ask`-команду при отправке |
| только `allow` | `ask` или нет | исполнение без вопросов (лишний `ask` — не отказ, решение владельца) |

Решение в момент отправки страхует расхождение обхода и отправки: подстрока
программы без начального `ask`, решённая `ask`, — отказ всей строки тем же
текстом, код 2; сделанное до неё (только `allow`, то есть чтение) не
откатывается. Живой случай — правило изменено другим процессом во время
исполнения (книга правил перечитывает файл перед решением, `ask-door.md`).
Получателя, неизвестного обходу (`x := kiten . @x comment …`), в языке 166 нет:
группа значением не бывает — появится вместе с объектом-группой.

## Вопрос на каждую запись

- Текст вопроса — строка **этой** команды с уже вычисленными значениями, как у
  однокомандной строки: `выполнить mpu kiten comment id: 12 text: ping? [y/N]`.
- «да» — команда исполняется, вычисление идёт дальше.
- «нет» (или «спросить некого», таймаут) — команда не исполняется, вычисление
  останавливается: stderr — текст однокомандной двери (`mpu kiten comment id:
  12 text: ping: не подтверждено`), код 1. Следующие команды вопросов не
  получают.
- Код подстроки наружу: 2 (отказ до исполнения, в том числе адресный при
  отправке) — как есть; прочие ненулевые — 1 (166).
- Сделанное до отказа не откатывается.
- Журнал вызовов: каждая дошедшая команда — своей записью с исходом (`да`,
  `нет`).

## Инварианты

- Однокомандная строка — как в `ask-door.md` (голдены не меняются).
- Ни одна `ask`-команда не исполняется без своего «да».
- Ни одна команда не исполняется, если обход нашёл `deny` или `ask` без
  начального `ask`.

## Граничные случаи

Реестр поддельный: `kiten ls` — `allow`, три карточки (в голденах — `id` 11, 12, 13); `kiten
comment` — `ask`; `sql` — `deny`.

| Строка, ответы | Ожидается |
|---|---|
| `kiten ls each: do :c kiten comment id: @c id text: ping done` | отказ «строка может записать (`kiten comment`) — начни с `ask`: mpu ask kiten ls each: …», код 2, `kiten ls` не вызван |
| `ask kiten ls each: do :c kiten comment id: @c id text: ping done`, ответы y y y | три вопроса с `id: 1`, `id: 2`, `id: 3`; три комментария; код 0 |
| то же, ответы y y n | два комментария; третий вопрос — «нет»; «mpu kiten comment id: 3 text: ping: не подтверждено», код 1 |
| пять записей в цикле, ответы y y n | первые две исполнены, третья нет, четвёртая и пятая вопросов не получили, код 1 |
| `ask kiten ls end size` | исполнение без вопросов, код 0 |
| `ask kiten ls . 2 plus: 2` | исполнение без вопросов |
| `kiten ls each: do :c sql target: 1 sql: x done` | отказ правила `sql` (deny), код 1, `kiten ls` не вызван |
| `kiten ls each: do :c kiten comment id: @c id text: a done` без `ask`; обход видит `kiten comment` = `allow`, другой процесс ставит `ask: kiten comment` до первой отправки | `kiten ls` исполнен; первая отправка — отказ всей строки, код 2 |
| `ask kiten ls each: …` через `/agent/line` без человека | первый вопрос — «спросить некого», код 1, ничего не записано |
| MCP `["kiten","ls","each:","do",":c","kiten","comment",…]` | `refusal.hint` — те же слова с `ask` первым |
