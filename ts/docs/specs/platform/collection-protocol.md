# Протокол коллекции у результата-данных

Статус: к реализации — порция 162.

## Назначение

Результат-данные отвечает на сообщения отбора: агент получает только нужное,
а не весь JSON. Реализуется один раз у вида «данные»; команды ничего не
пишут. Имена — по слепым замерам `sonnet` (агент сам пишет `where: … less:`,
`first: 3`, `size`).

## Виды данных

| Вид | Что это |
|---|---|
| коллекция | результат-список (строки SQL, карточки, клиенты) |
| запись | элемент коллекции или результат-объект с полями |
| скаляр | текст, число, булево, `nil` |

Результаты команд — конверты (`kiten ls` → `{view, rows}`, `sql-ro` → `{…,
outcome: {columns, rows}}`), поэтому «где коллекция» знает команда — одним
объявлением `items`: «результат → записи» и обратное «результат с этими
записями» (`kiten ls` — `rows`; `sql-ro` — `columns` × `rows` ↔ записи). Без
объявления результат — запись (поля — унарными); запись ровно с одним
полем-скаляром — скаляр (его значение), то же правило, что у значения ключа
(161). Прочее — один раз у вида данных — у **любых** данных, не только у
результата команды (`policy`, ответ `complete:` и прочие данные дерева).

Текстовый вид: отобранная коллекция — вид команды над результатом с
подменёнными записями (одно место — команда); отобранная запись — строки
`поле\tзначение`; скаляр — его значение. `end json` после отбора — JSON
отобранного (коллекция — массив записей).

## Сообщения

| Получатель | Сообщение | Итог |
|---|---|---|
| коллекция | `size` | число |
| коллекция | `isEmpty` | булево |
| коллекция | `first`, `last` | запись; пустая коллекция — `nil` |
| коллекция | `first: <n>` | коллекция первых n (`n` ≥ 0) |
| коллекция | `pick: <поле>` | коллекция значений поля (скаляров) |
| коллекция | `where: <поле> is: <значение>` | записи с равным полем (сравнение по тексту значения) |
| коллекция | `where: <поле> less:` / `greater:` `<значение>` | числа — как числа, иначе — как текст (даты ISO сравниваются текстом верно) |
| коллекция | `where: <поле> includes: <значение>` | поле-текст содержит значение без учёта регистра |
| коллекция | `sortBy: <поле>` | по возрастанию; `nil` — в конце |
| запись | `<имя поля>` (унарное) | значение поля; нет поля — `doesNotUnderstand` с «ближайшими» полями |
| запись | `pick: <поле>` | то же, для имени поля, совпадающего с сообщением протокола (`size`, `help` …) |
| скаляр | — | только форматы и протокол отражения |

Цепочка — через `end`: `mpu kiten ls end where: column is: review end size`.
**И без `end` сразу за командой**: ключевое сообщение, которого команда не
понимает вовсе, при том что у неё нет обязательных ключей, а объявленный вид
результата его понимает, — команда исполняется без ключей, сообщение уходит
результату: `mpu kiten ls where: column is: review end size` (деление
частично понятого ключевого 158 с пустой понятой частью; проверка до
исполнения). Во всех слепых замерах описания агент писал именно так. Формат
после отбора — последним: `… end first: 3 end json`.

## Где исполняется

Отбор идёт по результату исполненной команды, в `back`, без повторного запроса.
Команда исполняется один раз; поток (`logs --follow`) отбору не подлежит —
отказ «поток — только форматы», код 2, до исполнения.

## Значение ключа (161)

Скаляр отбора годится значением: `mpu kiten comment id: do kiten ls end first
id end text: ping`. Отказ 161 «не скаляр» подсказывает готовую строку с `first`
и полем, если у записей одно поле-идентификатор (`id`).

## Граничные случаи

| Строка | Ожидается |
|---|---|
| `mpu kiten ls end size` | число карточек |
| `mpu kiten ls where: column is: review end first: 3 end json` | JSON трёх карточек |
| `mpu sql-ro target: 54 sql: "select 1 as n" end first n` | `1` |
| `mpu kiten ls end first nope` | `…: запись не понимает nope; ближайшие: …` поля (нет близких — все поля), код 2 |
| `mpu kiten ls where: column is: review end size` | как `mpu kiten ls end where: …`; команда исполнена один раз |
| `mpu sql-ro target: 54 where: n is: 1` | отказ до исполнения: у `sql-ro` обязательный `sql:` не дан |
| `mpu kiten ls end first: -1` | отказ «ожидается n ≥ 0», код 2 |
| `mpu kiten ls where: updated less: 2026-09-01 end size` | карточки старше даты (у строк `kiten ls` поле `updated`) |
| `mpu kiten ls end sortBy: updated end first title` | название самой давней |
| `mpu jsdate end size` | `…: скаляр не понимает size`, код 2 |
| `mpu logs --follow target: sl-1 end size` | отказ «поток — только форматы», до исполнения |
| пустая коллекция `end first` | `nil` печатается пустой строкой, код 0 |

## Инварианты

- Команда исполняется один раз, как без отбора.
- Отбор не меняет код выхода команды, кроме отказа самого отбора (2).
- Форматы понимает любой вид данных.

## Golden-примеры

Текстовый вид коллекции записей — тот же, что у команды без отбора (вид
команды применяется к отобранному); снимает исполнитель на `kiten ls` и
`sql-ro` с подменённым транспортом.
