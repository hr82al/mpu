# Workspace `ts/`: переезд реализации в `ts/back/`

Статус: к реализации

## Назначение

Дерево `ts/` становится рабочей областью из нескольких самодостаточных
подпроектов. Первый и пока единственный подпроект — `ts/back/`: в него
переезжает вся нынешняя реализация (`main.ts`, `src/`, её скрипты). Следующие
порции добавят рядом `ts/mcp/`, `ts/cli/`, `ts/complete/`, `ts/supervisor/`,
`ts/web/`.

Порция — только переукладка: перенос и правка путей. Поведение бинаря,
тесты, голдены и права не меняются.

## CLI-контракт

Нет новых команд. Всё, что ниже, выполняется из каталога `ts/` и должно
работать так же, как до порции (те же коды выхода, тот же вывод, кроме путей
файлов в сообщениях тестов):

| Вызов из `ts/` | Ожидается |
|---|---|
| `deno fmt --check` | код 0; голдены `testdata` не переформатированы |
| `deno lint` | код 0 |
| `deno check .` | код 0, проверены все подпроекты |
| `deno task test` | код 0, прогнаны тесты всех подпроектов; число тестов равно числу до порции |
| `deno task smoke` | код 0, те же проверки и те же `skip`, что до порции |
| `deno task build` | бинарь `~/.local/bin/mpu` (в изолированной сессии не запускается — см. «Побочные эффекты») |
| `deno task tools:snapshot` | снапшоты тулов перезаписаны побайтово теми же |
| `deno task handoff status` | тот же ответ о ячейке `ts/.tmp/buf.txt` |

## Ввод/вывод

- Бинарь, собранный после порции: `mpu --help`, `mpu version`, справка каждой
  команды, дополнение и голдены всех команд побайтово равны тем же у бинаря,
  собранного из последнего коммита до порции.
- Снапшоты тулов MCP (профили `ro` и `rw`) побайтово равны прежним.

## Побочные эффекты

- Установленный бинарь, собранный **до** порции, командой `mpu build --check`
  находит дерево исходников после порции тем же порядком кандидатов, что
  описан в `specs/build.md` (каталог рядом с программой, рабочая область по
  сентинелу `<корень>/mpu/ts`, запомненное дерево), и заканчивает с кодом 0.
  Иначе оператор не сможет пересобрать `mpu` установленной программой.
- Бинарь, собранный **после** порции, делает то же самое.
- Сами `mpu build` (без `--check`), `deno task build` и всё, что пишет в
  `~/.local/bin` или перезапускает службу MCP, изолированная сессия не
  запускает: на машине работает настоящая служба. Живой прогон делает
  спецификатор.

## Конфигурация

- Корень `ts/deno.jsonc` перечисляет подпроекты. Задачи из таблицы
  «CLI-контракт» вызываются из `ts/`.
- Файл блокировки зависимостей — один на рабочую область.
- `ts/docs/`, `ts/handoff/`, `ts/.tmp/`, `ts/.deno/`, `ts/cov/` остаются на
  своих местах: это общее для всех подпроектов, а не часть `back`.
- Права задач `build`, `test`, `smoke` не расширяются; каждое право — прежней
  строкой с прежним обоснованием.

## Инварианты

- Вся реализация прежних `ts/main.ts` и `ts/src/` находится в `ts/back/`.
- В корне `ts/` остаются файлы `deno.jsonc` и `main.ts`: по их наличию
  установленный бинарь узнаёт дерево исходников (`specs/build.md`), и бинарь,
  собранный до порции, другого признака не знает. Что в `ts/main.ts` —
  решение исполнителя; логики в нём нет. Других новых файлов в корне `ts/`
  порция не добавляет.
- Код `ts/back/` не импортирует ничего вне `ts/back/`, кроме файлов канала
  `ts/docs/specs/fixtures/` (закрытый список публикации тулов читается оттуда,
  как и сейчас).
- Коммиты порции — перемещения файлов и правка путей (импорты, задачи,
  исключения форматтера, пути в комментариях и в `ts/CLAUDE.md`). Тела функций
  и тексты тестов не меняются.
- `ts/CLAUDE.md` после порции называет пути нового дерева (образец стиля,
  разделы о структуре, о `main.ts`, о командах).

## Граничные случаи и ошибки

| Дано | Ожидается |
|---|---|
| запомненное дерево (`build-source`) указывает на `…/mpu/ts` | `mpu build --check` старым бинарём — код 0 |
| сентинел рабочей области найден, запомненного дерева нет | то же — код 0 |
| тест читает голден по пути относительно своего файла | путь продолжает указывать на тот же файл |
| `deno fmt` без аргументов из `ts/` | ни один файл `testdata` и `docs/` не изменён |
| временная правка кода для проверки | не попадает в коммит |

## Golden-примеры

Эталон — дерево до порции: вывод `mpu --help`, `mpu version`, голдены команд
и снапшоты тулов, которые уже лежат в `testdata`. Новых голденов нет.
