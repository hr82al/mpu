# Порции D1–D8 — пакеты команд `tslibs/cmd-<каталог>`

Статус: к реализации (2026-10-08), после N3. План —
`docs/plans/2026-10-08-tslibs-full-slicing.md`. Договор пакета —
`platform/tslibs-package.md`; поведение команд — их спеки (не меняется).

## Общее для всех порций D

- Один каталог `ts/back/src/<каталог>` → один пакет `tslibs/cmd-<каталог>`
  (`@mpu/cmd-<каталог>`); адаптеры прежних выносов (`ts/back/src/{kaiten,
  loki,slback,telegram,exec}`) уходят в пакет команд своего домена (какой —
  в спеке порции).
- Пакет команд зависит только от пакетов (`@mpu/command`, `@mpu/language`,
  `@mpu/base`, клиентов) — необязательные `peerDependencies` плюс
  `devDependencies` архивом; от `ts/` — никогда.
- `ts/back/src/registry` регистрирует команды импортом пакета вместо
  каталога; других правок в `registry` нет.
- Тесты, которым нужен стенд приложения (`backend`, `line`, `entrypoint`),
  остаются в `ts/` поверх пакета; тесты самой команды — в пакете.

## Сценарии, общие для каждой порции [S.n]

1. Каждый пакет порции: `bun install && bun run gate` → зелёно под Bun, Node,
   Deno, `check:release` зелёный; архив `release/mpu-cmd-<каталог>-0.1.0.tgz`
   закоммичен.
2. Списки листовых случаев каталогов порции до = после (пакеты + `ts/`),
   строка в строку; ушедшие без преемника (сверки копий фикстур — `ts/` не
   читает папки пакетов) — поимённо в отчёте.
3. `rg -n 'Deno\.|Bun\.' tslibs/cmd-*/src` → пусто; в пакетах нет импорта из
   `ts/`; каталогов порции в `ts/back/src` нет.
4. `ts/package.json` — архивы; свежая установка с пустым кэшем Bun (договор
   [S.12]) проходит; гейты `ts/` и `bun run smoke` зелёные.
5. Голдены команд порции — без изменений и зелёные; `mpu help` и
   `mpu <команда> help` — вывод побайтно прежний.
6. Живьём (хост после установки): чтение каждой команды порции (по
   примеру из её справки, только пути `allow`) — вывод прежней формы.
