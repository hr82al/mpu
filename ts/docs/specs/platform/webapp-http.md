# platform/webapp-http — Apps Script webapp и кэш листов

Статус: к реализации (заморожена 2026-08-27; открытые вопросы закрыты
живыми пробами, формы сняты парой)

## Назначение

Общая обвязка семейства `mpu sheet` (спека `sheet.md`; будущие спеки
записи и batch-операций): транспорт Apps Script webapp, retry,
A1-диапазоны, whole-tab кэш листов и метаданных, housekeeping,
инвалидация, резолв цели-spreadsheet. Контракт — не API реализации.

## Ввод/вывод

### Запрос

- Единственный сетевой канал — POST на URL из env `WB_PLUS_WEB_APP_URL`
  с `Content-Type: application/json` и телом `{"action": "<имя>",
  …параметры}`; редиректы следуются (webapp отвечает 302 на
  `script.googleusercontent.com`), таймаут запроса — 120 s. URL —
  публичный deployment без авторизации: знание URL эквивалентно
  доступу, поэтому URL не печатается ни в данных, ни в текстах ошибок.
- Экшены и параметры (дословно):
  - `spreadsheets/values/batchGet` — `{ssId, ranges: [A1-строки],
    majorDimension: "ROWS", valueRenderOption: "UNFORMATTED_VALUE" |
    "FORMULA" | "FORMATTED_VALUE", dateTimeRenderOption:
    "SERIAL_NUMBER"}` → `{valueRanges: [{range, values?}]}`; `values`
    отсутствует у пустого диапазона, даты — числа (serial);
  - `spreadsheets/values/batchUpdate` — `{ssId, requestBody:
    {valueInputOption, data: [{range, values}]}}`;
  - `spreadsheets/batchUpdate` — `{ssId, requestBody: {requests: […]}}`
    (структурные запросы Sheets API, атомарно);
  - `spreadsheets/get` — `{ssId}` → `{sheets: [{properties: {title,
    sheetId, index, gridProperties: {rowCount, columnCount}}}]}`.

### Ответ и retry

- Тело ответа — JSON-объект `{success, result?, error?}`; результат
  вызова — `result`, не-объект оборачивается в `{"value": <result>}`.
- Бюджет — 6 попыток на вызов; каждый повтор — заметкой в журнал
  вызовов (`platform/invoke-log.md`), не в терминал. Ветки по исходу:
  - транспортная ошибка или HTTP ≥ 500 → пауза backoff (250 ms × 2ⁿ по
    номеру попытки, потолок 8 s, плюс случайный jitter до 25 %) и
    следующая попытка; на шестой — `<action> failed after 6 attempts:
    transport: <причина>` либо `… HTTP <status>: <тело до 200
    символов>`;
  - HTTP 429, либо тело содержит `quota exceeded` / `too many requests`
    (без учёта регистра), либо `success` ложен и `error` содержит
    `quota` (без учёта регистра) → пауза 60 s и следующая попытка;
  - HTTP 404 → не более 3 повторов с паузой 10 s (webapp транзиентно
    отдаёт HTML вместо ответа); четвёртый подряд 404 → немедленная
    ошибка `<action>: HTTP 404: <тело до 500 символов>`;
  - прочий статус ≥ 400 → немедленно
    `<action>: HTTP <status>: <тело до 500 символов>`;
  - тело не JSON → `<action>: non-JSON response: <тело до 200>`; JSON
    не объект → `<action>: response is not an object: <тело до 200>`;
  - ложный `success` без quota-текста → `<action>: <error>` (нет поля
    `error` → `<action>: unknown error`), без повторов;
  - бюджет исчерпан повторами quota/404-веток → `<action>: исчерпан
    лимит попыток (6). Last error: <последняя ошибка транспорта/5xx,
    иначе пусто>`.

### A1-диапазоны

- Форма `[Лист!]span`. Имя листа с символом вне `[A-Za-z0-9_]` берётся
  в одинарные кавычки, `'` внутри удваивается; разбор зеркален.
- span: `A1`, `A1:C3`, открытые `A:A`, `1:5`, `A1:A`. Строка без `!`,
  не содержащая `:` и не совпадающая с образцом ссылки-ячейки
  (`^[A-Za-z]{1,3}\d*$` либо `^\d+$`), — имя листа, весь лист. Диапазон
  без имени листа при незаданном листе-умолчании — ошибка ввода
  (реакция CLI — `sheet.md`).

### Кэш листов

- Единица кэширования — лист целиком. Таблица `sheet_tabs` кэш-БД:
  `(ss_id, tab_name, payload, size_bytes, fetched_at)`, PK
  `(ss_id, tab_name)`; `payload` — gzip-сжатый JSON `{values, formulas,
  dims: {rows, cols}}`, `size_bytes` — размер сжатого payload. Запись
  жива, пока `now − fetched_at ≤ sheet.cache.tab_ttl` на момент чтения
  (изменение TTL действует и на уже лежащие записи).
- Промах/протухание → чтение метаданных → два `batchGet` всего листа
  диапазоном `<Лист>!A1:<последняя колонка><число строк>`
  (UNFORMATTED_VALUE и FORMULA); оба слоя паддятся `""` до rows×cols из
  метаданных; запись upsert'ится. Запрошенный span вырезается
  пост-фактум с паддингом `""`; A1-адрес результата нормализуется к
  закрытой форме по фактическим границам листа.
- Большой лист (оценка rows×cols×16 байт больше
  `sheet.cache.max_tab_bytes`) не кэшируется: прямой `batchGet` только
  запрошенных диапазонов, признак «из кэша» ложен, адрес результата —
  из ответа webapp. Рендер `formatted` — всегда прямой `batchGet`
  FORMATTED_VALUE мимо кэша (locale-зависим).
- Принудительное обновление (refresh) не читает кэш (листов и
  метаданных), но перезаписывает его свежими данными. Лист,
  отсутствующий в метаданных, → ошибка с перечнем существующих листов
  (форма и код выхода — `sheet.md`).

### Метаданные

Список листов — экшен `spreadsheets/get`; берутся `title`, `sheetId`,
`index`, `rowCount`, `columnCount` каждого листа, порядок — как в
ответе. Кэш — таблица `cache` кэш-БД, ключ `sheet:info:<ss_id>`, TTL
фиксированные 7200 s (конфигом не меняется); запись жива, пока её
`expires_at > now`.

### Housekeeping и инвалидация

- Перед каждой командой семейства: из `sheet_tabs` удаляются записи
  старше TTL; затем при сумме `size_bytes` больше
  `sheet.cache.max_total_mb` МБ — удаление старейших по `fetched_at` до
  укладки в лимит. Отсутствие таблиц кэша — не ошибка: housekeeping
  пропускается.
- Инвалидация после успешной записи в лист (write-команды семейства):
  удаляются запись `(ss_id, лист)` из `sheet_tabs` и ключ
  `sheet:info:<ss_id>` из `cache`; остальные листы остаются в кэше.

### Резолв цели-spreadsheet

- Источники по приоритету, первый непустой побеждает целиком:
  флаг `-s/--spreadsheet` → env `MPU_SS` → конфиг `sheet.default`.
- Разбор значения — по порядку до первого совпадения:
  1. подстрока `https://docs.google.com/spreadsheets/d/<ID>` → `<ID>`
     (символы `[A-Za-z0-9_-]`), вид `url`;
  2. вся строка — 20+ символов `[A-Za-z0-9_-]` → она и есть ID, `id`;
  3. точное имя из таблицы алиасов `sheet_aliases` → его `ss_id`, вид
     `alias`;
  4. одни цифры → активные (`is_active = 1`) строки `sl_spreadsheets`
     с `client_id = <число>`: ровно одна → её `ss_id`, вид `client_id`;
     несколько → «неоднозначно»; ни одной → «не найден»;
  5. иначе → активные строки, заголовок которых содержит строку без
     учёта регистра, в порядке заголовка: та же логика, вид
     `title_fuzzy`.
- Тексты ошибок резолва (дословно): ни один источник не задан →
  `Spreadsheet не указан. Используй --spreadsheet/-s, export
  MPU_SS=<id-or-name>, или установи `sheet.default` в config.`; цифры
  без совпадений → `client_id=<число> не найден в sl_spreadsheets.
  Запусти `mpu sheet sync` чтобы обновить кэш.`; заголовок без
  совпадений → `Spreadsheet '<строка>' не найден ни как
  ID/URL/alias/client_id/title. Запусти `mpu sheet sync` чтобы обновить
  кэш.`; несколько совпадений → многострочно: `Несколько spreadsheet'ов
  матчат '<строка>':`, далее до 10 строк `  <ss_id>  <заголовок>`, при
  большем числе — строка `  …(+<N> more)`, затем `Уточни через
  --spreadsheet/-s или используй точный ID/alias.`.
- Резолв — только чтение кэш-БД, без сети; `sheet_aliases` наполняет
  `mpu sheet alias`, `sl_spreadsheets` — `mpu sheet sync` (их спеки —
  отдельные).

## Побочные эффекты

Сеть — только POST на webapp-URL. Кэш-БД (`Store`, bootstrap —
`init.md`): чтение `config`, `sheet_aliases`,
`sl_spreadsheets`; чтение и запись `sheet_tabs` и `cache`.

## Конфигурация

- `WB_PLUS_WEB_APP_URL` — обязателен для сетевых операций; не задан →
  ошибка до первого запроса: `WB_PLUS_WEB_APP_URL не задан. Добавь в
  <путь env-файла> или export в shell.` (путь — `platform/env-file.md`).
- Цель: env `MPU_SS`, конфиг-ключ `sheet.default` (str). Int-ключи
  (приоритет env → config → default — `platform/config.md`):
  `sheet.cache.tab_ttl` (7200), `sheet.cache.max_tab_bytes` (10485760),
  `sheet.cache.max_total_mb` (500); env-имена `MPU_SHEET_CACHE_TAB_TTL`
  / `MPU_SHEET_CACHE_MAX_TAB_BYTES` / `MPU_SHEET_CACHE_MAX_TOTAL_MB`.
  Нечисловое значение слоя → заметка в журнал вызовов, действует
  следующий слой; команда продолжает работу.

## Инварианты

- Ложный `success` без quota-текста всегда завершает вызов ошибкой.
- Частичных записей кэша не бывает: запрошенный span всегда вырезается
  из целого закэшированного листа.
- Режим `formatted` и листы крупнее `sheet.cache.max_tab_bytes` никогда
  не читают и не пишут кэш листов.
- Резолв цели детерминирован: источники не смешиваются, победивший
  источник разбирается целиком.

## Граничные случаи и ошибки

- Шесть попыток подряд 429 (пауза 60 s каждая) → `<action>: исчерпан
  лимит попыток (6). Last error: ` с пустым хвостом.
- Таблицы кэша отсутствуют (свежая БД) → housekeeping и чтение кэша
  молча пропускаются; резолв по client_id/заголовку даёт «не найден».
- `MPU_SHEET_CACHE_TAB_TTL=abc` (нечисловой env) → заметка в журнал,
  действует config/default, команда работает.

## Открытые вопросы

нет.

Семантика `sheet.cache.max_tab_bytes` закреплена наблюдаемой (снято
2026-08-27): порог сравнивается с **оценкой** объёма листа до загрузки —
`строки × колонки × 16` по метаданным, — а не с фактическим размером
записи. Так и задумано: решение «кэшировать или читать напрямую»
принимается прежде, чем лист скачан. Поле `size_bytes` в кэше — размер
уже сохранённого payload и участвует только в вытеснении по общему
объёму.
