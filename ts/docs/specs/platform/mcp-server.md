# platform/mcp-server — MCP-сервер над реестром команд

Статус: к реализации (создана 2026-08-03)

## Назначение

Вторая точка входа к тем же командам: публикует команды маршрута `native` как
тулы и исполняет их по запросу агента. Транспорт — Streamable HTTP на локальном
интерфейсе, протокол — JSON-RPC ревизии `2026-07-28`.

Человек этой точкой входа не пользуется: `mpu <cmd>` исполняется в своём
процессе и поднятого сервера не требует.

## CLI-контракт

`mpu mcp [--profile ro|rw|ro,rw] [--port N]`

- Поднимает долгоживущий процесс, слушающий `127.0.0.1`; на прочих интерфейсах
  не слушает.
- Порт: `--port`, иначе ключ конфига `mcp.port`, иначе `7337`.
- `--profile` перечисляет поднимаемые профили, по умолчанию оба. Профиль `ro`
  обслуживается путём `/ro`, профиль `rw` — путём `/rw`.
- Порт занят → exit 1, stderr `mpu mcp: порт <N> занят`.
- Значение `--profile` вне `ro`/`rw` → exit 2.

`mpu mcp token`

- Печатает в stdout JSON-объект заголовков авторизации одной строкой:
  `{"Authorization":"Bearer <токен доступа>"}`. Такова форма, которую ожидает
  клиент, подставляющий заголовки при подключении.
- Токена нет → создаётся, затем печатается. exit 0.
- Ни в каких других поверхностях токен не печатается.

## Ввод/вывод

Транспорт. Каждое JSON-RPC-сообщение — отдельный HTTP POST на путь профиля.

- Поддерживается только `POST`; прочие методы отвергаются.
- Ответ на запрос — всегда `Content-Type: application/json`. SSE в этой редакции
  не реализуется: пока нет ни уведомлений о прогрессе, ни подписок, ответ одним
  объектом удовлетворяет протоколу.
- Тело-нотификация принимается без ответного тела.
- Заголовки `Mcp-Session-Id` и `Last-Event-ID` игнорируются: сессий нет, потоки
  не возобновляются.

Обязательные заголовки запроса: `MCP-Protocol-Version` и `Mcp-Method`; для
`tools/call` — дополнительно `Mcp-Name`. Значения сверяются с телом; значение в
форме `=?base64?…?=` декодируется перед сверкой.

Методы:

- `server/discover` — поддерживаемые версии протокола, возможности, идентичность
  сервера и инструкции профиля. Идентичность несёт **версию сборки бинаря**: по
  ней видно, что запущенный сервер отстал от пересобранного бинаря. Реализация
  метода обязательна.
- `tools/list` — тулы того профиля, чьим путём пришёл запрос.
- `tools/call` — исполнение команды по имени тула.

Инструкции профиля — свободный текст в `server/discover`, а не в `tools/list`:
клиент читает их при подключении, до того как ему понадобился список тулов. Они
не перечисляют команды, а объясняют, для каких задач тулы этого профиля искать.

Отображение исхода `tools/call`:

| Исход                         | Ответ                                                   |
| ----------------------------- | ------------------------------------------------------- |
| успех                         | результат со структурным содержимым по схеме результата |
| доменная ошибка               | результат с признаком ошибки и человекочитаемым текстом |
| ошибка ввода, неизвестный тул | JSON-RPC-ошибка                                         |

Различие последних двух строк существенно: доменная ошибка приходит агенту
содержимым результата, чтобы он её прочитал и исправился, а не транспортным
сбоем. Классы ошибок — `platform/command-contract.md`.

Имя тула строится из пути команды: сегменты соединяются `_`, дефисы внутри
сегмента тоже становятся `_`.

Аннотации тула: тул профиля `ro` помечается как не изменяющий окружение. Тул,
чей эффект необратим вне этой машины, дополнительно помечается требованием
подтверждения на каждый вызов.

Объём. Инструкции профиля и описание одного тула — не длиннее **2048 байт**
каждое: клиент обрезает их ровно на этом пределе. Тул, размер результата
которого не ограничен по построению, объявляет в схеме аргументов ограничитель
со значением по умолчанию, а в схеме результата — признак усечения.

## Побочные эффекты

Слушающий сокет на `127.0.0.1` и файл токена доступа. Исполнение тула порождает
те же побочные эффекты, что и вызов той же команды из CLI, — они описаны спеками
команд.

## Конфигурация

- `mcp.port` — порт по умолчанию (`platform/config.md`).
- Токен доступа — отдельный файл в конфиг-каталоге с правами 0600, создаётся при
  первой надобности. Ключом конфига не является и в вывод `mpu config` не
  входит.
- Список допустимых значений `Origin` фиксирован реализацией; запрос без этого
  заголовка принимается.

## Инварианты

- Профили не пересекаются: множества имён тулов `/ro` и `/rw` не имеют общих
  элементов.
- На `/ro` нет ни одного тула с политикой `rw` — профиль их не регистрирует, а
  не запрещает при вызове.
- Имя тула уникально в пределах профиля и однозначно восстанавливает путь
  команды.
- `tools/list` не содержит команд маршрута `legacy` (утверждение —
  `platform/registry.md`; здесь его операционная проверка: пересечение множества
  имён тулов обоих профилей с множеством имён `legacy`-команд реестра пусто).
- Ни одна схема аргументов не содержит `anyOf`, `oneOf` или `allOf` на верхнем
  уровне.
- Ни один ответ не содержит токена доступа.
- `tools/list` при неизменном реестре побитово одинаков между вызовами.

## Граничные случаи и ошибки

Отказ выражается кодом HTTP; тело отказа несёт JSON-RPC-ошибку, кроме случаев,
где протокол тела не предполагает.

| Условие                                                | HTTP | Тело                                                                                 |
| ------------------------------------------------------ | ---- | ------------------------------------------------------------------------------------ |
| метод HTTP не `POST`                                   | 405  | нет                                                                                  |
| `Origin` присутствует и не разрешён                    | 403  | JSON-RPC-ошибка без `id`                                                             |
| нет заголовка авторизации либо токен неверен           | 401  | нет                                                                                  |
| путь не `/ro` и не `/rw`                               | 404  | нет                                                                                  |
| нет обязательного заголовка либо он расходится с телом | 400  | JSON-RPC-ошибка, код `-32020`                                                        |
| версия протокола не поддерживается                     | 400  | JSON-RPC-ошибка, код `-32022`, в `data` — список поддерживаемых версий и запрошенная |
| метод JSON-RPC неизвестен                              | 404  | JSON-RPC-ошибка, код `-32601`                                                        |
| тело не разбирается как JSON                           | 400  | JSON-RPC-ошибка без `id`                                                             |
| тело — нотификация, принята                            | 202  | нет                                                                                  |
| имя тула отсутствует в профиле                         | 200  | JSON-RPC-ошибка                                                                      |
| аргументы не удовлетворяют схеме                       | 200  | JSON-RPC-ошибка                                                                      |
| команда завершилась доменной ошибкой                   | 200  | результат с признаком ошибки                                                         |

Клиент, получив 401 или 403, повторяет подключение со свежими заголовками и
повторяет вызов один раз. Поэтому пересоздание токена не требует ручного
вмешательства на стороне клиента.

## Golden-примеры

Фикстуры в `fixtures/mcp-server/`, по файлу на класс. Каждый файл несёт пару
«запрос → ответ»: метод, путь, заголовки и тело запроса; код, заголовки и тело
ответа. Данные синтетические.

| Файл                           | Класс                                             |
| ------------------------------ | ------------------------------------------------- |
| `discover-ok.json`             | успешный `server/discover` с инструкциями профиля |
| `tools-list-ok.json`           | успешный `tools/list` профиля `ro`                |
| `tools-call-ok.json`           | успешный `tools/call` с структурным результатом   |
| `tools-call-invalid-args.json` | аргументы не удовлетворяют схеме                  |
| `tools-call-domain-error.json` | команда упала доменной ошибкой                    |
| `err-header-mismatch.json`     | `Mcp-Name` расходится с телом                     |
| `err-method-not-allowed.json`  | `GET` на путь профиля                             |
| `err-unknown-method.json`      | неизвестный метод JSON-RPC                        |

Схемы тулов в `tools-list-ok.json` — эталон формы, а не полный список: состав
тулов растёт с переносом команд, поэтому сравнивать по составу реестра, а не
байтами.

## Известные отклонения

нет: у этой точки входа нет оригинала в Python-реализации.

## Открытые вопросы

- Момент введения SSE. Он потребуется с первой командой, у которой есть
  наблюдаемый прогресс, либо с подпиской на изменение списка тулов. Пока таких
  нет.
- Зеркалирование параметров тула в заголовки HTTP протокол разрешает, но не
  требует. Решать, когда появится посредник, которому нужна маршрутизация без
  разбора тела.
- Жизненный цикл процесса вне контракта команды: запуск вручную достаточен для
  одной машины. Автозапуск — вопрос эксплуатации, не спеки.
