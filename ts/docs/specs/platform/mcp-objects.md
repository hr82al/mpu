# `mpu-mcp`: переводчик MCP ↔ `mpu-back`

Статус: реализовано — порция 144 (`d23bafd`, `6f6c382`; подпроект `ts/mcp/`, задача `mcp`); принято 2026-09-18: гейты зелёные (тестов 2150, smoke 21/1), живой прогон хостом в Claude Code 2.1.274 через `headersHelper` — тул виден, форма подтверждения `выполнить mpu version?`, Accept → `0.1.0`, Decline → `не подтверждено`, `allow:` → `изменить правила может только человек` без формы. `tools.json` заморожен.

## Назначение

Тонкий MCP-сервер для Claude Code: два тула — `help` и `mpu`. Сам он ничего
не исполняет и о командах не знает: каждое обращение превращает в строку
`mpu-back` по HTTP (`platform/back-http-line.md`), а вопрос подтверждения
строки — в запрос подтверждения у человека в интерфейсе клиента
(elicitation). Новый метод в `back` виден агенту без перезапуска `mcp`.

Подпроект `ts/mcp/`, задача `deno task mcp`. До переключения (порция 8)
слушает `127.0.0.1:7339` и не мешает нынешнему `mpu mcp` на 7337.

## CLI-контракт

```
deno task mcp [--port <число>]
```

- слушает только `127.0.0.1`, порт по умолчанию 7339, `--port 0` — от ОС;
- печатает в stdout `mpu-mcp: http://127.0.0.1:<порт>/mcp` и перевод строки,
  когда слушает;
- SIGTERM/SIGINT — закрывает сессии, код 0; порт занят — stderr
  `mpu-mcp: порт <порт> занят`, код 1.

Адрес `mpu-back` — `http://127.0.0.1:7338`, `MPU_BACK_URL` заменяет.

## Транспорт и доступ

- Официальный SDK `npm:@modelcontextprotocol/sdk` (версия закрепляется;
  решение владельца 2026-09-18), Streamable HTTP с сессиями, путь `/mcp`.
  Ревизия протокола — та, на которой проверено подтверждение (`2025-11-25`,
  голден `fixtures/mcp-objects/`); на `server/discover` сервер отвечает
  «метод не найден», и клиент переходит на неё сам (так было в пробе).
- Неизвестный `mcp-session-id` — **404** (только на него клиент сам
  переподключается; голден `fixtures/mcp-objects/README.md`).
- `Origin` — хост `127.0.0.1`, `localhost` или `[::1]`, иначе 403; нет
  заголовка — принимается.
- `GET /health` — 200, `{"ok": true, "version": …, "pid": <номер процесса>}`,
  без токена (порция 145: установка ждёт ответа нового процесса).
- Токен клиента — свой: файл `$HOME/.config/mpu/mcp-token`, права 0600,
  создаётся `mcp` при старте, если нет. Заголовок
  `Authorization: Bearer <mcp-token>`, иначе 401. Основной и агентский токены
  `back` клиенту MCP не подходят.
- К `mpu-back` `mcp` ходит с **основным** токеном `back` (читает файл при
  старте): только так `human: true` на `/agent/line` принимается и вопрос
  доходит до человека.

## Тулы

| Тул | Вход | Что делает |
|---|---|---|
| `help` | `{"path": ["kiten", "card"]}`; `path` необязателен, по умолчанию `[]` | строка `["help", ...path]` |
| `mpu` | `{"words": ["kiten", "ls"]}`; `words` обязателен, не пуст | строка `words` |

Строка уходит в `POST /agent/line` с `Accept: application/json`, `cwd` —
домашний каталог, `human` — `true`, если клиент в `initialize` объявил
способность `elicitation`, иначе `false`.

**Ответ тула** — из собранного ответа `back`:

- `content`: блок `text` со stdout; если stderr не пуст — второй блок `text`
  с `stderr:\n` и stderr;
- `structuredContent`: `{"stdout": …, "stderr": …, "exit": N}`;
- `isError`: `true`, если `exit` ≠ 0.

**Вопрос подтверждения.** Собранный ответ пришёл с `ask` и `ticket` →
`elicitation/create` клиенту в той же сессии, форма — как в голдене
(`fixtures/mcp-objects/elicitation.json`): `message` — текст вопроса, одно
обязательное поле `confirm` (boolean, заголовок `Выполнить?`). Ответ клиента:

| Ответ | Уходит в `…/answer` |
|---|---|
| `action: "accept"` и `confirm: true` | `y` |
| `accept` с `confirm: false`, `decline`, `cancel`, ошибка, нет ответа | `n` |

Ответ `back` на `…/answer` снова может кончиться вопросом — повторяется то же.

**Описания тулов** — не длиннее 2048 байт каждое (клиент режет молча,
`platform/mcp-server.md`): у `mpu` — грамматика строки (унарные слова,
`ключ: значение` и `--ключ значение`, `.`), что справку даёт тул `help`, что
некоторые строки спрашивают подтверждение у человека; у `help` — что без
`path` приходит справка корня.

## Отказы

| Дано | Ответ тула |
|---|---|
| `mpu-back` не отвечает | повторы до 10 секунд; затем `isError`, текст `mpu-back недоступен на <адрес>` |
| `back` ответил 401/403 | `isError`, текст `mpu-back отказал в доступе (<код>)` |
| `words` пуст или не массив строк | ошибка JSON-RPC `-32602` (SDK) |
| номер подтверждения истёк, пока человек думал (404 от `back`) | `isError`, текст `подтверждение истекло` |

## Инварианты

- `mcp` не исполняет команд и не хранит сведений о них: список тулов — два,
  неизменный.
- Итог тула `mpu` (stdout, stderr, код) равен итогу той же строки через
  `POST /agent/line` при том же ответе человека.
- Изменить правило через `mcp` нельзя ни при каком ответе (канал агента,
  `platform/policy.md`).
- Ни один токен не появляется в ответах тулов, логах и stdout.
- Рестарт `back` при живом `mcp` не требует перезапуска `mcp`.

## Граничные случаи и ошибки

| Дано | Ожидается |
|---|---|
| `tools/list` | ровно `help` и `mpu`, схемы — голден `fixtures/mcp-objects/tools.json` |
| `mpu` `["version"]` | текст `0.1.0\n`, `exit` 0 |
| `mpu` `["kitn"]` | второй блок `stderr:\nmpu: не понимает kitn; ближайшие: kiten\n`, `isError` |
| `help` без `path` | справка корня |
| `mpu` `["allow:", "kiten ls"]` | `изменить правила может только человек`, `isError`, вопроса нет |
| решение `ask`, клиент с elicitation, `accept` + `true` | строка исполнена |
| то же, `decline` | `…: не подтверждено`, `isError` |
| решение `ask`, клиент без elicitation | `… спросить некого`, `isError` |
| запрос с неизвестной сессией | 404 |
| без токена / чужой токен | 401 |

## Открытые вопросы

Нет. Подключение в Claude Code — полем `headersHelper` (команда печатает JSON
заголовков, запускается вне песочницы и правил разрешений Bash, при
подключении и на 401/403 — документация Claude Code, раздел MCP):

```json
{"mcpServers": {"mpu-next": {"type": "http", "url": "http://127.0.0.1:7339/mcp",
  "headersHelper": "printf '{\"Authorization\":\"Bearer %s\"}' \"$(cat ~/.config/mpu/mcp-token)\""}}}
```

Токен не лежит в конфиге клиента; чтение `mcp-token` агенту запрещается
правилом разрешений клиента (решение владельца, как для основного токена).
Живую проверку делает хост при приёмке; реализации это не касается.
