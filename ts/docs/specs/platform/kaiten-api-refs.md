# platform/kaiten-api-refs — справочники и пользователь

Статус: реализовано (2026-08-14, приёмка: шесть вызовов, курсорная пагинация
транспорта и перевод прогрева справочников на этот каталог; гейты, мутации и
совпадение копий голденов с каналом перепроверены независимо, расхождений со
спекой нет)

## Назначение

Каталог шести вызовов внешнего API Kaiten: владелец токена, лента его
действий, оргструктура компании (пространства → доски → дорожки/колонки) и
определения кастомных полей компании. Ни рендера, ни бизнес-логики, ни
локального кэша — только точная форма обмена по каждому вызову. Локальный
кэш справочников (ускоритель Tab-дополнения) — отдельная надстройка над этим
каталогом, ядру о нём не известно.

Слой API — порт к внешней системе: полнота порта — требование, а не
спекулятивная гибкость. Каталог покрывает вызов независимо от того, есть ли
на него вызывающий код в первой волне команд; отсутствие вызывающего —
нормальное, ожидаемое состояние этого слоя.

Транспорт (базовый URL, токен, заголовки, формат ошибок не-2xx, ретрай 429,
разбор селектора карточки) описан в `platform/kaiten-http.md` — здесь не
повторяется, ниже — только специфика каждого из шести вызовов.

## Ввод/вывод

### 1. `GET /users/current` — владелец токена

- Query: нет. Тело: нет.
- Ответ — один объект: `id` (число, обязателен), `full_name` (строка),
  `username` (строка), `email` (строка). Отсутствующее в ответе поле —
  пустая строка, не `null`.
- Пагинации нет. Значимо всё: `id` — идентификатор владельца токена
  (используется как «мои» в фильтрах ленты и записей времени), остальные —
  представление в выводах команд.

### 2. `GET /users/current/activities` — лента действий пользователя

- Query каждого запроса: `offset` — всегда `0` (глубина не через offset);
  `limit` — не больше 100; `actions` — CSV список типов действий, сервер
  принимает произвольную строку без проверки по словарю; `cursor_created` и
  `cursor_id` — курсор последнего элемента предыдущей страницы, на первой
  странице обе — пустые строки. Тело: нет.
- Ответ — массив объектов: `id` (строка — тот же курсор `cursor_id`),
  `created` (строка ISO-8601 или `null`), `action` (строка), `card_id`
  (число или `null`), `card` (объект или `null`). `card`, когда присутствует,
  — карточка на момент действия (форма — как элемент `GET /cards`); может
  отсутствовать, если действие не привязано к карточке.
- Вход вызова каталога: список типов действий (CSV), потолок числа страниц и
  — необязательно — нижняя граница даты. Курсор наружу не выходит: обход
  страниц выполняет сам вызов, вызывающему достаётся конкатенация
  прочитанных страниц в порядке чтения. Умолчаний ни потолку, ни границе
  каталог не задаёт — их называет командная спека, иначе глубина ленты
  оказалась бы свойством порта.
- Пагинация — курсорная: следующий запрос несёт `cursor_created`/`cursor_id`
  последнего элемента текущей страницы. Останов — пустая страница, страница
  короче `limit`, у последнего элемента страницы нет `created` или `id`,
  исчерпан потолок страниц, либо задана нижняя граница даты и `created`
  последнего элемента стал меньше её (строки ISO-8601 сравниваются
  лексикографически).
- Неочевидность: серверного фильтра по дате нет. Параметры `from`/`to`/
  `since`, если передать, сервер принимает без ошибки (200), но выдачу не
  меняет — глубина по дате достижима только чтением достаточного числа
  страниц и остановом на стороне вызывающего по прочитанному `created`.
- Ошибка сверх общих: `limit>100` → 400 в общем формате не-2xx.

### 3. `GET /spaces` — пространства компании

- Query/тело: нет.
- Ответ — массив объектов: `id` (число), `title` (строка), `archived`
  (булево), `boards` (массив). Элемент `boards[]`: `id` (число), `title`
  (строка), `space_id` (число; если в ответе отсутствует — принадлежность
  берётся от id родительского пространства).
- Пагинации нет — один запрос отдаёт все пространства компании.
- Неочевидность: отдельного справочника досок не существует —
  `GET /boards` без пути отвечает 405. Единственный способ получить список
  досок — собрать вложенный `boards[]` из каждого пространства этого ответа;
  доски не приходят вне контекста своего пространства.

### 4. `GET /boards/{board_id}/lanes` — дорожки одной доски

- Path: `board_id` — id доски из вложенного `boards[]` вызова 3. Query/тело:
  нет.
- Ответ — массив объектов: `id` (число), `board_id` (число), `title`
  (строка).
- Пагинации нет.
- Неочевидность: глобального списка дорожек нет — запрос делается на
  каждую доску отдельно. Обход набора досок несколькими вызовами — забота
  вызывающего, не свойство этого вызова.
- Ошибка сверх общих: несуществующий `board_id` → ошибка не-2xx общего
  формата.

### 5. `GET /boards/{board_id}/columns` — колонки одной доски

- Path: `board_id`. Query/тело: нет.
- Ответ — массив объектов: `id` (число), `board_id` (число), `title`
  (строка), `sort_order` (дробное или `null` — вес колонки на доске слева
  направо; порядок элементов самого массива этот порядок не гарантирует).
- Пагинации нет.
- Неочевидность — та же, что у вызова 4: глобального списка колонок нет,
  запрос на каждую доску отдельно.
- Ошибка сверх общих: несуществующий `board_id` → ошибка не-2xx общего
  формата.

### 6. `GET /company/custom-properties` — определения кастомных полей

- Query/тело: нет.
- Ответ — массив объектов: `id` (число), `name` (строка), `type` (строка
  или `null`).
- Пагинации нет.
- Значимо: пара `id → name` — перевод числового id свойства карточки
  (`properties.id_NNN` в `GET /cards/{id}`) в читаемое название поля; `type`
  — тип поля (текст, число, файл и т.п.), формат значения самим этим
  вызовом не описывается.

## Побочные эффекты

Сеть — только Kaiten API, один запрос на вызов (для 4 и 5 — один запрос на
каждую доску; обход множества досок — ответственность вызывающего). Каталог
не пишет ни в какое хранилище: локальный кэш справочников об этих шести
вызовах не знает.

## Конфигурация

`KITEN_API_KEY`, `KITEN_BASE_URL` — `platform/kaiten-http.md`; здесь без
изменений.

## Инварианты

- `GET /users/current` всегда возвращает ровно один объект с непустым `id`.
- Элементы `GET /users/current/activities` идут от новых к старым (`created`
  не возрастает); курсор следующей страницы строится из последнего (самого
  старого) элемента текущей.
- `boards[]` в ответе `GET /spaces` — единственный источник списка досок;
  отдельного запроса на список досок не существует ни при каких условиях.
- Дорожки и колонки одной доски резолвятся независимо друг от друга: вызов
  4 не требует вызова 5 и наоборот, оба требуют только `board_id`.
- `id` в `GET /company/custom-properties` уникален в пределах компании;
  несколько полей с одинаковым `type` допустимы.

## Граничные случаи и ошибки

- `GET /boards` без пути (без `{board_id}`) — 405; не входит в каталог как
  вызов, упомянут как причина отсутствия справочника досок.
- `GET /users/current/activities` c `limit=101` — 400 в общем формате, в
  отличие от `GET /cards`, где избыток лимита сервер молча капает (см.
  `platform/kaiten-http.md`).
- `GET /users/current/activities` на первой странице — `cursor_created` и
  `cursor_id` пустыми строками; сервер трактует пустой курсор как «начать
  сначала», не как ошибку ввода.
- `GET /spaces` в компании без пространств — `[]`, не ошибка.
- `GET /boards/{board_id}/lanes` и `.../columns` на несуществующий
  `board_id` — ошибка не-2xx общего формата, как любой другой путь с
  плейсхолдером.
- `GET /company/custom-properties` в компании без кастомных полей — `[]`.

## Golden-примеры

- `users-current-ok` — успешный `GET /users/current` → объект пользователя
  со всеми четырьмя полями.
- `activities-page-ok` — первая страница `GET /users/current/activities`
  (пустые курсоры на входе) → массив с непустыми `created`/`id` у каждого
  элемента, включая элемент без `card`.
- `activities-cursor-boundary` — вторая страница по курсору, взятому из
  последнего элемента первой → страница короче `limit`, корректный останов.
- `activities-limit-error` — запрос с `limit=101` → 400 в общем формате.
  Через сам каталог случай недостижим: `limit` задаёт порт, и он равен ста;
  пример описывает границу внешней системы и понадобится тому, кто выведет
  `limit` наружу. Класс ошибки (не-2xx на этом пути) закрыт отдельно.
- `spaces-ok` — `GET /spaces` с двумя пространствами: одно с двумя
  вложенными досками, второе — с `boards: []`; файл существует —
  `fixtures/platform/kaiten-http/spaces-ok.json`.
- `boards-405` — `GET /boards` (без пути) → 405, подтверждающий отсутствие
  справочника досок.
- `lanes-ok` / `columns-ok` — `GET /boards/{id}/lanes` и `.../columns` на
  существующую доску → непустые массивы, у колонок различный `sort_order`;
  файлы существуют — `fixtures/platform/kaiten-http/lanes-ok.json` и
  `columns-ok.json`.
- `lanes-not-found` — `GET /boards/{id}/lanes` на несуществующий `board_id`
  → ошибка не-2xx общего формата.
- `custom-properties-ok` — `GET /company/custom-properties` → несколько
  полей с разными `type`, включая `type: null`.
