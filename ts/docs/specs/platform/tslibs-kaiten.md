# Порция KA1 — клиент Kaiten пакетом `tslibs/kaiten`

Статус: к реализации после T1 (2026-10-07). Гибрид владельца 2026-10-07:
TS-домены — пакеты `tslibs/<домен>` в монолите. Договор пакета —
`platform/tslibs-package.md`; поведение — `platform/kaiten-http.md`,
`kaiten-api-time.md`, `kaiten-api-cards.md`, `kaiten-api-refs.md` (не
меняется). Следующий домен «по связности»: `back/src/kaiten` (~2700 строк)
уже на `@mpu/http`, со слоем команд связан двумя местами, потребители — все
подкоманды `mpu kiten` и шаг 4 `init`. Клиент GitLab (`back/src/gitlab`)
пакетом не выносится: его работу забирает отдельная программа на Go.

## Кто и зачем

Разработчик хочет, чтобы разговор с API Kaiten (доступ, форма запроса,
повтор на 429, пагинация, формат ошибки, каталоги карточек, времени,
справочников) был библиотекой без привязки к рантайму и к слою команд, а
команды `mpu kiten …` и `init` брали её архивом.

## Граница (наблюдаемая, снято с `main` 2026-10-07)

В библиотеку — `http`, `card_ref`, `cards`, `time`, `refs` и их тесты,
фикстуры `testdata/`, фейки `testing.ts` (точка входа `@mpu/kaiten/testing`).
Связи со слоем команд, которые распутывает исполнитель (`.tmp/design-KA1.md`
до кода):

- `card_ref.ts` бросает `UsageError` из `../command/mod.ts` («нет id
  карточки») — библиотека бросает свой класс, перевод в код 2 — на границе
  `ts/`, как в T1;
- `warmup.ts` пишет справочники в `CacheDb` слоя команд — остаётся в `ts/`
  (это запись в кэш команд, не разговор с Kaiten), берёт каталоги из
  библиотеки.

## Сценарии [S.n]

1. `tslibs/kaiten`: `bun install && bun run gate` → зелёно под Bun, Node,
   Deno, `check:release` зелёный; `release/mpu-kaiten-0.1.0.tgz` закоммичен;
   `@mpu/http` — необязательный `peerDependency` плюс `devDependency` архивом
   (договор [S.9]); тестовые помощники — `@mpu/testing`.
2. Список листовых случаев `back/src/kaiten` до = объединение после
   (библиотека + `ts/`), строка в строку; сверх — только новые случаи перевода
   отказа на границе.
3. `rg -n 'Deno\.|Bun\.' tslibs/kaiten/src` → пусто; в библиотеке нет импорта
   из `ts/`; в `ts/` нет файлов `back/src/kaiten/{http,card_ref,cards,time,refs}.ts`.
4. `ts/package.json` → `"@mpu/kaiten": "file:../tslibs/kaiten/release/mpu-kaiten-0.1.0.tgz"`;
   `cd ts && rm -rf node_modules && bun install --frozen-lockfile` проходит
   (лок совпадает с закоммиченным архивом); гейты `ts/` и `bun run smoke`
   зелёные.
5. Голдены команд `kiten ls|card|move|comment|time|status|refs|checklist|field|close`
   и `init` (шаг 4) — без изменений и зелёные.
6. `mpu kiten card id: abc` — прежний текст отказа «не удалось извлечь id
   карточки из 'abc'» дословно, код 2.
7. Токен Kaiten не появляется ни в выводе, ни в тексте ошибки, ни в журнале —
   существующие тесты зелёные.
8. Живьём (хост после установки): `mpu kiten ls date-from: 2026-09-01`,
   `mpu kiten card id: <последняя>`, `mpu kiten time status` — вывод той же
   формы, что до порции.

## Инварианты

- Наблюдаемое поведение команд не меняется.
- Библиотека не знает о слое команд: ни импорта из `ts/`, ни кэш-БД, ни
  текстов справки.

## Границы

- Самоописание `about`, конверт — этап 6.
- `warmup.ts` и всё, что пишет в кэш-БД команд, — в `ts/`.
- Тексты отказов не переписываются (их приведение к «ошибка и как
  исправить» — отдельная вычистка после этапа 6).

## Пункты чек-листа

выведены из него; 2 особые случаи — 429 / страница / ошибка формата — в
транспорте, не у вызывающего; 7 основание проверкой — [S.2], [S.4].
`design-mpu.md`: 4 один источник — форма запроса и ошибки Kaiten в

параметрами; прочее — ничего.
