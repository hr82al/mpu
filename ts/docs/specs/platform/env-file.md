# platform/env-file — слой секретов и подключений

Статус: реализовано (2026-08-04; доработка 2026-08-05 — чтение
окружения процесса исключено, конфигурация только из файла — выполнена
порцией Б init и принята 2026-08-05). Golden сняты с живой
Python-версии — `fixtures/platform/env-file/`; вердикты по отчёту
реализации внесены: дубликат ключа, тексты ошибок записи, путь без
`HOME`, момент чтения MCP-сервером. 2026-08-05: дописаны умолчания и
обязательность ключей dev-стенда — поведение прежнее, спека их просто не
называла (вопрос порции sql-ro)

## Назначение

Env-файл (dotenv) — слой секретов и адресов внешних систем: PG-креды,
API-ключи, адреса серверов стенда; кроме них — несекретные служебные
переменные обвязки, не входящие в реестр предпочтений (`MPU_LOG_*`).
Его читают команды, ходящие во внешние системы. Установленная Python-версия
читает тот же файл, пока существует на машине: формат обязан разбираться
одинаково, иначе один и тот же ключ означал бы у них разное. Пользовательские
предпочтения — не этот слой: у них свой реестр без секретов и команда
`mpu config` (`platform/config.md`).

## CLI-контракт

нет (механизм конфигурации; правится пользователем руками, команд
редактирования env-файла нет).

## Ввод/вывод

- Файл: `$XDG_CONFIG_HOME/mpu/.env` (дефолт `~/.config/mpu/.env`; пустая
  `XDG_CONFIG_HOME` равнозначна незаданной), кодировка UTF-8.
- Формат — dotenv в объёме golden-пары `fixtures/platform/env-file/
  sample.env` → `sample-parsed.json` (снята с живого разборщика):
  комментарии `#` (хвостовой у безкавычного значения отрезается только
  при пробеле перед `#`: `va#lue` — часть значения), префикс `export `,
  пробелы вокруг `=` не входят ни в имя, ни в значение, пустое значение,
  одинарные кавычки — литерал (`#` внутри не режется), двойные кавычки;
  при повторе ключа в файле действует последнее вхождение. Строка без
  `=` ключа не даёт. Конструкции вне пары (подстановка `${VAR}`,
  многострочные значения, escape-последовательности в двойных кавычках,
  битые строки вроде незакрытой кавычки) контрактом не гарантируются — в
  файле не использовать.
- Файл читается не более одного раза за процесс, лениво при первом
  обращении к любому ключу; это относится и к долгоживущему
  MCP-серверу — изменение файла требует его перезапуска. Отсутствие
  файла — не ошибка (все ключи по дефолтам).
- Чтение: только файл, затем дефолт потребителя. Окружение процесса
  слой не читает (решение 2026-08-05): право бинаря на чтение окружения
  закрыто коротким списком служебных переменных (пути `HOME`/
  `XDG_CONFIG_HOME`, совместимость completion), конфиг-ключей в нём
  нет — экспорт ключа в shell на native-команды не влияет (см.
  отклонения). В список входят и имена, которые безусловно читает
  сторонний драйвер внешней системы (`PGAPPNAME` у клиента
  PostgreSQL — без права он не создаётся вовсе); конфигурацией это не
  является: прочитанное значение перекрывается явной опцией
  реализации, и на наблюдаемое поведение экспорт такой переменной не
  влияет — что и требует проверять smoke-сценарий.
- Обязательный для команды ключ отсутствует ИЛИ пуст → ошибка слоя:
  `environment variable <ИМЯ> is not set. Add it to <путь env-файла> or
  export in shell.` Как ошибка рендерится (префикс, exit-код) — спека
  команды.
- Программная запись (команды, кэширующие токены внешних систем, —
  `init.md`): атомарная замена файла (tmp + rename), права итога 0600,
  update-or-append: первая строка вида `[export ]ИМЯ=` (отступ
  допускается) заменяется целиком строкой `ИМЯ=значение` — golden
  `write-before.env` → `write-after.env` (`export`-префикс заменённой
  строки не сохраняется); прочие строки и комментарии нетронуты; новый
  ключ дописывается в конец; файл завершается переводом строки. Форма
  значения: «простое» (непустое, без пробельных, `#` и кавычек) — как
  есть; иначе — в одинарных кавычках; значение с переводом строки или
  одинарной кавычкой — ошибка записи
  (`cannot write env value for <ИМЯ>: value contains a newline or a
  single quote`), файл не тронут. Ключ повторяется в файле → отказ до
  касания диска (`cannot write env value for <ИМЯ>: a later line in
  <путь> repeats the key and would override the write`) — иначе запись
  молча не действовала бы (см. отклонения). Записанное значение
  действует в текущем процессе немедленно, без перечитывания файла.

## Побочные эффекты

Чтение файла; запись — только атомарная замена (см. выше); каталог
`mpu/` создаётся при первой записи. Сети нет.

## Конфигурация

Ключи обвязки (ключи конкретных доменов — в спеках этих доменов, по мере
переезда):

- `sl_<N>`, `pg_<N>` — IP серверов стенда (N = 0…), `sl_<N>_portainer` —
  legacy-fallback оркестратора;
- `PG_PORT` (5432), `PG_DB_NAME` (`wb`), `PG_MY_USER_NAME` /
  `PG_MAIN_USER_NAME`, `PG_MY_USER_PASSWORD` / `PG_MAIN_USER_PASSWORD`
  (личные креды приоритетнее общих — независимо по каждому ключу: имя
  берётся из `PG_MY_USER_NAME`, иначе `PG_MAIN_USER_NAME`, и так же
  отдельно пароль);
- dev-стенд (одна БД на всех клиентов): `DEV_PG_HOST` — обязателен,
  дефолта нет; `DEV_PG_PORT` (`5434`), `DEV_PG_DB` (`mp_sl_1_dev`);
  `DEV_PG_USER` / `DEV_PG_PASSWORD` — собственные креды стенда,
  обязательны и из `PG_MY_*` / `PG_MAIN_*` не подставляются;
- `MPU_LOG_*` — журнал вызовов (контракт — `platform/invoke-log.md`).

## Инварианты

- Секреты не покидают машину и не печатаются: значения env-ключей не
  появляются ни в выводе команд, ни в журнале вызовов (маскирование —
  `platform/invoke-log.md`).
- Порядок чтения: env-файл → дефолт потребителя; одинаков для всех
  ключей. Значения окружения процесса на ключи слоя не влияют.
- Пустое значение обязательного ключа равнозначно его отсутствию.
- Атомарная запись не теряет и не дублирует прочие строки файла;
  повторная запись того же значения идемпотентна.
- Изменение файла извне не влияет на уже запущенный процесс.

## Граничные случаи и ошибки

- Переменная и в окружении процесса, и в файле → действует файл:
  окружение слоем не читается.
- Значение для записи содержит перевод строки или одинарную кавычку →
  ошибка записи, файл не тронут.
- Нет обязательного для команды ключа → ошибка слоя с именем ключа (см.
  «Ввод/вывод»), а не generic-ошибка подключения.
- `XDG_CONFIG_HOME` (или `HOME`) задана, но пуста → как незаданная.
- Путь файла неопределим (нет ни `XDG_CONFIG_HOME`, ни `HOME`) → чтение
  отдаёт только окружение процесса; запись — ошибка `cannot write env
  file: no config directory`; в тексте ошибки обязательного ключа
  печатается канонический путь `~/.config/mpu/.env`.
- Ключ повторяется в файле → чтение отдаёт последнее вхождение; запись
  этого ключа отказывает (см. «Ввод/вывод»).

## Golden-примеры

- `sample.env` → `sample-parsed.json` — разбор всех гарантированных
  конструкций формата (снято dotenv-разборщиком живой версии).
- `write-before.env` + запись `TARGET` = `new value with space`, затем
  `APPENDED` = `bare-token` → `write-after.env` — замена `export`-строки
  с кавычением значения и дописывание нового ключа; права файла после
  записи 0600.

## Известные отклонения

- **preserve** — расположение учитывает `XDG_CONFIG_HOME` (внешний
  контракт для существующей машины; идея унификации — в журнал переезда).
- **fix** — оригинальный текст ошибки обязательного ключа завершается
  строкой `See <каталог пакета>/.env.example for the template.` — путь
  внутрь установленного пакета Python-реализации, у нового бинаря такого
  файла нет. Новая реализация эту строку не печатает; остальной текст —
  дословно.
- **fix** — в оригинале две читалки слоя с разной семантикой: часть
  ключей (адреса серверов и оркестратора, Loki, PG-параметры —
  `sl_<N>`, `pg_<N>`, `PORTAINER_*`, `LOKI_URL`, `PG_PORT`,
  `PG_DB_NAME`, `PG_MY_USER_*`, `PG_MAIN_USER_*`) читается отдельным
  механизмом с жёстким путём `~/.config/mpu/.env` — без учёта `XDG_CONFIG_HOME` и без
  приоритета переменных окружения процесса (обнаружено прогоном
  2026-08-04: `XDG_CONFIG_HOME` на пустой каталог скрывает ключи
  Kaiten, но не Portainer/Loki). Новая реализация применяет единую
  семантику слоя (эта спека) ко всем ключам.
- **fix** — оригинал для ключей первой читалки (Kaiten, `MPU_LOG_*`)
  давал переменной окружения процесса приоритет над файлом. Новая
  реализация окружение процесса не читает вовсе (решение оператора
  2026-08-05): вся конфигурация — env-файл, право бинаря на чтение
  окружения закрыто служебным списком (пути, completion) и не
  расширяется. Имена, которые читает не наш код, а драйвер PostgreSQL
  мимо этого списка (`USER`, `NODE_PG_FORCE_NATIVE`), бинарь запрещает
  явно (`--deny-env`, решение оператора 2026-08-20): значения ему не
  нужны — имя пользователя задано опциями подключения, а
  `NODE_PG_FORCE_NATIVE` из окружения сменил бы клиент на `pg-native`.
  Драйвер оба чтения выполняет в `try/catch` и отказ переносит молча;
  без явного запрета Deno спрашивал бы разрешение на терминале при
  каждом подключении, а под MCP-клиентом такой вопрос остановил бы
  сервер без вывода. Экспорт конфиг-ключа в shell на native-команды не
  влияет; Python-реализация до вывода из эксплуатации сохраняет своё
  поведение.
- **fix** — при повторе ключа в файле оригинал молча заменяет первое
  вхождение, и запись не действует: чтение отдаёт последнее (проверено
  прогоном живой версии: `PG_PORT=5432/6432`, запись `7777` → читается
  `6432`). Новая реализация отказывает до касания диска с явной ошибкой
  (текст — «Ввод/вывод»); файл без дублей ведёт себя идентично
  оригиналу.
