# platform/env-file — слой секретов и подключений

Статус: черновик (адаптирована 2026-08-04 под один бинарь: env-файл читает
сам CLI)

## Назначение

Env-файл (dotenv) — слой секретов и адресов внешних систем: PG-креды,
API-ключи, адреса серверов стенда. Его читают native-команды, ходящие во
внешние системы; Python-реализация (маршрут `legacy`) читает тот же файл —
общая граница двух реализаций на время переезда. Пользовательские
предпочтения — не этот слой: у них свой реестр без секретов и команда
`mpu config` (`platform/config.md`).

## CLI-контракт

нет (механизм конфигурации; правится пользователем руками, команд
редактирования env-файла нет).

## Ввод/вывод

- Файл: `$XDG_CONFIG_HOME/mpu/.env` (дефолт `~/.config/mpu/.env`),
  формат dotenv, права 0600. Отсутствие файла — не ошибка (все ключи по
  дефолтам); отсутствие ключа, обязательного для команды, — ошибка этой
  команды с именем ключа (текст и exit-код — в спеке команды/атома).
- Уже экспортированная в окружение процесса переменная побеждает файл.
- Программная запись переменной (команды, кэширующие токены внешних
  систем, — `init.md`): атомарная замена файла (tmp + rename), права
  0600, update-in-place существующей строки; значение с переводом строки
  или одинарной кавычкой — ошибка; с пробелами/`#` — одинарные кавычки.

## Побочные эффекты

Чтение файла при запуске команды; запись — только атомарная замена
(см. выше). Сети нет.

## Конфигурация

Ключи обвязки (ключи конкретных доменов — в спеках этих доменов, по мере
переезда):

- `sl_<N>`, `pg_<N>` — IP серверов стенда (N = 0…), `sl_<N>_portainer` —
  legacy-fallback оркестратора;
- `PG_PORT` (5432), `PG_DB_NAME` (`wb`), `PG_MY_USER_NAME` /
  `PG_MAIN_USER_NAME`, `PG_MY_USER_PASSWORD` / `PG_MAIN_USER_PASSWORD`
  (личные креды приоритетнее общих);
- `DEV_PG_HOST/PORT/DB` (dev-стенд, одна БД на всех клиентов),
  `DEV_PG_USER/PASSWORD`;
- `MPU_LOG_*` — журнал вызовов (контракт — `platform/invoke-log.md`).

## Инварианты

- Секреты не покидают машину и не печатаются: значения env-ключей не
  появляются ни в выводе команд, ни в журнале вызовов (маскирование —
  `platform/invoke-log.md`).
- Порядок приоритета: переменная окружения процесса → env-файл → дефолт;
  одинаков для всех ключей и никогда не инвертируется.
- Атомарная запись не теряет и не дублирует прочие строки файла;
  повторная запись того же значения идемпотентна.

## Граничные случаи и ошибки

- Переменная и в окружении процесса, и в файле → действует окружение.
- Значение для записи содержит перевод строки или одинарную кавычку →
  ошибка записи, файл не тронут.
- Нет обязательного для команды ключа → команда падает с именем
  недостающего ключа, а не generic-ошибкой подключения.

## Golden-примеры

нет — механизм без собственной пользовательской поверхности; контракт
закрепляется контрактными тестами (приоритет слоёв, атомарная запись,

## Известные отклонения

- **preserve** — расположение учитывает `XDG_CONFIG_HOME` (внешний
  контракт для существующей машины; идея унификации — в журнал переезда).

## Открытые вопросы

- Момент чтения env-файла долгоживущим MCP-сервером одного бинаря: на
  старте процесса или на каждый вызов тула. Решить при переезде первой
  native-команды, зависящей от env-файла; для одноразового CLI-процесса
  вопроса нет — чтение при запуске.
