# platform/loki-http — HTTP-обвязка Loki

Статус: к реализации (2026-09-14: обход прокси окружения — раздел
«Прокси окружения» и отклонение fix ниже; прежняя часть реализована
2026-08-05 порцией Б init)

## Назначение

Единая форма обращения к Loki стенда: базовый URL, discovery множества
хостов и сервисов через series API. Потребители: прогрев кэша в
`init.md` и `update.md` (best-effort), позже — команда `logs`.

## CLI-контракт

нет (платформенная возможность).

## Ввод/вывод

Discovery пар (host, service) — один запрос:

- `GET {LOKI_URL}/loki/api/v1/series` с параметрами:
  `match[]={host=~".+"}`, `start=<нс>`, `end=<нс>` — окно «последние
  24 часа» (86400 s), границы в наносекундах unix-времени.
- Заголовков авторизации нет; TLS проверяется; переменные прокси
  окружения игнорируются.
- Ответ — JSON `{"status": …, "data": [ {label: value, …}, … ]}`; из
  каждой записи читаются лейблы `host` (строка, обязателен для учёта)
  и `compose_service` (строка, опционален). Пример —
  `fixtures/platform/loki-http/series-ok.json`. Ответ неожиданной
  формы (тело не JSON, нет `data`, `data` не список) даёт пустой
  результат, не ошибку; внутри валидного списка запись без пригодного
  `host` (не-объект, отсутствующий или нестроковый `host`)
  пропускается поштучно — остальные разбираются.
- Результат — уникальные хосты и уникальные пары (host, service).

Запись результата в кэш-БД (`platform/store.md`): таблицы `loki_hosts`
и `loki_services_by_host`, полная перезапись (DELETE + INSERT) одной
транзакцией, `discovered_at` — unix-время.

## Прокси окружения

Требование «переменные прокси окружения игнорируются» относится ко
всем вызовам общего HTTP-транспорта, которым вызывающий не передал
прокси явно: Loki, Portainer (`logs.md`, `health.md`), Kaiten, GitLab
(`gitlab-api.md`), sl-back, x10, webapp. Такой вызов открывает
соединение напрямую, какими бы ни были `HTTP_PROXY`, `HTTPS_PROXY`,
`ALL_PROXY`, `NO_PROXY` и их варианты в нижнем регистре. Явный прокси
(Bot API, `telegram-log.md`) работает как прежде.

Наблюдаемый след: при `HTTP_PROXY`/`HTTPS_PROXY`, указывающих на
слушателя, который принимает соединение и не отвечает, запрос к
отвечающему серверу получает его ответ, а слушатель не получает ни
одного соединения. С явным прокси тот же запрос приходит слушателю.

Замеры 2026-09-14 (Deno 2.9.6), на которых держится требование:

- `fetch` без клиента и `fetch` с `Deno.createHttpClient({})` берут
  прокси из окружения; право `--allow-env` на это не влияет — без
  него прокси применяется точно так же. Значит, отказ в праве читать
  переменные прокси требования не выполняет.
- `request` из `node:http` в том же окружении идёт напрямую: ответ 200
  за 38 мс там, где `fetch` висел до таймаута.
- С `NO_PROXY`, содержащим адрес (или CIDR `192.168.0.0/16`), `fetch`
  идёт напрямую — это обход окружением, а не свойство программы, в
  контракт не входит.

## Побочные эффекты

Сеть — только Loki; запись — только кэш-БД (см. выше).

## Конфигурация

`LOKI_URL` (env-слой — `platform/env-file.md`) — базовый URL; не
задан → discovery не выполняется, потребитель получает ошибку
`LOKI_URL не задан` (best-effort потребители печатают её как пропуск).

## Инварианты

- Один HTTP-запрос на discovery; per-host запросов нет.
- Запрос ограничен таймаутом; зависший Loki не блокирует потребителя
  дольше таймаута (инварианты устойчивости потребителя — `init.md`).
- Ошибка сети/HTTP/формы не оставляет частичной записи: обе таблицы
  либо перезаписаны целиком, либо не тронуты.

## Граничные случаи и ошибки

- `LOKI_URL` не задан → без сети, ошибка-пропуск (см. «Конфигурация»).
- HTTP-ошибка или таймаут → ошибка потребителю с причиной БЕЗ
  префикса: `HTTP <код>`, `no response headers within <N>ms`,
  `no response within <N>ms` либо первая строка системной ошибки сети
  (те же формы, что у Portainer в `init.md`); префикс `loki:`
  добавляет строка потребителя. Кэш не изменяется.
- Ответ без `data`/не-список → пустой результат, таблицы перезаписаны
  пустыми множествами (наблюдаемое поведение оригинала).

## Golden-примеры

`fixtures/platform/loki-http/series-ok.json` — форма ответа series API
(синтетическая). Поведенческие golden — в спеках потребителей.

## Известные отклонения

- **fix** — прокси окружения применяется к вызовам без явного прокси.
  Сессия агента выставляет `HTTP_PROXY=http://127.0.0.1:8888`, этот
  прокси до адресов стенда за VPN (`192.168.150.0/24`) не доходит, и
  любой вызов `mpu logs` падает `loki: no response headers within
  3000ms`; напрямую тот же Loki отвечает за 26 мс. Требуемое
  поведение — раздел «Прокси окружения». Проверка — тестом со
  слушателем-ловушкой из «Наблюдаемого следа», без сети наружу.

## Открытые вопросы

- Окно 24 ч и матчер `{host=~".+"}` — константы оригинала; их
  конфигурируемость не заводить до реальной нужды (YAGNI).
