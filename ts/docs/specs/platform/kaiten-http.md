# platform/kaiten-http — HTTP-обвязка Kaiten

Статус: черновик

## Назначение

Общая обвязка подкоманд `mpu kiten` (спеки `kiten-*.md`): авторизация и
форма HTTP-запросов к Kaiten API, retry, пагинация, формат ошибок,
разбор селектора карточки, резолв справочных ссылок и локальный кэш
справочников. Контракт возможности — не API реализации.

## CLI-контракт

нет

## Ввод/вывод

### Запрос

- Базовый URL: env `KITEN_BASE_URL`; не задан — `https://btlz.kaiten.ru`.
  Все пути API — под `{base}/api/latest`: запрос «GET /cards» уходит на
  `{base}/api/latest/cards`.
- Заголовки каждого запроса: `Authorization: Bearer <KITEN_API_KEY>`,
  `Accept: application/json`; JSON-тело сопровождается
  `Content-Type: application/json`.
- Web-URL карточки (поле `url` в выводах команд): `{base}/{card_id}`.
- Тело успешного ответа разбирается как JSON; пустое тело — отсутствие
  данных, не ошибка разбора.

### Retry и ошибки

- Единственный автоповторяемый статус — 429: до 6 попыток на запрос.
  Пауза перед повтором — целое число секунд из заголовка `Retry-After`;
  заголовка нет — экспоненциальный backoff: 1 s, ×2 за попытку, потолок
  30 s. Каждый повтор логируется в stderr:
  `[kaiten] 429 rate-limit, sleep {N}s`.
- Любой другой не-2xx — немедленная ошибка без повторов. Текст:
  `kaiten {METHOD} {path} -> {status}: {body}`, тело обрезано до 300
  символов.
- Все 6 попыток ответили 429 → та же ошибка со статусом 429 и телом
  `exhausted retries`.
- Команда, получившая ошибку API, печатает в stderr
  `mpu kiten <sub>: kaiten error: <текст ошибки>` и завершает процесс
  exit 1.

### Пагинация

- `GET /cards`: offset-пагинация, `limit=100`, `offset=0,100,200,…`;
  останов — пустая страница либо страница короче 100 (последняя
  неполная). Полный список = конкатенация страниц в порядке запросов.
  `limit>100` сервер молча уменьшает до 100 — поднимать лимит нельзя.
- `GET /users/current/activities`: курсорная пагинация — каждый запрос
  несёт `offset=0`, `limit=100`, `actions=<csv>`, `cursor_created` и
  `cursor_id` последнего элемента предыдущей страницы (на первой
  странице — пустые строки). `limit>100` сервер отвергает статусом 400.
  Серверного фильтра по дате у эндпоинта нет: параметры
  `from`/`to`/`since` он принимает, но игнорирует (200 с той же
  выдачей) — глубина управляется только числом прочитанных страниц
  (потолок задаёт вызывающая команда). Останов: пустая страница,
  страница короче 100, отсутствие cursor-полей у последнего элемента,
  либо задана нижняя граница даты и `cursor_created` стал меньше её
  (строки ISO-8601 сравниваются лексикографически).
- `GET /users/{id}/time-logs?from=&to=`: пагинации нет; `from` и `to`
  обязательны — без них сервер отвечает 500, а не «за всё время». Оба
  параметра передаются всегда.

### Селектор карточки

Единый разбор аргумента-карточки во всех командах `kiten-*`:

- строка из одних цифр → id карточки;
- иначе строка разбирается как URL: id — ПОСЛЕДНИЙ полностью числовой
  сегмент пути (`…/space/286794/boards/card/65634936` → 65634936, не
  286794); query и fragment отбрасываются;
- числового сегмента нет → ошибка ввода, exit 2:
  `не удалось извлечь id карточки из '<строка>'`.

### Резолв справочной ссылки

Опции `--space`/`--board`/`--lane`/`--column`/`--role` принимают «ID
или подстроку названия»; резолв — по локальному кэшу справочников, без
сети:

- строка из одних цифр → ID как есть (работает и при пустом кэше);
- иначе точное совпадение названия без учёта регистра; ровно одно →
  его ID;
- иначе совпадение по подстроке без учёта регистра; ровно одно → его ID;
- ноль совпадений → ошибка ввода, exit 2:
  ``{kind} '{ref}' не найден — см. `mpu kiten {kind}s` `` — `{kind}` —
  одно из `space`/`board`/`lane`/`column`/`role`;
- больше одного → ошибка ввода, exit 2: `{kind} '{ref}' неоднозначен
  ({N} совпадений): {id} ({title}), …` — не более 10 кандидатов.

## Побочные эффекты

Сеть — только Kaiten API. Локальный кэш справочников — таблицы в
кэш-БД (`Store`, bootstrap — `init.md`): пространства
(id, title, archived), доски (id, space_id, title), дорожки и колонки
(id, board_id, title), роли (id, name), кастомные поля (id, name,
type); каждая строка несёт время обнаружения. Обновление — полной
заменой содержимого таблицы; дорожки и колонки заменяются только по
обойдённым доскам (частичный рефреш не стирает кэш остальных досок).
Отсутствие таблиц кэша — не ошибка: они создаются при первой записи.

## Конфигурация

- `KITEN_API_KEY` — обязателен, Bearer-токен Kaiten. Не задан →
  команда завершается ошибкой ввода до первого сетевого запроса,
  exit 2, stderr: `mpu kiten <sub>: KITEN_API_KEY не задан; попробуй:
  добавить KITEN_API_KEY в env-файл` (env-файл — `platform/env-file.md`).
- `KITEN_BASE_URL` — опционален, дефолт `https://btlz.kaiten.ru`.

## Инварианты

- Каждый запрос несёт Bearer-токен и `Accept: application/json`; токен
  не попадает ни в stdout, ни в stderr, ни в тексты ошибок.
- 429 — единственный статус с автоповтором; такой повтор безопасен и
  для мутирующих запросов (429 означает «запрос не обработан»).
- Разбор селектора карточки и резолв справочных ссылок не ходят в сеть.
- Отсутствие `KITEN_API_KEY` обнаруживается до первого запроса.

## Граничные случаи и ошибки

- Ответ 429 с `Retry-After: 7` → пауза 7 s, лог в stderr, повтор.
- Шесть ответов 429 подряд → ошибка
  `kaiten {METHOD} {path} -> 429: exhausted retries`, exit 1.
- Сетевая недоступность хоста → ошибка команды в том же формате
  `mpu kiten <sub>: kaiten error: <причина>`, exit 1, без трейсбека.
- Кэш справочника пуст, ссылка нечисловая → «не найден» (см. резолв).

## Известные отклонения

- **fix** — при отсутствии `KITEN_API_KEY` часть подкоманд (в т.ч.
  `whoami`, `card`, `ls`, `status`) обрывается необработанным
  исключением с многострочным трейсбеком и exit 1, а справочные
  подкоманды печатают машинно-читаемую ошибку. Правильное поведение —
  единый формат из раздела «Конфигурация» (stderr одной строкой,
  exit 2) во всех подкомандах.

## Открытые вопросы

- Таймаут HTTP-соединения оригиналом не задаётся (системный дефолт,
  зависшее соединение ждёт неограниченно). Значение таймаута
  зафиксировать при переводе зависимых спек в «к реализации».
