# Библиотека `tslibs/<имя>` — договор пакета

Статус: к реализации (2026-10-07); первым применяет порция K1 (`platform/tslibs-receiver.md`), затем H1
(`platform/tslibs-http.md`). План — `docs/plans/2026-10-06-bun-tslibs-objects-plan.md`,
этап 4; решения владельца 2026-10-07: библиотеки — автономные пакеты, не
workspaces; потребитель ставит архив пакета.

## Кто и зачем

Разработчик хочет вести домен отдельной библиотекой: сессия, запущенная в
`tslibs/<имя>`, видит, собирает и тестирует только её; потребитель (`ts/`,
другая библиотека) получает её готовым архивом без исходников.

## Сценарии [S.n] (на примере `tslibs/http`, версия 0.1.0)

1. Чистый клон, `cd tslibs/http && bun install && bun run gate` → зелёно;
   `ts/` для этого не нужен.
2. `bun run gate` исполняет по порядку: `biome check .`, `tsc --noEmit`, тесты
   под Bun, Node и Deno (`bun run test:bun`, `test:node`, `test:deno` — один и
   тот же Vitest 3.2.4), сборку, сверку архива ([S.10]); любое красное — код
   выхода ≠ 0.
3. `bun run build` → `dist/index.js` (бандл `bun build --target node`),
   `dist/index.d.ts`; при наличии фейков — `dist/testing.js` и
   `dist/testing.d.ts` (точка входа `@mpu/http/testing`).
4. `bun run release` → `release/mpu-http-0.1.0.tgz`; `tar tzf` архива
   печатает ровно `package/package.json` и файлы `package/dist/…` — ни `src/`,
   ни тестов, ни `index.ts`.
5. В потребителе `package.json`:
   `"@mpu/http": "file:../tslibs/http/release/mpu-http-0.1.0.tgz"`; после
   `bun install` в `node_modules/@mpu/http` — только `package.json` и `dist/`.
6. Потребитель ставит библиотеку `bun install` (Bun распаковывает архив
   `file:…tgz` штатно). Deno потребителем локального пакета не бывает: проба
   2026-10-07 — `deno install` архив не распаковывает, а `file:` на папку
   разрешён только в `nodeModulesDir: "manual"` с цепочкой обходов.
7. `rg -n 'Deno\.|Bun\.' tslibs/http/src` → пусто; `rg -n "from \"\.\./\.\./"`
   (выход из папки библиотеки) → пусто, кроме зависимостей-архивов других
   библиотек через `package.json`.
8. Новая версия: `version` в `package.json` и архив `release/mpu-http-0.2.0.tgz`
   в одном коммите, прежний архив удалён; потребитель переходит на новую
   версию своей правкой `package.json`. Любое изменение `dist/` — новая
   версия; архив той же версии переупаковывается только если `dist/` побайтно
   прежний (поменялись лишь скрипты `package.json`, как в T1).
9. Библиотека зависит от другой библиотеки так: `peerDependencies`
   (`"@mpu/http": "0.1.0"`, необязательная в `peerDependenciesMeta`) плюс
   `devDependencies` архивом (`"file:../http/release/mpu-http-0.1.0.tgz"`) для
   своих тестов; потребитель ставит обе библиотеки сам. Вложенный `file:` в
   `dependencies` Bun разрешает от корня потребителя — установка падает (T1).
   Дополнительные точки входа (`./session`, `./thrown`) — по спеке библиотеки,
   кроме `.` и `./testing`.
12. Свежая установка потребителя — только с пустым кэшем Bun: `cd ts && rm
    -rf node_modules && BUN_INSTALL_CACHE_DIR=$(mktemp -d) bun install
    --frozen-lockfile` → код 0. С тёплым кэшем Bun берёт прежнюю распаковку
    архива той же версии и не замечает, что хэш в `bun.lock` устарел (на
    2026-10-08 так прятались три записи — `telegram`, `http`, `testing`).
10. Сверка архива (`bun run check:release`, последний шаг `gate`): собрать
    (`build`, затем упаковка — работает и без готового `dist/`) архив текущей
    версии во временный каталог и сравнить побайтно с
    `release/mpu-<имя>-<версия>.tgz` (`bun pm pack` воспроизводим, проверено в
    H1). Исходники поменялись, архив нет →
    `release/mpu-http-0.1.0.tgz не совпадает с исходниками — bun run release и закоммить архив`,
    код 1. Архива нет → то же сообщение.
11. Тестовые помощники, общие для `ts/` и пакетов (тестовый HTTP-сервер,
    `rejected`, …), живут в `tslibs/testing` (`tslibs-testing.md`); пакет
    ставит его `devDependency` архивом. Своей копии помощника в пакете нет.

## Инварианты

- Исходники библиотеки не попадают ни в архив, ни в `node_modules`
  потребителя.
- Архив в `release/` — единственный способ потребителя получить
  библиотеку; он закоммичен, собран из закоммиченных исходников той же
  версии.
- Код библиотеки одинаково работает под Bun, Node и Deno.

## Раскладка (одна на все библиотеки) [D.1]

```
tslibs/<имя>/
  package.json     name "@mpu/<имя>", version, type module, files ["dist"],
                   exports "." (+ "./testing"), scripts gate/test:*/build/release,
                   точные версии зависимостей
  bun.lock         коммитится
  tsconfig.json    strict, noEmit; d.ts — отдельным tsc при сборке
  biome.json       форматтер как в `ts/biome.jsonc` (пробелы, 2, 80), линтер —
                   рекомендованный без выключений
  vitest.config.ts
  index.ts         поверхность библиотеки (JSDoc на каждом экспорте)
  testing.ts       фейки для тестов потребителя (если нужны)
  src/             устройство
  release/         архивы версий (коммитятся)
  dist/            не коммитится
  CLAUDE.md        что это, команды, правила кода, ядро чек-листов и порядок
                   «гейт → рецензия → гейт → коммит»; сессия библиотеки не видит
                   `ts/CLAUDE.md`, поэтому нужные правила — здесь. Чек-листы не
                   копируются: путь `../../ts/docs/checklists/`, сессию
                   библиотеки запускают с `--add-dir` на этот каталог
```
