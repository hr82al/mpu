# mpu update

Статус: к реализации (утверждена 2026-08-05; закрыты вопросы черновика:
`<S>` в summary — только успешно опрошенные инстансы, DDL кэш-таблиц —
фикстура `platform/store.md`; добавлена устойчивость: таймаут на каждое
PG-обращение, конкурентный фан-аут)

## Назначение

Синк снапшота кэш-БД с PG: список клиентов с main-сервера, таблицы
клиентов с каждого инстанса, WB-sid'ы — полная перезапись одной
транзакцией. Кэшем живёт резолв селектора (`platform/selector.md`).
Помимо CLI, возможность вызывается программно поисковой командой:
полный синк как fallback пустого поиска и точечный синк одного клиента.

## CLI-контракт

`mpu update [--quiet]`

Три источника; шаги 2 и 3 зависят от результата шага 1, между собой
независимы; все обращения к PG — SELECT:

1. main (sl-0): `SELECT id, server, is_active, is_locked, is_deleted
   FROM public.clients` — единственный авторитет по списку клиентов и
   их серверам.
2. Из значений `server` извлекаются номера по `sl-(\d+)`; для каждого
   уникального номера N > 0 (main и нераспознанные значения в фан-аут
   не входят) на инстансе N: `SELECT client_id, spreadsheet_id, title,
   template_name, is_active FROM public.spreadsheets`. Обход инстансов
   допускает конкурентность. Сбой одного инстанса (подключение, запрос,
   таймаут, отсутствие `pg_<N>` в env-файле) → сервер попадает в список
   упавших (номер + первая строка сообщения об ошибке), синк
   продолжается по остальным.
3. main: `SELECT DISTINCT client_id, sid FROM public.wb_tokens
   WHERE sid IS NOT NULL`; sid сохраняется строкой; строка с client_id,
   отсутствующим в выборке шага 1, отбрасывается молча.

Запись: bootstrap схемы по `platform/store.md` (предваряет запись;
self-heal старого кэша без части таблиц), затем **одна
SQLite-транзакция** полного замещения трёх таблиц снапшота: `DELETE` +
вставка клиентов (`sl_clients`), таблиц клиентов (`sl_spreadsheets`,
накопительно по всем успешно опрошенным инстансам, имя сервера —
`sl-<N>`, пустой/NULL заголовок — пустой строкой), sid'ов
(`sl_wb_sids`). Прерывание внутри транзакции не оставляет частичного
снапшота.

Затем best-effort обновляется кэш Loki (контракт —
`platform/loki-http.md`); его ошибка не влияет ни на код выхода, ни на
PG-часть; прогрев выполняется и при `--quiet` — подавляется только
печать.

Вывод без `--quiet`: одна строка stdout
`clients: <N> rows, spreadsheets: <M> rows from <S> servers,
wb sids: <K> rows, took <t>s` (t — секунды с двумя знаками; `<S>` —
число успешно опрошенных инстансов, упавшие не входят); затем
Loki-строка: успех — stdout `loki: <H> hosts, <P> (host, service) пар`,
ошибка — stderr `loki: пропущено (<причина>)`; при упавших серверах —
stderr `warning: failed to query servers: sl-<N> (<первая строка
ошибки>), …` (через запятую, по возрастанию номера сервера). `--quiet`
подавляет весь блок печати целиком — summary, Loki-строку и
предупреждения; сами обращения и записи выполняются полностью.

Exit 0 — включая прогоны с упавшими инстансами; недоступный main —
exit 1 (см. «Известные отклонения»).

### Не-CLI возможности (вызываются поисковой командой)

**Полный синк в quiet-режиме** — fallback поиска: любой селектор без
локальных результатов, не похожий на IP (email обслуживается отдельной
веткой поиска и сюда не доходит) и без явного запрета обновления →
полный синк + повторный локальный поиск. Единственное место неявного
запуска синка. Результат — (число клиентов, число таблиц, длительность).

**Точечный синк одного клиента** (по client_id; Loki не трогается) —
три независимые best-effort части:

1. main: строка `public.clients` по `id` (тот же состав колонок, что в
   шаге 1 CLI). main недоступен или клиент не найден → отказ, кэш не
   изменяется.
2. Таблицы клиента с его инстанса (тот же SELECT, что в шаге 2) —
   только если из `server` извлекается N > 0; сбой → таблицы не
   обновлены, остальное пишется.
3. sid'ы клиента с main: строки `public.wb_tokens` клиента с непустым
   sid, DISTINCT по (client_id, sid); сбой → sid'ы не обновлены,
   остальное пишется.

Запись — точечный upsert строк этого клиента: соседние клиенты не
затрагиваются; строки клиента, исчезнувшие из выборки, не удаляются
(их вычищает полный синк). Имя сервера в записях — исходная строка
`server` (в т.ч. `sl-0`).

## Ввод/вывод

stdout — summary (см. выше); stderr — предупреждения и ошибки, без
трейсбеков. Exit: 0 — успех, включая деградацию по инстансам; 1 —
недоступный main.

## Побочные эффекты

Сеть: PG-подключения к main и каждому инстансу фан-аута (только
SELECT); HTTP к Loki. Запись — только локальная кэш-БД. Внешние
системы не мутируются.

## Конфигурация

Env-файл (`platform/env-file.md`): `pg_<N>` — адреса инстансов;
`PG_PORT`, `PG_DB_NAME`, креды (личные `PG_MY_USER_*` приоритетнее
общих `PG_MAIN_USER_*`) — там же; `LOKI_URL` — best-effort Loki-кэш.
Отсутствие `pg_<N>` для сервера из фан-аута — сбой этого сервера
(попадает в предупреждение), не отказ команды. Кэш-БД —
`platform/store.md`. Дефолты таймаутов — решение реализации,
задокументированы в `--help`.

## Инварианты

- Каждое PG-обращение ограничено таймаутом — и установление
  соединения, и сам запрос; обращения, ждущего неограниченно, не
  существует. Числа — дефолты реализации, видны в `--help`.
- Молчащий или упавший инстанс не блокирует ни другие инстансы, ни
  завершение команды дольше своего таймаута; его данные в снапшот
  прогона не входят, что видно в предупреждении.
- Конкурентность фан-аута ненаблюдаема ничем, кроме времени: состав
  снапшота и порядок строк вывода детерминированы.
- Три таблицы снапшота переписываются целиком в одной транзакции: после
  успешного прогона в них нет ни одной строки прошлых прогонов (в
  отличие от кэша контейнеров — `specs/init.md`).
- sid без клиента в текущей выборке не пишется никогда.
- Фан-аут — только инстансы N > 0; main на spreadsheets не опрашивается.
- Все внешние обращения — чтение; команда не выполняет ни одной мутации
  в PG и Loki.
- Сбой любого инстанса не влияет ни на код выхода, ни на данные
  остальных серверов.
- Точечный синк не изменяет строки других клиентов.

## Граничные случаи и ошибки

- Все инстансы недоступны → клиенты записаны, `sl_spreadsheets` пуста,
  предупреждение перечисляет все серверы, exit 0.
- Инстанс молчит (таймаут запроса) → как прочий сбой инстанса:
  предупреждение, продолжение, общее время ограничено.
- `server` клиента — `sl-0`, пустой или нераспознанный → клиент в кэше
  есть, его таблицы не запрашиваются.
- Многострочное сообщение ошибки инстанса → в предупреждении только
  первая строка.
- Несколько токенов одного (client_id, sid) → одна строка кэша
  (DISTINCT; первичный ключ (sid, client_id)).
- Старый кэш без одной из таблиц снапшота → таблица создаётся
  bootstrap'ом до записи (self-heal), прогон успешен.
- main недоступен → ошибка без записи, exit 1 (см. «Известные
  отклонения»).
- Точечный синк: клиент не найден → отказ без записи; сбой части 2
  или 3 → частичная запись остального.

## Golden-примеры

Фикстур нет: формы всех строк вывода закреплены дословно в тексте
спеки, DDL таблиц снапшота — фикстура `platform/store.md`. Классы
закрепляются контрактными тестами реализации без живых систем (PG — за
узким интерфейсом на стороне потребителя): happy path на двух
инстансах; падение одного инстанса (warning + счётчики только с живых);
падение всех инстансов; недоступный main (текст отказа, exit 1, кэш не
изменён); orphan sid отброшен; повторный прогон с изменившейся
выборкой — полное замещение; `--quiet` (печати нет, записи выполнены);
таймаут молчащего инстанса (warning + ограниченное время завершения);
self-heal старого кэша; точечный синк — happy, «клиент не найден»,
сбой части 2, сбой части 3, клиент на sl-0.

## Известные отклонения

- **fix** — недоступный main роняет команду необработанным исключением
  (трейсбек, ненулевой код) — без симметрии с best-effort инстансов и
  с точечным синком, который отказывает тихо. Правильное поведение:
  stderr `mpu update: main (sl-0) недоступен: <причина>` без
  трейсбека, exit 1, кэш-БД не изменяется.
- **fix** — PG-сессии снапшота открываются без серверного запрета
  записи, хотя выполняются только SELECT. Правильное поведение —
  read-only сессия (`platform/readonly-default.md`).
- **fix** — у оригинала таймаутом ограничено только установление
  соединения; сам запрос таймаута не имеет — зависший инстанс блокирует
  синк неограниченно. Все обращения ограничены (см. инварианты).
- **fix** — обход инстансов у оригинала строго последовательный;
  конкурентность разрешена, наблюдаемое следствие — только время;
  порядок серверов в предупреждении фиксирован (по возрастанию).
