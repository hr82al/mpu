# mpu telegram file

Статус: к реализации (порция TF1)

## Назначение

Скачать вложение одного сообщения Telegram в локальный файл, чтобы его можно
было прочитать. Зовут, когда в выдаче `telegram search` у сообщения есть
`file` (раздел «Вложение» `telegram-search.md`): коллега прислал md-разбор,
xlsx-выгрузку или скриншот. Подручного средства нет: выдача поиска несёт
только текст и подпись, а сеанс Telegram живёт внутри `mpu`.

Сеанс, конфигурация, прокси, приведение адресата и ошибки протокола — общие,
`platform/telegram-mtproto.md`; поиск чата по названию — `telegram-ls.md`.

## CLI-контракт

```
mpu telegram file chat: X id: N
```

- `chat:` — обязателен; чат сообщения: маркированный id (поле `chat_id`
  выдачи поиска), `@username`, ссылка t.me, название или `me`.
  `TELEGRAM_DEFAULT_CHAT` не читается: файл берётся из названного чата, а не
  из умолчания отправки.
- `id:` — обязателен; идентификатор сообщения внутри чата, целое > 0 (поле
  `id` выдачи поиска).

Вариантов и форматов вывода нет. Видна агенту, исполняется без `ask` ([D.6]).

## Ввод/вывод

Файл кладётся в каталог `/tmp/mpu-telegram/` под именем
`<chat_id>-<id>-<имя>`: `chat_id` — маркированный идентификатор чата (как в
выдаче поиска), `id` — сообщения, `имя` — имя вложения по таблице ниже, в
котором `/` и NUL заменены на `_` ([D.2]). Каталога нет → создаётся с правами
0700; есть → используется как есть. Файл с тем же путём заменяется.

| Вложение сообщения | `name` | `mime` | файл? |
|---|---|---|---|
| документ с именем `разбор.md`, тип `text/markdown` | `разбор.md` | `text/markdown` | да |
| документ с именем, тип пустой | имя | `null` | да |
| документ без имени (голосовое, кружок), тип `audio/ogg` | `file-<id>` | `audio/ogg` | да |
| стикер, гифка, видео, аудио — документ с именем | имя | тип документа | да |
| фото (всегда без имени) | `photo-<id>.jpg` | `image/jpeg` (задаёт команда) | да, наибольший размер |
| документ с именем `../../x.md` | `../../x.md` | тип документа | да, на диске `.._.._x.md` |
| текст без вложения | — | — | нет |
| превью ссылки в тексте | — | — | нет |
| геоточка, контакт, опрос, кубик | — | — | нет |
| служебное сообщение (вход в чат, закреп) | — | — | нет |

Правило таблицы — одно для `telegram file` и для поля `file` выдачи поиска
(design-mpu 4).

stdout — одна строка JSON, юникод не экранируется, за ней один перевод
строки; четыре ключа в этом порядке:

- `path` — абсолютный путь записанного файла;
- `name` — имя вложения по таблице (до замены `/` и NUL);
- `size` — число байт, записанных в файл ([D.3]);
- `mime` — по таблице; строка либо `null`.

stderr при успехе пуст.

## Побочные эффекты

В Telegram — только чтение. Локально — один файл в `/tmp/mpu-telegram/` (и
сам каталог при первом вызове). Кэш-БД не трогается. Каждый вызов открывает и
закрывает сеанс Telegram.

Стенд — подменный клиент Telegram, как у тестов `search` и `send`; каталог
файлов в тестах — временный, подставленный вместо `/tmp/mpu-telegram/`. Чат
`-1000000000101` — супергруппа без имени. Ответ клиента в сценариях —

## Инварианты

- Ошибки ввода — до сети.
- Вне `/tmp/mpu-telegram/` команда не пишет ничего, при любом имени вложения.
- `size` в выводе равен размеру файла по `path` сразу после вызова.
- По `path` из вывода лежит только полностью скачанное вложение; неудачный
  вызов не меняет того, что лежало по этому пути.
- Повторный вызов с теми же аргументами даёт тот же stdout и тот же файл,
  если сообщение не менялось.
- Права Deno не расширяются: `/tmp` уже в праве записи у CLI и у `back`
  (`deno.jsonc`).
- Секреты в вывод не попадают (слой).

## Граничные случаи и ошибки

- Код 2 — ошибки ввода (F10–F12); код 1 — Telegram и слой (F6–F8, F13,
  F16, F17); 0 — файл записан.
- Каталог создать или файл записать нельзя (нет места, нет прав) → exit 1,
  stderr `telegram: не удалось записать <путь>: <причина>`; файла по пути нет.
- Rate-limit и прочий отказ протокола — по правилам слоя, exit 1.
- Размер вложения не ограничивается.

## Поле `file` в выдаче поиска

`telegram search` получает ключ `file` между `text` и `link`: `null` или
объект `{"name", "size", "mime"}` по таблице «Ввод/вывод»; `size` — размер,
заявленный Telegram (у фото — наибольшего размера). Подробно —
`telegram-search.md`, раздел «Вложение (порция TF1)».

| # | Дано | Строка | Итог |
|---|---|---|---|
| F18 | как F1 | `mpu telegram search query: "" chat: -1000000000101` | у сообщения 42: `"text": "Отписал по спеке"`, `"file": {"name": "разбор.md", "size": 1234, "mime": "text/markdown"}` |
| F19 | как F6 и F7 | то же | у сообщений 45 и 47 `"file": null` |
| F20 | как F4 | то же | у сообщения 43 `"file": {"name": "photo-43.jpg", "size": 2048, "mime": "image/jpeg"}` |
| F21 | как F18 | та же строка с `end table` | колонки таблицы прежние ([D.5]) |

## Golden-примеры

`fixtures/telegram-file/` — снимает исполнитель. Форма ответа клиента на
документ и фото снимается **до кода** живым `telegram search` по
собственному сообщению с файлом (`chat: me`); содержимое голденов —
синтетическое, как у `telegram-search`:

- `file-stdout.txt` — F1;
- `err-no-file-stderr.txt` — F6;
- `err-no-chat-stderr.txt` — F10.

Голден `fixtures/telegram-search/search-json-stdout.txt` получает ключ `file`
(раздел «Вложение» `telegram-search.md`). Каждый файл вывода оканчивается
одним переводом строки.

## Решения спецификатора

- [D.1] Отдельная команда, а не вариант `search`: поиск отвечает «какие
  сообщения», файл — «дай вложение этого сообщения»; у поиска нет адреса
  одного сообщения, у файла нет выдачи списком.
- [D.2] Имя на диске — `<chat_id>-<id>-<имя>`: префикс делает путь
  уникальным и предсказуемым (из выдачи поиска путь известен заранее). В
  `имя` `/` и NUL заменяются на `_`; другой нормализации нет — точки,
  пробелы и кириллица остаются. Фото — `photo-<id>.jpg`, документ без имени —
  `file-<id>` без расширения: тип не угадывается, он есть в `mime`.
- [D.3] `size` — из результата записи, а не из заявки Telegram: при обрыве
  они расходятся. В выдаче поиска файла ещё нет — там `size` заявленный.
- [D.4] Запись — во временный файл в том же каталоге и переименование после
  полного скачивания; при отказе временный файл удаляется (F16, F17).
- [D.5] `end table` поиска вложение не показывает: колонки — контракт
  `telegram-search.md`, а вложение нужно агенту, который читает JSON.
- [D.6] В закрытом списке публикации
  (`fixtures/mcp-server/tool-policies.json`) — в `ro`, рядом с
  `telegram search`: в Telegram команда только читает, локально пишет лишь во
  временный каталог; без публикации агент файл не получит, а он — главный
  читатель. Правка списка — в этой порции вместе с пересборкой снапшотов
  (`deno task tools:snapshot`): до пересборки дерево красное, это ожидаемо.
