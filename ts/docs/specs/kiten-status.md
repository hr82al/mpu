# mpu kiten status

Статус: черновик

## Назначение

Вся моя работа в Kaiten одной таблицей по всем доскам: карточки, где я
назначен, где списывал время и где что-то делал (комментарий,
перемещение). Ни один из трёх источников по отдельности не полон —
выдача строится их объединением. Только чтение.

## CLI-контракт

`mpu kiten status [--since 7d] [--out matrix|group|json|md|url]
[--stage X] [--board REF] [--source assigned|time|activity|touch]
[--only open|done] [--format TPL] [--time-since 365d]`

- `--since` — окно активности: `<число>{s|m|h|d}` либо unix-ts; дефолт
  `7d`.
- `--time-since` — окно суммирования колонки ВРЕМЯ, тот же формат;
  дефолт `365d`.
- `--out` — форма вывода; дефолт `matrix`.
- `--stage` — только один этап: латинский алиас
  (`queue|estimate|work|review|test|dev|preprod|done`), точное имя или
  подстрока канонического этапа (без учёта регистра).
- `--board` — ID или подстрока названия (`platform/kaiten-http.md`).
- `--source` — почему карточка в выдаче; `touch` — карточка ТОЛЬКО из
  ленты действий (не назначена, время не списывал).
- `--only` — `open` (незавершённые) | `done` (завершённые).
- `--format TPL` — строка на карточку; перекрывает `--out`.

Примеры из практики: `mpu kiten status`, `mpu kiten status --only
open`, `mpu kiten status --out json --since 30d`, `mpu kiten status
--source touch`.

## Ввод/вывод

Сбор:

1. `GET /users/current` → мой id.
2. Назначенное (источник `assigned`): `GET /cards?member_ids=<id>&
   condition=1` И `GET /cards?responsible_id=<id>&condition=1` — обе
   выборки, пагинация по `platform/kaiten-http.md`.
3. Время (источник `time`): `GET /users/<id>/time-logs?from=<начало
   --time-since, ISO UTC>&to=<сейчас, ISO UTC>`. Минуты карточки =
   сумма записей окна `--time-since` (не зависит от `--since`).
   Источником `time` карточка помечается, если есть её запись с датой
   ≥ дня начала `--since`.
4. Действия (источник `activity`): `GET /users/current/activities`,
   параметр `actions` — CSV без пробелов из шести действий:
   `card_add`, `card_move`, `card_archive`, `comment_add`,
   `card_assign_responsible`, `card_assign_member`; курсорная пагинация
   по `platform/kaiten-http.md`; потолок страниц =
   `min(12, max(1, round(окно --since в неделях)) × 3)`. Источником
   считаются события с `created` ≥ начала окна `--since`.
5. Слияние по id карточки: из нескольких версий побеждает та, у
   которой известно название колонки (карточки из time-logs и ленты
   приходят усечёнными); источники объединяются в множество.
6. Попадание в выдачу: карточка живая (condition=1 и не в архиве) ЛИБО
   день `updated` ≥ дня начала окна `--since`. Архивные видны только
   внутри окна.
7. Карточка, попавшая ТОЛЬКО из ленты и только событием `comment_add`,
   перепроверяется запросом `GET /cards/{id}/comments`: моего
   комментария нет (удалён) → строка отбрасывается; проверка не
   удалась → строка остаётся.
8. Этап — по названию колонки. Недостающие названия — из локального
   кэша справочника; доски, которых нет в кэше, дозагружаются
   (`GET /boards/{id}/columns` + запись в кэш); не удалось → этап `—`.

Этапы — конвейер и подстроки названий колонок (без учёта регистра):
Очередь (`очеред`, `бэклог`, `backlog`, `назначенн`) → Оценка
(`оцен`) → В работе (`в работе`, `разработ`, `баги`, `эскалац`) →
Ревью (`ревью`, `согласовани`) → Тест (`тестирован`, `тест`) → DEV
(`dev`, `выгрузк`, `выгружен`) → Пред-прод (`pred-prod`, `предпрод`,
`фг`) → Готово (`готово`, `выполненные`). Сопоставление идёт ОТ КОНЦА
конвейера к началу («Готово к тестированию» → Тест), а «Готово»
проверяется последним из всех; ни одна подстрока не совпала → `—`.
Env `KITEN_STAGE_MAP` (JSON: название колонки → канонический этап,
ключи без учёта регистра) перекрывает правила для своих колонок.
Колонка с подстрокой `эскалац` дополнительно даёт строке флаг
эскалации.

Строка завершена (`closed`), если state=3 (`done`) или condition=2
(архив). Сортировка: незавершённые выше; внутри — по `updated` по
убыванию. Фильтры `--stage`/`--board`/`--source`/`--only` применяются
после сбора, каждый независимо.

Формы вывода:

- `--out json` — массив строк `{id, title, url, stage, column, board,
  space, lane, state, closed, escalated, due_date, updated,
  my_minutes, sources}` (отступ 2, юникод как есть); `state` — метка
  как в `kiten-card.md`; `sources` — отсортированный массив из
  `assigned|time|activity`; пусто → `[]`.
- `--out md` — GFM-таблица `ID | ЭТАП | ВРЕМЯ | ОБНОВЛ | ДОРОЖКА |
  TITLE`. ВРЕМЯ: `{часы}ч{минуты:02}м`, без часов `{минуты}м`, 0 →
  `—`. ОБНОВЛ: `сегодня` / `вчера` / `MM.DD`, пусто → `—`. ДОРОЖКА:
  дорожка, иначе пространство, иначе доска. Экранирование ячеек — как
  в `kiten-ls.md`.
- `--out url` — `[{title}]({url})` по строке; `[`/`]` в title
  экранируются.
- `--format TPL` — плейсхолдеры `{n}` (с 1), `{id}`, `{title}`,
  `{url}`, `{stage}`, `{board}`, `{lane}`, `{due}` (`YYYY-MM-DD` или
  пусто), `{min}` (минуты числом), `{src}` (имена источников по
  алфавиту через запятую); текстовая замена, как в `kiten-ls.md`.
- `--out matrix` (дефолт) и `--out group` — человекочитаемые: матрица
  «карточка × этап» (`●` — текущий этап, печатаются только непустые
  этапы) либо секции по этапам; в строке — ID (эскалация помечена),
  время, дата обновления, место, маркеры источников (👤 назначена ·
  🕒 списывал время · 📝 комментировал/двигал), заголовок; завершённые
  приглушены. Подвал: число карточек (в работе/закрыто), сумма
  списанного времени за окно `--since` с разбивкой по ролям записей,
  счётчик touch-строк. Точная раскладка — свобода реализации. Пустая
  выдача → `(нет карточек)`.

Предупреждение о неполной ленте: если самая старая прочитанная запись
ленты новее начала окна `--since`, в stderr печатается
`mpu kiten status: лента действий прочитана только до {YYYY-MM-DD}
(предел {N} страниц); карточки, которые я лишь комментировал раньше
этой даты, могли не попасть в выдачу` — при любой форме вывода;
exit 0.

Exit: 0 — успех; 2 — ошибки ввода; 1 — ошибки API.

## Побочные эффекты

Чтение Kaiten (только GET). Дозагрузка колонок недостающих досок пишет
в локальный кэш справочника (кэш-БД).

## Конфигурация

- `KITEN_API_KEY`, `KITEN_BASE_URL` — `platform/kaiten-http.md`.
- `KITEN_STAGE_MAP` — JSON-объект «название колонки → канонический
  этап».

## Инварианты

- Строка выдачи уникальна по id карточки; `sources` непусто.
- Колонка ВРЕМЯ зависит только от `--time-since`; попадание в таблицу —
  только от живости карточки и окна `--since`.
- Фильтры сужают выдачу, не меняя состава полей строк.
- `--format` и `--out json|md|url` не печатают подвал и рамки.
- Kaiten не мутируется ни на одном шаге.

## Граничные случаи и ошибки

- Ни одной карточки → exit 0: `(нет карточек)` (matrix/group), `[]`
  (json), пустой вывод (url/format).
- Невалидный `--since` → exit 2: `mpu kiten status: --since: ожидается
  <число>{s|m|h|d} или unix-ts, получено '<значение>'` (аналогично
  `--time-since`).
- Неизвестный `--stage` → exit 2: `mpu kiten status: неизвестный этап
  '<значение>'; допустимо: queue, estimate, work, review, test, dev,
  preprod, done`.
- Неизвестное значение `--out`/`--source`/`--only` → ошибка ввода,
  exit 2.
- Некорректный JSON в `KITEN_STAGE_MAP` → stderr `mpu kiten status:
  некорректный JSON в KITEN_STAGE_MAP: <детали>` (не-объект →
  `mpu kiten status: KITEN_STAGE_MAP должен быть JSON-объектом`),
  правила по умолчанию действуют, команда работает.
- Событие ленты без вложенной карточки → строку не создаёт.
- Ошибка API → exit 1: `mpu kiten status: kaiten error: <текст>`.

## Golden-примеры

Снять при переводе в «к реализации» (свой тестовый пользователь, без
клиентских данных): `status --out json --since 30d`, `status --out md`,
`status --format '{n} {id} {stage} {min}'`, `status --stage bogus`
(ошибка, exit 2), `status --since bogus` (ошибка, exit 2).

## Известные отклонения

- **fix** — предупреждение о неполной ленте действий оригинал печатает
  только в формах matrix/group; в json/md/url/format выдача молча
  выглядит полной. Правильное поведение — предупреждать в stderr при
  любой форме (данные в stdout не смешиваются).
- **fix** — ошибки ввода `--since`/`--time-since`/`--stage` оригинал
  завершает exit 1; правильное поведение — exit 2, как у остальных
  ошибок ввода.
- **fix** — `{src}` в `--format` оригинал склеивает имена источников
  без разделителя (`activityassignedtime`); правильное поведение —
  через запятую.

## Открытые вопросы

- Перепроверка «touch-карточек с единственным comment_add» даёт +1
  запрос на каждую такую карточку без потолка; нужен ли лимит при
  широком `--since` — решить при переводе в «к реализации».
