# mpu code copies

Статус: реализовано (2026-10-15, порция CC1). Голден — `fixtures/code/copies-file.stdout.txt`.

## Назначение

Какие куски кода в этом файле скопированы и какая константа файла преобразуется по месту не один раз. Повод звать —
приёмка и рецензия файла, прежде всего теста: правило «одно знание — одно место» (`review.md`) нарушается не только
литералом. Литералы `code literals` уже видит, а копию из имён — нет: на `ChecklistClient.spec.tsx` (ozon !811)
литералы были вынесены в константы, `code literals` стал пуст, а ревьюер вручную нашёл три копии — засев памяти,
повторённый 26 раз, четыре локальные `const option = (…) => (…)`, четыре одинаковых ответа опций — и
`Number(SELLER_ID)` семь раз. Греп одинаковую строку найдёт, но не отличит копию от вложенного в неё куска, не сведёт
многострочную запись с однострочной и не поймёт, что `String(input)` двух разных функций — это не одна величина.
`code twins` отвечает на другой вопрос: тело функции и его близнецы по всему репозиторию перед правкой.

## CLI-контракт

`mpu code copies АДРЕС... [--base REF] [--limit N]`

Политика — `ro`, команда видна агенту (`fixtures/mcp-server/tool-policies.json`, внесено). Адрес, `--base`, `--limit`,
шапка, несколько адресов и репозиториев, порядок проверок адреса — как у `code literals` (`code-literals.md`, включая
«Решения по отчёту CL1»): адрес — `[РЕПОЗИТОРИЙ:]ПУТЬ` к `.ts`/`.tsx` без строки; `--base` оставляет записи, у
которых хоть одно вхождение стоит на строке, добавленной или изменённой относительно `merge-base REF HEAD` в
рабочем дереве, и печатает такую запись со всеми вхождениями; `--limit` — предел записей в каждом разделе,
по умолчанию 200. Шапка — отметка дерева без поля гарантии (абзац-исключение `platform/code-analyzer.md`
дополнен `code copies`, внесено спецификатором).

Справка живёт в коде рядом с командой. Состав: вопрос в одностроке; первый абзац — момент (приёмка и рецензия) и чем
лучше грепа и `code literals`; что считается копией и преобразованием, оба порога числом; что исключено; оба раздела;
`--base` и `--limit` с умолчанием; коды выхода; полный пример вызова с разбираемым адресом.

## Что считается

**Фрагмент** — узел синтаксиса файла одного из видов: вызов, `new`, объектный литерал, литерал массива, стрелочная
функция, функциональное выражение, объявление переменных (`const`/`let`/`var` целиком, со своим `;`). Операторы-обёртки
(`if`, `return`, оператор-выражение, блок) фрагментом не считаются: их содержимое — выражения, и они уже фрагменты.

**Не фрагмент** — вызов `describe`, `it`, `test` и их форм через точку (`it.each`, `describe.skip`, `test.only` …)
и функция, переданная таким вызову аргументом: это контейнеры тестов, а не код. Фрагменты внутри контейнера
считаются как обычно.

**Равенство фрагментов** — по последовательности лексем: лексема — то, что отдаёт сканер TypeScript (имя, ключевое
слово, знак, литерал, кусок JSX); пробелы, переводы строк и комментарии не лексемы. Многострочная запись равна
однострочной, если лексемы те же; лишняя запятая в конце — другая лексема, и фрагменты различны.

**Размер** — число лексем фрагмента.

**Копия** — группа равных фрагментов, у которой **не меньше 3 вхождений** и **не меньше 20 лексем**. Группа не
печатается, если её поглощает другая группа: у той **столько же** вхождений, она длиннее, и каждое вхождение первой
лежит внутри какого-нибудь вхождения второй. Так засев, повторённый 24 раза, печатается одной записью, а не четырьмя
(вызов, `JSON.stringify(…)`, объект внутри). Вложенный кусок, у которого вхождений **больше**, чем у объемлющего,
печатается своей записью: он повторён и вне него.

**Преобразование** — вызов `Number`, `String`, `Boolean` или `BigInt` ровно с одним аргументом-именем, когда имя
объявлено на верхнем уровне файла (`const`, `let`, `var`, имя из `import`) и не перекрыто параметром или
объявлением в объемлющей функции. В раздел попадает каждое такое преобразование, повторённое **не меньше 2 раз**:
константа хранится в одной форме, а нужна в другой — вторую форму держат одной константой. Аргумент-литерал,
выражение, свойство (`String(a.b)`) и имя параметра — не преобразования константы.

## Ввод/вывод

Шапка раздела репозитория — отметка дерева без поля гарантии. Дальше по каждому файлу, в порядке путей: строка с
путём от корня репозитория, под ней два раздела, записи — с отступом в два пробела.

**копии: N** — по строке на копию:

    ТЕКСТ ×K  строки A, B, …

`ТЕКСТ` — исходный текст первого вхождения, каждая цепочка пробельных знаков (включая переводы строк) сжата в один
пробел; длиннее 60 знаков — первые 59 и `…`. `K` — число вхождений; строки — строка начала каждого вхождения, по
возрастанию, каждая один раз. Порядок записей — по началу первого вхождения; при равном начале — более длинная
раньше.

**преобразования: N** — по строке на преобразование:

    Number(SELLER_ID) ×K  строки A, B, …

Текст вызова — как в файле. Порядок — по первой строке вхождения, при равной — в порядке появления.

После всех файлов репозитория — **не разрешено: N**, как у `code literals`. Вывод оканчивается одним переводом строки.

Только чтение; с `--base` — ещё `git merge-base` и `git diff` только для чтения.

## Конфигурация

Своей нет. Пороги 3, 20 и 2 — не ключи: они — правило, обоснованное замером выше.

## Инварианты

- Контейнеры тестов не попадают ни в один раздел ни при каком числе вхождений.
- Группа, поглощённая другой группой с тем же числом вхождений, не печатается.
- Запись «копий» — только при `K ≥ 3` и размере ≥ 20 в одном файле; между файлами копии не складываются.
- Преобразование имени параметра или перекрытого имени не печатается.
- С `--base` запись печатается целиком или не печатается.
- Порядок — детерминированный; времени в выводе нет. Команда только читает.

## Граничные случаи и ошибки

Ошибки — stderr с префиксом `mpu code copies: `, отказ — «ошибка и как исправить».

| Вход | Ожидаемое поведение |
| --- | --- |
| Адресов нет | exit 2, `нужен хотя бы один адрес файла: mpu code copies ПУТЬ.spec.tsx` |
| Адрес с номером строки (`путь:12`) | exit 2, `адрес — файл без строки: копии ищутся по всему файлу` |
| Файла нет | exit 2, `файла <путь> нет в репозитории <имя>` |
| Не `.ts`/`.tsx` | exit 2, `копии ищутся только в .ts и .tsx: <путь>` |
| `--base` не разрешается в коммит | exit 2, `базу <REF> не найти: git merge-base <REF> HEAD не ответил` |
| Файл с синтаксической ошибкой | exit 0, файл — строкой в «не разрешено», разделы по остальным адресам печатаются |
| Копий и преобразований нет | exit 0, `копии: 0`, `преобразования: 0`, `не разрешено: 0` |
| Записей в разделе больше `--limit` | exit 0, строка `усечено: показано N из M` |

## Решения по отчёту CC1 (спецификатор, 2026-10-15)

Поведение, о котором спека молчала, принято так, как реализовано:

- `--base`: запись задевает любая строка, которую занимает хоть одно вхождение, от строки начала до строки конца;
  печатаются по-прежнему строки начала.
- Текст преобразования — первое вхождение с сжатыми пробелами, без усечения.
- «Начало» в порядке копий — позиция в тексте, не строка.
- Контейнер теста — вызов, у которого корень цепочки вызываемого — имя `describe`/`it`/`test`; корень не-имя
  (`/x/.test(…)`, `foo().it(…)`) контейнером не считается.
- Константа файла — объявление верхнего уровня `const`/`let`/`var` (оператор объявления) или имя из `import`, по ответу
  разбора одного файла; `for (var N of xs)` верхнего уровня и деструктуризация в нём константой не считаются;
  деструктуризация в операторе объявления — считается.
- JSDoc внутри фрагмента — не лексема.

Живая приёмка снята спецификатором 2026-10-15 прогоном исходников ветки на обеих редакциях файла: вывод совпал с
пробой построчно (12 копий и три преобразования до ревью, 10 копий и `String(SKU) ×7` после).

Универсальный `design.md`:

| пункт | что изменил |
| --- | --- |
| 1 примитивы | два: «фрагмент файла — лексемы и место» и «группа равных фрагментов»; поглощение, оба порога и печать выводятся из групп в одном месте; преобразование — фрагмент со своим правилом отбора, а не второй обход |

| 4 кто решает | печатать ли группу, решают порог и поглощение у самой группы, не цикл печати |
