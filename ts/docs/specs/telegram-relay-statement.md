# Ретранслятор вопросов Claude Code в Telegram — постановка порции R1

Статус: черновик постановки (сценарии; спеки `platform/telegram-questions.md` и
`claude-hook-permission-request.md` пишутся по ней после согласования)

Серия R — «любое ожидание человека в любой сессии Claude Code приходит в
Telegram, и на него можно ответить оттуда». Порции: R1 — права и
AskUserQuestion (эта); R2 — свободный текст и конец хода через канал; R3 —
подтверждения `mpu ask` и чужие MCP-формы; R4 — нераспознанное ожидание
снимком окна tmux. Живые образцы — пробы 2026-10-06 (`fixtures/telegram-relay/`,
снятые payload'ы обезличены).

Реализация R1 — двумя порциями исполнителя: **R1a** — вопросы в Telegram в
ядре (`platform/telegram-questions.md`, без потребителей, тесты на голденах
Bot API); **R1b** — хук, клиент, посев, установка
(`claude-hook-permission-request.md`).

## 1. Кто и зачем

Владелец, у которого открыто несколько сессий Claude Code, хочет получать
каждый вопрос сессии о разрешении и каждый вопрос AskUserQuestion в своём чате
с ботом — с теми же вариантами, что в терминале, — и отвечать кнопкой, не
переходя между окнами.

## 2. Сценарии

Общие данные. Бот @MpuLogBot, чат владельца — `TELEGRAM_BOT_ID=111`. Сессия A:
`cwd=/home/user/mr/mp/ozon`, запущена в окне tmux `w:2` с именем `claude`.
Сессия B: `cwd=/home/user/mr/mp/sl-back`, вне tmux. Режим разрешений сессий —
`default`. Хук настроен фрагментом из §2.У.

Права:

1. **Вопрос о праве доходит с вариантами терминала.** Сессия A просит
   `Bash` с `{"command":"touch /tmp/x1.txt","description":"Create probe file"}`
   и подсказкой правила `{"toolName":"Bash","ruleContent":"touch /tmp/x1.txt"}`.
   → В терминале A показан обычный диалог. Одновременно в чат приходит
   сообщение:
   ```
   🔐 Bash · ozon · w:2 claude
   Create probe file
   touch /tmp/x1.txt
   ```
   с кнопками `Yes` · `Yes, always: Bash(touch /tmp/x1.txt)` / `No`.
2. **Ответ кнопкой решает.** В сценарии 1 владелец жмёт `Yes`. → Диалог в
   терминале A закрывается, команда выполняется, в ленте A —
   «Allowed by PermissionRequest hook». Сообщение в чате правится на
   `… ✅ Yes — из чата`, кнопок больше нет.
3. **«Всегда» записывает правило.** В сценарии 1 жмёт
   `Yes, always: Bash(touch /tmp/x1.txt)`. → Команда выполнена; правило
   `Bash(touch /tmp/x1.txt)` дописано в `.claude/settings.local.json` корня
   git-репозитория, где лежит `cwd` (так делает и терминальный вариант 2);
   следующий такой же вызов вопроса не задаёт ни в терминале, ни в чате.
4. **Отказ кнопкой.** Жмёт `No`. → Команда не выполняется, Claude получает
   отказ и продолжает ход; сообщение — `… ❌ No — из чата`.
5. **Отказ с пояснением.** Вместо кнопки владелец пишет боту текст
   `не трогай /tmp, пиши в ./out` (просто сообщением; reply не нужен —
   активный вопрос один). → Команда не выполняется,
   Claude получает отказ с этим текстом; сообщение — `… ❌ No: не трогай /tmp,
   пиши в ./out — из чата`.
6. **Ответ в терминале.** В сценарии 1 владелец нажимает `1` в терминале A.
   → Команда выполнена; сообщение в чате правится на `… ✅ решено в терминале`
   не позже чем через 2 с, кнопок нет.
7. **Опоздавшая кнопка.** После сценария 6 владелец жмёт `No` в старом
   сообщении. → Ничего не меняется; во всплывающей подсказке Telegram —
   «вопрос уже решён».
8. **Вне tmux.** Сессия B просит то же право. → Заголовок —
   `🔐 Bash · sl-back`, без окна.

AskUserQuestion:

9. **Один выбор.** Сессия A задаёт вопрос `{"question":"Какой цвет?",
   "header":"Цвет","options":[{"label":"Красный","description":"Красный
   цвет"},{"label":"Синий","description":"Синий цвет"}],"multiSelect":false}`.
   → В терминале обычный диалог; в чат:
   ```
   ❓ Цвет · ozon · w:2 claude
   Какой цвет?
   • Красный — Красный цвет
   • Синий — Синий цвет
   ```
   с кнопками `Красный` / `Синий`. Жмёт `Синий` → в ленте A
   «User answered Claude's questions: · Какой цвет? → Синий», сообщение —
   `… ✅ Синий — из чата`.
10. **Множественный выбор.** Вопрос `Какой размер?`, варианты `S`, `M`,
    `multiSelect: true`. → Кнопки `☐ S` / `☐ M` / `Готово`. Жмёт `S`, `M` —
    кнопки становятся `☑ S`, `☑ M`; жмёт `Готово` → в ленте A
    «Какой размер? → S, M». `Готово` без отмеченных — подсказка
    «отметьте хотя бы один вариант», вопрос остаётся.
11. **Свой вариант.** В сценарии 9 владелец пишет боту текст `зелёный`. → В ленте A «Какой цвет? → зелёный».
12. **Несколько вопросов в одном.** AskUserQuestion с двумя вопросами
    («Какой цвет?», «Какой размер?»). → В чате сначала первый, после ответа
    то же сообщение показывает второй (`2/2` в заголовке); ответ уходит в
    сессию только после последнего, одним решением.

Несколько сессий:

13. **По одному.** Сессия A ждёт ответа (сценарий 1), затем сессия B задаёт
    вопрос. → В чате одно сообщение с кнопками — вопрос A, внизу строка
    `ещё ждут: 1`. После ответа на A приходит **новое** сообщение с вопросом B
    (с уведомлением на телефоне), строки «ещё ждут» в нём нет.
14. **Ожидающий решён в терминале.** В сценарии 13 вопрос B решён в
    терминале B до ответа на A. → Строка `ещё ждут: 1` в сообщении A исчезает;
    после ответа на A нового сообщения нет.
15. **Два вызова в одном ходу.** Сессия A в одном ходу зовёт два Bash, оба
    под вопросом. → В чат приходит первый; второй — только после ответа на
    первый (так их задаёт сам Claude Code), как отдельное сообщение.

Сбои:

16. **Бот недоступен.** Нет сети до Telegram (или нет `TELEGRAM_BOT_TOKEN`).
    → Терминальный диалог показан как обычно и работает; сессия ничего не
    замечает. В чат ничего не приходит; повторная попытка — со следующим
    вопросом.
17. **Сервер mpu перезапущен, пока вопрос ждёт.** → Вопрос в терминале
    остаётся и решается там; сообщение в чате правится на
    `… ⌛ истёк — ответьте в терминале`, кнопок нет.
18. **Вопрос ждёт дольше срока хука** (по умолчанию 1 ч). → То же, что 17.
19a. **Текст, когда вопросов нет.** Владелец пишет боту `привет`, ни одна
    сессия не ждёт. → Бот отвечает `сейчас вопросов нет`; ничего не решено.
19. **Чужой в чате.** Пользователь с id `222` пишет боту или жмёт кнопку
    пересланного сообщения. → Ничего не решено; подсказка «не ваш вопрос»;
    владельцу ничего не приходит.

Установка (§2.У):

20. **Первая установка.** `install.sh` на машине с `claude`. → В
    `~/.claude/settings.json` появляется хук `PermissionRequest` с командой
    `mpu claude-hook permission-request`; вывод — `install: claude хук
    permission-request: вписано`. Прочие хуки и правила файла не изменены.
21. **Повторная установка.** `install.sh` второй раз. → `… : без изменений`,
    файл не переписан (время изменения то же).
22. **Хук правили руками.** Владелец сменил в своей записи `timeout` на 600.
    → Повторная установка возвращает своё значение, записей хука ровно одна;
    чужие записи `PermissionRequest` (другие команды) остаются как были.

Команда хука:

23. **Справка.** `mpu claude-hook permission-request help` → однострока
    `Как ответить на вопрос Claude Code о праве из Telegram?`; первый абзац —
    зовёт Claude Code хуком `PermissionRequest`, руками не зовут; код 0.
24. **Агенту не видна.** Список тулов MCP-сервера `mpu` команды не содержит;
    строка `["claude-hook","permission-request"]` тулом `mpu` — `вход не
    разобран: stdin — не JSON-объект`, код 0, в чат ничего не уходит.
25. **Без человека.** Хук запущен Claude Code без терминала. → Правила `mpu`
    пропускают строку без вопроса (посев `allow`), «спросить некого» нет.
26. **Мусор на входе.** stdin `[]`. → stdout пуст, stderr
    `mpu claude-hook permission-request: без решения — вход не разобран:
    stdin — не JSON-объект`, код 0; в чат ничего не уходит.
27. **Секрет рядом.** `TELEGRAM_BOT_TOKEN` неверен, Telegram отвечает 401. →
    stderr `… без решения — бот недоступен: 401 Unauthorized`; токена нет ни
    в stderr, ни в журнале `mpu log`.

## 3. Инварианты

- На один вопрос сессии приходит не больше одного решения; решение из чата,
  пришедшее после решения в терминале, ничего не меняет.
- Кнопку, решающую вопрос, может нажать только владелец (`TELEGRAM_BOT_ID`).
- В чате в каждый момент не больше одного сообщения с действующими кнопками.
- Сбой бота или сервера mpu никогда не блокирует терминальный диалог и не
  решает вопрос сам.
- Токен бота не появляется ни в чате, ни в выводе, ни в журнале.
- Подписи вариантов берутся из самого вопроса; новый вопрос с невиданными
  вариантами показывается без изменения бота.

## 4. Правила

Подписи кнопок права:

| Подсказка в вопросе | Кнопки |
|---|---|
| нет подсказок | `Yes` / `No` |
| одно правило `Bash` `touch /tmp/x1.txt` | `Yes` · `Yes, always: Bash(touch /tmp/x1.txt)` / `No` |
| два правила в одной подсказке | `Yes` · `Yes, always: Bash(a), Bash(b)` / `No` |
| две подсказки | `Yes` · по кнопке на подсказку · `No` |
| подсказка без `ruleContent` (`Read`) | `Yes, always: Read` |
| подсказка про каталог (`addDirectories`) | `Yes, always: dir /home/user/x` |
| подсказка неизвестного вида | `Yes, always: <type>` |
| подпись длиннее 60 символов | обрезана до 60 с `…`, решение то же |
| режим `acceptEdits`, `Edit` | так же: вопрос пришёл — показывается |

Заголовок:

| Сессия | Заголовок |
|---|---|
| `cwd=/a/ozon`, tmux `w:2`, окно `claude` | `🔐 Bash · ozon · w:2 claude` |
| `cwd=/a/ozon/`, вне tmux | `🔐 Bash · ozon` |
| `cwd` нет | `🔐 Bash` |
| MCP-тул `mcp__mpu__mpu` | `🔐 mpu (MCP) · ozon` |
| AskUserQuestion, `header: Цвет` | `❓ Цвет · ozon` |
| AskUserQuestion без `header` | `❓ Вопрос · ozon` |
| 2-й из 3 вопросов | `❓ Цвет 2/3 · ozon` |

Исход сообщения:

| Что случилось | Последняя строка сообщения |
|---|---|
| кнопка `Yes` | `✅ Yes — из чата` |
| кнопка «всегда» | `✅ Yes, always: … — из чата` |
| кнопка `No` | `❌ No — из чата` |
| текст боту на вопрос о праве | `❌ No: <текст> — из чата` |
| ответ на AskUserQuestion | `✅ <ответ> — из чата` |
| решено в терминале | `✅ решено в терминале` |
| сервер перезапущен / срок хука вышел | `⌛ истёк — ответьте в терминале` |

## 5. Вывод — примеры

Хук отвечает Claude Code одной строкой в stdout, код выхода всегда 0:

```
{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}
{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow","updatedPermissions":[{"type":"addRules","rules":[{"toolName":"Bash","ruleContent":"touch /tmp/x1.txt"}],"behavior":"allow","destination":"localSettings"}]}}}
{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"deny","message":"не трогай /tmp, пиши в ./out"}}}
{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow","updatedInput":{"questions":[…],"answers":{"Какой размер?":"S, M"}}}}}
```

Без решения (терминал, сбой, срок) — stdout пуст, stderr одна строка:

```
mpu claude-hook permission-request: без решения — решено в терминале
mpu claude-hook permission-request: без решения — бот недоступен: <причина>
mpu claude-hook permission-request: без решения — сервер mpu не отвечает
```

## 6. Границы

- Режимы `auto`, `plan`, `bypassPermissions`: Claude Code вопроса не задаёт —
  в чат ничего не приходит.
- Не переключает режим сессии (варианта «switch to auto mode» в чате нет).
- Свободный текст сессии, конец хода, MCP-формы, `mpu ask` в терминале — не
  R1.
- Текст команды уходит в Telegram как есть: что видно в терминальном диалоге,
  то видно и в чате.
- Сообщение длиннее предела Telegram усекается с `…`; полный текст — в
  терминале.
- Не совместим с официальным Telegram-плагином Claude Code на том же токене:
  у бота один читатель.
- История вопросов не хранится; после перезапуска сервера прежние вопросы не
  переспрашиваются.

## 7. Свойства решения

- Решение доставляется сессии не позже 2 с после нажатия; само нажатие
  подтверждается сразу (кнопка перестаёт крутиться, подсказка — меньше чем
  через 1 с): Telegram отказывает подтверждению, пришедшему поздно
  (`400 query is too old`, снято 2026-10-06).
- Повторная доставка того же нажатия Telegram'ом не даёт второго решения.
- Ожидание вопроса не занимает исполнителей строк `mpu` и не мешает другим
  строкам.
- Установка идемпотентна: повторный прогон — «без изменений», байты файла те
  же.
