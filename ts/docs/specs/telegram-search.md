# mpu telegram search

Статус: к реализации

## Назначение

Найти сообщения **по содержимому**: без `--chat` — по всем диалогам, с `--chat`
— внутри одного чата. Сеанс, конфигурация, прокси и приведение адресата — общие,
`platform/telegram-mtproto.md`; поиск чата по названию (вторая попытка резолва) —
`telegram-ls.md`.

Ищутся сообщения, а не чаты: адресатов и их идентификаторы даёт `telegram ls`.

## CLI-контракт

```
mpu telegram search [QUERY] [--chat X] [--from Y] [--limit N] [--table]
```

- `QUERY` — необязателен. Пустой (отсутствует либо пустая строка) допустим
  **только** вместе с `--chat`: это история чата без текстового фильтра.
- `--chat X` — искать только в этом чате. Строка приводится общим резолвом
  адресата; отказ по названию говорит «чат».
- `--from Y` — оставить только сообщения этого отправителя. Строка приводится
  тем же резолвом; отказ по названию говорит «отправителя».
- `--limit N` — целое 1..500, по умолчанию 50. Ограничивает число сообщений в
  выдаче, а не число просмотренных.
- `--table` — человекочитаемая таблица вместо JSON.

`TELEGRAM_DEFAULT_CHAT` подкоманда **не читает**: значение по умолчанию есть у
отправки, а у поиска умолчание — «по всем диалогам».

Примеры: `mpu telegram search 'выгрузка' --chat me`;
`mpu telegram search --chat 'Команда' --from @ivan --limit 20 --table`.

## Ввод/вывод

Два режима поиска, различаются наличием `--chat`:

- **внутри чата** (`--chat` задан) — `messages.search` в пределах чата; `--from`
  здесь фильтр серверный; пустой `QUERY` даёт историю чата;
- **глобально** (`--chat` не задан) — `messages.searchGlobal`; непустой `QUERY`
  обязателен. Фильтра по отправителю у глобального поиска нет, поэтому `--from`
  без `--chat` — фильтр на стороне команды поверх глобальной выдачи: она
  просматривается по порядку, отбираются сообщения нужного отправителя, отбор
  прекращается на `--limit` совпадений либо на потолке **1000 просмотренных**
  сообщений («Граничные случаи»).

Дефолтный вывод — **JSON-массив**, отступ 2, юникод не экранируется, за массивом
один перевод строки. Пустая выдача — `[]`. Порядок — как отдал сервер: от новых
сообщений к старым.

Каждый элемент — семь ключей в этом порядке:

- `id` — идентификатор сообщения внутри его чата (число);
- `chat_id` — маркированный идентификатор чата сообщения: канал или супергруппа
  `−(10¹² + raw)`, базовая группа `−raw`, пользователь или бот `raw`. Значение
  пригодно как `--chat` без правки;
- `chat_title` — название чата: у группы и канала — название, у пользователя и
  бота — отображаемое имя (имя, при наличии — через пробел фамилия). Название
  не пришло — пустая строка, не `null`;
- `sender` — отображаемое имя отправителя по тем же правилам; Telegram его не
  отдал (анонимный админ, сообщение от имени канала) → `null`;
- `date` — время отправки в UTC, ISO 8601 со смещением `+00:00` и без долей
  секунды: `2026-08-16T07:54:28+00:00`. Времени нет → `null`;
- `text` — текст сообщения либо подпись вложения; ни того ни другого (например,
  файл без подписи) → пустая строка, не `null`;
- `link` — ссылка на сообщение: супергруппа или канал с именем пользователя →
  `https://t.me/<username>/<id>`, супергруппа или канал без имени →
  `https://t.me/c/<raw>/<id>`, где `raw` — немаркированный идентификатор. Для
  пользователя, бота и базовой группы публичной ссылки не существует → `null`.

Ключи присутствуют всегда; отсутствующее значение — `null` (либо пустая строка
там, где это сказано выше), а не пропуск ключа.

`--table` печатает колонки `DATE`, `CHAT`, `SENDER`, `TEXT` в этом порядке и
завершает вывод строкой-итогом `(N messages)`. Пустая выдача — одна строка
`(ничего не найдено)`, без счётчика. Обрамление таблицы (рамка, разделители,
ширины по содержимому) — оформление, не контракт: сравнивается структурно.

Предупреждения (потолок скана) идут в stderr, данные — в stdout.

## Побочные эффекты

Только чтение: ни сообщений, ни файлов, ни записей в кэш-БД. Каждый вызов
открывает и закрывает сеанс Telegram.

## Конфигурация

Своей нет; всё — из `platform/telegram-mtproto.md`. `TELEGRAM_DEFAULT_CHAT` не
читается.

## Инварианты

- Подкоманда ничего не меняет: повторный вызов с теми же аргументами даёт тот же
  результат, если не изменилась переписка.
- Ошибки ввода — до сети: сочетания аргументов, запрещённые контрактом, и
  диапазон `--limit` проверяются без единого обращения к Telegram.
- Длина выдачи не превышает `--limit` ни в одном режиме.
- `chat_id` из выдачи пригоден как `--chat`: значение, напечатанное здесь, можно
  без изменений передать обратно.
- JSON — единственный формат по умолчанию, `--table` — единственная
  альтернатива; третьего нет.
- Секреты в вывод не попадают (слой).

## Граничные случаи и ошибки

- Пустой `QUERY` без `--chat` → exit 2 до сети, одной строкой: `telegram: нужен
  текст запроса или --chat (пустой глобальный поиск запрещён)`.
- `--from` без `--chat` при пустом `QUERY` → exit 2 до сети: `telegram: --from
  без --chat требует текст запроса (глобальный поиск по отправителю — только с
  текстом)`.
- `--limit` вне 1..500 → отказ разбора аргументов, exit 2 до сети, одной
  строкой: `mpu telegram search: --limit вне диапазона 1..500: <значение>`.
- `--from` без `--chat`, просмотрен потолок в 1000 сообщений, а совпадений
  меньше `--limit` → в stderr одна строка `telegram: скан остановлен на 1000
  сообщениях; более старые совпадения не показаны`, найденное печатается,
  exit 0. Потолок не достигнут — предупреждения нет.
- `QUERY` из одних пробелов → непустой запрос, уходит на сервер: пробел —
  значимый символ поиска.
- Ничего не найдено → `[]` (или `(ничего не найдено)` с `--table`), exit 0. Не
  ошибка.
- Адресат `--chat` или `--from` не резолвится → по правилам слоя и
  `telegram-ls.md`: exit 1, «чат» для `--chat`, «отправителя» для `--from`.
- Отказ Telegram — по правилам слоя: rate-limit и прочий отказ протокола,
  exit 1.

## Golden-примеры

`fixtures/telegram-search/`. Формы сняты живым прогоном рабочей версии на
собственном аккаунте, **содержимое синтетическое**: идентификаторы, названия,
имена и тексты вымышлены, состав и число полей сохранены.

- `search-json-stdout.txt` — три сообщения: супергруппа с именем пользователя
  (ссылка вида `t.me/<username>/<id>`), канал без имени (ссылка `t.me/c/…`,
  `sender: null` — пост от имени канала), личная переписка (`link: null`,
  пустой `text`).
- `search-empty-stdout.txt` — ничего не найдено, `[]`.
- `search-empty-table-stdout.txt` — то же с `--table`.
- `err-empty-query-stderr.txt` — вызов без `QUERY` и `--chat`, exit 2.
- `err-from-without-chat-stderr.txt` — `--from` без `--chat` и без `QUERY`,
  exit 2.
- `err-limit-stderr.txt` — `--limit 0`, exit 2. Голден **нормализован**: рабочая
  версия печатает многострочную рамку разбора флагов, воспроизводить которую
  запрещено, поэтому здесь одна строка требуемого вида.
- `warn-scan-cap-stderr.txt` — предупреждение о потолке скана.

Голдена на непустой `--table` нет намеренно: ширины колонок считаются по
содержимому, и побайтовое сравнение проверяло бы оформление.

Каждый файл вывода оканчивается одним переводом строки.

## Известные отклонения

- **fix** — ошибки ввода прежняя реализация завершает кодом 1 и проверяет
  запреты пустого глобального поиска уже после подключения к Telegram.
  Правильно — код 2 и проверка до сети; тексты этих двух ошибок неизменны.
- **fix** — `link` прежняя реализация строит по имени пользователя любого чата,
  включая личную переписку: получается `https://t.me/<username>/<id>`, ссылка,
  которая ведёт не на сообщение (у пользователей публикаций нет). Правильно —
  ссылка только у супергруппы и канала, иначе `null` (замер живым прогоном
  2026-08-16: `--chat me` даёт ссылку на собственное имя пользователя).
- **fix** — клиентский фильтр `--from` без `--chat` прежняя реализация молча
  обрывает на потолке скана: выдача короче `--limit` неотличима от «совпадений
  больше нет». Правильно — предупреждение в stderr.
- **fix** — текст отказа по диапазону `--limit` прежняя реализация берёт у
  библиотеки разбора флагов: `0 is not in the range 1<=x<=500`, по-английски и в
  её словах; остальные тексты команды русские. Правильно — своя строка, как в
  голдене.
- **preserve** — потолок клиентского фильтра — 1000 просмотренных сообщений.
  Фильтра по отправителю у глобального поиска Telegram нет, а без потолка вызов
  с редким отправителем вычерпывал бы выдачу неограниченно.
- **preserve** — итоговая строка таблицы англоязычная (`(N messages)`), тогда
  как пустая выдача сообщается по-русски: та же пара, что у `ls`, и та же
  причина — строка разошлась как признак конца вывода.
