# mpu api wb-cards-reset — полный проход загрузчика карточек

**Статус:** к реализации (2026-08-28). Контракт неймспейса — `api.md`,
обвязка — `platform/slback-http.md`.

## Назначение

Вторая из трёх кастомных групп остатка `api`, одна команда. Своя механика —
**резолв селектора до sid**, включая прямой режим в обход резолва.

Зачем нужна: маркетплейс не обновляет отметку времени карточки при изменении
одной лишь склейки, поэтому инкрементальный проход по курсору переклеенные
карточки пропускает, и новая склейка подтягивается лишь на еженедельном полном
проходе. Команда сбрасывает курсор загрузчика в пустое значение — ближайший
прогон делает полный перечит с актуальной склейкой.

```
mpu api wb-cards-reset СЕЛЕКТОР [--sid SID] [--client-id ID] [-p|--print]
```

## Путь и тело, снятые с объекта

```
POST /admin/wb-loader/loaders/<sid>/cards/v1/reset
body {"state": {"cursor": null}}
```

Главный сервер проксирует `/admin/wb-loader/<хвост>` в загрузчик, а тот
маршрутизирует по sid на инстанс-владельца. Запись гейтится ролями на стороне
сервера — отказ приходит оттуда, локальной проверки ролей нет и заводить её не
надо.

## Механика резолва

Загрузчик ключуется **по sid**; идентификатор клиента и сервер для него
косметика. Отсюда два режима:

1. **Прямой** — если задан `--sid` **или** сам селектор имеет форму sid.
   Резолв не выполняется вовсе, кэш не читается.
2. **Через кэш** — иначе селектор резолвится как в `mpu search` (клиент,
   таблица, заголовок). Нашлось несколько sid — отказ с требованием `--sid`,
   а не выбор первого.

## Инварианты

1. **Прямой режим не трогает кэш.** Проверяется тем, что команда работает при
   недоступном кэше, а не тем, что «не звала» (замер порции 78: остановленная
   база доказывает границу, подставная — лишь намерение).

2. **Неоднозначность — отказ, а не выбор.** Несколько sid у селектора → код 2
   с перечнем и требованием `--sid`. Молчаливый выбор первого недопустим:
   сброс уйдёт не тому кабинету.

3. **`--print` ничего не выполняет.** Печатает эквивалентный вызов и
   завершается; ни одного запроса ни к кэшу-владельцу, ни к серверу сверх
   резолва.

4. **Тело фиксировано.** `{"state": {"cursor": null}}` — не собирается из
   опций, своего `--body` у команды нет.

## Граничные случаи и ошибки

- селектор не резолвится → код 2 с перечнем кандидатов (общий путь);
- несколько sid, `--sid` не задан → код 2 (инвариант 2);
- сервер отказал (роли, недоступный инстанс) → код 1, тело ответа в выводе;
- базовый адрес не настроен → код 1 с указанием ключа.

## Проверка — только на локальном стенде

Как и весь `api` (указание владельца 2026-08-28). Ограничение стенда назвать
заранее: загрузчика на нём нет (`mp-wb-loader-main-app` недостижим — видно в
логах главного сервера), поэтому успешный сброс живьём **непроверяем**.
Проверяемо: резолв, оба режима, отказ на неоднозначности, `--print`, форма
запроса до отправки и текст отказа сервера.

Что непроверяемо — говорить прямо, а не выдавать за проверенное.

## Приёмка

- прямой режим по `--sid` и по sid-селектору: кэш не открывается (проверять
  остановленным кэшем);
- селектор с несколькими sid → код 2, перечень;
- `--print` не отправляет запроса;
- путь и тело совпадают со снятыми дословно.
