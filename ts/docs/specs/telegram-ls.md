# mpu telegram ls

Статус: к реализации

## Назначение

Найти адресата: без запроса — последние диалоги, с запросом — поиск по
контактам и глобальному каталогу. Отсюда же берут числовой id или имя
пользователя, чтобы указать их в других подкомандах. Сеанс, конфигурация,
прокси и приведение адресата — общие, `platform/telegram-mtproto.md`.

Вместе с этой подкомандой едет **поиск чата по названию** — та часть резолва,
которую платформенный слой явно оставил ей (см. «Резолв по названию»).

## CLI-контракт

```
mpu telegram ls [QUERY] [--limit N] [--table]
```

- `QUERY` — необязателен. Отсутствует или пустая строка → последние диалоги.
  Непустой → серверный поиск.
- `--limit N` — целое 1..500, по умолчанию 50.
- `--table` — человекочитаемая таблица вместо JSON.

Адресата подкоманда не принимает: `--chat` здесь нет, `TELEGRAM_DEFAULT_CHAT`
не читается.

## Ввод/вывод

Дефолтный вывод — **JSON-массив**, отступ 2, юникод не экранируется, за
массивом один перевод строки. Пустая выдача — `[]`.

Каждый элемент — четыре ключа в этом порядке:

- `id` — маркированный идентификатор чата: канал или супергруппа `−(10¹² +
  raw)`, базовая группа `−raw`, пользователь или бот `raw`. Значение пригодно
  как адресат других подкоманд без правки.
- `title` — название чата: у пользователя и бота — отображаемое имя, у группы и
  канала — название.
- `kind` — один из `user`, `bot`, `group`, `channel`, `unknown`.
- `username` — имя пользователя без `@`; у чата без имени — `null`.

Ключи присутствуют всегда; отсутствующее значение — `null`, а не пропуск ключа.

Порядок: без `QUERY` — порядок диалогов, как их отдал сервер (недавние
раньше); с `QUERY` — порядок ответа сервера, с дедупом по `id`, где побеждает
первое вхождение.

`--table` печатает те же данные колонками `ID`, `KIND`, `USERNAME`, `TITLE` в
этом порядке и завершает вывод строкой-итогом `(N dialogs)`. Пустая выдача —
одна строка `(нет диалогов)`, без счётчика. Обрамление таблицы (рамка,
разделители, ширины колонок по содержимому) — оформление, не контракт: оно
сравнивается структурно, а не побайтово, как и рамки ошибок разбора флагов.

## Побочные эффекты

Только чтение: ни сообщений, ни файлов, ни записей в кэш-БД. Каждый вызов
открывает и закрывает сеанс Telegram.

## Конфигурация

Своей нет; всё — из `platform/telegram-mtproto.md`.

## Резолв по названию

Строка, которую платформенный слой не свёл к `me`, числовому id, имени
пользователя, ссылке `t.me` или телефону, ищется здесь — по названию чата, тем
же серверным поиском, что и `ls` с запросом: контакты и глобальный каталог,
первые 50 кандидатов, сравнение без учёта регистра, точные совпадения
приоритетнее подстрочных.

- ровно одно совпадение → это и есть адресат;
- несколько → exit 1: `telegram: под название '<название>' подходит несколько
  чатов: '<title>' → id <id>; …; попробуй: указать адресата по id или
  @username`. Кандидаты перечисляются в порядке выдачи поиска;
- ни одного → exit 1: `telegram: не удалось найти <что> '<цель>': <причина>;
  попробуй: mpu telegram ls '<название>' и укажи id или @username`, где
  `<что>` — «чат» для адресата и «отправителя» для фильтра по автору.

Этой возможностью пользуются `send`, `status` и `search`; сама `ls` её не
вызывает — она и есть её поверхность.

## Инварианты

- Подкоманда ничего не меняет: повторный вызов с теми же аргументами даёт тот
  же результат, если не изменились сами диалоги.
- JSON — единственный формат по умолчанию, `--table` — единственная
  альтернатива; третьего нет.
- `id` из выдачи пригоден как адресат: значение, напечатанное здесь, можно без
  изменений передать в `--chat`.
- Секреты в вывод не попадают (слой).
- Дедуп по `id` не меняет порядок оставшихся элементов.

## Граничные случаи и ошибки

- `--limit` вне 1..500 → отказ разбора аргументов, exit 2 до сети, одной
  строкой: `mpu telegram ls: --limit вне диапазона 1..500: <значение>`.
- Пустая выдача → `[]` (или `(нет диалогов)` с `--table`), exit 0. Не ошибка.
- `QUERY` из одних пробелов → трактуется как непустой запрос и уходит на
  сервер: пробел — значимый символ поиска, а не пустота.
- Отказ Telegram — по правилам слоя: rate-limit и прочий отказ протокола,
  exit 1.

## Golden-примеры

`fixtures/telegram-ls/`, сняты с рабочей версии на собственном аккаунте.
**Обезличены полностью**: идентификаторы заменены на синтетические, названия и
имена пользователей — на вымышленные, состав и число полей сохранены.

- `ls-json-stdout.txt` — три диалога разных видов, JSON.
- `ls-empty-stdout.txt` — пустая выдача, `[]`.
- `ls-empty-table-stdout.txt` — пустая выдача с `--table`.
- `err-limit-stderr.txt` — `--limit 0`, exit 2. Голден **нормализован**: рабочая
  версия печатает многострочную рамку разбора флагов, воспроизводить которую
  запрещено, поэтому здесь одна строка требуемого вида.

Голдена на непустой `--table` нет намеренно: ширины колонок считаются по
содержимому, и побайтовое сравнение проверяло бы оформление, а не поведение.

Каждый файл вывода оканчивается одним переводом строки.

## Известные отклонения

- **fix** — ошибки ввода прежняя реализация оформляет общим многострочным
  форматом ошибок разбора флагов. Контракт — факт отказа, код 2 и текст
  причины одной строкой; рамка не воспроизводится.
- **fix** — текст отказа по диапазону `--limit` прежняя реализация берёт у
  библиотеки разбора флагов: `0 is not in the range 1<=x<=500`, по-английски и
  в её словах. Это не авторский контракт, а побочный вывод инструмента, и
  остальные тексты команды — русские. Правильно — своя строка, как в голдене.
- **preserve** — поиск по названию смотрит только первые 50 кандидатов
  серверной выдачи: канонические адресаты — id и имя пользователя, а лимит тот
  же, что у `ls` по умолчанию.
- **preserve** — итоговая строка таблицы англоязычная (`(N dialogs)`), тогда
  как пустая выдача сообщается по-русски. Расхождение видно пользователю, но
  строка уже разошлась по чужим скриптам как признак конца вывода.
