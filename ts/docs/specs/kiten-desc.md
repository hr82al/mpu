# mpu kiten desc

Статус: не реализовано — сверено 2026-09-10: `mpu kiten desc --help` — нет такой команды. Спека: к реализации (2026-09-10 — постановка по живому случаю: описание двух карточек пришлось
заменять прямым вызовом API, потому что команды нет, хотя справочник по `mpu kiten` её уже
описывает. Факты ниже — из того прогона: запрос, код ответа, чтение обратно. Голдены ещё не сняты,
см. «Открытые вопросы»)

## Назначение

Заменить описание карточки Kaiten целиком. Читающий аналог уже есть — `mpu kiten card <sel> --md`.

Зачем отдельная команда, а не «поправить в браузере»:

- **веб-редактор Kaiten экранирует markdown при вставке**: `- [ ]` превращается в `* \[ \]`,
  `~6 ч` — в `\~6 ч`, ломаются таблицы и ссылки. Через API текст уходит как есть — проверено
  2026-09-10 чтением обратно: отправленное и прочитанное совпали байт в байт, экранирования нет;
- описание карточки — это постановка задачи, её правят вместе с MR и чек-листом, из терминала, по
  файлу; ходить ради этого в браузер значит терять markdown, см. выше.

Обвязка HTTP — `platform/kaiten-http.md`.

## CLI-контракт

`mpu kiten desc SELECTOR (-m TEXT | -F PATH) [--dry-run] [--force]`

- `SELECTOR` — селектор карточки (`platform/kaiten-http.md`, «Селектор карточки»).
- `-m/--message TEXT` либо `-F/--body-file PATH` — **ровно один** источник текста; `-F -` — весь
  stdin. Та же пара флагов и то же правило, что у `mpu kiten comment` и `mpu mr describe`: оператор
  не должен помнить, у какой команды какой флаг.
- `--dry-run` — прочитать карточку, показать построчный дифф «было → станет», ничего не записывать.
- `--force` — записать, даже если описание изменилось с момента чтения (см. «Инварианты»).

Живые сценарии: `mpu kiten desc 69746549 -F ~/tmp/desc.md --dry-run`;
`mpu kiten desc 69746549 -F ~/tmp/desc.md`; `cat desc.md | mpu kiten desc 69746549 -F -`.

## Ввод/вывод

HTTP-граница:

- `GET /cards/{id}` — читается ДО записи: текущее `description` (для диффа) и `updated` (для защиты
  от одновременной правки);
- `PATCH /cards/{id}` body `{"description": <TEXT>}` — замена. Ответ 200; проверено 2026-09-10 на
  двух карточках;
- `GET /cards/{id}` — повторное чтение ПОСЛЕ записи: команда сверяет, что описание легло тем
  текстом, что отправлен (см. «Инварианты»).

Вывод при успехе, одна строка в stdout:

```
ok: описание заменено (952 → 1 486 байт) · https://btlz.kaiten.ru/69746354
```

`--dry-run` печатает унифицированный дифф и строку `dry-run: запись не выполнялась`, exit 0.
Текст без изменений — `ok: описание не изменилось`, без `PATCH`.

## Побочные эффекты

Одна мутация — `PATCH /cards/{id}` с полем `description`. Других полей карточки команда не трогает:
тело запроса несёт только `description`, чтобы замена не могла задеть колонку, владельца или
свойства. Локального состояния нет.

## Конфигурация

Ключи env-файла — те же, что у всей группы: `KITEN_API_KEY` (обязателен), `KITEN_BASE_URL`
(по умолчанию `https://btlz.kaiten.ru`).

## Инварианты

- **Замена целиком, дописывания нет.** Описание уходит одним полем; «добавить абзац в конец»
  делается чтением через `card --md`, правкой файла и этой командой. Отдельный режим дописывания
  не заводится: он тащит за собой вопрос «куда именно», а ответ на него всегда — «в файле».
- **Одновременная правка не затирается молча.** Команда запоминает `updated` при чтении и
  перечитывает карточку непосредственно перед `PATCH`: изменилось — отказ с названием, кто и когда
  менял, exit 1. `--force` снимает защиту. Причина конкретная: описание — общий текст команды, и
  замена целиком по устаревшей копии тихо стирает чужую правку. У Kaiten нет условной записи по
  версии, поэтому защита — перечитывание, а не заголовок запроса.
- **Записанное проверяется чтением.** После `PATCH` команда читает карточку и сравнивает
  описание с отправленным (без учёта концевых пробелов и перевода строки). Разошлось — exit 1 с
  диффом. Код ответа сам по себе доказательством не считается.
- **Повтор безопасен.** Замена идемпотентна: тот же текст даёт то же состояние. Поэтому
  таймаут на заголовках ответа (см. «Граничные случаи») команда вправе повторить сама — в отличие
  от `comment`, где повтор задваивает запись.
- **Чекбоксы в описании — предупреждение, не отказ.** Если в тексте есть строки `- [ ]` /
  `- [x]`, в stderr уходит одна строка: Kaiten рисует их текстом, кликнуть нельзя, живые отметки —
  `mpu kiten checklist`. Запись при этом выполняется: чек-лист в описании бывает осознанным
  снимком состояния, и это решение оператора.

## Граничные случаи и ошибки

| Случай | Поведение | Exit |
| --- | --- | ---: |
| ни `-m`, ни `-F` | отказ до сети, названы оба флага | 2 |
| заданы оба | отказ до сети | 2 |
| `-F` на несуществующий файл | отказ до сети, назван путь | 2 |
| пустой текст (0 байт или только пробелы) | отказ до сети: очистка описания — отдельное намерение, случайно её не делать; явно — `-m ''` не принимается, для очистки открытый вопрос | 2 |
| селектор без числового сегмента | отказ до сети | 2 |
| карточка недоступна | Kaiten отвечает 403 с пустым телом (`kiten-live-probe`), команда называет id | 1 |
| описание изменилось между чтением и записью | отказ, назван `updated` и автор последней правки; `--force` пишет | 1 |
| прочитанное после записи не совпало | exit 1, дифф в stderr | 1 |
| таймаут «no response headers» на `GET` или `PATCH` | повтор с паузой, до пяти попыток; исчерпано — отказ, в сообщении сказано, что запись **могла пройти** и её надо проверить `card --md` | 1 |

⚠️ Последняя строка — не теория. 2026-09-10 Kaiten в течение часа ронял больше половины запросов с
`kaiten error: no response headers within 3000ms`; повторять вручную пришлось каждую мутацию, а
перед каждым повтором — читать карточку, потому что таймаут на заголовках не означает, что запись
не прошла.

## Golden-примеры

Не сняты. Снимать на тестовой карточке (как для `checklist` и `comment`, память
`kiten-live-probe-findings`: 68757706 / 68757875): успешная замена, `--dry-run`, «не изменилось»,
отказ по одновременной правке, предупреждение о чекбоксах. Ветку таймаута воспроизвести нельзя —
она закрывается подменой транспорта в наборах.

## Известные отклонения

- **Справочник опередил код.** Справочник по `mpu kiten` уже описывает `desc` как существующую
  команду (раздел «desc — заменить описание карточки»), а `mpu kiten desc` отвечает
  `No such command 'kiten desc'`. Реализация этой спеки закрывает расхождение; до неё справочник
  вводит в заблуждение.
- **Таймаут транспорта — 3 с на заголовки ответа.** Для чтения этого хватает, для мутаций Kaiten
  под нагрузкой — нет. Вопрос общий для всей группы, а не только для `desc`, поэтому здесь он
  записан отклонением, а решается в `platform/kaiten-http.md`.

## Открытые вопросы

1. **Очистка описания.** Нужна ли вообще, и каким флагом (`--clear`)? Сейчас пустой текст —
   отказ, чтобы пустой файл не стёр постановку.
2. **Таймаут для мутаций.** Поднять ли общий таймаут заголовков для `PATCH`/`POST` группы или
   оставить 3 с плюс повтор? Повтор безопасен у `desc`, `checklist add` и `check`, но **не** у
   `comment` — там увеличение таймаута лучше повтора.
3. **Голдены** — см. раздел выше; снимаются живым прогоном при реализации.
