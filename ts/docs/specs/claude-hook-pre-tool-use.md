# mpu claude-hook pre-tool-use

Статус: спека, код не начат (порция P1). Постановка — у хоста, вопросы по ней
закрыты ответом хоста 2026-10-05.

## Назначение

Claude Code перед каждым вызовом инструмента зовёт хук `PreToolUse`. Команда
отвечает ему решением правил самого `mpu` (`platform/policy.md`) для вызова
`mpu` агентом — Bash-строкой `mpu …` или MCP-тулом `mcp__mpu__mpu`:
`allow` — Claude Code исполняет без своего вопроса, `deny` — отказывает. Где
правило говорит `ask`, где вызов не «одна простая строка `mpu`» и при любом
сомнении — решения нет, и Claude Code проверяет вызов как обычно.

Зачем: правила разрешений живут в одном месте — у `mpu`. Без хука их пришлось
бы повторять правилами `permissions` настроек Claude Code, которые видят
только начало текста команды и расходятся с правилами `mpu` при первой правке.

## CLI-контракт

```
mpu claude-hook pre-tool-use
```

- Аргументов и ключей нет. Весь вход — stdin, JSON-объект payload'а хука.
- Политика объявления — `ro`: команда ничего не пишет. Отсюда посев `allow`
  общим правилом (`policy.md`, «Посев»), отдельной строки в таблице посева
  нет. Запуск из хука (без tty) получает решение, а не «спросить некого» (S23).
- Тулом MCP-сервера не публикуется: в закрытом списке
  `fixtures/mcp-server/tool-policies.json` её нет (как у
  `claude-hook notification`), а переводчик `mcp-objects.md` публикует два
  тула (`help`, `mpu`). Тул `mpu` со словами `["claude-hook",
  "pre-tool-use"]` вызвать можно: stdin у MCP нет — `вход не разобран: stdin —
  не JSON-объект`, код 0 (S22).
- Исполняет строку ядро (сервер строк), а не исполнитель: `run` объявления
  отвергает вызов, как у `image sync` («строку claude-hook pre-tool-use
  исполняет ядро, не исполнитель»). [D.1]
- Код выхода всегда 0 — свойство всей команды вместе с клиентом (см.
  «Клиент»). Кода 2 (блокировка вызова в Claude Code) нет ни в одном исходе.

### Справка (S21)

`mpu claude-hook pre-tool-use --help` и `… help` — справка листа, код 0.
Требования к тексту (`registry.md`, «Что говорит справка»; текст живёт в коде
рядом с объявлением):

- однострока: `Какое решение правил mpu у вызова инструмента Claude Code?`;
- первый абзац — когда зовут: звать не руками; её зовёт Claude Code хуком
  `PreToolUse` на Bash `mpu …` и на `mcp__mpu__mpu`; чем лучше правил
  `permissions` настроек — одно место правил, у `mpu`, и решение по пути
  строки, а не по началу текста;
- дальше состав: вход (stdin — payload), три исхода (`allow`/`deny` JSON в
  stdout, без решения — строка в stderr), код всегда 0, фрагмент настроек
  (ниже), пример `mpu claude-hook pre-tool-use < payload.json`.

Голден справки снимает исполнитель прогоном, хост сверяет с этим списком.

### Фрагмент настроек

Вписывает человек в `~/.claude/settings.json` (команда настройки не правит и
в установку не входит). Голден — `fixtures/claude-hook-pre-tool-use/
settings-fragment.json`:

```json
{"hooks":{"PreToolUse":[{"matcher":"Bash|mcp__mpu__mpu",
  "hooks":[{"type":"command","command":"mpu claude-hook pre-tool-use","timeout":10}]}]}}
```

Matcher `Bash` ставит хук на **каждый** Bash-вызов агента, поэтому фрагмент
вписывается только после установки версии `mpu`, в которой команда есть
(проверка: `mpu claude-hook pre-tool-use --help` — код 0). Прежний клиент
отвечает на незнакомую строку кодом 2, а это блокировка всех вызовов Bash.

## Ввод/вывод

### Ввод

Payload `PreToolUse` снят живьём 2026-10-05 (`claude -p --settings …`, хук
`tee` в файл), идентификаторы обезличены. Голдены —
`fixtures/claude-hook-pre-tool-use/live-bash-mpu-version.json` и
`live-mcp-mpu-version.json`. Многострочные: снятый вывод перенесён
отформатированным, сам хук отдаёт одну строку — разбору всё равно.

Читаются три поля, прочие игнорируются (разбор терпимый, как у
`claude-hook-notification.md`):

| Поле | Требование | Нарушено → без решения, причина |
|---|---|---|
| весь stdin | JSON-объект | `вход не разобран: stdin — не JSON-объект` (пусто, не JSON, массив, число, `null`) |
| `tool_name` | строка | `вход не разобран: нет tool_name` |
| `tool_name` | `Bash` или `mcp__mpu__mpu` (равенство) | `не вызов mpu` |
| `tool_input` | объект | `вход не разобран: tool_input — не объект` |
| `tool_input.command` (Bash) | строка | `вход не разобран: tool_input.command — не строка` |
| `tool_input.words` (MCP) | список строк | `вход не разобран: tool_input.words — не список строк` |
| `tool_input.words` (MCP) | не пуст | `вход не разобран: tool_input.words пуст` |

Порядок проверок — сверху вниз; первая нарушенная даёт причину.
`hook_event_name` не проверяется: событие выбирает настройка, второе место
отбора — второй источник правды. MCP-сервер, зарегистрированный под другим
именем (`mcp__другое__mpu`), — «не вызов mpu».

Содержимое stdin не попадает ни в одну поверхность вывода (тот же довод, что у
`claude-hook notification`).

### Вывод

Ровно одна поверхность на исход, перевод строки в конце.

`allow` — stdout, stderr пуст:

```
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow","permissionDecisionReason":"mpu sql-ro: разрешено правилом «sql-ro»"}}
```

`deny` — stdout, stderr пуст:

```
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"mpu kiten card: запрещено правилом «kiten card»"}}
```

JSON без пробелов, порядок ключей как выше. `mpu <путь>` — путь строки без
звена `<args>` и без двери `ask` (`ask-door.md` [D.4]); `«…»` — путь
выигравшего правила, корень — `*`.

Без решения — stdout пуст, stderr ровно одна строка
`mpu claude-hook pre-tool-use: без решения — <причина>`. Причины — закрытый
список:

| Причина | Когда |
|---|---|
| `правило «<путь правила>» — ask` | решение правил `ask`; ни одно правило не совпало — `правило «*» — ask` |
| `решает только человек` | команда, которую правила не решают (`ownerOnly`: `task rule`, `task owner-answer`, `task role`) |
| `изменение правил` | сообщение корню `allow:` / `ask:` / `deny:` / `forget:` |
| `программа: содержимое не видно` | `run:` первым словом (после `ask`); Bash `mpu` без слов или только `mpu ask` (программа из stdin) |
| `решается при исполнении` | программа словами (`isProgram`), вызов метода образа, строка образа (`image sync`, `image export`, `… define:`), группа `do … end` или `stdin` на месте значения |
| `правила строку не решают` | строка дошла до конца, правил не спросив: справка (`--help`, `help`), `it`, методы корня `web`, `web-logout` |
| `строка не разобрана: <reason>` | отказ строки при обходе; `<reason>` — `refusal.reason` (`refusal-object.md`), у отказа без вида — `отказ` |
| `оболочка: подстановка` / `раскрытие` / `не одна простая команда` / `незакрытая кавычка` | разбор Bash, ниже |
| `не вызов mpu` | не тот инструмент; первое слово Bash-строки не `mpu` |
| `вход не разобран: …` | таблица «Ввод» |
| `правила недоступны: <причина>` | файл правил не читается, сервер строк не отвечает, нет токена, отказ на собственном пути хука (см. «Клиент») |

Значений ключей строки нет ни в одной причине: `<reason>` — постоянная строка
вида отказа, а не его текст (текст отказа `mpu kiten card id: 1: понимаю id:;
…` несёт значения).

### Разбор Bash-строки [D.4]

Принимается ровно одна простая команда с литеральными словами. Разбор — один
проход слева направо по символам; **первое событие решает**. Конец первого
слова — тоже событие: первое слово не `mpu` (после снятия кавычек) — `не вызов
mpu`, что бы ни шло дальше (`cd /tmp && mpu …`, `cat p.mpu | mpu`,
`FOO=1 mpu`, `sudo mpu`, `/…/bin/mpu`, `echo mpu`). Пустая строка и строка из
одних пробелов — `не вызов mpu`.

Таблица символов вне кавычек:

| Символ | Событие |
|---|---|
| пробел, табуляция | разделитель слов; повторы и края строки не значат ничего |
| перевод строки | в хвосте строки (дальше только пробелы и переводы) — разделитель; иначе `оболочка: не одна простая команда` |
| `;` `&` `\|` `<` `>` `(` `)` | `оболочка: не одна простая команда` (`2>&1`, `> out`, `&&`, `\|`, `&` — сюда) |
| `#` в начале слова | `оболочка: не одна простая команда` (комментарий: оболочка выбросит хвост, хук его не снимает) |
| `$` | `оболочка: подстановка` (`$(…)`, `$x`, `${x}`, `$((…))`) |
| `` ` `` | `оболочка: подстановка` |
| `*` `?` `[` `{` `~` | `оболочка: раскрытие` (консервативно: и там, где bash не раскрыл бы) |
| `\` + символ | символ буквально; `\` + перевод строки — ничего (продолжение строки) |
| `'` | одинарные кавычки до следующей `'`: всё буквально, включая перевод строки, `$`, `\` |
| `"` | двойные кавычки до следующей неэкранированной `"`; внутри `$` и `` ` `` — `оболочка: подстановка`; `\` экранирует только `$ ` `` ` `` `" \` и перевод строки (последний — продолжение), перед прочими остаётся буквой |
| прочее | буква слова |

Кавычки не закрыты к концу строки — `оболочка: незакрытая кавычка`. Пустые
кавычки (`''`) дают пустое слово. `!` — буква (хук зовёт неинтерактивную
оболочку). Псевдонимы и функции оболочки с именем `mpu` хук не видит:
считается, что `mpu` — установленный клиент (граница).

Цена строгости — без решения там, где по смыслу безобидно: `2>&1`, `# note`,
`cd x && mpu …`. Это сознательно (постановка, §7): ошибка в сторону «без
решения» стоит один вопрос человеку, в сторону `allow` — исполнение без него.

MCP: слова `tool_input.words` идут как есть — оболочки нет.

## Побочные эффекты

Нет: хук читает stdin и файл правил, ничего не исполняет и не пишет (кроме
посева при первом открытии файла новой версией — свойство любой строки). Как
это держится — ниже.

### Как находится решение [D.1, D.2, D.3]

Сквозной инвариант: решение хука совпадает с тем, что `mpu` решил бы для той
же строки в тот же момент. Держится он не повторением правил, а тем, что хук
спрашивает **те же объекты**, которые решают при исполнении:

1. Строка `claude-hook pre-tool-use` — обычная строка сервера строк: файл
   правил открывается ей (`RuleBook.open`, сверка `data_version` перед каждым
   решением — правило, изменённое другим процессом, видно со следующего
   вызова хука), внешний путь `claude-hook pre-tool-use` решается `Session`
   как у любой команды. Только после `allow` внешнего пути ядро читает stdin.
2. Payload → вызов (Bash: разбор выше; MCP: слова). Слова = строка `mpu` после
   первого слова.
3. Источник слов: пусто или только `ask` (Bash) / `run:` первым (после `ask`) —
   `программа: содержимое не видно`. `isProgram`, вызов метода образа, строка
   образа (`imageLineOf`/`syncLineOf` не `NOT_IMAGE`) — `решается при
   исполнении`. Те же функции, которыми ядро выбирает путь строки
   (`line/mod.ts`), — второго правила «что программа» нет.
4. Обход слов **той же цепочкой** (`registryRoot` над тем же экземпляром
   книги, те же методы образа, вход двери `entryOf`), где на месте `Session`
   — проба `Consultation` (реализация `Line`). Проба ничего не исполняет:
   - конец строки у листа (`dispatch`, `select`, `consent`) → согласие
     команды (`Consent`): `rules` — шаг 5; `human` — `решает только человек`;
   - `listRules` (строка `policy`) — шаг 5 по звеньям пути `policy`;
   - `change` (`allow:` …) — `изменение правил`.
5. Решение — `RuleBook.decide(report.links())` → `Ruling.settle(execution,
   NOBODY, OUTSIDE.ahead)`: адрес «`allow` → исполнить, `ask` → переадресовать»
   (тот же, что у обхода программ, `line/ahead.ts`), канал без человека.
   Исход приходит в `Execution<HookReply>` пробы:
   - `run()` → `allow`, причина `mpu <путь>: разрешено правилом «<won>»`;
   - `redirect()` → без решения, `правило «<won>» — ask`;
   - `refuse(reason, text)` → `deny`, причина — `text`, который сложил
     `FORBIDDEN` из `verdict.ts`: `mpu kiten card: запрещено правилом «kiten
     card»` дословно, потому что `execution.text` пробы — путь без `<args>`.
   `<won>` берётся из `ruling.record()` ровно в одном месте — при сборке пробы;
   `won: null` (наследуемое правило) — названный вид пустоты, текст `*`.
   [D.3]
   Дверь (`ask` первым словом) на решение не влияет: адрес пробы один на обе
   (постановка, §6).
6. Обход отказал (Speech пробы получает объект отказа) — `строка не разобрана:
   <reason>`; обход кончился, не спросив пробу (справка, `it`) —
   `правила строку не решают`. Сбой книги (`PolicyError`) при решении —
   `правила недоступны: <текст ошибки>`.
7. Ответ печатает себя сам (`HookReply.tell`), строка возвращает 0.

Что в обходе подменено, чтобы проба ничего не исполнила и не записала [D.5]:

| Место | Иначе было бы | В пробе |
|---|---|---|
| исполнение листа (`runLine`, исполнитель) | исполнение команды, запись журнала, `it` | не вызывается: решает проба |
| методы корня `rootMethod.produce()` (`web`, `web-logout`) и `it` | исполняются мимо правил | заменены стоячими методами того же имени и справки: конец строки → `правила строку не решают` |
| группа `do … end` значением (`LineValues`) | обход исполняет вложенную строку | значения пробы: группа → `решается при исполнении` |
| `stdin` значением | читает stdin строки хука | то же → `решается при исполнении` |
| `ruled` строк образа (`define.ts`) — `book.sow` | запись посева | строки образа отсеяны на шаге 3 |
| вопрос каналу (`CONFIRM`, `amend`) | вопрос человеку | недостижим: адрес пробы не даёт `CONFIRM`, `change`/`human` проба не передаёт каналу |
| stdout/stderr обхода (справка, текст отказа) | печать | Speech пробы: текст выбрасывается, объект отказа — в причину |
| подсказки `target:` (`targets`) | чтение кэш-БД | как есть: только чтение, при обходе не зовутся |

Журнал вызовов: записи нет ни у внутренней строки, ни у самой
`claude-hook pre-tool-use` — запись делает исполнение листа (`runLine`), а
его у хука нет; отказ правил записи не оставляет, как у любой строки.
Наблюдаемый след — `mpu log` после вызова хука не меняется (тест).

Посев: `RuleBook.open` сеет пути, которые ещё ни разу не видел, — свойство
любой строки `mpu`, а не хука. После первого открытия файла новой версией
хук файлов состояния не пишет (§8 постановки держится в установившемся
режиме; проверка — `data_version`/размер `policy.db`, журнала и кэш-БД до и
после вызова на уже посеянном файле).

Таймаут: `PRAGMA busy_timeout` книги — 5 с (`BUSY_TIMEOUT_MS`), меньше 10 с
таймаута настройки: занятый файл даёт `правила недоступны: …`, а не снятие
хука по таймауту.

### Клиент [D.6]

Код 0 — свойство всей команды. Сервер строк до строки может не дойти, а
собственный путь хука может решиться не `allow`; тогда сегодняшний клиент
вернул бы 1 или 2 (`ask` на пути хука — адресный отказ двери, код 2 =
блокировка всего Bash). Поэтому клиент (`cli/`) для строки **ровно** из слов
`claude-hook pre-tool-use` (без `--help`, `help` и прочего — у них обычная
судьба) выбирает другой исход строки:

- код строки 0 — как есть (вывод ядра уже напечатан);
- отказ до сокета (сервер не отвечает, нет токена, 401/403), обрыв сокета до
  кадра `exit`, кадр `exit` с кодом не 0 — stdout пуст, stderr одна строка
  `mpu claude-hook pre-tool-use: без решения — правила недоступны: <причина>`,
  код 0. `<причина>` — текст клиента без префикса `mpu: `, либо первая
  строка текста кадров `err` ядра (её клиент держит, а не печатает).

Слова строки и форма строки «без решения» — в `back/src/frames/` (контракт,
общий обеим сторонам: клиенту разрешён только этот импорт). Ядро печатает
причины через ту же функцию — один источник текста.

Сценарии клиента (`cases.json`, раздел `environment`):

| S20b | `policy.db` — мусор | `… правила недоступны: правила подтверждения: …`, код 0 |
| S20c | `policy.db` без права чтения | то же |
| S20d | нет файла токена | `… правила недоступны: нет токена доступа (…)`, код 0 |
| S20e | `deny: "claude-hook pre-tool-use"` | `… правила недоступны: mpu claude-hook pre-tool-use: запрещено правилом «claude-hook pre-tool-use»`, код 0 |
| S20f | `ask: "claude-hook pre-tool-use"`, без человека | `… правила недоступны: mpu claude-hook pre-tool-use: требует подтверждения …`, код 0 |

## Инварианты

- Код выхода — 0 на любом входе и в любом окружении (с клиентом).
- `allow` — только когда исполнится ровно одна строка `mpu` и решение правил
  по её пути `allow`.
- Решение совпадает с тем, что `mpu` решил бы для той же строки в тот же
  момент: решает тот же `RuleBook.decide` и тот же `Verdict.settle`.
- `ask` правил не становится ни `allow`, ни `deny`; недоступные правила не
  дают ни `allow`, ни `deny`.
- Хук ничего не исполняет из строки, не спрашивает человека, не пишет в
  правила, журнал и кэш-БД (после первого посева).
- Ни stdout, ни stderr не содержат значений ключей строки и содержимого
  stdin — только путь и путь правила.
- `allow`/`deny` — stderr пуст; без решения — stdout пуст, stderr одна строка.

## Граничные случаи и ошибки

- Дыра правил с ключом `target:` вместо режима (`owner-questions`, вопрос 7)
  не закрывается: хук повторяет решение правил, какое оно есть.
- Правила `deny` настроек Claude Code хук не перекрывает (свойство Claude
  Code); хуковый `allow` снимает их `ask`.
- `deny`/`ask` человека на пути `claude-hook pre-tool-use` — способ отключить
  хук: исход `правила недоступны: …`, код 0 (S20e, S20f).
- Задан tty у процесса хука и `ask` на пути хука — вопрос в терминал; хук
  снимет таймаут настройки (10 с), вызов идёт обычной проверкой.
- Старый клиент без команды: код 2 — блокировка; отсюда граница «фрагмент —
  после установки».
- MCP-сервер под другим именем — «не вызов mpu».

## Решения

- **[D.1] Хук — строка ядра, не команда исполнителя.** Путь строки знает
  только ядро: дерево, книга правил, дверь, образ живут там
  (`line/mod.ts`). Исполнитель (`mpu-worker`) их не имеет; командой реестра
  хук остаётся ради справки, посева и места в дереве, `run` отвергает вызов
  (прецедент `image sync`). Альтернатива — новый кадр «спросить решение»
  (`back-rpc.md`): клиент разбирал бы payload сам. Отвергнута: правка
  контракта кадров ради одной команды, а разбор payload и оболочки на
  клиенте — второй экземпляр кода вне тестов ядра.
- **[D.2] Один источник решения — обход той же цепочкой с пробой вместо
  `Session`.** Прецеденты: `SyncLine` (обёртка `Line`), `Ahead` (проба
  `Execution` без исполнения). Путь строки — `report.links()` листа, до
  которого дошла цепочка: разбор ключей, вариантов, двери и `end` — те же,
  что при исполнении (S3, S4, S15). Свой разбор пути у хука — второй
  источник, отвергнут.
- **[D.3] Исход — `Ruling.settle` у адреса обхода.** Решение `allow/ask/deny`
  не разбирается строкой: проба — `Execution<HookReply>`, каждое решение само
  выбирает её сообщение (`run`/`redirect`/`refuse`), `deny` складывает
  `FORBIDDEN`. `<won>` — из `record()` в одном месте.
- **[D.4] Разбор оболочки — граница ввода.** Посимвольный проход с `switch`
  по классу символа и закрытым набором состояний (вне кавычек, `'…'`, `"…"`,
  после `\`) — разбор входа, где `switch` допустим. Принимается только
  подмножество «одна простая команда, литеральные слова»; всё прочее —
  событие с причиной.
- **[D.5] Проба ничего не исполняет по построению**, а не по
  внимательности: каждое место обхода, которое исполняет или пишет, названо
  в таблице подмен и закрыто тестом-мутацией.
- **[D.6] Код 0 держит клиент.** Ядро не может ответить, когда его нет;
  исход строки хука выбирает клиент по словам строки — объект «исход строки»
  (обычный: код как есть; хук: любой ненулевой → строка «правила недоступны»
  и 0). Текст строки — в `frames/`, общем контракте.
- **[D.7] Ответ — объект.** Три реализации `HookReply` (`Allowed`, `Denied`,
  `Undecided`) с `tell(speech)`: JSON в stdout или строка в stderr. Код
  выхода не принадлежит ответу — он всегда 0 у строки.

### Примитивы (`design.md` п. 1)

| Примитив | Владелец |
|---|---|
| решение правил для звеньев пути | `RuleBook.decide` (есть) |
| исход решения у адреса | `Verdict.settle` / `Address` (есть) |
| слова вызова из payload | `ToolCall` (новый, граница ввода) |
| ответ хука печатает себя | `HookReply.tell` (новый) |

Производные: причина «строка не разобрана» — из объекта отказа в Speech
пробы (одно место — проба); текст `deny` — из `FORBIDDEN` (одно место —
`verdict.ts`); строка «без решения» — одна функция в `frames/` (ядро и
клиент); «программа ли» — `isProgram`/`callsImage`/`imageLineOf` ядра.

### Особые случаи → реализации (п. 2)

| Ветка | Реализация / причина |
|---|---|
| вид инструмента (Bash / MCP / другой / вход битый) | `switch` по `tool_name` на границе DTO → `BashCall`, `McpCall`, `NotMpu`, `Unparsed` — один протокол «слова или ответ» |
| `allow` / `ask` / `deny` | `Ruling.settle` + адрес обхода → сообщения пробы (`run`/`redirect`/`refuse`) |
| согласие правилами / только человеком | `Consent.settle` (есть) → ветви пробы |
| изменение правил | `Consultation.change` |
| стоячие методы корня | отдельная реализация метода корня, не флаг |
| значение-выражение | реализация значений пробы |
| исход строки на клиенте (обычная / хук) | две реализации исхода, выбор по словам строки |
| символ оболочки | граница ввода: `switch` допустим |

### Сообщение → кто решает (п. 4)

| Сообщение | Решает | Перенесено? |
|---|---|---|
| исполнять ли внешнюю строку | `Session` + правила (как у всех) | нет |
| какие слова у вызова | `ToolCall` по payload | новое |
| простая ли команда оболочки | разбор оболочки | новое |
| программа ли строка | функции ядра (`isProgram` …) | нет, переиспользуются |
| путь строки | цепочка (`report.links()`) | нет |
| решение пути | `RuleBook` → `Ruling` | нет |
| исход решения | `Verdict` у адреса | нет |
| текст ответа | `HookReply` | новое |
| код выхода хука | строка ядра (0) и исход клиента | новое |

Модульное состояние: нет. Книга — у строки (открыта на строку, закрыта ею).
