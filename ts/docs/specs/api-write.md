# mpu api — остаток неймспейса (79 команд)

**Статус:** к реализации (2026-08-28). Контракт неймспейса — `api.md`,
обвязка — `platform/slback-http.md`.

## Назначение

Весь остаток `mpu api` после переезда читающих объявлений и `get-token`:
**79 команд**, и они делятся по способу объявления, а не по методу.

- **68 декларативных** — объявлены таблицей `COMMANDS` в источнике, механика
  одна: обёртка одного эндпоинта. Из них 65 меняют состояние (50 POST, 8
  DELETE, 7 PATCH) и 3 читают. **Эта порция — про них.**
- **11 кастомных** — объявлены вне таблицы, каждая со своей механикой:
  `ss-access request|status|revoke|reset` (авто-тело и резолв через базу),
  `wb-cards-reset` (резолв селектора), `api wb-loader-*` — шесть команд,
  которые **не** те же, что переехавший верхнеуровневый `mpu wb-loader`.
  Их описывать прозой, отдельными спеками, как `api-wb-loader.md`; в этой
  порции они не участвуют.

Название «пишущая половина» неточно вдвойне: и читающие тут есть, и деление
проходит не по методу.

После этой группы `api` уходит с маршрута `legacy` последним из пяти имён, и
подпроцесс Python перестаёт быть частью поставки.

## Эталон вместо описаний

Дословная фиксация 51 команды — таблица, а не проза, и она **снята с
источника, а не переписана**: `docs/specs/fixtures/api/write-endpoints.json`,
по записи на команду — имя, метод, путь, path-параметры, поля тела и их
типы, признак приёма произвольного тела.

Так — по правилу `CLAUDE.md`, «Фикстуру стыка снимают, а не сочиняют».
Переписать полсотни путей и сотню полей руками значит гарантированно ошибиться
в одном-двух местах, причём незаметно: тест на переписанное сойдётся с
переписанным.

**Эталон — не источник объявлений, а голден переноса.** Объявления живут в
коде (`src/api/endpoints.ts`), как и у переехавшей половины; эталон отвечает
на один вопрос: перенесли ли мы всё и без искажений. Поэтому тест сверяет
**только снятые поля** — имя, метод, путь, path-параметры, набор полей тела —
и не претендует на полноту объявления.

Так — потому что объявление несёт решения, которых в источнике нет и быть не
может: `sensitiveOutput` (запрет писать чужие секреты и персональные данные в
журнал вызовов, см. `api.md`, «Известные отклонения»), имена опций, признаки
публикации. Сделай мы объявления производными от эталона — пришлось бы
дописывать в него наши решения, и он перестал бы быть снимком источника,
то есть потерял бы то единственное, ради чего снят.

Расхождение по снятым полям — красный тест с указанием команды.

**Эталон снят у объекта, а не у текста источника** — и это не мелочь стиля.
Первый снимок разбирался регулярками по исходнику и молча соврал: пропустил
имена, собираемые в цикле (в эталон попал сам шаблон `{prefix}-{suffix}`),
не увидел трёхуровневых команд, недобрал поля тела у восьми записей и
path-параметры у девяти. Разбор текста — та же догадка о чужой форме, только
про синтаксис; снимок у объекта её не содержит.

Контрольная сумма состава — **независимый снимок**
`fixtures/platform/registry/tree.json` (машинный дамп дерева CLI): 103 листа
`api`, из них после вычета переехавших остаётся 79 — 68 декларативных плюс 11
кастомных. Сверка с ним и вскрыла неполноту первого эталона; выборка,
считавшая записи внутри одного снимка, её пропустила.

## Разрез

**68 декларативных берутся целиком, одной порцией.** Механика однородная:
обёртки одного эндпоинта, различаются путём, методом и полями тела. Резать по
числу бессмысленно — риск не в них.

**11 кастомных не входят в эту порцию.** У каждой своя механика, и разрез
проходит по ней, а не по числу: их спеки пишутся отдельно.

Крупно по коду, мелко по риску — противоположность исключённой `sync`, где
было наоборот.

## Инварианты

1. **Состав команд равен эталону.** Ни одной сверх, ни одной недостающей;
   проверяется тестом против `write-endpoints.json`.

2. **Путь с параметрами не собирается склейкой строк.** Значение
   path-параметра попадает в путь только через подстановку с экранированием;
   параметр, содержащий `/` или `?`, не должен менять адрес запроса.

3. **Тело отправляется только объявленными полями.** Поле, которого нет в
   объявлении команды, — ошибка ввода с кодом 2, а не молчаливая отправка на
   сервер. Для команд с признаком произвольного тела — своё правило: тело
   принимается как есть, но остаётся объектом.

4. **Мутация не выполняется на угаданном адресе.** Команда без обязательного
   path-параметра — код 2 до сети, а не запрос по пути с пустым сегментом.

5. **Ответ печатается как есть.** Величины из ответа не досочиняются: если
   сервер вернул только признак успеха, печатается он, а не выдуманный
   счётчик (`CLAUDE.md`, «Величина берётся там, где совершается работа»).

## Голдены

**Снимаются только на локальном sl-back.** Это ограничение жёстче, чем у
`sheet`: там черновая таблица, здесь боевые клиенты. Ни один голден пишущей
команды не снимается с прода — ни «безобидный», ни «только посмотреть».

Читающие три команды (`auth-verify`, `auth-resend-email` и GET-запись
остатка) можно снимать где угодно.

## Приёмка

- состав команд совпал с эталоном (тест);
- на локальном sl-back: по одной мутации каждого метода (POST, PATCH,
  DELETE) — результат виден в базе стенда, а не только в коде возврата;
- path-параметр со слэшем не меняет адрес запроса;
- лишнее поле тела отвергается до сети;
- после переезда `mpu api <любая>` не обращается к подпроцессу, и `api`
  исчезла из `legacy_tree.ts`.
