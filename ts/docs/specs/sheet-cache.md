# mpu sheet cache — состояние и очистка локального кэша вкладок

**Статус:** к реализации (2026-08-28).

## Назначение

Две команды-хозяина локального кэша вкладок: `cache info` показывает его
состояние, `cache clear` очищает. Прочие команды семейства `sheet` кэш только
потребляют (`get`, `ls`, `open` — читают и наполняют), владеет им эта пара.

Кэш живёт в двух местах, и это существенно для обеих команд:

- таблица `sheet_tabs` — тела вкладок, ключ `(ss_id, tab_name)`, поля
  `payload`, `size_bytes`, `fetched_at`;
- строка таблицы `cache` с ключом `sheet:info:<ss_id>` — метаданные вкладок
  (перечень, идентификаторы, размеры сетки) со сроком жизни.

## CLI-контракт

```
mpu sheet cache info
mpu sheet cache clear [-s|--spreadsheet ЦЕЛЬ]
```

`ЦЕЛЬ` — идентификатор таблицы, алиас или подстрока заголовка; резолв тот же,
что у прочих команд семейства (`sheet.md`, «Резолв цели»). Без `-s` очищается
весь кэш.

## Ввод/вывод

`cache info` печатает итог и разбивку по таблицам:

```
total: <N> tabs, <X> KB
  <ss_id>  tabs=<n>  size=<x>KB  latest=<unixtime>
```

Строки разбивки отсортированы по убыванию размера. Пустой кэш — только строка
итога с нулями, разбивки нет.

`cache clear` печатает, что именно удалено (см. «Инварианты», след).

## Побочные эффекты

`cache info` **не меняет состояние**: только чтение. Это требование, а не
описание текущего поведения — команда «покажи состояние», молча его меняющая,
делает недостоверной любую следующую пару.

`cache clear` удаляет **две** вещи: строки `sheet_tabs` и ключ
`sheet:info:<ss_id>`. С `-s` — по одной таблице, без `-s` — целиком
(`sheet_tabs` полностью, ключи по образцу `sheet:info:%`).

## Инварианты

1. **След измерим и при нуле.** Вывод `clear` различает три исхода: чистить
   было нечего; удалены вкладки; вкладок не было, но метаданные сброшены.
   Одним числом это не выражается — вкладок бывает сотня, ключ метаданных
   один, и их сумма смешала бы разнородное. Поэтому число печатается для
   вкладок (всегда, включая ноль), а про метаданные говорится отдельно: был
   ли ключ и удалён ли он.

2. **Сообщение называет ту величину, которая в него подставлена.** Оригинал
   этому не удовлетворяет: он чистит обе вещи, а печатает счётчик только по
   вкладкам, поэтому при нуле вкладок сообщает `cleared 0 tabs`, умалчивая об
   удалённом ключе метаданных. Это расхождение вывода с работой, и переносить
   его не нужно.

3. **Очистка кэша — одно устройство на весь репозиторий.** Точечная
   инвалидация уже есть: `invalidateTabs` (`src/sheet/cache.ts`) удаляет
   перечисленные вкладки и тот же ключ `sheet:info:<ss_id>`; её зовёт
   `batch-update` после успешной записи (`platform/webapp-http.md`,
   «Housekeeping и инвалидация»). Охват у команд разный — `invalidateTabs`
   бьёт по именам вкладок, `cache clear` по всей таблице, — но удаление
   ключа метаданных у них общее и обязано жить в одном месте. Две правды об
   одном действии расходятся; это тот же класс, что расхождение
   `wb_cabinets` со связками.

4. **Отсутствие таблиц кэша — не ошибка.** Так уже устроены `writeTab` и
   `invalidateTabs`. `info` в этом случае говорит, что кэша нет, и советует
   инициализацию; `clear` завершается успехом.

## Граничные случаи и ошибки

- цель не резолвится → код 2, перечень кандидатов (общий путь семейства);
- `-s` с целью, у которой в кэше ничего нет → код 0 и сообщение по инварианту 1;
- таблиц кэша нет → код 0, сообщение об этом; `mpu init` в подсказке.

## Приёмка

Живая пара на черновой таблице, по следу, а не по коду возврата:

- до и после `clear -s`: число строк `sheet_tabs` по этому `ss_id` и наличие
  ключа `sheet:info:<ss_id>`;
- прогон `clear -s` дважды подряд: второй сообщает «чистить нечего», а не
  повторяет первый;
- `clear -s` на таблице, у которой вкладок нет, но ключ метаданных есть
  (готовится вызовом `open` с именем листа): сообщение обязано отличаться от
  «нечего чистить»;
- до и после `info`: обе таблицы кэша побайтово те же.
