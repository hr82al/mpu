# Запасной путь: снимок окна tmux в Telegram (порция R4)

Статус: реализовано — порция R4 (`e609b1a1`…`18023767`); принято 2026-10-06 хостом: гейты зелёные, рецензии `.tmp/review-R4.md`, `review-R4b.md`. (серия R, порция R4; решено хостом автономно —
владелец поручил серию R целиком, 2026-10-06). Меняет `claude-hook-notification.md`.

## Назначение

Ожидание, которое Claude Code не отдал хукам R1–R3 (новый вид диалога,
вход, доверие к каталогу, любое будущее), владелец видит в Telegram снимком
окна tmux, ужатым под телефон, и отвечает кнопками-клавишами, которые
нажимаются в этом окне. Бот вида ожидания не знает: он читает экран.

## Когда приходит снимок

Хук `Notification` (`mpu claude-hook notification`, payload — как сегодня,
`fixtures/claude-hook-notification/`). Ключ сессии —
`CLAUDE_CODE_MESSAGING_SOCKET`, окно — `TMUX`/`TMUX_PANE` клиента (как R1b).

| Уведомление | Поведение |
|---|---|
| `auth_success` и прочие без ожидания (`notification_type` не оканчивается на `_prompt`/`_dialog`) | как сегодня: строка-уведомление в бота |
| ожидание (`*_prompt`, `*_dialog`), у сессии через 3 с есть вопрос в ряду (R1–R3: право, AskUserQuestion, «ждёт ввода», `ask`, форма) | ничего: ожидание уже в чате |
| ожидание, вопроса нет, окно tmux известно | вопрос-снимок (ниже) |
| ожидание, вопроса нет, окна нет | строка-уведомление `Claude · <проект> · <тип>` / `<message>` (как сегодня) |

Хук выходит сразу; снимок живёт в ядре до исхода.

## Вопрос-снимок

Срочный (блокирующий диалог). Сообщение:

```
🖥 <сессия> — <проект> · <окно>
<блок диалога, ужатый>
```

Блок диалога — по снятому экрану (`capture-pane -p`):

1. Блок — строки после **последней** сплошной линии из `─` (≥ 20 знаков),
   под которой есть хотя бы одна строка не-линия; нижняя рамка Claude Code
   (`─── <имя окна> ─` последней строкой) в счёт не идёт.
2. Из блока убираются: линии `─`/`╌`/`═`; строки `Tip: …`; строки-подсказки
   клавиш (`Esc to cancel…`, `Enter to select…`, `Enter to confirm…`,
   `↑/↓ to navigate…`); пустые строки по краям, подряд идущие — до одной.
3. Ведущие пробелы снимаются; маркер выбора `❯ ` снимается.
4. Пункты `N. <текст>` (N — 1–9): в тексте остаются строкой
   `N. <текст>` (с описанием следующей строкой, если оно есть, — через ` — `);
   кнопкой — `N. <текст до « · »>`, ≤ 60 символов; кнопка нажимает `N`.
5. Текст — обычный (не моноширинный), первая строка блока — жирным; длина —
   предел Telegram, усечение с начала блока (вопрос и пункты — внизу).

Кнопки: пункты (по одному в ряд), затем ряд клавиш `⏎` · `⎋` · `↑` · `↓`,
затем `весь экран`. Нажатие: `tmux -S <сокет> send-keys -t <pane> <клавиша>`
(`1`…`9`, `Enter`, `Escape`, `Up`, `Down`), затем через 1 с снимок заново и
правка сообщения. `весь экран` — отдельным сообщением снимок целиком
моноширинным блоком, без кнопок. Свой текст — да: текст владельца
вписывается в окно (`send-keys -l`) и нажимается `Enter`.

## Исходы

| Что | Сообщение |
|---|---|
| после нажатия блок диалога исчез (нет пунктов и подсказок клавиш) | `✅ окно сменилось — <первая строка нового блока или «лента»>`, кнопок нет |
| блок изменился без нажатия (ответили в терминале) — проверка каждые 2 с | `✅ решено в терминале` |
| окно закрыто / tmux не отвечает | `⌛ окно недоступно` |
| у сессии появился структурный вопрос (R1–R3) | снимок снят `↷ вопрос в чате` |

## Отклонения, принятые при приёмке R4

- Начало блока: линия, за которой идёт пункт `N ≥ 2` при пунктах выше, — не
  начало блока (голден AskUserQuestion: линия перед `4. Chat about this`).
- Пустых строк в теле нет вовсе (по голденам), а не «до одной».
- Экран без блока диалога — строка-уведомление, а не снимок.
- Тексты отказов — службы вопросов (`бот не настроен`, `бот недоступен: …`).

## Инварианты

- Нажатие уходит только в окно своей сессии (сокет и панель — с её хука).
- Снимок не дублирует структурный вопрос той же сессии.
- Текст окна уходит в Telegram как есть после ужатия: что видно в терминале,
  то видно в чате (граница R1).
