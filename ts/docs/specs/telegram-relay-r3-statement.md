# Ретранслятор Claude Code в Telegram — постановка порции R3

Статус: решено хостом автономно (владелец поручил серию R целиком,
2026-10-06); спеки — `platform/ask-telegram.md`, `claude-hook-elicitation.md`.

Серия R (общая постановка — `telegram-relay-statement.md`). R3 — подтверждения
`mpu ask` и чужие MCP-формы в Telegram. Живые образцы — пробы 2026-10-06:
форма хука `Elicitation` (`fixtures/telegram-relay/r3/live-elicitation-mpu.json`),
отмена формы сервером (проба R3-1).

## 1. Кто и зачем

Владелец, отошедший от терминала, хочет подтверждать записи `mpu ask` и
отвечать на формы других MCP-серверов из Telegram так же, как вопросы о праве.

## 2. Сценарии

Подтверждение `mpu ask` (правило `ask`, `platform/policy.md`):

1. **Терминал.** В терминале `mpu ask kiten comment id: 55 text: ок` →
   терминал спрашивает `выполнить mpu kiten comment? [y/N] `; одновременно в
   чат: `❓ mpu ask — <окно, если клиент под tmux>` / `выполнить mpu kiten
   comment?` с кнопками `Да` / `Нет`.
2. **Ответ в чате.** Жмёт `Да` → строка исполняется; в терминале ввод больше
   не ждётся, в stderr строка `mpu: решено в Telegram — да`; сообщение —
   `✅ Да — из чата`.
3. **`Нет` в чате** → строка не исполняется (тот же отказ, что у `n` в
   терминале); stderr `mpu: решено в Telegram — нет`.
4. **Ответ в терминале** `y` → строка исполнена; сообщение в чате —
   `✅ решено в терминале`.
5. **Агент (MCP).** Агент зовёт тул `mpu` со словами `["ask","kiten","comment",…]`
   → в Claude Code форма `выполнить mpu kiten comment? [y/N]`, в чате — тот
   же вопрос (`❓ mpu ask (MCP)`). `Да` в чате → форма в Claude Code
   закрывается, вызов исполняется.
6. **Пароль.** Вопрос вида `secret` (`Пароль GitLab: `) → в чат не уходит
   никогда; только терминал.
7. **Бот не настроен** → вопрос только в терминале/форме, как до R3.
8. **`mpu confirm`** (ворота конвейера `[y/N]`) → так же, как сценарии 1–4.

Чужие MCP-формы (хук `Elicitation`):

9. **Форма да/нет.** MCP-сервер `gitlab` просит форму без полей
   (`requested_schema: {"type":"object","properties":{}}`, сообщение
   `Удалить ветку?`) → терминальная форма ждёт хука; в чат —
   `📝 gitlab — <откуда>` / `Удалить ветку?` с кнопками `Accept` ·
   `Decline` / `В терминале`.
10. **Accept** → форма принята (`action: accept`, `content: {}`).
11. **Поля.** Схема `{"properties":{"env":{"type":"string","enum":["dev","prod"]},
    "force":{"type":"boolean"},"note":{"type":"string"}}}` → шаги: `env` —
    кнопки `dev`/`prod`; `force` — `Да`/`Нет`; `note` — текст. Итог
    `{"action":"accept","content":{"env":"dev","force":false,"note":"…"}}`.
12. **В терминале** → хук выходит без решения; Claude Code показывает форму в
    терминале; сообщение — `↪ ответ в терминале`.
13. **Форма самого mpu** (`mcp_server_name: "mpu"`) → хук не задаёт вопроса
    (его уже задал mpu, сценарий 5): выходит без решения сразу.
14. **Режим `url`** → без вопроса: в чат уведомление со ссылкой, ответ — в
    браузере/терминале.

## 3. Инварианты

- На один вопрос — одно решение; проигравшая сторона снята (терминал не ждёт
  ввода, форма MCP закрыта, сообщение помечено).
- Скрытый ввод не появляется в Telegram ни в каком виде.
- Хук `Elicitation` никогда не решает за владельца: без ответа — без решения.

## 4. Границы

- Не пересылает вопросы-строки, кроме `[y/N]`-подтверждений (`ask` вида
  `line` с вопросом подтверждения и `mpu confirm`).
- Форма MCP с полями неизвестного типа (объект, массив) — только `В
  терминале` и `Decline`.
