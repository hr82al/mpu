# mpu kiten ls

Статус: к реализации (заморожена 2026-08-19; формы сняты прогоном
рабочей версии, значения в фикстурах заменены синтетическими)

## Назначение

Список карточек Kaiten, где я участник (member), со сводом фильтров по
осям «CLI-флаг > env > дефолт» и четырьмя машинными видами вывода.
Только чтение.

## CLI-контракт

`mpu kiten ls [--archived] [--state queued|in-progress|done]
[--space REF] [--board REF] [--lane REF] [--column REF]
[--date-from YYYY-MM-DD] [--date-to YYYY-MM-DD]
[--json | --format TPL | --only-url | --md]`

- `--archived` — архивные карточки (condition=2) вместо активных.
- `--state` — этап: `queued`→1, `in-progress`→2, `done`→3 (параметр
  `states`).
- `--space`/`--board`/`--lane`/`--column` — ID или подстрока названия;
  резолв — `platform/kaiten-http.md` («Резолв справочной ссылки»).
  `--lane`/`--column` резолвятся в скоупе эффективной доски: явный
  `--board`, иначе (вне глобального режима) env `KITEN_LS_BOARD_ID`,
  иначе весь кэш.
- `--date-from`/`--date-to` (принимаются и написания
  `--date_from`/`--date_to`) — окно последней активности карточки,
  формат `YYYY-MM-DD`; можно задавать по одной границе.
- Виды вывода, по убыванию приоритета: `--json` → `--format` →
  `--only-url` → `--md` → таблица (дефолт).

Примеры из практики (обезличены):

    mpu kiten ls --json
    mpu kiten ls --date-from 2026-07-01 --date-to 2026-07-15 --json
    mpu kiten ls --only-url
    mpu kiten ls --format '{n}. {column_mapped} {url}'

## Ввод/вывод

HTTP: `GET /users/current` → мой id; затем `GET /cards` с
`member_ids=<мой id>` и осями фильтра, пагинация — по
`platform/kaiten-http.md`. Оси запроса: `condition`, `states`,
`space_id`, `board_id`, `lane_id`, `column_id`, `updated_after`,
`updated_before`; незаданная ось в запрос не попадает.

Свод фильтров — ПООСНО, каждая ось независимо: CLI-флаг → env
`KITEN_LS_*` → дефолт. Дефолт есть только у `condition` — 1 (активные);
`--archived` даёт `condition=2` поверх env.

Глобальный режим: задана хотя бы одна из `--date-from`/`--date-to` →
env-оси (`KITEN_LS_*`, включая доску по умолчанию) НЕ применяются,
`condition` не передаётся (и активные, и архивные; `--archived` →
condition=2); явные CLI-флаги сохраняют силу. Даты → границы окна по
полю `updated`, инклюзивно: `--date-from X` → `updated_after=
XT00:00:00Z`, `--date-to Y` → `updated_before=YT23:59:59Z`.

Виды вывода (метка `state` — как в `kiten-card.md`; порядок карточек —
порядок выдачи сервера):

- `--json` — массив объектов
  `{id, state, due_date, updated, title, url}` (отступ 2, юникод как
  есть); пусто → `[]`.
- `--format TPL` — строка на карточку, нумерация с 1; плейсхолдеры
  `{n}`, `{id}`, `{title}`, `{url}`, `{state}`, `{due}` (`YYYY-MM-DD`
  или пусто), `{column}` (название колонки по локальному кэшу; промах
  кэша → id числом; колонки нет → пусто), `{column_mapped}` (метка из
  env `KITEN_COLUMN_MAP`; ключ-id проверяется раньше ключа-названия;
  нет в карте → `{column}`). Подстановка — текстовая замена: фигурные
  скобки в данных не интерпретируются, неизвестный плейсхолдер
  остаётся как есть.
- `--only-url` — `[{title}]({url})` по строке на карточку; `[` и `]` в
  title экранируются `\[` / `\]`.
- `--md` — GFM-таблица с колонками `ID | STATE | COLUMN | DUE | TITLE |
  URL`; в ячейках `|` → `\|`, переводы строк → пробел; пустой список →
  только шапка и разделитель.
- Дефолт — человекочитаемая таблица с теми же колонками и итогом
  `({N} cards)`; пусто → `(нет карточек)`. Оформление — свобода
  реализации.

Exit: 0 — успех (в т.ч. пустая выдача); 2 — ошибки ввода; 1 — ошибки
API.

## Побочные эффекты

Чтение Kaiten (только GET). Кэш справочников не обновляется — резолв
`REF` и колонка COLUMN читают существующий кэш.

## Конфигурация

- `KITEN_API_KEY`, `KITEN_BASE_URL` — `platform/kaiten-http.md`.
- `KITEN_LS_CONDITION`, `KITEN_LS_SPACE_ID`, `KITEN_LS_BOARD_ID`,
  `KITEN_LS_LANE_ID`, `KITEN_LS_COLUMN_ID` — целые; `KITEN_LS_STATES` —
  строка (значение `states` как есть). Пустое/пробельное значение =
  не задано.
- `KITEN_COLUMN_MAP` — JSON-объект «id-или-название колонки → метка»
  для `{column_mapped}`.

## Инварианты

- Kaiten не мутируется; локальная кэш-БД не пишется.
- Каждая ось фильтра сводится независимо от остальных.
- `--archived` побеждает env-`condition` в обоих режимах.
- Наличие даты полностью отключает env-скоуп; без дат поведение от дат
  не зависит.
- `--json`-вывод не зависит от состояния кэша справочников.

## Граничные случаи и ошибки

- Ничего не найдено → exit 0: `[]` / пустой вывод / `(нет карточек)`.
- Невалидная дата → exit 2:
  `--date-from='2026-13-01': ожидается YYYY-MM-DD` (аналогично
  `--date-to`).
- Нечисловое значение целочисленной env-оси → exit 2:
  `KITEN_LS_CONDITION='x': ожидалось целое число` (с именем виноватой
  переменной).
- Неизвестное значение `--state` → ошибка ввода, exit 2.
- Нерезолвящийся `REF` → exit 2 («не найден» / «неоднозначен»,
  `platform/kaiten-http.md`).
- Некорректный JSON в `KITEN_COLUMN_MAP` → stderr
  `mpu kiten ls: некорректный JSON в KITEN_COLUMN_MAP: <детали>`
  (не-объект → `mpu kiten ls: KITEN_COLUMN_MAP должен быть
  JSON-объектом`), карта считается пустой, команда работает.
- Ошибка API → exit 1: `mpu kiten ls: kaiten error: <текст>`.

## Golden-примеры

`fixtures/kiten-ls/`. Два файла — глобальный режим (`--date-from`),
снятый 2026-08-19 прогоном рабочей версии. **Нормализовано**:
идентификаторы, заголовки карточек и названия колонок заменены
синтетическими, список укорочен до трёх карточек; даты, состояния и
форма ссылки оставлены как есть.

- `ls-global.json` — шесть ключей в порядке вывода: `id`, `state`,
  `due_date`, `updated`, `title`, `url`. Обратите внимание: колонки,
  доски и дорожки в этой форме нет — она уже её потеряла;
- `ls-global.md` — та же выдача таблицей markdown: шапка
  `ID STATE COLUMN DUE TITLE URL`, дата срока — только календарная
  часть, без времени.

Каждый файл оканчивается одним переводом строки. Формы с рамкой
(режим по умолчанию) голденами не закрываются — ширина зависит от
терминала. Тексты отказов голденами тоже не закрываются: у оригинала
их печатает его CLI-парсер, а правильная форма — `mpu kiten ls:
<причина>`, exit 2 — задана разделом «Граничные случаи».
