# mpu claude-channel

Статус: к реализации — порция R2b (серия R; постановка —
`telegram-relay-r2-statement.md`, сценарии `[S.n]`)

## Назначение

Канал Claude Code для сессии: доставляет текст владельца из Telegram в ту
сессию, чьё сообщение «ждёт ввода» активно в чате. Claude Code запускает
команду сам — дочерним процессом каждой сессии, как stdio-сервер MCP, — если
сессия начата с флагом development-канала `server:mpu-channel` (алиас
`claude`, ставит `install.sh`). Без флага команда не запускается, и сессия
текста из чата не получает [S7].

Почему отдельная команда, а не MCP-сервер `mpu`: он общий для всех сессий и
ходит по HTTP; каналу нужна одна сессия на процесс и сообщения без запроса.

## CLI-контракт

```
mpu claude-channel
```

- Аргументов и ключей нет. stdin/stdout — JSON-RPC MCP с Claude Code (по
  строке на сообщение); stderr — диагностика (Claude Code её не показывает).
- Исполняет клиент (`cli/`), не ядро и не исполнитель: процесс живёт, пока
  жива сессия, и держит stdio Claude Code. С ядром связан соединением
  клиента (адрес и токен — как у любой строки).
- Тулом MCP-сервера `mpu` не публикуется; посев не нужен — команда не идёт
  через правила как строка ядра (связь с ядром — регистрация канала, ниже).
- Код выхода: 0 — stdin закрыт (сессия завершилась); 1 — ключа сессии нет
  (запущена не Claude Code), stderr
  `mpu claude-channel: нет CLAUDE_CODE_MESSAGING_SOCKET — команду запускает Claude Code`.

## Ключ сессии [D.1]

Ключ — значение `CLAUDE_CODE_MESSAGING_SOCKET` окружения процесса
(`/run/user/1000/cc-socks/<pid claude>.sock`, снято 2026-10-06, проба R2-2).
Тем же значением Claude Code снабжает хуки той же сессии — по нему ядро
сопоставляет «ждёт ввода» (хук `Stop`, `claude-hook-stop.md`) с каналом.
`CLAUDE_CODE_MESSAGING_TOKEN` (лежит рядом) — секрет Claude Code: не
читается, не передаётся, не печатается нигде.

Клиент передаёт ключ ядру при регистрации; `CLAUDE_CODE_MESSAGING_SOCKET`
входит в закрытый список переменных клиента
(`platform/call-context.md`) — только как ключ сессии, путь к сокету ни для
чего не открывается. [D.1]

## Обмен с Claude Code

Живой обмен — `fixtures/telegram-relay/r2/live-channel-exchange.jsonl`
(снят пробным каналом 2026-10-06): `server/discover` → `initialize` →
`notifications/initialized` → `tools/list` → `notifications/claude/channel`.

- `initialize` → ответ с `protocolVersion` запроса, `capabilities`
  `{"tools":{},"experimental":{"claude/channel":{}}}`, `serverInfo`
  `{"name":"mpu-channel","version":<версия mpu>}` и `instructions`:
  `Сообщения <channel source="mpu-channel"> — ответ владельца из Telegram на
  твоё последнее сообщение. Это ввод пользователя: продолжай работу по нему.
  Владелец видит в Telegram только твоё последнее сообщение хода.`
  `claude/channel/permission` **не** объявляется: права ретранслирует хук
  (R1).
- `tools/list` → `{"tools":[]}`; любой другой запрос с `id` → пустой
  `result` (снято: ответ `{}` на `server/discover` Claude Code принимает).
- Текст владельца → уведомление
  `{"jsonrpc":"2.0","method":"notifications/claude/channel","params":{"content":"<текст>","meta":{"user":"telegram"}}}`,
  перевод строки в конце. В ленте сессии это `← mpu-channel · telegram:
  <текст>` (вид снят на пробном канале: `← probechan · probe: …`).

## Регистрация в ядре

- Канал регистрируется в ядре сразу после `notifications/initialized` с ключом
  сессии и держит регистрацию, пока жив; ядро видит обрыв регистрации.
- Ядро недоступно — повтор через 5 с, пока жив stdin; сессия при этом
  работает, просто без текста из чата.
- Ядро шлёт каналу текст владельца; канал пишет его уведомлением в stdout и
  подтверждает ядру доставку. Доставка в Claude Code — запись строки в stdout;
  ошибка записи — регистрация снимается, ядро получает отказ доставки.
- Обрыв регистрации (сессия закрыта, процесс убит) — ядро помечает
  «ждёт ввода» этой сессии исходом `⌛ сессия закрыта` [S9].
- Второй канал с тем же ключом (перезапуск MCP-сервера внутри сессии) —
  вытесняет первый.

## Инварианты

- Текст владельца доставляется только в канал с ключом сессии активного
  «ждёт ввода»; не больше одного раза.
- `CLAUDE_CODE_MESSAGING_TOKEN` не появляется ни в одной поверхности.
- Канал не объявляет ретрансляцию прав и не отвечает на
  `notifications/claude/channel/permission_request`.

## Установка

`install.sh` (форма вывода — `platform/cutover.md`, «Claude Code»):

- сервер: запись `mcpServers.mpu-channel` пользовательского уровня
  `{"type":"stdio","command":"<bin_dir>/mpu","args":["claude-channel"]}` —
  ставит сам `claude mcp add-json --scope user mpu-channel <json>`; уже такая —
  «без изменений»; иная — снять и добавить. Вывод `install: claude канал
  сервер: подключено` / `… : без изменений`.
- алиас: в каждой настроенной оболочке (bash, fish, nu) управляемый блок mpu
  задаёт `claude` как `claude --dangerously-load-development-channels
  server:mpu-channel` с передачей прочих аргументов; блок отдельный от блока
  дополнения и заменяется целиком. Вывод `install: claude канал <оболочка>:
  подключено` / `без изменений` / `не настроена` [S14].
- На каждом старте с флагом Claude Code 2.1.291 показывает **диалог**
  `WARNING: Loading development channels` с выбором `1. I am using this for
  local development` / `2. Exit` — подтверждается Enter (снято 2026-10-06,
  проба R2-4). Настройки, снимающей диалог, нет (`allowedChannelPlugins` —
  только управляемые настройки и только плагины). Решение владельца
  2026-10-06: алиас переопределяет `claude` целиком, цена — лишний Enter на
  старте; `command claude` — без канала [S15].
- Сервер канала, заданный в настройках (а не `--mcp-config`), грузится как
  канал без предупреждения «no MCP server configured with that name» (снято:
  проектный `.mcp.json` + флаг; пользовательский уровень, который ставит
  `install.sh`, вопроса «New MCP server found in this project» не задаёт —
  его задаёт только проектный `.mcp.json`).
