# mpu copy-client --date-from / --top-up

Статус: не реализовано — сверено 2026-09-10: `mpu copy-client --help` без флага `--date-from`. Спека: к реализации, только спецификация (2026-09-10). Расширение действующей `specs/copy-client.md`:
окно копирования по дате и доливка хвоста. Сама `copy-client.md` не меняется — её поведение без новых
флагов остаётся прежним. Соседнее расширение для вертикали Ozon — `specs/copy-dev-ozon.md`.

## Доливка хвоста — `--top-up`

Добавлено к исходной постановке по ручному прогону 2026-09-10 (`specs/copy-dev-ozon.md`): копия
стенда **стареет на сутки каждые сутки**. Перенос окном годится на один день; для ежедневной работы
нужен режим «дотянуть до сегодня», а не повторная полная копия.

`mpu copy-client SELECTOR --top-up`

- копируются только строки датируемых таблиц, новее локального максимума своей колонки даты, с
  **перекрытием в 2 дня** назад: маркетплейс досылает правки свежих суток задним числом, и без
  перекрытия они на стенд не попадут;
- справочники и ручной ввод — как в правилах окна ниже: целиком;
- схема клиента **не пересоздаётся** (в отличие от полной копии, где «сначала дамп, потом снос
  цели»): доливка пишет строки поверх существующих по ключу, иначе она уничтожила бы ровно ту копию,
  которую дополняет;
- клиента на стенде нет вовсе — `--top-up` выполняется как полная копия и говорит об этом строкой.

Вместе с `--date-from` — ошибка ввода: у доливки нижняя граница вычисляется, а не задаётся.

---

## 1. Кто и зачем

Разработчик поднимает у себя копию клиента, чтобы посмотреть его экраны и воспроизвести жалобу.
Сегодня копируется вся история клиента целиком; у крупных клиентов это десятки минут и десятки
гигабайт, притом что жалоба почти всегда про последние недели.

**Что появится:** окно копирования по дате — копируются строки от названного дня и новее.

## 2. Как выглядит вызов

```
mpu copy-client 4326 --date-from 2025-06-01
```

Ключ необязателен. Без него поведение прежнее — копируется всё.

## 3. Сценарии «дано → ожидается»

| Дано | Ожидается |
| --- | --- |
| `--date-from 2025-06-01`, у клиента данные с 2023 года | скопированы строки с 2025-06-01 включительно и новее; строк за 2023–2024 в копии нет |
| Ключ не задан | копируется всё, вывод и время как раньше |
| `--date-from` = день, раньше которого у клиента данных нет | копируется всё; в выводе сказано, что окно ничего не отсекло |
| `--date-from` = завтрашний день | копия пустая по датируемым таблицам, но команда **не падает**: это законный ввод, и в выводе прямо сказано, что перенесено ноль строк |
| `--date-from 01.06.2025` (не ISO) | отказ до всякой работы: назван ключ, названо ожидаемое `ГГГГ-ММ-ДД`, назван полученный текст |
| `--date-from 2025-13-40` | тот же отказ, теми же словами |
| В таблице нет колонки с датой | таблица копируется **целиком**, и в выводе против неё стоит пометка «без окна» |
| Таблица-справочник (единицы, тарифы, статусы) | копируется целиком независимо от окна |
| Повторный запуск с тем же окном | результат тот же: копия не двоится и не растёт |
| Повторный запуск с более ранним `--date-from` | в копии появляются недостающие старые строки; ручной уборки не требуется |
| Прод недоступен на середине переноса | прежняя локальная копия не разрушена; сказано, на какой таблице остановились |
| Локальный приёмник не поднят | отказ до чтения прода, с подсказкой, чем поднять |

## 4. Инварианты

- **Прод только читается.** Ключ окна не добавляет ни одной записи в прод.
- **Структура копируется всегда полностью.** Окно режет строки, а не таблицы и не колонки: копия
  без таблицы отличается от копии с пустой таблицей, и второе — то, что нужно.
- **Строка либо целиком в копии, либо целиком отсутствует.** Частично перенесённых строк не бывает.
- **Молчаливого отсечения не существует.** Каждая таблица, к которой окно не применилось, названа в
  выводе с причиной.
- **Ноль строк — не ошибка.** Пустой результат отличается от отказа и там, и там сказан словами.

## 5. Правила: какие строки попадают в копию

| Случай таблицы | Что копируется | Почему так |
| --- | --- | --- |
| есть колонка дня или даты события | строки от `--date-from` включительно | это и есть окно |
| несколько колонок с датой | окно применяется к той, по которой строка относится к дню в отчётах; выбор колонки печатается | иначе оператор не поймёт, что именно отсеклось |
| колонка есть, но у части строк пуста | строки с пустой датой копируются | пустая дата — не «раньше окна», а «неизвестно», и потерять её хуже |
| колонки с датой нет | таблица целиком | молчаливая потеря справочника дороже лишних мегабайт |
| справочник или настройка клиента | таблица целиком | без них копия не открывается |
| ручной ввод пользователя (себестоимость, планы, заметки) | таблица целиком | это авторские данные, их немного, а их отсутствие меняет числа на экранах |

⚠️ **Скользящие окна.** Часть показателей считается по предыдущим 30 дням (например доля выкупа).
На копии, обрезанной ровно по `--date-from`, первые дни окна посчитаются по неполной истории и
разойдутся с продом. Команда обязана сказать это в выводе одной строкой — не как предупреждение
«на всякий случай», а с конкретикой: с какого дня числа сопоставимы.

## 6. Вывод — примерами

Успешный прогон:

```
клиент 4326 «Glasson» · сервер sl-5 · окно с 2025-06-01

таблица                        строк     окно
wb_unit_nm_id                  412 118   с 2025-06-01
wb_unit_user_input_barcodes      8 940   с 2025-06-01
wb_cards                        21 004   без окна (нет колонки с датой)
wb_tariffs                         312   без окна (справочник)

перенесено 442 374 строки за 3 мин 12 с
⚠️ показатели со скользящим окном 30 дней сопоставимы с продом с 2025-07-01
```

Окно ничего не отсекло:

```
окно с 2019-01-01 · у клиента нет данных раньше 2023-04-11 — скопировано всё
```

Пустой результат:

```
окно с 2026-12-01 · перенесено 0 строк по датируемым таблицам
справочники и ручной ввод скопированы целиком
```

Отказ по формату:

```
параметр «--date-from»: ожидается ГГГГ-ММ-ДД, получено «01.06.2025»
```

## 7. Границы

- Команда не выбирает окно сама и не имеет умолчания «последние N дней»: без ключа — прежнее
  поведение.
- Не переносит данные между контурами, кроме «прод → локальный стенд», как и раньше.
- Не удаляет из локальной копии строки, оказавшиеся вне окна при повторном прогоне с более поздней
  датой: сузить копию, не пересоздав её, нельзя, и команда этого не обещает.
- Не занимается вертикалью Ozon и её ClickHouse — это режим `copy-dev --ozon`, `specs/copy-dev-ozon.md`.

## 8. Свойства решения

- **Дёшево на большом клиенте.** Смысл ключа — время и объём; если окно не сокращает ни того, ни
  другого, ключ бесполезен.
- **Повторяемо.** Тот же селектор и то же окно дают ту же копию.
- **Не разрушает прежнюю копию до того, как новая получена** — правило действующей команды, окно
  его не отменяет.
- **Проверяемо чтением, а не счётчиком.** По завершении команда сама показывает крайний день по
  главной витрине клиента: счётчик строк не доказывает, что экран откроется, а крайний день —
  доказывает.

## 9. Развилки владельцу

1. **Хвост под скользящие окна.** Дотягивать данные на 30 дней раньше `--date-from` молча,
   чтобы производные считались верно, — или копировать ровно по границе и предупреждать текстом?
   Рекомендация: копировать ровно по границе, предупреждать. Молчаливое расширение окна делает
   ключ непредсказуемым по времени и объёму — ровно по тому, ради чего он заводится.
2. **Умолчание.** Оставить «без ключа — всё» навсегда или через какое-то время сделать умолчанием
   окно в год? Рекомендация: оставить как есть; смена умолчания меняет поведение у всех разом.
3. **Ключ-компаньон `--date-to`.** Нужен ли верхний край окна? Рекомендация: не заводить, пока не
   попросят: воспроизведение жалобы всегда упирается в свежие данные, а не в исторический срез.
