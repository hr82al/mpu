# mpu telegram status

Статус: к реализации

Реализована целиком, кроме единицы измерения предела: усечение считает кодовые
точки, а контракт (ниже) требует кодовые единицы UTF-16. Правка едет хвостом
ближайшей порции.

Последняя подкоманда `telegram`. Общая часть — сеанс, конфигурация, прокси,
строка сессии, резолв адресата, коды выхода — в
`platform/telegram-mtproto.md`; сама отправка и её вывод — в
`telegram-send.md`; поиск адресата — в `telegram-ls.md`.

## Назначение

Отправить себе (или в указанный чат) отчёт за сегодня: какие карточки Kaiten я
сегодня двигал и куда. Источников два — локальный журнал перемещений, который
пополняют команды `kiten`, и, по умолчанию, живой опрос Kaiten.

## CLI-контракт

```
mpu telegram status [--chat X] [--live/--no-live] [--dry-run]
```

- `--chat X` — адресат, приводится общим резолвом (вторая попытка — поиск чата
  по названию). Не задан → `TELEGRAM_DEFAULT_CHAT`.
- `--live` / `--no-live` — дополнять журнал живым опросом Kaiten. По умолчанию
  включено.
- `--dry-run` — напечатать текст отчёта в stdout и завершиться: ни Telegram, ни
  адресат при этом не нужны. Kaiten при `--live` опрашивается и здесь.

Сегодня — календарный день **МСК** (UTC+3), окно `[00:00:00; 23:59:59]`
включительно по обеим границам.

Пример: `mpu telegram status --dry-run --no-live`.

## Ввод/вывод

**Сбор.** Записей две породы, они складываются в один список:

- **журнал перемещений** — таблица `kaiten_card_moves` кэш-БД, которую пишет
  `kiten move` (состав строки — `kiten-move.md`): берутся строки, чей момент
  записи попал в сегодняшнее окно; из строки нужны id карточки, заголовок, url,
  колонка-куда и момент записи. Пустой url → web-URL карточки
  `{KITEN_BASE_URL}/{id карточки}`;
- **живой опрос** (`--live`) — Kaiten REST (обвязка и web-URL —
  `platform/kaiten-http.md`): `GET /users/current` — мой id; затем
  `GET /cards?member_ids=<мой id>&updated_after=<начало дня, ISO UTC>&updated_before=<конец дня>`;
  на каждую карточку выборки — `GET /cards/{id}/location-history`; названия
  колонок — `GET /boards/{id}/columns` по доскам выборки. В отчёт идут карточки,
  у которых есть смена колонки с автором «я» за сегодняшний МСК-день; берётся
  последняя по времени. Порядок обращений, кроме «мой id раньше выборки
  карточек», контрактом не задан.

Название колонки: из ответа по доске; названия нет → id колонки числом; id
колонки нет → `—`.

**Текст отчёта.** Первая строка — `Отчёт за сегодня (YYYY-MM-DD МСК):`.

- записей нет → шапка, пустая строка, `Сегодня перемещений не было.`;
- записи есть → шапка, пустая строка и по строке на запись, нумерация с 1:
  `N. [Заголовок](url) — Колонка эмодзи`.

Дедуп по id карточки: побеждает запись с наибольшим моментом. Порядок — по паре
(момент, id карточки) по убыванию. `[` и `]` в заголовке заменяются на
полноширинные `［` и `］` (иначе рвётся markdown-ссылка); заголовка нет →
`#<id карточки>`.

Имя колонки сперва заменяется по `KITEN_COLUMN_MAP`, и эмодзи считается уже по
заменённому имени, без учёта регистра, первым сработавшим правилом:

1. переопределение из `KITEN_STATUS_EMOJI`;
2. точное «готово» или «выполнено» → ✅;
3. первая подстрока из списка в этом порядке: `ревью` 👀, `тест` 🧪,
   `разработ` 🛠️, `выгру` 🚀, `dev` 🚀, `prod` 🚀, `очеред` 📋, `оцен` 📊,
   `баг` 🐞;
4. ничего не сработало → 🔹.

**Отправка.** Текст уходит адресату с markdown-разметкой; stdout — та же
JSON-строка, что печатает отправка (`telegram-send.md`). Текст длиннее 4096
перед отправкой усекается: маркер `\n…(обрезано)` ставится так, чтобы вместе с
ним уложиться в предел. Единица предела — **кодовая единица UTF-16**: символ вне
основной плоскости (а это большинство эмодзи) считается двумя. Так меряет длину
сама внешняя система, и счёт кодовыми точками выпустил бы сообщение длиннее
предела — отказ пришёл бы уже от Telegram. `--dry-run` печатает текст
целиком, без усечения, и завершает вывод одним переводом строки.

## Побочные эффекты

Без `--dry-run` — реальное сообщение от имени личного аккаунта: необратимо и
видно получателю (`me` — «Избранное» — безопасно). Кэш-БД читается (при первом
обращении её схема создаётся), при `--live` идут GET-запросы к Kaiten.
PostgreSQL не используется. Журнал перемещений эта подкоманда не пополняет и не
чистит.

## Конфигурация

Переменные сеанса — `platform/telegram-mtproto.md`. Свои:

- `KITEN_API_KEY`, `KITEN_BASE_URL` — живой опрос и web-URL карточки
  (`platform/kaiten-http.md`);
- `KITEN_STATUS_EMOJI`, `KITEN_COLUMN_MAP` — JSON-объекты «имя колонки →
  эмодзи» и «имя колонки → замена», ключи сравниваются без учёта регистра.
  Пусто, невалидный JSON или не объект → переопределений нет, молча.

## Инварианты

- Отчёт не зависит от того, сколько раз его собрали: повторный вызов на тех же
  данных даёт тот же текст.
- `--dry-run` не открывает сеанс Telegram ни при каком вводе.
- Ни одна ошибка Kaiten не отменяет отчёт: живой опрос — дополнение к журналу,
  и при его отказе отчёт строится на журнале.
- Ошибки ввода (код 2) обнаруживаются **до любой сети**, включая Kaiten:
  отсутствующий адресат при вызове без `--dry-run` останавливает команду прежде
  живого опроса.
- В stdout идёт только отчёт (или JSON отправки); предупреждения — в stderr.

## Граничные случаи и ошибки

- Адресат не задан и нет `TELEGRAM_DEFAULT_CHAT`, вызов без `--dry-run` →
  exit 2 до сети: `telegram: адресат не задан; укажи --chat или
  TELEGRAM_DEFAULT_CHAT в .env`.
- Журнал пуст и живой опрос ничего не дал (либо `--no-live`) → текст «Сегодня
  перемещений не было.», exit 0. Не ошибка.
- Живой опрос не состоялся — отказ Kaiten либо отсутствующий `KITEN_API_KEY` →
  в stderr одна строка `mpu telegram status: live-обогащение пропущено (Kaiten:
  <текст>)`, отчёт строится на журнале, exit 0. Трейсбека нет ни в одном из этих
  случаев.
- Карточка попала в выборку, но её история перемещений недоступна → карточка в
  отчёт не идёт, и в stderr одна строка `mpu telegram status: история карточки
  <id> недоступна (Kaiten: <текст>)`. Отчёт продолжается.
- Колонки доски недоступны → названия колонок этой доски печатаются id числом
  (правило «названия нет»), отдельного предупреждения нет.
- Отказ резолва адресата, rate-limit, прочий отказ Telegram → по правилам слоя,
  exit 1.

## Golden-примеры

`fixtures/telegram-status/`. Пустой отчёт снят живым прогоном
(`--dry-run --no-live`); отчёт с записями — синтетический: живые записи это
названия чужих карточек. Дата в обоих голденах фиксированная, тест подставляет
её часами, а не берёт стенные.

- `status-empty-stdout.txt` — отчёт без записей, `--dry-run`.
- `status-report-stdout.txt` — три записи: обычная, заголовок со скобками
  (заменены на полноширинные), карточка без заголовка и с неизвестным названием
  колонки (id числом, эмодзи по умолчанию).
- `warn-live-skipped-stderr.txt` — живой опрос пропущен.
- `warn-card-history-stderr.txt` — история одной карточки недоступна.
- `err-no-chat-stderr.txt` — адресат не задан, exit 2.

Каждый файл оканчивается одним переводом строки.

## Известные отклонения

- **fix** — усечение прежняя реализация делает по сырым символам: маркер
  `…(обрезано)` встаёт посреди разорванной markdown-ссылки. Правильно — резать
  по границе целых строк, чтобы ни одна ссылка не осталась половиной.
- **fix** — прежняя реализация опрашивает Kaiten **до** проверки адресата:
  вызов без адресата и без `--dry-run` сперва ходит в сеть и только потом
  отказывает, да ещё кодом 1. Правильно — код 2 и отказ до сети.
- **fix** — отсутствующий `KITEN_API_KEY` при `--live` прежняя реализация
  роняет трейсбеком: перехвачены только отказы самого API, но не отсутствие
  ключа. Правильно — та же строка «live-обогащение пропущено», отчёт на
  журнале.
- **fix** — недоступная история конкретной карточки прежней реализацией
  проглатывается молча: карточка исчезает из отчёта без следа. Правильно —
  строка предупреждения, как в «Граничных случаях».
- **preserve** — `--dry-run` печатает неусечённый текст: усечение — свойство
  отправки, а человеку показывается полный отчёт.
- **preserve** — недоступные колонки доски отдельным предупреждением не
  сообщаются: наблюдаемое следствие — id колонки числом — уже описано
  контрактом и различимо в отчёте.
