# mpu telegram status

Статус: черновик

Команда разделена по подкомандам (2026-08-16). Общая часть — сеанс, конфигурация,
прокси, строка сессии, резолв адресата, коды выхода — в
`platform/telegram-mtproto.md`; отправка сообщения — в `telegram-send.md`, поиск
адресата — в `telegram-ls.md`, поиск по содержимому — в `telegram-search.md`.
Здесь осталась одна подкоманда, она ждёт своей порции.

## Назначение

Telegram от имени пользователя (личный аккаунт, протокол MTProto, не бот):
`status` — отправить отчёт о карточках Kaiten, перемещённых мной сегодня.
Авторизация — заранее, `mpu init` (`init.md`).

## CLI-контракт

Адресат (`--chat`) приводится по правилам `platform/telegram-mtproto.md`, включая
вторую попытку — поиск чата по названию (`telegram-ls.md`). Без `--chat` берётся
`TELEGRAM_DEFAULT_CHAT`.

`mpu telegram status [--chat X] [--live/--no-live] [--dry-run]` — отправить
адресату отчёт за сегодня (календарный день МСК, UTC+3); `--live` (дефолт) —
дополнить журнал данными Kaiten; `--dry-run` — текст в stdout, без Telegram.

Пример из практики: `mpu telegram status --dry-run --no-live`.

## Ввод/вывод

stdout — данные; stderr — ошибки команды одной строкой `telegram: <причина>[;
попробуй: <подсказка>]`, без трейсбеков; отказ разбора аргументов/опций CLI —
стандартным форматом ошибок парсинга флагов («Известные отклонения»). Exit:
0 — успех; 2 — ошибки ввода (до сети); 1 — конфиг и Telegram. `status` после
отправки печатает ту же JSON-строку, что и `telegram-send.md`.

`status` — сбор: (1) журнал перемещений — таблица `kaiten_card_moves` кэш-БД
(пишется командами `mpu kiten`): строки с `moved_at` (epoch-секунды) в
инклюзивном окне [00:00:00; 23:59:59] текущего МСК-дня; поля `card_id`,
`title`, `url`, `to_column`, `moved_at`; пустой `url` → web-URL карточки
`{base}/{card_id}`. (2) `--live` — Kaiten REST (обвязка и web-URL —
`platform/kaiten-http.md`): `GET /users/current` → мой id; `GET /cards?
member_ids=<id>&updated_after=<начало дня, ISO UTC>&updated_before=<конец
дня>`; на карточку — `GET /cards/{id}/location-history`; в отчёт — карточки с
моей сменой колонки (author_id = мой id) за текущий МСК-день, берётся
последняя; название колонки — `GET /boards/{id}/columns` по доскам выборки,
названия нет → id числом, id колонки нет → `—`.

`status` — текст: шапка `Отчёт за сегодня (YYYY-MM-DD МСК):`; записей нет →
`<шапка>\n\nСегодня перемещений не было.`; иначе после пустой строки — строки
`N. [Заголовок](url) — Колонка эмодзи` (с 1): дедуп по card_id (побеждает
наибольший `moved_at`), порядок по (`moved_at`, card_id) по убыванию; `[`/`]`
заголовка → полноширинные `［`/`］`; заголовка нет → `#<card_id>`. Имя колонки
заменяется по `KITEN_COLUMN_MAP`; эмодзи — по заменённому имени (без учёта
регистра): override из `KITEN_STATUS_EMOJI` → точное «Готово»/«Выполнено» →
✅ → первая подстрока (`ревью` 👀, `тест` 🧪, `разработ` 🛠️,
`выгру`/`dev`/`prod` 🚀, `очеред` 📋, `оцен` 📊, `баг` 🐞) → 🔹. Текст
длиннее 4096 символов (лимит Telegram) перед отправкой усекается по границе
целых строк так, чтобы с маркером `\n…(обрезано)` в конце уложиться в лимит;
`--dry-run` печатает без усечения; отправка в Markdown; вывод — как у
отправки (`telegram-send.md`).

## Побочные эффекты

`status` без `--dry-run` отправляет реальное сообщение от имени личного
аккаунта — необратимо и видно получателям (`me` — Избранное —
безопасно). Каждый вызов открывает и закрывает соединение с Telegram. `status`
читает кэш-БД (при первом обращении инициализирует её схему), при `--live` —
GET-запросы к Kaiten. PostgreSQL не используется.

## Конфигурация

Общие переменные (`TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION`,
`TELEGRAM_DEFAULT_CHAT`, `TELEGRAM_PROXY`) и все их ошибки — в
`platform/telegram-mtproto.md`. Своё у этих трёх подкоманд только одно:

- `KITEN_API_KEY`, `KITEN_BASE_URL` — live-обогащение `status`
  (`platform/kaiten-http.md`); `KITEN_STATUS_EMOJI`, `KITEN_COLUMN_MAP` —
  JSON-объекты «имя колонки → эмодзи/метка», ключи без учёта регистра; пусто /
  невалидный JSON / не-объект → молча без переопределений.

## Инварианты

- Один вызов — один сеанс: соединение открывается заново и гарантированно
  закрывается даже при ошибке; авторизация проверяется до операции, ошибки
  ввода (exit 2) — до открытия соединения.
- `--chat` всегда приоритетнее `TELEGRAM_DEFAULT_CHAT`; числовой адресат —
  всегда id, не название; `status --dry-run` не обращается к Telegram (Kaiten
  при `--live` — обращается).
- Секреты (`TELEGRAM_API_HASH`, строка сессии, пароль прокси) не попадают в
  вывод.

## Граничные случаи и ошибки

- Адресат не задан → exit 2 до сети: `telegram: адресат не задан; укажи --chat
  или TELEGRAM_DEFAULT_CHAT в .env`.
- Отказ поиска чата по названию (несколько совпадений либо ни одного) — тексты
  и коды в `telegram-ls.md`, «Резолв по названию»; здесь `<что>` — всегда
  «чат».
- rate-limit Telegram → exit 1: `telegram: rate-limit, подожди <N>s`; прочая
  ошибка RPC → exit 1: `telegram: RPC error: <текст>`.
- `status`: журнал и live пусты → текст «Сегодня перемещений не было.», не
  ошибка; ошибка Kaiten при `--live` → stderr `mpu telegram status:
  live-обогащение пропущено (Kaiten: <текст>)`, работа продолжается на журнале.

## Golden-примеры

Снять при переводе в «к реализации» на собственном аккаунте (без чужих личных
данных в фикстурах; отправка — только в `me`, Избранное): `status --dry-run
--no-live` (happy path без сети Telegram) и `status` без адресата (exit 2).

## Известные отклонения

- **fix** — ошибки ввода оригинал завершает exit 1. Правильно — exit 2 и
  проверка до сети; тексты ошибок неизменны.
- **fix** — усечение `status` оригинал делает по сырым символам: маркер
  `…(обрезано)` может встать посреди разорванной markdown-ссылки. Правильно —
  усечение по границе целых строк (см. «Ввод/вывод»).
- **preserve** — `--dry-run` печатает неусечённый текст: усечение — свойство
  отправки, dry-run показывает человеку полный отчёт.
- **preserve** — резолв по названию ищет только среди первых 50 результатов
  серверного поиска; название вне их → «не удалось найти». Причина:
  канонические адресаты — id и @username; лимит — тот же, что у `ls`.
- **fix** — отказ разбора аргументов/опций CLI оригинал печатает многострочной
  рамкой (`Usage:` + `Invalid value for …`), без префикса команды.
  Воспроизводить её запрещено: контракт — одна строка причины и exit 2, как в
  `telegram-ls.md`.

## Открытые вопросы

- Судьба журнала перемещений `kaiten_card_moves`: его пишет `kiten move`, а
  читает эта подкоманда. Решается вместе со спекой `kiten move` — до тех пор
  сбор из журнала описан как есть.
