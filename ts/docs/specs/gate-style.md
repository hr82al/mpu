# mpu gate style

Статус: черновик (2026-09-10 — постановка по живому случаю; к реализации — после ответа на
«Открытые вопросы»)

## Назначение

Ворота code style фронта над диффом ветки: добавленные строки комментариев, которые правила
репозитория запрещают. Одна команда вместо ручного конвейера `git diff | grep | grep -v`, с
понятным отчётом и кодом выхода — чтобы приёмка мерила правило, а не читала его.

**Живой случай (2026-09-10).** Правило «поясняющих комментариев нет, только `TODO`/`TEMP`» стояло и
в `ozon/apps/front/.ai/core/CODE_STYLE.md`, и в спеке карточки «Чек-лист», но дифф MR `!559`
набрал 35 строк комментариев в `apps/front` и 83 в `packages/ui` — правило читали, приёмка его не
мерила. Ворота собирались так:

```
git diff origin/main...HEAD -- apps/front \
  | grep -E '^\+\s*(//|/\*|\*|\{/\*)' \
  | grep -vE 'TODO|TEMP|@dataflow-node|^\+\s*//\s{2,}\w+:|@end|@vitest-environment|eslint-|@ts-|@param|@returns'
```

После чистки (коммит `e4203eaf`) — 0 строк; в ките 83 строки прозы стали 29 однострочными пометками
`ПРАВКА ПОРТА`. Исключения ворот появлялись по живым строкам: `@dataflow-node … @end` на
BFF-роутах — машинная разметка репозитория; `@vitest-environment jsdom` — директива; `@param` в
существующем JSDoc публичного API — правило монорепо обновлять `@param` вместе с сигнатурой.

## CLI-контракт

`mpu gate style [--repo REPO] [--base REF] [--json]`

- `--repo` — репозиторий рабочей области; дефолт — репозиторий текущего каталога.
- `--base` — база сравнения; дефолт по репозиторию: `ozon` → `origin/main`, `sw-front` →
  `origin/dev` (целевые ветки MR этих репозиториев). Сравнение — `git diff <base>...HEAD`
  (три точки: только изменения ветки).
- `--json` — вместо отчёта JSON-объект.

Политика — `ro`.

## Ввод/вывод

### Области и правила

| Репозиторий | Путь | Нарушение |
| --- | --- | --- |
| `ozon` | `apps/front` | добавленная строка-комментарий, кроме исключений |
| `ozon` | `packages/ui` | добавленная строка-комментарий без `ПРАВКА ПОРТА` (донорские комментарии в диффе не появляются — добавленных строк у них нет) |
| `sw-front` | весь репозиторий | добавленная строка-комментарий, кроме исключений |

**Строка-комментарий** — добавленная строка диффа (`+`, не `+++`), которая после ведущих пробелов
начинается с `//`, `/*`, `*` или `{/*`.

**Исключения** (строка не нарушение, если содержит): `TODO`, `TEMP`, `@dataflow-node`, `@end`,
продолжение блока `@dataflow-node` (`//` и два пробела и `ключ:`), `@vitest-environment`,
`eslint-`, `@ts-`, `@param`, `@returns`.

⚠️ `TODO`/`TEMP` без условия удаления правила репозитория тоже запрещают, но проверить «условие»
строкой нельзя: такие строки уходят в раздел «на глаз» отчёта, не в нарушения.

### Результат

`{ repo, base, violations: [{ file, line, text, area }], review: [{ file, line, text }], counts:
{ violations, review } }` — `line` — номер строки в новой версии файла (из заголовков хунков),
`area` — путь-область из таблицы, `review` — строки `TODO`/`TEMP`.

Отчёт (без `--json`): по файлу — `<file>` и под ним `  <line>: <text>`; затем раздел `на глаз:`
с `TODO`/`TEMP`; последняя строка — `нарушений: N` и перевод строки.

## Побочные эффекты

Нет.

## Конфигурация

Нет своей. Правило и исключения зашиты в команду; их источник — правила самих репозиториев
(`ozon/apps/front/AGENTS.md`, `.ai/core/CODE_STYLE.md`, `ozon/packages/ui/AGENTS.md`,
`sw-front/AGENTS.md`).

## Инварианты

- Смотрятся только добавленные строки ветки; существующие комментарии основной ветки не судятся.
- Exit 0 — нарушений нет (раздел «на глаз» не влияет), 1 — есть.

## Граничные случаи и ошибки

- База не найдена (нет `origin/main`) → exit 2, `нет базы <REF>: git fetch?`.
- Репозиторий не из таблицы → exit 2, `для <repo> правила нет`.
- Пустой дифф → `нарушений: 0`, exit 0.

## Golden-примеры

Нет — снимаются при реализации на фикстуре-диффе, содержащей по одной строке каждого исключения,
поясняющий комментарий, строку кита с `ПРАВКА ПОРТА` и без, `TODO` без условия.

## Известные отклонения

Нет.

## Открытые вопросы

- JSX-комментарий `{/* … */}` в середине строки (после кода) — ловить ли? Живьём не встречался.
- Нужны ли остальные разделы `CODE_STYLE` (слои, импорты) — они не проверяются строкой; вне этой
  команды.
- Для `sw-back` (бэкенд, NestJS) правила комментариев другие — команда его не покрывает.
