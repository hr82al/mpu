# CLAUDE.md

Overview дерева `mpu` целиком. Корневой CLAUDE.md монорепо (`../CLAUDE.md`)
применяется как есть.

`mpu` (monorepo python utilities) — multi-purpose CLI для вспомогательных операций
над данными монорепо. Отдельный `.git` (этот каталог) — версионируется независимо
от `sl-back` / `sw-back` / `sw-front`. Ветки/MR не создавать, коммитить прямо в
`main` (как и `mp`; см. корневой Git & MR workflow).

## Структура

- `py/` — текущая реализация (Python 3.12+, uv, typer, pytest, ruff, pyright
  strict). Специфика — `py/CLAUDE.md`.
- `go/` — постепенный переезд серверной части (брокер) на Go
  (greenfield-модуль: `go.mod`, свой `CLAUDE.md`, кода ещё нет). Правила
  переезда (скоуп, гейты, ограничения для LLM) — `docs/go-migration.md`;
  архитектура (Go-брокер + Deno/TS CLI) — `docs/broker-architecture.md`.
  Go-сессии
  изолированы (`py/`, `docs/`, этот файл им не видны); знание о поведении
  Python-версии передаётся только через спеки в `go/docs/specs/` по
  правилам `go/docs/CLAUDE.md`: сначала снять/обновить спеку, реализация —
  в изолированной Go-сессии строго по ней. Из монорепо/mpu-сессии внутри
  `go/` не трогать ничего, кроме `go/docs/`.
- `ts/` — Deno/TS CLI (`mpu`, собирается `deno compile`). Пока только
  `docs/` — канал CLI-спек для изолированных Deno-сессий (правила —
  `ts/docs/CLAUDE.md`; протокол брокера — общий канал
  `go/docs/specs/protocol/`, ts-сессиям read-only). Код появится с
  первым вертикальным срезом; из монорепо-сессии внутри `ts/` не
  трогать ничего, кроме `ts/docs/`.

Весь функционал `mpu` пока в `py/`. Целевая архитектура — Go-брокер
(удалённый сервис) + CLI на Deno/TS, собираемый `deno compile` в точку
входа `~/.local/bin/mpu`; на время переезда брокер делегирует ещё не
переехавшие операции Python-реализации (`docs/broker-architecture.md`).

## Общее для py/ и go/

- `.env.example` — справочник переменных рантайм-конфига (`~/.config/mpu/.env`),
  не завязан на язык реализации.
- `.gitignore` — общий для обеих реализаций.
